Prefix Sum один раз складывает начало Array, и потом сумма любого отрезка стоит одно вычитание.

1. Сумма на отрезке: сколько стоит повторять

Вход: Array a = [3, 1, 4, 1, 5, 9, 2, 6] длины n = 8 и q запросов. Запрос [l, r] спрашивает сумму a[l] + a[l + 1] + ... + a[r]. Номера с 0, оба конца входят в отрезок.

Запросы [2, 5], [0, 7] и [3, 3]. Ответы: 4 + 1 + 5 + 9 = 19, сумма всего Array 31 и одно число a[3] = 1.

Brute Force считает каждый запрос заново. Если начинать с суммы 0, то k чисел дают k сложений. Здесь 4 + 8 + 1 = 13 сложений.

Время: O(n · q) в худшем случае. Дополнительная память: O(1), одна сумма. Ответ отдельно: q чисел.

2. Prefix Sum с нулём в начале

Сохраним суммы всех начал Array один раз: p[0] = 0, p[1] = a[0], p[2] = a[0] + a[1] и так далее. Каждое следующее число получается одним сложением: p[i + 1] = p[i] + a[i]. Для нашего a получаем p = [0, 3, 4, 8, 9, 14, 23, 25, 31]: n + 1 = 9 чисел за 8 сложений.

p[6] это сумма a[0..5], а p[2] это сумма a[0..1]. Разность убирает общее начало: p[6] − p[2] = 23 − 4 = 19, это сумма a[2..5].

Правило. p[0] = 0 и p[i + 1] = p[i] + a[i]. Сумма a[l] + ... + a[r] равна p[r + 1] − p[l]. Номера с 0, оба конца входят.

Проверим другие запросы. [0, 7]: p[8] − p[0] = 31 − 0 = 31. [3, 3]: p[4] − p[3] = 9 − 8 = 1. Число p[0] = 0 нужно для запроса с l = 0: та же формула работает без отдельного if.

Ошибка на один номер

Запрос [2, 5] с ответом 19. p[5] − p[2] = 14 − 4 = 10: потерян a[5] = 9, потому что p[5] заканчивается на a[4]. p[6] − p[3] = 23 − 8 = 15: потерян a[2] = 4, потому что p[3] уже содержит a[2]. Правая граница берёт p[r + 1], левая берёт p[l].

Список без нуля в начале, s[i] = a[0] + ... + a[i], тоже работает, но запрос с l = 0 требует отдельной ветки: сумма равна s[r]. Для [2, 5] ветка не нужна: s[5] − s[1] = 23 − 4 = 19. Для [0, 7] нужна: s[7] = 31. Ноль в начале p убирает эту ветку.

a = [3, 1, 4, 1, 5, 9, 2, 6]
p = [0]
for x in a:
    p.append(p[-1] + x)
print(p)
print(p[6] - p[2])

Тот же список даёт list(accumulate(a, initial=0)) из модуля itertools.

Время: n сложений на построение и одно вычитание на запрос, O(n + q). Дополнительная память: p хранит n + 1 чисел, O(n). Ответ отдельно: q чисел.

3. Номера с 1: Codeforces 1807D

На Codeforces элементы часто нумеруют с 1: a[1], ..., a[n]. Тогда удобно хранить p[i] = a[1] + ... + a[i] и p[0] = 0. Сумма a[l..r] равна p[r] − p[l − 1]. Это правило раздела 2, только номера сдвинулись на один.

В задаче 1807D запрос l, r, k заменяет все a[l..r] на k и спрашивает, будет ли сумма всего Array нечётной. Пример из условия: a = [2, 2, 1, 3, 2], p = [0, 2, 4, 5, 8, 10], total = 10. Запрос l = 2, r = 3, k = 3: на отрезке p[3] − p[1] = 5 − 2 = 3, новая сумма 10 − 3 + 3 · 2 = 13. Она нечётная: YES.

Правило. С номерами с 1 сумма a[l..r] равна p[r] − p[l − 1]. После замены отрезка на k сумма равна total − (p[r] − p[l − 1]) + k · (r − l + 1).

Во втором наборе примера a состоит из десяти единиц, total = 10. Запрос 1 9 100: на отрезке p[9] − p[0] = 9, новая сумма 10 − 9 + 100 · 9 = 901. Она нечётная: YES, последняя строка вывода.

for _ in range(q):
    l, r, k = map(int, input().split())
    s = total - (p[r] - p[l - 1]) + k * (r - l + 1)
    out.append("YES" if s % 2 == 1 else "NO")

Сам Array менять не нужно: запрос не меняет вход для следующих запросов. Каждый набор строит свой p заново, иначе суммы прошлого набора попадут в новый. Новая сумма не больше 2 · 105 · 109 = 2 · 1014.

Время: O(n + q) на набор. Дополнительная память: O(n) для p. Ответ: q строк.

Быстрый ввод для Codeforces разобран в главе 4 лекции Two Pointers: sys.stdin.buffer.read().split() читает весь вход один раз.

4. Опорный индекс: сумма слева и справа

LeetCode 724: найдите самый левый индекс i, для которого сумма чисел слева от i равна сумме чисел справа. Пусть left это сумма слева, total это сумма всех чисел. Тогда справа от i лежит total − left − nums[i].

nums = [1, 7, 3, 6, 5, 6], total = 28. i = 0: слева 0, справа 27. i = 1: 1 и 20. i = 2: 8 и 17. i = 3: 11 и 11, ответ 3. Проверено 4 индекса, хранились только total и left.

Правило. Сумма справа от i равна total − left − nums[i]. Список p не нужен: хватает total и бегущей суммы left.

def pivot(nums):
    total = sum(nums)
    left = 0
    for i, x in enumerate(nums):
        if left == total - left - x:
            return i
        left += x
    return -1

print(pivot([1, 7, 3, 6, 5, 6]), pivot([1, 2, 3]), pivot([2, 1, -1]))

Частая ошибка: сравнить left с total − left. Тогда nums[i] попадает в сумму справа. Для [1, 7, 3, 6, 5, 6] на i = 3 получится 11 и 17, ни один индекс не подойдёт, и ответ 3 пропадёт.

Проверим вывод руками. В [1, 2, 3] total = 6, пары слева и справа (0, 5), (1, 3), (3, 0) не равны: ответ −1. В [2, 1, −1] total = 2, при i = 0 слева 0 и справа 2 − 0 − 2 = 0: ответ 0. Программа печатает 3 -1 0.

Время: n чтений в sum и не больше n шагов цикла, O(n). Дополнительная память: O(1), два числа. Срезы sum(nums[:i]) и sum(nums[i + 1:]) для каждого i дают O(n²) времени и O(n) временной памяти.

5. Prefix Product: произведение всех, кроме себя

LeetCode 238: для каждого i нужно произведение всех чисел, кроме nums[i]. nums = [1, 2, 3, 4]. Произведения чисел слева от i: [1, 1, 2, 6]. Справа от i: [24, 12, 4, 1]. Перемножим по местам и получим ответ [24, 12, 8, 6].

Почему не разделить произведение всех чисел на nums[i]? Возьмём nums = [−1, 1, 0, −3, 3]. Произведение всех чисел 0, а делить на nums[2] = 0 нельзя. При этом ответ для i = 2 равен (−1) · 1 · (−3) · 3 = 9.

Правило. ans[i] = (произведение чисел до i) · (произведение чисел после i). Первый проход пишет в ans префиксы, второй умножает ans на суффиксы.

nums = [1, 2, 3, 4]
n = len(nums)
ans = [1] * n
left = 1
for i in range(n):
    ans[i] = left
    left *= nums[i]
right = 1
for i in range(n - 1, -1, -1):
    ans[i] *= right
    right *= nums[i]
print(ans)

Проверим ноль: nums = [0, 4, 5]. Первый проход даёт ans = [1, 0, 0], произведения справа [20, 5, 1], ответ [20, 0, 0]. Ненулевое произведение 4 · 5 = 20 получает только место нуля.

Время: n умножений left, n умножений ans[i] *= right и n умножений right, всего 3n, O(n). Дополнительная память: O(1), два числа. Ответ отдельно: n чисел. Отдельные списки префиксов и суффиксов дают O(n) дополнительной памяти.

6. Две Prefix Sum для одного входа

Codeforces 433B: вопрос первого вида спрашивает сумму v[l..r], вопрос второго вида сумму u[l..r], где u это стоимости v в неубывающем порядке. Номера с 1. Пример: v = [6, 4, 2, 7, 2, 7], u = sorted(v) = [2, 2, 4, 6, 7, 7].

Строим две Prefix Sum: pv = [0, 6, 10, 12, 19, 21, 28] и pu = [0, 2, 4, 8, 14, 21, 28]. Вопрос 2, l = 3, r = 6: pu[6] − pu[2] = 28 − 4 = 24. Вопрос 1, l = 3, r = 4: pv[4] − pv[2] = 19 − 10 = 9.

sorted(v) создаёт новый список и не меняет v. После v.sort() вопросы первого вида получат суммы упорядоченного списка.

Время: Sorting O(n log n) один раз, построение O(n), O(1) на вопрос: O(n log n + m). Дополнительная память: O(n) для u и двух списков p. Ответ отдельно: m чисел. Пересчёт суммы для каждого вопроса стоит O(n · m): при n = 105 и m = 5 · 104 вопросов по всему Array это 5 · 109 сложений.

Сумма может дойти до 105 · 109 = 1014. Целые числа Python не переполняются, а в C++ для такой суммы нужен 64-битный тип.

Когда Prefix Sum не помогает

Если элемент Array меняется, меняются и все следующие p, и новый p стоит O(n). Много изменений между запросами требуют других структур, в этой лекции их нет.

Минимум нельзя вычесть. a = [5, 1, 4], минимумы начал [5, 1, 1]. Минимум отрезка [2, 2] равен 4, но из чисел 1 и 1 его не получить. Сумма обратима: вычитание убирает начало.

7. Что нужно запомнить

  • p длины n + 1 с p[0] = 0. Сумма a[l..r] равна p[r + 1] − p[l] при номерах с 0 и p[r] − p[l − 1] при номерах с 1.
  • Построение стоит O(n) времени и O(n) памяти, каждый запрос O(1).
  • Если нужна только сумма слева, храните одно число: total и left дают сумму справа.
  • Для произведений идите слева и справа и не делите: ноль ломает деление.

8. Как решать задачи этой главы

  1. Запишите, с какого номера начинаются элементы и входят ли оба конца.
  2. Проверьте формулу на запросе с l = 0 или l = 1 и на отрезке из одного элемента.
  3. Посчитайте построение и запросы отдельно: O(n + q), а не O(n · q).
  4. Посчитайте наибольшую сумму и решите, нужен ли 64-битный тип в другом языке.
