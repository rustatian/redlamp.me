Сумма Subarray равна разности двух префиксов, поэтому Hash Table уже встреченных префиксов находит нужное начало за один шаг.

1. Сумма Subarray как разность префиксов

Two Sum (LeetCode 1) уже разобран в главе 4 лекции Two Pointers, раздел «Two Sum без порядка»: dict хранит число и его номер. Для nums[j] сначала ищите target − nums[j] среди более ранних чисел, потом записывайте nums[j] → j, иначе число станет парой само себе. Ниже тот же шаг работает с префиксами: для нового префикса s ищем более ранний префикс s − k.

LeetCode 217 Contains Duplicate делает этот шаг без номеров: set хранит уже встреченные числа. nums = [1, 2, 3, 1]: числа 1, 2 и 3 новые, их добавляем в set. Четвёртое число 1 уже есть в set, ответ True после 4 проверок. Brute Force сравнивает все n(n − 1)/2 пар: при n = 105 это почти 5 · 109 сравнений.

Возьмём nums = [1, 2, 3] и Prefix Sum из главы 1: p = [0, 1, 3, 6]. Сумма nums[l..r] равна p[r + 1] − p[l]. Условие «сумма равна k» значит p[r + 1] − p[l] = k, то есть p[l] = p[r + 1] − k. Это Two Sum на префиксах, только с разностью вместо суммы.

Пусть k = 3. Для p[1] = 1 нужен более ранний префикс −2: его нет. Для p[2] = 3 нужен 0: это p[0], Subarray [1, 2]. Для p[3] = 6 нужен 3: это p[2], Subarray [3]. Ответ 2, как в примере 2 задачи 560.

В главе 3 лекции про Heap, Queue и Deque Sliding Window работал, потому что стоимости положительные. Здесь числа бывают отрицательными: при расширении сумма окна может уменьшиться, и правило сдвига границ ломается. Prefix Sum с Hash Table не зависит от знаков чисел.

2. Считаем Subarray с суммой k

LeetCode 560: nums = [1, −1, 1, 1, −1], k = 1. Сумму 1 имеют 7 Subarray, по номерам с 0: (0, 0), (2, 2), (3, 3), (0, 2), (1, 3), (0, 4) и (2, 4). Префиксы равны 0, 1, 0, 1, 2, 1. Одно значение префикса встречается много раз, поэтому dict cnt хранит для каждого значения число встреч.

На последнем шаге s = 1, и мы ищем s − k = 0. Префикс 0 уже встретился два раза: пустой префикс и префикс после двух чисел. Поэтому шаг даёт 2 новых Subarray: (0, 4) и (2, 4).

Правило. cnt начинается с {0: 1}: это пустой префикс. Для нового префикса s прибавьте к ответу cnt.get(s − k, 0), потом увеличьте cnt[s].

nums = [1, -1, 1, 1, -1]
k = 1
cnt = {0: 1}
s = 0
ans = 0
for x in nums:
    s += x
    ans += cnt.get(s - k, 0)
    cnt[s] = cnt.get(s, 0) + 1
print(ans, cnt)

Программа печатает 7 {0: 2, 1: 3, 2: 1}. dict хранит ключи в порядке первой записи: 0 с самого начала, потом 1 и 2.

Порядок двух строк в цикле важен. Если сначала увеличить cnt[s], то при k = 0 каждый префикс найдёт сам себя, и ответ получит лишний пустой отрезок.

Время: n поисков и n записей в dict, ожидаемое O(n): на обычных входах одна операция dict стоит O(1). Дополнительная память: до n + 1 разных ключей, O(n); здесь 3 ключа. Ответ отдельно: одно число до n(n + 1)/2.

3. Баланс 0 и 1: самый длинный Subarray

LeetCode 525: найдите самый длинный Subarray, в котором поровну 0 и 1. Замените 0 на −1. Тогда равное число 0 и 1 значит сумму 0, то есть два равных префикса. Префикс здесь удобно звать балансом: единицы минус нули.

nums = [0, 1, 1, 1, 1, 1, 0, 0, 0]. Балансы по позициям 0..9: 0, −1, 0, 1, 2, 3, 4, 3, 2, 1. Позиция i значит «после i чисел». Баланс 1 впервые на позиции 3 и снова на позиции 9: Subarray из чисел с номерами 3..8 имеет длину 9 − 3 = 6. Это [1, 1, 1, 0, 0, 0].

Для самой большой длины нужна самая ранняя позиция баланса. Поэтому первую позицию записывают один раз и потом не меняют.

Правило. Для самого длинного Subarray храните первую позицию каждого баланса и не меняйте её. Для подсчёта Subarray храните число встреч.

nums = [0, 1, 1, 1, 1, 1, 0, 0, 0]
first = {0: 0}
b = 0
best = 0
for i, x in enumerate(nums, 1):
    b += 1 if x == 1 else -1
    if b in first:
        best = max(best, i - first[b])
    else:
        first[b] = i
print(best, first)

Программа печатает 6 {0: 0, -1: 1, 1: 3, 2: 4, 3: 5, 4: 6}. Балансы 3, 2 и 1 повторились, но их первые позиции 5, 4 и 3 остались прежними.

Частая ошибка: записывать позицию при каждой встрече. nums = [1, 1, 0, 0, 1, 0], балансы 0, 1, 2, 1, 0, 1, 0. Баланс 0 стоит на позициях 0, 4 и 6. С первой позицией ответ 6 − 0 = 6, весь Array. Если на позиции 4 заменить 0 на 4, то на позиции 6 получится только 6 − 4 = 2, и ответ станет 4.

Время: n шагов, ожидаемое O(n). Дополнительная память: до n + 1 балансов, O(n); здесь 6 ключей. Ответ отдельно: одно число.

list вместо dict

Баланс лежит от −n до n. list из 2n + 1 мест с индексом b + n заменяет dict: O(n) времени в худшем случае и O(n) памяти. Для n = 9 это 19 мест. Место без позиции хранит −1.

4. Есть ли Subarray с нулевой суммой

Codeforces 1915E: Юлия пьёт из нечётных стаканов, её спутник из чётных. Поставим нечётным стаканам знак +, чётным знак −. Равный сок на отрезке [l, r] значит сумму 0 со знаками, то есть повтор префикса.

a = [1, 3, 2]: префиксы 0, 1, −2, 0. Префикс 0 повторился на позициях 0 и 3: YES, стаканы с 1-го по 3-й, 1 + 2 = 3. a = [1, 6, 9, 8, 55, 3, 14, 2, 7, 2]: префиксы 0, 1, −5, 4, −4, 51, 48, 62, 60, 67, 65. Все 11 значений разные: NO.

Проследим set для [1, 3, 2]. Сначала в нём {0}. После 1 префикс 1, его нет, set {0, 1}. После 3 префикс −2, его нет, set {0, 1, −2}. После 2 префикс 0 уже есть: ответ YES, дальше можно не смотреть.

Правило. Два равных префикса на местах i < j значат Subarray с суммой 0 с номера i + 1 по j. Достаточно найти первый повтор.

Здесь не нужны ни число встреч, ни позиции: set хранит только сами префиксы, начиная с 0.

seen = {0}
s = 0
found = False
for i, x in enumerate(a):
    s += x if i % 2 == 0 else -x
    if s in seen:
        found = True
        break
    seen.add(s)

Создавайте новый set для каждого набора. Старый set хранит префиксы прошлого набора и может дать ложный YES.

Время: ожидаемое O(n) на набор. Дополнительная память: O(n) для set. Ответ: одна строка на набор. Brute Force по всем парам l, r стоит O(n²): при n = 2 · 105 это 2 · 1010 пар.

5. Перепишите условие в сумму

Codeforces 1398C: Subarray хороший, если сумма его цифр равна его длине. Вычтите 1 из каждой цифры: у Subarray длины m сумма уменьшится на m. Тогда хороший Subarray имеет сумму 0, и число хороших Subarray равно числу пар равных префиксов.

Строка 120: b = [0, 1, −1], префиксы 0, 0, 1, 0. Значение 0 встречается 3 раза, это 3 · 2 / 2 = 3 пары. Ответ 3, как в условии: [1], [2, 0] и [1, 2, 0].

Строка 11011: b = [0, 0, −1, 0, 0], префиксы 0, 0, 0, −1, −1, −1. Значение 0 встречается 3 раза и даёт 3 пары, значение −1 тоже 3 раза и тоже 3 пары. Ответ 3 + 3 = 6, как во втором наборе примера.

Правило. Для пар равных префиксов прибавляйте cnt[s] до увеличения cnt[s]. Это LeetCode 560 с k = 0 и тот же шаг, что в Number of Good Pairs из лекции Permutations и Combinations, только для префиксов.

cnt = {0: 1}
s = 0
ans = 0
for c in digits:
    s += int(c) - 1
    ans += cnt.get(s, 0)
    cnt[s] = cnt.get(s, 0) + 1

Время: ожидаемое O(n) на набор. Дополнительная память: O(n) для cnt. Ответ: одно число до n(n + 1)/2 = 5 000 050 000 при n = 105. Такое число не помещается в 32-битный тип.

Hash Table: ожидаемый и худший случай

Оценка O(1) для одной операции dict и set ожидаемая: так бывает на обычных входах. Специальные входы могут дать много коллизий, тогда операция стоит дороже. В тестах этого сайта нет входов, которые специально создают коллизии. Если ключи лежат в узком диапазоне, list со сдвигом даёт ту же оценку в худшем случае: в 1398C префиксы лежат от −n до 8n.

6. Что нужно запомнить

  • Subarray с суммой k означает пару префиксов с разностью k.
  • Начинайте с префикса 0: {0: 1} для подсчёта, {0: 0} для первой позиции.
  • Сначала ищите, потом записывайте текущий префикс.
  • Для длины храните первую позицию, для числа Subarray храните число встреч.

7. Как решать задачи этой главы

  1. Перепишите условие как сумму, равную k или 0: замените 0 на −1, вычтите 1, поставьте знаки + и −.
  2. Решите, что хранить для каждого префикса: число встреч, первую позицию или только факт встречи.
  3. Проверьте Subarray, который начинается с первого элемента.
  4. Посчитайте ключи Hash Table и наибольший ответ.
