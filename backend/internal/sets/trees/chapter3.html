Dynamic Programming на Tree хранит для каждой вершины лучший ответ её поддерева, иногда в двух вариантах, и считает вершины в порядке «дети раньше родителя».

1. Состояние вершины

В главе 2 вершина передавала родителю размер или сумму своего поддерева. Теперь она передаёт лучший ответ: наименьший или наибольший. Возьмём Tree T с корнем 0, parent = [-1, 0, 0, 1, 1, 2, 4], и дадим вершинам числа w = [5, 2, 4, 3, 1, 6, 2]. Для каждой вершины v найдём dp[v]: наименьшую сумму w на пути от v вниз до листа.

У листа путь из одной вершины: dp[3] = 3, dp[5] = 6, dp[6] = 2. У вершины 4 один ребёнок 6: dp[4] = 1 + 2 = 3. У вершины 1 дети 3 и 4, оба дают 3: dp[1] = 2 + min(3, 3) = 5. Дальше dp[2] = 4 + 6 = 10 и dp[0] = 5 + min(5, 10) = 10. Это путь 0, 1, 3 с суммой 5 + 2 + 3 = 10.

Правило. Состояние dp[v] описывает только поддерево v. Его считают по состояниям детей, поэтому вершины идут с конца порядка BFS.

dp = [0] * n
for v in reversed(order):
    dp[v] = w[v]
    if children[v]:
        dp[v] += min(dp[c] for c in children[v])

Так устроена задача Codeforces 1900C. Там dp[v] - наименьшее число замен букв на пути от v до листа. У листа dp = 0, а ребёнок добавляет 1, если буква вершины v ведёт не к нему.

Brute Force поднимается от каждого листа к корню и каждый раз считает сумму заново. Подъём от листа на глубине h делает h шагов. Возьмём цепочку из n/2 вершин, у каждой из которых есть ещё один ребёнок-лист. Глубины листьев 1, 2, 3, ..., и шагов около n²/8. Для n = 100 000 это около 1,25 · 109 шагов, а проверка даёт 3 с на скрытый тест.

Время: O(n), одно сравнение на ребро. Дополнительная память: O(n) для dp и порядка.

2. Взять или пропустить вершину

Новая задача на том же T и тех же w. Выберем вершины так, чтобы никакие две выбранные не были соединены ребром, и получим наибольшую сумму w. Одного числа на вершину здесь мало. Если вершина 1 взята, её детей 3 и 4 брать нельзя. Если вершина 1 пропущена, детей брать можно. Лучший ответ поддерева зависит от того, взят ли его корень.

Поэтому у каждой вершины два числа. take[v] - лучшая сумма в поддереве v, если v взята. skip[v] - лучшая сумма, если v пропущена. Сначала take[v] = w[v] и skip[v] = 0: у листа это уже ответ. Взятая вершина прибавляет skip каждого ребёнка. Пропущенная вершина прибавляет лучший из двух вариантов каждого ребёнка.

parent = [-1, 0, 0, 1, 1, 2, 4]
order = [0, 1, 2, 3, 4, 5, 6]
w = [5, 2, 4, 3, 1, 6, 2]
take = w[:]
skip = [0] * len(w)
for v in reversed(order):
    p = parent[v]
    if p != -1:
        take[p] += skip[v]
        skip[p] += max(take[v], skip[v])
print(take)
print(skip)
print(max(take[0], skip[0]))

Код печатает [16, 4, 4, 3, 1, 6, 2], [11, 5, 6, 0, 2, 0, 0] и 16. Рисунок показывает каждый шаг.

Ответ 16 даёт набор вершин {0, 3, 5, 6}: 5 + 3 + 6 + 2 = 16. Ни одно ребро T не соединяет две вершины этого набора.

Правило. Если у вершины два варианта, храните два числа. Взятая вершина разрешает детям только «пропустить», пропущенная берёт лучший вариант каждого ребёнка.

Brute Force проверяет все наборы вершин. Для T их 27 = 128, а для n = 40 уже 240 ≈ 1,1 · 1012.

Время: O(n): 2 прибавления на ребро, здесь 12. Дополнительная память: O(n): два Array по n чисел.

Почему не брать лучшую вершину сразу

Путь 0 − 1 − 2, w = [3, 5, 4]. Если сначала взять самое большое число 5, то соседей 0 и 2 брать нельзя, сумма 5. Два состояния дают take[0] = 3 + skip[1] = 3 + 4 = 7: вершины 0 и 2 не соседи. Выбор по одной вершине не видит, что два меньших числа вместе больше одного большого.

3. Только концы отрезка

В Codeforces 1528A у каждой вершины v есть отрезок [l_v, r_v], и значение a_v можно выбрать любым целым числом из него. Красота Tree - сумма |a_u − a_v| по всем рёбрам. Нужна наибольшая красота.

Сначала числа. У вершины два соседа со значениями 1 и 2, а её значение x можно взять от 4 до 6. При x = 4 сумма 3 + 2 = 5, при x = 5 сумма 4 + 3 = 7, при x = 6 сумма 5 + 4 = 9. Лучше всего конец 6. Середина отрезка никогда не бывает лучше обоих концов, поэтому у вершины только два значения-кандидата: a_v = l_v или a_v = r_v. Это снова два состояния.

Правило. dp[v][0] и dp[v][1] - лучшая сумма в поддереве при a_v = l_v и при a_v = r_v. Если у родителя значение x, ребёнок c добавляет max(dp[c][0] + |x − l_c|, dp[c][1] + |x − r_c|).

Возьмём путь 0 − 1 − 2 с отрезками l = [1, 4, 1], r = [10, 6, 10] и корнем 1. Дети 0 и 2 - листья, у них dp = 0, поэтому каждый ребёнок даёт max(|x − l_c|, |x − r_c|).

l = [1, 4, 1]
r = [10, 6, 10]
best = 0
for x in (l[1], r[1]):
    total = 0
    for c in (0, 2):
        total += max(abs(x - l[c]), abs(x - r[c]))
    print(x, total)
    best = max(best, total)
print(best)

Код печатает «4 12», «6 10» и 12. При a_1 = 4 соседям выгоднее значение 10, при a_1 = 6 выгоднее 1.

Меньший конец 4 оказался лучше большего конца 6. Поэтому нельзя всегда брать r_v: нужны оба состояния.

Время: O(n): 4 вычисления |...| на ребро. Дополнительная память: O(n) для двух Array. Ответ одного набора меньше 105 · 109 = 1014, в Python это обычный int.

Почему середина отрезка не нужна

Каждое слагаемое |x − a| уменьшается, пока x идёт к a, и растёт, когда x уходит от a. У суммы таких слагаемых нет «горба» внутри отрезка: её наибольшее значение стоит на одном из концов. Соседи 1 и 2, x от 4 до 6: суммы 5, 7, 9, лучший правый конец. Соседи 3 и 7, x от 2 до 8: при x = 2 сумма 1 + 5 = 6, при x = 5 сумма 2 + 2 = 4, при x = 8 сумма 5 + 1 = 6. Середина даёт меньше всего, концы больше.

4. Оставить хотя бы одну вершину на каждом пути

В LeetCode 2925 операция забирает значение вершины в счёт и пишет в вершину 0. На каждом пути от корня к листу должно остаться хотя бы одно ненулевое значение. Выгодно оставить как можно меньшую сумму и забрать всё остальное. keep[v] - наименьшая сумма оставленных значений в поддереве v, при которой каждый путь от v вниз до листа что-то сохраняет.

Вариантов два. Оставить саму вершину v: все пути через неё уже защищены, и всё ниже можно забрать. Это стоит w[v]. Или забрать v: тогда каждый ребёнок защищает свои пути сам, это стоит сумму keep детей. У листа выбора нет: keep[v] = w[v].

На T с теми же w: keep[3] = 3, keep[5] = 6, keep[6] = 2, keep[4] = min(1, 2) = 1, keep[1] = min(2, 3 + 1) = 2, keep[2] = min(4, 6) = 4, keep[0] = min(5, 2 + 4) = 5. Сумма всех w равна 23, ответ 23 − 5 = 18.

below = [0] * n
keep = [0] * n
for v in reversed(order):
    keep[v] = w[v] if below[v] == 0 else min(w[v], below[v])
    if parent[v] != -1:
        below[parent[v]] += keep[v]
print(sum(w) - keep[0])

Здесь below[v] - сумма keep детей. Все w не меньше 1, поэтому below[v] = 0 только у листа.

Правило. Минимум из двух вариантов «оставить эту вершину» и «оставить что-то в каждом ребёнке» - это тоже переход Dynamic Programming.

Время: O(n): 6 прибавлений keep детей и 4 сравнения min у вершин с детьми. Дополнительная память: O(n): keep, below и порядок по 7 чисел.

5. Цепочки вниз и путь через вершину

down[v] - число вершин самой длинной цепочки от v вниз. У листа down = 1, иначе down[v] = 1 + наибольший down среди детей. Для T down = [4, 3, 2, 1, 2, 1, 1], самая длинная цепочка от корня: 0, 1, 4, 6.

Теперь самый длинный путь в Tree. У каждого пути есть самая верхняя вершина v. Из неё путь спускается не больше чем к двум разным детям, иначе он бы разветвлялся. Через вершину 0 путь берёт цепочку через ребёнка 1 (down 3) и цепочку через ребёнка 2 (down 2): 1 + 3 + 2 = 6 вершин. Это путь 6, 4, 1, 0, 2, 5 из 5 рёбер. Через вершину 1 проходит только 1 + 2 + 1 = 4 вершины.

Правило. Самый длинный путь проходит через свою самую верхнюю вершину v и спускается не больше чем к двум разным детям. Храните для v два наибольших значения down среди детей: top1 ≥ top2; если ребёнка нет, значение 0.

parent = [-1, 0, 0, 1, 1, 2, 4]
order = [0, 1, 2, 3, 4, 5, 6]
n = len(parent)
down = [1] * n
top1 = [0] * n
top2 = [0] * n
for v in reversed(order):
    down[v] = 1 + top1[v]
    p = parent[v]
    if p != -1:
        if down[v] > top1[p]:
            top1[p], top2[p] = down[v], top1[p]
        elif down[v] > top2[p]:
            top2[p] = down[v]
print(down)
print(max(1 + top1[v] + top2[v] for v in range(n)))

Код печатает [4, 3, 2, 1, 2, 1, 1] и 6.

Новое значение down[v] сравнивают с top1 родителя. Если оно больше, старый top1 переходит в top2. Иначе его сравнивают с top2. Так шаг v = 1 на рисунке сдвинул 2 из top1[0] в top2[0].

В LeetCode 2246 по ребру можно идти, только если буквы его концов разные. Ребёнок c с той же буквой, что у v, не передаёт down родителю, остальной код тот же. В LeetCode 3593 best[v] - наибольшая сумма cost на пути вниз. Каждый ребёнок, у которого best меньше наибольшего best среди детей того же родителя, требует одного увеличения.

Время: O(n): не больше 2 сравнений на ребро. Дополнительная память: O(n) для down, top1 и top2. BFS от каждой вершины дал бы O(n²): 49 посещений для T, 1010 для n = 100 000.

6. Что нужно запомнить

  • Состояние вершины - ответ для её поддерева; у листа его задают сразу.
  • Два варианта вершины - два числа: взять и пропустить, левый и правый конец.
  • Путь через вершину складывают из двух самых длинных цепочек разных детей.

7. Как решать задачи этой главы

  1. Опишите словами, что знает состояние о поддереве.
  2. Если у вершины несколько вариантов, заведите число на каждый вариант.
  3. Запишите значение у листа и переход от детей к родителю.
  4. Пройдите порядок BFS с конца; ответ возьмите у корня или как максимум по всем вершинам.
