Размер, сумма и любой другой счётчик поддерева складываются из ответов детей, и один проход по порядку BFS с конца считает их для всех вершин за O(n).

1. Поддерево и его размер

Возьмём Tree T из главы 1 с корнем 0: parent = [-1, 0, 0, 1, 1, 2, 4]. Поддерево вершины v - это сама v, её дети, дети детей и так дальше до самого низа. Поддерево вершины 1 - это вершины 1, 3, 4 и 6, его размер 4. Поддерево вершины 3 - только сама вершина 3, размер 1. Поддерево корня - всё Tree, размер 7.

Размеры всех поддеревьев T: size = [7, 4, 2, 1, 2, 1, 1]. Посмотрите на вершину 1. Её дети 3 и 4 имеют размеры 1 и 2, и size[1] = 1 + 1 + 2 = 4: единица - сама вершина 1, остальное дают поддеревья детей.

Правило. size[v] = 1 + сумма size[c] по всем детям c. Ответ вершины готов, когда готовы ответы всех её детей.

Brute Force делает отдельный обход для каждой вершины. Обход поддерева v посещает size[v] вершин, поэтому для T он сделает 7 + 4 + 2 + 1 + 2 + 1 + 1 = 18 посещений. На пути из n вершин с корнем на конце размеры равны n, n − 1, ..., 1, и посещений n(n + 1)/2. Для n = 100 000 это 5 000 050 000 посещений, а проверка даёт 3 с на скрытый тест.

Время: O(n²) для Brute Force на пути. Дополнительная память: O(n) для обхода одного поддерева.

2. Порядок BFS с конца

В порядке BFS родитель стоит раньше своих детей. Для T глава 1 дала порядок [0, 1, 2, 3, 4, 5, 6]. Пройдём этот порядок с конца. Тогда каждый ребёнок идёт раньше своего родителя. Когда проход доходит до вершины v, все её дети уже прошли, и size[v] готов. Остаётся прибавить size[v] к size[parent[v]].

parent = [-1, 0, 0, 1, 1, 2, 4]
order = [0, 1, 2, 3, 4, 5, 6]
size = [1] * len(parent)
for v in reversed(order):
    if parent[v] != -1:
        size[parent[v]] += size[v]
print(size)

Код печатает [7, 4, 2, 1, 2, 1, 1]. Рисунок показывает каждый шаг.

Вершина 4 передаёт свой размер вершине 1 только после шага v = 6, поэтому size[4] = 2 уже верный. Каждое ребро между parent[v] и v даёт одно прибавление: 6 прибавлений для 6 рёбер.

Время: O(n): 6 прибавлений, по одному на ребро. Дополнительная память: O(n): size и order по 7 чисел.

Иногда номера уже дают нужный порядок. В Codeforces 1676G родитель вершины i имеет меньший номер: a_i < i. Возьмём a = [1, 1, 2] для вершин 2, 3 и 4: родитель вершин 2 и 3 - вершина 1, родитель вершины 4 - вершина 2. Порядок 1, 2, 3, 4 уже «родитель раньше детей», и BFS не нужен. Идём i = 4, 3, 2: сначала size[2] = 1 + 1 = 2, потом size[1] = 1 + 1 = 2 и size[1] = 2 + 2 = 4.

Правило. Пройдите порядок «родитель раньше детей» с конца и прибавьте ответ вершины к ответу родителя. Подходит порядок BFS, порядок DFS со Stack и номера, у которых родитель меньше ребёнка.

Recursion для размеров

Ту же формулу можно записать через Recursion:

def subtree_size(v):
    return 1 + sum(subtree_size(c) for c in children[v])

Для T это работает. На пути из 4000 вершин глубина вызовов 4000. С пределом по умолчанию около 1000 код падает с RecursionError, а глава 1 показала, что Recursion внутри sum падает и с поднятым пределом. У прохода с конца порядка нет предела глубины.

3. От рёбер к суммам поддеревьев

Часто вход - список рёбер. Тогда сначала строим список соседей и порядок BFS, как в главе 1. В Python BFS можно написать без Deque: цикл for v in order: читает list, а order.append(u) добавляет вершину в его конец. Цикл for по list доходит и до элементов, которые добавили во время цикла. Каждая вершина попадает в order один раз.

У каждой вершины T есть число: values = [2, 1, 4, 3, 5, 2, 1]. Сумма поддерева считается так же, как размер, только вместо 1 берём values[v].

n = 7
edges = [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5], [4, 6]]
values = [2, 1, 4, 3, 5, 2, 1]
k = 3
adj = [[] for _ in range(n)]
for a, b in edges:
    adj[a].append(b)
    adj[b].append(a)
parent = [-1] * n
order = [0]
for v in order:
    for u in adj[v]:
        if u != parent[v]:
            parent[u] = v
            order.append(u)
total = values[:]
for v in reversed(order):
    if parent[v] != -1:
        total[parent[v]] += total[v]
print(total)
print(sum(1 for s in total if s % k == 0))

Код печатает [18, 10, 6, 3, 6, 2, 1] и 4. Сумма поддерева 1 равна 1 + 3 + 6 = 10: своё число 1, сумма вершины 3 и сумма вершины 4, то есть 5 + 1 = 6.

Правило. Сумма поддерева v равна values[v] плюс суммы детей. Ребро над v делит Tree на поддерево v и остальную часть.

На 3 делятся суммы вершин 0, 2, 3 и 4. Разрежем рёбра над 2, 3 и 4. Получатся части {3} с суммой 3, {4, 6} с суммой 6, {2, 5} с суммой 6 и остаток {0, 1} с суммой 18 − 3 − 6 − 6 = 3. Каждая часть делится на 3, частей 4. Это задача LeetCode 2872. Если сумма поддерева v делится на k, то после разреза ребра над v остальная часть тоже делится на k: от общей суммы, которая делится на k, отняли число, которое делится на k.

Время: O(n): 12 чтений соседей в BFS и 6 прибавлений. Дополнительная память: O(n): adj, parent, order и total.

4. Что остаётся без вершины

Удалим из T вершину 1 вместе с её тремя рёбрами. Останутся три части: {3} с размером 1, {4, 6} с размером 2 и верхняя часть {0, 2, 5}. Размер верхней части не нужно считать новым обходом. Это все вершины, кроме поддерева 1: 7 − size[1] = 7 − 4 = 3. Произведение размеров 1 · 2 · 3 = 6 - оценка вершины 1 в LeetCode 2049.

Правило. Без вершины v остаются поддеревья её детей и верхняя часть из n − size[v] вершин. У корня верхней части нет.

score = max(n - size[v], 1)
for c in children[v]:
    score *= size[c]

У корня n − size[0] = 0, а пустая часть в произведение не входит, поэтому max(..., 1). Для корня T остаются части 4 и 2, оценка 8. Если удалить только ребро над v, частей две: size[v] и n − size[v]. Для ребра над вершиной 1 это 4 и 3.

Время: после размеров O(число детей) для одной вершины и O(n) для всех: каждая вершина - ребёнок только одного родителя. Дополнительная память: O(1) сверх size.

5. Перевозка по рёбрам

В LeetCode 2477 из каждого города в столицу 0 едет один представитель. По ребру над вершиной v едут все люди её поддерева: size[v] человек. В машине seats мест, поэтому им нужно size[v] / seats машин с округлением вверх. Например, 5 человек при seats = 2 займут 3 машины. В Python это (size[v] + seats - 1) // seats. Каждая машина тратит 1 литр на одно ребро.

Возьмём T и seats = 2. Размеры вершин 1, 2, 3, 4, 5, 6 равны 4, 2, 1, 2, 1, 1. Машин над ними 2, 1, 1, 1, 1, 1, всего 7 литров. При seats = 1 машин столько же, сколько людей: 4 + 2 + 1 + 2 + 1 + 1 = 11 литров. Это сумма глубин 0 + 1 + 1 + 2 + 2 + 2 + 3 = 11: каждый человек проезжает столько рёбер, какова его глубина.

Меньше машин над ребром не бывает: по нему едут все size[v] человек поддерева. И столько машин хватает: люди садятся вместе, когда встречаются в общей вершине.

Правило. Если ответ складывается по рёбрам, посчитайте вклад ребра над каждой вершиной по данным её поддерева.

size = [1] * n
fuel = 0
for v in reversed(order):
    if parent[v] != -1:
        fuel += (size[v] + seats - 1) // seats
        size[parent[v]] += size[v]

Время: O(n), одно деление на ребро. Дополнительная память: O(n). На пути из n вершин при seats = 1 ответ n(n − 1)/2: для n = 100 000 это 4 999 950 000, в Python обычный int.

6. Другие счётчики: листья и цвета

Лист Tree с корнем - вершина без детей. У T листья 3, 5 и 6. Корень Tree с n ≥ 2 имеет ребёнка, поэтому он не лист, даже если у него одно ребро. Например, в пути 1 − 2 − 3 с корнем 1 лист только один: вершина 3.

Число листьев в поддереве: leaves[v] = 1 у листа, иначе сумма leaves детей. Для T leaves = [3, 2, 1, 1, 1, 1, 1]. В Codeforces 1843D яблоко из вершины x спускается по детям, пока не дойдёт до листа. Оно может упасть из любого листа поддерева x. Поэтому ответ на запрос x, y равен leaves[x] · leaves[y]. Для вершин 0 и 1 в T это 3 · 2 = 6.

leaves = [0] * n
for v in reversed(order):
    if leaves[v] == 0:
        leaves[v] = 1
    if parent[v] != -1:
        leaves[parent[v]] += leaves[v]

Цвета (Codeforces 1676G). Дадим белой вершине W число +1, а чёрной вершине B число −1. Сумма поддерева равна разности числа белых и чёрных вершин. Например, путь W − B − W: поддерево корня даёт +1 − 1 + 1 = 1, а поддерево средней вершины даёт −1 + 1 = 0. Поддерево с суммой 0 сбалансировано: белых и чёрных вершин поровну.

Правило. Любой счётчик, который складывается по детям, считается тем же проходом: размер, сумма, число листьев, разность цветов.

Время: O(n), как в разделе 2: одно прибавление на ребро. Дополнительная память: O(n) для счётчика и порядка.

7. Что нужно запомнить

  • Порядок BFS с конца: дети раньше родителя.
  • size[v] и n − size[v] - две части Tree без ребра над v.
  • Один проход: O(n) времени и O(n) памяти; отдельный обход каждого поддерева: O(n²).

8. Как решать задачи этой главы

  1. Найдите величину, которая складывается из ответов детей.
  2. Получите порядок «родитель раньше детей»: BFS, DFS со Stack или номера с a_i < i.
  3. Пройдите порядок с конца и передайте ответ вершины родителю.
  4. Посчитайте ответ задачи по size, n − size или суммам и проверьте, насколько большие числа получаются.
