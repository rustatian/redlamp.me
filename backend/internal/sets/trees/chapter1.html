В Tree из n вершин n − 1 рёбер и нет циклов, поэтому один обход от корня за O(n) даёт родителя и глубину каждой вершины без Recursion.

1. Вершины, рёбра и степени

Возьмём Tree T из n = 7 вершин с номерами от 0 до 6. Его 6 рёбер: edges = [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5], [4, 6]]. Ребро соединяет две вершины. Путь от 3 до 5 идёт так: 3, 1, 0, 2, 5. Другого пути нет, потому что в Tree нет циклов, то есть замкнутых путей.

Степень вершины - это число рёбер у этой вершины. У вершины 1 три ребра: к 0, 3 и 4. Все степени T: [2, 3, 2, 1, 2, 1, 1]. Их сумма 12 = 2 · 6.

Правило. В Tree из n вершин ровно n − 1 рёбер и нет циклов, а из каждой вершины можно дойти до любой другой. Между двумя вершинами ровно один путь. Сумма степеней равна 2(n − 1): каждое ребро добавляет 1 обоим концам.

Почему рёбер n − 1. Начнём с вершины 0 и будем добавлять по одной вершине вместе с ребром к уже построенной части: 1 к 0, 2 к 0, 3 к 1, 4 к 1, 5 к 2, 6 к 4. Каждое ребро добавляет одну вершину, поэтому 7 вершин дают 6 рёбер. Ещё одно ребро, например (3, 5), создало бы второй путь от 3 до 5, то есть цикл 3, 1, 0, 2, 5, 3.

Звезда (LeetCode 1791): одна вершина-центр соединена со всеми остальными. Степень центра n − 1, у других вершин степень 1. Центр входит в каждое ребро, поэтому центр - общая вершина первых двух рёбер. Для [[1, 2], [2, 3], [4, 2]] это 2: она есть и в [1, 2], и в [2, 3].

Время: O(n) для подсчёта степеней: n − 1 рёбер и 2(n − 1) прибавлений, здесь 12. Дополнительная память: O(n), n счётчиков. Проверка первых двух рёбер звезды: O(1) времени и памяти.

2. Список соседей

Обход идёт от вершины к её соседям, поэтому для каждой вершины нужен список соседей. Ребро (a, b) записывает b в список вершины a и a в список вершины b.

n = 7
edges = [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5], [4, 6]]
adj = [[] for _ in range(n)]
for a, b in edges:
    adj[a].append(b)
    adj[b].append(a)
print(adj)

Код печатает [[1, 2], [0, 3, 4], [0, 5], [1], [1, 6], [2], [4]]. Список adj[0] = [1, 2]: у вершины 0 соседи 1 и 2. Список adj[1] = [0, 3, 4]: ребро (0, 1) записало 0, рёбра (1, 3) и (1, 4) записали 3 и 4. У вершины 3 один сосед 1. Длина adj[v] равна степени v, поэтому все списки вместе хранят 12 записей.

Правило. Для каждого ребра (a, b) добавьте b в adj[a] и a в adj[b]. Список соседей хранит 2(n − 1) записей.

Время: O(n): 6 рёбер и 12 вызовов append. Дополнительная память: O(n): 7 list и 12 записей; вход edges не считаем.

Почему не таблица n × n

Можно хранить таблицу g, где g[a][b] = 1, если есть ребро (a, b). Для n = 100 000 в такой таблице 1010 клеток. Даже по одному байту на клетку это 10 ГБ. Ребро есть только в 2(n − 1) ≈ 200 000 клетках, остальные хранят 0. Список соседей хранит только эти 200 000 записей.

3. Корень, родитель и глубина

Выберем корень 0 и нарисуем T от него вниз. Сосед вершины, который ближе к корню, - её родитель. Остальные соседи - её дети. Для T parent = [-1, 0, 0, 1, 1, 2, 4]: у корня родителя нет, поэтому там −1. Дети вершины 1: 3 и 4.

Глубина вершины - число рёбер от неё до корня: depth = [0, 1, 1, 2, 2, 2, 3]. Подъём от 6 идёт так: 6 → 4 → 1 → 0. Это 3 шага, и depth[6] = 3.

Вход задачи может сразу быть Array родителей: manager в LeetCode 1376, parents в LeetCode 2049, parent в LeetCode 2246. Списки детей получаем одним проходом:

parent = [-1, 0, 0, 1, 1, 2, 4]
children = [[] for _ in parent]
for v, p in enumerate(parent):
    if p != -1:
        children[p].append(v)
print(children)

Код печатает [[1, 2], [3, 4], [5], [], [6], [], []]. У вершин 3, 5 и 6 детей нет. Списки детей хранят 6 записей, а не 12: ребро к родителю в них не входит.

Правило. У каждой вершины, кроме корня, ровно один родитель. Array родителей описывает Tree полностью: n − 1 чисел и −1 у корня. Глубина вершины равна числу шагов вверх до корня.

В наборе «Heap (Priority Queue), Queue и Deque» у места i дети 2i + 1 и 2i + 2: это Tree, где родителя даёт формула, а не Array.

Время: O(n) для списков детей, здесь 6 append. Дополнительная память: O(n): 7 list и 6 записей. Подъём от одной вершины к корню делает depth шагов. Подъём от каждой вершины пути из n вершин делает 0 + 1 + ... + (n − 1) шагов: O(n²). Для n = 100 000 это 4 999 950 000 шагов.

4. BFS от корня

BFS берёт вершины из Deque в порядке прихода. Сначала он находит соседей корня, затем вершины глубины 2, и так дальше. Каждая новая вершина получает родителя и глубину на 1 больше.

from collections import deque

adj = [[1, 2], [0, 3, 4], [0, 5], [1], [1, 6], [2], [4]]
n = len(adj)
parent = [-1] * n
depth = [0] * n
order = []
q = deque([0])
while q:
    v = q.popleft()
    order.append(v)
    for u in adj[v]:
        if u != parent[v]:
            parent[u] = v
            depth[u] = depth[v] + 1
            q.append(u)
print(order)
print(parent)
print(depth)

Код печатает порядок [0, 1, 2, 3, 4, 5, 6], затем parent и depth из раздела 3. Рисунок показывает каждый вызов popleft.

Правило. В Tree у вершины v уже найден только один сосед: её родитель. Поэтому проверка u != parent[v] заменяет Array посещённых вершин.

В порядке BFS родитель стоит раньше детей, и глубина не убывает: 0, 1, 1, 2, 2, 2, 3. В главе 2 мы пройдём этот порядок с конца.

Чётность глубины. Каждое ребро соединяет глубины d и d + 1. Поэтому вершины чётной глубины и вершины нечётной глубины образуют две группы, и каждое ребро соединяет эти группы. У T чётные {0, 3, 4, 5}, нечётные {1, 2, 6}.

Дороги с направлением (LeetCode 1466). Для дороги a → b запишите (b, 1) в adj[a] и (a, 0) в adj[b]. BFS от 0 складывает флаги рёбер к детям: флаг 1 значит, что дорога ведёт от 0. В первом примере задачи ответ 3.

Почему проверка родителя работает только в Tree

Возьмём Graph с циклом: рёбра (0, 1), (1, 2), (2, 0). BFS от 0 добавит 1 и 2. У вершины 1 сосед 0 - её родитель, а сосед 2 не родитель. Поэтому 2 войдёт в Deque второй раз, уже с родителем 1. Дальше вершины входят снова и снова, и цикл while не заканчивается. Для Graph с циклами нужен Array посещённых вершин seen: вершина входит в Deque, только если seen[u] ещё False.

Deque и popleft за O(1) разобраны в главе «Queue и Deque» набора «Heap (Priority Queue), Queue и Deque».

Время: O(n): вершина 0 входит в Deque при создании, ещё 6 append и 7 popleft, 12 чтений списка соседей. Дополнительная память: O(n): parent, depth и order по 7 чисел; в Deque одновременно не больше 3 вершин.

5. Recursion и предел глубины

Тот же обход можно написать через Recursion:

def dfs(v, p):
    for u in adj[v]:
        if u != p:
            dfs(u, v)

Как вызовы ждут в Call Stack, показано в наборе «Permutations и Combinations», глава 2, раздел «Recursion и Call Stack». Здесь важно одно: число вложенных вызовов равно глубине Tree. Для пути 0 − 1 − ... − 99 999 вызов dfs(0, -1) ждёт вызова для 1, тот ждёт вызова для 2, и так 100 000 вложенных вызовов.

По умолчанию Python разрешает около 1000 вложенных вызовов, и проверка запускает код с этим пределом. sys.setrecursionlimit поднимает предел. Но Recursion внутри sum(...) или другой встроенной функции падает и с большим пределом, а в браузере такая ошибка останавливает Python целиком. У цикла нет предела глубины. Проверка в браузере даёт 2 с на пример, 3 с на скрытый тест.

Правило. Если n может быть больше 1000, обходите Tree циклом: BFS с Deque или DFS со Stack. Recursion оставьте для маленьких примеров.

Время: O(n) для Recursion. Дополнительная память: O(h) вызовов, где h - высота Tree, то есть наибольшая глубина вершины. На пути h = n − 1.

Recursion с setrecursionlimit

С sys.setrecursionlimit(200000) фрагмент выше проходит путь из 105 вершин: CPython и Python в браузере (Pyodide) дошли до конца. Но такой код падает на той же глубине даже с поднятым пределом:

def subtree_size(v):
    return 1 + sum(subtree_size(c) for c in children[v])

Здесь каждый вызов идёт через sum и генератор. CPython даёт RecursionError, а Pyodide останавливается с фатальной ошибкой. Циклу эти пределы не мешают.

6. DFS со Stack

Замените Deque на list, а popleft() на pop(). Получится DFS со Stack:

adj = [[1, 2], [0, 3, 4], [0, 5], [1], [1, 6], [2], [4]]
parent = [-1] * len(adj)
order = []
stack = [0]
while stack:
    v = stack.pop()
    order.append(v)
    for u in adj[v]:
        if u != parent[v]:
            parent[u] = v
            stack.append(u)
print(order)

Код печатает [0, 2, 5, 1, 4, 6, 3]. pop() берёт последнюю добавленную вершину, поэтому DFS идёт вглубь: 0, 2, 5, затем 1, 4, 6, 3. Порядок другой, чем у BFS, но родитель всё равно стоит раньше детей. Строка depth[u] = depth[v] + 1 работает и здесь.

Правило. Stack заменяет Call Stack: снимите вершину, добавьте её детей. Каждая вершина входит в Stack один раз.

Время: O(n): 6 append и 7 pop у Stack, 12 чтений соседей. Дополнительная память: O(n); здесь в Stack не больше 2 вершин. На пути от конца в Stack всегда 1 вершина, а у звезды из n вершин после центра в Stack n − 1 вершин.

7. Что нужно запомнить

  • n вершин, n − 1 рёбер, один путь между двумя вершинами.
  • Список соседей: 2(n − 1) записей и O(n) памяти.
  • BFS и DFS со Stack дают parent, depth и порядок «родитель раньше детей» за O(n).
  • С пределом по умолчанию Recursion глубже примерно 1000 вызовов падает: обходите Tree циклом.
