Число Combinations быстро становится огромным, поэтому задачи просят остаток по модулю 109 + 7, а его дают Pascal's Triangle и таблицы Factorial.

В главе 1 мы считали C(n, k) точно. Здесь берём остатки из лекции Modular Arithmetic: сумму и произведение по модулю из главы 1, pow из главы 2 и таблицы fact и inv_fact из главы 3. Дополнительная память, как и раньше, не включает вход и ответ.

1. Pascal's Triangle по модулю

Строки от 0 до 5: 1; 1 1; 1 2 1; 1 3 3 1; 1 4 6 4 1; 1 5 10 10 5 1. Каждое внутреннее число равно сумме двух чисел над ним: C(n, k) = C(n − 1, k − 1) + C(n − 1, k). Например, в строке 5 число 10 = 4 + 6.

Теперь возьмём остатки от деления на 7. Строка 5 даёт 1 5 3 3 5 1: число 10 даёт остаток 3. Строка 6 даёт 1 6 1 6 1 6 1, а строка 7 даёт 1 0 0 0 0 0 0 1. Складывать можно сами остатки: 5 + 3 = 8 даёт остаток 1, и C(6, 2) = 15 тоже даёт остаток 1.

Правило. C(n, k) % M = (C(n − 1, k − 1) % M + C(n − 1, k) % M) % M. Берите % после каждого сложения, тогда все числа меньше M.

M = 7
row = [1]
for n in range(1, 8):
    row = [1] + [(row[k - 1] + row[k]) % M for k in range(1, n)] + [1]
print(row)

Код выводит [1, 0, 0, 0, 0, 0, 0, 1]: это строка 7. Все внутренние C(7, k) делятся на 7.

Та же сумма есть в LeetCode 3179. Array [1, 1, 1, 1] после одной секунды становится [1, 2, 3, 4], после двух [1, 3, 6, 10]. Каждое новое число равно сумме соседа слева и числа выше, как в Pascal's Triangle: это Prefix Sum строки.

Маленькую таблицу полезно выписать и тогда, когда формула в задаче другая. По таблице для n до 6 легко увидеть закономерность, а потом проверить её на примере условия.

Время: строки от 0 до N требуют около N²/2 сложений: O(N²). Для N = 7 это 21 сложение, для N = 1000 около 500 000, для N = 105 около 5 · 109: при 3 с на скрытый тест это слишком много. Дополнительная память: O(N) для одной строки, O(N²) для всей таблицы.

2. C(n, k) через таблицы Factorial

В главе 1 была формула C(n, k) = n! / (k! · (n − k)!). Возьмём таблицы по модулю 7 из главы 3 лекции Modular Arithmetic: fact = [1, 1, 2, 6, 3, 1, 6] и inv_fact = [1, 1, 4, 6, 5, 1, 6]. Для C(5, 2) нужны fact[5] = 1, inv_fact[2] = 4 и inv_fact[3] = 6. Произведение 1 · 4 · 6 = 24 даёт остаток 3, и C(5, 2) = 10 тоже даёт остаток 3.

Деление на k! и (n − k)! заменили умножением на inv_fact[k] и inv_fact[n − k]. Тот же код по модулю 109 + 7:

M = 10**9 + 7
N = 10
fact = [1] * (N + 1)
for i in range(1, N + 1):
    fact[i] = fact[i - 1] * i % M
inv_fact = [1] * (N + 1)
inv_fact[N] = pow(fact[N], M - 2, M)
for i in range(N, 0, -1):
    inv_fact[i - 1] = inv_fact[i] * i % M

def C(n, k):
    if k < 0 or k > n:
        return 0
    return fact[n] * inv_fact[k] % M * inv_fact[n - k] % M

print(C(5, 2), C(10, 3), C(10, 7), C(3, 5))

Код выводит 10 120 120 0. C(10, 7) = C(10, 3): выбрать 7 чисел из 10 значит выбрать 3 оставшихся. При k > n способов нет, и функция возвращает 0.

Правило. C(n, k) = fact[n] · inv_fact[k] · inv_fact[n − k] % M при 0 ≤ k ≤ n, иначе 0. Таблицы строят один раз до наибольшего n задачи.

Время: O(N + log M) на таблицы и O(1) на каждое C(n, k). Дополнительная память: O(N) для двух таблиц.

Размер таблиц задаёт самое большое n, которое встретится в C(n, k). Например, для C(n + k − 1, k) при n, k ≤ 1000 таблицы строят до 1999.

Почему нельзя fact[n] // (fact[k] · fact[n − k])

По модулю 7 fact[5] = 1, а fact[2] · fact[3] = 2 · 6 = 12. Тогда 1 // 12 = 0, но C(5, 2) % 7 = 3. Остатки не делятся нацело, поэтому делитель заменяют обратным элементом.

3. Stars and Bars

5 одинаковых конфет делят между 3 детьми, кому-то можно дать 0. Запишем раздачу звёздами и палочками: ★★|★|★★ значит 2, 1, 2. Палочки отделяют долю одного ребёнка от доли следующего. В записи 7 мест: 5 звёзд и 2 палочки. Выбираем 2 места для палочек: C(7, 2) = 21.

Проверим на маленьких числах: 3 конфеты, 2 ребёнка. Раздачи (0, 3), (1, 2), (2, 1), (3, 0) дают 4 способа. По записи 3 звезды и 1 палочка занимают 4 места: C(4, 1) = 4.

Stars and Bars. n одинаковых предметов по k разным группам, пустые группы можно: C(n + k − 1, k − 1). Если в каждой группе хотя бы один предмет: C(n − 1, k − 1).

Вторая формула следует из первой. Пусть каждый из 3 детей получает хотя бы одну конфету из 5. Сначала дайте каждому по конфете. Остаются 2 конфеты без ограничений: C(2 + 3 − 1, 2) = C(4, 2) = 6, и это C(5 − 1, 3 − 1).

Та же модель считает неубывающие последовательности. Длина L, значения от 1 до v: C(v + L − 1, L) последовательностей. При L = 2 и v = 3 это 11, 12, 13, 22, 23, 33: 6 последовательностей, и C(4, 2) = 6. Последовательность задаёт, сколько раз взяли каждое значение: L предметов по v группам, C(L + v − 1, v − 1) = C(v + L − 1, L). Например, 13 значит: значение 1 взяли один раз, 2 ни разу, 3 один раз.

Ту же формулу даёт сдвиг. Прибавьте к i-му числу последовательности i − 1: 11 станет 12, 13 станет 14, 33 станет 34. Числа стали разными, от 1 до v + L − 1 = 4. Значит, последовательностей столько же, сколько способов выбрать L разных чисел из v + L − 1: C(4, 2) = 6. Сдвиг помогает, когда соседние значения могут совпадать.

Время: O(n + k + log M) на таблицы до n + k и O(1) на ответ. Дополнительная память: O(n + k). Brute Force посещает все C(n + k − 1, k − 1) раскладок: для 5 конфет и 3 детей 21, для 100 конфет и 10 детей больше 4 · 1012.

4. Пути на прямой

Из 0 нужно попасть в 2 за 4 шага, каждый шаг на 1 влево или вправо. Пусть r шагов вправо и 4 − r влево. Тогда r − (4 − r) = 2, и r = 3. Остаётся выбрать место одного шага влево: C(4, 1) = 4 способа. Это пути RRRL, RRLR, RLRR и LRRR, где R - шаг вправо, L - шаг влево.

За 3 шага в 2 не попасть. Каждый шаг меняет чётность позиции, и после 3 шагов из 0 позиция нечётная.

Рисунок показывает и Dynamic Programming: число путей в позицию p после шага s равно сумме чисел в позициях p − 1 и p + 1 после шага s − 1. Строки рисунка совпадают со строками Pascal's Triangle, только между числами стоят пустые клетки.

Правило. Пусть d = |конец − начало|: путь влево считают так же, как путь вправо. Путь из k шагов на 1 влево или вправо имеет r = (k + d)/2 шагов в сторону конца. Если d > k или k − d нечётно, путей нет. Иначе путей C(k, r).

from math import comb

M = 10**9 + 7

def ways(d, k):
    d = abs(d)
    if d > k or (k - d) % 2 == 1:
        return 0
    return comb(k, (k + d) // 2) % M

print(ways(2, 4), ways(2, 3), ways(0, 4))

Код выводит 4 0 6: в ту же позицию за 4 шага ведут C(4, 2) = 6 путей. math.comb удобна для одного ответа. Для многих запросов используйте таблицы из раздела 2.

Так же считают пути в сетке из главы 4. Число путей в сетке m × n по модулю M равно C(m + n − 2, m − 1) % M: из m + n − 2 шагов выбирают m − 1 шагов вниз.

Время: O(k + log M) с таблицами до k; Dynamic Programming по шагам и позициям стоит O(k²). Дополнительная память: O(k). Brute Force проверяет 2k путей: при k = 1000 это число из 302 цифр.

5. Раскраски с заданным числом смен

3 флажка, 3 цвета, ровно 1 раз соседние флажки разного цвета. Место смены выбираем из 2 промежутков: C(2, 1) = 2. Первый флажок можно покрасить в 3 цвета, флажок после смены в 2 других цвета. Product Rule даёт 2 · 3 · 2 = 12 раскрасок.

Проверим перечислением с цветами A, B и C. Смена после первого флажка: ABB, ACC, BAA, BCC, CAA, CBB. Смена после второго: AAB, AAC, BBA, BBC, CCA, CCB. Всего 12.

Правило. Ряд из n мест, m цветов, ровно k смен цвета: C(n − 1, k) · m · (m − 1)k. Product Rule соединяет выбор мест и выбор цветов.

ans = C(n - 1, k) * m % M * pow(m - 1, k, M) % M

Проверим край: при m = 1 и k = 0 pow(0, 0, M) = 1, и ответ 1: все места одного цвета. При m = 1 и k ≥ 1 pow(0, k, M) = 0: сменить цвет нельзя.

Время: O(n + log M): таблицы до n и одна pow. Дополнительная память: O(n). Dynamic Programming по местам и числу смен стоит O(nk) времени.

6. Что нужно запомнить

  • Pascal's Triangle по модулю: % после каждого сложения, O(N²) для всех строк до N.
  • Для C(n, k) с большим n стройте fact и inv_fact один раз.
  • Stars and Bars: C(n + k − 1, k − 1) для n одинаковых предметов в k групп.
  • Пути из шагов на 1: сначала проверьте чётность, затем C(k, (k + d)/2).
