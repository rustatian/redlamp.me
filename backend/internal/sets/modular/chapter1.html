Остаток от деления заменяет огромное число маленьким и сохраняет нужный ответ: делится ли число на m и какая у него последняя цифра.

1. Остаток от деления

17 конфет делим поровну на 5 детей. Каждый получает 3 конфеты, и 2 конфеты остаются: 17 = 5 · 3 + 2. В Python частное 17 // 5 равно 3, а остаток 17 % 5 равен 2. Ещё два примера: 20 % 5 равно 0, потому что 20 делится на 5, а 3 % 5 равно 3, потому что 3 = 5 · 0 + 3.

Теперь отрицательное число: −7 = 3 · (−3) + 2. Python округляет частное вниз, поэтому -7 // 3 равно −3, а -7 % 3 равно 2. C++ и Java для тех же чисел дают частное −2 и остаток −1.

Правило. Для m > 0 Python даёт частное q = a // m, округлённое вниз, и остаток r = a % m от 0 до m − 1. Всегда a = m · q + r. Число a делится на m, если a % m == 0.

print(17 % 5, 17 // 5)
print(-7 % 3, -7 // 3)

Код выводит 2 3 и 2 -3. Чётность тоже проверяют остатком: число чётное, если a % 2 == 0. Для −4 остаток 0, для −3 остаток 1.

Время: одна операция % или // с числами из ограничений задач стоит O(1). Для числа из d цифр Python делает O(d) работы. Дополнительная память: O(1).

Почему в C++ остаток бывает отрицательным

C++ и Java округляют частное к нулю: −7 / 3 = −2. Тогда −7 = 3 · (−2) − 1, и остаток равен −1. Поэтому там пишут ((a % m) + m) % m. В Python так писать не нужно: -1 % 3 равно 2. Делимость не зависит от знака: -6 % 3 равно 0.

2. Остаток суммы и произведения

Последняя цифра числа - это его остаток от деления на 10. Сложим 38 + 47 = 85: последняя цифра 5. По последним цифрам 8 + 7 = 15, тоже 5. Умножим 38 · 47 = 1786: последняя цифра 6. По последним цифрам 8 · 7 = 56, тоже 6. Разность: 23 − 18 = 5, и по последним цифрам (3 - 8) % 10 = -5 % 10 = 5.

Правило. (a + b) % m = (a % m + b % m) % m, (a − b) % m = (a % m − b % m) % m, (a · b) % m = (a % m) · (b % m) % m. Поэтому % можно брать после каждого шага, и числа остаются меньше m.

Последняя цифра произведения четырёх чисел:

nums = [38, 47, 59, 123]
r = 1
for x in nums:
    r = r * x % 10
print(r)

r принимает значения 8, 6, 4, 2, и код выводит 2. Полное произведение 12 961 002 тоже кончается на 2. Без % после каждого шага r хранит всё произведение: для 105 чисел до 109 в нём около 900 000 цифр.

Двоичное число растёт по одному биту справа. После нового бита число x становится 2x + bit. Для битов [1, 0, 1, 0] получаем x = 1, 2, 5, 10. Остатки от деления на 5 можно считать без x: r = (2r + bit) % 5 даёт 1, 2, 0, 0. Это идея LeetCode 1018.

nums = [1, 0, 1, 0]
r = 0
out = []
for bit in nums:
    r = (2 * r + bit) % 5
    out.append(r == 0)
print(out)

Код выводит [False, False, True, True]: числа 5 и 10 делятся на 5.

Время: n шагов; в каждом умножение, сложение и % с числами меньше 10: O(n). Дополнительная память: O(1) для r; ответ LeetCode 1018 - n значений bool, O(n). Без % число x после n битов имеет n двоичных цифр. Тогда каждый шаг стоит O(n) работы с цифрами, всего O(n²). При n = 105 это число из 100 000 двоичных цифр.

Отрицательные числа тоже входят в классы: -1 % 3 равно 2, -3 % 3 равно 0, -5 % 3 равно 1. Разность двух чисел одного класса делится на 3: 14 − 5 = 9, и у 14 и 5 один остаток 2.

Правило. Числа с одним остатком от деления на m образуют класс остатков. Разность a − b делится на m, если a % m == b % m. Сумма a + b делится на m, если b % m == (−a) % m.

Счётчик классов: cnt = [0] * m, затем cnt[x % m] += 1 для каждого x. Для a = [7, 1, 3, 4, 2] и m = 3 остатки 1, 1, 0, 1, 2, поэтому cnt = [1, 3, 1]. Ход +1 переводит число в следующий класс: 2 + 1 = 3, и число переходит из класса 2 в класс 0.

Время: O(n + m): создание cnt и один проход. Дополнительная память: O(m) счётчиков. Если m большое, например 109, используйте dict: O(u) записей для u разных остатков.

4. Пары с суммой, кратной k

Возьмём a = [4, 7, 6, 1, 8, −3, 2] и k = 4. Остатки 0, 3, 2, 1, 0, 1, 2. Сумма делится на 4 для остатков 0 + 0, 1 + 3 и 2 + 2. Пары: 4 + 8, 7 + 1, 7 + (−3) и 6 + 2. Всего 4 пары. Brute Force проверяет n(n − 1)/2 = 21 пару.

Один проход: для нового x ищем раньше записанные числа с остатком (−x) % k. Сначала прибавляем cnt[(−x) % k], потом записываем остаток x. Так каждая пара i < j посчитана один раз.

a = [4, 7, 6, 1, 8, -3, 2]
k = 4
cnt = [0] * k
pairs = 0
for x in a:
    pairs += cnt[-x % k]
    cnt[x % k] += 1
print(pairs, cnt)

Код выводит 4 [2, 2, 2, 1]. В Python -x % k означает (−x) % k: унарный минус выполняется раньше %.

Правило. Для нового x второе число пары должно иметь остаток (−x) % k. Сначала прибавьте cnt[(−x) % k], затем увеличьте cnt[x % k]. Остаток 0 соединяется с остатком 0, а при чётном k остаток k/2 соединяется с k/2.

Пары внутри одного класса

При k = 4 возьмём a = [2, 6, 10]. Все остатки равны 2, и (−2) % 4 = 2: каждое число ищет свой же класс. Проход прибавляет 0, 1 и 2, всего 3 пары: 2 + 6, 2 + 10 и 6 + 10. Это c(c − 1)/2 для c = 3. Код, который соединяет только разные остатки r и k − r, пропустит этот класс и класс 0. Код из примера выше считает оба случая без отдельной ветки, потому что прибавляет cnt до записи x.

Когда все числа должны войти в пары, сравните счётчики классов: строить сами пары не нужно.

Время: O(n + k): создание cnt и n шагов по O(1). Дополнительная память: O(k) счётчиков; ответ - одно число. Brute Force проверяет n(n − 1)/2 пар: при n = 200 000 это 19 999 900 000 проверок. При 3 с на скрытый тест это слишком много.

5. Subarray с суммой, кратной k

В лекции Prefix Sum (глава 2) мы писали p[0] = 0 и p[i + 1] = p[i] + nums[i]. Сумма nums[l..r] равна p[r + 1] − p[l]. Эта разность делится на k, если p[l] и p[r + 1] лежат в одном классе остатков.

Возьмём nums = [−2, 5, 1, −4, 3] и k = 3. Префиксы p = 0, −2, 3, 4, 0, 3, их остатки 0, 1, 0, 1, 0, 0. Класс 0 из 4 префиксов даёт 4 · 3 / 2 = 6 Subarray. Класс 1 из 2 префиксов даёт 1 Subarray, это [5, 1]. Ответ 7.

В C++ -2 % 3 равно −2: префикс −2 попал бы в другой класс, чем 4, и Subarray [5, 1] потерялся бы.

nums = [-2, 5, 1, -4, 3]
k = 3
cnt = {0: 1}
p = 0
ans = 0
for x in nums:
    p = (p + x) % k
    ans += cnt.get(p, 0)
    cnt[p] = cnt.get(p, 0) + 1
print(ans, cnt)

Код выводит 7 {0: 4, 1: 2}. По шагам p = 1, 0, 1, 0, 0, а ans = 0, 1, 2, 4, 7.

Пустой префикс нужен для Subarray, которые начинаются с nums[0]. Например, [−2, 5] имеет сумму p[2] − p[0] = 3 − 0 = 3. Таких Subarray здесь три. Без записи p[0] код не найдёт их и выведет 4.

Правило. Сумма nums[l..r] делится на k, если p[l] % k == p[r + 1] % k. Класс из c префиксов даёт c(c − 1)/2 таких Subarray. Пустой префикс p[0] = 0 записывают до прохода.

Время: O(n): n шагов, в каждом O(1) операций dict в среднем. Дополнительная память: O(min(n + 1, k)) записей dict; ответ - одно число. Brute Force проверяет n(n + 1)/2 Subarray: для n = 30 000 это 450 015 000, даже с накоплением суммы O(n²) времени.

6. Ключ из двух остатков

Возьмём x = 3, y = 2 и a = [1, 5, 2, 8, 4]. Пара подходит, если сумма делится на 3, а разность на 2. Ключ числа a - это пара остатков (a % 3, a % 2): 1 → (1, 1), 5 → (2, 1), 2 → (2, 0), 8 → (2, 0), 4 → (1, 0). Для нового числа ищем среди прежних ключ ((−a) % 3, a % 2).

Ответ 3: пары (1, 5), (2, 4) и (8, 4). Ключ следует из правила раздела 3: разность делится на y, если остатки по y равны, а сумма делится на x, если остаток второго числа по x равен (−a) % x. Это идея Codeforces 1931D.

need = (-a % x, a % y)
ans += cnt.get(need, 0)
key = (a % x, a % y)
cnt[key] = cnt.get(key, 0) + 1

Время: O(n) в среднем при O(1) операциях Hash Table. Дополнительная память: O(n) ключей в худшем случае: при x и y до 109 все ключи могут быть разными.

7. Что нужно запомнить

  • В Python a % m при m > 0 лежит от 0 до m − 1, даже для отрицательного a.
  • Остаток суммы, разности и произведения считают по остаткам. Берите % после каждого шага.
  • Числа с равными остатками образуют класс. Пары и Subarray считают по счётчикам классов.
  • Для Subarray нужны остатки префиксов и пустой префикс p[0] = 0.

8. Как решать задачи этой главы

  1. Найдите, какое число должно делиться: само число, сумма пары или сумма Subarray.
  2. Замените это число остатком и проверьте правило на маленьком примере, также с отрицательными числами.
  3. Решите, какой ключ хранить в счётчике: остаток, пару остатков или остаток префикса.
  4. Посчитайте проходы и размер счётчика. Сравните их с n(n − 1)/2 проверками Brute Force.
