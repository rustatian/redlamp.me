Binary Exponentiation возводит число в степень b по модулю m за O(log b) умножений: показатель раскладывают на степени двойки.

1. Степень простым циклом

Посчитаем 35 по модулю 7. Начнём с r = 3. Затем 3 · 3 = 9 даёт остаток 2. Дальше 2 · 3 = 6, остаток 6. Потом 6 · 3 = 18, остаток 4. Последний шаг: 4 · 3 = 12, остаток 5. Проверка: 35 = 243 = 7 · 34 + 5.

Код делает то же самое b раз. После каждого умножения он берёт остаток, как в главе 1, поэтому r всегда меньше m.

a, b, m = 3, 5, 7
r = 1
for _ in range(b):
    r = r * a % m
print(r)

Код выводит 5.

Время: b умножений и b операций %: O(b). Дополнительная память: O(1). Python делает около 107 простых шагов в секунду (это оценка, а не замер). При b = 109 цикл работает около 100 с, при b = 1015 около 108 с, больше трёх лет. У нас 2 с на пример и 3 с на скрытый тест.

Запись a ** b % m тоже не помогает: Python сначала строит число ab целиком. Число 2 ** (10 ** 6) имеет 301 030 десятичных цифр, а 2 ** (10 ** 9) занимает 109 битов, около 125 МБ.

2. Квадраты вместо умножений

38 = ((32)2)2: 32 = 9, 92 = 81, 812 = 6561. Три возведения в квадрат заменяют 7 умножений на 3. Для 316 хватает 4 квадратов, для 31024 хватает 10.

Правило. Для чётного b: ab = (ab/2)2. Для нечётного b: ab = ab − 1 · a. Каждое возведение в квадрат уменьшает показатель вдвое.

Другой показатель раскладывают на степени двойки. 13 = 8 + 4 + 1, в двоичной записи 1101. Поэтому 313 = 38 · 34 · 31. По модулю 7: 31 даёт остаток 3, 32 = 9 даёт остаток 2, 34 даёт остаток 2 · 2 = 4, 38 даёт остаток 4 · 4 % 7 = 2. Произведение нужных остатков 3 · 4 · 2 = 24 даёт остаток 3. Проверка: 313 = 1 594 323 = 7 · 227 760 + 3.

3. Цикл Binary Exponentiation

Цикл читает двоичные цифры b с младшей. Младшая цифра равна b % 2, а b //= 2 убирает её. В переменной a лежит исходное a в степени 1, 2, 4, 8, ... по модулю m. Если текущая цифра 1, r умножают на a.

def power(a, b, m):
    r = 1
    a %= m
    while b > 0:
        if b % 2 == 1:
            r = r * a % m
        a = a * a % m
        b //= 2
    return r

print(power(3, 13, 7))
print(power(2, 10, 1000))

Код выводит 3 и 24: 210 = 1024 даёт остаток 24 при делении на 1000. Строка a %= m в начале уменьшает большое основание: в LeetCode 372 основание доходит до 231 − 1, а модуль равен 1337. Без неё первое a · a имело бы 19 цифр.

Правило. Пока b > 0: если b нечётно, умножьте r на a; затем a = a · a % m и b //= 2. После шага i в a лежит исходное a в степени 2i по модулю m.

Время: цикл делает столько шагов, сколько цифр в двоичной записи b, это примерно log₂ b. В каждом шаге не больше двух умножений: O(log b). Дополнительная память: O(1): r, a и b.

Для 313 переменная b принимает значения 13, 6, 3, 1, а r после шагов равно 3, 3, 5, 3. Код сделал 4 возведения в квадрат и 3 умножения r, всего 7. Простой цикл сделал бы 13 умножений.

Лишний квадрат на последнем шаге

На последнем шаге a = a · a % m уже не нужен: b станет 0, и новое a код не прочитает. Проверка b перед этой строкой добавила бы условие в каждый шаг, а экономит одно умножение. Оценка O(log b) не меняется.

Биты выбирают степени: особые числа

Двоичная запись k = 5 равна 101: 5 = 22 + 20. Заменим каждую степень 2 на ту же степень 3: 32 + 30 = 10. Суммы различных степеней 3 по возрастанию: 1, 3, 4, 9, 10, 12, 13. Это k = 1, 2, 3, 4, 5, 6, 7 с двоичной записью 1, 10, 11, 100, 101, 110, 111. Цикл по битам k тот же, что в power, но копит сумму, а не произведение: при бите 1 к ответу прибавляют p, затем p = p · n % m. Так решают Codeforces 1594B.

4. Встроенная pow(a, b, m)

В Python есть встроенная функция pow(a, b, m). Она использует тот же способ: квадраты и умножения по двоичным цифрам b.

print(pow(3, 13, 7))
print(pow(2, 10**18, 10))
print(pow(7, 2026, 10))

Код выводит 3, 6 и 9. Второе и третье число - последние цифры степеней. Степени 2 кончаются на 2, 4, 8, 6, и эти цифры повторяются через 4. 1018 делится на 4, поэтому цифра та же, что у 24 = 16, то есть 6. Степени 7 кончаются на 7, 9, 3, 1. 2026 = 4 · 506 + 2, поэтому цифра та же, что у 72 = 49, то есть 9.

Правило. Последние цифры степеней числа повторяются по циклу. Для b ≥ 1: если длина цикла p, у ab та же последняя цифра, что у ar для r = b % p. При r = 0 возьмите ap. pow(a, b, 10) даёт эту цифру и без поиска цикла.

Как найти длину цикла

Умножайте последнюю цифру на a и берите % 10, пока не вернётся первая цифра. Для 4: 4, 16 даёт 6, 6 · 4 = 24 даёт 4. Цикл 4, 6, длина 2. Для 8: 8, 4, 2, 6, затем снова 8, длина 4. Для 5 цикл из одной цифры 5. Длина цикла последней цифры всегда 1, 2 или 4.

Время: pow(a, b, m) делает O(log b) умножений чисел меньше m; для b = 1018 это до 120 умножений. Дополнительная память: O(1) чисел меньше m. Запись a ** b % m требует около b · log₂ a битов только для ab.

Разность степеней снова берут по модулю, как в главе 1: (pow(3, n, M) - pow(2, n, M)) % M. Без последней операции % разность может быть отрицательной.

5. Степени в подсчёте вариантов

Сколько String длины 3 можно составить из цифр 0 и 1? На каждой позиции 2 варианта, и выбор на одной позиции не зависит от других. По Product Rule из главы 1 лекции Permutations и Combinations вариантов 2 · 2 · 2 = 23 = 8: 000, 001, 010, 011, 100, 101, 110, 111.

Правило. Если на каждой из n позиций k независимых вариантов, всего kn вариантов. Если на p позициях k вариантов, а на q других позициях l вариантов, всего kp · lq. По модулю M это pow(k, p, M) · pow(l, q, M) % M.

Пример: пароль из 4 символов, на позициях 0 и 2 стоит цифра (10 вариантов), на позициях 1 и 3 буква из 26. Вариантов 102 · 262 = 100 · 676 = 67 600.

Основание тоже бывает формулой. Пусть каждый из n предметов получает непустой Subset из 3 цветов. Каждый цвет предмет берёт или не берёт: 23 = 8 Subset, без пустого остаётся 23 − 1 = 7. Предметы выбирают независимо, поэтому для n = 2 вариантов 72 = 49.

M = 10**9 + 7
print(pow(10, 2, M) * pow(26, 2, M) % M)
print(pow((pow(2, 3, M) - 1) % M, 2, M))

Код выводит 67600 и 49. Вычитание единицы стоит внутри скобок, и после него снова берут % M.

Время: две или три pow: O(log p + log q) умножений. Дополнительная память: O(1). Brute Force проверяет все kn вариантов: для 10 позиций по 10 цифр это уже 1010 строк.

6. Показатель из цифр

В LeetCode 372 показатель дан списком цифр. Пусть b = 10x + d, где d - последняя цифра, а x - число из остальных цифр. Тогда ab = (ax)10 · ad. Поэтому идём по цифрам слева направо и храним в r степень a для уже прочитанных цифр.

Пример: a = 2, цифры [1, 2], m = 1000. После цифры 1: r = 21 = 2. После цифры 2: r = 210 · 22 = 1024 · 4. По модулю 1000 это 24 · 4 = 96. Проверка: 212 = 4096 даёт остаток 96.

Правило. В начале r = 1. Для каждой цифры d слева направо: r = r10 · ad по модулю m.

a, digits, m = 2, [1, 2], 1000
r = 1
for d in digits:
    r = pow(r, 10, m) * pow(a, d, m) % m
print(r)

Код выводит 96. Для цифр [1, 2, 3] в r по очереди лежат a1, a12 и a123 по модулю m: каждая новая цифра дописывается к показателю справа.

Время: L цифр, на каждую две pow с показателем не больше 10: до 8 шагов цикла, всего O(L). Дополнительная память: O(1). Перевод цифр в одно число Python тоже работает: 2000 десятичных цифр дают около 6644 двоичных цифр и столько же шагов pow.

Показатель нельзя брать по модулю m

25 = 32 даёт остаток 2 при делении на 3, а 25 % 3 = 22 = 4 даёт остаток 1. По модулю берут основание и результаты умножений, но не показатель. В LeetCode 2961 формула задаёт порядок: сначала x = pow(a, b, 10), затем pow(x, c, m). Показатель c не заменяйте на c % m.

7. Что нужно запомнить

  • Простой цикл делает b умножений, Binary Exponentiation около log₂ b шагов.
  • pow(a, b, m) - встроенная Binary Exponentiation. Не пишите a ** b % m для больших b.
  • Последние цифры степеней повторяются: смотрите на остаток показателя от деления на длину цикла.
  • Показатель нельзя заменять его остатком от деления на m.
  • Product Rule даёт степени: k вариантов на каждой из n позиций дают kn.
  • После вычитания по модулю снова возьмите % m.

8. Как решать задачи этой главы

  1. Найдите основание и показатель: n, 2m − 1 или число из цифр.
  2. Проверьте формулу на маленьком примере: сравните её с Brute Force.
  3. Замените каждую степень на pow(a, b, m) и берите % после каждого умножения и вычитания.
  4. Оцените число шагов по двоичным цифрам показателя, а не по самому показателю.
