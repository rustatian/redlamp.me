Binary Search нужен не порядок всего Array, а правило, которое по одной проверке середины оставляет половину с ответом.

1. Matrix с упорядоченными рядами

LeetCode 1351: grid = [[4, 3, 2, -1], [3, 2, 1, -1], [1, 1, -1, -2], [-1, -1, -2, -3]]. Каждый ряд не возрастает, поэтому отрицательные числа стоят в конце ряда. Для ряда 2 = [1, 1, −1, −2] условие row[j] < 0 идёт «нет, нет, да, да». Индекс первого отрицательного числа - первое «да», его находит шаблон Lower Bound из главы 2. Ряд длины n с границей j даёт n − j отрицательных чисел.

def first_negative(row):
    lo, hi = 0, len(row)
    while lo < hi:
        mid = (lo + hi) // 2
        if row[mid] < 0:
            hi = mid
        else:
            lo = mid + 1
    return lo

grid = [[4, 3, 2, -1], [3, 2, 1, -1], [1, 1, -1, -2], [-1, -1, -2, -3]]
print([first_negative(r) for r in grid])
print(sum(len(r) - first_negative(r) for r in grid))

Программа выводит [3, 3, 2, 0] и 8: границы рядов 3, 3, 2, 0, отрицательных 1 + 1 + 2 + 4 = 8.

Поиск в рядах делает 2 + 2 + 2 + 3 = 9 проверок, а Linear Scan читает все 16 клеток.

Бывает и другой порядок. В LeetCode 74 Matrix из m рядов по n чисел упорядочена ряд за рядом: каждый ряд начинается с числа больше последнего числа предыдущего ряда. Такую Matrix можно читать как один упорядоченный Array из m · n чисел. Номер k даёт клетку (k // n, k % n): для m = 3, n = 4 номер 7 - это ряд 7 // 4 = 1, столбец 7 % 4 = 3.

Правило. Если каждый ряд упорядочен, ищите границу в каждом ряду: O(m log n). Если Matrix упорядочена ряд за рядом целиком, номер k даёт клетку (k // n, k % n), и хватает одного поиска: O(log(mn)).

Время: для 100 × 100 не больше 7 проверок на ряд, всего 700; Linear Scan читает 10 000 клеток. В примере 9 проверок против 16 клеток. Дополнительная память: O(1).

Обход лесенкой за O(m + n)

В LeetCode 1351 столбцы тоже не возрастают. Начните в левом нижнем углу. Если число отрицательное, то и весь остаток ряда справа отрицательный: прибавьте длину остатка и поднимитесь на ряд выше. Иначе шагните вправо. Каждый шаг убирает ряд или столбец, поэтому шагов не больше m + n = 200 для 100 × 100. Этот обход не Binary Search, но он тоже использует порядок.

2. Гора: сравните с соседом

LeetCode 852: arr = [1, 3, 6, 9, 7, 4, 2]. Значения растут до вершины 9, потом убывают. Сравните каждое число с правым соседом: условие arr[i] > arr[i + 1] для i = 0, 1, ..., 5 идёт «нет, нет, нет, да, да, да». Вершина - первое «да», индекс 3. Поиск идёт на [0, n − 1], чтобы arr[mid + 1] всегда существовал.

def peak(arr):
    lo, hi = 0, len(arr) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] > arr[mid + 1]:
            hi = mid
        else:
            lo = mid + 1
    return lo

print(peak([1, 3, 6, 9, 7, 4, 2]), peak([0, 10, 5, 2]))

Программа выводит 3 1. Второй ответ - пример 3 задачи.

Для [1, 3, 6, 9, 7, 4, 2] поиск делает 3 проверки: mid = 3, 1, 2. Вершина в индексе 3.

Правило. В горе условие arr[i] > arr[i + 1] идёт «нет, ..., нет, да, ..., да». Вершина - первый индекс «да». Ищите его шаблоном Lower Bound на [0, n − 1].

Время: O(log n), не больше 17 проверок для n = 10⁵. Дополнительная память: O(1). Linear Scan в поиске максимума читает все n чисел.

Ternary Search и равные соседи

Ternary Search берёт две точки m1 < m2 и отбрасывает треть отрезка: при arr[m1] < arr[m2] вершина правее m1. Каждый шаг оставляет 2/3 отрезка, поэтому для n = 10⁵ нужно около 28 шагов против 17 проверок с соседом, а каждый шаг и каждая проверка читают 2 числа. Оба способа требуют строгого подъёма и строгого спуска. При равных соседях сравнение не говорит, где вершина: в [1, 5, 1, 1, 1, 1] и в [1, 1, 1, 1, 5, 1] середина 2 видит arr[2] = arr[3] = 1, а вершина в первом случае левее, во втором правее. В задачах главы равных соседей нет.

3. Долина: модуль разности

Codeforces 2009E: a = [k, k + 1, ..., k + n − 1], нужно выбрать i и сделать наименьшим x = |a₁ + ... + aᵢ − aᵢ₊₁ − ... − aₙ|. Пусть S(i) = a₁ + ... + aᵢ. Правая часть равна S(n) − S(i), поэтому x = |2 · S(i) − S(n)|. Обозначим d(i) = 2 · S(i) − S(n).

Пример: n = 5, k = 3, a = [3, 4, 5, 6, 7], S(5) = 25. d = [−19, −11, −1, 11, 25] растёт, ведь каждое aᵢ > 0. |d| = [19, 11, 1, 11, 25] сначала убывает, потом растёт: это долина. Ответ - дно долины, 1.

Array хранить нельзя: n до 10⁹. Но S(i) = i · k + i(i − 1) / 2 считается по формуле: для i = 3 это 9 + 3 = 12 = 3 + 4 + 5. d(i) растёт, поэтому первый i с d(i) ≥ 0 находит Lower Bound, а дно стоит в i или в i − 1.

def klee(n, k):
    total = n * k + n * (n - 1) // 2
    def d(i):
        return 2 * (i * k + i * (i - 1) // 2) - total
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if d(mid) >= 0:
            hi = mid
        else:
            lo = mid + 1
    return min(abs(d(lo - 1)), abs(d(lo)))

print([2 * (i * 3 + i * (i - 1) // 2) - 25 for i in range(1, 6)])
print(klee(2, 2), klee(7, 2), klee(5, 3), klee(10**9, 10**9))

Программа выводит d для примера и ответы четырёх наборов из примера задачи: [-19, -11, -1, 11, 25] и 1 5 1 347369930. d(1) = 2k − S(n) < 0 при n ≥ 2, поэтому lo ≥ 2, и d(lo − 1) всегда относится к настоящему индексу.

Для n = 5, k = 3 поиск делает 2 проверки: середины 3 и 4. Первый i с d(i) ≥ 0 равен 4, ответ min(|d(3)|, |d(4)|) = min(1, 11) = 1.

Правило. Если d(i) растёт, то |d(i)| образует долину. Дно стоит рядом с местом, где d меняет знак: найдите первый i с d(i) ≥ 0 и сравните |d(i − 1)| и |d(i)|.

Время: O(log n), не больше 30 проверок на набор; для t = 10⁴ наборов около 3 · 10⁵. Linear Scan по i дал бы до 10⁹ шагов на один набор, а лимит 2 с на пример и 3 с на скрытый тест. Дополнительная память: O(1) на набор, ответы отдельно.

4. Повёрнутый Array: где минимум

LeetCode 153: nums = [4, 5, 6, 7, 0, 1, 2]. Это упорядоченный [0, 1, 2, 4, 5, 6, 7], у которого начало [0, 1, 2] перенесли в конец. Сравните каждое число с последним числом 2: левая часть 4, 5, 6, 7 больше 2, правая часть 0, 1, 2 не больше 2. Условие nums[i] ≤ nums[−1] идёт «нет, нет, нет, нет, да, да, да». Минимум - первое «да», индекс 4.

def find_min(nums):
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] <= nums[-1]:
            hi = mid
        else:
            lo = mid + 1
    return lo

for nums in [[4, 5, 6, 7, 0, 1, 2], [3, 4, 5, 1, 2], [11, 13, 15, 17]]:
    i = find_min(nums)
    print(i, nums[i])

Программа выводит три строки: 4 0, 3 1 и 0 11. Это примеры 2, 1 и 3 задачи. Третий Array упорядочен целиком, и все его числа не больше последнего, поэтому минимум в индексе 0.

Для [4, 5, 6, 7, 0, 1, 2] поиск делает 3 проверки: mid = 3, 5, 4. Минимум nums[4] = 0.

Правило. В повёрнутом Array без повторов числа левой части больше последнего числа, а числа правой части не больше его. Минимум - первый индекс i с nums[i] ≤ nums[−1].

Время: O(log n), не больше 13 проверок для n = 5000. Дополнительная память: O(1). min(nums) читает все n чисел.

5. Число в повёрнутом Array

LeetCode 33: nums = [4, 5, 6, 7, 0, 1, 2]. Минимум стоит в индексе p = 4. Части с индексами [0, 3] и [4, 6] упорядочены. target = 0 ≤ nums[−1] = 2: ищем в правой части, ответ 4. target = 3 > 2: ищем в левой части [4, 5, 6, 7], числа 3 там нет, ответ −1.

p = find_min(nums)
if target <= nums[-1]:
    lo, hi = p, len(nums) - 1
else:
    lo, hi = 0, p - 1
# дальше поиск из главы 1 на отрезке [lo, hi]

Правило. Сначала найдите место поворота p. Части [0, p − 1] и [p, n − 1] упорядочены. target ≤ nums[−1] может стоять только в правой части, иначе только в левой.

Время: два поиска, не больше 13 + 13 = 26 проверок для n = 5000, O(log n). Дополнительная память: O(1).

Один проход и повторы

Можно обойтись одним поиском. При nums[lo] ≤ nums[mid] упорядочена левая половина [lo, mid], иначе правая. Если target лежит между краями упорядоченной половины, ищите там, иначе в другой половине. С повторами правило ломается: в [1, 1, 1, 0, 1] и в [1, 0, 1, 1, 1] середина и последнее число равны 1, а минимум в первом случае правее середины, во втором левее. Тогда в худшем случае нужно O(n) проверок.

6. Что нужно запомнить

  • Binary Search нужно правило «нет, ..., да», а не полный порядок Array.
  • Гора: arr[i] > arr[i + 1]. Повёрнутый Array: nums[i] ≤ nums[−1]. Долина: знак d(i).
  • В Matrix ищите в каждом упорядоченном ряду или читайте её как один Array.
  • Проверьте края: arr[mid + 1] должен существовать, повторов быть не должно.

7. Как решать задачи этой главы

  1. Выпишите условие для каждого индекса маленького примера и убедитесь, что оно идёт «нет, ..., да».
  2. Выберите отрезок поиска так, чтобы все чтения были внутри Array.
  3. Найдите границу шаблоном Lower Bound.
  4. Если нужно число, а не граница, сделайте второй поиск в упорядоченной части.
  5. Посчитайте проверки и память; сравните с Linear Scan.
