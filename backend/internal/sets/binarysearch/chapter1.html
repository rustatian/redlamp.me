Binary Search находит число в упорядоченном Array из 100 чисел не больше чем за 7 проверок середины: каждая проверка отбрасывает половину оставшихся мест.

1. Игра «угадай число»

Загадано число от 1 до 100. Каждый вопрос называет середину оставшихся чисел: «Это 50? Если нет, оно больше или меньше?». Ответ «больше» оставляет только числа правее середины, ответ «меньше» только числа левее.

Пусть загадано 100, это худший путь. Вопросы: 50, 75, 88, 94, 97, 99, 100. Перед каждым вопросом остаётся кандидатов: 100, 50 (51..100), 25 (76..100), 12 (89..100), 6 (95..100), 3 (98..100), 1 (100). Седьмой вопрос «Это 100?» получает ответ «да». Всего 7 проверок. Linear Scan 1, 2, 3, ... задал бы 100 вопросов.

⌊x⌋ - это x, округлённое вниз. ⌊log₂ 10⌋ = 3, потому что 2³ = 8 ≤ 10 < 16 = 2⁴. ⌊log₂ 100⌋ = 6, потому что 2⁶ = 64 ≤ 100 < 128, и 6 + 1 = 7 проверок, как в игре.

Правило. Binary Search работает, когда кандидаты упорядочены. Одна проверка середины оставляет не больше половины кандидатов. Для n кандидатов проверок не больше ⌊log₂ n⌋ + 1.

Время: O(log n) проверок в худшем случае. Дополнительная память: O(1), три числа lo, hi и mid. Таблица считает проверки, а не секунды.

2. Инвариант lo и hi

Дан Array a = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], n = 10, ищем target = 23. Отрезок [lo, hi] - это индексы, где target ещё может стоять. Сначала lo = 0 и hi = 9. Середина mid = (lo + hi) // 2.

Поиск 23: каждая строка - одна проверка

5975656 > 23: hi = 6

Правило. Инвариант: если target есть в a, его индекс лежит в отрезке [lo, hi]. При a[mid] < target ответ правее: lo = mid + 1. При a[mid] > target ответ левее: hi = mid − 1. Цикл идёт, пока lo ≤ hi; пустой отрезок lo > hi значит, что target нет.

def search(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

a = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print(search(a, 23), search(a, 40))

Почему инвариант верен. Перед первой проверкой отрезок [0, n − 1] содержит все индексы. Если a[mid] < target, то все числа a[0..mid] тоже меньше target, ведь Array упорядочен: target может стоять только в [mid + 1, hi]. При a[mid] > target так же отбрасываем [mid, hi].

Программа выводит 5 -1. Поиск 40: mid = 4 (16 < 40, lo = 5), mid = 7 (56 > 40, hi = 6), mid = 5 (23 < 40, lo = 6), mid = 6 (38 < 40, lo = 7). Теперь lo = 7 > hi = 6: отрезок пуст, ответ −1. Число 40 стояло бы между 38 и 56.

Время: для n = 10 не больше ⌊log₂ 10⌋ + 1 = 4 проверок. Поиск 23 сделал 3 проверки, поиск 40 сделал 4. В общем случае O(log n). Дополнительная память: O(1): числа lo, hi и mid. Вход a не считаем.

Проверьте свой код на трёх маленьких входах: Array из одного числа, target меньше всех чисел и target, равный последнему числу. Эти три входа находят все три ошибки таблицы.

Правило. После проверки mid уже не кандидат. Новая граница mid + 1 или mid − 1, поэтому отрезок [lo, hi] становится короче на каждом шаге.

Срезы, Recursion и переполнение

Recursion со срезом search(a[mid + 1:], target) копирует ссылки. Для n = 1024 и target больше всех срезы длины 512, 256, ..., 1 вместе копируют 1023 ссылки. Все срезы живы, пока идут вложенные вызовы, поэтому время O(n) и дополнительная память O(n), а не O(log n). Ещё срез теряет исходные индексы. Recursion с числами lo и hi ничего не копирует: время O(log n), Call Stack хранит O(log n) вызовов. Цикл даёт O(1) дополнительной памяти. В Python (lo + hi) // 2 не переполняется; в C++ и Java пишут lo + (hi - lo) / 2.

4. Когда Binary Search выгоден

Дан упорядоченный Array из n = 100 000 чисел и q = 100 000 запросов «есть ли x». Linear Scan делает до n · q = 10¹⁰ сравнений. Binary Search делает 17 проверок на запрос, всего 1 700 000. Лимит: 2 с на пример и 3 с на скрытый тест. 10¹⁰ сравнений не успеют, 1,7 · 10⁶ успеют.

Если Array не упорядочен, Sorting стоит O(n log n) один раз. Сравнение Linear Scan, Sorting с Binary Search и Hash Table для q запросов есть в главе 1 набора «Permutations и Combinations».

LeetCode 2540: nums1 и nums2 упорядочены. Для каждого x из nums1 по порядку ищем x в nums2. Первое найденное x и есть наименьшее общее число. Для nums1 = [1, 2, 3, 6] и nums2 = [2, 3, 4, 5] поиск 1 даёт −1, поиск 2 находит число: ответ 2.

Для n = m = 100 000 это до 1,7 · 10⁶ проверок. Two Pointers из главы 3 набора «Two Pointers» проходят оба Array за n + m = 200 000 шагов. Binary Search выгоднее, когда n мало, а m велико: при n = 10 и m = 10⁵ это 170 проверок против 100 010 шагов.

Правило. Binary Search выгоден, когда данные уже упорядочены или запросов много. Для одного запроса к неупорядоченному Array Linear Scan дешевле Sorting.

Время: q поисков стоят O(q log n), здесь 1 700 000 проверок. Дополнительная память: O(1) на запрос; ответы хранятся отдельно. sorted(a) создаёт новый list из n ссылок. a.sort() меняет a на месте, но может временно взять до n / 2 ссылок.

5. Array, заданный формулой

Квадраты x · x для x = 1..8: 1, 4, 9, 16, 25, 36, 49, 64. Это упорядоченный Array, но хранить его не нужно: mid · mid считаем на месте. LeetCode 367 спрашивает, есть ли целое x с x · x = num.

def is_square(num):
    lo, hi = 1, num
    steps = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        steps += 1
        if mid * mid == num:
            return True, steps
        if mid * mid < num:
            lo = mid + 1
        else:
            hi = mid - 1
    return False, steps

print(is_square(49), is_square(50))

Программа выводит (True, 5) (False, 6). Для 49 середины 25 (625 > 49), 12 (144 > 49), 6 (36 < 49), 9 (81 > 49), 7 (49 = 49): 5 проверок. Для 50 поиск делает 6 проверок: середины 25, 12, 6, 9, 7, 8. Квадраты 49 и 64 стоят по обе стороны от 50, поэтому ответ False.

Правило. Binary Search не требует хранить Array. Нужна функция f(x), которая растёт вместе с x, и границы lo и hi, между которыми лежит ответ. Для квадратов f(x) = x · x, lo = 1, hi = num.

Codeforces 192A: треугольные числа T(k) = k(k + 1) / 2 равны 1, 3, 6, 10, 15, 21, ... Нужно узнать, равно ли n сумме двух таких чисел. Выпишем все T(k) < n в list: он упорядочен. Для каждого T(i) ищем n − T(i) в этом list через Binary Search. Для n = 25: ищем 25 − 1 = 24, 25 − 3 = 22, 25 − 6 = 19 и не находим; 25 − 10 = 15 находим, ответ YES.

Для n ≤ 10⁹ таких T(k) < n не больше 44 720. Все пары дают около 2 · 10⁹ сравнений, а Binary Search для каждого первого числа даёт 44 720 · 16 = 715 520 проверок.

Время: для num ≤ 2³¹ − 1 не больше 31 проверки, O(log num). Linear Scan x = 1, 2, ... дошёл бы до 46 341: O(√num). Дополнительная память: O(1); list всех квадратов занял бы O(√num), около 46 341 числа. В задаче 192A list треугольных чисел занимает O(√n) памяти, около 44 720 чисел.

6. Что нужно запомнить

  • Binary Search нужен порядок: упорядоченный Array или функция, которая растёт.
  • Инвариант: ответ, если он есть, лежит в [lo, hi]. Каждый шаг убирает mid и одну половину.
  • Для n кандидатов не больше ⌊log₂ n⌋ + 1 проверок и O(1) дополнительной памяти без срезов.

7. Как решать задачи этой главы

  1. Найдите порядок: какой Array или какая функция растёт.
  2. Выберите lo и hi так, чтобы ответ точно лежал между ними.
  3. Запишите три случая: a[mid] меньше, равно или больше target.
  4. Проверьте один элемент, ответ на краях и отсутствие ответа.
  5. Посчитайте проверки и дополнительную память; сравните с Linear Scan.
