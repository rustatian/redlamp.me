Sliding Window длины k сдвигается на один шаг: в окно входит один элемент и выходит один элемент, поэтому данные об окне можно обновить, а не считать заново.

n - длина входа, k - длина окна. Окно с концом r занимает номера r − k + 1..r. Сравнения и арифметика чисел из ограничений стоят O(1). Дополнительная память - наибольший объём рабочих данных, которые нужны одновременно, без входа и готового ответа.

1. Сумма окна: вычесть и прибавить

a = [2, 1, 5, 1, 3, 2], k = 3. Окна: [2, 1, 5] = 8, [1, 5, 1] = 7, [5, 1, 3] = 9, [1, 3, 2] = 6. Наибольшая сумма 9.

Brute Force складывает каждое окно заново: 4 окна по 3 чтения, всего 12 чтений. Соседние окна [2, 1, 5] и [1, 5, 1] имеют общую часть [1, 5]. Достаточно вычесть 2 и прибавить 1: 8 − 2 + 1 = 7.

Правило. Окно с концом r занимает номера r − k + 1..r. При сдвиге вправо входит a[r], выходит a[r − k]: новая сумма = старая сумма − a[r − k] + a[r].

a = [2, 1, 5, 1, 3, 2]
k = 3
s = sum(a[:k])
sums = [s]
for r in range(k, len(a)):
    s += a[r] - a[r - k]
    sums.append(s)
print(sums, max(sums))

Код печатает [8, 7, 9, 6] 9: 8; 8 − 2 + 1 = 7; 7 − 1 + 3 = 9; 9 − 5 + 2 = 6. Окон n − k + 1 = 4: первое кончается на r = k − 1 = 2, последнее на r = n − 1 = 5.

Время: k чтений для первого окна и по 2 чтения на каждый из n − k сдвигов: O(n). Дополнительная память: срез a[:k] временно хранит k ссылок, O(k); цикл по первым k номерам вместо среза требует O(1) памяти. list sums - это ответ из n − k + 1 чисел, его считаем отдельно.

Prefix Sum вместо суммы окна

p[0] = 0, p[j] - сумма первых j чисел. Сумма окна с концом r равна p[r + 1] − p[r + 1 − k]. Для a = [2, 1, 5, 1, 3, 2]: p = [0, 2, 3, 8, 9, 12, 14], окно с концом 3 даёт 9 − 2 = 7. Время тоже O(n), но list p хранит n + 1 чисел: O(n) дополнительной памяти. Prefix Sum полезен, когда нужны суммы окон разной длины; для одной длины k хватает одной переменной s.

2. Счётчик в окне: Codeforces 1690D

s = "BBWBW", k = 3. Окна BBW, BWB, WBW содержат 1, 1 и 2 белые клетки W. Ответ 1: достаточно перекрасить одну клетку.

Чтобы окно стало чёрным, нужно перекрасить все его W. Поэтому ответ - наименьшее число W среди всех n − k + 1 окон.

Храните не сумму, а число W в окне. Вошла W: +1. Вышла W: −1. В Python сравнение (s[r] == "W") даёт True или False, а в арифметике это 1 или 0.

w = s[:k].count("W")
best = w
for r in range(k, n):
    w += (s[r] == "W") - (s[r - k] == "W")
    best = min(best, w)

Время: O(n) на набор, O(Σn) на весь вход. Дополнительная память: O(k) на срез s[:k], потом O(1). Ответ - одно число на набор. Brute Force считает каждое окно заново: O(nk), при n = 200 000 и k = 100 000 это около 1010 чтений.

3. set последних k чисел: LeetCode 219

nums = [1, 2, 3, 1, 2, 3], k = 2. Нужны два равных числа на расстоянии не больше 2. Здесь равные числа стоят на расстоянии 3, ответ False.

Правило. set хранит числа nums[i − k..i − 1]. Перед добавлением nums[i] проверьте, есть ли оно в set. После добавления удалите nums[i − k], если в set стало больше k чисел.

window = set()
for i, x in enumerate(nums):
    if x in window:
        return True
    window.add(x)
    if len(window) > k:
        window.remove(nums[i - k])
return False

Пока повтор не найден, все числа окна разные, поэтому len(window) равна числу элементов окна. Граница важна: для nums = [1, 2, 1] и k = 1 равные числа стоят на расстоянии 2 > 1, ответ False. set из k + 1 чисел нашёл бы этот повтор по ошибке.

Время: n проверок, n добавлений и не больше n удалений, в среднем O(n) для Hash Table; при плохих хешах возможно O(n²). Дополнительная память: до k + 1 чисел в set, O(min(n, k + 1)). Ответ - True или False. Brute Force сравнивает пары на расстоянии до k: при n = k = 100 000 это 4 999 950 000 пар.

4. Счётчики букв и dict: LeetCode 438 и 2461

s = "cbaebabacd", p = "abc". Две строки - Anagram, если в них одинаковые счётчики букв. Из окон длины 3 подходят cba и bac, ответ [0, 6].

Правило. При сдвиге два обновления: +1 для вошедшей буквы и −1 для вышедшей. Если это одна буква, её счётчик не меняется. Сравнивайте счётчики окна со счётчиками p.

s = "cbaebabacd"
p = "abc"
k = len(p)
need = [0] * 26
have = [0] * 26
for c in p:
    need[ord(c) - 97] += 1
res = []
for r in range(len(s)):
    have[ord(s[r]) - 97] += 1
    if r >= k:
        have[ord(s[r - k]) - 97] -= 1
    if r >= k - 1 and have == need:
        res.append(r - k + 1)
print(res)

Код печатает [0, 6]. ord("a") = 97, поэтому ord(c) − 97 даёт место буквы: a → 0, b → 1, z → 25.

Здесь have получает 10 прибавлений и 7 вычитаний, а код делает 8 сравнений двух list по 26 чисел. Время: O(m + 26n), где n = len(s), m = len(p); для алфавита из 26 букв это O(n + m). Дополнительная память: два list по 26 чисел, O(1) для этого алфавита. Ответ отдельно: до n − m + 1 номеров.

LeetCode 2461: dict cnt хранит счётчики чисел окна, total - сумму окна. Окно подходит, когда len(cnt) == k: все k чисел разные. Когда счётчик стал 0, удалите ключ, иначе len(cnt) считает число, которого уже нет в окне. Для [1, 5, 4, 2, 9, 9, 9], k = 3 подходят окна с суммами 10, 11 и 15, ответ 15. Время: в среднем O(n). Дополнительная память: до k + 1 ключей, O(k).

Сравнение способов для Anagram

Sorting каждого окна: n − m + 1 окон, каждое за O(m log m) времени и O(m) памяти. Счётчик совпадений: храните число букв, у которых have и need равны; при сдвиге он меняется только для двух букв, и шаг стоит O(1) без 26 сравнений. collections.Counter - это dict для счётчиков, сравнение двух Counter проверяет все ключи.

5. Постоянная часть и выигрыш окна: Codeforces 961B

a = [1, 3, 5, 2, 5, 4], t = [1, 1, 0, 1, 0, 0], k = 3. Когда Миша не спит (t = 1), он записывает теоремы сам: 1 + 3 + 2 = 6. Окно добавляет только теоремы минут сна. Выигрыши окон: 5, 5, 10, 9. Ответ 6 + 10 = 16.

Правило. Если окно меняет только часть ответа, посчитайте постоянную часть один раз. Sliding Window ищет наибольший выигрыш окна.

base = 0
gain = 0
for i in range(n):
    if t[i] == 1:
        base += a[i]
    elif i < k:
        gain += a[i]
best = gain
for r in range(k, n):
    gain += a[r] * (1 - t[r]) - a[r - k] * (1 - t[r - k])
    best = max(best, gain)
print(base + best)

a[r] · (1 − t[r]) - выигрыш минуты r: a[r], если Миша спит, и 0, если нет. Для примера код печатает 16.

Время: один проход для основы и один для окон, O(n). Дополнительная память: O(1), если выигрыш a[i] при t[i] = 0 считать на месте; отдельный list выигрышей займёт O(n). Вход a и t занимает O(n), ответ - одно число.

6. Что нужно запомнить

  • При сдвиге окна длины k меняются два элемента: a[r] входит, a[r − k] выходит.
  • Храните только то, что нужно знать об окне: сумму, число нужных элементов, счётчики или set.
  • Время O(n) получается, когда одно обновление стоит O(1). Сравнение двух list по 26 чисел стоит 26 шагов.
  • Срез a[l:r] создаёт копию: O(r − l) времени и памяти.

7. Как решать задачи этой главы

  1. Найдите длину окна k и то, что нужно знать об окне.
  2. Запишите, как меняется это знание, когда один элемент вошёл, а другой вышел.
  3. Проверьте первое и последнее окно: r = k − 1 и r = n − 1.
  4. Посчитайте время и дополнительную память, ответ отдельно.
