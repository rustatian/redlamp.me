Для каждой правой границы r найдите все хорошие начала l: их число и есть вклад окон с концом r в ответ.

Правило r − l + 1 вы уже видели в главе 3 набора Heap (Priority Queue), Queue и Deque (LeetCode 2762): для каждого r найдите самую левую допустимую l и прибавьте r − l + 1. Раздел 1 только напоминает его. Новые правила этой главы: окна не короче k, граница от каждого элемента, «хотя бы» и «ровно K». Ответ может быть до n(n + 1)/2, поэтому выписывать окна нельзя. Дополнительная память считается без входа и ответа.

1. Напоминание: окна с концом r (LeetCode 713)

nums = [10, 5, 2, 6], k = 100. Считаем Subarray с произведением меньше 100. При r = 3 окно [5, 2, 6] хорошее, и хороши все окна с концом 3 внутри него: [6], [2, 6], [5, 2, 6]. Это 3 = r − l + 1 окна.

Правило. Пусть любая часть хорошего окна тоже хорошая. Тогда при конце r хорошие начала - это l, l + 1, ..., r, где l - самое левое хорошее начало. Прибавьте r − l + 1.

nums = [10, 5, 2, 6]
k = 100
prod = 1
l = 0
res = 0
for r in range(len(nums)):
    prod *= nums[r]
    while l <= r and prod >= k:
        prod //= nums[l]
        l += 1
    res += r - l + 1
print(res)

Код печатает 8: вклады 1, 2, 2, 3. Новое здесь - ловушка k ≤ 1. Тогда даже одно число не меньше k, и окно становится пустым. Без условия l <= r цикл while уведёт l правее r.

Здесь 4 умножения, 1 деление и 4 прибавления к ответу. Время: n умножений и не больше n делений, O(n). Дополнительная память: O(1); произведение окна меньше k · 1000 ≤ 109. Brute Force перебирает n(n + 1)/2 окон: 10 здесь и 450 015 000 при n = 30 000. Лимит 2 с на пример, 3 с на скрытый тест: 450 015 000 умножений Python не успеет.

Brute Force для сравнения

Для каждого начала i код умножает числа вправо и останавливается, когда произведение стало не меньше k:

res = 0
for i in range(n):
    prod = 1
    for j in range(i, n):
        prod *= nums[j]
        if prod >= k:
            break
        res += 1

Остановка помогает, когда числа большие. Для 30 000 единиц и k = 106 произведение всегда 1, и код делает все 450 015 000 умножений. Окно делает 30 000 умножений.

2. Окна не короче k: Codeforces 1840C

a = [0, 3, −2, 5, −4, −4], k = 1, q = 3. Подходят дни с a ≤ q. Для каждого r берём L - число подходящих дней подряд, которые кончаются на r.

Ответ 9. Для a = [12, 12, 10, 15], k = 3, q = 12 значения L равны 1, 2, 3, 0, а вклады 0, 0, 1, 0: подходит только [12, 12, 10].

Правило. Если окно должно иметь длину не меньше k, при конце r подходят начала l..r − k + 1. Прибавьте max(0, L − k + 1), где L = r − l + 1.

run = 0
res = 0
for x in a:
    if x <= q:
        run += 1
    else:
        run = 0
    res += max(0, run - k + 1)

Время: O(n) на набор, O(Σn) на весь вход. Дополнительная память: O(1). Ответ до n(n + 1)/2: при n = 200 000 это 20 000 100 000, больше 2 147 483 647. В Python целое число растёт само.

Проверка формулой

Блок из L ≥ k подходящих дней даёт ненулевые вклады 1, 2, ..., L − k + 1. Их сумма (L − k + 1)(L − k + 2)/2. Для a = [5, 5, 5, 5], k = 2, q = 5: L = 4, вклады 0, 1, 2, 3, сумма 6 = 3 · 4 / 2. Разбор задачи на Codeforces считает ответ этой формулой для каждого блока.

3. Каждый элемент ограничивает начало: Codeforces 1736C1

a = [2, 1, 4, 3]. Subarray хороший, если каждый его элемент на месте i (места с 1) не меньше i.

В Subarray с началом l элемент a[r] стоит на месте r − l + 1. Условие a[r] ≥ r − l + 1 даёт l ≥ r − a[r] + 1. Это условие не зависит от конца окна. Часть хорошего Subarray тоже хорошая: если убрать первый элемент, место каждого другого элемента уменьшится на 1, и условие станет только легче. Поэтому работает правило раздела 1, нужно только найти l.

Правило. Если каждый элемент запрещает начала левее своей границы, держите l = max(l, граница). Граница l только растёт, и при конце r хороших начал r − l + 1.

Время: O(n) на набор. Дополнительная память: O(1). Brute Force продлевает каждое начало вправо: n(n + 1)/2 проверок, при n = 200 000 это 20 000 100 000.

4. «Хотя бы»: прибавляем l (LeetCode 1358)

s = "abcabc". Нужны подстроки, где есть хотя бы по одной букве a, b и c. Если окно хорошее, то окно, продлённое влево, тоже хорошее. Поэтому хорошие начала с концом r - это 0, 1, ..., l − 1.

Правило. Если любое окно, которое содержит хорошее окно, тоже хорошее, сжимайте окно, пока оно хорошее. После while начала 0, 1, ..., l − 1 дают хорошие окна с концом r: прибавьте l.

s = "abcabc"
cnt = {"a": 0, "b": 0, "c": 0}
l = 0
res = 0
for ch in s:
    cnt[ch] += 1
    while cnt["a"] > 0 and cnt["b"] > 0 and cnt["c"] > 0:
        cnt[s[l]] -= 1
        l += 1
    res += l
print(res)

Код печатает 10. Здесь 6 прибавлений к счётчикам, 4 вычитания и вклады 0, 0, 1, 2, 3, 4. Время: O(n). Дополнительная память: O(1): три счётчика.

Типичная ошибка - прибавить r − l + 1, как в разделе 1. После while окно [l, r] плохое, и r − l + 1 считает плохие окна. Для "abcabc" получится 1 + 2 + 2 + 2 + 2 + 2 = 11: это 21 − 10, число окон без одной из букв.

Другой способ: последние места букв

Храните last[c] - последнее место буквы c до r включительно. Окно с концом r хорошее, если его начало не правее min(last[a], last[b], last[c]). Когда все три буквы уже были, прибавьте этот минимум + 1. Для "abcabc" при r = 5 места 3, 4, 5, и вклад 3 + 1 = 4. Время O(n), память O(1).

5. Ровно K: две задачи «не больше» (LeetCode 992)

nums = [1, 2, 1, 2, 3], k = 2. «Ровно 2 разных» не подходит под правило раздела 1: окно [1, 2, 1] хорошее, а его часть [1] плохая. «Не больше K разных» подходит: в части окна разных чисел не больше, чем во всём окне.

Правило. Число окон, где ровно K разных чисел, равно числу окон, где их не больше K, минус число окон, где их не больше K − 1.

def at_most(nums, m):
    cnt = {}
    l = 0
    res = 0
    for r in range(len(nums)):
        x = nums[r]
        cnt[x] = cnt.get(x, 0) + 1
        while len(cnt) > m:
            y = nums[l]
            cnt[y] -= 1
            if cnt[y] == 0:
                del cnt[y]
            l += 1
        res += r - l + 1
    return res

nums = [1, 2, 1, 2, 3]
print(at_most(nums, 2), at_most(nums, 1), at_most(nums, 2) - at_most(nums, 1))

Код печатает 12 5 7. Время: два прохода по n шагов, в среднем O(n) для Hash Table. Дополнительная память: dict до K + 1 ключей, O(min(n, K + 1)). Brute Force с set для каждого начала: n(n + 1)/2 шагов, при n = 20 000 это 200 010 000.

При k = 1 второй проход at_most(nums, 0) даёт 0: while убирает каждое число сразу после добавления.

Почему не одна граница l

Для «ровно K» хорошие начала с концом r лежат между двумя границами: левее в окне больше K разных, правее - меньше K. Первая граница - l прохода «не больше K», вторая - l прохода «не больше K − 1». При r = 4 это начала от 3 до 3: одно окно [2, 3], и 2 − 1 = 1 в разности вкладов.

6. Что нужно запомнить

  • Если любая часть хорошего окна хорошая, при конце r прибавляйте r − l + 1.
  • Если окно должно быть не короче k, прибавляйте max(0, L − k + 1).
  • Если окно, которое содержит хорошее окно, тоже хорошее, сжимайте, пока оно хорошее, и прибавляйте l.
  • «Ровно K» = «не больше K» − «не больше K − 1».

7. Как решать задачи этой главы

  1. Проверьте, что происходит с хорошим окном, если убрать или добавить элемент слева или справа.
  2. Выберите вклад: r − l + 1, max(0, L − k + 1) или l.
  3. Для «ровно K» напишите функцию для «не больше m» и вызовите её дважды.
  4. Оцените наибольший ответ: n(n + 1)/2 может быть больше 32-битного целого.
