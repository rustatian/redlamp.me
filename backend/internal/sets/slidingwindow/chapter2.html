В окне переменной длины правая граница r идёт вперёд на каждом шаге, а левая граница l догоняет её, только когда окно стало плохим.

Вы уже видели такие окна: в главе 4 набора Two Pointers сумма положительных чисел не больше S, в главе 3 набора Heap (Priority Queue), Queue и Deque условие max − min ≤ limit. Здесь окно хранит счётчики и Hash Table. Окно [l, r] хорошее, если оно выполняет условие задачи. Дополнительная память считается без входа и ответа.

1. Шаблон: расширить справа, сжать слева

LeetCode 1004: nums = [1, 0, 1, 1, 0, 0, 1], k = 1. Можно заменить на 1 не больше одного нуля, поэтому окно хорошее, если в нём не больше k нулей. Самое длинное хорошее окно [1, 0, 1, 1], длина 4.

Правило. Добавьте nums[r]. Пока окно плохое, убирайте nums[l] и увеличивайте l. После этого окно [l, r] хорошее: обновите ответ длиной r − l + 1.

nums = [1, 0, 1, 1, 0, 0, 1]
k = 1
l = 0
zeros = 0
best = 0
for r in range(len(nums)):
    if nums[r] == 0:
        zeros += 1
    while zeros > k:
        if nums[l] == 0:
            zeros -= 1
        l += 1
    best = max(best, r - l + 1)
print(best, l)

Код печатает 4 5: лучшая длина 4, а в конце l = 5. LeetCode 485 - тот же шаблон при k = 0: ноль сразу делает окно плохим, и l переходит за него.

Здесь r сделал 7 шагов, l - 5 шагов: 2 на шаге r = 4 и 3 на шаге r = 5. Время: r делает n шагов, l за весь проход не больше n шагов, всего не больше 2n сдвигов: O(n). Вложенный while не даёт O(n²), потому что l никогда не уменьшается. Дополнительная память: O(1) для l, zeros и best. Brute Force проверяет каждое начало и идёт вправо: до n(n + 1)/2 шагов, при n = 100 000 и k = n это 5 000 050 000. Лимит 2 с на пример, 3 с на скрытый тест: столько шагов Python не успеет.

Brute Force для сравнения

Для каждого начала i код идёт вправо, пока в окне не больше k нулей:

best = 0
for i in range(n):
    zeros = 0
    for j in range(i, n):
        if nums[j] == 0:
            zeros += 1
        if zeros > k:
            break
        best = max(best, j - i + 1)

При k = n внутренний цикл не прерывается: n + (n − 1) + ... + 1 = n(n + 1)/2 шагов. Шаблон делает те же проверки, но не начинает каждое окно заново.

2. Когда шаблон работает

Найдём самое длинное окно с суммой не больше S = 2 в a = [5, −4, 1]. Шаблон убирает 5 на первом шаге и больше к нему не возвращается. Он ответит 2, а окно [5, −4, 1] имеет сумму 2 и длину 3.

Правило. Шаблон верен, если плохое окно остаётся плохим после расширения вправо. Тогда отброшенное начало больше не понадобится. С отрицательными числами сумма может снова уменьшиться, и шаблон ошибается.

Вы уже видели это условие. В главе 4 набора Two Pointers при отрицательных числах правило удаления не работает. В главе 3 набора Heap (Priority Queue), Queue и Deque (LeetCode 2398) расширение не уменьшает цену, поэтому отвергнутую левую границу возвращать не нужно. Нули в задаче 1004, повторы в LeetCode 3 и три вида в задаче 904 этому правилу подходят: новый элемент не убирает старый ноль, старый повтор или старый вид. Самый короткий Subarray с суммой не меньше k при отрицательных числах решает глава 4.

3. Hash Table в окне: LeetCode 3 и 904

s = "pwwkew". Окно хорошее, если в нём нет повторов.

Ответ 3.

Правило. Новый символ c может испортить только свой счётчик. Сжимайте окно, пока cnt[c] > 1.

cnt[c] = cnt.get(c, 0) + 1
while cnt[c] > 1:
    cnt[s[l]] -= 1
    l += 1
best = max(best, r - l + 1)

Время: n добавлений и не больше n удалений, в среднем O(n) для Hash Table. Дополнительная память: dict хранит не больше min(n, σ) ключей, где σ - число разных символов; в задаче σ ≤ 95.

LeetCode 904: fruits[i] - вид фрукта на дереве i, окно хорошее, если в нём не больше двух видов. dict cnt хранит счётчики видов окна. Пока len(cnt) > 2, убирайте fruits[l] и сдвигайте l. Ключ со счётчиком 0 удалите, иначе len(cnt) считает вид, которого уже нет в окне. Для [0, 1, 1, 2, 1] при r = 3 приходит третий вид: l убирает 0, окно [1, 1, 2]. Ответ 4: окно [1, 1, 2, 1]. Если при третьем виде начинать окно с прошлого дерева, получится [1, 2, 1] и ответ 3. Время: O(n). Дополнительная память: не больше трёх ключей, O(1).

Перебор начал для LeetCode 3 останавливается на первом повторе: не больше σ + 1 шагов на начало, O(n · σ). В задаче 904 на деревьях двух видов перебор от каждого начала идёт до конца: при n = 100 000 это 5 000 050 000 шагов.

Вариант с последним номером символа

Храните last[c] - последний номер символа c. При повторе ставьте l = max(l, last[c] + 1). Без max для "abba" граница l вернётся с 2 на 1, и код ответит 3 вместо 2. Время O(n), память O(min(n, σ)).

4. Удаления с двух концов: Codeforces 1692E

a = [0, 1, 0, 1, 1, 1, 0, 0, 1], s = 3. После удалений с концов остаётся непрерывная часть. Самое длинное окно с суммой 3 занимает номера 2..7, длина 6. Ответ 9 − 6 = 3.

Правило. Удаления с двух концов оставляют одно окно. Найдите самое длинное окно с суммой не больше s и вычтите его длину из n. Если сумма всего Array меньше s, ответ −1.

Числа 0 и 1 не отрицательные, поэтому шаблон верен. Если сумма всего Array не меньше s, у самого длинного окна с суммой не больше s сумма ровно s: иначе окно можно расширить на один элемент, и сумма вырастет не больше чем на 1.

if sum(a) < s:
    print(-1)
else:
    total = 0
    l = 0
    best = 0
    for r in range(n):
        total += a[r]
        while total > s:
            total -= a[l]
            l += 1
        best = max(best, r - l + 1)
    print(n - best)

Время: O(n) на набор, O(Σn) на весь вход. Дополнительная память: O(1) сверх входа. Перебор числа удалений слева и справа даёт O(n²): при n = 200 000 это около 2 · 1010 пар.

Другой способ: Prefix Sum и Binary Search

Можно перебрать левую границу и для каждой найти Binary Search по Prefix Sum самую дальнюю правую границу с суммой s. Это O(n log n) времени и O(n) памяти для list p. Окно решает задачу за O(n) времени и O(1) памяти.

5. Самое короткое окно: LeetCode 76

s = "bdab", t = "ab". Нужно самое короткое окно, в котором есть все символы t с повторами. Ответ "ab".

Здесь шаблон другой: расширяем окно, пока оно плохое, и сжимаем, пока оно хорошее. need[c] - сколько символов c ещё нужно; отрицательное число - лишние символы c в окне. missing - сколько символов t не хватает всего.

Правило. Для самого короткого окна обновляйте ответ внутри while: пока окно хорошее, запишите длину и сожмите окно на один символ.

s = "bdab"
t = "ab"
need = {}
for c in t:
    need[c] = need.get(c, 0) + 1
missing = len(t)
l = 0
best_len, best_l = len(s) + 1, 0
for r in range(len(s)):
    c = s[r]
    if need.get(c, 0) > 0:
        missing -= 1
    need[c] = need.get(c, 0) - 1
    while missing == 0:
        if r - l + 1 < best_len:
            best_len, best_l = r - l + 1, l
        need[s[l]] += 1
        if need[s[l]] > 0:
            missing += 1
        l += 1
print(s[best_l:best_l + best_len] if best_len <= len(s) else "", l)

Код печатает ab 3. Здесь r сделал 4 шага, l - 3 шага, ответ обновлён 2 раза. Время: n шагов для need, m шагов r и не больше m шагов l, где m = len(s), n = len(t): O(m + n). Дополнительная память: need хранит не больше 52 ключей (латинские буквы), O(1) для такого алфавита. Код хранит начало и длину ответа и делает срез один раз: O(длина ответа) для строки ответа.

Почему не запоминать срез при каждом улучшении

best = s[l:r + 1] при каждом улучшении копирует строку. Улучшений может быть до m, и копии вместе в худшем случае стоят O(m²) времени. Номер начала и длина стоят O(1).

6. Что нужно запомнить

  • Правая граница добавляет, левая убирает; обе идут только вправо.
  • Самое длинное окно: ответ после while. Самое короткое окно: ответ внутри while.
  • Шаблон верен, только если плохое окно остаётся плохим при расширении вправо.
  • Если важно число ключей dict, удаляйте ключи со счётчиком 0.

7. Как решать задачи этой главы

  1. Назовите хорошее окно одной фразой.
  2. Проверьте, что расширение плохого окна не делает его хорошим.
  3. Решите, где обновлять ответ: после while или внутри него.
  4. Считайте шаги l за весь проход, а не за один шаг r.
