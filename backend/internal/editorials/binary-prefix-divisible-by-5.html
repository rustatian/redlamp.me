Двоичная запись 101 даёт префиксы 1, 10 и 101. Для префикса 10 начнём с остатка 0. После единицы получим (2 · 0 + 1) % 5 = 1, а после нуля получим (2 · 1 + 0) % 5 = 2. Конечный остаток отличен от нуля, поэтому ответ для 10 равен False. Если так пересчитать остаток для каждого префикса с начала, получится 1 + 2 + 3 = 6 прочитанных битов. Для n битов в nums такой Brute Force прочитает n · (n + 1) / 2 битов. При n = 100 000 это 5 000 050 000 чтений. Каждое чтение обновляет остаток от 0 до 4 за O(1) времени. Такой пересчёт занимает O(n²) времени в худшем случае.

Решение 1. Остаток префикса

В двоичной записи 110 две единицы дают 4 + 2 = 6. Если дописать справа ноль, получится 1100, то есть 8 + 4 = 12. Вес каждой прежней цифры удвоился. Если справа дописать бит bit, число x станет равно 2 · x + bit.

Число 12 при делении на 5 даёт остаток 2. Допишем справа единицу. С полным числом получим 2 · 12 + 1 = 25, а с остатком получим 2 · 2 + 1 = 5. Разница равна 20 и делится на 5. Заменяя число его остатком r, мы отбрасываем слагаемое, кратное 5. Удвоение сохраняет делимость этого слагаемого на 5, а bit в обоих расчётах одинаков. Поэтому (2 * r + bit) % 5 даёт остаток нового префикса.

До первого бита r = 0, а ответ пока пуст. Если первый бит равен 0, остаток остаётся нулём и код добавляет True. Для nums = [1, 1, 0, 0, 1] получаем остатки 1, 3, 1, 2, 0. Только последний префикс делится на 5, поэтому только для него проверка r == 0 даёт True.

class Solution:
    def prefixesDivBy5(self, nums: list[int]) -> list[bool]:
        answer = []
        r = 0
        for bit in nums:
            r = (2 * r + bit) % 5
            answer.append(r == 0)
        return answer

Время: O(n) в худшем случае. Цикл проходит по nums один раз. Перед % получается не больше 2 · 4 + 1 = 9, так как r лежит от 0 до 4. Дополнительная память: O(1) в худшем случае. Кроме входа и ответа, нужны только текущий бит и остаток. В ответе n значений.

Решение 2. Сумма по группам из четырёх битов

Разделим 11001 слева на группы по четыре бита и допишем справа три нуля. Получатся группы 1100 и 1000 со значениями 12 и 8. Дописанные нули умножили исходное число 25 на 8. Каждый такой ноль удваивает число. Если остаток равен 1, 2, 3 или 4, его удвоенное значение равно 2, 4, 6 или 8. Ни одно из этих значений не делится на 5, а удвоенный ноль равен нулю. Поэтому дописанные нули сохраняют ответ для каждого префикса.

Число из этих двух групп равно 12 · 16 + 8 = 200, а сумма их значений равна 12 + 8 = 20. Разница равна 15 · 12 и делится на 5. Допишем третью группу 0001 и получим 16 · 200 + 1 = 3201. У 200 и 20 остаток равен 0. Поэтому 200 + 1 = 201 и сумма групп 20 + 1 = 21 дают остаток 1, как и 3201.

При записи следующих четырёх битов число x умножается на 16, затем к нему прибавляется значение группы b. Выражения 16 · x + b и x + b дают одинаковый остаток, так как разница равна 15 · x. Прибавление b к x и к прежней сумме групп сохраняет их разность. Значит, для проверки делимости достаточно сложить значения всех групп.

В группе 1100 единицы дают 8 + 4, а первая единица следующей группы снова даёт 8. Так для битов слева направо повторяются веса 8, 4, 2, 1. Пока группа неполна, свободные места справа считаем нулями. При i = 4 выражение i % 4 снова даёт индекс первого веса. Бит на позиции i прибавляет к сумме bit * weights[i % 4]. Переменная total хранит остаток этой суммы при делении на 5.

class Solution:
    def prefixesDivBy5(self, nums: list[int]) -> list[bool]:
        weights = (8, 4, 2, 1)
        total = 0
        answer = []
        for i, bit in enumerate(nums):
            total = (total + bit * weights[i % 4]) % 5
            answer.append(total == 0)
        return answer

Время: O(n) в худшем случае. Для каждого бита код один раз выбирает вес и обновляет total. Дополнительная память: O(1) в худшем случае. Четыре веса и переменные цикла занимают постоянную память сверх входа и ответа.
