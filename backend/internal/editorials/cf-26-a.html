12 = 2 · 2 · 3, поэтому у числа 12 два разных простых делителя: 2 и 3. Чтобы посчитать разные простые делители для каждого числа от 1 до n, заведём список счётчиков factors длины n + 1 из нулей и будем перебирать p от 2 до n по возрастанию. Чтобы учесть двойку один раз, при p = 2 пройдём по кратным 2: 2, 4, 6, 8, 10, 12 и так далее. При каждом таком шаге прибавим единицу к счётчику этого кратного в factors.

Когда дойдём до 3, его счётчик ещё равен нулю: тройка не делится на 2. А у числа 4 уже есть отметка от двойки. Любое простое число p не делится ни на одно меньшее простое число, поэтому его счётчик остаётся нулевым до своего шага. У каждого составного числа есть меньший простой делитель, который уже отметил это число. Значит, в момент проверки factors[p] == 0 выполнено для каждого простого p и только для него. Поэтому идти по кратным p нужно именно при этом условии.

Каждый простой делитель прибавляет единицу ровно один раз к счётчику каждого своего кратного. Остаётся посчитать, сколько счётчиков равны двум. До 10 включительно подходят 6 и 10. У единицы счётчик остаётся нулевым.

До 27 включительно есть 11 почти простых чисел. Само число 27 = 33 имеет только один простой делитель. У числа 28 = 22 · 7 их два, поэтому ответ растёт до 12. При n = 30 ответ остаётся тем же: число 29 простое, а у числа 30 = 2 · 3 · 5 три разных простых делителя.

n = int(input())
factors = [0] * (n + 1)
for p in range(2, n + 1):
    if factors[p] == 0:
        for multiple in range(p, n + 1, p):
            factors[multiple] += 1
answer = factors.count(2)
print(answer)

Время: O(n log log n) в худшем случае. Для каждого простого p внутренний цикл делает по одному шагу на каждые p чисел. При n = 10 для простых чисел 2, 3, 5, 7 получается 5 + 3 + 2 + 1 = 11 прибавлений. Для каждого простого p их число равно n // p, поэтому n // p ≤ n · (1/p). Сложим эти оценки для всех простых p ≤ n и вынесем n за скобки: при n = 10 получаем 11 ≤ 10 · (1/2 + 1/3 + 1/5 + 1/7). Для произвольного n сумма обратных величин 1/p по всем простым числам p ≤ n растёт как log(log n). Запись log log n означает log(log n): сначала считают log n, а потом берут логарифм от результата. Например, при n = 3000 получаем log2 3000 < 12, так как 3000 < 4096 = 212. Второй логарифм ещё меньше: log2(log2 3000) < 4, так как 12 < 16 = 24. Сумма дробей 1/p по простым числам до 3000 равна около 2,34, а внутренний цикл делает 6846 прибавлений. Отсюда при умножении n на сумму дробей 1/p в оценке времени появляется множитель log log n. Создание списка и окончательный подсчёт двоек требуют ещё O(n) времени. Дополнительная память: O(n) в худшем случае. В списке n + 1 счётчиков. Программа решает один случай, поэтому это оценки для всего запуска. При чтении одной строки и при печати одного ответа временно требуется O(log n) символов. Списка ответов нет.
