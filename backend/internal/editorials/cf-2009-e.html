Нужно найти место разреза i, при котором сумма левой части Array ближе всего к сумме правой части.

Как выглядит x

Пример: n = 5, k = 3, a = [3, 4, 5, 6, 7], сумма всех чисел равна 25. Индекс i делит Array на левую часть из первых i чисел и правую часть из остальных. При i = 3 левая часть равна 3 + 4 + 5 = 12, правая равна 6 + 7 = 13, поэтому x = |12 − 13| = 1. Правая часть равна 25 − 12, поэтому x = |12 − (25 − 12)| = |2 · 12 − 25|.

Пусть S(i) = a1 + ... + ai - сумма первых i чисел. Для любого i левая часть равна S(i), правая равна S(n) − S(i), и x = |2 · S(i) − S(n)|. Обозначим d(i) = 2 · S(i) − S(n). Тогда x = |d(i)|.

В примере d(i) равно −19, −11, −1, 11, 25 при i = 1, 2, 3, 4, 5, а x = |d(i)| равно 19, 11, 1, 11, 25. Наименьшее x равно 1.

d(i) растёт: d(i + 1) − d(i) = 2 · ai+1, а все числа Array положительные. В примере разности равны 8, 10, 12, 14: это 2 · 4, 2 · 5, 2 · 6, 2 · 7. Поэтому d(i) переходит от отрицательных значений к неотрицательным не больше одного раза. Решение 1 ниже показывает, что d(1) < 0 < d(n), поэтому переход есть.

Пусть lo - первый i с d(i) ≥ 0. Для i < lo числа d(i) отрицательные и растут, поэтому |d(i)| уменьшается: в примере 19, 11, 1 при i = 1, 2, 3. Для i ≥ lo числа d(i) неотрицательные и растут, поэтому |d(i)| растёт: 11, 25 при i = 4, 5. Значит, наименьшее x стоит в lo − 1 или в lo, и ответ равен min(|d(lo − 1)|, |d(lo)|). В примере lo = 4 и ответ min(1, 11) = 1.

Array из 109 чисел хранить нельзя: даже по 1 байту на число это 109 байт, а лимит памяти равен 256 мегабайтам. Но S(i) считается по формуле S(i) = i · k + i(i − 1) / 2: число k входит в сумму i раз, а добавки 0 + 1 + ... + (i − 1) дают i(i − 1) / 2. Для i = 4 получается S(4) = 3 + 4 + 5 + 6 = 4 · 3 + (0 + 1 + 2 + 3) = 12 + 6 = 18. Поэтому d(i) считается по формуле, без цикла по i.

Brute Force проходит i = 1, 2, ..., n и считает d(i) по формуле, то есть делает O(n) вычислений на набор. При n = 109 это 109 вычислений d, а при t = 104 наборов около 1013: слишком долго.

Решение 1. Binary Search

Binary Search ищет lo: условие d(i) ≥ 0 идёт «нет, ..., нет, да, ..., да», и lo - первое «да», то есть Lower Bound.

Поиск хранит отрезок [lo, hi], в котором лежит первое «да», и сужает его, пока lo не станет равно hi. Сначала отрезок равен [2, n]. Число d(1) = 2 · k − S(n) отрицательное: при n ≥ 2 сумма S(n) не меньше a1 + a2 = 2 · k + 1. Для n = 2, k = 2 получается 4 − 5 = −1. Значит, i = 1 не бывает первым «да», и поиск начинается с lo = 2. Число d(n) = S(n) положительное, поэтому на [2, n] первое «да» есть.

Пример: n = 7, k = 2, a = [2, 3, 4, 5, 6, 7, 8], S(7) = 35, d = [-31, -25, -17, -7, 5, 19, 35]. Поиск идёт на [2, 7]. Сначала mid = (2 + 7) // 2 = 4 и d(4) = −7 < 0: первое «да» правее, lo = 5. Потом mid = (5 + 7) // 2 = 6 и d(6) = 19 ≥ 0, поэтому hi = 6. Потом mid = (5 + 6) // 2 = 5 и d(5) = 5 ≥ 0, поэтому hi = 5. Теперь lo = hi = 5 после 3 проверок, и ответ равен min(|d(4)|, |d(5)|) = min(7, 5) = 5.

Индекс lo − 1 настоящий, потому что lo ≥ 2.

import sys


def d(i, k, total):
    return 2 * (i * k + i * (i - 1) // 2) - total


data = sys.stdin.buffer.read().split()
t = int(data[0])
out = []
for case in range(t):
    n, k = int(data[1 + 2 * case]), int(data[2 + 2 * case])
    total = n * k + n * (n - 1) // 2
    # d(1) < 0 и d(n) > 0: первый i с d(i) >= 0 лежит на [2, n]
    lo, hi = 2, n
    while lo < hi:
        mid = (lo + hi) // 2
        if d(mid, k, total) >= 0:
            hi = mid
        else:
            lo = mid + 1
    out.append(min(abs(d(lo - 1, k, total)), abs(d(lo, k, total))))
print("\n".join(map(str, out)))

Каждая проверка оставляет не больше половины значений (с округлением вверх): из 6 значений i на [2, 7] остаются 3, потом 2 и 1.

Время: O(log n) на набор в худшем случае. На отрезке [2, n] не больше 109 − 1 чисел, а 229 < 109 − 1 ≤ 230, поэтому проверок не больше 30. Для t = 104 наборов это не больше 3 · 105 проверок. Дополнительная память: O(1) на набор в худшем случае: хранятся числа n, k, total, lo, hi и mid, и их количество не зависит от n. Вход (список data) и ответ (список out) считаем отдельно.

Решение 2. Math

Формулу d(i) можно упростить: 2 · (i · k + i(i − 1) / 2) = 2 · i · k + i2 − i, поэтому d(i) = i2 + b · i − S(n), где b = 2 · k − 1. Для n = 5, k = 3 получается b = 5 и S(5) = 25. Тогда d(3) = 9 + 15 − 25 = −1 и d(4) = 16 + 20 − 25 = 11.

Ответ стоит рядом с корнем уравнения d(i) = 0, то есть i2 + b · i − S(n) = 0. Для него дискриминант D = b2 − 4 · 1 · (−S(n)) = b2 + 4 · S(n), а положительный корень равен (−b + √D) / 2. Второй корень отрицательный, он не нужен. В примере D = 25 + 100 = 125, √125 ≈ 11,18, а корень равен (11,18 − 5) / 2 ≈ 3,09: он лежит между i = 3 и i = 4.

Пусть r - целая часть корня, в примере r = 3. Тогда d(r) ≤ 0 < d(r + 1), а d растёт, поэтому ответ равен min(|d(r)|, |d(r + 1)|). В примере это min(|−1|, 11) = 1.

Целую часть √D даёт isqrt: isqrt(125) равен 11, а √125 ≈ 11,18. Тогда r = (isqrt(D) − b) // 2 = (11 − 5) // 2 = 3.

Эта формула даёт целую часть корня для любых n и k. Целая часть r - наибольшее целое m, для которого (√D − b) / 2 ≥ m. Это неравенство равносильно 2 · m + b ≤ √D. Число 2 · m + b целое, поэтому 2 · m + b ≤ √D тогда и только тогда, когда 2 · m + b ≤ isqrt(D). В примере для m = 3 число 2 · m + b = 11 подходит: 11 ≤ 11,18 и 11 ≤ 11. Для m = 4 число 13 не подходит: 13 > 11,18 и 13 > 11. Значит, r - наибольшее целое m с 2 · m ≤ isqrt(D) − b, то есть (isqrt(D) − b) // 2. Если isqrt(D) − b нечётное, деление // округляет вниз: для n = 7, k = 2 получается D = 149, isqrt(149) = 12 и r = (12 − 3) // 2 = 4.

Индексы r и r + 1 настоящие: d(1) < 0 < d(n), поэтому корень лежит между 1 и n, и оба индекса лежат на [1, n]. Для n = 2, k = 2 получается D = 9 + 20 = 29, isqrt(29) = 5, r = (5 − 3) // 2 = 1, ответ min(|d(1)|, |d(2)|) = min(1, 5) = 1.

import sys
from math import isqrt


def d(i, k, total):
    return 2 * (i * k + i * (i - 1) // 2) - total


data = sys.stdin.buffer.read().split()
t = int(data[0])
out = []
for case in range(t):
    n, k = int(data[1 + 2 * case]), int(data[2 + 2 * case])
    total = n * k + n * (n - 1) // 2
    # d(i) = i * i + b * i - total: корень уравнения d(i) = 0 лежит между r и r + 1
    b = 2 * k - 1
    r = (isqrt(b * b + 4 * total) - b) // 2
    out.append(min(abs(d(r, k, total)), abs(d(r + 1, k, total))))
print("\n".join(map(str, out)))

Время: O(1) на набор в худшем случае: одна формула, один isqrt и два вычисления d. Число D растёт вместе с n и k, поэтому при n, k ≤ 109 оно наибольшее при n = k = 109: D = 9 999 999 994 000 000 001, в нём 19 цифр. Поэтому один isqrt занимает ограниченное время. Для t = 104 наборов это 104 таких вычислений. Дополнительная память: O(1) на набор в худшем случае: хранятся числа n, k, total, b и r, и их количество не зависит от n и k. Вход (список data) и ответ (список out) считаем отдельно.

Типичные ошибки

  • Брать только d(lo). Для n = 5, k = 3 получается |d(4)| = 11 вместо 1.
  • Брать только d(lo − 1). Для n = 7, k = 2 получается |d(4)| = 7 вместо 5.
  • Искать i с d(i) = 0. Для n = 7, k = 2 среди значений d(i) нуля нет, а ответ равен 5.
  • Писать / 2 вместо // 2 в формуле S(i). Деление / даёт дробное число (float), а float хранит все целые числа точно только до 253 ≈ 9 · 1015, и S(i) доходит до 1,5 · 1018. Для n = 7, k = 2 программа печатает 5.0 вместо 5, а для n = k = 109 печатает 347369984.0 вместо 347369930.
