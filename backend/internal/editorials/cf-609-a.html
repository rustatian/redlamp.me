Для файла на 5 МБ есть флешки на 2, 1 и 3 МБ. Даже самая большая флешка вмещает только 3 МБ. А двух самых больших хватает: 3 + 2 = 5 МБ.

Представим, что мы выбрали флешки на 3 и 1 МБ с общей ёмкостью 3 + 1 = 4 МБ. Заменим флешку на 1 МБ свободной флешкой на 2 МБ. Число флешек осталось прежним, а места стало больше: 3 + 2 = 5 МБ. Для любого числа k выбранных флешек такая замена сохраняет их число и увеличивает общую ёмкость. Если продолжать замены, пока среди свободных флешек есть флешка больше одной из выбранных, то среди выбранных останутся k самых больших флешек. Поэтому больше места при том же числе флешек получить нельзя.

Расположим объёмы по убыванию и будем прибавлять их к сумме total по одному. Обозначим размер файла через m. В первом примере после упорядочивания получаем список [3, 2, 1], а m = 5 МБ. После первой флешки used = 1 и total = 3 < 5: места пока мало. После второй флешки used = 2 и total = 3 + 2 = 5 ≥ 5: места хватает. Пока total < m, такого числа флешек не хватит при любом выборе. Как только total ≥ m, файл можно разделить между выбранными флешками. Их число used и есть ответ.

n = int(input())
m = int(input())
drives = [int(input()) for _ in range(n)]
drives.sort(reverse=True)

total = 0
for used, size in enumerate(drives, start=1):
    total += size
    if total >= m:
        print(used)
        break

Время: O(n log n) в худшем случае для одного набора и всей программы: на входе один набор. Чтение и проход по списку занимают O(n). Вызов drives.sort(reverse=True) занимает одну строку программы, но внутри метода число сравнений в худшем случае составляет O(n log n). Дополнительная память: O(n) в худшем случае для набора и всей программы. Программа читает по одной короткой строке и хранит в списке n объёмов. Метод sort меняет сам список, но для слияния его частей может временно хранить ещё O(n) ссылок. Программа печатает одно число от 1 до 100, поэтому для вывода достаточно O(1) памяти.
