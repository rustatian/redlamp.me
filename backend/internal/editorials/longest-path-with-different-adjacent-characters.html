Во втором примере из условия у вершин 0 и 1 буква a, поэтому ребро между ними пропускаем. Из 0 обход идёт только к вершинам 2 и 3. В цепочке с буквами abab из каждой из 4 вершин можно дойти до всех четырёх. Самый длинный путь из вершины 1, 1 → 2 → 3, содержит 3 вершины. Brute Force запускает обход из каждой вершины. Обход пропускает рёбра между одинаковыми буквами и считает вершины на пути от старта до текущей вершины. Ответ равен наибольшей длине пути за все обходы. В этой цепочке четыре обхода дают 4 · 4 = 16 посещений. За один обход каждое ребро проверяем не более двух раз. При n вершинах будет n обходов, в каждом не более n посещений. Число посещений ограничено произведением n · n, поэтому время в худшем случае равно O(n2). В цепочке из 100 000 вершин с чередующимися буквами получится 10 миллиардов посещений.

Решение 1. Dynamic Programming на Tree

Во втором примере из условия пути 2 → 0 и 0 → 3 можно соединить. Получится путь 2 → 0 → 3 с буквами bac.

Добавим к вершине 3 ребёнка 4 с буквой d и ребёнка 5 с буквой e. Теперь parent = [-1, 0, 0, 0, 3, 3] и s = "aabcde". Путь 4 → 3 → 5 содержит 3 вершины. Путь из 0 может идти через 3 к 4 или к 5. Чтобы пройти через обоих детей, пришлось бы посетить 3 дважды, а вершины пути не повторяются. Поэтому родителю передадим down[v], число вершин в самой длинной подходящей цепочке от v вниз.

У вершин 4 и 5 нет детей. Это листья, и длина цепочки у каждого равна 1. У вершины 3 получаем down[3] = 1 + 1 = 2. При parent = [-1, 2, 0, 0] начинаем с order = [0]. У корня два ребёнка: дописываем 2 и получаем [0, 2], затем дописываем 3 и получаем [0, 2, 3]. При обработке вершины 2 дописываем её ребёнка 1: order = [0, 2, 3, 1]. Поэтому обход посетит 3 раньше, чем 1. При чтении с конца получим [1, 3, 2, 0] и вычислим down[1] раньше down[2]. В общем случае заполняем order обходом BFS. Начнём с 0 и для каждой вершины списка допишем в его конец всех её детей. При чтении с конца каждый ребёнок встретится раньше родителя.

В примере с шестью вершинами цепочка через ребёнка 2 даёт одну вершину ниже корня, а через ребёнка 3 даёт две. Путь 2 → 0 → 3 → 4 содержит 1 + 1 + 2 = 4 вершины. На пути 4 → 3 → 5 ближе всего к корню вершина 3. Хотя у неё три соседа, на этом пути у неё только два ребра: к 4 и к 5. Если бы первый шаг от 3 вёл к родителю 0, на пути была бы вершина ближе к корню, чем 3. После шага от 3 к ребёнку 4 шаг вверх вернул бы нас в 3. На пути 3 → 4 ближе всего к корню вершина 3. Это один из концов пути, поэтому от 3 до этого конца нужно 0 шагов. Если конец пути совпадает с ближайшей к корню вершиной v, шагов от неё к этому концу нет. К концу, отличному от v, первый шаг ведёт вниз, а любой следующий шаг вверх повторил бы предыдущую вершину. У вершины v на выбранном пути не более двух рёбер. Значит, нужны цепочки не более чем от двух детей. У разных детей поддеревья не пересекаются, поэтому две такие цепочки можно соединить через v. Среди детей с буквой, отличной от s[v], сохраняем две наибольшие длины, top1 и top2. У листа 4 top1 = top2 = 0. В его цепочке только сам лист, отсюда и down[4] = 1. На место отсутствующей цепочки ставим 0.

Для родителя оставляем down[v] = 1 + top1. В цепочке 0 → 1 → 2 → 3 с буквами aabc путь 1 → 2 → 3 начинается в вершине 1. Её единственный ребёнок 2 даёт top1 = 2, а второй цепочки нет, поэтому top2 = 0. Этот путь даёт ответ 3, хотя down[0] равно 1. Поэтому в best сохраняем максимум down[v] + top2 по всем вершинам v.

class Solution:
    def longestPath(self, parent: list[int], s: str) -> int:
        n = len(parent)
        children = [[] for _ in range(n)]
        for v in range(1, n):
            children[parent[v]].append(v)

        order = [0]
        for v in order:
            order.extend(children[v])

        down = [1] * n
        best = 1
        for v in reversed(order):
            top1 = top2 = 0
            for child in children[v]:
                if s[child] == s[v]:
                    continue
                length = down[child]
                if length > top1:
                    top2 = top1
                    top1 = length
                elif length > top2:
                    top2 = length
            down[v] = 1 + top1
            best = max(best, down[v] + top2)
        return best

В примере с шестью вершинами в списках детей пять записей. При построении order и при расчёте down код читает все пять записей по одному разу за проход. Для n вершин таких записей n − 1: каждый ребёнок записан только у своего родителя. Время: O(n) в худшем случае. Во внешнем списке children шесть записей, по одной на вершину. Во внутренних списках хранятся те же пять номеров детей. В order и down ещё по шесть записей. Всего 6 + 5 + 6 + 6 = 23 записи, а для n вершин 4n − 1. Дополнительная память: O(n) в худшем случае.

Решение 2. Leaf Peeling

В том же примере с шестью вершинами уберём ребро между 0 и 1. Вершина 1 останется одна, а в остальной части Tree любой путь подходит. Так можно сразу отбросить все рёбра между одинаковыми буквами и искать самый длинный путь среди оставшихся частей.

Сначала уберём вершины 1, 2, 4 и 5. У вершины 1 нет соседей, а у вершин 2, 4 и 5 по одному. В слой входят все вершины, у которых в начале шага один сосед или ни одного. От пути 2 → 0 → 3 → 4 останется ребро между 0 и 3. Так две оставшиеся вершины по-прежнему соединены. Между любыми двумя оставшимися вершинами одной части сохраняется весь путь: у каждой промежуточной вершины в начале шага было хотя бы два соседа на этом пути. Значит, при удалении слоя часть не может распасться. У корня 0 и его ребёнка 3 теперь по одному соседу. При снятии слоёв такие вершины называем листьями, поэтому в следующий слой войдут обе. Если вернуть к вершине 0 лист 2, а к вершине 3 лист 4, получим прежнюю длину 2 · 1 + 2 = 4.

В цепочке с буквами baaba удалим ребро между вершинами 1 и 2. Останутся пара 0 → 1 и путь 2 → 3 → 4 с буквами aba. В первом слое пара исчезнет, а от пути останется только вершина 3. Если вернуть к ней листья 2 и 4, получим исходный путь длины 3.

Пусть в части из трёх или более вершин самый длинный путь содержит L вершин. Если бы у конца пути был ещё один сосед, он лежал бы вне пути, иначе получился бы цикл. Через такого соседа путь можно было бы продлить, поэтому оба конца самого длинного пути будут листьями. У каждой вершины между концами есть два соседа на пути, поэтому она останется. После удаления обоих концов останется путь длины L − 2. Значит, новая наибольшая длина не меньше L − 2.

Возьмём теперь самый длинный путь после удаления листьев. Если в нём хотя бы две вершины, у каждого конца остался один сосед. В начале шага у каждого конца было хотя бы два соседа, иначе его удалили бы. Поэтому к каждому концу можно вернуть по листу. Это разные листья, ведь у каждого был только один сосед. Если осталась одна вершина, у неё было хотя бы два соседа-листа. В обоих случаях путь с двумя возвращёнными листьями имеет длину не больше L. Значит, новая наибольшая длина не больше L − 2. Обе оценки дают ровно L − 2.

У вершины 3 в примере с шестью вершинами соседи 0, 4 и 5. Сумма их номеров равна 9, а после удаления 4 и 5 остаётся 9 − 4 − 5 = 0. Так код находит единственного соседа по сумме neighbor_sum, когда число соседей degree равно 1.

В цепочке baaba при удалении листа 2 у вершины 3 остаётся один сосед. Как только число соседей у вершины уменьшается до 1, код добавляет её в next_leaves. После удаления листа 4 у вершины 3 уже нет соседей, но она остаётся в списке для следующего слоя. В этом слое код убирает ребро между 0 и 1, поэтому к концу слоя width = 2, а next_leaves = [3]. В последнем слое у вершины 3 нет рёбер: width = 1, а next_leaves = []. Со старым значением 2 код получил бы 2 · 1 + 2 = 4 вместо 2 · 1 + 1 = 3.

В этом примере исходный путь через вершину 3 длиннее пути 0 → 1. Пусть layers слоёв уже снято. Если часть исчезает в текущем слое, от неё осталась одна вершина или пара. Прибавим по две вершины за каждый снятый слой и получим исходную длину не больше 2 · layers + 2. В части, которая дойдёт до следующего слоя, сейчас есть путь хотя бы из трёх вершин. До снятия слоёв самый длинный путь в ней имел длину не меньше 2 · layers + 3. Значит, в части, которая осталась, самый длинный исходный путь длиннее любого пути в части, которая исчезла.

Поэтому код заново задаёт width = 1 в начале каждого слоя. Если в этом слое код удаляет хотя бы одно ребро, он ставит width = 2.

Если в оставшейся части несколько вершин, у конца её самого длинного пути один сосед. У единственной вершины соседей нет. В начале шага у такой вершины было хотя бы два соседа, иначе она попала бы в текущий слой. Число соседей уменьшалось на 1 при каждом удалении соседа. Когда оно достигло 1, вершина попала в next_leaves, как вершина 3 в цепочке baaba. Если список next_leaves пуст, все части исчезли.

В примере с шестью вершинами ребро между 0 и 3 в последнем слое даёт width = 2. При удалении 0 код уменьшает degree[3] до нуля. При обработке вершины 3 проверка degree[v] == 0 пропускает это ребро. В последнем слое концы любого ребра образуют отдельную пару. Даже одной пары достаточно, чтобы самый длинный путь в слое содержал две вершины. Если рёбер нет, в каждой оставшейся части по одной вершине. Ответ равен 2 · layers + width.

class Solution:
    def longestPath(self, parent: list[int], s: str) -> int:
        n = len(parent)
        degree = [0] * n
        neighbor_sum = [0] * n
        for v in range(1, n):
            p = parent[v]
            if s[v] != s[p]:
                degree[v] += 1
                degree[p] += 1
                neighbor_sum[v] += p
                neighbor_sum[p] += v

        leaves = [v for v in range(n) if degree[v] <= 1]
        layers = 0
        while leaves:
            next_leaves = []
            width = 1
            for v in leaves:
                if degree[v] == 0:
                    continue
                width = 2
                u = neighbor_sum[v]
                degree[v] = 0
                degree[u] -= 1
                neighbor_sum[u] -= v
                if degree[u] == 1:
                    next_leaves.append(u)
            if not next_leaves:
                return 2 * layers + width
            leaves = next_leaves
            layers += 1

В примере с шестью вершинами код проверяет пять рёбер между детьми и родителями и обрабатывает шесть вершин: четыре в первом слое и две в последнем. Для n вершин он проверяет все n − 1 рёбер и обрабатывает каждую вершину один раз. Время: O(n) в худшем случае. В degree и neighbor_sum по шесть записей. В конце первого слоя в leaves четыре вершины, а в next_leaves две, всего 6 + 6 + 4 + 2 = 18 записей. Каждая вершина входит только в один слой, поэтому в двух списках слоёв вместе не больше n записей. С двумя списками по n чисел это не больше 3n записей. Дополнительная память: O(n) в худшем случае.
