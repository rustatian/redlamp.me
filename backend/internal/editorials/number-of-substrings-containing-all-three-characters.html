Хорошая подстрока - подстрока, где есть все три буквы a, b и c. Ответ - число хороших подстрок, а n - длина s.

Brute Force проверяет каждую подстроку: есть ли в ней a, b и c. Подстрок n(n + 1)/2: для s = "abcabc" это 6 · 7 / 2 = 21, и 10 из них хорошие. При n = 5 · 104 это 1 250 025 000 подстрок, и каждую ещё нужно проверить. Python делает около 107 простых шагов в секунду, а лимит 3 с: слишком долго.

Решение 1. Sliding Window

Окно [l, r] - подстрока от места l до места r. Места нумеруются с 0. Правая граница r идёт по строке слева направо. Для каждого r код считает хорошие начала: места i, для которых подстрока от i до r хорошая. Это число - вклад r в ответ, а сумма вкладов по всем r - ответ. У каждой подстроки один конец, поэтому каждая хорошая подстрока попадает ровно в один вклад. Hash Table cnt хранит для каждой буквы число таких букв в окне.

Возьмите s = "abcabc" и r = 4. Подстроки с концом на месте 4: "b", "ab", "cab", "bcab", "abcab". Хорошие из них "cab", "bcab" и "abcab": начала 2, 1 и 0. Начала 3 и 4 плохие: в "ab" и в "b" нет буквы c. Подстрока от места 1 содержит подстроку от места 2 и ещё одну букву, поэтому тоже хорошая. То же верно для начала 0. Хорошие начала идут подряд от 0, и вклад r = 4 равен 3. Это первое плохое начало: l = 3.

Код ищет это l. На каждом r он добавляет s[r] в cnt. Пока в окне есть все три буквы, он убирает s[l] и сдвигает l вправо. В таком окне не меньше 3 букв: r − l + 1 ≥ 3, поэтому l ≤ r − 2, и s[l] стоит внутри строки. Когда цикл остановился, в окне [l, r] нет какой-то буквы, и начало l плохое. Код прибавляет l.

Пройдите s = "abcabc". При r = 0 и r = 1 в окне нет буквы c, цикл не работает, l = 0, вклад 0. При r = 2 в cnt по одной букве: {"a": 1, "b": 1, "c": 1}. Все счётчики больше 0, и код убирает s[0] = a. Теперь l = 1, в окне "bc" нет a, вклад 1: подстрока "abc". Дальше при r = 3, 4, 5 цикл убирает по одной букве, и l = 2, 3, 4. Вклады 0, 0, 1, 2, 3, 4 дают ответ 10.

Правило. Добавьте s[r] в cnt. Пока все три счётчика больше 0, вычтите 1 из счётчика s[l] и сделайте l += 1. После цикла прибавьте l к ответу.

Начала левее l хорошие. При r = 4 цикл убрал c с места 2, потому что окно [2, 4] "cab" было хорошим. Окна [1, 4] и [0, 4] содержат его, поэтому тоже хорошие. Возьмите s = "abcc": при r = 2 цикл убирает a с места 0, l = 1. При r = 3 цикл не работает, но окно [0, 3] "abcc" содержит "abc", поэтому хорошее. Вклад равен 1, а ответ 2: "abc" и "abcc". Если на шаге r цикл не работал, начало l − 1 убрали на меньшем r, и окно с этим началом тогда было хорошим. Окно [l − 1, r] содержит то окно, поэтому тоже хорошее.

Начала от l плохие. Цикл остановился, потому что в окне [l, r] нет какой-то буквы. При r = 4 это окно [3, 4] "ab" без c. Окно [4, 4] "b" лежит внутри него, поэтому в нём тоже нет c.

class Solution:
    def numberOfSubstrings(self, s: str) -> int:
        cnt = {"a": 0, "b": 0, "c": 0}
        l = 0
        res = 0
        for ch in s:
            cnt[ch] += 1
            while cnt["a"] > 0 and cnt["b"] > 0 and cnt["c"] > 0:
                cnt[s[l]] -= 1
                l += 1
            res += l
        return res

Время: r делает n шагов. Каждый шаг l убирает букву, которую раньше добавил r, поэтому l делает не больше n шагов за весь проход. Всего не больше 2n шагов. Каждая операция с Hash Table занимает ожидаемое O(1), поэтому время ожидаемое O(n). В примере r делает 6 шагов, а l - 4 шага. При n = 5 · 104 это не больше 105 шагов вместо 1 250 025 000 у Brute Force. Дополнительная память: cnt всегда хранит 3 ключа, и есть числа l и res: O(1) в худшем случае.

Типичные ошибки

  • Прибавлять r − l + 1 вместо l. После цикла окно [l, r] плохое, и r − l + 1 считает плохие начала. Для "abcabc" получится 1 + 2 + 2 + 2 + 2 + 2 = 11, а ответ 10. Число 11 равно числу подстрок, где нет какой-то буквы: 11 = 21 − 10.
  • Писать if вместо while. Для s = "aabc" при r = 3 после первого сдвига окно [1, 3] "abc" ещё хорошее, а if на этом останавливается и прибавляет 1. Цикл делает ещё один сдвиг, l = 2, и прибавляет 2: подстроки "aabc" и "abc".
