Ответ зависит только от k и от расстояния d = |endPos − startPos|. Решение 1 находит ответ формулой Combinations из главы. Решение 2 считает пути по шагам с Dynamic Programming и обходится без формулы.

Решение 1. Combinations

Запишем путь строкой из букв R и L: R - шаг вправо, L - шаг влево. В примере 1 k = 3. На каждом из 3 мест стоит R или L, поэтому строк 23 = 8. Рисунок показывает все 8. В позицию 2 приходят 3 строки: LRR, RLR и RRL. В каждой из них 2 буквы R и 1 буква L.

Конец пути зависит только от числа букв R, а не от их порядка. Пусть в строке r букв R и k − r букв L. Тогда путь сдвигается на r − (k − r) = 2r − k. В примере 1 сдвиг endPos − startPos = 1, поэтому 2r − 3 = 1 и r = 2. Строку задают места букв R: 2 места из 3, это C(3, 2) = 3 способа.

Если endPos меньше startPos, поменяем ролями R и L: число путей то же. Поэтому код берёт d = |endPos − startPos|, и из 2r − k = d получает r = (k + d)/2 шагов в сторону конца. Ответ C(k, r). При startPos = 7, endPos = 3 и k = 6 получаем d = 4, r = 5 и C(6, 5) = 6.

В примере 2 d = 3 и k = 10, тогда r = 13/2 не целое, и путей нет. Каждый шаг меняет чётность позиции. После 10 шагов из чётной позиции 2 путь стоит в чётной позиции, а 5 нечётно. Здесь k − d = 7 нечётно. Числа k + d = 13 и k − d = 7 отличаются на 2d = 6, поэтому у них одна чётность. Путей нет всегда, когда k − d нечётно: тогда и k + d нечётно, и r не целое. Второй случай без путей: d > k. При startPos = 1, endPos = 10 и k = 3 даже 3 шага вправо ведут только в 4. Код проверяет оба случая в одной строке if и возвращает 0.

Осталось найти C(k, r) по модулю M = 109 + 7. В примере 1 C(3, 2) = 3! / (2! · 1!) = 6 / 2 = 3, и в общем случае C(k, r) = k! / (r! · (k − r)!). Список fact хранит остатки Factorial: fact[i] = i! % M. Делить остатки нацело нельзя (глава 5, раздел 2). Поэтому код умножает fact[k] на обратный элемент к x = fact[r] · fact[k − r]: это pow(x, M - 2, M) по малой теореме Ферма из лекции Modular Arithmetic.

В примере 1 fact = [1, 1, 2, 6] и x = fact[2] · fact[1] = 2. Обратный элемент pow(2, M − 2, M) = 500000004: произведение 2 · 500000004 = 1 000 000 008 = M + 1 даёт остаток 1. Ответ 6 · 500000004 % M = 3.

Обратный элемент есть всегда. Число M простое, а все множители r! и (k − r)! не больше 1000, то есть меньше M. Поэтому произведение r! · (k − r)! не делится на M.

Brute Force перебирает все 2k строк. При k = 1000 это около 1,07 · 10301 строк: слишком долго.

Время: цикл делает k умножений для fact. Число M − 2 имеет 30 двоичных цифр, поэтому pow делает около 30 возведений в квадрат. Итого O(k + log M) в худшем случае. Дополнительная память: O(k): fact хранит k + 1 чисел.

class Solution:
    def numberOfWays(self, startPos: int, endPos: int, k: int) -> int:
        M = 10**9 + 7
        d = abs(endPos - startPos)
        if d > k or (k - d) % 2 == 1:
            return 0
        r = (k + d) // 2  # шагов в сторону конца
        fact = [1] * (k + 1)
        for i in range(1, k + 1):
            fact[i] = fact[i - 1] * i % M
        # вместо деления на r! * (k - r)! умножаем на pow(..., M - 2, M)
        return fact[k] * pow(fact[r] * fact[k - r] % M, M - 2, M) % M

Решение 2. Dynamic Programming

В примере 1 за 2 шага в позицию 1 ведут 2 пути (1 → 0 → 1 и 1 → 2 → 1), а в позицию 3 ведёт 1 путь (1 → 2 → 3). Путь в позицию 2 делает последний шаг из 1 или из 3. Поэтому за 3 шага в позицию 2 ведут 2 + 1 = 3 пути. Так же для любой позиции x: число путей в x за s шагов равно сумме чисел путей в x − 1 и в x + 1 за s − 1 шагов.

За k шагов путь уходит от startPos не дальше чем на k. Поэтому код хранит позиции от startPos − k до startPos + k: 2k + 1 клеток. Клетка ways[i] отвечает позиции startPos − k + i. В примере 1 это 7 клеток для позиций от −2 до 4, и сначала ways[3] = 1: путь стоит в позиции 1. Отрицательные позиции −1 и −2 тоже есть в списке.

Список pad добавляет 0 с каждого края, поэтому индекс в pad на 1 больше индекса в ways. В примере 1 позиции 2 отвечает клетка i = 2 − 1 + 3 = 4. На шаге 3 код берёт pad[4] + pad[6] = ways[3] + ways[5] = 2 + 1 = 3: пути из позиций 1 и 3. В общем случае клетка i отвечает позиции x, а pad[i] = ways[i - 1] и pad[i + 2] = ways[i + 1] отвечают позициям x − 1 и x + 1. Ноль за краем верен. В примере 1 перед шагом 3 пути стоят в позициях от −1 до 3, а за краями лежат −3 и 5. В общем случае перед шагом путь сделал не больше k − 1 шагов, а клетка за краем лежит на расстоянии k + 1 от startPos.

После шага 3 в примере 1 позиции −1, 1 и 3 имеют 0 путей: клетки неверной чётности остаются 0, и проверка чётности не нужна. Проверка abs(endPos - startPos) > k нужна только для индекса. При startPos = 1, endPos = 10 и k = 3 индекс 10 − 1 + 3 = 12, а в списке 7 клеток. При startPos = 10, endPos = 2 и k = 3 индекс 2 − 10 + 3 = −5 отрицательный. Python читает ways[-5], то есть ways[7 − 5] = ways[2] для позиции 9, и код без проверки возвращает 3 вместо 0.

Время: k шагов, каждый строит список из 2k + 1 сумм: k · (2k + 1) сложений, O(k²) в худшем случае. При k = 1000 это 1000 · 2001 = 2 001 000 сложений. Дополнительная память: O(k): ways и новый список хранят по 2k + 1 чисел, pad 2k + 3 числа.

class Solution:
    def numberOfWays(self, startPos: int, endPos: int, k: int) -> int:
        M = 10**9 + 7
        if abs(endPos - startPos) > k:
            return 0
        # ways[i]: число путей в позицию startPos - k + i
        ways = [0] * (2 * k + 1)
        ways[k] = 1
        for _ in range(k):
            pad = [0] + ways + [0]
            ways = [(pad[i] + pad[i + 2]) % M for i in range(2 * k + 1)]
        return ways[endPos - startPos + k]

Типичные ошибки

  • Нет проверки чётности. В примере 2 код берёт r = (10 + 3) // 2 = 6 и возвращает C(10, 6) = 210 вместо 0.
  • d = endPos − startPos без abs. При startPos = 10, endPos = 1 и k = 3 получаем d = −9, и проверка d > k не срабатывает. Тогда r = (3 − 9) // 2 = −3, и fact[k - r] = fact[6] падает с IndexError: в fact только 4 числа.
  • Dynamic Programming только по позициям от 0. При startPos = 1, endPos = 1 и k = 4 путь 1 → 0 → −1 → 0 → 1 проходит через −1. Такой код теряет этот путь и возвращает 5 вместо C(4, 2) = 6.
