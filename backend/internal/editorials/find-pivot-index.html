Нужен самый левый индекс i, для которого сумма чисел слева от него равна сумме чисел справа.

Решение 1. Linear Scan с total и left

Возьмите пример 1: nums = [1, 7, 3, 6, 5, 6]. Brute Force считает обе суммы для каждого i заново: sum(nums[:i]) и sum(nums[i + 1:]). Для i = 3 это 1 + 7 + 3 = 11 и 5 + 6 = 11, код читает 5 чисел. Для любого i он читает все числа, кроме nums[i]: n − 1 чисел, где n - длина nums. Если опорного индекса нет, код проверяет все n индексов и читает n · (n − 1) чисел. При n = 104 это 104 · 9999 ≈ 108 чтений. Каждый срез ещё копирует свои числа в новый список. Это O(n²) времени и O(n) временной памяти.

Сумма слева от i = 2 равна 1 + 7 = 8. Сумма слева от i = 3 равна 8 + 3 = 11: хватает одного сложения. Суммы слева для соседних индексов отличаются одним числом. Поэтому код хранит сумму слева в left и после проверки индекса i прибавляет к ней nums[i].

Сумма всех чисел примера равна 28. В неё входят три части: числа слева от i, само nums[i] и числа справа. Для i = 3 это 28 = 11 + 6 + 11. Значит, сумма справа равна 28 − 11 − 6 = 11. Поэтому код не складывает числа справа: для любого i их сумма равна total − left − nums[i], где total - сумма всех чисел.

Код считает total один раз и идёт по i слева направо. При i = 0 слева 0, справа 28 − 0 − 1 = 27. При i = 1 слева 1, справа 28 − 1 − 7 = 20. При i = 2 слева 8, справа 28 − 8 − 3 = 17. При i = 3 слева 11 и справа 11: суммы равны, и код возвращает 3. Он проверил 4 индекса из 6.

Перед проверкой индекса i в left лежит сумма чисел от nums[0] до nums[i − 1]. Поэтому условие left == total - left - x, где x - число nums[i], сравнивает те же две суммы, что и определение опорного индекса. В [0, 0, 0] подходят все 3 индекса, и код возвращает 0: он проверяет индексы по порядку от 0 и возвращает первый подходящий, то есть самый левый.

В примере 3, [2, 1, -1], total = 2. При i = 0 слева чисел нет, left = 0, справа 2 − 0 − 2 = 0: ответ 0. В [1, -1, 3] total = 3. При i = 2 слева 1 + (−1) = 0, справа чисел нет, и формула даёт 3 − 0 − 3 = 0: ответ 2. Края не требуют отдельного if. До цикла left = 0. Для последнего индекса left + nums[i] равно сумме всех чисел, поэтому total − left − nums[i] равно 0.

class Solution:
    def pivotIndex(self, nums: list[int]) -> int:
        total = sum(nums)
        left = 0  # сумма чисел слева от i
        for i, x in enumerate(nums):
            if left == total - left - x:
                return i
            left += x
        return -1

Время: sum читает n чисел, цикл делает не больше n шагов: O(n) в худшем случае. При n = 104 без опорного индекса это 2 · 104 чтений вместо 108. Дополнительная память: числа total, left, i и x, O(1).

Решение 2. Prefix Sum

Запишите для примера 1 суммы слева для всех 6 индексов и сумму всех чисел: 0, 1, 8, 11, 17, 22, 28. Это список p из 7 чисел: p[0] = 0 и p[i + 1] = p[i] + nums[i]. Число p[i] равно сумме первых i чисел nums, то есть сумме слева от индекса i. Последнее число p[n] равно сумме всех чисел. Для i = 3 слева p[3] = 11. Справа стоят nums[4] и nums[5]. Их сумма равна сумме всех чисел без суммы первых 4 чисел: p[6] − p[4] = 28 − 17 = 11. Для любого i сумма справа равна p[n] − p[i + 1].

Решение 1 считает те же числа, но не хранит их. Его left равно p[i], total равно p[n], а left + x равно p[i + 1]. Список p нужен, когда задача много раз спрашивает суммы разных отрезков. Здесь код читает числа p по порядку слева направо, поэтому хватает чисел left и total.

class Solution:
    def pivotIndex(self, nums: list[int]) -> int:
        n = len(nums)
        p = [0]  # p[i]: сумма первых i чисел
        for x in nums:
            p.append(p[-1] + x)
        for i in range(n):
            if p[i] == p[n] - p[i + 1]:
                return i
        return -1

Время: n сложений строят p, затем цикл делает не больше n проверок: O(n) в худшем случае. Дополнительная память: p хранит n + 1 чисел, O(n).

Типичные ошибки

  • Условие left == total - left. Число nums[i] попадает в сумму справа. В примере 1 при i = 3 код сравнивает 11 и 28 − 11 = 17. Равенства нет ни для одного индекса, и код возвращает -1 вместо 3.
  • Строка left += x перед проверкой. Тогда left уже содержит nums[i]. В примере 1 при i = 3 код сравнивает 17 и 28 − 17 − 6 = 5 и тоже возвращает -1.
  • Выход из цикла, когда left стало больше суммы справа. Без отрицательных чисел left не уменьшается, а сумма справа не растёт, и такой выход верен. Но в nums бывают отрицательные числа. В [1, 4, -3, 0, 2] при i = 1 слева 1, справа −1. Такой код возвращает -1, а ответ стоит дальше: при i = 3 слева 2 и справа 2.
