Нужно сосчитать пути робота из клетки (0, 0) в клетку (m − 1, n − 1). Клетка (r, c) стоит в строке r и столбце c. Ход вниз увеличивает r на 1, ход вправо увеличивает c на 1.

Решение 1. Dynamic Programming

Возьмите пример 2: m = 3, n = 2. Робот идёт в клетку (2, 1). Последний ход в неё идёт сверху, из клетки (1, 1), или слева, из клетки (2, 0). Пути «Вправо, Вниз, Вниз» и «Вниз, Вправо, Вниз» кончаются ходом вниз из (1, 1). Путь «Вниз, Вниз, Вправо» кончается ходом вправо из (2, 0). В клетку (1, 1) ведут 2 пути, в клетку (2, 0) ведёт 1 путь, и ответ 2 + 1 = 3.

То же верно для любой клетки (r, c), где r ≥ 1 и c ≥ 1. Каждый путь в клетку сверху вместе с ходом вниз даёт путь в (r, c). Каждый путь в клетку слева вместе с ходом вправо тоже даёт путь в (r, c). У этих двух групп разный последний ход, поэтому ни один путь не попадает в обе группы. Последний ход любого пути в (r, c) идёт вниз или вправо, поэтому других путей нет. Отсюда правило: число путей в клетку равно сумме чисел путей в клетку сверху и в клетку слева. В каждую клетку строки 0 ведёт 1 путь: робот не ходит вверх, поэтому идёт только вправо. В каждую клетку столбца 0 тоже ведёт 1 путь: только вниз.

Правило можно сразу записать через Recursion: f(r, c) = f(r − 1, c) + f(r, c − 1), а в строке 0 и в столбце 0 f = 1. Такой код считает одну клетку много раз: в примере 1 у сетки 21 клетка, а вызовов 55. Вызовы в строке 0 или в столбце 0 возвращают по 1, и ответ складывается из этих единиц. Поэтому таких вызовов столько же, сколько путей. Самый большой ответ, который допускают ограничения, равен 1 984 829 850 при m = 69, n = 8. Тогда одних вызовов в строке 0 и в столбце 0 почти 2 · 109: слишком долго.

Dynamic Programming записывает число путей каждой клетки в таблицу и считает каждую клетку один раз. Строки идут сверху вниз, клетки строки идут слева направо. Тогда клетка сверху и клетка слева уже готовы. В примере 1 строка 0: семь единиц. Строка 1: 1, 2, 3, 4, 5, 6, 7. Строка 2: 1, 3, 6, 10, 15, 21, 28. Ответ 28 стоит в последней клетке строки 2.

Для строки 2 нужна только строка 1. Поэтому код хранит одну строку таблицы в list row и меняет её на месте. Сначала row = [1] * n: это строка 0. Каждый проход внешнего цикла делает из строки r − 1 строку r. Цикл по j идёт слева направо и начинает с j = 1, поэтому row[0] всегда равно 1. Перед командой row[j] += row[j - 1] в row[j] ещё лежит число из прошлой строки таблицы, то есть число сверху. В row[j - 1] уже лежит новое число слева. Во втором проходе примера 1 при j = 3 это 4 и 6, и row[3] становится 10.

Рисунок показывает row на примере 1: начало, конец первого прохода и каждое сложение второго прохода.

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        row = [1] * n  # строка 0: в каждую клетку ведёт 1 путь
        for _ in range(m - 1):
            for j in range(1, n):
                # row[j] ещё хранит число сверху, row[j - 1] уже хранит новое число слева
                row[j] += row[j - 1]
        return row[-1]

Время: O(mn) для любого входа. Код создаёт n чисел row и делает (m − 1)(n − 1) сложений. В примере 1 это 2 · 6 = 12 сложений.

Дополнительная память: O(n): row хранит n чисел. Ответ не меняется, если поменять m и n местами: в каждом пути заменим ход вниз ходом вправо, а ход вправо ходом вниз. Например, в сетке 7 × 3 тоже 28 путей. Поэтому пример 1 можно считать как сетку 7 × 3: тогда row хранит 3 числа, а не 7. Если передать меньшую сторону сетки как n, память будет O(min(m, n)).

Решение 2. Combinations

В примере 2 каждый путь из условия состоит из 2 ходов вниз и 1 хода вправо. Путь задаёт номер хода вправо: 1, 2 или 3. Так получаются 3 пути из примера. В общем случае робот проходит от строки 0 до строки m − 1 и от столбца 0 до столбца n − 1. Поэтому любой путь состоит из m − 1 ходов вниз и n − 1 ходов вправо, всего m + n − 2 ходов. Наоборот, возьмите любую запись из m − 1 ходов вниз и n − 1 ходов вправо. Робот делает не больше m − 1 ходов вниз и не больше n − 1 ходов вправо, поэтому он не выходит из сетки и кончает путь в клетке (m − 1, n − 1). Значит, ответ равен числу способов выбрать места m − 1 ходов вниз среди m + n − 2 мест: C(m + n − 2, m − 1). В примере 1 это C(8, 2) = 8 · 7 / 2 = 28.

Выбрать 2 места для ходов вниз из 8 мест значит выбрать 6 мест для ходов вправо: C(8, 2) = C(8, 6). Код берёт меньшее число k = min(m, n) − 1, поэтому в примере 1 шагов цикла 2, а не 6.

Код считает C(total, k), где total = m + n − 2, по шагам. После шага i в res лежит C(total − k + i, i). В примере 1 total = 8 и k = 2. Шаг i = 1: res = 1 · 7 // 1 = 7 = C(7, 1). Шаг i = 2: res = 7 · 8 // 2 = 28 = C(8, 2). Деление идёт без остатка, потому что C(8, 2) = 8 · 7 / (1 · 2) = C(7, 1) · 8 / 2. Произведение 7 · 8 = 56 равно 2 · 28. В общем случае C(a, i) = C(a − 1, i − 1) · a / i: в дроби для C(a, i) числитель имеет на один множитель a больше, а знаменатель на один множитель i больше. Поэтому на каждом шаге res * (total - k + i) равно i · C(total − k + i, i).

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        total = m + n - 2  # все ходы пути
        k = min(m, n) - 1  # ходы в более короткую сторону
        res = 1
        for i in range(1, k + 1):
            # сначала умножение: res * (total - k + i) делится на i без остатка
            res = res * (total - k + i) // i
        return res

Время: O(min(m, n)) для любого входа. Цикл делает k = min(m, n) − 1 шагов, в каждом одно умножение и одно деление. В примере 1 это 2 шага. Шаг умножает res на дробь (total − k + i) / i, а она не меньше 1. Поэтому res не больше ответа, а ответ не больше 2 · 109: каждое действие с числами занимает O(1).

Дополнительная память: O(1): код хранит только total, k, res и i.

Типичные ошибки

  • for j in range(n) вместо range(1, n). При j = 0 код читает row[-1]: в Python это последняя клетка, и ошибки при запуске нет. В примере 2 ответ 8 вместо 3.
  • for _ in range(m) вместо range(m - 1). Код делает на 1 проход больше и считает пути в сетке из m + 1 строк. В примере 2 ответ 4 вместо 3.
  • res = res * ((total - k + i) // i): деление раньше умножения. В примере 1 ответ случайно верный: 28. В сетке 3 × 4 шаг i = 2 даёт 4 · (5 // 2) = 4 · 2 = 8 вместо 10.
