Нужно посчитать Subarray, в которых число на месте i не меньше i. Для каждого конца r решение находит самое левое подходящее начало l и прибавляет r − l + 1.

Brute Force берёт каждое начало l и двигает конец r вправо. Пока новое число ar не меньше своего места r − l + 1, он прибавляет 1. На первом плохом числе он останавливается: все более длинные Subarray с этим началом тоже плохие. Если все числа равны n, плохих чисел нет, и код делает n(n + 1)/2 проверок. При n = 2 · 105 это 20 000 100 000 проверок: слишком долго. Время Brute Force в худшем случае: O(n²).

Решение 1. Sliding Window

Возьмите a = [2, 1, 4, 3], это третий набор примера. Числа нумеруем с 1, как в условии. Subarray [1, 4, 3] идёт от l = 2 до r = 4. Число 3 стоит в нём на месте 4 − 2 + 1 = 3, и 3 ≥ 3. Числа 1 и 4 стоят на местах 1 и 2: 1 ≥ 1 и 4 ≥ 2. Subarray хороший.

Число aj стоит в Subarray с началом l на месте j − l + 1. Нужно aj ≥ j − l + 1, то есть l ≥ j − aj + 1. Число bj = j − aj + 1 назовём границей числа aj. Для [2, 1, 4, 3] границы b1, b2, b3, b4 равны 0, 2, 0, 2. Граница b4 = 4 − 3 + 1 = 2 запрещает начало l = 1: в Subarray [2, 1, 4, 3] число 3 стоит на месте 4, и 3 < 4.

Числа левее l не входят в Subarray, но их границы тоже не мешают: bj ≤ j < l, потому что aj ≥ 1. Например, при l = 3 число a2 не входит в Subarray, а условие l ≥ b2 = 2 верно. Поэтому для конца r достаточно проверить границы всех чисел от 1 до r.

Правило. Subarray от l до r (1 ≤ l ≤ r) хороший ровно тогда, когда l ≥ bj для каждого j от 1 до r.

Пусть l = max(1, b1, ..., br). Это самое левое хорошее начало для конца r, а хорошие начала - это l, l + 1, ..., r. Их r − l + 1: это вклад конца r в ответ. Начало l не больше r, потому что bj ≤ j ≤ r. При r = 4 получается l = max(1, 0, 2, 0, 2) = 2: хорошие начала 2, 3, 4 и Subarray [1, 4, 3], [4, 3], [3]. Начало 1 запрещают границы b2 = 2 и b4 = 2.

Переход от r − 1 к r добавляет одну границу br. Например, при r = 3 к l = max(1, 0, 2) = 2 добавляется b3 = 0: max(1, 0, 2, 0) = max(2, 0) = 2. Поэтому новое самое левое начало равно max(l, r − ar + 1). Начало l не идёт назад: оно стоит на месте или растёт. Это Sliding Window: правый край r идёт вправо, левый край l тоже только вправо.

Для [2, 1, 4, 3] начало l идёт 1, 2, 2, 2, а вклады r − l + 1 равны 1, 1, 2, 3. Их сумма 7.

Ещё два набора примера. Для [1, 1, 1] границы равны 1, 2, 3: l идёт 1, 2, 3, вклады 1, 1, 1, ответ 3. Для [1, 2, 3] границы равны 1, 1, 1: l остаётся 1, вклады 1, 2, 3, ответ 6.

Код читает весь вход в data. Элемент data[pos] - это n, поэтому ar лежит в data[pos + r]. Для каждого набора l и ans начинаются заново.

import sys

data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n = int(data[pos])
    l = 1
    ans = 0
    for r in range(1, n + 1):
        a = int(data[pos + r])
        l = max(l, r - a + 1)  # a_r стоит на месте r - l + 1, и нужно a_r >= r - l + 1
        ans += r - l + 1
    pos += n + 1
    out.append(str(ans))
print("\n".join(out))

Время: n - длина Array набора. Цикл по r делает n шагов, и каждый шаг читает число, считает max и прибавляет к ответу за O(1). На набор это O(n) в худшем случае. Во всех наборах вместе не больше 2 · 105 чисел, поэтому на весь вход цикл делает не больше 2 · 105 шагов. Дополнительная память: O(1) в худшем случае: код хранит только целые числа t, pos, n, l, r, a, ans и счётчик цикла по наборам. Вход data и список ответов out считаем отдельно.

Наибольший ответ даёт Array из одних n: у него хороши все Subarray. Для [3, 3, 3] границы равны −1, 0, 1, l остаётся 1, вклады 1, 2, 3, ответ 6 = 3 · 4 / 2. Такой Array длины n даёт ответ n(n + 1)/2, как и число проверок Brute Force выше. При n = 2 · 105 ответ больше 2 147 483 647, но целые числа Python не переполняются.

Число r − l + 1 - это длина самого длинного хорошего Subarray с концом r. Назовём dp эту длину для конца r − 1. Перед r = 1 она равна 0. Для конца r длина равна min(dp + 1, ar): хороший Subarray с концом r − 1 растёт на одно число, но число ar не может стоять на месте больше ar. Это то же правило. Проверим на r = 3: старое l = 2, a3 = 4, b3 = 0, dp = r − l = 1. Слева 3 − max(2, 0) + 1 = 4 − max(2, 0) = min(4 − 2, 4 − 0) = min(2, 4) = 2. Справа min(dp + 1, a3) = min(2, 4) = 2. В общем виде r − max(l, r − ar + 1) + 1 = min(r − l + 1, ar) = min(dp + 1, ar), потому что dp = r − l. Для [2, 1, 4, 3] получаются min(0 + 1, 2) = 1, min(1 + 1, 1) = 1, min(1 + 1, 4) = 2 и min(2 + 1, 3) = 3. Сумма этих длин равна 7. Код с dp = min(dp + 1, a) и ans += dp даёт те же числа.

Типичные ошибки

  • Сдвинуть l только на 1. Для [3, 3, 3, 1] при r = 4 граница b4 = 4 − 1 + 1 = 4, и нужно l = 4. Сдвиг на 1 даёт l = 2 и вклад 3 вместо 1: ответ 9 вместо 7.
  • Писать l = r - a + 1 без max. Для [2, 1, 4, 3] получаются l = 0, 2, 0, 2: начало выходит левее первого числа и при r = 3 идёт назад с 2 на 0. Вклады 2, 1, 4, 3, ответ 10 вместо 7.
  • Задать l и ans один раз до цикла по наборам. Тогда набор продолжает счёт прошлого. Для входа с наборами [3, 3, 3] и [1, 1, 1] ответы будут 6 и 9 вместо 6 и 3.
