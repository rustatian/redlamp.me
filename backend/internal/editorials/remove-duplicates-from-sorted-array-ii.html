Нужно оставить в начале nums каждое число не больше двух раз и вернуть длину этой части k. Здесь n - длина nums.

Решение 1. Two Pointers

Возьмите пример 1: nums = [1, 1, 1, 2, 2, 3]. Array отсортирован, поэтому равные числа стоят подряд. Индекс read читает ячейки слева направо. Индекс write показывает ячейку для следующего оставленного числа.

Число в ячейке 0 или 1 не может быть третьим одинаковым числом: левее него меньше двух чисел. Поэтому первые два числа остаются на месте, write = 2, а read начинает с ячейки 2. Число nums[read] лишнее, когда оно равно nums[write - 2].

  • read = 2: число 1 равно nums[0] = 1. Это третья единица, записи нет.
  • read = 3: число 2 больше, чем nums[0] = 1. Число 2 записано в ячейку 2, и write = 3.
  • read = 4: число 2 больше, чем nums[1] = 1. Число 2 записано в ячейку 3, и write = 4.
  • read = 5: число 3 больше, чем nums[2] = 2. Число 3 записано в ячейку 4, и write = 5.

Метод возвращает k = write = 5, и первые 5 ячеек содержат [1, 1, 2, 2, 3].

Почему достаточно сравнить с nums[write - 2]. Оставленные числа лежат в ячейках от 0 до write - 1. Они взяты из ячеек левее read в прежнем порядке. Array отсортирован, поэтому каждое следующее из них не меньше предыдущего, а число nums[read] не меньше каждого из них. При read = 2 оставлены [1, 1], и число 1 равно nums[0] = 1. Число nums[1] не меньше nums[0] = 1 и не больше нового числа 1, поэтому тоже равно 1. Две единицы уже оставлены, и третья не нужна. При read = 4 оставлены [1, 1, 2], и число 2 больше, чем nums[1] = 1. Числа в ячейках 0 и 1 не больше nums[1] = 1. Поэтому двойка может стоять только в ячейке write - 1 = 2, и оставлена не больше чем одна двойка. Значит, вторая двойка нужна, и код её пишет.

Почему запись не портит непрочитанные числа. Каждый шаг увеличивает read на 1, а write на 0 или на 1. В цикле оба индекса начинают с 2, поэтому write никогда не больше read. Например, при read = 5 число 3 идёт в ячейку 4. Двойку из ячейки 4 read уже прочитал при read = 4.

Инвариант. После каждого шага первые write ячеек содержат все числа, которые во входе стояли в ячейках от 0 до read, в прежнем порядке: каждое число столько раз, сколько оно там встречается, но не больше двух раз. После read = 4 в примере 1 это [1, 1, 2, 2].

Рисунок показывает пример 2: nums = [0, 0, 1, 1, 1, 1, 2, 3, 3]. Четыре единицы стоят в ячейках от 2 до 5. При read = 4 и read = 5 единица равна nums[2] = 1, и код её пропускает. Всего 7 сравнений и 5 записей, метод возвращает 7.

При n = 1, например nums = [5], код ставит write = min(2, 1) = 1. Цикл не делает ни одного шага, и метод возвращает 1.

class Solution:
    def removeDuplicates(self, nums: list[int]) -> int:
        write = min(2, len(nums))  # первые два числа остаются всегда
        for read in range(2, len(nums)):
            if nums[read] != nums[write - 2]:  # равные числа идут подряд
                nums[write] = nums[read]
                write += 1
        return write

Время: при n ≥ 2 цикл делает одно сравнение для каждой ячейки от 2 до n − 1: всего n − 2 сравнений. Запись идёт для каждого оставленного числа, кроме первых двух: k − 2 записей. Итого O(n) в худшем случае. В примере 1 n = 6 и k = 5: 4 сравнения и 3 записи. Дополнительная память: индексы read и write, O(1). Ответ лежит в самом nums.

Другие способы

Hash Table счётчиков тоже показывает, какие числа оставить. Но она хранит до u счётчиков для u разных чисел: O(u) дополнительной памяти, а условие разрешает только O(1). Новый list из оставленных чисел занимает O(k) дополнительной памяти, и его k чисел нужно ещё переписать в nums.

Можно удалять лишние числа: начать с i = 2 и, если nums[i] == nums[i - 2], выполнить del nums[i], иначе увеличить i на 1. Ответ будет верным. Но после каждого удаления все числа правее сдвигаются на одну ячейку влево. Для [4, 4, 4, 4, 4] три удаления сдвигают 2, 1 и 0 чисел: всего 3 сдвига. Для n ≥ 2 одинаковых чисел это (n − 2)(n − 3)/2 сдвигов, O(n²) в худшем случае. При n = 3 · 104 это около 4,5 · 108 сдвигов. Эти сдвиги делает сам Python циклом на языке C, поэтому код всё же работает около 0,1 с. Решение 1 на этом входе делает 29 998 сравнений и ни одной записи.

Типичные ошибки

  • Сравнение с nums[read - 2] вместо nums[write - 2]. Код пишет в ячейку write, а она может быть левее read. Поэтому в ячейке read - 2 может стоять уже не то число, что было во входе. В примере 1 при read = 3 число 2 записано в ячейку 2. При read = 4 код сравнивает 2 с nums[2], где теперь стоит 2, а не 1, и пропускает вторую двойку. Такой код возвращает 4, и в начале стоит [1, 1, 2, 3].
  • Начало с write = 2 при любом n. Для nums = [5] такой код возвращает 2.
