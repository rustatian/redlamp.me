Поворот по часовой стрелке запишем как +ai, против часовой стрелки как −ai. Нужно узнать, есть ли выбор знаков, после которого стрелка стоит на нуле.

В примере 1 сумма 10 + 20 − 30 = 0, и стрелка на нуле. В примере 3 сумма 120 + 120 + 120 = 360: это полный оборот, и стрелка тоже на нуле. Сумма 720 даёт два оборота, сумма −360 один оборот в другую сторону. Стрелка указывает на ноль, когда сумма со знаками делится на 360.

В Python остаток total % 360 лежит от 0 до 359 и для отрицательной суммы: -30 % 360 равно 330, -360 % 360 равно 0. Поворот на 30 градусов против часовой стрелки ставит стрелку на деление 330. Поэтому проверка total % 360 == 0 верна для суммы любого знака.

У каждого поворота 2 варианта знака, поэтому наборов знаков 2n: 8 при n = 3 и 32 768 при n = 15.

Решение 1. Backtracking

Функция dfs(i, total) получает в total сумму со знаками первых i поворотов. Для поворота i она пробует оба знака: сначала dfs(i + 1, total + a[i]), потом dfs(i + 1, total - a[i]). При i == n все знаки выбраны, и вызов возвращает результат проверки total % 360 == 0.

Пример 1, a = [10, 20, 30]. Сначала функция берёт плюс, поэтому первые вызовы такие: dfs(0, 0), dfs(1, 10), dfs(2, 30) и dfs(3, 60). Остаток 60 % 360 = 60, и этот вызов возвращает False. Тогда dfs(2, 30) вызывает dfs(3, 0) с минусом для 30: 0 % 360 = 0, True. Оператор or не вычисляет вторую часть, если первая дала True. Поэтому True идёт вверх без новых вызовов, и вызовов всего 5.

Пример 2, a = [10, 10, 10]. Вызовы с i = 3 получают суммы 30, 10, 10, −10, 10, −10, −10, −30. Ни одна не делится на 360, поэтому каждый вызов с i < 3 делает оба вызова. Всего 1 + 2 + 4 + 8 = 15 вызовов, ответ NO.

Каждый набор знаков задаёт один путь вызовов от dfs(0, 0) до вызова с i == n: плюс для поворота i ведёт в первый вызов, минус во второй. Значит, функция проверяет наборы по одному, пока не найдёт подходящий. YES получается только из набора с суммой, кратной 360. NO получается только после проверки всех 2n наборов.

import sys


def dfs(i, total):
    # повороты 0, ..., i - 1 уже выбраны, total это их сумма со знаками
    if i == n:
        return total % 360 == 0
    return dfs(i + 1, total + a[i]) or dfs(i + 1, total - a[i])


n = int(sys.stdin.readline())
a = [int(sys.stdin.readline()) for _ in range(n)]
print("YES" if dfs(0, 0) else "NO")

Время: O(2n). Без раннего выхода вызовов 1 + 2 + ... + 2n = 2n+1 − 1, и каждый делает O(1) действий. При n = 15 это 65 535 вызовов. Дополнительная память: O(n): Call Stack держит до n + 1 вызовов, при n = 15 это 16 вызовов. Список a это вход.

Решение 2. Bitmask Enumeration

В примере 1 n = 3. Числа от 0 до 7 в двоичной записи из 3 цифр это 000, 001, 010, 011, 100, 101, 110, 111. Получаем 8 разных записей, и других записей из 3 цифр нет. Каждая запись задаёт один из 8 наборов знаков. Например, 4 = 100 задаёт +10 + 20 − 30: это набор из пояснения к примеру.

Набор знаков можно задать одним числом mask от 0 до 2n − 1. Запишите mask в двоичной записи из n цифр. Цифры нумеруем справа, начиная с 0: цифра с номером i это бит i. Бит i, равный 0, означает поворот i по часовой стрелке, а бит i, равный 1, означает поворот i против часовой стрелки.

Выражение (mask >> i) & 1 даёт бит i. Сдвиг >> i убирает i цифр справа, а & 1 оставляет последнюю цифру. Например, 6 = 110: 6 >> 1 равно 3 = 11, и 3 & 1 равно 1. Значит, бит 1 числа 6 равен 1.

Самое большое значение mask это 2n − 1, и оно записывается n единицами, как 7 = 4 + 2 + 1 = 111 при n = 3. Значит, каждое число от 0 до 2n − 1 помещается в n цифр. У разных чисел записи разные. Чисел 2n, и записей из n цифр тоже 2n, потому что у каждой цифры 2 варианта. Поэтому каждая запись из n цифр есть среди них, и цикл по mask проверяет каждый набор знаков ровно один раз. Для каждого mask код считает сумму всех n поворотов заново.

Пример 1: mask = 0 даёт 10 + 20 + 30 = 60, mask = 1 даёт 40, mask = 2 даёт 20. Число 3 = 011 даёт −10 − 20 + 30 = 0, и цикл останавливается. Это набор из пояснения, только каждый поворот сделан в другую сторону. На рисунке строка «бит i» идёт по номерам i слева направо, поэтому биты стоят в обратном порядке двоичной записи.

import sys

n = int(sys.stdin.readline())
a = [int(sys.stdin.readline()) for _ in range(n)]
answer = "NO"
for mask in range(1 << n):
    total = 0
    for i in range(n):
        if (mask >> i) & 1:
            total -= a[i]  # бит i равен 1: против часовой стрелки
        else:
            total += a[i]  # бит i равен 0: по часовой стрелке
    if total % 360 == 0:
        answer = "YES"
        break
print(answer)

Время: O(n · 2n): 2n значений mask, для каждого n шагов внутреннего цикла. При n = 15 и ответе NO это 32 768 · 15 = 491 520 шагов. Дополнительная память: O(1): числа mask, total, i и строка answer.

Решение 3. Dynamic Programming

Решения 1 и 2 различают наборы знаков, даже если стрелка после них стоит в одной точке. Наборы +10 − 10 и −10 + 10 оба оставляют стрелку на 0. Следующие повороты двигают стрелку одинаково, откуда бы она ни пришла. Поэтому достаточно хранить точки шкалы, где стрелка может стоять после первых k поворотов. Таких точек не больше 360: от 0 до 359.

Список can хранит 360 значений: can[r] равно True, если стрелка может стоять на r. Сначала True только can[0]. Поворот x переводит точку r в (r + x) % 360 и в (r - x) % 360. Новый список nxt собирает эти точки и заменяет can. После всех поворотов ответ YES, если can[0] равно True.

Пример 1: после поворота 10 стрелка может стоять на 10 или на 350, потому что −10 % 360 = 350. После поворота 20 точек 4, после поворота 30 точек 7, и среди них есть 0.

Пример 2: после трёх поворотов по 10 точки такие: сначала 10 и 350, затем 0, 20 и 340, затем 10, 30, 330 и 350. Точки 0 в конце нет, ответ NO.

Точка r есть в can после k поворотов ровно тогда, когда сумма со знаками первых k поворотов может дать остаток r. При k = 0 это точка 0 пустой суммы. Шаг добавляет к каждой такой сумме +x и −x, поэтому новые точки дают остатки всех сумм первых k + 1 поворотов. Например, точка 330 после двух поворотов примера 1 это сумма −10 − 20 = −30.

import sys

n = int(sys.stdin.readline())
a = [int(sys.stdin.readline()) for _ in range(n)]
# can[r] = True, если после сделанных поворотов стрелка может стоять на r
can = [False] * 360
can[0] = True
for x in a:
    nxt = [False] * 360
    for r in range(360):
        if can[r]:
            nxt[(r + x) % 360] = True
            nxt[(r - x) % 360] = True
    can = nxt
print("YES" if can[0] else "NO")

Время: O(360 · n): на каждый поворот 360 проверок can[r] и не больше 720 записей в nxt. При n = 15 это 5400 проверок. Дополнительная память: O(360): два списка can и nxt по 360 значений.

Типичные ошибки

  • Проверка total == 0 вместо total % 360 == 0. В примере 3 суммы со знаками равны 360, 120, −120 и −360, и ни одна не равна 0. Такая проверка даёт NO вместо YES.
  • Проверка только сумм 0, 360 и −360. Пять поворотов по 144 дают суммы ±144, ±432 и ±720. Подходят только 720 = 2 · 360 и −720, поэтому такая проверка даёт NO вместо YES.
  • Greedy: каждый поворот делать в ту сторону, где стрелка ближе к нулю. В примере 1 Greedy заканчивает на 20 или на 340 и отвечает NO, хотя ответ YES. После поворота 10 точки 10 и 350 одинаково близки к нулю, поэтому концов два. При верном наборе +10 + 20 − 30 стрелка после двух поворотов стоит на 30, а Greedy выбирает точку ближе к нулю.
