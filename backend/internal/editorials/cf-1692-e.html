После удалений с двух концов остаётся одна непрерывная часть Array: окно. Число операций равно n − (длина окна), где n - длина Array. Нужно самое длинное окно с суммой s.

Окно с суммой s

Пример: a = [0, 1, 0, 1, 1, 1, 0, 0, 1], s = 3, n = 9. Номера в коде начинаются с 0. Если удалить 2 элемента слева и 1 справа, останутся элементы 2..7: [0, 1, 1, 1, 0, 0]. Их сумма равна 3, длина 6, операций 9 − 6 = 3. Окно 4..8, [1, 1, 0, 0, 1], тоже имеет сумму 3, но длину 5: это 9 − 5 = 4 операции. Окон с суммой 3 длиннее 6 нет, поэтому ответ 3.

Brute Force берёт каждое начало l и идёт вправо, прибавляя числа, пока сумма не станет больше s. Окно с суммой s он сравнивает с лучшим по длине. В худшем случае Array состоит из одних нулей: сумма не растёт, и каждое начало проходит все числа до конца. Это n + (n − 1) + ... + 1 = n(n + 1)/2 шагов. При n = 2 · 105 это 200 000 · 200 001 / 2 = 20 000 100 000 шагов, около 2 · 1010: слишком долго.

Решение 1. Sliding Window

Граница r идёт по Array слева направо и добавляет a[r] к сумме окна total. Граница l стоит на начале окна. Пока total больше s, граница l убирает a[l] из суммы и сдвигается на 1 вправо. После этого сумма окна l..r не больше s, и длина r − l + 1 может стать новым лучшим значением best.

Окно 0..2 имеет сумму 1, меньше 3. Рядом стоит a[3] = 1: окно 0..3 имеет сумму 2, не больше 3, и оно длиннее. Если сумма всего Array не меньше s, окно с суммой меньше s всегда можно удлинить. Оно не весь Array, потому что у всего Array сумма не меньше s. Новый элемент добавляет не больше 1, поэтому сумма окна остаётся не больше s. Значит, у самого длинного окна с суммой не больше s сумма равна ровно s, и ответ равен n − best.

Для примера до r = 4 сумма не больше 3: окно 0..4 имеет сумму 0 + 1 + 0 + 1 + 1 = 3 и длину 5, поэтому best = 5. На шаге r = 5 приходит a[5] = 1, и сумма становится 4. Граница l убирает a[0] = 0: сумма остаётся 4, l = 1. Граница l убирает a[1] = 1: сумма 3, l = 2. Окно 2..5 имеет длину 4, а best остаётся 5.

Граница l не возвращается назад. Окно 0..5 имеет сумму 4, больше 3. Любое окно с началом 0 и концом не меньше 5 содержит окно 0..5, а числа Array не отрицательные, поэтому его сумма не меньше 4. Начало 0 не подходит ни для какого r не меньше 5. Для начала 1 то же самое: окно 1..5 имеет сумму 4.

Если сумма всего Array меньше s, окна с суммой s нет, и ответ -1. Для a = [1, 0, 1, 0, 0, 0] и s = 3 сумма равна 2.

import sys

t = int(sys.stdin.readline())
out = []
for _ in range(t):
    n, s = map(int, sys.stdin.readline().split())
    a = list(map(int, sys.stdin.readline().split()))
    if sum(a) < s:
        out.append(-1)
        continue
    # total - сумма окна a[l..r]
    total = 0
    l = 0
    best = 0
    for r in range(n):
        total += a[r]
        while total > s:
            total -= a[l]
            l += 1
        best = max(best, r - l + 1)
    out.append(n - best)
print("\n".join(map(str, out)))

Время: O(n) в худшем случае на набор: sum(a) читает n чисел, r делает n шагов, l делает не больше n шагов, потому что l только растёт. В примере r делает 9 шагов, l - 4 шага. Все наборы вместе имеют не больше 2 · 105 чисел, поэтому весь вход обрабатывается за O(∑n), где ∑n - сумма длин всех наборов. Дополнительная память: O(n) в худшем случае на набор: Python хранит набор в списке a из n чисел. Сам Sliding Window добавляет к нему только числа total, l, r и best, то есть O(1). Список out хранит ответы: по одному числу на набор.

Решение 2. Prefix Sum и Binary Search

Пусть p[j] - сумма первых j чисел Array. Для примера p = [0, 0, 1, 1, 2, 3, 4, 4, 4, 5]. В p на 1 число больше, чем в a, потому что p[0] = 0. Окно l..e − 1 имеет сумму p[e] − p[l]. Например, окно 2..7 имеет сумму p[8] − p[2] = 4 − 1 = 3.

Для каждого начала l нужно самое правое место e с p[e] = p[l] + s. При l = 2 нужно p[e] = 1 + 3 = 4. Число 4 стоит в p на местах 6, 7 и 8. Каждая единица увеличивает p на 1, а каждый нуль повторяет предыдущее значение. Поэтому p не убывает, но числа в нём могут повторяться. Нужно самое правое место 8: окно 2..7 длины 6. Место 6 даёт только окно 2..5 длины 4.

Так как p не убывает, нужное место ищет Binary Search. Вызов bisect_right(p, x) возвращает место первого числа больше x. Поэтому bisect_right(p, x) - 1 - самое правое место числа не больше x. Для x = 4 первое число больше 4 стоит на месте 9 (p[9] = 5), и e = 8.

Если p[e] − p[l] не равно s, значения p[l] + s в p нет, и окна с суммой s и началом l нет. При l = 5 нужно 3 + 3 = 6. Чисел больше 6 в p нет, поэтому bisect_right(p, 6) возвращает длину p, то есть 10. Самое правое место числа не больше 6 равно 9, и p[9] − p[5] = 5 − 3 = 2. Сумма 2 не равна 3, поэтому окна с суммой 3 и началом 5 нет. Если окон нет ни для одного l, best остаётся 0 и ответ -1: окно с суммой s не пусто, так как s не меньше 1.

import sys
from bisect import bisect_right

t = int(sys.stdin.readline())
out = []
for _ in range(t):
    n, s = map(int, sys.stdin.readline().split())
    a = list(map(int, sys.stdin.readline().split()))
    # p[j] - сумма первых j чисел
    p = [0] * (n + 1)
    for i in range(n):
        p[i + 1] = p[i] + a[i]
    best = 0
    for l in range(n):
        # самое правое место e с p[e] <= p[l] + s: окно a[l..e - 1]
        e = bisect_right(p, p[l] + s) - 1
        if p[e] - p[l] == s:
            best = max(best, e - l)
    out.append(n - best if best else -1)
print("\n".join(map(str, out)))

Время: O(n log n) в худшем случае на набор: n шагов для p и n поисков. При n = 2 · 105 список p хранит 200 001 число. Каждое сравнение Binary Search оставляет не больше половины области поиска, поэтому поиск делает не больше 18 сравнений: 217 = 131 072 меньше 200 001, а 218 = 262 144 больше. Всего не больше 200 000 · 18 = 3 600 000 сравнений. Дополнительная память: O(n) в худшем случае на набор: p хранит n + 1 число, а список a - ещё n чисел.

Типичные ошибки

  • Нет проверки суммы всего Array. В Решении 1 без if sum(a) < s для a = [1, 0, 1, 0, 0, 0] и s = 3 окно - весь Array, best = 6, ответ 0 вместо -1.
  • В Решении 2 берут самое левое место числа p[l] + s (так ищет bisect_left) вместо самого правого. Тогда для начала l выбрано самое короткое окно с суммой s, а не самое длинное. Для примера лучшее окно имеет длину 5, и ответ 4 вместо 3.
  • Ответ считают как число единиц, которые нужно убрать: сумма Array минус s. Для a = [0, 0, 1, 1, 0, 0] и s = 1 это 2 − 1 = 1, но единицы стоят в середине. Чтобы убрать одну из них, нужно убрать с одного конца 3 элемента: два нуля и единицу. Ответ 3.
