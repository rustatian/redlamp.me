В цепочке 1 → 2 → 3 → 4 отдельный обход каждого поддерева посетит вершины 4 + 3 + 2 + 1 = 10 раз. Такой Brute Force заново считает цвета одних и тех же вершин. В любом Tree из четырёх вершин каждый из четырёх обходов посетит не больше четырёх вершин. Для n вершин это не более n · n посещений, то есть O(n2) времени в худшем случае. Под суммой для цепочки из четырёх вершин запишем ту же сумму в обратном порядке. Пары 4 + 1, 3 + 2, 2 + 3 и 1 + 4 дают по пять. На цепочке из n вершин каждое следующее поддерево от корня к листу на одну вершину меньше. Всего получаем n + (n − 1) + … + 1 посещений. С обратной суммой получим n пар по n + 1. Делим на два, так как учли каждое посещение дважды, и получаем n · (n + 1) / 2. При n = 4000 это 8 002 000 посещений. По ограничению на общее число вершин таких цепочек может быть не больше 200 000 / 4000 = 50. Для них потребуется 400 100 000 посещений, что слишком много для лимита в одну секунду.

Решение 1. От детей к родителю

В первом наборе примера вершина 2 чёрная, а её единственный ребёнок 4 белый. Дадим белой вершине вес +1, а чёрной вес −1. Сумма для поддерева вершины 2 равна −1 + 1 = 0. Сумма весов даёт баланс поддерева, то есть число белых вершин минус число чёрных. Нулевой баланс означает, что цветов поровну.

У вершины 3 двое детей, 5 и 6. В поддереве вершины 5 обе вершины белые. У чёрной вершины 6 нет детей. К весу самой вершины 3 прибавим балансы детей и получим −1 + 2 − 1 = 0. Путь от вершины v к любой другой вершине поддерева v проходит ровно через одного ребёнка v. Значит, прибавив к весу v балансы поддеревьев всех детей v, мы учтём каждую вершину поддерева один раз.

В обратном порядке номеров вершина 7 прибавит свой вес к balance[5] ещё до того, как 5 передаст сумму вершине 3. По условию номер каждого ребёнка больше номера его родителя. Поэтому к шагу v все дети уже прибавили свои суммы к balance[v], и родитель получит баланс всего поддерева v.

В первом наборе примера нули получаются у вершин 2 и 3, поэтому ответ равен 2. Во втором наборе с цветами BW число 1 в строке родителей относится к вершине 2. Цикл ищет родителя по номеру вершины, поэтому значение parent[2] должно быть равно 1. Индексы 0 и 1 цикл не использует, поэтому заполняем эти ячейки нулями и получаем parent = [0, 0, 1]. Сначала balance = [0, -1, 1]. Прибавляем вес ребёнка к balance[1] и получаем −1 + 1 = 0, как у вершины 2 в первом наборе. Теперь balance = [0, 0, 1]. У корня нет родителя, поэтому цикл заканчивается после вершины 2. Ноль по индексу 1 означает, что поддерево корня сбалансировано. Вершины с номером 0 нет, поэтому balance[0] сохраняет начальный ноль. Срез balance[1:] содержит один ноль, а во всём списке их два.

import sys

read = sys.stdin.readline


def solve_case():
    n = int(read())
    parent = [0, 0] + list(map(int, read().split()))
    colors = read().strip()
    balance = [0] + [1 if color == "W" else -1 for color in colors]

    for v in range(n, 1, -1):
        p = parent[v]
        balance[p] += balance[v]

    return balance[1:].count(0)


answers = [str(solve_case()) for _ in range(int(read()))]
print("\n".join(answers))

В первом наборе split() даёт шесть строк с номерами родителей. Вызов list(map(...)) собирает шесть чисел, и строки больше не нужны. В восемь ячеек parent оператор + копирует два нуля и шесть номеров. Код добавляет во временный список по одному весу для каждого из семи цветов. Для пятого веса Python расширяет список с четырёх ячеек до восьми. При этом он может перенести четыре ссылки на веса. Затем + копирует ноль и семь весов в восемь ячеек balance. После + временный список больше не нужен. Цикл от вершины 7 до вершины 2 делает шесть сложений. Срез копирует семь значений, а count проверяет все семь.

На входе n − 1 номеров родителей и n цветов. При n ≤ 4000 в каждом номере не больше четырёх цифр. При расширении Python на сайте оставляет хотя бы k / 8 свободных ячеек на k занятых. По оценке для Stack из решения 2 все добавления номеров и весов с учётом переносов занимают O(n) времени. Каждое соединение копирует n + 1 ссылок за O(n) времени. Цикл делает n − 1 сложений, а count проверяет n значений. В балансе не больше n весов +1 или −1 от разных вершин. Модуль баланса не больше 4000. Для него хватает 12 двоичных цифр, так как 4000 < 212. Сложение и сравнение с нулём занимают O(1) времени. Время: O(n) в худшем случае на набор. Для среза нужны ещё n ячеек. Дополнительная память: O(n) на набор в худшем случае.

Три набора на 7, 2 и 8 вершин дают 6 + 1 + 7 = 14 сложений. Пока answers хранит строки «2», «1», «4», join соединяет их в одну. С двумя переводами строки это 3 + 2 = 5 символов. Для пяти наборов по две вершины код добавляет в answers пять строк по одной. Для пятого ответа Python выделяет восемь ячеек вместо четырёх и может перенести четыре ссылки на строки. Пусть nmax - наибольшее число вершин в наборе, а t - число наборов. Как и для весов, все t добавлений с переносами занимают O(t) времени. Вершин не больше 4000, поэтому в ответе до четырёх цифр. В строке для печати до 4 · t цифр и t − 1 переводов строки. Сборка и печать строки занимают O(t) времени. В каждом наборе хотя бы две вершины, а всего их не меньше 2 · t. Поэтому время для всех наборов в худшем случае пропорционально общему числу вершин. На список и строку нужно O(t) памяти, а с текущим набором O(nmax + t) дополнительной памяти в худшем случае.

Решение 2. DFS и Prefix Sum

В первом наборе примера строка родителей начинается с 1 1. Первый родитель указан для вершины 2, поэтому enumerate(..., start=2) даёт сначала пары (2, 1) и (3, 1). В обеих парах родитель p = 1, поэтому children[p].append(v) добавляет в children[1] сначала вершину 2, затем 3.

Вызов pop() извлекает из Stack начальную запись (1, None) о входе в корень. Сумма весов до входа равна нулю, поэтому кладём в Stack запись о выходе (1, 0). При v = 1 читаем W из colors[0], потому что первый символ строки имеет индекс 0. Прибавляем к сумме prefix вес белого корня и получаем 0 + 1 = 1. Значение None на втором месте означает вход, а любое число, в том числе ноль, означает выход. Цикл по reversed(children[v]) берёт детей корня с конца и кладёт в Stack сначала (3, None), затем (2, None). Следующий вызов pop() берёт запись о входе в 2. При входе в 2 кладём поверх (3, None) запись о выходе (2, 1), а над ней запись о входе (4, None). Вызовы pop() снимают запись о входе в 4, запись о выходе из неё, затем (2, 1) и только потом (3, None).

DFS входит в вершины в порядке 1, 2, 4, 3, 5, 7, 6. Последние четыре вершины 3, 5, 7, 6 образуют поддерево вершины 3. При входе в любую вершину v кладём запись о выходе из неё поверх записей других ветвей. Над ней кладём записи детей и при входе в каждого из них повторяем те же действия. Поэтому на отрезке от входа в v до выхода из неё в сумму попадают веса всех вершин её поддерева и только они.

Перед входом в 3 сумма весов уже посещённых вершин равна 1 − 1 + 1 = 1. В первом решении мы получили нулевой баланс поддерева вершины 3. Поэтому на выходе сумма равна 1 + 0 = 1. Пусть prefix хранит сумму с начала обхода, а before хранит её значение перед входом в текущую вершину. Если на выходе prefix == before, то баланс поддерева равен нулю и можно увеличить ответ.

import sys

read = sys.stdin.readline


def solve_case():
    n = int(read())
    children = [[] for _ in range(n + 1)]
    for v, p in enumerate(map(int, read().split()), start=2):
        children[p].append(v)
    colors = read().strip()

    prefix = 0
    answer = 0
    stack = [(1, None)]
    while stack:
        v, before = stack.pop()
        if before is None:
            stack.append((v, prefix))
            prefix += 1 if colors[v - 1] == "W" else -1
            for child in reversed(children[v]):
                stack.append((child, None))
        elif prefix == before:
            answer += 1

    return answer


answers = [str(solve_case()) for _ in range(int(read()))]
print("\n".join(answers))

В первом наборе read().split() снова даёт шесть строк. Цикл читает из каждой строки число p и добавляет номер ребёнка в children[p]. Список из n − 1 строк нужен только до конца цикла. Затем код читает в colors семь символов. На каждую вершину приходятся вход и выход, всего 7 · 2 = 14 вызовов pop(). Для вершин 1, 2, 3, 5 цикл по детям добавляет в Stack 2 + 1 + 2 + 1 = 6 записей. Ещё семь записей нужны для выхода, всего 6 + 7 = 13 вызовов stack.append. При входе в белую вершину 7 сумма prefix растёт с 1 до 2.

Для n вершин получаем 2 · n извлечений. Каждая вершина, кроме корня, встречается ровно в одном списке детей, поэтому за весь обход этот цикл добавляет в Stack n − 1 записей. С учётом n записей о выходе получаем 2 · n − 1 добавлений.

В первом наборе для (7, None) в четырёх ячейках Stack нет места. Для пятой записи Python на сайте выделяет восемь ячеек. Код снимает её и кладёт на её место (7, 1). После извлечения (7, 1) заняты четыре ячейки, после (5, 0) только три. Python пересчитывает число ячеек, когда для append нет места или после pop() непустой список заполнен меньше чем наполовину. К новой длине k он прибавляет целую часть k / 8 и шесть, затем округляет сумму вниз до кратного четырём. Здесь 3 + 0 + 6 = 9 даёт прежние восемь ячеек.

На цепочке из 32 вершин перед выходом из вершины 16 заняты 16 ячеек из 32. После pop() длина равна 15, а 15 + 1 + 6 = 22 даёт 20 ячеек. До расширения нужно 21 − 15 = 6 добавлений, до сокращения 15 − 9 = 6 извлечений. При девяти записях остаётся 9 + 1 + 6 = 16 ячеек. Каждый вызов меняет длину на единицу, поэтому в среднем на вызов приходится не больше 20 / 6 < 4 скопированных ячеек.

Пусть после пересчёта выделено c ячеек. Первое округление убирает меньше единицы, второе не больше трёх. Прибавка шести покрывает обе потери, поэтому k + k / 8 ≤ c ≤ k + k / 8 + 6. При k ≥ 16 получаем 6 ≤ 3k / 8 и c ≤ 3k / 2. До расширения нужно c + 1 − k ≥ k / 8 добавлений, до сокращения k − c / 2 + 1 ≥ k / 4 извлечений. До следующего пересчёта пройдёт хотя бы k / 8 вызовов. Последний вызов в этой группе копирует до c ячеек, в среднем до (3k / 2) / (k / 8) = 12 на вызов. При k < 16 он копирует не больше тех 20 ячеек, что получили при k = 15. Вызов без пересчёта занимает O(1) времени. Такие группы не пересекаются, поэтому все вызовы занимают O(n) времени.

В первом наборе код добавляет в children восемь пустых списков, а в них шесть номеров детей. Код создаёт пустой список за O(1) времени. По оценке для append все n + 1 добавлений списков и n − 1 добавлений номеров занимают O(n) времени. Чтение родителей и цветов тоже занимает O(n) времени.

В prefix каждый вес входит один раз, а before хранит сумму до входа. Для модулей обеих сумм хватает тех же 12 двоичных цифр, поэтому прибавление веса и сравнение prefix == before занимают O(1) времени. Время: O(n) в худшем случае на набор.

В первом наборе больше всего записей в Stack перед входом в 7. В восьми ячейках три пары для выхода (1, 3, 5) и две для входа (6, 7). Код снимает запись о входе до добавления записи о выходе. На вершину в Stack не больше одной пары, всего до 2n значений. После пересчёта c ≤ k + k / 8 + 6 ≤ 2k + 6. Иначе занята хотя бы половина, и ячеек не больше 2k. Для Stack хватает 2n + 6 ячеек.

Во втором наборе три из четырёх ячеек children указывают на списки детей. При k = n + 1 хватит 2(n + 1) + 6 ячеек. В первом наборе шесть номеров детей лежат в 4 списках по 4 ячейки, всего 4 · 4 = 16 ячеек. Сложим оценки 2k + 6 для всех n + 1 списков. Сумма их длин равна n − 1, поэтому хватит 2(n − 1) + 6(n + 1) ячеек. Даже пустой список children[4] хранит длину. Это ещё O(1) памяти на список. Дополнительная память: O(n) на набор в худшем случае.

В примере pop() извлекает 14 + 4 + 16 = 34 записи. По оценке для Stack добавление t строк в answers с переносами занимает O(t) времени. Столько же тратят join и print. В худшем случае время пропорционально общему числу вершин. Со списком и строкой для печати нужно O(nmax + t) дополнительной памяти в худшем случае.
