Нужно выписать каждый набор чисел из nums один раз.

Решение 1. Backtracking после Sorting

Возьмите пример 1: nums = [1, 2, 2]. Пусть n - длина nums, здесь n = 3. Наборов индексов 23 = 8. Набор [2] получается из индекса 1 и из индекса 2, набор [1, 2] тоже два раза. Поэтому разных ответов 6, а не 8.

Число ответов можно посчитать заранее. Единицу ответ берёт ноль или один раз: 2 варианта. Двойку он берёт ноль, один или два раза: 3 варианта. Всего 2 · 3 = 6. Если значение встречается f раз, у него f + 1 вариантов. Пусть U - произведение чисел f + 1 по всем разным значениям. Тогда ответов ровно U. Для десяти разных чисел U = 210 = 1024, а для десяти чисел 7 только U = 11.

Сначала nums.sort() ставит равные числа рядом. Вызов dfs(start) кладёт в res копию path: каждый вызов даёт один ответ. Затем цикл выбирает следующее число ответа среди индексов от start до n − 1. Правило: в одном цикле каждое значение берём один раз. Индекс i пропускаем, если i > start и nums[i] == nums[i - 1].

Повторов нет. В вызове dfs(0) цикл берёт 1 с индекса 0 и 2 с индекса 1. Индекс 2 он пропускает: nums[2] = nums[1] = 2, и 2 > 0. Поэтому [2] строится только из индекса 1. Так в любом вызове. Индексы пути растут, а nums отсортирован, поэтому два пути к одному набору дают одни и те же числа в одном порядке. Они расходятся в одном вызове: там оба берут одно значение с разных индексов. Цикл берёт это значение только с самого левого индекса, поэтому второго пути нет.

Ответы не теряются. Набору [2, 2] нужны обе двойки. После выбора индекса 1 идёт вызов dfs(2). В нём i = 2 = start, проверка i > start ложна, и вторая двойка попадает в path. Путь к любому ответу может брать каждый раз самую левую из оставшихся копий нужного значения. Слева от неё стоит меньшее число, или она стоит на месте start. Проверка её не пропускает, поэтому каждый из U ответов строится. Рисунок показывает 6 вызовов, 2 пропуска и 2 проверки, где i = start и вторая двойка идёт в path.

class Solution:
    def subsetsWithDup(self, nums: list[int]) -> list[list[int]]:
        nums.sort()  # равные числа встают рядом
        res = []
        path = []

        def dfs(start):
            res.append(path[:])  # каждый вызов даёт один ответ
            for i in range(start, len(nums)):
                if i > start and nums[i] == nums[i - 1]:
                    continue  # на этом уровне такое число уже брали
                path.append(nums[i])
                dfs(i + 1)
                path.pop()

        dfs(0)
        return res

Время: каждый вызов даёт один ответ, поэтому вызовов ровно U. Вызов копирует path длины не больше n и проверяет в цикле не больше n индексов. Вместе с Sorting получаем O(n log n + n · U) в худшем случае. Для [1, 2, 2] это 6 вызовов, 9 скопированных чисел и 7 проверок в цикле, из них 2 пропуска. Для десяти разных чисел 1024 вызова копируют 5120 чисел.

Дополнительная память: path хранит до n чисел, Call Stack держит до n + 1 вызовов dfs. Вместе с Sorting это O(n). Ответ занимает U list и не больше n · U чисел, его считаем отдельно.

Можно отсортировать nums, перебрать все 2n наборов индексов и убрать повторы через set из tuple. После Sorting одинаковые наборы чисел дают одинаковые tuple. При n = 10 это 1024 набора по 10 проверок индексов: 10 240 проверок, O(n · 2n). Такой перебор тоже проходит тесты, но для десяти чисел 7 он строит 1024 набора ради 11 разных. Решение 1 на этом входе делает 11 вызовов.

Решение 2. Hash Table и число копий

Счёт 2 · 3 даёт второй способ. Counter - это Hash Table: для [1, 2, 2] он хранит пары 1: 1 раз и 2: 2 раза. Сначала res = [[]]. После значения 1 res равен [[], [1]]. Значение 2 продлевает [] до [2] и [2, 2], а [1] до [1, 2] и [1, 2, 2]. Всего 2 · 3 = 6 ответов.

Для значения v с числом копий f к каждому старому ответу добавляем в конец 1, 2, ..., f копий v. Старые ответы тоже остаются: в них 0 копий v. sorted перебирает значения по возрастанию, поэтому числа в каждом ответе идут по возрастанию, как в примере. Тесты принимают и другой порядок чисел в ответе.

Каждый ответ задаётся числом копий каждого значения, а циклы перебирают все эти числа от 0 до f. Поэтому ни один ответ не теряется. Два новых ответа из разных старых различаются там же, где старые: [2] и [1, 2] различаются числом единиц. Два новых ответа из одного старого различаются числом копий v: [1, 2] и [1, 2, 2]. Цикл for k in range(old) идёт только по старым ответам. Новые ответы уже содержат v: из нового [2] ещё одна двойка дала бы [2, 2] второй раз.

from collections import Counter


class Solution:
    def subsetsWithDup(self, nums: list[int]) -> list[list[int]]:
        res = [[]]
        for v, f in sorted(Counter(nums).items()):
            old = len(res)
            # к каждому старому ответу добавляем 1, 2, ..., f копий v
            for k in range(old):
                for c in range(1, f + 1):
                    res.append(res[k] + [v] * c)
        return res

Время: Counter проходит nums за O(n) в среднем случае Hash Table, а sorted упорядочивает не больше n пар за O(n log n). Новый ответ длины L строится копированием за O(L). Сумма длин всех ответов не больше n · U, поэтому всего O(n log n + n · U), как у решения 1. Для [1, 2, 2] пять новых ответов имеют длины 1, 1, 2, 2 и 3: всего 9 чисел.

Дополнительная память: Counter и список его пар хранят не больше n пар, временный list [v] * c хранит не больше n чисел: O(n). Все list в res - это ответ.

Типичные ошибки

  • Проверка i > 0 вместо i > start. Тогда вторая двойка пропускается и в dfs(2), где она первая в цикле. Для [1, 2, 2] код вернёт 4 ответа: [], [1], [1, 2] и [2]. Ответы [1, 2, 2] и [2, 2] пропадут.
  • Решение 1 без nums.sort(). Проверка соседей не видит равных чисел, которые стоят не рядом. Для [4, 4, 4, 1, 4] код вернёт 16 наборов, но разных среди них только 10: например, [4, 1] и [1, 4] - это один набор.
  • res.append(path) без копии. Тогда все элементы res - это один и тот же list path. После последнего pop он пуст, и для [1, 2, 2] ответ равен [[], [], [], [], [], []].
