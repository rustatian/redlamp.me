Нужно число пар с суммой от l до r. Его дают два более простых подсчёта: пары с суммой не больше r и пары с суммой не больше l − 1. Оба подсчёта работают на отсортированном Array.

Sorting не меняет ответ

В первом тесте примера a = [5, 1, 2]. Три пары номеров дают суммы 5 + 1 = 6, 5 + 2 = 7 и 1 + 2 = 3. После Sorting a = [1, 2, 5], и три пары дают те же суммы 3, 6 и 7. Sorting переносит каждое число на новое место. Пара двух чисел становится парой их новых мест, и её сумма не меняется. Числа 5 и 1 стоят на местах 1 и 2, а после Sorting на местах 3 и 1. Меньшее место пишем первым: получаем пару (1, 3), и i < j снова выполнено. Поэтому после Sorting число пар с суммой от l до r то же.

Ответ как разность двух подсчётов

Пусть count(x) - число пар i < j с суммой ai + aj ≤ x. Во втором тесте примера l = 5, r = 8, и после Sorting a = [1, 2, 3, 4, 5]. Десять пар дают суммы 3, 4, 5, 5, 6, 6, 7, 7, 8, 9. Не больше 8 девять сумм: count(8) = 9. Не больше 4 две суммы 3 и 4: count(4) = 2. Остальные 9 − 2 = 7 сумм лежат от 5 до 8, и ответ теста 7.

Правило. Ответ равен count(r) − count(l − 1). Суммы целые, поэтому сумма не меньше l - это сумма больше l − 1.

Решение 1. Two Pointers

Дальше номера идут с 0, как в коде: a[0] - первое число. count(x) ставит указатель lo = 0 на левый край отсортированного a, а указатель hi = n − 1 на правый. Каждый шаг проверяет сумму a[lo] + a[hi] и сдвигает один указатель. Пример: x = 8, a = [1, 2, 3, 4, 5].

Первый шаг: a[0] + a[4] = 1 + 5 = 6 ≤ 8. Каждое число a[1], ..., a[4] не больше a[4] = 5, поэтому каждая сумма 1 + a[k] не больше 1 + 5 = 6 ≤ 8. Все hi − lo = 4 пары с числом a[0] подходят: res = 4. Ход lo += 1 ничего не теряет: все пары с a[0] уже посчитаны. Следующие шаги дают 2 + 5 = 7 и 3 + 5 = 8: ещё 3 и 2 пары, res = 9. Последний шаг 4 + 5 = 9 > 8 сдвигает hi, и count(8) = 9.

Проход с x = 4 начинается с 1 + 5 = 6 > 4. Каждое число a[0], ..., a[3] не меньше a[0] = 1, поэтому каждая сумма a[k] + 5 не меньше 1 + 5 = 6 > 4. Число a[4] = 5 не даёт ни одной подходящей пары, и ход hi -= 1 ничего не теряет. Сумма 1 + 4 = 5 > 4 так же убирает число 4. Сумма 1 + 3 = 4 ≤ 4 даёт 2 пары: 1 + 2 и 1 + 3. Сумма 2 + 3 = 5 > 4 убирает число 3, и lo = hi = 1: count(4) = 2.

Перед каждой проверкой res равен числу подходящих пар, у которых хотя бы один номер вне окна от lo до hi. Номер слева от lo при ходе lo += 1 дал все свои подходящие пары с номерами справа от него. Номер справа от hi при ходе hi -= 1 не имел подходящих пар с номерами окна. Указатель lo только растёт, поэтому в том окне были все номера от текущего lo до этого номера, в том числе меньшие номера справа от hi. Проход кончается при lo = hi: в окне одно число, пар внутри окна нет, и res = count(x).

Каждый шаг сдвигает lo или hi на 1, и разность hi − lo падает с n − 1 до 0. Поэтому проход делает ровно n − 1 проверок: при n = 5 это 4 проверки.

import sys


def count(a, x):
    # число пар lo < hi с суммой a[lo] + a[hi] <= x, Array a отсортирован
    lo, hi = 0, len(a) - 1
    res = 0
    while lo < hi:
        if a[lo] + a[hi] <= x:
            # a[lo] + a[k] <= x для каждого k от lo + 1 до hi: hi - lo пар
            res += hi - lo
            lo += 1
        else:
            # a[k] + a[hi] > x для каждого k от lo до hi - 1: у a[hi] нет пар в окне
            hi -= 1
    return res


data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, l, r = int(data[pos]), int(data[pos + 1]), int(data[pos + 2])
    a = sorted(map(int, data[pos + 3:pos + 3 + n]))
    pos += 3 + n
    # пары с суммой от l до r: пары с суммой не больше r без пар с суммой не больше l - 1
    out.append(count(a, r) - count(a, l - 1))
print("\n".join(map(str, out)))

Время: O(n log n) на тест в худшем случае. Sorting делает O(n log n) сравнений, а два прохода count вместе делают 2(n − 1) проверок. Сумма n по всем тестам не больше 2 · 105, поэтому проходы всех тестов вместе делают меньше 4 · 105 проверок. Дополнительная память: O(n) на тест для любого входа: срез data[pos + 3:pos + 3 + n] и список a хранят по n элементов, а count хранит только lo, hi и res. Кроме того, список data хранит все 1 + 3t + ∑n чисел входа, где ∑n - сумма n по всем тестам. Ответ отдельно: в out t чисел.

Решение 2. Binary Search

На том же a = [1, 2, 3, 4, 5] при x = 4 и i = 0 справа от номера 0 нужны числа не больше 4 − 1 = 3. Подходят 2 и 3 на номерах 1 и 2, а 4 на номере 3 уже больше 3. bisect_right(a, 3, 1) возвращает end = 3, и пар 3 − 1 = 2. Для каждого номера i count(x) ищет пары с номерами j > i. Нужны числа a[j] ≤ x − a[i]. В отсортированном Array они стоят подряд, начиная с номера i + 1: если a[j] ≤ x − a[i], то и каждое число от a[i + 1] до a[j] не больше a[j] и тоже подходит. bisect_right(a, x - a[i], i + 1) возвращает end: первый номер от i + 1, где a[end] > x − a[i], или n, если такого номера нет. Подходят номера от i + 1 до end − 1, это end − (i + 1) пар.

Пример: x = 8, a = [1, 2, 3, 4, 5]. При i = 0 нужны числа не больше 8 − 1 = 7: подходят все четыре числа 2, 3, 4, 5, и end = 5. При i = 1 и i = 2 подходят 3 и 2 числа. При i = 3 нужно a[j] ≤ 4, но a[4] = 5: end = 4, пар нет. При i = 4 справа чисел нет, и end = 5 = i + 1. Всего 4 + 3 + 2 = 9 = count(8).

import sys
from bisect import bisect_right


def count(a, x):
    # число пар i < j с суммой a[i] + a[j] <= x, Array a отсортирован
    res = 0
    for i in range(len(a)):
        # j ищем только справа от i: a[j] <= x - a[i] для j от i + 1 до end - 1
        end = bisect_right(a, x - a[i], i + 1)
        res += end - (i + 1)
    return res


data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, l, r = int(data[pos]), int(data[pos + 1]), int(data[pos + 2])
    a = sorted(map(int, data[pos + 3:pos + 3 + n]))
    pos += 3 + n
    # пары с суммой от l до r: пары с суммой не больше r без пар с суммой не больше l - 1
    out.append(count(a, r) - count(a, l - 1))
print("\n".join(map(str, out)))

Время: O(n log n) на тест в худшем случае. Кроме Sorting, два прохода count делают 2n поисков. Поиск справа от i идёт по n − 1 − i числам и делает O(log n) сравнений: при n = 2 · 105 не больше 18. Дополнительная память: O(n) на тест для любого входа, как в решении 1: count хранит только i, end и res.

Что не подходит

Brute Force проверяет каждую пару: n(n − 1)/2 сумм на тест, O(n²). При n = 2 · 105 это 19 999 900 000 проверок, около 2 · 1010: слишком долго.

Типичные ошибки

  • Ответ count(r) − count(l) теряет пары с суммой ровно l. Во втором тесте count(5) = 4, и разность 9 − 4 = 5 вместо 7: пропали пары 1 + 4 и 2 + 3 с суммой 5.
  • Binary Search по всему Array, а не справа от i, считает каждую пару дважды и пару числа с самим собой. В первом тесте после Sorting a = [1, 2, 5], l = 4, r = 7. Такой подсчёт находит 1 + 5 и 5 + 1, 2 + 5 и 5 + 2, а также 2 + 2 = 4: 5 пар вместо 2.
  • Проход Two Pointers без Sorting может потерять пару. В первом тесте a = [5, 1, 2], и при x = l − 1 = 3 суммы 5 + 2 = 7 и 5 + 1 = 6 больше 3, и hi доходит до lo = 0. Пара 1 + 2 = 3 теряется: count(3) = 0 вместо 1, и ответ count(7) − count(3) = 3 − 0 = 3 вместо 2.
