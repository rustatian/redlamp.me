При k = 5 возьмём [1, 1, 4, 4]. Поищем пару для первой единицы среди остальных чисел слева направо. Сначала проверим сумму с другой единицей, потом с четвёркой. Уберём первую единицу и первую четвёрку. Для оставшихся единицы и четвёрки хватит одной проверки. Когда чисел не осталось, возвращаем True.

В списке [1, 6, 4, 9] при поиске пары для 1 первым подходит число 4. Возьмём любое разбиение всех чисел на подходящие пары, если такое разбиение есть. Если 1 и 4 уже в одной паре, её можно сразу убрать. Если у них другие партнёры, заменим пары (1, 9) и (6, 4) на (1, 4) и (6, 9). Два подходящих партнёра одного числа отличаются на кратное k, ведь их разность равна разности двух сумм, кратных k. Если поменять таких партнёров местами в готовых парах, обе суммы останутся кратными k. Поэтому можно убрать первую найденную пару.

В третьем примере из условия при k = 10 суммы единицы с числами от 2 до 6 равны 3, 4, 5, 6 и 7. Ни одна из них не делится на 10. Если поиск не находит партнёра, возвращаем False.

При k = 5 запишем подряд 50 000 единиц, а за ними 50 000 четвёрок. Первый поиск проверит 49 999 других единиц и одну четвёрку. Мы убираем по одной единице и четвёрке, поэтому каждый следующий поиск проверит на одну единицу меньше, прежде чем дойдёт до четвёрки. Такой Brute Force проверит 50 000 + 49 999 + … + 1 = 1 250 025 000 сумм. За три секунды, отведённые на тест, Python не успеет проверить столько сумм. При n = len(arr) один поиск проверяет меньше n сумм и занимает O(n) в худшем случае. После каждого поиска мы убираем пару или останавливаемся. Поэтому поисков не больше n // 2, а общее время в худшем случае равно O(n2).

Решение 1. Счётчики остатков

В первом примере из условия 6 + 9 = 15. Остатки от деления на 5 равны 1 и 4, а 1 + 4 = 5. При замене 6 на 1 мы вычли 5, а при замене 9 на 4 вычли ещё 5. Число и его остаток отличаются на кратное k, поэтому такая замена сохраняет остаток суммы.

Среди остатков от 0 до 4 только 4 даёт с 1 сумму, кратную 5. В Python выражение (-1) % 5 даёт нужный остаток 5 − 1 = 4, так как −1 = −5 + 4. Для нуля 0 % 5 даёт 0. Сумма двух остатков меньше 2 · k, поэтому из кратных k возможны только 0 и k. Для нуля нужен ноль, для ненулевого r нужен k − r. При 0 < r < k прибавим k к −r без изменения остатка. Получим число k − r от 1 до k − 1, то есть сам остаток. Формула other = (-r) % k даёт нужный остаток в обоих случаях.

В том же примере числа 1 и 6 дают остаток 1, а числа 4 и 9 дают остаток 4. Из этих групп получаются две пары (1, 4) и (6, 9). Счётчик cnt[r] хранит количество чисел с остатком r. Если r и other различны, каждая пара берёт по одному числу из каждой группы. При равных счётчиках можно соединить все числа этих групп, а при разных в большей группе останутся числа без пары.

Числа 5 и 10 дают остаток 0 и составляют одну пару. Чтобы разбить на пары всю группу с остатком 0, нужен чётный cnt[0]. При k = 4 числа 2 и 6 дают остаток 2, а 2 + 2 = 4. Ненулевой остаток r подходит сам к себе только при r + r = k. Тогда k чётно и r = k // 2. Числа этой группы образуют пары только друг с другом, поэтому её счётчик тоже должен быть чётным. В списке [4, 2, 1, 3] при k = 4 числа 1 и 3 составят пару, но 4 и 2 останутся по одному в своих группах. Ответ для этого списка равен False.

Вернёмся к первому примеру из условия, где k = 5.

При r = 2 цикл получает other = 3 и сравнивает cnt[2] с cnt[3]. Оба счётчика равны 2, поэтому из этих групп получаются две пары. Вместе с парами из остальных групп это пять пар. При r = 3 цикл сравнил бы те же счётчики. Из двух разных остатков с суммой k меньший всегда меньше половины k. Поэтому цикл проверяет r от 0 до k // 2 включительно.

class Solution:
    def canArrange(self, arr: list[int], k: int) -> bool:
        cnt = [0] * k
        for x in arr:
            cnt[x % k] += 1

        for r in range(k // 2 + 1):
            other = (-r) % k
            if r == other:
                if cnt[r] % 2:
                    return False
            elif cnt[r] != cnt[other]:
                return False
        return True

Время: O(n + k) в худшем случае. Код создаёт k счётчиков, проходит по n числам и проверяет группы остатков. Дополнительная память: O(k) в худшем случае для списка cnt.

Решение 2. Собирать пары по ходу чтения

При k = 5 в списке [1, 6, -1, 4] первые два числа имеют остаток 1. У первого числа пары пока нет, и waiting.get(1, 0) в пустом словаре даёт 0. Код прибавляет 1 и создаёт ключ словаря 1 со значением 1 (waiting = {1: 1}). После чтения четвёрки код удаляет последний ключ и получает waiting = {}. Все четыре числа вошли в пары, и not waiting даёт True. Если оставить waiting = {1: 0}, в словаре будет один ключ и not waiting даст False.

В waiting ключ словаря обозначает остаток, а значение показывает, сколько чисел с этим остатком ещё без пары. Если в словаре есть other, код берёт одно число с этим остатком в пару к x. Код уменьшает счётчик и удаляет запись при нулевом значении. Если пары для x пока нет, код увеличивает waiting[r].

Среди чисел без пары не останется двух с подходящими друг другу остатками. При чтении второго числа код сразу использует одно число с нужным остатком. Если в конце словарь пуст, все числа вошли в пары.

При k = 5 в списке [1, 6, 11, 4] три числа с остатком 1 и одно с остатком 4. Вычеркнем из списка пару (1, 4). Останутся числа 6 и 11 с остатком 1. В словаре waiting = {1: 2} есть ключ 1, а нужного для пары ключа 4 нет. Разность размеров групп останется равной 2 (3 − 1 = 2 − 0). Когда мы вычёркиваем пару из двух разных групп, в каждой становится на одно число меньше, поэтому разность их размеров сохраняется. Для оставшегося ключа r найдём остаток для пары по формуле other = (-r) % k. Если r != other, то чисел с остатком other без пары нет. Значит, чисел с остатком r было больше с самого начала.

При k = 4 в списке [4, 8, 12, 2] три числа с остатком 0. Числа 4 и 8 образуют пару, и из трёх чисел этой группы остаётся только 12. При r == other каждое второе число группы образует пару с предыдущим. Если такой ключ остался в waiting, то без пары осталось ровно одно число этой группы. Значит, исходный счётчик был нечётным. В обоих случаях разбить все числа на пары нельзя, и код возвращает False.

class Solution:
    def canArrange(self, arr: list[int], k: int) -> bool:
        waiting = {}
        for x in arr:
            r = x % k
            other = (-r) % k
            if other in waiting:
                waiting[other] -= 1
                if waiting[other] == 0:
                    del waiting[other]
            else:
                waiting[r] = waiting.get(r, 0) + 1
        return not waiting

Время: O(n), ожидаемое для Hash Table. На каждое число приходится постоянное количество операций со словарём. Дополнительная память: ожидаемое потребление памяти для Hash Table составляет O(min(n, k)). У каждого ключа есть хотя бы одно число без пары, а разных остатков всего k.
