Нужно сосчитать наборы из k отрезков с целыми концами от 0 до n − 1. Отрезок (a, b) покрывает b − a + 1 точек, и их хотя бы 2, поэтому a < b. Набор {(0,1),(1,2)} из примера 1 разрешён: у отрезков общий конец 1, но нет общей части.

Решение 1. Combinations

Возьмём набор {(0,2),(2,3)} из примера 1 и выпишем концы отрезков слева направо: 0, 2, 2, 3. Число 2 повторяется, потому что у отрезков общий конец 2. Из любых двух отрезков набора один кончается не правее начала другого: его пишем первым. Так отрезки встают слева направо: (a1, b1), (a2, b2), ..., (ak, bk), и a1 < b1 ≤ a2 < b2 ≤ ... ≤ ak < bk. Внутри отрезка концы разные, поэтому равные соседи в ряду концов бывают только там, где два отрезка делят конец.

Если бы общих концов не было, набор задавали бы 2k разных чисел от 0 до n − 1, и ответ был бы C(n, 2k). Повторы убирает сдвиг. Сдвинем оба конца второго отрезка на 1: ряд 0, 2, 2, 3 станет 0, 2, 3, 4. Набор {(0,1),(1,2)} даёт ряд 0, 1, 1, 2, а после такого сдвига 0, 1, 2, 3. В общем случае прибавим i − 1 к обоим концам i-го отрезка: первый остаётся на месте, второй сдвигается на 1, третий на 2. Похожий сдвиг есть в разделе Stars and Bars этой главы. Там i − 1 прибавляют к i-му числу, а здесь к обоим концам i-го отрезка: концы одного отрезка уже разные.

После сдвига все 2k чисел разные и идут по возрастанию. Оба конца i-го отрезка сдвинуты на одно и то же число i − 1, поэтому ai + i − 1 < bi + i − 1. Начало следующего отрезка сдвинуто на i, то есть на 1 больше. Из bi ≤ ai+1 получаем bi + i − 1 < ai+1 + i. В ряду 0, 2, 2, 3 конец первого отрезка остаётся 2, а начало второго становится 3. Самое малое число a1 не меньше 0. Самое большое bk + k − 1 не больше (n − 1) + (k − 1) = n + k − 2. Значит, набор задаёт 2k разных чисел от 0 до n + k − 2, а всего таких чисел n + k − 1. В примере 1 это 5 чисел от 0 до 4.

Обратно, возьмём любые 2k разных чисел от 0 до n + k − 2 по возрастанию. Первые два числа - концы первого отрезка, следующие два - концы второго, и так далее. Из концов i-го отрезка вычтем i − 1. Например, в примере 1 числа 0, 1, 3, 4 дают отрезки (0, 1) и (3 − 1, 4 − 1) = (2, 3). Начало каждого отрезка остаётся меньше его конца. Начало пары i + 1 хотя бы на 1 больше конца пары i, а вычитаем из него на 1 больше. Поэтому конец i-го отрезка не правее начала следующего, и отрезки не перекрываются. Самый правый конец не больше (n + k − 2) − (k − 1) = n − 1. Получился правильный набор, и сдвиг вернёт из него те же числа.

Так каждый набор отрезков даёт свой выбор 2k чисел из n + k − 1, и каждый выбор получается ровно из одного набора. Ответ C(n + k − 1, 2k). В примере 1 это C(5, 4) = 5: рисунок показывает 5 наборов и их числа. В примере 3 n = 30 и k = 7, поэтому наборов C(36, 14) = 3796297200, как в пояснении условия.

Осталось найти C(N, 2k) по модулю M = 109 + 7, где N = n + k − 1. По формуле C(N, 2k) = N! / ((2k)! · (N − 2k)!). Код строит таблицу fact до N, как в разделе 2 этой главы. Делить остатки нельзя. Поэтому код умножает на обратный элемент знаменателя x = (2k)! · (N − 2k)! % M: это pow(x, M − 2, M) из лекции Modular Arithmetic. Все множители (2k)! и (N − 2k)! не больше N ≤ 1000 + 999 − 1 = 1998, то есть меньше M. M - простое число, поэтому x не делится на M, и обратный элемент есть. Нужно одно число C, поэтому хватает одной таблицы и одного pow. В примере 1 получаем N = 5, fact = [1, 1, 2, 6, 24, 120], и 120 / (24 · 1) = 5.

class Solution:
    def numberOfSets(self, n: int, k: int) -> int:
        M = 10**9 + 7
        N = n + k - 1  # после сдвига концы - разные числа от 0 до n + k - 2
        fact = [1] * (N + 1)
        for i in range(1, N + 1):
            fact[i] = fact[i - 1] * i % M
        # C(N, 2k) = N! / ((2k)! · (N - 2k)!), деление - умножение на обратный элемент
        return fact[N] * pow(fact[2 * k] * fact[N - 2 * k] % M, M - 2, M) % M

Время: O(n + k + log M) для любого входа: N = n + k − 1 умножений для таблицы и одно pow за O(log M). Дополнительная память: O(n + k): list fact хранит n + k чисел. При n = 1000 и k = 999 это 1999 чисел.

Решение 2. Dynamic Programming и Prefix Sum

Этот способ обходится без сдвига. Пусть f(j, i) - число способов нарисовать j отрезков на точках от 0 до i. Возьмём пример 1: j = 2, i = 3. Наборы делятся на две группы. В первой ни один отрезок не кончается в точке 3, и оба отрезка лежат на точках от 0 до 2. Такой набор один: {(0,1),(1,2)}, то есть f(2, 2) = 1. Во второй группе последний отрезок (a, 3), где a от 0 до 2. Первый отрезок тогда лежит на точках от 0 до a: f(1, 0) = 0, f(1, 1) = 1, f(1, 2) = 3. Всего f(2, 3) = 1 + 0 + 1 + 3 = 5.

То же верно для любых j ≥ 1 и i ≥ 1: f(j, i) = f(j, i − 1) + f(j − 1, 0) + f(j − 1, 1) + ... + f(j − 1, i − 1). В первой группе точка i не конец отрезка, во второй группе конец, поэтому ни один набор не попадает в обе группы. Если последний отрезок (a, i), остальные j − 1 отрезков кончаются не правее точки a, и для них f(j − 1, a) способов. Без отрезков способ один: f(0, i) = 1. На одной точке 0 отрезок не помещается: f(j, 0) = 0 при j ≥ 1. Ответ f(k, n − 1).

Если для каждой клетки считать сумму заново, клетка f(j, i) стоит i сложений. Всего k · n(n − 1) / 2 сложений: при n = 1000 и k = 999 это около 5 · 108, слишком долго.

В примере 1 при j = 2 сумма для i = 2 равна f(1, 0) + f(1, 1) = 0 + 1 = 1, а для i = 3 равна 0 + 1 + 3 = 4: на f(1, 2) = 3 больше. Так всегда: сумма для клетки i больше суммы для клетки i − 1 ровно на f(j − 1, i − 1). Поэтому код хранит сумму в s и на каждом шаге прибавляет к ней prev[i - 1]: это Prefix Sum строки j − 1. Строку j − 1 хранит list prev, строку j хранит list cur. Строка j = 1 в примере 1 равна 0, 1, 3, 6, и шаг j = 2, i = 3 даёт s = 1 + 3 = 4 и cur[3] = 1 + 4 = 5.

class Solution:
    def numberOfSets(self, n: int, k: int) -> int:
        M = 10**9 + 7
        prev = [1] * n  # 0 отрезков: на точках от 0 до i один способ
        for j in range(1, k + 1):
            cur = [0] * n  # cur[i]: способы для j отрезков на точках от 0 до i
            s = 0  # prev[0] + ... + prev[i - 1]
            for i in range(1, n):
                s = (s + prev[i - 1]) % M
                # последний отрезок кончается до точки i или в точке i
                cur[i] = (cur[i - 1] + s) % M
            prev = cur
        return prev[n - 1]

Время: O(nk) для любого входа: k проходов по n − 1 точкам, в каждом шаге два сложения. При n = 1000 и k = 999 это 998001 шаг. Дополнительная память: O(n): prev и cur хранят по n чисел.

Типичные ошибки

  • Ответ C(n, 2k). Так считают только наборы, где все 2k концов разные. В примере 1 ответ 1 вместо 5: остаётся только набор {(0,1),(2,3)}.
  • Таблица fact до n вместо N = n + k − 1. При k ≥ 2 число N больше n, и код читает fact[N] за концом таблицы: пример 1 падает с IndexError.
  • Строка cur[i] = (cur[i - 1] + s) % M стоит перед строкой, которая прибавляет prev[i - 1] к s. Тогда в счёт попадают только отрезки, которые покрывают 3 точки и больше. В примере 2 ответ 1 вместо 3: остаётся только отрезок (0, 2).
