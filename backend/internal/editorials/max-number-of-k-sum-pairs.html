Число x даёт сумму k только с числом k − x. В примере 1 при k = 5 число 1 идёт в пару с 4, а число 2 с 3. Нужно составить как можно больше таких пар, и каждое число входит не больше чем в одну пару.

Решение 1. Sorting + Two Pointers

Ответ это число операций, места чисел в ответ не входят. Поэтому порядок чисел можно менять, и nums.sort() ответ не меняет. Возьмите пример 2: после Sorting nums = [1, 3, 3, 3, 4], k = 6. Указатель l стоит на месте 0, указатель r на месте 4.

Сумма 1 + 4 = 5 меньше 6. Числа окна от l до r не больше 4, поэтому число 1 с любым из них даёт не больше 5. Числу 1 пары нет, и l идёт вправо. Теперь сумма 3 + 4 = 7 больше 6. Числа окна не меньше 3, поэтому число 4 с любым из них даёт не меньше 7. Числу 4 тоже пары нет, и r идёт влево.

Сумма 3 + 3 = 6 равна k. Это операция: ops становится 1, и оба указателя идут внутрь. Теперь l и r стоят на месте 2, и цикл заканчивается. Число 3 на месте 2 осталось без пары, ответ 1.

При равной сумме решение сразу убирает оба числа, и ответ от этого не становится меньше. Возьмите nums = [1, 1, 4, 4, 4] и k = 5. При l = 0 и r = 4 сумма 1 + 4 = 5. Число 1 даёт сумму 5 только с числом 4. Пусть какой-то способ не делает ни одной операции 1 + 4. Тогда все числа 1 и 4 остаются без пары, и можно сделать ещё одну операцию. Значит, лучший способ делает хотя бы одну операцию 1 + 4. Все числа 1 одинаковы, все числа 4 тоже, поэтому неважно, какие из них убрать. После операции остаются числа [1, 4, 4], и решение снова находит 1 + 4 = 5. Ответ 2. Для суммы 3 + 3 = 6 в примере 2 рассуждение то же: числу 3 подходит только другое число 3.

Правило. Сумма меньше k: l += 1. Сумма больше k: r -= 1. Сумма равна k: ops += 1, затем l += 1 и r -= 1.

Каждый ход убирает из окна только числа, которые уже вошли в операцию или которым нет пары среди чисел окна. Число без пары в окне не получит пару и позже: окно только сужается. Значит, окно от l до r всегда хранит все числа, которые ещё могут войти в операцию.

class Solution:
    def maxOperations(self, nums: List[int], k: int) -> int:
        nums.sort()
        l, r = 0, len(nums) - 1
        ops = 0
        while l < r:
            s = nums[l] + nums[r]
            if s == k:
                ops += 1  # убираем оба числа
                l += 1
                r -= 1
            elif s < k:
                l += 1  # nums[l] мало даже с самым большим числом окна
            else:
                r -= 1  # nums[r] много даже с самым маленьким числом окна
        return ops

Время: n это длина nums. Sorting занимает O(n log n). Сначала r - l равно n − 1. Каждая сумма уменьшает эту разность на 1 или на 2, поэтому сумм не больше n − 1. В примере 2 n = 5, и сумм 3. Всего O(n log n) в худшем случае. Дополнительная память: l, r, s и ops занимают O(1), но nums.sort() в Python в худшем случае берёт O(n) рабочей памяти. Всего O(n). Ответ это одно число.

Решение 2. Hash Table

Пары можно посчитать и без Sorting. Hash Table cnt хранит, сколько раз каждое число есть в nums. Для nums = [1, 1, 4, 4, 4] и k = 5 это cnt[1] = 2 и cnt[4] = 3. Каждая операция убирает одно число 1 и одно число 4. Чисел 1 только два, поэтому операций не больше 2. Две операции 1 + 4 можно сделать, и одно число 4 останется. Для числа x и другого числа y = k − x операций min(cnt[x], cnt[y]).

Пары разных значений не мешают друг другу: в примере 1 число 1 идёт только с 4, а число 2 только с 3. Поэтому решение складывает min(cnt[x], cnt[y]) по всем x < y. Условие x < y считает пару 1 и 4 один раз: при x = 1. При x = 4 цикл её пропускает.

Особый случай: x = y. В примере 2 k = 6, и числу 3 нужно другое число 3. Чисел 3 три, cnt[3] = 3. Одна операция убирает два числа 3, поэтому операций 3 // 2 = 1. Числу 1 нужно 6 − 1 = 5, а чисел 5 нет. Counter даёт 0 для числа, которого в нём нет, поэтому min(cnt[1], cnt[5]) = min(1, 0) = 0. Числу 4 нужно 2, и 4 > 2, поэтому цикл пропускает его. Ответ 1.

from collections import Counter


class Solution:
    def maxOperations(self, nums: List[int], k: int) -> int:
        cnt = Counter(nums)  # cnt[x] - сколько раз число x есть в nums
        ops = 0
        for x in cnt:
            y = k - x  # единственное число, которое даёт с x сумму k
            if x < y:
                ops += min(cnt[x], cnt[y])
            elif x == y:
                ops += cnt[x] // 2  # пара из двух равных чисел
        return ops

Время: Counter(nums) читает каждое из n чисел один раз. Каждое чтение и каждая запись в Hash Table занимают ожидаемое O(1). Цикл делает u шагов, где u это число разных значений в nums, и u ≤ n. Всего ожидаемое O(n). Дополнительная память: cnt хранит u записей: O(u). В примере 2 u = 3. Ответ это одно число.

Что не подходит

Brute Force берёт числа по очереди и ищет пару среди следующих чисел, которые ещё не убраны. Убранные числа он отмечает. Если пар нет совсем, он проверяет все n(n − 1)/2 пар мест: O(n²). При n = 105 это 4 999 950 000 проверок: слишком долго.

Типичные ошибки

  • При равной сумме двигать только l. Для nums = [1, 1, 4] и k = 5 число 4 войдёт в две операции, и ответ будет 2 вместо 1.
  • Считать min(cnt[x], cnt[y]) и при x = y. В примере 2 получится min(3, 3) = 3, а три числа 3 дают только одну операцию.
  • Считать пары без условия x < y. Тогда пара 1 и 4 войдёт в ответ при x = 1 и ещё раз при x = 4. В примере 1 получится 4 вместо 2.
  • Обычный dict вместо Counter. В примере 2 cnt[5] даёт KeyError, потому что числа 5 в nums нет. Для dict нужен cnt.get(y, 0).
