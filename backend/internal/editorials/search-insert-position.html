Ответ - одно из n + 1 мест от 0 до n, где n - длина nums: место, на котором target стоит или стоял бы.

Linear Scan идёт слева направо и останавливается на первом числе, которое не меньше target. При n = 104 это до 104 сравнений, то есть O(n), а задача требует O(log n). Binary Search ниже делает для такого n не больше 14 проверок.

Решение 1. Binary Search

Возьмите пример 2: nums = [1, 3, 5, 6], target = 2. Проверим условие nums[i] ≥ target в каждом индексе: 1 ≥ 2 нет, 3 ≥ 2 да, 5 ≥ 2 да, 6 ≥ 2 да. Первое «да» стоит в индексе 1: это ответ. Array упорядочен по возрастанию, поэтому после первого «да» идут только «да»: условие идёт «нет, да, да, да».

Первое «да» даёт ответ, и когда target есть в nums, и когда его нет. Числа левее него меньше target, поэтому target стоит правее них. Если число с первым «да» равно target, ответ - его индекс. Если оно больше, как 3 при target = 2, target занимает его место, а это число сдвигается вправо. Для target = 5 условие даёт нет, нет, да, да: первое «да» в индексе 2, и число 5 стоит именно там. Для target = 7 все четыре проверки дают «нет». Тогда ответ n = 4: место после конца Array.

Правило. Ответ - Lower Bound: первый индекс i с nums[i] ≥ target, а если такого индекса нет, то n.

Binary Search находит первое «да» без проверки каждого индекса. Возьмём lo = 0 и hi = 4: ответ лежит от lo до hi включительно. Середина mid = (0 + 4) // 2 = 2, и 5 ≥ 2: «да». Первое «да» стоит в mid или левее, поэтому hi = 2. Теперь mid = (0 + 2) // 2 = 1, и 3 ≥ 2: «да», поэтому hi = 1. Теперь mid = 0, и 1 ≥ 2: «нет». Первое «да» правее mid, поэтому lo = 1. Теперь lo = hi = 1: ответ 1. Это 3 проверки.

Правило. При nums[mid] ≥ target шаг hi = mid, иначе шаг lo = mid + 1. Цикл идёт, пока lo < hi. При lo = hi ответ равен lo.

Середина с «да» может быть ответом, поэтому hi = mid, а не mid - 1. Возьмите nums = [1, 3] и target = 3. Первая середина 1 даёт 3 ≥ 3, и ответ как раз 1. Шаг hi = mid - 1 дал бы hi = 0 и ответ 0. Середина с «нет» не может быть ответом, поэтому lo = mid + 1.

Начальное значение hi = len(nums), а не len(nums) - 1, потому что ответ n возможен. Пример 3: target = 7. Середина 2 даёт 5 < 7 и lo = 3. Середина 3 даёт 6 < 7 и lo = 4. Теперь lo = hi = 4: ответ 4. Цикл не читает nums[4]. При lo = 3 и hi = 4 середина mid = (3 + 4) // 2 = 3 меньше hi. То же верно для любых lo < hi: mid < hi. Значение hi начинается с n = 4 и только уменьшается, поэтому mid не больше 3.

В примере 2 длины hi - lo равны 4, 2, 1, 0. Цикл заканчивается, потому что длина каждый раз уменьшается. После hi = mid длина равна mid - lo: она меньше, потому что mid < hi. После lo = mid + 1 длина равна hi - mid - 1: она меньше, потому что mid ≥ lo.

class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        lo, hi = 0, len(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] >= target:
                hi = mid  # mid может быть первым «да»
            else:
                lo = mid + 1  # mid и числа левее него меньше target
        return lo

Время: каждая проверка оставляет не больше половины отрезка: из длины 5 получается 2 в обоих случаях, из длины 4 получается 2 или 1. Самые длинные отрезки при n = 104: 10000, 5000, 2500, 1250, 625, 312, 156, 78, 39, 19, 9, 4, 2, 1. Это 14 проверок: O(log n) в худшем случае. Дополнительная память: lo, hi и mid, O(1) в худшем случае.

Готовая функция

Функция bisect_left(nums, target) из модуля bisect возвращает тот же ответ. Для примеров 1, 2 и 3 это 2, 1 и 4. Её время O(log n) в худшем случае, дополнительная память O(1) в худшем случае.

Типичные ошибки

  • hi = len(nums) - 1. Для nums = [1, 3, 5, 6] и target = 7 цикл заканчивается при lo = hi = 3 и возвращает 3, а нужен ответ 4.
  • hi = mid - 1 при while lo < hi теряет середину с «да», как в примере с nums = [1, 3] выше.
  • while lo <= hi вместе с hi = mid. Для nums = [1] и target = 1 после первой проверки lo = hi = 0, и шаг hi = mid = 0 повторяется без конца.
  • nums[mid] > target вместо nums[mid] ≥ target. Для примера 1 цикл возвращает 3, а нужен ответ 2. Индекс 3 - это Upper Bound, место сразу после числа 5.
