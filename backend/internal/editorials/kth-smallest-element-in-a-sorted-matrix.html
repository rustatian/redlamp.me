Если выписать все n2 чисел matrix по неубыванию, ответ стоит на месте k, считая с 1. Можно собрать их в один list и применить Sorting за O(n2 log(n + 1)) времени. При n = 300 такая копия хранит 90 000 чисел: это O(n2) дополнительной памяти, а условие требует меньше. Ниже два способа без копии.

Решение 1. K-Way Merge строк через Min-Heap

Возьмём пример 1: matrix = [[1, 5, 9], [10, 11, 13], [12, 13, 15]], k = 8. Каждая строка - отсортированная последовательность. Наименьшее из оставшихся чисел стоит первым среди оставшихся чисел своей строки: правее в строке числа не меньше. Поэтому Min-Heap h хранит для каждой строки одну запись (число, строка, столбец): её первое ещё не удалённое число.

Сначала в h лежат (1, 0, 0), (10, 1, 0) и (12, 2, 0). heappop достаёт вершину h[0], наименьшую запись (1, 0, 0): число 1 первое по порядку. Затем heappush добавляет следующее число той же строки: (5, 0, 1). Следующие удаления дают 5, 9, 10, 11, 12, 13 и 13. После удаления 9 строка 0 кончилась, и код ничего не добавляет. Восьмое удаление достаёт (13, 2, 1): ответ 13.

Почему удаления идут по неубыванию. После трёх удалений строка 0 пуста, а в h лежат (10, 1, 0) и (12, 2, 0). Остальные числа строки 1 - это 11 и 13, они не меньше 10. Остальные числа строки 2 - это 13 и 15, они не меньше 12. Значит, все оставшиеся числа не меньше 10, и 10 стоит на месте 4. Так на каждом шаге: в h лежит первое оставшееся число каждой непустой строки. Каждое оставшееся число не меньше записи своей строки, а любая запись не меньше вершины. Поэтому вершина не больше любого оставшегося числа, и удаление номер k даёт число на месте k. Решению нужен только порядок в строках.

Повторы считаются отдельно, потому что у каждой клетки своя запись. Записи (13, 1, 2) и (13, 2, 1) уходят седьмым и восьмым удалением.

Время: создание n записей и heapify стоят O(n). Затем k − 1 шагов: один heappop и не больше одного heappush. В h не больше n записей, поэтому одна такая операция стоит O(log(n + 1)). Последний heappop даёт ответ. Итого O(n + k log(n + 1)) в худшем случае. В примере 1 это 3 начальные записи, 1 heapify, 8 heappop и 5 heappush. При n = 300 и k = 90 000 код делает 90 000 heappop. Оценка O(n + k log(n + 1)) и оценка Решения 2 не считают чтение входа из текста: чтение n2 чисел отдельно стоит O(n2). Дополнительная память: за heappop идёт не больше одного heappush, поэтому в h никогда не больше n записей: O(n). В примере 1 пик 3 записи.

import heapq


class Solution:
    def kthSmallest(self, matrix: list[list[int]], k: int) -> int:
        n = len(matrix)
        h = [(matrix[i][0], i, 0) for i in range(n)]  # (число, строка, столбец): первое число каждой строки
        heapq.heapify(h)
        for _ in range(k - 1):
            v, i, j = heapq.heappop(h)
            if j + 1 < n:
                heapq.heappush(h, (matrix[i][j + 1], i, j + 1))  # следующее число той же строки
        return heapq.heappop(h)[0]  # k-е удаление

Решение 2. Binary Search по значению

Пусть cnt(x) - сколько чисел Matrix не больше x. В примере 1 cnt(12) = 6: это 1, 5, 9, 10, 11 и 12. А cnt(13) = 8: добавились два числа 13. При k = 8 ответ 13 - наименьшее x, для которого cnt(x) ≥ 8.

Почему это верно. По неубыванию числа примера идут так: 1, 5, 9, 10, 11, 12, 13, 13, 15. cnt(12) = 6 < 8, поэтому число на месте 8 больше 12. cnt(13) = 8, поэтому оно не больше 13. Между 12 и 13 других целых чисел нет, и на месте 8 стоит 13. В общем случае: если x - наименьшее значение с cnt(x) ≥ k, то cnt(x − 1) < k. Число на месте k больше x − 1 и не больше x, значит, оно равно x. Поэтому найденное x всегда есть в Matrix.

Когда x растёт, cnt(x) не уменьшается. Поэтому Binary Search ищет x от lo = matrix[0][0] до hi = matrix[n - 1][n - 1], в примере от 1 до 15. Это наименьшее и наибольшее числа. В примере 1 путь от левого верхнего угла до клетки matrix[1][2] = 13 идёт ходами вправо, вправо и вниз через числа 1, 5, 9 и 13, а ход вниз от неё ведёт к 15 в правом нижнем углу. От левого верхнего угла до любой клетки и от неё до правого нижнего угла всегда можно дойти ходами вправо и вниз, а на таком пути числа не убывают. Если cnt(mid) ≥ k, ответ не больше mid, и код ставит hi = mid. Иначе ответ больше mid, и код ставит lo = mid + 1. В примере 1 круги внешнего цикла такие: mid = 8, cnt = 2, lo = 9; mid = 12, cnt = 6, lo = 13; mid = 14, cnt = 8, hi = 14; mid = 13, cnt = 8, hi = 13. Теперь lo = hi = 13: это ответ.

Код считает cnt(mid) одним путём от левого нижнего угла: i - строка, j - столбец. Для mid = 13 путь начинается с matrix[2][0] = 12. 12 ≤ 13, а столбец 0 отсортирован, поэтому числа над 12 тоже не больше 13: cnt = 3, j = 1. matrix[2][1] = 13 ≤ 13: столбец 1 даёт ещё 3, cnt = 6, j = 2. matrix[2][2] = 15 больше 13. Числа строки 2 от столбца 2 и правее не меньше 15, а 12 и 13 левее уже посчитаны. Строка 2 закончена: i = 1. matrix[1][2] = 13 ≤ 13: cnt = 8, j = 3. Путь вышел за правый край, и cnt(13) = 8.

Каждый шаг пути сдвигает j вправо или i вверх. Для mid = 8 путь сделал 3 сдвига вверх и 2 вправо: i дошло до −1, и путь кончился. Для mid = 13 путь сделал 3 сдвига вправо и 1 вверх: j дошло до 3 = n. Сдвигов каждого вида не больше n: j может вырасти от 0 только до n, а i может уменьшиться от n − 1 только до −1. Путь кончается, как только сдвигов одного вида стало n, поэтому сдвигов другого вида не больше n − 1. Значит, один подсчёт делает не больше n + (n − 1) = 2n − 1 шагов. В примере 1 подсчёты сделали 5, 5, 4 и 4 шага, а 2n − 1 = 5.

Время: значений от lo до hi всего D = matrix[n − 1][n − 1] − matrix[0][0] + 1. Каждый круг оставляет не больше половины значений, с округлением вверх. В примере 1 из 15 значений остаются 7, затем 3, 2 и 1. Поэтому кругов O(log(D + 1)). Здесь D ≤ 2 · 109 + 1 < 231, и кругов не больше 31. Один круг - это один подсчёт за O(n) шагов. Итого O(n log(D + 1)) в худшем случае. При n = 300 это не больше 31 · 599 = 18 569 шагов пути. Дополнительная память: семь чисел n, lo, hi, mid, cnt, i и j: O(1). Это ответ на первый дополнительный вопрос условия.

class Solution:
    def kthSmallest(self, matrix: list[list[int]], k: int) -> int:
        n = len(matrix)
        lo, hi = matrix[0][0], matrix[n - 1][n - 1]
        while lo < hi:
            mid = (lo + hi) // 2
            # cnt - сколько чисел не больше mid; путь от левого нижнего угла
            cnt, i, j = 0, n - 1, 0
            while i >= 0 and j < n:
                if matrix[i][j] <= mid:
                    cnt += i + 1  # столбец j: строки от 0 до i
                    j += 1
                else:
                    i -= 1  # строка i: числа от столбца j и правее больше mid
            if cnt >= k:
                hi = mid
            else:
                lo = mid + 1
        return lo

Типичные ошибки

  • Читать Matrix по строкам: matrix[(k - 1) // n][(k - 1) % n]. Строка 1 может начинаться с числа меньше конца строки 0. Для matrix = [[1, 2], [1, 3]], k = 2 такой код вернёт 2, а ответ 1.
  • Heap с ходами вправо и вниз без отметки добавленных клеток. В matrix = [[1, 2, 3], [4, 5, 6], [7, 8, 9]] клетку с 5 добавят дважды: под 2 и справа от 4. Шесть удалений дадут 1, 2, 3, 4, 5, 5, и при k = 6 код вернёт 5 вместо 6. Решение 1 добавляет только соседа справа, поэтому каждая клетка попадает в h один раз.
  • Возвращать mid, когда cnt(mid) = k. В примере 1 cnt(14) = 8, и такой код вернёт 14. Этого числа нет в Matrix. Круги должны идти, пока lo < hi.
  • mid = int((lo + hi) / 2). Здесь int() отбрасывает дробную часть, то есть округляет к нулю. Для matrix = [[-10, -5, 0], [-8, -3, 2], [-6, 1, 9]], k = 5 круги доходят до lo = −4, hi = −3. Тогда mid = −3, cnt(−3) = 5 ≥ 5, и hi = mid оставляет hi = −3: цикл не кончается. Оператор // округляет вниз: (-4 + -3) // 2 даёт −4.
