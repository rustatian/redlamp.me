Array упорядочен по возрастанию, но его начало могли перенести в конец: нужен индекс числа target или -1.

Brute Force читает числа слева направо и останавливается на первом числе, равном target. Это Linear Scan за O(n) в худшем случае: при n = 5000 он делает до 5000 сравнений, а условие требует O(log n). Обычный Binary Search на всём Array не подходит. В nums = [4, 5, 6, 7, 0, 1, 2] для target = 0 середина nums[3] = 7 больше 0, и поиск уходит влево, а 0 стоит в индексе 4. Решение 1 сначала находит место разрыва. Решение 2 на каждом шаге ищет упорядоченную половину.

Решение 1. Binary Search по месту разрыва

Возьмите пример 1: nums = [4, 5, 6, 7, 0, 1, 2]. Порядок ломается один раз, между 7 и 0. Числа 4, 5, 6, 7 до разрыва идут по возрастанию, числа 0, 1, 2 после разрыва тоже. Каждое число левой части больше последнего числа 2, а каждое число правой части не больше него.

Поэтому условие nums[i] ≤ nums[-1] идёт «нет, нет, нет, нет, да, да, да». Первое «да» стоит в индексе 4: это минимум, и с него начинается правая часть. Обозначим этот индекс p. Первое «да» находит шаблон Lower Bound.

Проверим на числах. Сначала lo = 0, hi = 6, mid = 3, и 7 > 2: «нет». Первое «да» правее mid, поэтому lo = 4. Теперь mid = 5, и 1 ≤ 2: «да». Первое «да» стоит в mid или левее, поэтому hi = 5. Теперь mid = 4, и 0 ≤ 2: «да», поэтому hi = 4. Получилось lo = hi = 4, то есть p = 4. Это 3 проверки.

Теперь выберем часть. Для target = 0 имеем 0 ≤ 2. Все числа левой части 4, 5, 6, 7 больше 2, значит, больше 0, и числа 0 среди них нет. Ищем в правой части, на индексах [4, 6]. Для target = 3 имеем 3 > 2. Все числа правой части 0, 1, 2 не больше 2, значит, меньше 3, и числа 3 среди них нет. Ищем в левой части, на индексах [0, 3].

Правило. Если target ≤ nums[-1], ищите на индексах [p, n − 1], иначе на индексах [0, p − 1]. Обе части упорядочены, поэтому в них работает обычный Binary Search.

Для target = 0 поиск идёт на [4, 6]. Середина mid = 5, и 1 > 0, поэтому hi = 4. Середина mid = 4, и 0 = 0: ответ 4. Это 2 проверки.

Для target = 3 поиск идёт на [0, 3]. Середина mid = 1, и 5 > 3, поэтому hi = 0. Середина mid = 0, и 4 > 3, поэтому hi = -1. Теперь hi = -1 меньше lo = 0: отрезок пуст, ответ -1. Это тоже 2 проверки.

Правило работает и для Array без поворота. Для nums = [1, 2, 3, 4, 5] каждое число не больше последнего числа 5, поэтому все ответы «да» и p = 0. Для target = 3 имеем 3 ≤ 5 и отрезок [0, 4]. Для target = 6 имеем 6 > 5 и отрезок [0, −1]: он пуст, ответ -1.

class Solution:
    def search(self, nums: list[int], target: int) -> int:
        n = len(nums)
        lo, hi = 0, n - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] <= nums[-1]:
                hi = mid
            else:
                lo = mid + 1
        p = lo  # индекс минимума
        if target <= nums[-1]:
            lo, hi = p, n - 1
        else:
            lo, hi = 0, p - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[mid] < target:
                lo = mid + 1
            else:
                hi = mid - 1
        return -1

Время: первый поиск оставляет не больше половины индексов, округлённой вверх (из 5 индексов остаётся не больше 3): из 5000 индексов получается 2500, 1250, 625, 313, 157, 79, 40, 20, 10, 5, 3, 2, 1. Это 13 проверок. Второй поиск оставляет не больше половины чисел, округлённой вниз (из 5 чисел остаётся не больше 2): из 5000 чисел получается 2500, 1250, 625, 312, 156, 78, 39, 19, 9, 4, 2, 1, 0. Это тоже 13 проверок. Всего не больше 13 + 13 = 26 проверок середины: O(log n) в худшем случае. Дополнительная память: n, lo, hi, mid и p, O(1) в худшем случае.

Решение 2. Binary Search за один проход

Возьмите пример 1: nums = [4, 5, 6, 7, 0, 1, 2], target = 0. Сначала lo = 0, hi = 6, mid = 3. Сравним nums[lo] и nums[mid]: 4 ≤ 7. Числа 4, 5, 6, 7 растут, и отрезок [0, 3] упорядочен. Число 0 меньше 4, поэтому в упорядоченной половине [0, 3] его нет: lo = mid + 1 = 4.

Теперь lo = 4 и mid = 5: nums[lo] = 0 ≤ nums[mid] = 1, поэтому отрезок [4, 5] упорядочен. Число target = 0 не меньше nums[4] = 0 и меньше nums[5] = 1. Другая половина, [6, 6], состоит из числа 2, оно больше 1. Значит, число 0 может стоять только в [4, 5], а nums[5] = 1 не равно 0: hi = mid - 1 = 4. Теперь mid = 4 и nums[4] = 0: ответ 4. Это 3 проверки.

Теперь возьмите nums = [6, 7, 0, 1, 2, 4, 5] и target = 4. Сначала lo = 0, hi = 6, mid = 3. Имеем nums[lo] = 6 > nums[mid] = 1: середина стоит после разрыва, который лежит между 7 и 0. Разрыв один, поэтому отрезок [3, 6] с числами 1, 2, 4, 5 упорядочен. Другая половина, [0, 2], состоит из чисел 6, 7, 0: они вне диапазона от 1 до 5. Число 4 лежит в этом диапазоне, поэтому оно может стоять только в [3, 6], а nums[3] = 1 не равно 4: lo = mid + 1 = 4. Теперь mid = 5 и nums[5] = 4: ответ 5. Это 2 проверки.

Разрывов порядка не больше одного, поэтому у любого отрезка [lo, hi] с серединой mid одна из половин [lo, mid] и [mid, hi] упорядочена. Какая именно, показывает сравнение nums[lo] с nums[mid]. Как в решении 1, числа левой части растут, числа правой части тоже, и каждое число левой части больше каждого числа правой части.

Если разрыв лежит в [lo, mid], то nums[lo] стоит в левой части, nums[mid] в правой части, и nums[lo] > nums[mid]. Если разрыва в [lo, mid] нет, то числа растут, и nums[lo] ≤ nums[mid]. Поэтому условие nums[lo] ≤ nums[mid] означает, что разрыва в [lo, mid] нет, как в примере 1. Условие nums[lo] > nums[mid] означает, что разрыв там есть, как в nums = [6, 7, 0, 1, 2, 4, 5], и середина стоит в правой части. Разрыв один, поэтому в [mid, hi] его нет, и эта половина упорядочена.

Число другой половины стоит в той же части, что и упорядоченная половина, или в другой части. В nums = [6, 7, 0, 1, 2, 4, 5] число 0 стоит в той же части, что и 1, и меньше 1. Числа 6 и 7 стоят в другой части и больше 5. В обоих случаях число меньше левого края упорядоченной половины или больше правого: числа одной части растут, а числа левой части больше чисел правой. Между краями числа другой половины нет.

Правило. Сначала сравните nums[mid] с target: при равенстве ответ mid. Если nums[lo] ≤ nums[mid], упорядочен отрезок [lo, mid]: при nums[lo] ≤ target < nums[mid] шаг hi = mid - 1, иначе lo = mid + 1. Если nums[lo] > nums[mid], упорядочен отрезок [mid, hi]: при nums[mid] < target ≤ nums[hi] шаг lo = mid + 1, иначе hi = mid - 1.

class Solution:
    def search(self, nums: list[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[lo] <= nums[mid]:  # отрезок [lo, mid] упорядочен
                if nums[lo] <= target < nums[mid]:
                    hi = mid - 1
                else:
                    lo = mid + 1
            else:  # отрезок [mid, hi] упорядочен
                if nums[mid] < target <= nums[hi]:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return -1

Время: каждая проверка исключает mid и оставляет не больше половины чисел, как во втором поиске решения 1. Для n = 5000 это не больше 13 проверок середины: O(log n) в худшем случае. Дополнительная память: lo, hi и mid, O(1) в худшем случае.

Типичные ошибки

  • Условие nums[mid] < nums[0] вместо nums[mid] <= nums[-1] в первом поиске. Для nums = [1, 2, 3] условие всюду «нет»: p = 2 вместо 0, и для target = 1 функция возвращает -1, а нужен ответ 0.
  • Выбор части по target >= nums[0] вместо target <= nums[-1]. Для nums = [1, 3] и target = 3 имеем p = 0, поиск идёт на пустом отрезке [0, −1], и функция возвращает -1, а нужен ответ 1.
  • Строгое сравнение nums[lo] < nums[mid] в решении 2. Для nums = [3, 1] и target = 1 имеем lo = mid = 0. Отрезок [0, 0] из одного числа считается неупорядоченным, поэтому код считает упорядоченным отрезок [0, 1] с числами 3, 1. Условие nums[mid] < target ≤ nums[hi] равно 3 < 1 ≤ 1 и неверно, поэтому hi = mid - 1 = -1, и функция возвращает -1, а нужен ответ 1.
