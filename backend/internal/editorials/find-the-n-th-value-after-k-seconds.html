Решение 1 находит ответ по формуле через Combinations. Решение 2 повторяет все k секунд, но тратит на одну секунду только n − 1 сложений.

Решение 1. Combinations и таблицы Factorial

Возьмём пример 1. После секунды 1 a = [1, 2, 3, 4]. После секунды 2 a[3] = 1 + 2 + 3 + 4 = 10. Первые три слагаемых дают 1 + 2 + 3 = 6, а это новое a[2]. Значит, новое a[3] = 6 + 4: новое a[2] плюс старое a[3]. Так при любом i ≥ 1 новое a[i] равно сумме нового a[i − 1] и старого a[i].

Запишем состояния Array в таблицу: строка s хранит a после s секунд. Старое a[i] стоит прямо над новым a[i], а новое a[i − 1] слева от него. Каждое число таблицы, кроме строки s = 0 и столбца i = 0, равно сумме соседа слева и числа выше.

По тому же правилу строят Pascal's Triangle: C(5, 2) = C(4, 1) + C(4, 2) = 4 + 6 = 10. В таблице это a[3] после секунды 2: выше 4, слева 6. Строка s = 2 содержит 1, 3, 6, 10, то есть C(2, 2), C(3, 2), C(4, 2) и C(5, 2). В общем виде a[i] после s секунд равно C(i + s, s).

Формула верна для всей таблицы. Строка s = 0 состоит из единиц, и C(i, 0) = 1. Столбец i = 0 тоже состоит из единиц: a[0] не меняется, и C(s, s) = 1. Остальные числа таблица получает сверху вниз и слева направо. Пусть число выше и число слева уже совпали с формулой: выше C(i + s − 1, s − 1), слева C(i + s − 1, s). По правилу Pascal's Triangle их сумма равна C(i + s, s). Так формула переходит от краёв ко всем числам таблицы.

Ответ стоит в столбце i = n − 1 и строке s = k: C(n − 1 + k, k) = C(n + k − 1, k). В примере 1 это C(8, 5) = 8! / (5! · 3!) = 40320 / 720 = 56, в примере 2 C(7, 3) = 35.

При n = k = 1000 нужно C(1999, 1000): в этом числе 601 цифра. Код не строит такое число. Он считает остаток от деления на M = 109 + 7 через таблицы fact и inv_fact из главы, и все числа в таблицах меньше M. Пусть N = n + k − 1. Таблицы строят до N, и C(N, k) = fact[N] · inv_fact[k] · inv_fact[N − k] % M, где N − k = n − 1. В примере 1 N = 8: деление на 5! и 3! код заменяет умножением на inv_fact[5] и inv_fact[3].

Время: O(n + k + log M): два цикла по N = n + k − 1 шагов и один pow за O(log M). При n = k = 1000 циклы делают 2 · 1999 = 3998 шагов. Дополнительная память: O(n + k): две таблицы по N + 1 = n + k чисел, при n = k = 1000 по 2000 чисел.

class Solution:
    def valueAfterKSeconds(self, n: int, k: int) -> int:
        M = 10**9 + 7
        N = n + k - 1  # ответ C(N, k), таблицы до N
        fact = [1] * (N + 1)
        for i in range(1, N + 1):
            fact[i] = fact[i - 1] * i % M
        inv_fact = [1] * (N + 1)
        inv_fact[N] = pow(fact[N], M - 2, M)
        for i in range(N, 0, -1):
            inv_fact[i - 1] = inv_fact[i] * i % M
        return fact[N] * inv_fact[k] % M * inv_fact[N - k] % M

Решение 2. Simulation с Prefix Sum

Правило условия можно выполнить буквально: каждую секунду заново складывать a[0] + ... + a[i] для каждого i. Сумма i + 1 чисел требует i сложений, поэтому одна секунда стоит 0 + 1 + ... + (n − 1) = n(n − 1)/2 сложений. При n = k = 1000 это 1000 · 499 500 = 499 500 000, около 5 · 108 сложений: слишком долго.

Новый a это Prefix Sum старого a. Переход из решения 1 даёт каждое новое a[i] за одно сложение. Код идёт по i слева направо и меняет числа прямо в списке: a[i] = (a[i] + a[i - 1]) % M. Когда код дошёл до i, a[i − 1] уже новое, а a[i] ещё старое. Рисунок показывает секунду 2 примера 1: a[1] = 2 + 1 = 3, a[2] = 3 + 3 = 6, a[3] = 4 + 6 = 10.

Код берёт % M после каждого сложения по правилу главы: остаток суммы равен остатку суммы остатков. Поэтому в конце a[n − 1] равно остатку ответа, а каждое число в a меньше M.

Время: O(n · k): k секунд по n − 1 сложений. При n = k = 1000 это 999 · 1000 = 999 000 сложений, в 500 раз меньше, чем при буквальном пересчёте. Дополнительная память: O(n): список a из n чисел.

class Solution:
    def valueAfterKSeconds(self, n: int, k: int) -> int:
        M = 10**9 + 7
        a = [1] * n
        for _ in range(k):
            for i in range(1, n):
                # a[i - 1] уже новое: сумма a[0] + ... + a[i - 1]
                a[i] = (a[i] + a[i - 1]) % M
        return a[n - 1]

Типичные ошибки

  • Проход справа налево в том же списке. Тогда к a[i] прибавляется старое a[i − 1], а не сумма всех чисел перед a[i]. При n = 3 и k = 1 список [1, 1, 1] становится [1, 2, 2], и ответ 2 вместо 3.
  • Таблицы до 1000, потому что n, k ≤ 1000. Формула берёт fact[N] при N = n + k − 1. При n = k = 1000 это fact[1999], и таблица из 1001 числа даёт IndexError.
  • C(n + k, k) вместо C(n + k − 1, k). Последний индекс равен n − 1, а не n: в примере 1 C(9, 5) = 126 вместо 56.
