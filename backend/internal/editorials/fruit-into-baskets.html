Вы собираете фрукты с деревьев подряд, и в двух корзинах помещаются не больше двух видов. Дерево, с которого вы начали, открывает участок. Участок кончается перед первым деревом третьего вида или в конце ряда. Значит, ответ - длина самого длинного участка подряд идущих деревьев, на котором не больше двух видов. Деревья нумеруются с 0, как места в Array, а n - длина fruits.

Brute Force берёт каждое дерево как начало и идёт вправо, пока видов не больше двух. В примере 3, fruits = [1, 2, 3, 2, 2], начало 0 даёт участок [1, 2] из 2 деревьев, а начало 1 даёт участок [2, 3, 2, 2] из 4 деревьев. Если на всех деревьях растут два вида, начало i проходит n − i деревьев. Всего n + (n − 1) + ... + 1 = n(n + 1)/2 шагов. При n = 105 это 5 000 050 000 шагов: слишком долго. Соседние начала i и i + 1 проходят почти одни и те же деревья, и эту работу можно не повторять.

Решение 1. Sliding Window и Hash Table

Окно [l, r] - это деревья от l до r. Окно хорошее, если в нём не больше двух видов. Hash Table cnt хранит для каждого вида число деревьев этого вида в окне. Правая граница r идёт вправо на одно дерево за шаг. Левая граница l идёт вправо, только когда в окне стало три вида.

Возьмите пример 3: fruits = [1, 2, 3, 2, 2]. При r = 0 в cnt один вид, при r = 1 два вида: {1: 1, 2: 1}. Окно [0, 1] хорошее, в нём 2 дерева. При r = 2 приходит вид 3, и в cnt три вида: {1: 1, 2: 1, 3: 1}. Окно плохое, и l убирает дерево 0 вида 1. Счётчик cnt[1] становится 0. Вида 1 в окне больше нет, поэтому ключ 1 удаляется: cnt = {2: 1, 3: 1}, и l = 1. Окно [1, 2] хорошее. При r = 3 и r = 4 приходят деревья вида 2, и после r = 4 cnt = {2: 3, 3: 1}, окно [1, 4], 4 дерева. Ответ 4.

Правило. Прибавьте 1 к счётчику вида дерева r. Пока в cnt больше двух ключей, уберите дерево l: вычтите 1 из его счётчика, при счётчике 0 удалите ключ, затем сдвиньте l. После этого обновите ответ длиной r − l + 1.

Счётчики нужны, потому что вид может расти на нескольких деревьях окна. Возьмите fruits = [1, 2, 1, 2, 3]. При r = 4 в cnt три вида: {1: 2, 2: 2, 3: 1}. Дерево 0 вида 1 уходит, но cnt[1] становится 1: вид 1 растёт ещё и на дереве 2. Дерево 1 вида 2 уходит, cnt[2] становится 1. Дерево 2 вида 1 уходит, cnt[1] становится 0, и ключ 1 удаляется. Видов два, l = 3. На одном шаге r левая граница сделала 3 шага.

Левая граница не возвращается назад. В этом примере при r = 4 окна с началами 0, 1 и 2 содержат деревья видов 1, 2 и 3. Окно с большим правым концом содержит те же деревья и ещё новые, поэтому в нём тоже не меньше трёх видов. Начала 0, 1 и 2 не подходят ни при каком r ≥ 4. Окно [l, r] после цикла while - самое длинное хорошее окно с правым концом r, потому что окна с началом левее l плохие. Ответ - наибольшая длина среди всех r.

class Solution:
    def totalFruit(self, fruits: list[int]) -> int:
        cnt = {}
        l = 0
        best = 0
        for r in range(len(fruits)):
            cnt[fruits[r]] = cnt.get(fruits[r], 0) + 1
            while len(cnt) > 2:
                cnt[fruits[l]] -= 1
                if cnt[fruits[l]] == 0:
                    del cnt[fruits[l]]  # len(cnt) считает только виды окна
                l += 1
            best = max(best, r - l + 1)
        return best

Время: правая граница r делает n шагов. Левая граница l не идёт назад и не проходит за r, поэтому за весь проход делает не больше n шагов. Всего не больше 2n сдвигов. Каждая операция с Hash Table занимает ожидаемое O(1), поэтому время ожидаемое O(n). В примере 3 r делает 5 шагов, а l делает 1 шаг. Дополнительная память: перед добавлением дерева r в cnt не больше двух ключей, после добавления не больше трёх, а после цикла while их снова не больше двух. Это O(1) в худшем случае, как и переменные l, r и best.

Решение 2. Один проход без Hash Table

Окно описывают четыре числа. Серия - это деревья одного вида подряд. Число b - вид последнего дерева окна, a - другой вид окна, run - длина серии вида b в конце окна, size - длина окна. Число x - вид дерева r, которое цикл читает сейчас. Начало окна равно r − size + 1 и нигде не хранится. Значение -1 означает, что вида нет, потому что виды деревьев не меньше 0. Сначала a = b = -1, а a остаётся равным -1, пока в окне один вид.

Возьмите fruits = [0, 1, 1, 1, 2, 2, 2]. Дерево 0: окно [0, 0], size = 1, run = 1. Дерево 1 имеет новый вид 1: окно [0, 1], size = 2. Деревья 2 и 3 имеют вид 1, как b: run становится 2 и 3, size становится 3 и 4. Дерево 4 имеет вид 2, это третий вид. Слева от него можно оставить только серию вида 1 из run = 3 деревьев: левее стоит дерево 0 вида 0, и с ним было бы три вида. Окно [1, 4], size = run + 1 = 4. Деревья 5 и 6 имеют вид 2: size становится 5 и 6. Ответ 6.

Вид x может совпасть с a. В примере 1, fruits = [1, 2, 1], дерево 2 имеет вид 1, как a. Окно растёт до [0, 2], size = 3. Теперь последний вид - 1, поэтому a и b меняются местами, и run = 1.

Правило. Вид x равен b: run += 1 и size += 1. Вид x равен a: a и b меняются местами, run = 1, size += 1. Вид x новый: size = run + 1 по старому run, затем a = b, b = x, run = 1.

Дерево 0 даёт окно [0, 0]. Это единственное окно с правым концом 0, и оно хорошее, поэтому оно самое длинное. Окно после дерева r - это окно перед деревом r + 1. Допустим, r ≥ 1 и перед деревом r окно - самое длинное хорошее окно с правым концом r − 1. Два случая ниже показывают, что после дерева r окно - самое длинное хорошее окно с правым концом r.

Вид x равен a или b. Окно вместе с деревом r имеет те же виды, и его длина size + 1. В примере дерево 5 имеет вид 2, как b: окно [1, 4] с size = 4 растёт до [1, 5]. Окно [0, 5] длиннее окна [1, 5]. Если убрать из него дерево 5, останется окно [0, 4] из 5 деревьев, а size = 4. В [0, 4] виды 0, 1 и 2, оно плохое, поэтому [0, 5] тоже плохое. Допустим, есть хорошее окно с правым концом r длиннее size + 1. Если убрать из него дерево r, получится хорошее окно с правым концом r − 1 длиннее size. Такого окна нет.

Вид x новый. В примере перед деревом 4 окно [0, 3] состоит из дерева 0 вида 0 (это a) и серии вида 1 (это b). Если в окне два вида, слева от серии вида b стоит дерево вида a. Если в окне один вид, оно начинается с дерева 0: дерево левее дало бы хорошее окно длиннее, а такого окна нет. Дерево вида a вместе с b и новым видом дало бы три вида. Поэтому самое длинное окно с правым концом r - это серия вида b и дерево r.

class Solution:
    def totalFruit(self, fruits: list[int]) -> int:
        a, b = -1, -1  # виды окна: b - вид последнего дерева, a - другой вид
        run = 0  # сколько деревьев вида b стоит подряд в конце окна
        size = 0  # длина окна
        best = 0
        for x in fruits:
            if x == b:
                run += 1
                size += 1
            elif x == a:
                a, b = b, a
                run = 1
                size += 1
            else:
                a, b = b, x
                size = run + 1  # окно начинается с серии вида b
                run = 1
            best = max(best, size)
        return best

Время: цикл делает n шагов, и каждый шаг выполняет O(1) действий. Всего O(n) в худшем случае. Дополнительная память: a, b, run, size, best и x, O(1) в худшем случае.

Типичные ошибки

  • Не удалять ключ со счётчиком 0. В примере 3 при r = 2 счётчик cnt[1] становится 0, но len(cnt) остаётся 3. Цикл while двигает l до конца Array и падает с IndexError.
  • Считать длину окна как r - l. Для fruits = [0] получится 0, а ответ 1: окно [0, 0] содержит одно дерево.
  • В решении 2 брать size = 2 при новом виде. Для fruits = [0, 1, 1, 1, 2, 2, 2] получится 4 вместо 6: при дереве 4 окно станет [3, 4], и деревья 1 и 2 вида 1 пропадут из окна.
