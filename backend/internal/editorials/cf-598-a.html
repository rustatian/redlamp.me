Пусть N будет наибольшим из t входных чисел. При n = 4 прямой цикл Brute Force проходит числа 1, 2, 3, 4 за 4 шага и меняет сумму на каждое слагаемое: −1 − 2 + 3 − 4 = −4. Для одного числа n такой цикл делает n шагов и тратит O(n) времени в худшем случае, а для всего ввода время равно O(t · N). Если все t = 100 входных чисел равны 109, программа всего сделает 100 · 109 = 1011 сложений и вычитаний: слишком долго.

При n = 4 сумма без смены знаков равна 1 + 2 + 3 + 4 = 10. Запишем числа в обратном порядке под первой строкой: получатся пары 1 + 4, 2 + 3, 3 + 2 и 4 + 1. Сумма каждой пары равна 5. Для любого n таких столбцов будет n, а сумма каждой пары равна n + 1. Каждая строка даёт одну и ту же сумму, поэтому начальное значение total равно n · (n + 1) / 2. Из двух соседних целых чисел n и n + 1 ровно одно чётное: при n = 4 чётно число 4, при n = 5 чётно число 6. Поэтому произведение n · (n + 1) всегда делится на 2 без остатка, и в коде Python используют целочисленное деление n * (n + 1) // 2.

Чтобы заменить +4 на −4, нужно вычесть 4 + 4 = 8. Для каждой степени двойки power вычтем из total число 2 · power. Начнём с 1 = 20 и каждый раз будем удваивать power. Так мы один раз сменим знак у каждой степени двойки до n включительно, а остальные слагаемые сохранят свой знак. В примере нужно учесть и саму четвёрку: 10 − 2 · (1 + 2 + 4) = −4.

При n = 7 сумма равна 14. Следующее число 8 = 23 входит с минусом, поэтому сумма уменьшается до 14 − 8 = 6. У числа 9 знак плюс, и сумма снова растёт: 6 + 9 = 15.

import sys

read = sys.stdin.readline
t = int(read())
for _ in range(t):
    n = int(read())
    total = n * (n + 1) // 2
    power = 1
    while power <= n:
        total -= 2 * power
        power *= 2
    print(total)

Время: в худшем случае O(1 + log n) на одно число и O(t · (1 + log N)) на весь ввод. При n = 109 цикл сделает 30 шагов, так как 229 ≤ 109 < 230. Дополнительная память: в худшем случае O(1) на число и O(1) на весь ввод. Программа читает по одной строке и сразу печатает ответ. При данных ограничениях длины строки ввода и строки ответа ограничены константой, а размер буферов ввода и вывода не зависит от числа случаев.

Типичные ошибки

  • Деление n * (n + 1) / 2 вместо n * (n + 1) // 2. Оператор / в Python возвращает число типа float: при n = 4 программа выведет -4.0 вместо -4, а при n = 109 выведет 4.999999983525164e+17.
  • Преобразование int(n * (n + 1) / 2). Оно проходит первый пример (даёт -4 для n = 4 и 499999998352516354 для n = 109), но тип float точно хранит не все целые числа больше 253 = 9007199254740992. При n = 536870913 точная сумма 536870913 · 536870914 / 2 = 144115188881162241 больше 253. Результат деления 536870913 * 536870914 / 2 округляется, поэтому int(536870913 * 536870914 / 2) даёт 144115188881162240, а ответ становится 144115186733678594 вместо 144115186733678595.
