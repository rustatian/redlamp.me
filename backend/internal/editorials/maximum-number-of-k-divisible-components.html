Во втором примере k = 3. Разрежем ребро между вершинами 0 и 1. Со стороны вершины 1 сумма равна 0 + 1 + 5 = 6, а с другой стороны остаётся 18 − 6 = 12. Значит, для одного разреза достаточно проверить сумму с одной стороны. Общая сумма делится на k, поэтому при вычитании числа, которое делится на k, остаток останется нулевым.

Возьмём путь 0, 1, 2, 3 и для каждого ребра отдельно посчитаем сумму справа от него. Получится 3 + 2 + 1 = 6 посещений. На пути из n вершин такой Brute Force потребует n(n − 1)/2 посещений и O(n2) времени в худшем случае. При n = 30 000 это 449 985 000 посещений.

Решение 1. Суммы поддеревьев в обратном порядке BFS

Возьмём вершину 0 за корень. Во втором примере после обхода соседей корня получаем order = [0, 1, 2]. В списке neighbors[1] = [0, 3, 4] первым стоит родитель 0, от которого мы пришли в вершину 1. Цикл пропускает 0 и дописывает детей 3 и 4 в конец order. В Tree от корня к каждой вершине ведёт единственный путь, поэтому достаточно пропустить родителя, а всех остальных соседей записать как детей. Цикл читает order по порядку. Затем он обходит соседей вершины 2 и получает полный порядок BFS order = [0, 1, 2, 3, 4, 5, 6].

При проходе с конца дети 4 и 3 прибавят свои значения к total[1] раньше, чем цикл проверит вершину 1. К моменту проверки все дети v уже передали свои суммы, поэтому в total[v] лежит сумма всего поддерева. Если total[v] % k == 0, увеличиваем parts.

У листа 5 сумма равна 2, поэтому при k = 3 ребро над ним придётся оставить. Если разрезать ребро над вершиной v, её поддерево будет состоять из целых частей разбиения. В правильном разбиении суммы этих частей делятся на k, значит, и их сумма total[v] должна делиться на k.

На пути со значениями [3, 6, 3] выберем корень слева и положим k = 3. Если отделить правый лист, у средней вершины останется 9 − 3 = 6, и её по-прежнему можно отделить от корня. У каждой вершины выше по пути к корню сумма поддерева уменьшается на сумму отделённой части. Если отделённая сумма делится на k, остаток от деления на k у всех этих вершин сохраняется. Поэтому код передаёт родителю полную сумму total[v] и находит все рёбра, которые можно разрезать одновременно. Каждый разрез добавляет одну часть.

Во втором примере суммы обеих отделённых частей, 9 и 6, делятся на 3. У корня остаётся 18 − 9 − 6 = 3. Проверка полной суммы total[0] = 18 засчитывает эту последнюю часть, и parts = 3.

При 30 000 вершинах со значением 109 сумма у корня равна 30 000 · 109 = 3 · 1013. Это наибольшая возможная сумма по условию. В Python тип int хранит такую сумму точно.

class Solution:
    def maxKDivisibleComponents(
        self, n: int, edges: list[list[int]], values: list[int], k: int
    ) -> int:
        neighbors = [[] for _ in range(n)]
        for a, b in edges:
            neighbors[a].append(b)
            neighbors[b].append(a)

        parent = [-1] * n
        order = [0]
        for v in order:
            for u in neighbors[v]:
                if u != parent[v]:
                    parent[u] = v
                    order.append(u)

        total = values.copy()
        parts = 0
        for v in reversed(order):
            if total[v] % k == 0:
                parts += 1
            if parent[v] != -1:
                total[parent[v]] += total[v]
        return parts

Во втором примере 7 списков соседей хранят 12 записей, по две на каждое из 6 рёбер. Для Tree из n вершин это 2(n − 1) записей. BFS просматривает каждое ребро с обоих концов, а обратный проход прибавляет сумму к родителю один раз на ребро. Время: O(n) в худшем случае. В списках parent, order и total по 7 элементов, по одному на вершину. Дополнительная память: O(n) в худшем случае.

Решение 2. Удаление листьев

В первом примере у листа 4 значение 4, а единственный сосед листа имеет номер 2. Число 4 не делится на k = 6, поэтому сохраняем ребро (2, 4) в разбиении. Прибавляем значение листа к значению вершины 2 и получаем 1 + 4 = 5. Теперь вершина 2 представляет группу {2, 4}. После присваивания degree[4] = 0 цикл больше не выбирает вершину 4 как соседа. Когда лист 3 передаст своё значение вершине 1, она сама станет листом с суммой 8 + 4 = 12. Теперь ребро от 1 к 2 можно разрезать.

В degree[v] храним число оставшихся соседей, а в total[v] храним сумму с учётом присоединённых листьев. В первом примере у вершины 0 только один сосед (вершина 2). Поэтому 0 тоже входит в начальный список leaves = [0, 3, 4]. В Tree без корня листом считаем любую вершину с одним оставшимся соседом. Когда у вершины остаётся один сосед, добавляем номер этой вершины в leaves. У нового листа 1 в списке neighbors[1] = [2, 3] по-прежнему есть удалённая вершина 3. У неё degree[3] = 0, поэтому проверку degree[u] > 0 проходит только вершина 2.

После разреза (1, 2) в одной части остаётся ребро (1, 3), а в другой остаётся путь 0 → 2 → 4. Разрез единственного ребра от группы листа к соседу сохраняет все пути внутри группы. Путь между двумя вершинами вне группы тоже сохраняется, потому что для прохода через группу нужны два разных ребра. Лист с ненулевым остатком приходится присоединить к его единственному соседу. Лист с суммой, которая делится на k, выгодно отделить. Если в правильном разбиении лист и сосед были в одной части, сумма этой части без листа всё ещё делится на k, а сам лист даёт ещё одну часть.

В первом примере после удаления листа 4 остаётся путь 0 → 2 → 1 → 3. Ребро (0, 1) замкнуло бы цикл 0 → 2 → 1 → 0. Путь 0 → 2 → 1 можно продлить до вершины 3. После удаления листа оставшиеся вершины по-прежнему образуют Tree. Пока в нём хотя бы две вершины, у конца самого длинного пути ровно один сосед. Ребро к ещё одному соседу на пути замкнуло бы цикл, а в Tree циклов нет. Сосед вне пути позволил бы продлить путь. Все такие листья уже в leaves.

Перед последним шагом первого примера leaves = [0, 2]. Цикл берёт лист 2. Среди вершин из списка neighbors[2] = [0, 1, 4] только у вершины 0 ещё есть сосед. После присоединения листа сумма у вершины 0 равна 1 + 5 = 6. Единственный разрез дал две части. Номер 0 ещё в leaves, хотя у этой вершины уже нет соседей.

Лист в списке может потерять соседа, только если цикл удалит этого соседа как лист. Два соседних листа составляют всё оставшееся Tree, потому что ни у одного из них нет ребра к третьей вершине. Поэтому лист в списке может остаться без соседа только после последнего шага. При каждом вызове leaves.pop() список содержит хотя бы один лист, и у выбранного листа есть сосед.

Присоединение листа сохраняет общую сумму оставшихся групп. При разрезе из неё вычитаем число, кратное k, поэтому она по-прежнему делится на k. После n − 1 удалений остаётся одна вершина, и цикл заканчивается. Она хранит всю оставшуюся сумму, поэтому считаем её часть и возвращаем cuts + 1. При n = 1 цикл сразу пропускаем и получаем одну часть.

class Solution:
    def maxKDivisibleComponents(
        self, n: int, edges: list[list[int]], values: list[int], k: int
    ) -> int:
        neighbors = [[] for _ in range(n)]
        for a, b in edges:
            neighbors[a].append(b)
            neighbors[b].append(a)

        degree = [len(row) for row in neighbors]
        leaves = [v for v in range(n) if degree[v] == 1]
        total = values.copy()
        cuts = 0
        for _ in range(n - 1):
            v = leaves.pop()
            for u in neighbors[v]:
                if degree[u] > 0:
                    break
            if total[v] % k == 0:
                cuts += 1
            else:
                total[u] += total[v]
            degree[v] = 0
            degree[u] -= 1
            if degree[u] == 1:
                leaves.append(u)
        return cuts + 1

Время: O(n) в худшем случае. Каждую вершину удаляем не более одного раза, поэтому за весь цикл просмотрим не более 2(n − 1) записей в списках соседей. Эти списки занимают столько же места, сколько в первом решении. В degree и total по n элементов. Число оставшихся соседей может только уменьшаться, поэтому каждая вершина попадает в leaves не более одного раза. Длина списка не превышает n. Дополнительная память: O(n) в худшем случае.
