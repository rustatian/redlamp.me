Нужно узнать, есть ли целое x с x · x = num. Для num = 16 подходят x = 4 и x = −4: оба дают квадрат 16. Отрицательные x не нужны, потому что −x даёт тот же квадрат, что и x. Значение x = 0 не подходит: 0 · 0 = 0, а num ≥ 1. Для x ≥ 1 верно x ≤ x · x: при x = 4 число 4 не больше 16. Если x · x = num, то x ≤ num. Значит, искать x нужно среди 1, 2, ..., num.

Brute Force - это Linear Scan по x = 1, 2, 3, ...: он останавливается, когда x · x становится не меньше num. Для num = 16 он проверяет x = 1, 2, 3, 4 с квадратами 1, 4, 9, 16: это 4 проверки. Для num = 231 − 1 = 2 147 483 647 он доходит до x = 46 341, потому что 46 340 · 46 340 = 2 147 395 600 меньше num, а 46 341 · 46 341 = 2 147 488 281 уже больше. Это 46 341 проверка, O(√num): она укладывается в лимит 3 с на скрытый тест. Binary Search ниже делает не больше 31 проверки.

Решение 1. Binary Search

Отрезок [lo, hi] - это значения x, среди которых ответ ещё может быть. Сначала lo = 1 и hi = num. Середина: mid = (lo + hi) // 2. Квадраты растут вместе с x: 3 · 3 = 9 меньше 4 · 4 = 16. Поэтому квадрат середины отрезка показывает, в какую сторону идти. Array квадратов хранить не нужно: mid · mid считается на месте.

Пример 1: num = 16. Сначала mid = (1 + 16) // 2 = 8, и 8 · 8 = 64 больше 16. Для x ≥ 8 квадраты не меньше 64, поэтому все они больше 16: ставим hi = 7. Теперь mid = (1 + 7) // 2 = 4, и 4 · 4 = 16 = num. Ответ True после 2 проверок.

Пример 2: num = 14. Середина 7 даёт 7 · 7 = 49, это больше 14: hi = 6. Середина 3 даёт 3 · 3 = 9, это меньше 14: lo = 4. Середина 5 даёт 25, это больше 14: hi = 4. Середина 4 даёт 16, это больше 14: hi = 3. Теперь lo = 4 больше hi = 3, отрезок пуст. Ответ False после 4 проверок. Квадраты 9 и 16 стоят по обе стороны от 14.

Правило. Если mid * mid == num, ответ True. Если mid * mid < num, то lo = mid + 1. Если mid * mid > num, то hi = mid - 1. Отрезок пуст, когда lo > hi: ответ False.

Почему hi = mid - 1 ничего не теряет. В примере 2 при mid = 7 квадраты x = 7, 8, ..., 14 равны 49, 64, ..., 196. Все они больше 14, поэтому среди этих x ответа нет. При любом mid ≥ 1 из x ≥ mid следует x · x ≥ mid · mid. Если mid · mid больше num, то все такие x не подходят.

Так же для lo = mid + 1. В примере 2 при mid = 3 квадраты x = 1, 2, 3 равны 1, 4, 9. Все они меньше 14. Из x ≤ mid следует x · x ≤ mid · mid, и при mid · mid меньше num все такие x не подходят. Поэтому целое x с x · x = num всегда остаётся в отрезке [lo, hi], если оно есть. Каждая проверка убирает mid из отрезка, и цикл заканчивается.

class Solution:
    def isPerfectSquare(self, num: int) -> bool:
        lo, hi = 1, num  # x не больше x * x = num
        while lo <= hi:
            mid = (lo + hi) // 2
            if mid * mid == num:
                return True
            if mid * mid < num:
                lo = mid + 1
            else:
                hi = mid - 1
        return False

Время: каждая проверка оставляет не больше половины отрезка, поэтому проверок не больше ⌊log2 num⌋ + 1: O(log num) в худшем случае. Здесь ⌊x⌋ - это x, округлённое вниз: ⌊log2 14⌋ = 3, потому что 23 = 8 ≤ 14 < 16 = 24. Для num = 14 это 3 + 1 = 4 проверки, и пример 2 использует все 4. Для num = 231 − 1 получается ⌊log2 num⌋ = 30, потому что 230 ≤ num < 231. Это 30 + 1 = 31 проверка. Дополнительная память: O(1) в худшем случае: три числа lo, hi и mid.

Типичные ошибки

  • while lo < hi вместо lo <= hi. При num = 1 сразу lo = hi = 1, цикл не начинается, и ответ False вместо True. При num = 25 середины 13, 6, 3, 4 оставляют lo = hi = 5, и 5 · 5 = 25 не проверяется.
  • hi = num // 2 вместо hi = num. При num = 1 получается hi = 0, отрезок [1, 0] пуст, и ответ False вместо True.
  • lo = mid вместо lo = mid + 1. При num = 2 отрезок [1, 2] даёт mid = 1, и 1 · 1 = 1 меньше 2. Ход оставляет lo = 1, и цикл не заканчивается.
  • Цикл for x in range(1, num + 1) с проверкой x * x == num и без остановки. При num = 14 квадрат 4 · 4 = 16 уже больше 14, и дальше квадраты только растут, но цикл доходит до x = 14. При num = 231 − 1 ответ False, поэтому цикл делает все 2 147 483 647 проверок: слишком долго. Нужна остановка, когда x · x не меньше num, как в Brute Force выше.
