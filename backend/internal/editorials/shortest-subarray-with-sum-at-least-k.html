Нужна наименьшая длина Subarray с суммой k или больше. Сумму любого Subarray даёт Prefix Sum: p[0] = 0, а p[j] - сумма первых j чисел nums. В примере 3 получаем p = [0, 2, 1, 3]. Числа с места i до места j − 1 дают сумму p[j] − p[i]. Номер i назовём началом, номер j концом. Для чисел −1 и 2 это p[3] − p[1] = 3 − 2 = 1. Значит, нужна пара i < j с p[j] − p[i] ≥ k и наименьшей разностью j − i. В примере 3 при k = 3 такая пара одна: p[3] − p[0] = 3, длина 3.

Brute Force проверяет все пары i < j. Их n(n + 1)/2, где n - длина nums: время O(n²) в худшем случае. При n = 105 это 5 000 050 000 пар: слишком долго.

Sliding Window из главы 2 здесь ошибается. Он сдвигает левый край, пока сумма окна не меньше k. Возьмём nums = [84, -37, 32, 40, 95] и k = 167. Сумма всех 5 чисел равна 214, и окно длины 5 подходит. Без числа 84 сумма равна 130 и меньше k: сдвиг останавливается, ответ 5. Но 32 + 40 + 95 = 167, и верный ответ 3. Число −37 надо отбросить, а сдвиг по сумме этого не делает: без −37 сумма была бы 130 + 37 = 167. С отрицательными числами сумма окна при сдвиге левого края может вырасти.

Решение 1. Prefix Sum и Monotonic Deque

Для каждого конца j код ищет начало i < j с p[j] − p[i] ≥ k. В Deque dq лежат номера начал, которые ещё могут дать ответ. Два правила убирают лишние номера.

Правило спереди. В примере 3 при j = 3 получаем p[3] − p[0] = 3 − 0 = 3 ≥ 3: длина 3 подходит. Если бы был конец 4, он дал бы для начала 0 длину 4 − 0 = 4, а это больше 3. Так для любого начала i: если p[j] − p[i] ≥ k, то каждый следующий конец j' даёт длину j' − i больше, чем j − i. Номер i больше не нужен, и он уходит из dq.

Правило сзади. В примере 3 p[1] = 2 и p[2] = 1. Для конца j = 3 начало 1 даёт сумму 3 − 2 = 1 и длину 2, а начало 2 даёт сумму 3 − 1 = 2 и длину 1. Начало 2 лучше по сумме и по длине. Так для любых i1 < i2 с p[i1] ≥ p[i2]: для каждого конца j правее i2 сумма p[j] − p[i2] не меньше суммы p[j] − p[i1], а длина j − i2 меньше. Номер i1 не нужен, и он уходит из dq не позже, чем приходит j = i2.

После правила сзади p в dq растут вместе с номерами. Первый номер имеет наименьший p, то есть даёт наибольшую сумму p[j] − p[i]. Если он не подходит, то не подходит ни один номер dq. Поэтому цикл спереди останавливается на первом номере, который не подходит.

Правило. Для каждого j: пока p[j] − p[dq[0]] ≥ k, запишите длину j − dq[0] и уберите номер спереди. Затем, пока p[dq[-1]] ≥ p[j], уберите номер сзади. В конце добавьте j в dq.

Цикл спереди может убрать несколько номеров за один шаг. Возьмём nums = [84, -37, 32, 40, 95] и k = 167. Здесь p = [0, 84, 47, 79, 119, 214]. При j = 2 номер 1 уходит сзади: p[1] = 84 ≥ p[2] = 47, и начало с числа 32 лучше начала с числа −37. При j = 5 сначала 214 − 0 = 214 ≥ 167: длина 5, номер 0 уходит. Потом 214 − 47 = 167 ≥ 167: длина 3, номер 2 уходит. Потом 214 − 79 = 135 меньше 167, и цикл останавливается. Следующий номер 4 с p[4] = 119 даёт ещё меньше: 214 − 119 = 95. Лучшая длина 3.

Начальное best = n + 1 больше длины любого Subarray. Если в конце best больше n, подходящего Subarray нет, и ответ −1.

from collections import deque


class Solution:
    def shortestSubarray(self, nums: list[int], k: int) -> int:
        n = len(nums)
        p = [0] * (n + 1)
        for i, x in enumerate(nums):
            p[i + 1] = p[i] + x
        best = n + 1
        dq = deque()  # номера начал, их p растут
        for j in range(n + 1):
            # начало i даёт сумму не меньше k: длина j - i, номер i больше не нужен
            while dq and p[j] - p[dq[0]] >= k:
                best = min(best, j - dq.popleft())
            # начало j правее и с p не больше: номера с p не меньше p[j] не нужны
            while dq and p[dq[-1]] >= p[j]:
                dq.pop()
            dq.append(j)
        return best if best <= n else -1

Время: Prefix Sum считает n сумм. Каждый из n + 1 номеров входит в dq один раз и выходит не больше одного раза. Каждая проверка в двух циклах либо убирает номер, либо заканчивает свой цикл. Номер уходит не больше n + 1 раз, а каждый из двух циклов заканчивается один раз для каждого j: 2(n + 1) раз. Всего проверок не больше (n + 1) + 2(n + 1) = 3(n + 1). Всё вместе O(n) в худшем случае. В примере 3 код делает 4 вызова append, 1 вызов pop и 1 вызов popleft. Дополнительная память: p из n + 1 чисел и dq до n + 1 номеров, O(n) в худшем случае. При nums = [1, 1, 1] и k = 10 ни один номер не уходит, и dq хранит все 4 номера.

Решение 2. Prefix Sum и Heap

Правило спереди использует начало с наименьшим p: оно даёт наибольшую сумму. Heap хранит наименьший p первым и убирает его за O(log n), поэтому правило сзади не нужно. В Heap лежат пары (p[i], i) начал, которые ещё могут дать ответ. Для каждого j код делает так: пока для пары (p[i], i) с наименьшим p[i] верно p[j] − p[i] ≥ k, он записывает длину j − i и убирает пару. Потом пара (p[j], j) входит в Heap.

Возьмём снова nums = [84, -37, 32, 40, 95] и k = 167. При j = 5 в Heap лежат начала с p = 0, 84, 47, 79 и 119. Цикл убирает p = 0 (214 − 0 = 214, длина 5) и p = 47 (214 − 47 = 167, длина 3). Потом наименьший p равен 79, и 214 − 79 = 135 меньше 167.

Если наименьший p не даёт k, то и остальные не дают: их p не меньше. Здесь p = 84 и p = 119 дают суммы 214 − 84 = 130 и 214 − 119 = 95: тоже меньше 167. Если наименьший p даёт k, то длина j − i подходит, и номер i больше не нужен, как в решении 1. Heap отдаёт пары по возрастанию p, а не по возрастанию номеров: пара p = 47 (номер 2) ушла, а пара p = 84 (номер 1) осталась в Heap, хотя решение 1 убрало её сзади при j = 2. Поэтому цикл убирает все пары с p[j] − p[i] ≥ k и записывает длину каждой.

import heapq


class Solution:
    def shortestSubarray(self, nums: list[int], k: int) -> int:
        n = len(nums)
        p = [0] * (n + 1)
        for i, x in enumerate(nums):
            p[i + 1] = p[i] + x
        best = n + 1
        heap = []  # пары (p[i], i) начал, которые ещё могут дать ответ
        for j in range(n + 1):
            # наименьший p даёт наибольшую сумму; подошедшее начало больше не нужно
            while heap and p[j] - heap[0][0] >= k:
                best = min(best, j - heapq.heappop(heap)[1])
            heapq.heappush(heap, (p[j], j))
        return best if best <= n else -1

Время: код делает n + 1 вызов heappush и не больше n + 1 вызова heappop. Каждый вызов стоит O(log n), поэтому время O(n log n) в худшем случае. При n = 105 это 100 001 вызов heappush и не больше 100 001 вызова heappop. Дополнительная память: p из n + 1 чисел и Heap до n + 1 пар, O(n) в худшем случае.

Типичные ошибки

  • Спереди стоит if, а не while. В примере с k = 167 при j = 5 уходит только номер 0, и ответ 5 вместо 3.
  • Нет правила сзади. Для nums = [5, -10, 4, 4] и k = 8 получаем p = [0, 5, -5, -1, 3]. В dq остаются все номера, спереди стоит номер 0, и 3 − 0 = 3 меньше 8: цикл останавливается. Код возвращает −1, а верный ответ 2: p[4] − p[2] = 3 − (−5) = 8.
  • Нет проверки на отсутствие ответа: код возвращает best, а не best if best <= n else -1. Для nums = [1, 2] и k = 4 он вернёт 3 вместо −1.
  • Спереди стоит > вместо >=. В примере 3 сумма 3 − 0 = 3 равна k, а > требует больше. Код вернёт −1 вместо 3.
