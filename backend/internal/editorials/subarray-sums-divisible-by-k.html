У [4, 5, 0] есть три отрезка с началом в первой позиции, два с началом во второй и один с началом в третьей. При k = 5 считаем отрезок [5] сразу, а после прибавления нуля считаем и [5, 0]. Brute Force выбирает начало и прибавляет по одному числу, пока не дойдёт до конца nums. После каждого сложения проверяем, делится ли сумма на k. Если делится, прибавляем к ответу 1. Для n чисел это n(n + 1)/2 сложений и O(n2) времени в худшем случае. При n = 30 000 придётся проверить 450 015 000 отрезков.

Решение 1. Prefix Sum и счётчики остатков

В примере [4, 5, 0, -2, -3, 1] сумма первых трёх чисел равна 9, а первых пяти равна 4. Если вычесть первую сумму из второй, останется сумма отрезка [-2, -3]. Обе суммы дают остаток 4, поскольку 9 = 5 · 1 + 4 и 4 = 5 · 0 + 4. При вычитании получаем 4 − 9 = 5 · (0 − 1) + (4 − 4) = −5.

У границы с номером i слева лежат i чисел, а p[i] обозначает их сумму. Между границами i и j, где i < j, лежит непустой отрезок с суммой p[j] − p[i]. Если остатки двух сумм равны, при вычитании они сокращаются и разность делится на k. У границ 4 и 5 остатки разные, и при вычитании получаем 4 − 7 = 5 · (0 − 1) + (4 − 2) = −3. Разность сумм отличается от разности остатков на число, кратное k. Если разность сумм делится на k, то и разность остатков делится на k. При k = 5 наименьшая разность остатков равна 0 − 4 = −4, а наибольшая равна 4 − 0 = 4. Числа −5 и 5 лежат за этими пределами, поэтому из всех таких разностей только 0 делится на 5. Оба остатка лежат в пределах от 0 до k − 1, поэтому их разность строго между −k и k. В этом промежутке на k делится только 0, значит, остатки равны.

После числа -3 остаток 4 встречается в четвёртый раз. Он уже встречался после одного, двух и трёх чисел. Каждая из этих трёх границ даёт своё начало для отрезка с концом на -3. Поэтому к answer прибавляем count[rem], число прежних границ с текущим остатком. Затем увеличиваем этот счётчик для следующих шагов.

У границ 0 и 6 суммы равны 0 и 5. Остатки равны, поэтому отрезок из всех шести чисел подходит. Чтобы учесть начальную границу, до первого числа записываем count[0] = 1. Всего получаем 7 отрезков.

Перед числом -3 сумма равна 7, а её остаток равен 2. После прибавления -3 получаем 4 и −1. Эти числа отличаются на 5, поэтому выражения (7 - 3) % 5 и (2 - 3) % 5 дают один остаток. В Python результат равен 4, так как −1 = (−1) · 5 + 4. Когда к сумме и к rem прибавляют одно и то же value, их разность по-прежнему делится на k. Поэтому для следующего шага достаточно хранить в rem только остаток суммы.

Если для [5] при k = 9 сначала увеличить счётчик, граница после пятёрки составит пару с собой. Код ошибочно учтёт пустой отрезок и вернёт 1 вместо 0.

class Solution:
    def subarraysDivByK(self, nums: list[int], k: int) -> int:
        count = [0] * k
        count[0] = 1
        rem = 0
        answer = 0
        for value in nums:
            rem = (rem + value) % k
            answer += count[rem]
            count[rem] += 1
        return answer

Время: O(n + k) в худшем случае на создание k счётчиков и проход по n числам. Дополнительная память: O(k) в худшем случае для count.

Решение 2. Подсчёт пар в Hash Table

В примере freq[4] = 4, поэтому первую границу с остатком 4 можно выбрать четырьмя способами. Для второй границы остаётся три варианта. Например, выбор (1, 2) или (2, 1) даёт один и тот же отрезок [5] с левой границей 1 и правой границей 2. Граница с меньшим номером всегда лежит слева. Каждая пара встречается дважды, поэтому получаем 4 · 3 / 2 = 6 пар. При freq[0] = 2 получаем ещё 2 · 1 / 2 = 1 пару. Остаток 2 встречается один раз и пар не даёт.

Группа из size границ с одним остатком даёт size · (size − 1)/2 пар. Сначала в freq считаем границы для каждого остатка, который встретился. Затем складываем число пар по всем остаткам.

class Solution:
    def subarraysDivByK(self, nums: list[int], k: int) -> int:
        freq = {0: 1}
        rem = 0
        for value in nums:
            rem = (rem + value) % k
            freq[rem] = freq.get(rem, 0) + 1

        answer = 0
        for size in freq.values():
            answer += size * (size - 1) // 2
        return answer

Время: ожидаемое O(n). Первый цикл обрабатывает n чисел, второй перебирает только записи freq. Поиск и обновление счётчика в Hash Table занимают в среднем O(1) времени. Дополнительная память: ожидаемое O(min(n + 1, k)). У n чисел всего n + 1 границ, а у суммы только k возможных остатков. Поэтому в freq не более min(n + 1, k) записей.
