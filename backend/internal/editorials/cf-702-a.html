В первом примере после 1, 7 идёт 2. Участок роста не может пройти через эту пару: 7 > 2, а пропускать числа нельзя. С числа 2 начинается новый участок: 2, 11, 15. Во втором примере все шесть чисел равны 100. В каждой паре 100 = 100 нет строгого роста, поэтому наибольшая длина равна 1.

В третьем примере 1, 2, 3 все соседние пары растут. Если запускать новый проход от каждого начала, от 1 проверим 2 пары, от 2 ещё 1 пару, а от 3 справа чисел нет: всего 2 + 1 = 3 сравнения. На n строго возрастающих числах такой Brute Force делает n(n − 1) / 2 сравнений и работает за O(n2) в худшем случае. При n = 105 это около 5 · 109 сравнений: слишком долго.

Решение. Linear Scan

Пусть cur хранит длину самого длинного участка роста, который заканчивается на текущем числе. В первом примере значения cur идут по числам так: для 1 это 1, для 7 > 1 получаем 2, для 2 < 7 снова 1. Затем для 11 > 2 получаем 2, а для 15 > 11 уже 3. Во втором примере после каждой пары 100 = 100 остаётся cur = 1.

На первом числе участок состоит только из него, поэтому cur = 1. Если следующее число больше предыдущего, любой участок длины хотя бы 2 с концом в новом числе не может пропускать элементы. Значит, такой участок проходит через предыдущее число. Без нового элемента остаётся участок с концом на предыдущем числе, и его длина не больше прежнего значения cur. Поэтому для нового числа наибольшая длина равна cur + 1. Например, на числе 15 после участка 2, 11 длины 2 любой участок без пропусков проходит через 11, поэтому cur = 2 + 1 = 3 и длиннее участка быть не может. При спаде или равенстве пара не даёт строгого роста, поэтому подходит только само новое число и cur = 1.

На входе 1, 2 ответ уже равен 2, хотя спада ещё не было. Заведём переменную best для наибольшей найденной длины. Для первого числа cur = best = 1, поэтому при n = 1 соседних пар нет и ответ равен 1. После каждой пары сохраняем в best большую из двух длин: прежнюю best и новую cur. У каждого участка есть последнее число, поэтому так мы учтём и самый длинный участок, даже если он доходит до конца ввода. В первом примере его длина равна 3.

import sys

read = sys.stdin.readline
n = int(read())
a = list(map(int, read().split()))
cur = best = 1
for i in range(1, n):
    if a[i] > a[i - 1]:
        cur += 1
    else:
        cur = 1
    best = max(best, cur)
print(best)

Время: O(n) в худшем случае: читаем n чисел и сравниваем n − 1 соседних пар. Дополнительная память: O(n) в худшем случае. При чтении Python хранит строку, затем список её частей, а из них строит список целых чисел a. Программа выводит одно число, в его записи не больше цифр, чем в записи n. Во входе один случай, поэтому оценки для всего ввода те же.

Типичные ошибки

  • Написать a[i] >= a[i - 1] вместо a[i] > a[i - 1]. Во втором примере из шести чисел 100 соседние элементы равны (100 = 100), поэтому нестрогое сравнение посчитает их ростом и выдаст 6 вместо 1.
