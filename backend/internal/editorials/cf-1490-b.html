Из трёх нулей один оставим без изменения, второй увеличим за один ход (0 → 1), а третий за два (0 → 1 → 2). Получим [0, 1, 2] за 1 + 2 = 3 хода. На каждом ходу выбираем остаток, который встречается больше n / 3 раз, и увеличиваем на единицу одно число с таким остатком. Если после каждого хода заново считать остатки всех чисел, то для трёх нулей получим 3 · 3 = 9 вычислений остатка. Из n нулей увеличим n / 3 чисел по одному разу и ещё n / 3 чисел по два раза. Это n ходов и O(n · n) времени с полным пересчётом. При n = 30 000 только на пересчёт уйдёт 900 000 000 операций %. На такой пересчёт двух секунд из условия не хватит.

Решение 1. Greedy по классам остатков

В первом примере числа 2, 5, 5, 8 дают один и тот же остаток 2. Остаток 0 даёт только ноль, а остаток 1 даёт четвёрка. Запишем размеры классов по порядку остатков и получим counts = [1, 1, 4]. В каждом классе должно быть по 6 / 3 = 2 числа, поэтому в коде цель target = n // 3.

Если увеличить 5 до 6 или 8 до 9, остаток сменится с 2 на 0. Один ход меняет остаток r на (r + 1) % 3, так что числа переходят из класса в класс по кругу 0 → 1 → 2 → 0. Сначала проверим класс 0, затем класс 1: в каждом по одному числу при цели 2, поэтому ничего не переносим. В классе 2 четыре числа, поэтому перенесём два лишних в класс 0 и получим [3, 1, 2]. В каждом проходе проверяем классы в порядке 0, 1, 2. Класс 0 мы уже проверили, поэтому в начале второго прохода перенесём из него одно число в класс 1 и получим [2, 2, 2]. Все три счётчика равны цели, ответ 2 + 1 = 3.

По условию можно выполнить ходы 5 → 6, 0 → 1, 8 → 9, выбрав первую пятёрку. После хода 5 → 6 счётчики равны [2, 1, 3]. В классе 0 уже два числа, но условие разрешает увеличить любой элемент, в том числе ноль. Из двух оставшихся ходов Greedy сначала выберет 8 → 9, так как излишек пока есть только в классе 2. Оба порядка дают [1, 2, 6, 5, 4, 9] за три хода.

Из четырёх чисел с остатком 2 хотя бы два должны сменить остаток, даже если в этот класс позже придут другие числа. Если extra = counts[r] − target положительно, то и в кратчайшей последовательности ходов придётся увеличить хотя бы extra разных элементов из класса r. Выберем extra таких элементов и перенесём первый ход для каждого из них в начало этой последовательности. Каждый элемент получит столько же прибавлений, поэтому результат и число ходов сохранятся.

Если в первом примере увеличить обе пятёрки, получим те же счётчики, что и в конце первого прохода. Для перехода 0 → 1 подойдёт ноль или любая из двух шестёрок. При переносе любых extra элементов из класса r счётчик класса r уменьшится на extra, а счётчик следующего класса увеличится на extra.

Во втором наборе [2, 0, 2, 1, 0, 0] начальные счётчики равны [3, 1, 2]. В первом проходе увеличим второй элемент с 0 до 1 и получим счётчики [2, 2, 2].

Если первый перенос завершает кратчайшую последовательность, то и у Greedy каждый счётчик уже равен target. Если ходы остались, возьмём класс, из которого начинается следующий ход в новом порядке. После переноса Greedy в этом классе тоже есть число для хода, потому что счётчики совпадают. Увеличим любое число этого класса: счётчики снова совпадут. Так можно повторить все оставшиеся переходы. Значит, с переноса Greedy можно начать кратчайшую последовательность ходов. Если бы после этого переноса можно было уравнять счётчики за меньшее число ходов, то и вся последовательность стала бы короче. Поэтому к новым счётчикам можно применить тот же довод при каждом следующем переносе.

Для трёх нулей начальные счётчики равны [3, 0, 0], а цель равна 1. Класс 0 передаёт два числа классу 1, и счётчики становятся [1, 2, 0]. Класс 1 передаёт одно лишнее число классу 2, и счётчики становятся [1, 1, 1]. При проверке код переносит весь излишек, поэтому в классе остаётся не больше target чисел. Класс 1 получает числа только из класса 0, а класс 2 только из класса 1. В обоих случаях к моменту проверки код уже обработал класс, из которого приходят числа. Поэтому после первого прохода излишек возможен только в классе 0.

После первого прохода в первом примере у класса 0 одно лишнее число, классу 1 не хватает одного, а в классе 2 уже два числа. Излишек равен сумме недостач (1 = 1 + 0). Если в классе 0 есть излишек, его туда передал класс 2, оставив у себя ровно target чисел. Сумма счётчиков равна 3 · target, поэтому классу 1 не хватает ровно столько чисел, сколько лишних в классе 0. Во втором проходе класс 0 отдаёт эти числа классу 1, и все три счётчика равны цели.

Если после первого прохода ни один счётчик не превышает target, их сумма может равняться 3 · target только тогда, когда каждый равен target. В этом случае, как и во втором наборе, второй проход не добавляет ходов.

import sys

readline = sys.stdin.readline
answers = []
for _ in range(int(readline())):
    n = int(readline())
    parts = readline().split()
    counts = [0, 0, 0]
    for part in parts:
        counts[int(part) % 3] += 1

    target = n // 3
    moves = 0
    for r in (0, 1, 2, 0, 1, 2):
        extra = counts[r] - target
        if extra > 0:
            counts[r] -= extra
            counts[(r + 1) % 3] += extra
            moves += extra
    answers.append(str(moves))

print("\n".join(answers))

Время: O(n) на набор в худшем случае, так как код читает n чисел и шесть раз проверяет счётчик. Дополнительная память: O(max n + t) в худшем случае, где max n - размер наибольшего набора, а t - число наборов. Для текущего набора split() создаёт список parts из n строк. Когда join собирает строку для вывода, в списке answers ещё хранятся все t отдельных ответов. Для самих переносов достаточно трёх счётчиков и нескольких переменных.

Решение 2. Сколько раз нужен каждый переход

В наборе [0, 2, 2] не хватает числа с остатком 1. Увеличим одну двойку сначала до 3, затем до 4. В класс 0 элемент вошёл и сразу вышел, поэтому там осталось 1 + 1 − 1 = 1 число. В класс 2 никто не пришёл, а одна двойка ушла, поэтому там осталось 2 + 0 − 1 = 1 число. Значит, в классе 1 осталось 3 − 1 − 1 = 1 число.

Обозначим число переходов 2 → 0 через x, число переходов 0 → 1 через y, а число переходов 1 → 2 через z. Для класса 0 получаем counts[0] + x − y = target, поэтому из него нужно сделать y = counts[0] + x − target переходов. Для класса 2 получаем counts[2] + z − x = target, откуда z = target + x − counts[2]. Когда в классах 0 и 2 останется по target чисел, для класса 1 получим counts[1] + y − z = n − 2 · target = target.

В примере y = 1 + x − 1 = x и z = 1 + x − 2 = x − 1. Чтобы x и y были неотрицательными, достаточно x ≥ 0, а для z нужно x ≥ 1. Наименьшее допустимое x = 1 дают два хода с двойкой в начале примера. При x = 2 понадобилось бы 2 + 2 + 1 = 5 ходов. Можно увеличить тот же элемент ещё три раза (4 → 5 → 6 → 7), и на последнем ходу он второй раз выйдет из класса 0.

Чтобы x, y, z были неотрицательными, нужны x ≥ 0, x ≥ target − counts[0] и x ≥ counts[2] − target. Наибольшая из этих трёх границ даёт наименьшее допустимое x. Для данного набора counts и target фиксированы, поэтому по формулам при увеличении x на единицу y и z тоже растут на единицу. Сумма x + y + z при этом растёт на три, поэтому наименьшее допустимое x даёт наименьшее число ходов.

Для трёх нулей формулы дают те же числа переходов, что и в первом решении (x = 0, y = 2 и z = 1). В любом наборе после прихода всех y чисел класс 1 может передать z чисел, так как counts[1] + y = target + z.

При наименьшем допустимом x одно из трёх неравенств становится равенством, поэтому хотя бы одно из чисел x, y, z равно нулю. В общем случае начнём с класса, в который никто не переходит, и обработаем классы по кругу. Когда дойдём до очередного класса, он уже получит все числа из предыдущего. По формулам в нём останется target чисел после переноса, значит, чисел для переноса хватит. Такой порядок даёт ровно x + y + z ходов, то есть достигает найденного минимума.

Если начать с [0, 1, 2], в каждом классе уже есть по одному числу, поэтому нужно 0 ходов.

import sys

readline = sys.stdin.readline
answers = []
for _ in range(int(readline())):
    n = int(readline())
    parts = readline().split()
    counts = [0, 0, 0]
    for part in parts:
        counts[int(part) % 3] += 1

    target = n // 3
    x = max(0, target - counts[0], counts[2] - target)
    y = counts[0] + x - target
    z = target + x - counts[2]
    answers.append(str(x + y + z))

print("\n".join(answers))

Время: O(n) на набор в худшем случае, так как код читает n чисел, для каждого увеличивает счётчик его остатка, а затем вычисляет x, y, z за постоянное число действий. Дополнительная память: O(max n + t) в худшем случае. Для parts и answers расчёт тот же, что и в первом решении.
