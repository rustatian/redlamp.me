У первого участника одна задача, у второго две. Порядок [1, 2] даёт список номеров выступающих [1, 2, 2], а порядок [2, 1] даёт [2, 1, 2]. Повтор возможен на границе кругов, потому что внутри круга каждый говорит не больше одного раза.

Brute Force проверяет каждый порядок по кругам и пропускает тех, у кого кончились задачи. На первое место можно выбрать любого из трёх участников, на второе остаются двое, на третье один. Получаем 3 · 2 · 1 = 6 порядков. Для n участников такое произведение записывают как n!. Если у всех 200000 участников по 109 задач, на один порядок уйдёт 2 · 1014 проверок, а самих порядков 200000!. В худшем случае перебор занимает O(n! · n · high) времени, где high обозначает наибольшее число задач у одного участника.

Решение 1. Вычтем плохие порядки

Для [5, 5, 5] все трое говорят в каждом круге, поэтому подходят все 3! = 6 порядков. Чтобы выступить дважды подряд, человек должен закончить один круг и начать следующий. Если в обоих кругах говорит ещё один участник, он выступит либо после этого человека в первом круге, либо до него во втором. Когда максимум встречается хотя бы дважды, в каждом круге говорят хотя бы двое с этим максимумом, так что подходят все n! порядков.

У участников А и Б по 2 задачи, у В их 3. При порядке АВБ в первом и втором кругах выступают по очереди А, В и Б. Второй круг заканчивает Б, а в третьем говорит только В. При порядке АБВ участник В выступает последним во втором круге и первым в третьем. Из шести порядков подходят четыре.

Пусть максимум единственный, а k обозначает число участников, у которых на одну задачу меньше. При k > 0 они выступают вместе с участником с максимумом до конца предпоследнего круга. У любых двух соседних кругов до последнего есть хотя бы два общих участника, поэтому на их границе повтора нет. В последнем круге говорит только участник с максимумом. Если хотя бы один из этих k участников стоит после него, он разделит два последних выступления участника с максимумом. Если все они стоят перед ним, порядок плохой. В наборе [1, 3, 3, 7] нет никого с шестью задачами. При k = 0 участник с максимумом говорит один в двух последних кругах при любом порядке.

В примере [3, 4, 2, 1, 3, 3] поставим участника 3 на пятое место, а участника 4 на шестое. Для порядка [1, 5, 6, 2, 3, 4] в двух последних кругах выступают [1, 5, 6, 2] и [2]. Из 4! = 24 порядков на свободных местах плохи те, где участник 2 стоит четвёртым. Таких порядков 3! = 6, потому что участников 1, 5 и 6 можно расставить на первых трёх местах в любом порядке.

В общем случае выделим участника с максимумом и тех k, у кого на одну задачу меньше. Зафиксируем места всех остальных участников и их порядок. На последнее из свободных мест можно поставить любого из выделенных, а остальные места заполнить k! способами. При любом выборе мест и порядка остальных участников доля плохих порядков равна 1 / (k + 1). Плохих порядков n! / (k + 1), а хороших n! − n! / (k + 1).

Если считать 4! по модулю 5, переменная total принимает значения 1, 2, 1, 4. На последнем шаге 6 · 4 и 1 · 4 дают одинаковый остаток, потому что их разность 24 − 4 = 20 делится на 5.

Для А, Б и В надо вычесть 6 / 3 = 2 плохих порядка. От 6 по модулю 5 остаётся 1, но 1 // 3 даст 0. Число 34 = 3 · 33 = 81 даёт остаток 1 по модулю 5. Значит, обратный элемент для 3 равен остатку от 33 = 27 по модулю 5, то есть 2. Так как 6 = 2 · 3, умножение на обратный элемент даёт 6 · 2 = 2 · (3 · 2). Множитель в скобках даёт остаток 1, поэтому остаток произведения равен частному 2. Разность остатков равна 1 − 2 = −1, а выражение (-1) % 5 в Python даёт 4.

В задаче модуль M = 998244353 простой, а делитель удовлетворяет условию 1 ≤ k + 1 ≤ n ≤ 200000 < M. По малой теореме Ферма число (k + 1)M − 1 = (k + 1) · (k + 1)M − 2 даёт остаток 1 по модулю M. Код находит обратный элемент для k + 1 по формуле inverse = pow(k + 1, M - 2, M). Если точное число плохих порядков равно q, то n! · inverse = q · ((k + 1) · inverse). Множитель (k + 1) · inverse даёт остаток 1, поэтому у всего произведения тот же остаток, что у q. После цикла переменная total хранит n! % M. Код вычисляет bad = total · inverse % M и вычитает bad из total. Операция % M после вычитания даёт ответ от 0 до M − 1, даже если разность отрицательная.

import sys

M = 998244353
read = sys.stdin.readline
answers = []
for _ in range(int(read())):
    n = int(read())
    tasks = list(map(int, read().split()))
    high = max(tasks)
    total = 1
    for size in range(2, n + 1):
        total = total * size % M

    if tasks.count(high) > 1:
        good = total
    else:
        k = tasks.count(high - 1)
        inverse = pow(k + 1, M - 2, M)
        bad = total * inverse % M
        good = (total - bad) % M
    answers.append(str(good))

print("\n".join(answers))

Время: O(n + log M) в худшем случае на набор с учётом проходов по списку и вызова pow. Дополнительная память: O(n) в худшем случае на набор из-за списка из n чисел и частей строки при чтении.

Решение 2. Вставим участников по одному

В наборе [3, 4, 2, 1, 3, 3] начнём с трёх участников, у которых по три задачи. Добавим участников 1, 5 и 6 по возрастанию номеров. Для первого есть одно место, для второго два, для третьего три. Затем вставим участника с четырьмя задачами на одно из трёх мест перед кем-нибудь из первых троих. После его вставки получим 1 · 2 · 3 · 3 = 18 порядков. Для участника с двумя задачами теперь есть пять мест, а для участника с одной задачей будет шесть. При вставке порядок уже добавленных участников не меняется. Всего получим 18 · 5 · 6 = 540 хороших порядков.

На шаге size код умножает ways на число доступных мест. При единственном максимуме сначала добавляем k участников с high − 1 задачами, затем участника с максимумом и затем остальных. Внутри каждой группы добавляем участников по возрастанию номеров. На шаге leader_step = k + 1 запрещено последнее место, поэтому множитель равен k. При k = 0 первый же множитель равен нулю. При повторе максимума на каждом шаге доступны все места.

Из хорошего порядка [3, 1, 2, 4, 5, 6] уберём сначала участника 4, затем участника 3. Останется [1, 2, 5, 6], где за участником 2 с максимумом стоят участники 5 и 6. Удаление остальных сохраняет порядок выделенных участников. Поэтому в хорошем порядке участник с единственным максимумом остаётся перед кем-то с high − 1 задачами и занимает разрешённое место на шаге leader_step.

Уберём участника 2 со второго места и получим [1, 5, 6]. Чтобы вернуть порядок [1, 2, 5, 6], надо вставить участника 2 на второе место. Если убирать участников в обратном порядке добавления, место каждого перед удалением совпадает с местом его вставки. Поэтому код считает каждый хороший порядок ровно один раз.

import sys

M = 998244353
read = sys.stdin.readline
answers = []
for _ in range(int(read())):
    n = int(read())
    tasks = list(map(int, read().split()))
    high = max(tasks)
    leader_step = None
    if tasks.count(high) == 1:
        leader_step = tasks.count(high - 1) + 1

    ways = 1
    for size in range(1, n + 1):
        places = size
        if size == leader_step:
            places -= 1
        ways = ways * places % M
    answers.append(str(ways))

print("\n".join(answers))

Время: O(n) в худшем случае на набор, так как для каждого из n участников считаем один множитель. Дополнительная память: O(n) в худшем случае на набор из-за списка чисел и частей строки при чтении.
