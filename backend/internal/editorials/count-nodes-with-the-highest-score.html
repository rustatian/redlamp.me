В примере parents = [-1, 2, 0, 2, 0] удалим вершину 2. Обход из 0 посетит только 0 и 4. Начнём новый обход с непосещённой вершины 1, затем ещё один с 3. Каждая из них осталась одна. Мы посетили все четыре вершины. Оценка равна 2 · 1 · 1 = 2.

После каждого удаления Brute Force обходит одну часть за другой, каждый раз начиная с непосещённой вершины. За пять удалений получим 5 · 4 = 20 посещений. Для n удалений это n · (n − 1) посещений. При n = 100 000 получим 9 999 900 000 посещений. Перебор за O(n2) слишком долог.

Решение 1. Размеры поддеревьев в обратном порядке BFS

В этом же примере путь от 3 к корню идёт через 2. Ребро к 4 дало бы вершине 3 второй путь к корню. В Tree путь единственный, значит, такого ребра нет.

Из поддерева каждого ребёнка наружу ведёт только ребро к родителю v. После удаления v рёбра внутри поддерева целы, и оно образует отдельную часть. У вершины 2 размер поддерева size[2] = 3, снаружи остаются 5 − 3 = 2 вершины. Вне поддерева путь к корню не проходит через v, поэтому при n − size[v] > 0 снаружи одна часть такого размера. У корня size[0] = 5, внешней части нет и оценка равна 3 · 1 = 3. Внизу на рисунке часть обозначена номером соседа удалённой вершины.

У 1 родитель 2, поэтому обход по убыванию номеров прочёл бы родителя первым. По parents запишем детей 1 и 3 в children[2]. К order = [0] допишем детей корня и получим [0, 2, 4]. Дописав детей 2, получим порядок BFS [0, 2, 4, 1, 3]. Цикл for v in order читает и записи, добавленные extend во время обхода. У каждой вершины ниже корня один родитель, и только он добавляет её в order.

Прочитаем order с конца и получим [3, 1, 4, 2, 0]. Родитель добавил ребёнка после себя, теперь ребёнок идёт первым. У 3 и 1 нет детей, поэтому size[3] = size[1] = 1. У 2 к единице за саму вершину прибавим размеры поддеревьев детей и получим size[2] = 1 + 1 + 1 = 3. У корня size[0] = 1 + 3 + 1 = 5. Путь к потомку идёт ровно через одного ребёнка корня, поэтому повторов в сумме нет.

У первых трёх вершин нет детей, поэтому outside = 5 − 1 = 4. Цикл по детям оставит score = 1, а с учётом outside оценка равна 4. У 2 и 0 оценки меньше, поэтому ways = 3.

Добавим к вершине 4 ребёнка 5. Он окажется в конце order, и обратный обход начнётся с 5, 3 и 1. Это листья, то есть вершины без детей. Удаление каждого оставляет одну часть размера 5. На первом листе best = 5, ways = 1. На следующих двух оценка та же, и ways растёт до 2, затем до 3. У 4 и 2 оценки ниже (1 · 4 = 4 и 1 · 1 · 3 = 3). Только корень даёт новый максимум 3 · 2 = 6, поэтому best = 6 и снова ways = 1.

class Solution:
    def countHighestScoreNodes(self, parents: list[int]) -> int:
        n = len(parents)
        children = [[] for _ in range(n)]
        for v in range(1, n):
            children[parents[v]].append(v)

        order = [0]
        for v in order:
            order.extend(children[v])

        size = [1] * n
        best = ways = 0
        for v in reversed(order):
            score = 1
            for child in children[v]:
                size[v] += size[child]
                score *= size[child]
            outside = n - size[v]
            if outside:
                score *= outside

            if score > best:
                best = score
                ways = 1
            elif score == best:
                ways += 1
        return ways

У вершины 2 в исходном примере три множителя. В Binary Tree детей не больше двух, а внешняя часть может быть только одна. В каждой части меньше n вершин. При n ≤ 105 оценка меньше (105)3 = 1015. Множители положительны, поэтому промежуточный результат не больше оценки. Так как 1000 < 1024 = 210, получаем 1015 = 10005 < 250. Для 7 хватит трёх двоичных цифр (111), а для 8 = 23 нужны четыре. Произведению меньше 250 хватит 50 цифр. Умножение и сравнение занимают O(1) времени, хранение оценки требует O(1) памяти.

В этом примере в children пять списков и четыре записи о детях. Оба обхода читают по 2 + 2 = 4 записи. В order и size по пять записей. На n списков детей приходится n − 1 записей, по одной на ребро.

Пронумеруем 129 вершин с 0, заполняя дерево по уровням слева направо. В Python на сайте после расширения order заняты 93 из 108 мест. Добавляем по два ребёнка. После семи таких добавлений заняты 93 + 7 · 2 = 107 мест. Для следующей пары нужно 107 + 2 = 109 мест, поэтому Python расширяет order до 128 мест. Вместе с этой парой добавили 109 − 93 = 16 записей. Если Python выделит для записей новое место в памяти, он скопирует содержимое не более чем 108 старых ячеек. Это меньше 7 · 16 ячеек. Когда в большой список добавляют по одной или по две записи, при расширении Python оставляет примерно одно свободное место на восемь занятых. Следующее расширение нужно, когда для новых записей не хватает свободных мест. Поэтому число скопированных ячеек не больше числа добавленных записей, умноженного на константу. Каждое добавление входит в один промежуток. Код добавляет n списков в children, n − 1 детей в них и n − 1 записей в order после корня. Время: O(n) в худшем случае. Дополнительная память: O(n) в худшем случае для children, order и size.

Решение 2. От листьев к корню

Возьмём parents = [-1, 0, 0, 1, 2]. По parents[4] = 2 увеличим счётчик детей pending[2]. По четырём записям получаем pending = [2, 1, 1, 0, 0]. В Stack ready = [3, 4] кладём листья с нулевым счётчиком.

Вначале size[2] = 1 за саму вершину. Произведения начинаются с единицы. Вызов ready.pop() извлечёт последний элемент, лист 4. Его размер даёт родителю size[2] = 1 + 1 = 2 и product[2] = 1 · 1 = 1. Других детей у 2 нет, поэтому pending[2] станет нулём и ready = [3, 2].

Теперь извлекаем 2 и получаем у корня product[0] = 1 · 2 = 2. Корню ещё нужен размер второго ребёнка, pending[0] = 1. Размер ребёнка прибавляем к size[p] родителя и умножаем на него product[p]. Уменьшаем pending[p] на единицу. При нуле учтены все дети.

Оценка самой вершины 2 с учётом внешней части равна 1 · (5 − 2) = 3.

Сразу после извлечения листа 3 список ready пуст. Это последний ребёнок 1, поэтому pending[1] стал нулём и к следующему шагу ready = [1]. Лист входит в ready один раз в начале. Родитель входит один раз, после последнего ребёнка. У самой далёкой от корня необработанной вершины все дети уже обработаны, ведь они ещё дальше. Значит, она в ready, и цикл продолжится.

После передачи от 1 оценка корня равна product[0] = 2 · 2 = 4. Для остальных вершин добавляем множитель n − size[v]. В product получим оценки [4, 3, 3, 4, 4]. Максимум 4 встречается трижды, поэтому count вернёт 3.

class Solution:
    def countHighestScoreNodes(self, parents: list[int]) -> int:
        n = len(parents)
        pending = [0] * n
        for v in range(1, n):
            pending[parents[v]] += 1
        ready = [v for v in range(n) if pending[v] == 0]

        size = [1] * n
        product = [1] * n
        while ready:
            v = ready.pop()
            p = parents[v]
            if p != -1:
                size[p] += size[v]
                product[p] *= size[v]
                pending[p] -= 1
                if pending[p] == 0:
                    ready.append(p)
                product[v] *= n - size[v]

        return product.count(max(product))

При заполнении pending код читает четыре записи из parents, а при отборе листьев проверяет пять счётчиков. После каждого из пяти извлечений код читает parents[v], в том числе для корня. Всего это 4 + 5 = 9 чтений из parents. В конце max и count читают по пять оценок. При n вершинах код читает n − 1 записей из parents при заполнении pending и ещё n в цикле извлечений, всего 2n − 1. Отбор листьев, max и count просматривают по n элементов. В pending, size и product по n элементов. В ready сначала два листа, а за шаг код извлекает вершину и добавляет не больше одной.

Первый вызов ready.pop() извлекает лист 4 из [3, 4] и оставляет одно занятое место из четырёх. Занято меньше половины мест, поэтому Python на сайте снова запрашивает четыре места. Адрес может остаться прежним, а при переносе Python скопирует содержимое не более чем четырёх старых ячеек. После извлечения листа 3 вызов ready.append(1) сразу выделяет четыре места в пустом списке. Старых записей для копирования нет, поэтому такое добавление занимает O(1) времени. У короткого списка число ячеек ограничено константой, поэтому даже при переносе одно добавление или извлечение занимает O(1) времени. Код делает не больше n добавлений и n извлечений, поэтому все операции с коротким списком вместе занимают O(n) времени.

На дереве из 129 вершин после одного сокращения ready заняты 37 из 44 мест. До следующего сокращения код извлечёт 32 вершины и добавит 16. Длина уменьшится на 32 − 16 = 16, с 37 до 21. Это меньше половины мест. За эти 32 + 16 = 48 изменений Python скопирует содержимое не более чем 44 старых ячеек, если для записей ready понадобится новое место в памяти. При сокращении большого списка остаётся тот же запас. До нового переноса в нём надо заполнить запас или удалить почти половину записей, чтобы занятых мест осталось меньше половины. Как и в решении 1, число скопированных ячеек в каждом промежутке не больше общего числа добавлений и извлечений за этот промежуток, умноженного на константу. За все n добавлений и n извлечений Python скопирует O(n) ячеек. Время: O(n) в худшем случае. Дополнительная память: O(n) в худшем случае, так как в ready не больше n вершин и на оценку хватает 50 двоичных цифр.
