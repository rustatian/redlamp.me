В Subarray [4, 2, 4] из примера 1 минимум 2, а максимум 4. Каждое число лежит от 2 до 4, поэтому любые два числа отличаются не больше чем на 4 − 2 = 2. Пара 4 и 2 даёт ровно 2. Так в любом Subarray: каждое число лежит от минимума до максимума, поэтому модуль разности двух чисел не больше max − min. Пара из максимума и минимума тоже есть в Subarray. Поэтому Subarray допустим ровно тогда, когда max − min ≤ 2. Для всего Array [5, 4, 2, 4] max − min = 5 − 2 = 3 > 2, поэтому длина 4 не подходит.

Решение 1. Sliding Window и два Monotonic Deque

Каждый допустимый Subarray посчитаем по его правому концу r. В примере 1 при r = 3 начало 0 даёт весь Array, а он не подходит. Начала 1, 2 и 3 дают [4, 2, 4], [2, 4] и [4] с разностями 4 − 2 = 2, 4 − 2 = 2 и 4 − 4 = 0: все три подходят. Значит, на r = 3 кончаются 3 − 1 + 1 = 3 допустимых Subarray.

Так для любого r. Пусть l - самый левый номер, при котором окно от l до r допустимо. Возьмите любое начало от l до r. Окно от этого начала до r - часть окна от l до r. Его максимум не больше, а минимум не меньше, поэтому его max − min тоже не больше 2, и оно допустимо. Начала левее l не подходят: l выбран самым левым. Значит, на r кончаются ровно r - l + 1 допустимых Subarray, и код прибавляет это число к total. Каждый Subarray кончается ровно на одном r, поэтому сумма по всем r считает его один раз.

Указатель l идёт только вправо. При r = 2 и l = 0 окно [5, 4, 2] не подходит: 5 − 2 = 3 > 2. Окно от номера 0 до номера 3 тоже содержит 5 и 2. Поэтому начало 0 не нужно ни для r = 2, ни для r = 3, и код делает ход l += 1.

Для проверки окна нужны его максимум и минимум. Их дают два Monotonic Deque из главы. В mx лежит часть номеров окна, их значения убывают, и nums[mx[0]] - это максимум окна. В mn тоже часть номеров окна, их значения растут, и nums[mn[0]] - это минимум окна.

При r = 1 приходит x = 4. В mn был номер 0 со значением 5. Это число больше 4 и стоит левее. Пока номер 0 в окне, номер 1 тоже в окне. Поэтому номер 0 больше не станет минимумом, и mn.pop() удаляет его. При r = 3 приходит x = 4, и из mx сзади уходят номера 2 и 1 со значениями 2 и 4. Номер 1 с равным значением 4 тоже уходит: число 4 на номере 3 остаётся в окне дольше.

Правило. Пришло x = nums[r]. Удалите сзади из mx номера со значениями ≤ x, а из mn номера со значениями ≥ x. Добавьте r в оба Deque. Пока разность nums[mx[0]] - nums[mn[0]] больше 2, делайте ход l += 1 и удаляйте спереди номер меньше l. Затем прибавьте r - l + 1 к total.

При r = 2 после добавления mx = [0, 1, 2] со значениями 5, 4, 2 и mn = [2]. Разность 5 − 2 = 3 > 2. Ход l += 1 даёт l = 1. Меньше 1 только номер 0, то есть старое l. Он стоит первым в mx, и mx.popleft() удаляет его. Первый номер в mn равен 2, 2 ≥ 1, и mn не меняется. Теперь 4 − 2 = 2 ≤ 2, и сжатие закончено. К total код прибавляет 2 − 1 + 1 = 2. По всем r получаем 1 + 2 + 2 + 3 = 8.

Так на каждом ходе l += 1: из каждого Deque спереди уходит не больше одного номера, поэтому в коде хватает if, а while не нужен. До первого хода l = 0, и все номера в Deque не меньше 0. Пусть до хода все номера не меньше l. После хода меньше нового l может быть только номер, равный старому l. Номера в Deque растут слева направо, поэтому этот номер стоит первым, и if удаляет его. Снова все номера не меньше l, а append добавляет номер r ≥ l.

from collections import deque


class Solution:
    def continuousSubarrays(self, nums: list[int]) -> int:
        mx = deque()  # часть номеров окна, их значения убывают
        mn = deque()  # часть номеров окна, их значения растут
        l = 0
        total = 0
        for r, x in enumerate(nums):
            while mx and nums[mx[-1]] <= x:
                mx.pop()
            mx.append(r)
            while mn and nums[mn[-1]] >= x:
                mn.pop()
            mn.append(r)
            # nums[mx[0]] - максимум окна, nums[mn[0]] - минимум
            while nums[mx[0]] - nums[mn[0]] > 2:
                l += 1
                if mx[0] < l:
                    mx.popleft()
                if mn[0] < l:
                    mn.popleft()
            total += r - l + 1
        return total

Время: n - длина nums. Каждый номер входит в mx и в mn по одному разу: ровно 2n вызовов append. Каждый номер выходит из каждого Deque не больше одного раза: не больше 2n вызовов pop и popleft вместе. Каждое сравнение в цикле удаления сзади либо удаляет номер, либо заканчивает этот цикл. Указатель l не обгоняет r: окно из одного числа даёт разность 0 ≤ 2. Поэтому сдвигов l не больше n − 1. Каждая проверка с разностью больше 2 даёт один сдвиг l. Проверка с разностью не больше 2 заканчивает цикл сжатия, и такая проверка одна на каждое r. Поэтому проверок разности не больше (n − 1) + n. Всё вместе O(n) в худшем случае. В примере 1 код делает 8 вызовов append, 4 вызова pop, 1 вызов popleft, 1 сдвиг l и 1 + 4 = 5 проверок разности.

Дополнительная память: O(1). После сжатия все числа окна лежат от nums[mn[0]] до nums[mn[0]] + 2: это не больше 3 разных целых чисел. Код удаляет сзади и равные значения, поэтому значения в mx строго убывают, а в mn строго растут. Значит, в каждом Deque после сжатия не больше 3 номеров, а до сжатия на один больше: не больше 4. Например, при nums = [5, 4, 3, 1] и r = 3 до сжатия mx = [0, 1, 2, 3]. В примере 1 наибольшее число номеров в двух Deque вместе равно 4: это mx = [0, 1, 2] и mn = [2] при r = 2 до сжатия. Ответ - одно целое число, при n = 105 не больше n(n + 1)/2 = 5 000 050 000.

Знаки <= и >= в циклах удаления сзади нужны для этой оценки памяти. С < и > ответ тот же, но при nums = [2, 2, ..., 2] каждый Deque хранит все n номеров: O(n) памяти.

Решение 2. Sliding Window и Hash Table

Из оценки памяти решения 1: в допустимом окне не больше 3 разных чисел. В окне [4, 2, 4] при r = 3 их два: 4 и 2. Поэтому вместо двух Deque можно хранить dict cnt: для каждого числа окна он хранит, сколько раз это число есть в окне. Вызовы max(cnt) и min(cnt) проходят по ключам и дают максимум и минимум окна.

Перед шагом r окно от l до r − 1 допустимо, и в cnt не больше 3 ключей. Число x добавляет не больше одного ключа, а при сжатии ключи только уходят. Поэтому в cnt всегда не больше 4 ключей. Указатель l двигается так же, как в решении 1. Ключ со счётчиком 0 код удаляет: иначе max(cnt) увидит число, которого уже нет в окне.

При r = 2 в примере 1 cnt = {5: 1, 4: 1, 2: 1}, и 5 − 2 = 3 > 2. Число nums[0] = 5 уходит из окна: его счётчик становится 0, и del удаляет ключ 5. Теперь cnt = {4: 1, 2: 1}, 4 − 2 = 2 ≤ 2 и l = 1.

class Solution:
    def continuousSubarrays(self, nums: list[int]) -> int:
        cnt = {}  # значение окна: сколько раз оно есть в окне
        l = 0
        total = 0
        for r, x in enumerate(nums):
            cnt[x] = cnt.get(x, 0) + 1
            # в cnt не больше 4 ключей, поэтому max и min читают не больше 4 чисел
            while max(cnt) - min(cnt) > 2:
                y = nums[l]
                cnt[y] -= 1
                if cnt[y] == 0:
                    del cnt[y]
                l += 1
            total += r - l + 1
        return total

Время: O(n) в худшем случае. Каждый номер один раз входит в окно и не больше одного раза выходит из него. Проверок разности не больше (n − 1) + n, как в решении 1. Каждая проверка и каждая операция с cnt работают не больше чем с 4 ключами: это постоянная работа. В примере 1 код делает 5 проверок разности и 1 сдвиг l.

Дополнительная память: O(1): в cnt не больше 4 ключей. В примере 1 их не больше 3.

Что не подходит

Brute Force перебирает каждое начало l и каждый конец r ≥ l и обновляет минимум и максимум на ходу. Это n(n + 1)/2 пар, O(n²) времени. В примере 1 это 10 пар. При n = 105 это 5 000 050 000 пар: слишком долго. Выход из внутреннего цикла на первом недопустимом окне не помогает: при nums = [2, 2, ..., 2] все пары допустимы, и перебор всё равно проходит все 5 000 050 000 пар.

Типичные ошибки

  • Проверять только соседние числа. В nums = [1, 3, 5, 3, 1] соседи отличаются на 2, но в [1, 3, 5] 5 − 1 = 4 > 2. Такой код вернёт 15 вместо 10.
  • После недопустимого окна ставить l = r. При nums = [1, 2, 3, 4] и r = 3 такой код прибавит 1. Верное l = 1 даёт 3: подходят [2, 3, 4], [3, 4] и [4]. Ответ 7 вместо 9.
  • Считать max(nums[l:r + 1]) и min(nums[l:r + 1]) при каждой проверке. При nums = [2, 2, ..., 2] окно не сжимается, и срезы длины 1, 2, ..., n читают n(n + 1)/2 чисел для max и столько же для min. При n = 105 это 10 000 100 000 чтений: слишком долго. Решение 2 вызывает max и min для ключей cnt, а не для среза окна.
  • В решении 2 оставить в cnt ключ со счётчиком 0. В примере 1 при r = 2 ключ 5 остаётся со счётчиком 0, max(cnt) - min(cnt) остаётся равным 3, и l растёт дальше r. Код падает с IndexError.
