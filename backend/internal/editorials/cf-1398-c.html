Нужно посчитать Subarray, у которых сумма цифр равна длине. Решение сводит это условие к сумме 0 и считает пары равных префиксов.

Вычтите 1 из каждой цифры

Возьмите первый набор примера: строка 120, цифры 1, 2, 0. Subarray [2, 0] хороший: сумма 2 + 0 = 2, длина 2. Вычтите 1 из каждой цифры. Получатся числа b = [0, 1, -1], и Subarray [2, 0] станет [1, -1] с суммой 0. Сумма уменьшилась на 2, то есть на длину: каждая из двух цифр потеряла 1.

У Subarray длины m сумма уменьшается на m: каждая из m цифр теряет 1. Subarray [1, 2] имеет сумму 3 и длину 2. После вычитания это [0, 1] с суммой 3 − 2 = 1. Сумма не равна 0, и этот Subarray не хороший.

Правило. Subarray хороший ровно тогда, когда сумма его чисел b равна 0.

Сумма 0 значит два равных префикса

Цифры и числа b нумеруем с 1, как в условии. Префикс на позиции i - это сумма первых i чисел b. На позиции 0 чисел ещё нет, поэтому префикс равен 0. Для строки 120 префиксы на позициях от 0 до 3 равны 0, 0, 1, 0.

На позициях 1 и 3 префикс один и тот же: 0. От позиции 1 до позиции 3 к префиксу прибавились числа b с номерами 2 и 3. Префикс не изменился, значит, их сумма равна 0: 1 + (−1) = 0. Это цифры 2 и 0, хороший Subarray [2, 0]. На позициях 1 и 2 префиксы разные: 0 и 1. Между ними одно число b с номером 2, оно равно 1 − 0 = 1. Это цифра 2: Subarray [2] не хороший.

Правило. Возьмите позиции j < i. Цифры с номерами от j + 1 до i образуют хороший Subarray ровно тогда, когда префиксы на позициях j и i равны.

Каждый Subarray задаёт одну пару позиций j < i: позицию перед его первой цифрой и позицию его последней цифры. Поэтому ответ равен числу пар позиций с равными префиксами. В строке 120 префикс 0 стоит на позициях 0, 1 и 3. Это 3 пары: (0, 1), (0, 3) и (1, 3). Они дают Subarray [1], [1, 2, 0] и [2, 0]. Префикс 1 стоит только на позиции 2 и пары не даёт. Ответ 3.

Решение 1. Prefix Sum и Hash Table

Код идёт по цифрам слева направо. Шаг i читает цифру с номером i и получает в s префикс на позиции i. Списка b в коде нет: строка s += int(c) - 1 сразу прибавляет цифру без единицы. Hash Table cnt хранит для каждого значения префикса, сколько раз оно уже встретилось. До цикла cnt = {0: 1}: это префикс 0 на позиции 0.

Шаг делает три действия. Сначала он считает новый префикс s. Потом прибавляет к ответу cnt.get(s, 0): каждая более ранняя позиция с таким же префиксом даёт одну пару, то есть один хороший Subarray, который кончается на текущей цифре. Потом увеличивает cnt[s] на 1.

Второй набор примера: строка 11011. Здесь b = [0, 0, -1, 0, 0], префиксы на позициях от 0 до 5 равны 0, 0, 0, −1, −1, −1. По шагам ответ растёт на 1, 2, 0, 1 и 2: всего 1 + 2 + 0 + 1 + 2 = 6. В конце cnt = {0: 3, -1: 3}.

Строки «ключ» и cnt показывают Hash Table в момент чтения, до записи cnt[s].

Пара позиций (3, 5) попадает в ответ на шаге 5. В этот момент в cnt записаны префиксы позиций от 0 до 4, и позиция 3 среди них. Префикс позиции 5 ещё не записан. Так для любой пары j < i: код считает её один раз, на шаге i. Префикс позиции i в этот момент ещё не записан, поэтому пара позиции с самой собой в ответ не попадает.

В строке 11011 значение −1 встретилось 3 раза, на шагах 3, 4 и 5, и прибавило к ответу 0 + 1 + 2 = 3. Столько пар у 3 позиций: 3 · 2 / 2 = 3. Значение 0 тоже встретилось 3 раза и тоже дало 3 пары, всего 3 + 3 = 6. Значение, которое встретилось x раз, даёт 0 + 1 + ... + (x − 1) = x(x − 1)/2 пар.

import sys

input = sys.stdin.readline

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    digits = input().strip()
    cnt = {0: 1}  # cnt[s] - сколько раз уже встретился префикс s; до цикла это префикс 0 на позиции 0
    s = 0
    ans = 0
    for c in digits:
        s += int(c) - 1
        ans += cnt.get(s, 0)  # каждый более ранний префикс s даёт один хороший Subarray
        cnt[s] = cnt.get(s, 0) + 1
    out.append(str(ans))
print("\n".join(out))

Время: n - длина строки набора. Цикл по цифрам делает n шагов. На каждом шаге два чтения и одна запись в cnt, каждое за ожидаемое O(1). На набор это ожидаемое O(n). Все строки входа вместе содержат не больше 105 цифр, поэтому на весь вход этот цикл делает не больше 105 шагов. Дополнительная память: в cnt не больше n + 1 ключей: один есть до цикла, и шаг добавляет не больше одного. Это O(n) в худшем случае. Ровно n + 1 ключей даёт строка из одних нулей: для 000 префиксы равны 0, −1, −2, −3. Во втором наборе примера ключей 2. Каждый набор создаёт новый cnt. Ответ - одно число на набор.

Наибольший ответ даёт строка из одних единиц: у неё хорошие все Subarray. У 111 их 3 · 4 / 2 = 6. У строки длины n их n(n + 1)/2. При n = 105 это 5 000 050 000. Целые числа Python не переполняются.

Что не подходит

Brute Force берёт каждое начало l, двигает конец r вправо и прибавляет цифру к бегущей сумме. На каждый из n(n + 1)/2 Subarray идёт одно сложение: O(n²). При n = 105 это 5 000 050 000 сложений: слишком долго.

Типичные ошибки

  • Начать с пустого cnt = {}. Тогда префикса позиции 0 в cnt нет, и теряются хорошие Subarray, которые начинаются с первой цифры. Для 120 это [1] и [1, 2, 0]: ответ 1 вместо 3.
  • Увеличить cnt[s] до прибавления к ответу. Тогда каждая позиция считает пару с самой собой, и каждый шаг прибавляет лишнюю 1. Для 120 получится 3 + 3 = 6 вместо 3.
  • Создать cnt один раз, до цикла по наборам. Тогда набор считает пары с префиксами прошлых наборов. Для входа с наборами 20 и 111 второй ответ будет 9 вместо 6.
