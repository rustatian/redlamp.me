В строке 22019020 вычеркнем 2019. Слева останется 2, а справа 020. Вместе они дают 2020.

В исходной строке 22019020 восемь цифр. Если начать удаление с первой цифры, есть 8 вариантов конца, а если со второй, то 7. Всего можно проверить 8 + 7 + … + 1 = 36 пар границ непустого участка. Для каждой пары проверим, останутся ли четыре цифры, и только в этом случае сравним их с 2020. При n = 4 непустое удаление оставляет меньше четырёх цифр, поэтому также сравним исходную строку с 2020 без удаления. При n = 200 перебор пар делает 200 · 201 / 2 = 20 100 проверок длины на одну строку, то есть O(n2) времени в худшем случае.

Решение 1. Сколько цифр оставить слева

В нашем примере нужно удалить ровно 8 − 4 = 4 цифры подряд. В общем случае пропускаем участок длины n − 4. При n = 4 сравниваем строку с 2020 целиком, без удаления.

В строке 22019020 правая часть начинается с индекса 1 + 4 = 5, если считать с нуля. Обозначим число оставленных слева цифр через left. Правую часть берём с индекса start = left + n − 4. Вызов sys.stdin.readline сохраняет в конце строки знак перевода строки, поэтому на индексе n может стоять '\n'. Срез s[start:n] заканчивается перед индексом n и не захватывает этот знак.

В 20209 можно пропустить одну цифру на позициях с 1 по 5: значения left = 0, 1, 2, 3, 4 дают строки 0209, 2209, 2009, 2029 и 2020. Совпадение даёт только пятая проверка при left = 4, когда справа не остаётся ни одной цифры. После удаления одного участка все оставшиеся цифры стоят либо до него, либо после. Чтобы получить 2020, нужно оставить left цифр в начале и 4 − left в конце. Поэтому цикл проверяет все возможные разбиения, перебирая left от 0 до 4. Код соединяет s[:left] и s[start:n] в строку kept. Если строка kept совпала с 2020, ответ YES. Если цикл прошёл все варианты без совпадения, ответ NO.

import sys


def verdict(s, n):
    for left in range(5):
        start = left + n - 4
        kept = s[:left] + s[start:n]
        if kept == "2020":
            return "YES"
    return "NO"


read = sys.stdin.readline
t = int(read())
answers = []
for _ in range(t):
    n = int(read())
    answers.append(verdict(read(), n))
print("\n".join(answers))

Время: O(1) на проверку готовой строки в худшем случае. Код сравнивает не более пяти строк по четыре цифры. С учётом чтения время в худшем случае равно O(n) на набор и O(n1 + … + nt) на все t наборов. Здесь ni обозначает длину строки в наборе с номером i. Дополнительная память: O(1) на проверку в худшем случае, если считать входную строку отдельно. В срезах вместе четыре цифры, в kept ещё четыре. При печати список из t ответов и строка, которую собрал join, занимают O(t) дополнительной памяти в худшем случае.

Решение 2. Greedy

В 20192020 начало 20 совпадает с началом 2020, а третья цифра 1 отличается от 2. Если оставить обе совпавшие цифры, справа нужны только 20, и строка ими заканчивается. Код берёт слева самое длинное совпадающее начало длины left и проверяет последние need = 4 − left цифр. При совпадении можно пропустить всё между выбранными частями.

В 200200 слева тоже совпали две цифры, но последние две равны 00. Если оставить слева только 2, справа понадобятся 020, а если ничего не оставить слева, справа нужны все 2020. Оба варианта требуют тех же последних цифр 20, поэтому ответ NO. При более коротком начале справа нужны те же последние need цифр и ещё несколько перед ними. Несовпадение в этих последних цифрах сохранится.

В 2020 и 20209 совпадают все четыре цифры начала: left = 4 и need = 0. Тогда срез s[n - need:n] становится s[n:n] и даёт пустую строку, как и срез "2020"[4:]. Срез s[-need:] здесь не подходит: при need = 0 запись s[-0:] даёт всю строку s, а при need > 0 может захватить знак перевода строки.

import sys


def verdict(s, n):
    target = "2020"
    left = 0
    while left < 4 and s[left] == target[left]:
        left += 1
    need = 4 - left
    if s[n - need:n] == target[left:]:
        return "YES"
    return "NO"


read = sys.stdin.readline
t = int(read())
answers = []
for _ in range(t):
    n = int(read())
    answers.append(verdict(read(), n))
print("\n".join(answers))

Время: O(1) на проверку в худшем случае. Цикл сравнивает до четырёх пар цифр, затем код один раз сравнивает концы строк. Чтение всех цифр даёт O(n) времени на набор и O(n1 + … + nt) на все наборы в худшем случае. Дополнительная память: O(1) на проверку в худшем случае, если считать входную строку отдельно. В каждом из двух срезов не больше четырёх цифр. Список answers и строка для печати занимают O(t) дополнительной памяти в худшем случае.
