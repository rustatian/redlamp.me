n - длина nums. Решение использует Dynamic Programming: dp[i] - наибольший счёт среди путей, которые начинаются на месте 0 и кончаются на месте i. Ответ - dp[n - 1].

Возьмите пример 1: nums = [1, -1, -2, 4, -7, 3], k = 2. Путь из одного места 0 даёт dp[0] = 1. На место 1 можно прыгнуть только с места 0: dp[1] = -1 + 1 = 0. На место 2 можно прыгнуть с мест 0 и 1: dp[2] = -2 + max(1, 0) = -1. На место 3 прыгают с мест 1 и 2: dp[3] = 4 + max(0, -1) = 4.

Правило. Места, с которых можно прыгнуть на место i, образуют окно i − k..i − 1, не левее места 0. Лучший путь до места j имеет счёт dp[j]. Если последний прыжок идёт с места j на место i, лучший счёт такого пути равен dp[j] + nums[i]. Значит, dp[i] = nums[i] + max(dp[j]) по местам j окна.

Дальше dp[4] = -7 + max(-1, 4) = -3 и dp[5] = 3 + max(4, -3) = 7. Ответ 7.

Brute Force читает окно циклом: шаг i читает min(i, k) значений dp. Время Brute Force: O(n · k) в худшем случае. Сумма min(i, k) по i от 1 до n − 1 при k ≥ n − 1 равна n(n − 1) / 2. При n = 105 и k = 105 это 4 999 950 000 чтений: слишком долго. Нужен максимум окна без чтения всего окна.

Решение 1. Monotonic Deque

В примере 1 при i = 3 место 3 получает dp[3] = 4. Старые места 1 и 2 имеют dp 0 и −1: оба меньше 4 и оба левее места 3. Окно любого места правее места 3 кончается на номере 3 или правее. Если оно содержит место 1 или 2, то содержит и место 3 с большим dp. Поэтому места 1 и 2 больше не дадут максимум, и их можно забыть. Это верно и при равном dp: более новое место выходит из окна позже.

Deque dq хранит номера мест, которые ещё могут дать максимум. Значения dp этих мест слева направо строго убывают, поэтому максимум окна стоит первым: dp[dq[0]].

Правило. На шаге i: если dq[0] < i − k, место dq[0] левее окна, и popleft удаляет его. Потом dp[i] = nums[i] + dp[dq[0]]. Потом pop удаляет с конца места с dp не больше dp[i], и i встаёт в конец dq.

Одного popleft хватает. На шаге 1 в dq только место 0, и оно в окне 0..0. Допустим, что после if шага i − 1 в dq только места окна i − k − 1..i − 2. Шаг i − 1 добавил в конец место i − 1, поэтому на шаге i в dq только места i − k − 1..i − 1. Левее окна i − k..i − 1 может стоять только место i − k − 1. Номера в dq растут слева направо, поэтому это место, если оно в dq, стоит первым, и один popleft удаляет его. В примере 1 шаг 2 оставил в dq места 0 и 1 окна 0..1 и добавил место 2. При i = 3 в dq номера 0, 1, 2, окно 1..2, и popleft удаляет место 0. В dq всегда есть место i − 1: оно в окне, потому что k ≥ 1. Значит, dq не пуст, и dq[0] существует.

Максимум окна стоит в dq[0]. Каждое место окна, которого нет в dq, удалил сзади более новый номер с не меньшим dp. Если он тоже удалён, его удалил ещё более новый номер, и так до номера из dq. Все эти номера лежат между этим местом и i − 1, то есть в окне. Поэтому наибольший dp окна есть среди dp номеров dq, а они убывают: он стоит первым. В примере 1 при i = 4 окно 2..3. Место 2 с dp −1 удалено при i = 3 местом 3 с dp 4, и dp[dq[0]] = dp[3] = 4 = max(-1, 4). В примере 2 (nums = [10, -5, -2, 4, 0, 3], k = 3) цепочка длиннее: при i = 5 окно 2..4. Место 2 с dp 8 удалено при i = 3 местом 3 с dp 14. Место 3 удалено при i = 4 местом 4: dp равны, 14 и 14. Место 4 стоит в dq, и dp[dq[0]] = dp[4] = 14 = max(8, 14, 14).

from collections import deque


class Solution:
    def maxResult(self, nums: list[int], k: int) -> int:
        dp = [0] * len(nums)
        dp[0] = nums[0]
        dq = deque([0])  # номера мест; их dp слева направо строго убывают
        for i in range(1, len(nums)):
            if dq[0] < i - k:
                dq.popleft()  # место i - k - 1 вне окна
            dp[i] = nums[i] + dp[dq[0]]
            while dq and dp[dq[-1]] <= dp[i]:
                dq.pop()  # место i новее и не хуже
            dq.append(i)
        return dp[-1]

Время: каждое место входит в dq один раз и выходит не больше одного раза. Место n − 1 входит последним и остаётся в dq, поэтому pop и popleft вместе вызываются не больше n − 1 раз. Каждая проверка условия while либо ведёт к pop, либо заканчивает while, поэтому проверок не больше 2n. Всего O(n) в худшем случае. В примере 1 в dq вошли 6 номеров (1 в начале и 5 append), 4 вышли через pop и 1 через popleft. Дополнительная память: dp из n чисел и dq из не больше min(n, k + 1) номеров: после popleft в dq не больше k номеров, а до popleft ещё место i − k − 1. Всего O(n) в худшем случае. Для [0, -1, -2, -3, -4] при k = 2 и i = 3 до popleft в dq три номера: 0, 1, 2.

Решение 2. Heap с отложенным удалением

heapq - это Min-Heap, поэтому код хранит пары (-dp, i): в h[0] пара с наибольшим dp.

В примере 1 при i = 3 в h пары (-1, 0), (0, 1) и (1, 2), а в h[0] пара (-1, 0). Место 0 меньше i − k = 1, пара вне окна, и heappop удаляет её. Новая пара h[0] = (0, 1) в окне: dp[3] = 4 + 0 = 4.

Правило. Модуль heapq не удаляет пару из середины. Поэтому пара вне окна остаётся в h, пока не окажется в h[0]. Тогда while удаляет её через heappop.

Каждая пара окна есть в h: while удаляет только пары с номером меньше i − k. После while пара h[0] в окне. Она наименьшая в h, то есть её dp наибольший среди всех пар h, а значит, и среди пар окна. В примере 1 при i = 4 окно 2..3, а в h пары мест 1, 2 и 3. Пара места 1 вне окна, но остаётся в h: она не в h[0]. Пара h[0] = (-4, 3): dp 4 больше dp 0 и −1 мест 1 и 2. В h всегда есть пара места i − 1: она в окне, и while её не удаляет.

import heapq


class Solution:
    def maxResult(self, nums: list[int], k: int) -> int:
        best = nums[0]
        h = [(-best, 0)]  # пары (-dp, i): в h[0] наибольший dp
        for i in range(1, len(nums)):
            while h[0][1] < i - k:
                heapq.heappop(h)  # вершина вне окна
            best = nums[i] - h[0][0]
            heapq.heappush(h, (-best, i))
        return best

Время: код делает n − 1 вызовов heappush: пара места 0 лежит в h с начала. Каждая пара удаляется не больше одного раза. Пара места n − 1 входит в h последней и остаётся в h, поэтому вызовов heappop не больше n − 1. В примере 1 n = 6: 5 вызовов heappush и 1 вызов heappop. В h не больше n пар, и каждый вызов стоит O(log n). Всего O(n log n) в худшем случае. Дополнительная память: O(n) в худшем случае. Для [1, 1, 1, 1, 1] при k = 2 dp равны 1, 2, 3, 4, 5. Каждая новая пара встаёт в h[0], старые пары не удаляются, и в конце в h все 5 пар.

Типичные ошибки

  • Нет проверки dq[0] < i - k. Старый максимум остаётся в dq[0] после выхода из окна. Для [10, -50, -50, -50, 1] и k = 2 код выдаёт 11 вместо −39: место 0 с dp 10 даёт dp[4], хотя до места 4 четыре шага.
  • Сравнение dq[0] <= i - k. Оно удаляет место i − k, которое ещё в окне. Для [9, -1, -1, -1, 0] и k = 4 код выдаёт 8 вместо 9.
  • Ответ max(dp) вместо dp[-1]. Путь обязан кончаться на последнем месте. В примере 3 max(dp) = 3, а ответ 0.
  • Greedy: каждый раз прыгать на место с наибольшим nums среди следующих k мест. Greedy проходит все три примера, но ошибается на [0, -1, -5, -5, 0] при k = 2. С места 0 он прыгает на место 1 (−1 больше −5). С места 1 места 2 и 3 дают −5: он берёт любое из них, потом прыгает на место 4. Счёт 0 − 1 − 5 + 0 = −6. Ответ −5 даёт путь 0, 2, 4.
