Нужно выписать каждый разный порядок чисел ровно один раз. Пусть n - длина nums, а U - число разных ответов.

Решение 1. Backtracking с пропуском повторов

Возьмите пример 1: nums = [1, 1, 2]. Backtracking из задачи Permutations ставит в path числа с разных мест nums. Порядков мест 3! = 6, а разных ответов 3. Каждый ответ получается дважды: единицы с мест 0 и 1 можно поставить в двух порядках. Если убрать повторы только в конце, то для 8 равных чисел код построит 8! = 40 320 порядков ради одного ответа.

Правило: равные числа идут в path в порядке своих мест. Единицу с места 1 можно взять, только когда единица с места 0 уже в path. Тогда ответ [1, 2, 1] имеет один порядок мест: 0, 2, 1. Порядок 1, 2, 0 запрещён: на первом шаге единица с места 0 ещё свободна. Любой ответ можно собрать по правилу: первую единицу ответа берём с места 0, вторую с места 1. Поэтому ответ не теряется и не повторяется.

После Sorting равные числа стоят рядом, и правило становится одной проверкой. Array used отмечает места, которые уже в path. Место i пропускаем, если nums[i] == nums[i - 1] и место i − 1 ещё свободно: not used[i - 1]. В [2, 2, 2] место 2 можно взять, только когда занято место 1, а место 1 занимают только после места 0. Хватает одного соседа: если место i − 1 с тем же числом занято, то по правилу заняты и все равные числа левее. Когда в path лежат n чисел, копия path[:] идёт в ответ.

Рисунок показывает все 9 вызовов dfs на примере 1. В первом вызове место 1 пропущено: nums[1] == nums[0], а место 0 свободно. Во втором вызове path = [1], место 0 занято, и единицу с места 1 уже можно взять. 3 вызова с полным path дают 3 ответа.

class Solution:
    def permuteUnique(self, nums: list[int]) -> list[list[int]]:
        nums.sort()  # Sorting ставит равные числа рядом
        n = len(nums)
        used = [False] * n
        path = []
        result = []

        def dfs():
            if len(path) == n:
                result.append(path[:])
                return
            for i in range(n):
                if used[i]:
                    continue
                if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                    continue  # равное число левее ещё свободно
                used[i] = True
                path.append(nums[i])
                dfs()
                path.pop()
                used[i] = False

        dfs()
        return result

Время: пусть V - число вызовов dfs с неполным path. Каждый такой вызов проверяет в цикле все n мест, всего nV проверок. Для каждого из U ответов path[:] копирует n чисел. Вместе с Sorting получаем O(n log n + nV + nU) в худшем случае. В примере 1 V = 6: 18 проверок и 9 скопированных чисел. Для 8 разных чисел V = 69 281: 554 248 проверок, а ответ занимает 40 320 · 8 = 322 560 чисел. Для 8 равных чисел ответ один, но V = 8 и проверок 8 · 8 = 64: цикл проверяет и занятые места.

В примере 1 неполные path - это [], [1], [1, 1], [1, 2], [2], [2, 1]: все начала 3 ответов длиной от 0 до 2. В любом вводе самое левое свободное место с данным числом можно взять: место левее с тем же числом уже занято или его нет. Поэтому каждый неполный вызов идёт дальше, и его path - начало ответа. По правилу числа в path задают и порядок мест, так что у разных вызовов path разные. У каждого ответа n начал, значит V ≤ nU: 6 ≤ 3 · 3 в примере 1, а для 8 равных чисел V = nU = 8. Отсюда время O(n log n + n2U) в худшем случае.

Дополнительная память: used и path хранят по n значений. Call Stack держит до n + 1 вызовов dfs: от пустого path до полного. Sorting в Python берёт до O(n) места. Всего O(n). Ответ занимает nU чисел.

Решение 2. Next Permutation

Next Permutation из главы 4 переводит Array в следующий вариант в Lexicographic Order. После Sorting в nums самый маленький вариант. Цикл копирует вариант в ответ и делает следующий шаг, пока шаг возможен.

Возьмите nums = [1, 1, 2, 2]. Шаги дают 6 вариантов: [1, 1, 2, 2], [1, 2, 1, 2], [1, 2, 2, 1], [2, 1, 1, 2], [2, 1, 2, 1], [2, 2, 1, 1]. Это все ответы: двойки занимают 2 места из 4, и таких выборов 4 · 3 / 2 = 6. Каждый вариант больше предыдущего, поэтому повторов нет. Например, [1, 1, 2, 2] меньше [1, 2, 1, 2]: первое отличие на месте 1, и 1 < 2. Шаг даёт ближайший больший вариант, поэтому между соседними вариантами нет пропущенного ответа.

Первый шаг. Идём справа налево: двойки на местах 2 и 3 не возрастают, а nums[1] = 1 меньше nums[2] = 2. Значит, i = 1. Хвост - числа после места i. Самое правое число больше 1 стоит на месте 3: j = 3. Обмен даёт [1, 2, 2, 1], а разворот хвоста [2, 1] даёт [1, 2, 1, 2].

Равные соседи тоже входят в хвост, поэтому в поиске i стоит >=. В [1, 2, 2, 1] двойки на местах 1 и 2 равны, поиск идёт дальше и находит i = 0. В [2, 2, 1, 1] все соседи не возрастают, поиск доходит до i = −1, и цикл кончается.

class Solution:
    def permuteUnique(self, nums: list[int]) -> list[list[int]]:
        nums.sort()  # первый вариант в Lexicographic Order
        n = len(nums)
        result = [nums[:]]
        while True:
            i = n - 2
            while i >= 0 and nums[i] >= nums[i + 1]:
                i -= 1
            if i < 0:
                return result  # весь nums не возрастает: это последний вариант
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]
            nums[i + 1:] = nums[i + 1:][::-1]
            result.append(nums[:])

Время: поиск i, поиск j и разворот хвоста проходят не больше n мест, а копия в ответ берёт n чисел: O(n) на шаг. Шагов U: U − 1 шагов дают новые варианты, последний находит i = −1. Вместе с Sorting получаем O(n log n + nU) в худшем случае. Ниже строка метода считается столько раз, сколько раз она выполнена. Для 8 равных чисел решение 2 выполняет 22 строки, а решение 1 выполняет 287 строк. Для 8 разных чисел решение 1 выполняет 2 470 274 строки, а решение 2 выполняет 449 755 строк: в 5,5 раза меньше.

Дополнительная память: срезы nums[i + 1:] и [::-1] создают две копии хвоста, до n − 1 чисел в каждой. Sorting тоже берёт до O(n) места. Recursion здесь нет, и Call Stack не растёт. Всего O(n). Ответ занимает nU чисел, а nums меняется на месте.

Типичные ошибки

  • Пропуск без not used[i - 1]: if i > 0 and nums[i] == nums[i - 1]: continue. Тогда единицу с места 1 нельзя взять никогда. Для [1, 1, 2] path не доходит до длины 3, и ответ пустой.
  • Правило без Sorting. В [2, 1, 2] двойки стоят на местах 0 и 2. Проверка сравнивает nums[2] с nums[1] = 1 и не видит повтор. Код вернёт 6 списков: каждый из 3 ответов дважды.
  • Next Permutation без Sorting. Для [3, 2, 1] первый же шаг находит i = −1, и ответ только [[3, 2, 1]] вместо 6 вариантов.
  • Строгое сравнение nums[i] > nums[i + 1] в поиске i. Для [1, 1, 2] после [2, 1, 1] снова идёт [1, 2, 1], и цикл не кончается. На первом шаге для [1, 1, 2, 2] поиск i сразу останавливается на i = 2: условие 2 > 2 ложно. Числа больше 2 нет, поэтому j уходит левее места 0. Индексы от −1 до −4 Python читает с конца списка, а при j = −5 код падает с IndexError.
