При n = 4 можно для каждой из четырёх монет выбрать одну из двух групп. Brute Force проверит все 24 = 16 вариантов, включая те, где в группах разное число монет. Если для каждого варианта заново считать монеты и складывать их веса, перебор займёт O(n · 2n) времени. При n = 30 один набор потребует 30 · 230 = 32 212 254 720 проверок монет.

Решение 1. Greedy

При n = 4 самая тяжёлая монета весит 16, а остальные вместе весят 2 + 4 + 8 = 14. Если прибавить к этой сумме 2, две двойки дадут 4, две четвёрки дадут 8, а две восьмёрки дадут 16. При любом n так получим 2n, поэтому сумма всех меньших весов равна 2n − 2. Группа с самой тяжёлой монетой тяжелее другой, даже когда в ней лежит только эта монета.

Пока монета весом 16 лежит отдельно, разность равна 16 − 14 = 2. Из четырёх монет в каждую группу должны попасть две, поэтому рядом с монетой весом 16 остаётся одно место. Если перенести к ней монету весом 2, получим разность 18 − 12 = 6. Если для того же места выбрать монету весом 4, получим (16 + 4) − (14 − 4) = 10. Перенос монеты весом w увеличивает вес тяжёлой группы на w и уменьшает вес лёгкой на w. Разность растёт на 2 · w.

В каждой группе должно быть half = n // 2 монет. Одно место в тяжёлой группе уже занято, поэтому переносим ровно half − 1 монет. Чтобы разность выросла как можно меньше, выбираем для переноса самые лёгкие монеты. При n = 2 переносить нечего, и ответ равен 4 − 2 = 2.

В Python сдвиг влево 1 << 4 даёт 16, так как единица умножается на двойку четыре раза. При n = 4 первый цикл начинает с heavy = 16 и прибавляет 2 при i = 1. Второй цикл прибавляет к light сначала 4 при i = half = 2, затем 8 при i = 3. Код прибавляет вес 1 << i к heavy при показателях от 1 до half − 1, а к light при показателях от half до n − 1.

import sys

read = sys.stdin.readline
t = int(read())
answers = []
for _ in range(t):
    n = int(read())
    half = n // 2
    heavy = 1 << n
    for i in range(1, half):
        heavy += 1 << i
    light = 0
    for i in range(half, n):
        light += 1 << i
    answers.append(str(heavy - light))

print("\n".join(answers))

При n = 4 циклы выполняют 1 + 2 = 3 сложения, а при любом чётном n всего n − 1 сложений. При n ≤ 30 даже сумма всех весов меньше 231, поэтому одну операцию с весами считаем за O(1). Время: в худшем случае O(n) на набор и O(N) на весь ввод, где N обозначает общее число монет во всех наборах. Дополнительная память: в худшем случае O(1) для подсчёта двух сумм и O(t) для всей программы. При выводе в памяти одновременно находятся t ответов в списке answers и строка, которую строит join.

Решение 2. Формула разности

При n = 6 начальная разность равна 64 − 62 = 2. К монете весом 64 переходят монеты весом 2 и 4, поэтому итоговая разность равна 2 + 2 · (2 + 4) = 14. Здесь half = 3, а сумма перенесённых весов равна 2 + 4 = 23 − 2.

В общем случае мы переносим все монеты легче 2half, поэтому их суммарный вес равен 2half − 2. Начальная разность всегда равна 2, а каждый перенесённый вес учитывается дважды. Отсюда difference = 2 + 2 · (2half − 2) = 2half + 1 − 2.

import sys

read = sys.stdin.readline
t = int(read())
answers = []
for _ in range(t):
    n = int(read())
    half = n // 2
    difference = (1 << (half + 1)) - 2
    answers.append(str(difference))

print("\n".join(answers))

Время: в худшем случае O(1) на набор и O(t) на весь ввод, так как для каждого набора код вычисляет формулу один раз. Дополнительная память: в худшем случае O(1) для вычисления разности и O(t) для списка ответов и строки вывода.
