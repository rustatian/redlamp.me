Greedy

В примере [1, 3, 3, 2] первые два числа уже стоят по возрастанию. Третье число равно соседу слева, поэтому прибавляем d = 2 и получаем 3 + 2 = 5. Последнее число за один ход вырастет лишь до 2 + 2 = 4, а за два хода достигнет 2 + 2 · 2 = 6. Всего нужно 1 + 2 = 3 хода.

Можно прибавлять d по одному ходу в цикле, пока число не станет больше исправленного левого соседа. Большой вход: n = 2000, d = 1, b0 = 106 и b1 = ... = b1999 = 1. Второе число растёт до 106 + 1 за 106 сложений, третье до 106 + 2 за 106 + 1, а последнее до 106 + 1999 за 106 + 1998 сложений. Всего получается 1999 · 106 + 1999 · 1998 / 2 = 2 000 997 001, или около 2 · 109 сложений: слишком долго. Поэтому число ходов посчитаем делением.

Обозначим через value текущее число, а через previous уже исправленное значение соседа слева. В примере [1, 3, 3, 2] для третьего числа value = 3 и соседа previous = 3 разность равна 3 − 3 = 0. Целая часть 0 // 2 = 0 ещё оставляет равенство 3 + 0 · 2 = 3, поэтому нужен 0 + 1 = 1 ход до 5. Для последнего числа value = 2 и исправленного соседа previous = 5 разность равна 5 − 2 = 3. Здесь 3 // 2 = 1 ход даёт 2 + 1 · 2 = 4 ≤ 5, а 1 + 1 = 2 хода дают 2 + 2 · 2 = 6 > 5. В общем случае при value ≤ previous пусть k = (previous − value) // d. Тогда k · d ≤ previous − value < (k + 1) · d, значит value + k · d ≤ previous < value + (k + 1) · d. После k ходов число ещё не больше соседа (при делении без остатка оно равно previous), а после k + 1 хода уже строго больше. Поэтому при value ≤ previous берём (previous − value) // d + 1 ходов. Если value > previous, оставляем 0 ходов.

В примере [1, 3, 3, 2] лишний ход для третьего числа поднял бы его с 5 до 7, и тогда последнему уже не хватило бы значения 6. У первого числа b0 нет соседа слева, а каждый ход только прибавляет d > 0. Поэтому любой ход на первом числе лишний: если его убрать, условие для второго числа станет слабее, а слева ограничений нет. Для каждого следующего числа, если убрать лишний ход сверх минимума, оно всё ещё больше исправленного левого соседа, а условие для правого соседа станет слабее. Так можно пройти слева направо по любому решению, оставить b0 без ходов и убрать все лишние ходы у чисел от b1 до bn − 1. Останутся ровно те ходы, которые считает программа.

При шаге 2 тройка [1, 2, 3] уже возрастает, а в тройке [1, 3, 3] хватает одного хода: последняя тройка станет пятёркой. В тройке [3, 1, 3] первое число остаётся равным 3, единицу нужно увеличить хотя бы до 5, а последнюю тройку уже до 7. На это нужно 2 + 2 = 4 хода.

n, d = map(int, input().split())
tokens = input().split()
previous = int(tokens[0])
total = 0
for i in range(1, n):
    value = int(tokens[i])
    moves = 0
    if value <= previous:
        moves = (previous - value) // d + 1
    previous = value + moves * d
    total += moves
print(total)

В программе tokens = input().split() считывает элементы последовательности как строки. Запись previous = int(tokens[0]) оставляет b0 без изменений, а цикл for i in range(1, n): обрабатывает числа от b1 до bn − 1.

В файле один случай, поэтому оценки для него и для всей программы совпадают. Время: O(n) в худшем случае: для каждого числа программа вычисляет число ходов сразу. Дополнительная память: O(n) в худшем случае: при чтении второй строки split() создаёт список из n строк с числами. При n ≤ 2000 и значениях d и bi до 106 длина записи ответа ограничена: print выводит одно число.
