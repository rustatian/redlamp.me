В примере из шести чисел Brute Force проверяет 0 + 1 + 2 + 3 + 4 + 5 = 15 пар. Каждое число он сравнивает со всеми, что стоят левее. Для n чисел это n(n − 1)/2 проверок и O(n2) времени. При n = 200 000 пришлось бы проверить 19 999 900 000 пар.

Решение 1. Hash Table по двум остаткам

В первом наборе x = 5 и y = 2. При делении на 5 получаем 9 = 5 + 4 и 1 = 0 + 1. Если отбросить 5 + 0, вместо 9 + 1 = 10 получим 4 + 1 = 5. Обе суммы делятся на 5. Остатки при делении на 5 лежат в пределах от 0 до 4, поэтому их сумма лежит в пределах от 0 до 8. В этих пределах на 5 делятся только 0 и 5. Можно сложить только остатки, ведь отброшенные части обоих чисел кратны x. Каждый остаток меньше x, поэтому сумма остатков может быть кратна x только при значении 0 или x.

При делении числа 9 на x = 5 получаем остаток rx = 4. До 5 ему не хватает 5 − 4 = 1. В Python -4 % 5 даёт ту же единицу, потому что −4 = 5 · (−1) + 1. Если 0 < rx < x, то до x не хватает x − rx. Это и есть остаток от деления −rx на x, так как −rx = −x + (x − rx) и 0 < x − rx < x. При x = 5 получаем 0 % 5 = 0. Если rx = 0, у второго числа остаток от деления на x тоже должен быть нулевым. Так для остатка rx одно выражение -rx % x находит нужный остаток в обоих случаях.

У чисел 1 и 9 одинаковый остаток от деления на 2, и их разность 1 − 9 = −8 делится на 2. При делении на 2 получаем 2 = 2 + 0 и 9 = 8 + 1. Разность чётных частей 2 − 8 = −6 делится на 2. Прибавим разность остатков 0 − 1 = −1 и получим нечётное число −6 + (−1) = −7. Разность частей, кратных y, делится на y. Разность остатков лежит строго между −y и y, а в этих пределах на y делится только 0. Поэтому разность исходных чисел делится на y ровно тогда, когда остатки равны.

Число 4 даёт остаток rx = 4 по x = 5 и остаток ry = 0 по y = 2, поэтому его ключ key = (4, 0). Слева ищем ключ need = (1, 0). У числа 1 есть нужный остаток 1 по 5, а у числа 2 есть нужный остаток 0 по 2. Ни одно число слева не даёт оба остатка сразу. В словаре seen по ключу (rx, ry) храним число позиций слева с такими остатками. Если ключа ещё нет, seen.get(need, 0) даёт ноль. При обработке 9 ключ (1, 1) уже встретился один раз, у числа 1. Для 6 совпадение даёт число 4 с ключом (4, 0). Всего в примере две пары.

У всех пятёрок при тех же делителях один и тот же ключ (0, 1). Для пары с пятёркой нужен тот же ключ.

Если сначала записать третью пятёрку в seen, поиск найдёт три совпадения, включая саму третью пятёрку. Сначала берём из seen число совпадений, затем увеличиваем счётчик для key на единицу. Так каждая красивая пара попадает в pairs один раз, при обработке правой позиции.

import sys


def count_pairs(values, x, y):
    seen = {}
    pairs = 0
    for value in values:
        rx, ry = value % x, value % y
        need = (-rx % x, ry)
        pairs += seen.get(need, 0)
        key = (rx, ry)
        seen[key] = seen.get(key, 0) + 1
    return pairs


read = sys.stdin.readline
answers = []
for _ in range(int(read())):
    n, x, y = map(int, read().split())
    values = list(map(int, read().split()))
    answers.append(str(count_pairs(values, x, y)))
print("\n".join(answers))

Время: ожидаемое O(n) на набор. Для каждого числа код дважды вызывает get и один раз записывает счётчик. Каждая такая операция занимает в среднем O(1) времени. Дополнительная память: O(n) в худшем случае. В seen не больше n ключей, так как каждое число добавляет не больше одного ключа. Входной список values считаем отдельно.

Решение 2. Sorting и Binary Search по ключам

В списке [1, 9, 4, 19] при x = 5 и y = 2 для числа 1 ищем ключ (4, 1). У чисел 9, 4, 19 ключи идут в порядке (4, 1), (4, 0), (4, 1). Первый остаток у всех трёх равен 4. По второму остатку (4, 0) идёт первым, так как 0 < 1. Теперь обе копии (4, 1) стоят рядом. Ключ (1, 1) числа 1 идёт перед (4, 0), потому что его первый остаток 1 меньше 4. Упорядочим ключи сначала по первому остатку, а при равенстве по второму.

Для [19, 1, 9] при тех же делителях число 1 образует пару и с 19, и с 9. У пар (19, 1) и (1, 19) одна и та же сумма 20, кратная 5. Разности 19 − 1 = 18 и 1 − 19 = −18 делятся на 2. Если поменять числа местами, сумма сохранится, а разность сменит знак и сохранит делимость. После Sorting получим [(1, 1), (4, 1), (4, 1)].

Справа от позиции i = 0 обе функции сначала сравнивают искомый ключ (4, 1) с таким же ключом на позиции 2. Функция bisect_left ищет начало группы, поэтому проверяет ещё и позицию 1. Там тоже стоит (4, 1), поэтому left = 1. Функция bisect_right ищет границу за последним совпадением, поэтому пропускает равный ключ на позиции 2 и возвращает right = 3. Число совпадений равно right − left = 2.

При i = 1 поиск ключа (1, 1) начинается с позиции 2. Там стоит единственный оставшийся ключ (4, 1), и он больше искомого. Для bisect_left это первая позиция с ключом не меньше искомого, а для bisect_right это первая позиция с ключом строго больше искомого. Обе функции возвращают 2, так что совпадений 2 − 2 = 0. Если нужного ключа справа нет, обе границы совпадают.

Поиск начинается с i + 1. Каждую красивую пару считаем один раз, когда берём её левую позицию в упорядоченном списке.

import sys
from bisect import bisect_left, bisect_right


def count_pairs(values, x, y):
    keys = sorted((v % x, v % y) for v in values)
    pairs = 0
    for i, (rx, ry) in enumerate(keys):
        need = (-rx % x, ry)
        left = bisect_left(keys, need, i + 1)
        right = bisect_right(keys, need, i + 1)
        pairs += right - left
    return pairs


read = sys.stdin.readline
answers = []
for _ in range(int(read())):
    n, x, y = map(int, read().split())
    values = list(map(int, read().split()))
    answers.append(str(count_pairs(values, x, y)))
print("\n".join(answers))

Пусть в области поиска 8 ключей. После сравнения со средним ключом остаётся проверить не больше 4 ключей, затем не больше 2, затем не больше 1. Для последнего ключа достаточно ещё одного сравнения. В худшем случае число сравнений растёт как логарифм от n, поэтому один поиск занимает O(log n) времени. Sorting занимает O(n log n) времени в худшем случае, а затем код делает по два поиска для каждой позиции. Время: O(n log n) в худшем случае на набор. Дополнительная память: O(n) в худшем случае. В keys лежат n пар остатков, и поиск работает по границам без копии списка.
