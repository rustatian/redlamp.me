У корня со значением 4 два ребёнка со значениями 3 и 3. У них нет детей, поэтому их называют листьями. Если оставить оба листа, можно забрать только 4. Если оставить только корень, можно забрать 3 + 3 = 6, а на каждом пути останется 4. Если забрать значения корня и одного листа, сумма на пути к этому листу станет 0 + 0 = 0. Такой выбор недопустим, хотя второй лист сохраняет значение 3. Все исходные значения положительны, поэтому выбор допустим ровно тогда, когда на каждом пути от корня до листа остаётся хотя бы одно ненулевое значение. Чем меньше сумма оставленных значений, тем больше счёт.

У каждой из трёх вершин два варианта, поэтому Brute Force проверит 23 = 8 наборов. Если оставить только корень, оба листа получат от него отметку. В недопустимом наборе отметку получит только лист, сохранивший 3. При обходе от корня отмечаем вершину, если оставили её значение или уже отметили её родителя. Отметка означает, что на пути от корня до этой вершины включительно осталось положительное значение. Набор подходит, если отметка есть у каждого листа. Посещаем по три вершины на набор, всего 8 · 3 = 24 посещения. Проверка всех наборов занимает O(n · 2n) времени. При n = 20 000 это 20 000 · 220 000 посещений вершин.

Решение 1. Dynamic Programming по поддеревьям

Во втором примере у вершины 1 значение 10. Её дети, листья 3 и 4, имеют значения 7 и 4. Если забираем значение корня, то в этой ветви можно оставить 10 в вершине 1 или 7 + 4 = 11 в листьях. Дешевле оставить 10.

Обозначим через keep[v] наименьшую сумму, которую надо оставить в поддереве v, чтобы на каждом пути от v до листа сохранилось положительное значение. В поддереве листа 3 есть только путь [3]. Если забрать 7, сумма на этом пути станет 0, поэтому keep[3] = 7. Для любого листа v получаем keep[v] = values[v].

У вершины 2 выгоднее оставить значения детей 3 + 5 = 8, чем сохранять её значение 9. В корне сравниваем 20 с суммой keep[1] + keep[2] = 10 + 8 = 18. Из общей суммы 58 получаем счёт 58 − 18 = 40.

Если оставляем values[v], каждый путь от вершины v до листа начинается с этого положительного значения. Поэтому остальные значения в поддереве можно забрать. Если забираем значение в v, надо выполнить условие отдельно у каждого ребёнка. Поддеревья детей не имеют общих вершин, поэтому их минимальные суммы складываются в child_sum. Эти два выбора охватывают все случаи, значит, у вершины с детьми keep[v] = min(values[v], child_sum).

Для расчёта keep[1] нужны готовые значения keep[3] и keep[4]. Код начинает список order с корня. Цикл добавляет соседей корня в order и запоминает их родителя. После обработки корня order = [0, 1, 2] и parent[1] = 0. Затем тот же цикл берёт из списка вершину 1 с соседями [0, 3, 4]. По условию child != parent[v] код пропускает родителя 0 и добавляет в order детей 3 и 4. Родитель попадает в список раньше детей, так что при обратном проходе все нужные keep[child] уже готовы. У листа 3 та же проверка исключает единственного соседа (родителя 1), поэтому child_sum = 0. Код пропускает min, и в keep[3] остаётся 7 из values.copy(). Условие if child_sum выполняется только у вершин с детьми, потому что каждое keep[child] положительно.

class Solution:
    def maximumScoreAfterOperations(self, edges: list[list[int]], values: list[int]) -> int:
        n = len(values)
        neighbors = [[] for _ in range(n)]
        for a, b in edges:
            neighbors[a].append(b)
            neighbors[b].append(a)

        parent = [-1] * n
        order = [0]
        for v in order:
            for child in neighbors[v]:
                if child != parent[v]:
                    parent[child] = v
                    order.append(child)

        keep = values.copy()
        for v in reversed(order):
            child_sum = 0
            for child in neighbors[v]:
                if child != parent[v]:
                    child_sum += keep[child]
            if child_sum:
                keep[v] = min(values[v], child_sum)
        return sum(values) - keep[0]

Во втором примере у шести рёбер по две записи. При построении order проверяем 2 · 6 = 12 записей, при расчёте keep ещё 12, всего 24. values.copy() копирует семь элементов в keep. sum(values) складывает исходные числа и даёт 58. Поддеревья детей не пересекаются, поэтому child_sum не превышает общей суммы.

В двоичной записи 3 и 5 имеют вид 11 и 101. Уравняем длины нулём слева. Слева 0 < 1, поэтому 011 < 101. Сравниваем слева до первого различия. Сложение справа даёт 1 + 1 = 10. Пишем 0 и переносим 1 влево. С переносом получаем 1 + 0 + 1 = 10 и 0 + 1 + 1 = 10, так что 011 + 101 = 1000. За 111 (7) идёт 1000 (23 = 8), первое число из четырёх двоичных цифр. У 245 за единицей 45 нулей. Это первое число из 46 цифр. По условию сумма не больше 20 000 · 109 = 20 000 000 000 000 < 245. На разряд нужно постоянное число действий, а разрядов не больше 45. Поэтому одно сложение или сравнение занимает O(1) времени.

Пусть у корня 78 листьев. При длине 65 Python на сайте выделил для order 76 мест. Ещё 11 добавлений заполняют их. На 12-м Python может скопировать 76 записей в другую часть памяти. После расширения большого списка свободно примерно одно место на восемь занятых. До нового переноса заполняем запас, поэтому на добавление в среднем приходится несколько копирований. В neighbors добавляем n списков, в них 2 · (n − 1) записей, в order ещё n − 1 вершин. Все добавления с переносами занимают O(n) времени.

У Tree с n вершинами n − 1 рёбер, отсюда 2 · (n − 1) проверок за обход. Копирование и подсчёт суммы читают по n значений. Время: O(n) в худшем случае. Во втором примере в семи списках соседей 12 записей. В parent, order и keep по семь элементов, по одному на вершину. Дополнительная память: O(n) в худшем случае.

Решение 2. Переходы по порядку DFS

Во втором примере код перебирает соседей корня в обратном порядке и добавляет в Stack сначала 2, затем 1. Извлекаем вершину 1 и добавляем её детей в порядке 4, 3. Теперь в Stack лежат вершины [2, 4, 3]. Метод pop() берёт последнюю запись. Листья 3 и 4 не добавляют записей, поэтому код извлекает оба листа раньше вершины 2. Получаем порядок DFS [0, 1, 3, 4, 2, 5, 6].

Если оставить вершину 1 и лист 3, в них останется 10 + 7 = 17. Обнуление листа увеличит счёт на 7, а значение 10 останется на пути к нему.

Сначала size[1] = 1, потому что считаем только саму вершину 1. Прибавляем единицу за лист 4 и получаем size[1] = 2. Прибавляем ещё единицу за лист 3 и получаем size[1] = 3. В поддереве вершины 2 тоже три вершины, включая листья 5 и 6. Для корня прибавляем к единице размеры обоих поддеревьев и получаем size[0] = 1 + 3 + 3 = 7. Для каждой вершины v начинаем с size[v] = 1. Как и в решении 1, при обратном проходе обрабатываем детей раньше родителя. У листа нет детей, и его размер остаётся равным 1. У вершины с детьми прибавляем к единице размер поддерева каждого ребёнка, поэтому size[v] > 1.

Вершины 1, 3, 4 занимают позиции 1, 2, 3. Оставив вершину 1, переходим на позицию end = 1 + 3 = 4 к вершине 2. В решении 1 порядок BFS равен [0, 1, 2, 3, 4, 5, 6]. В BFS тот же шаг пропустил бы вершину 2 другой ветви и привёл бы к листу 4 внутри поддерева.

В первом примере обработка вершины 2 меняет Stack с [3, 2] на [3, 4]. Затем код извлекает вершину 4 и кладёт её ребёнка 5 поверх вершины 3, получая [3, 5]. Вершины 2, 4, 5 идут подряд, и шаг с позиции 2 на 2 + size[2] = 5 ведёт к вершине 3. Код кладёт детей текущей вершины выше ожидающих вершин из других ветвей. Поэтому с позиции i подряд идут все size[v] вершин поддерева.

В начале ещё ничего не оставили, поэтому best[0] = 0. Во втором примере сумма оставленных значений не больше 58. В остальные ячейки записываем total + 1 = 59, чтобы первый же переход уменьшил это число. На рисунке пустая ячейка означает, что до этой позиции пока не дошли.

Забрав 20 в корне, получаем best[1] = 0. Обнулив вершину 1, получаем best[2] = 0. Оставляем 7 в листе 3 и 4 в листе 4. В позицию 4 приходим с суммой 11. Если оставить вершину 1, сразу попадём туда с суммой 10. Для листьев 5 и 6 в обоих случаях нужен найденный ранее минимум 8. Поэтому к пятому шагу best[4] = min(10, 11) = 10.

На пути от корня к каждому листу до позиции i в порядке DFS уже есть оставленное значение. Мы либо оставили значение самого листа, либо пропустили его, когда оставили значение предка. На путях к остальным листьям мы ещё ничего не оставили. Если бы мы оставили значение предка одного из этих листьев, то перешли бы за этот лист и пропустили позицию i. В best[i] храним наименьшую сумму оставленных значений, с которой можно прийти в позицию i.

Как и в решении 1, оставленная v даёт положительную сумму на каждом пути к листу её поддерева. Если оставить ещё и потомка, счёт уменьшится на его значение. Поэтому переходим на i + size[v] с суммой best[i] + values[v]. Обнулив вершину с детьми, переходим на i + 1 с прежней суммой. В листе придётся оставить его значение. У листа size[v] = 1, и мы тоже попадём на i + 1. Так можно дойти от 0 до любого i шагами по одной позиции. При i > 0 шаг из i − 1 уже дал сумму меньше total + 1.

Из одной позиции доступны одни и те же переходы, поэтому в best[i] сохраняем наименьшую сумму. Все переходы ведут вперёд. К началу шага i код уже проверил все переходы в эту позицию, поэтому для расчёта минимумов хватает одного прохода.

В конце порядка получаем best[7] = 10 + 8 = 18. На каждом пути от корня до листа мы сохранили положительное значение, поэтому ответ равен total − best[n].

class Solution:
    def maximumScoreAfterOperations(self, edges: list[list[int]], values: list[int]) -> int:
        n = len(values)
        neighbors = [[] for _ in range(n)]
        for a, b in edges:
            neighbors[a].append(b)
            neighbors[b].append(a)

        order = []
        stack = [(0, -1)]
        while stack:
            v, parent = stack.pop()
            order.append((v, parent))
            for child in reversed(neighbors[v]):
                if child != parent:
                    stack.append((child, v))

        size = [1] * n
        for v, parent in reversed(order):
            if parent != -1:
                size[parent] += size[v]

        total = sum(values)
        best = [total + 1] * (n + 1)
        best[0] = 0
        for i, (v, parent) in enumerate(order):
            end = i + size[v]
            best[end] = min(best[end], best[i] + values[v])
            if size[v] > 1:
                best[i + 1] = min(best[i + 1], best[i])
        return total - best[n]

Для тех же 78 листьев в stack выделено 92 места. После 32 извлечений занята половина. На 33-м остаётся 45 записей, и Python сокращает число мест до 56. До роста нужно не менее 56 − 45 + 1 = 12 добавлений, до сокращения ниже половины не менее 45 − 27 = 18 извлечений. При переносе копируем не больше прежнего числа мест, здесь до 56. После изменения размера большого списка занято около 8/9 мест. До роста надо заполнить около 1/9 мест, до сокращения освободить около 8/9 − 1/2 = 7/18. Делим число мест на число операций с прошлого изменения размера. Получаем лишь несколько копирований на операцию. Каждую операцию учитываем один раз. Все n добавлений и n извлечений требуют O(n) времени. Для neighbors и order верен расчёт из решения 1.

Во втором примере DFS проверяет 12 записей соседей, в общем случае 2 · (n − 1). Размеры поддеревьев считаем за семь шагов. Сохранение проверяем семь раз, обнуление только у вершин 0, 1, 2. В каждом проходе n шагов, на шаг не больше двух переходов. sum(values) читает n чисел. В best[i] только значения до i, поэтому best[i] + values[v] ≤ total. Даже для total + 1 ≤ 20 000 000 000 001 < 245 хватает 45 двоичных цифр. Сложение и сравнение требуют O(1) времени. Время: O(n) в худшем случае.

После добавления детей вершины 1 в Stack три записи, это максимум. Каждого ребёнка добавляет лишь родитель, поэтому в Stack не больше n записей. В neighbors те же семь списков с 12 записями. В order и size по семь записей. В best восемь мест: n + 1 с учётом позиции за последней вершиной. Дополнительная память: O(n) в худшем случае.
