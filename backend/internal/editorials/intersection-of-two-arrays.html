Общее число есть и в nums1, и в nums2. Нужны все общие числа, каждое один раз.

Решение 1. Sorting и Two Pointers

Возьмите пример 2: nums1 = [4, 9, 5], nums2 = [9, 4, 9, 8, 4]. После Sorting получаем a = [4, 5, 9] и b = [4, 4, 8, 9, 9]. Указатель i стоит на месте 0 в a, указатель j на месте 0 в b.

Числа a[0] = 4 и b[0] = 4 равны. Число 4 общее: код записывает его в ответ и сдвигает оба указателя. Теперь a[1] = 5 и b[1] = 4. Число 4 меньше 5, и код делает j += 1. Затем 5 меньше b[2] = 8, и код делает i += 1. Число 8 меньше a[2] = 9: снова j += 1. Числа a[2] = 9 и b[3] = 9 равны, и 9 идёт в ответ. Теперь i = 3 = len(a), и цикл кончается. Ответ [4, 9]: условие разрешает любой порядок.

Правило. a[i] < b[j]: i += 1. a[i] > b[j]: j += 1. Числа равны: код записывает число, если его ещё нет в ответе, и сдвигает оба указателя.

Ход i += 1 не теряет общее число. При a[1] = 5 и b[2] = 8 все числа b от места 2 не меньше 8, потому что b отсортирован. Число 5 меньше 8, поэтому в b от места 2 его нет.

Так в каждом случае. Код сохраняет инвариант: каждое общее число уже есть в ответе или стоит и в a от места i, и в b от места j. Сначала i = j = 0, и инвариант верен. Пусть a[i] < b[j]. Все числа b от места j не меньше b[j], поэтому числа a[i] там нет. Если бы a[i] было общим числом не из ответа, то по инварианту оно стояло бы в b от места j. Значит, число a[i] уже в ответе или не общее, и ход i += 1 сохраняет инвариант. Ход j += 1 сохраняет его по той же причине. В примере 2 ход j += 1 при a[1] = 5 и b[1] = 4 убирает второе число 4, а 4 уже в ответе.

После шага при равенстве a[i] = b[j] это число есть в ответе: код записал его сейчас или раньше. Другие общие числа не из ответа не равны ему. По инварианту они стоят в a от места i и в b от места j, поэтому остаются в a от места i + 1 и в b от места j + 1. Цикл кончается при i = len(a) или j = len(b). Тогда в a от места i или в b от места j нет ни одного числа, и все общие числа уже в ответе.

Теперь повторы. Возьмите пример 1: после Sorting a = [1, 1, 2, 2] и b = [2, 2]. Число 1 меньше 2, и i два раза идёт вправо. При i = 2 и j = 0 числа равны, и 2 идёт в ответ. При i = 3 и j = 1 числа снова равны 2. Последнее число ответа answer[-1] = 2, поэтому код не записывает 2 второй раз. Ответ [2].

Сравнения с последним числом ответа хватает. Указатели идут только вправо, а a отсортирован, поэтому каждое следующее равенство даёт число не меньше прошлого. Числа в ответе идут по возрастанию. Пусть ответ уже [4, 9]. Следующее равное число не меньше 9. Если оно равно 9, то это последнее число ответа. Число 4 встретиться уже не может: оно меньше 9.

class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        a, b = sorted(nums1), sorted(nums2)
        i = j = 0
        answer = []
        while i < len(a) and j < len(b):
            if a[i] < b[j]:
                i += 1  # числа a[i] нет в b от места j
            elif a[i] > b[j]:
                j += 1  # числа b[j] нет в a от места i
            else:
                if not answer or answer[-1] != a[i]:
                    answer.append(a[i])
                i += 1
                j += 1
        return answer

Время: n и m - длины nums1 и nums2. Sorting занимает O(n log n + m log m). Каждый шаг цикла сдвигает i или j, а цикл кончается при i = n или j = m. Поэтому шагов не больше n + m. В примере 2 шагов 5, а n + m = 8. Всего O(n log n + m log m) в худшем случае. Дополнительная память: копии a и b хранят n + m чисел: O(n + m). Ответ хранит k чисел, где k - число разных общих чисел.

Решение 2. Hash Table

Python set - это Hash Table. Проверка x in seen и удаление seen.remove(x) в среднем занимают O(1).

В примере 2 seen = set(nums1) хранит числа 4, 9 и 5. Код идёт по nums2 = [9, 4, 9, 8, 4]. Число 9 есть в seen: оно идёт в ответ и уходит из seen. С числом 4 то же самое. Когда код доходит до второго числа 9, его в seen уже нет. Числа 8 в seen нет. Со вторым числом 4 то же самое. Ответ [9, 4].

Удаление даёт уникальность: число попадает в ответ только при первой встрече в nums2. Каждое общее число есть в seen до этой первой встречи, поэтому в ответ попадают все общие числа.

class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        seen = set(nums1)
        answer = []
        for x in nums2:
            if x in seen:
                answer.append(x)
                seen.remove(x)  # второй раз x не попадёт в ответ
        return answer

Время: ожидаемое для Hash Table. set(nums1) делает n добавлений. Цикл делает m проверок и k удалений. Всего O(n + m) в среднем. Дополнительная память: seen хранит разные числа nums1, их не больше n: O(n). Ответ хранит k чисел.

Типичные ошибки

  • Записывать каждое равенство. В примере 1 равенство 2 = 2 случается два раза, и ответ будет [2, 2] вместо [2]. В решении 2 та же ошибка без seen.remove(x).
  • Взять answer[-1] без проверки not answer. При первом равенстве answer пуст, и answer[-1] даёт IndexError.
  • Сравнивать число с переменной last, которая хранит последнее записанное число и сначала равна 0. Для nums1 = [0] и nums2 = [0] код решит, что 0 уже в ответе, и вернёт [] вместо [0].
  • Two Pointers без Sorting. В примере 2 код сравнит 4 и 9: 4 меньше 9, и код сдвинет i. Число 4 из nums1 больше не встретится. Ответ [9] вместо [4, 9].
