В одной строке не может быть двух ферзей, а строк n. Поэтому n ферзей занимают все n строк, по одному в каждой. Доску задаёт list queens: queens[r] это столбец ферзя строки r. Первая доска примера 1 это queens = [1, 3, 0, 2].

Brute Force перебирает все варианты queens: в каждой из n строк n столбцов, всего nn досок. Каждую доску он проверяет по парам ферзей. При n = 4 это 44 = 256 досок. При n = 9 это 99 = 387 420 489 досок, и в каждой до 36 пар: слишком долго.

Решение 1. Backtracking с Pruning

Ставим ферзей сверху вниз. Вызов place(r) пробует для строки r столбцы c = 0, 1, ..., n − 1. Клетку (r, c), которую бьёт ферзь выше, код пропускает. На свободную клетку код ставит ферзя, вызывает place(r + 1) для следующей строки и потом убирает ферзя. Когда r == n, все n ферзей стоят, и код добавляет в res доску из n String. Для ферзя в столбце c код пишет c точек, "Q" и ещё n − 1 − c точек: при n = 4 и c = 1 это ".Q..", 1 точка, "Q" и 4 − 1 − 1 = 2 точки.

Клетку бьёт ферзь выше, если у них общий столбец или общая диагональ. На диагонали вниз вправо шаг прибавляет 1 и к строке, и к столбцу, поэтому разность r − c не меняется: у клеток (0, 1), (1, 2) и (2, 3) она равна −1. На диагонали вниз влево шаг прибавляет 1 к строке и вычитает 1 из столбца, поэтому не меняется сумма r + c: у клеток (0, 3), (1, 2), (2, 1) и (3, 0) она равна 3. Три set хранят столбцы и диагонали поставленных ферзей: cols их столбцы, diag1 их разности r − c, diag2 их суммы r + c. Python set использует Hash Table. Поэтому проверка клетки это три поиска в set, а не сравнение со всеми ферзями выше. Рисунок показывает числа r − c и r + c доски 4 × 4 в вызове place(2) при queens = [0, 2].

Рисунок ниже показывает первые 9 из 17 вызовов place при n = 4, до первого ответа. Знак × отмечает клетку строки r, которую бьёт ферзь выше. Вызов place(2) при queens = [0, 2] не находит свободной клетки: столбцы 0 и 2 есть в cols, у клетки (2, 1) сумма 3 есть в diag2, у клетки (2, 3) разность −1 есть в diag1. Цикл заканчивается без вызова place(3): строку 3 при этих двух ферзях код не перебирает. Это Pruning.

После вызова place(r + 1) код убирает ферзя: queens.pop() и три remove. Так при следующем столбце строки r три set такие же, как до ферзя. После ветки queens = [0, 2] код удаляет сумму 3 из diag2, а новый ферзь (1, 3) клетку (2, 1) не бьёт. Поэтому в вызове place(2) при queens = [0, 3] клетка (2, 1) свободна. Девятый вызов place(4) получает queens = [1, 3, 0, 2] и строит доску [".Q..", "...Q", "Q...", "..Q."], первую доску примера 1.

Код находит каждую доску ответа ровно один раз, и лишних досок в res нет. В вызове place(2) при queens = [1, 3] у клетки (2, 0) столбец 0, r − c = 2 и r + c = 2. У ферзей (0, 1) и (1, 3) столбцы 1 и 3, r − c = −1 и −2, r + c = 1 и 4. Общих чисел нет, поэтому place(2) ставит ферзя на (2, 0), и он не бьёт ферзей (0, 1) и (1, 3). Так каждый новый ферзь и ферзи выше не бьют друг друга, а ниже ферзей ещё нет. Поэтому каждую пару ферзей готовой доски код проверил, когда ставил нижнего из двух. Возьмите вторую доску примера 1, queens = [2, 0, 3, 1]. Вызов place(0) ставит ферзя на клетку (0, 2). Этот ферзь не бьёт клетку (1, 0), поэтому place(1) ставит ферзя на неё. Так же place(2) ставит ферзя на (2, 3), place(3) на (3, 1), и вызов place(4) получает эту доску. Так код доходит до любой доски ответа: в ней ферзи выше не бьют ферзя строки r, и place(r) не пропускает столбец queens[r].

Вызов place(0) один, и его цикл пробует c = 1 один раз. Поэтому вызов place(1) при queens = [1] тоже один. Так же по одному вызову получают queens = [1, 3], [1, 3, 0] и [1, 3, 0, 2]. Цикл каждого вызова пробует каждое c один раз, поэтому каждый вариант queens получает не больше одного вызова, и ни одна доска не повторяется.

При n = 2 и n = 3 ни один вызов не доходит до r == n, и ответ пустой.

Время: пусть V это число вызовов place с r < n, а Q число ответов. При n = 4 в 2 из 17 вызовов r == 4, поэтому Q = 2 и V = 17 − 2 = 15. Каждый из V вызовов проверяет n столбцов: при n = 4 это nV = 4 · 15 = 60 проверок. Проверка это до трёх поисков в set. Ферзя код ставит не чаще, чем проверяет клетку: при n = 4 он ставит ферзя 16 раз. Каждый из Q ответов строит n String по n символов: при n = 4 это n2Q = 16 · 2 = 32 символа. Всего O(nV + n2Q) в среднем случае Hash Table. При n = 9 код делает 8394 вызова, из них Q = 352, поэтому V = 8394 − 352 = 8042, nV = 9 · 8042 = 72 378 проверок и n2Q = 81 · 352 = 28 512 символов.

Дополнительная память: в вызове place(r) list queens и три set хранят по r чисел, r ≤ n. Вызов place(r + 1) начинается только внутри place(r), поэтому в Call Stack не больше n + 1 вызовов. Каждый String доски код собирает из временных String длины до n. Итого O(n). Доска строится сразу в вызове place(n), поэтому код не хранит номера столбцов всех ответов. Ответ занимает n2Q символов.

class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        res = []
        queens = []  # queens[r]: столбец ферзя строки r
        cols, diag1, diag2 = set(), set(), set()

        def place(r):
            if r == n:
                res.append(["." * c + "Q" + "." * (n - 1 - c) for c in queens])
                return
            for c in range(n):
                if c in cols or r - c in diag1 or r + c in diag2:
                    continue  # клетку (r, c) бьёт ферзь выше
                cols.add(c)  # поставить ферзя
                diag1.add(r - c)
                diag2.add(r + c)
                queens.append(c)
                place(r + 1)  # следующая строка
                queens.pop()  # убрать ферзя
                cols.remove(c)
                diag1.remove(r - c)
                diag2.remove(r + c)

        place(0)
        return res

Типичные ошибки

  • Проверка одной диагонали, без diag2. Для n = 4 код вернёт 7 досок вместо 2. Среди них [".Q..", "...Q", "..Q.", "Q..."], где ферзи (1, 3) и (2, 2) бьют друг друга: у обоих r + c = 4.
  • abs(r - c) вместо r − c. Клетки (1, 3) и (2, 0) лежат на разных диагоналях, но обе получают число 2. Обе клетки есть в доске [1, 3, 0, 2]. Во второй доске [2, 0, 3, 1] число 1 получают клетки (1, 0) и (2, 3). Поэтому для n = 4 код вернёт пустой list.
  • Отмена без трёх remove. Столбцы и диагонали ферзей из пройденных веток остаются занятыми, и для n = 4 код вернёт пустой list.
  • res.append(queens) без копии и сборка досок после поиска. Каждый элемент res это тот же list queens. После поиска он пустой, и для n = 4 код вернёт [[], []].
