Пусть n - длина nums. Brute Force строит все порядки чисел nums и ищет порядок после nums. При n = 100 разных чисел порядков 100!, это больше 9 · 10157: слишком долго. Решение ниже меняет только правую часть nums и делает O(n) шагов.

Решение 1. Next Permutation

Возьмите nums = [1, 2, 5, 4, 3] из главы. Хвост [5, 4, 3] убывает. Из чисел 5, 4 и 3 нельзя составить порядок больше 5 4 3: на первом месте уже самое большое число, на втором самое большое из оставшихся. Поэтому с началом [1, 2] большего Array нет, и число 2 должно вырасти.

Шаг 1. Код идёт справа налево и ищет первое место i, где nums[i] < nums[i + 1]. Пары 4, 3 и 5, 4 не подходят, пара 2, 5 подходит: i = 1. Правее i числа стоят по невозрастанию.

Шаг 2. На место i нужно самое маленькое число хвоста, которое больше 2. В хвосте 5 4 3 числа уменьшаются слева направо, поэтому самое правое число, которое больше 2, и есть самое маленькое такое число: 3 на месте j = 4. Обмен даёт [1, 3, 5, 4, 2].

Шаг 3. Хвост [5, 4, 2] всё ещё не возрастает: 5 и 4 больше 3, а значит больше 2. Правее j = 4 чисел нет. В [2, 3, 1] они есть: i = 0, j = 1, и правее j стоит 1. На месте j стоит самое правое число, которое больше nums[i], поэтому 1 не больше старого nums[0] = 2. Обмен даёт [3, 2, 1], и хвост [2, 1] тоже не возрастает. Разворот ставит хвост [5, 4, 2] по возрастанию: [2, 4, 5], это самый маленький порядок чисел 2, 4 и 5. Ответ [1, 3, 2, 4, 5].

Других порядков между [1, 2, 5, 4, 3] и [1, 3, 2, 4, 5] нет. Следующий порядок начинается с 1: [1, 3, 2, 4, 5] больше [1, 2, 5, 4, 3], а каждый порядок с числом больше 1 на месте 0 больше [1, 3, 2, 4, 5]. С началом [1, 2] большего порядка нет, поэтому на месте 1 стоит самое маленькое число хвоста, которое больше 2, то есть 3, а за ним самый маленький порядок чисел 2, 4 и 5.

В примере 2, [3, 2, 1], весь Array не возрастает, и места i нет. Это самый большой порядок. Цикл заканчивается с i = −1, обмена нет, и разворот всего Array даёт самый маленький порядок [1, 2, 3].

На [1, 5, 5] цикл i проходит пару 5, 5, потому что 5 ≥ 5, и останавливается на i = 0. Условие nums[i] >= nums[i + 1] пропускает и пары равных соседей, поэтому на месте i число строго меньше правого соседа. На [1, 5, 1] цикл j проходит nums[2] = 1, потому что 1 ≤ nums[0] = 1, и останавливается на j = 1. Обмен даёт [5, 1, 1], и разворот хвоста [1, 1] его не меняет. Условие nums[j] <= nums[i] пропускает и числа, равные nums[i], поэтому на месте j число строго больше nums[i].

Код главы разворачивает хвост строкой a[i + 1:] = a[i + 1:][::-1]. Срез и разворот создают две копии хвоста: для [1, 2, 5, 4, 3] это 6 чисел, в худшем случае O(n) памяти. Задача разрешает только постоянную дополнительную память. Поэтому решение меняет числа местами двумя индексами: left идёт от i + 1 вправо, right от n − 1 влево. Хвосту [5, 4, 2] нужен 1 обмен: 5 и 2. Sorting хвоста строкой nums[i + 1:] = sorted(nums[i + 1:]) даёт тот же ответ, но тоже создаёт две копии хвоста, а общая оценка Sorting O(n log n) хуже.

Время: цикл i сравнивает до n − 1 пар, цикл j сравнивает до n − 1 чисел, разворот делает до ⌊n/2⌋ обменов: O(n) в худшем случае. Для [1, 2, 5, 4, 3] это 4 сравнения чисел (3 в цикле i и 1 в цикле j) и 2 обмена. Для n = 100 чисел по убыванию это 99 сравнений пар и 50 обменов.

Дополнительная память: пять целых чисел n, i, j, left и right: O(1). Ответ записан в сам nums.

class Solution:
    def nextPermutation(self, nums: list[int]) -> None:
        n = len(nums)
        # Справа налево: первое число, которое меньше правого соседа
        i = n - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1
        if i >= 0:
            # Самое правое число хвоста, которое больше nums[i]
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]
        # Хвост после i стоит по невозрастанию: разворот обменами ставит его по возрастанию
        left, right = i + 1, n - 1
        while left < right:
            nums[left], nums[right] = nums[right], nums[left]
            left += 1
            right -= 1

Типичные ошибки

  • Цикл j с условием nums[j] < nums[i]. Он останавливается на числе, которое равно nums[i]. На [1, 5, 1] код меняет местами 1 и 1, разворачивает хвост, и в nums остаётся [1, 1, 5] вместо [5, 1, 1].
  • Цикл i с условием nums[i] > nums[i + 1]. На [1, 5, 5] он останавливается на паре 5, 5 с i = 1. В nums нет числа больше 5, поэтому j проходит 0 и становится отрицательным. Python считает отрицательный индекс с конца Array: при j = −1, −2 и −3 код снова читает nums[2], nums[1] и nums[0]. При j = −4 такого места нет, и код падает с IndexError. Верный ответ [5, 1, 5].
  • j = i + 1, то есть ближайшее число справа вместо самого правого большего. На [1, 3, 2] код ставит 3 на место 0 и даёт [3, 2, 1], а верный ответ [2, 1, 3].
