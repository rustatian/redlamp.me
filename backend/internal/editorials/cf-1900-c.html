В пятом наборе примера буква L ведёт из корня в вершину 5. Там написано R, но справа ребёнка нет, поэтому Кексич останется в вершине 5. На каждом следующем ходу он снова прочитает R и останется в вершине 5. Если до листа Кексич сделал ход на месте, он повторит этот ход и уже не дойдёт до листа. Если заменить R в вершине 5 на U, он будет повторять путь 1 → 5 → 1. При первом ходе вверх Кексич вернётся к родителю, из которого только что спустился. Буквы во время пути не меняются, поэтому родитель снова отправит его к тому же ребёнку. Значит, до первого листа успешный путь идёт только вниз.

На пути 1 → 5 → 4 → 7 все три шага идут влево. Оставим L в корне и заменим R на L в вершинах 5 и 4. После этих двух замен Кексич дойдёт до листа 7. На пути к выбранному листу проверяем букву перед каждым спуском. Если она указывает в другую сторону, замена необходима, ведь другого пути к этому листу нет. Если исправить все такие буквы, Кексич пройдёт по этому пути до конца.

При подъёме от листа 7 к его родителю 4 учитываем ту же замену R на L в вершине 4 для спуска к 7. Пусть левые рёбра образуют цепочку 1 → 2 → 3, а у каждой её вершины справа есть лист. Если считать замены отдельно от каждого листа к корню, придётся пройти 1 + 2 + 3 = 6 рёбер с учётом повторов. Если увеличить число вершин с 6 до 12, у такой цепочки будет шесть правых листьев, а сумма вырастет до 1 + 2 + 3 + 4 + 5 + 6 = 21. При n = 300 000 такая цепочка с 150 000 листьями потребует 1 + 2 + … + 150 000 = 11 250 075 000 шагов. Чтобы уложиться в 2,5 секунды, пришлось бы проходить больше 4,5 миллиарда рёбер в секунду. В Tree листьев не больше n, а от листа до корня не больше n − 1 рёбер. Поэтому на все подъёмы уйдёт не больше n · (n − 1) шагов. Оценка времени O(n2) означает, что в худшем случае число шагов Brute Force растёт не быстрее квадрата числа вершин.

Решение 1. Dynamic Programming от листьев к корню

В пятом наборе вершина 7 уже лист, поэтому dp[7] = 0 даже при букве U. В dp[v] храним наименьшее число замен, чтобы из v спуститься до листа. Из вершины 4 можно спуститься только влево, в 7. Замена в вершине 4 даёт dp[4] = 1 + dp[7] = 1.

Для каждого ребёнка складываем цену первого шага и готовый ответ ребёнка. Букву вершины 4 берём из s[3], а пару детей (7, 0) из children[4]. Позиции в строке начинаются с нуля. Перед чтением детей кладём в children[0] пару (0, 0), поэтому индекс каждой следующей пары равен номеру вершины. Для левого шага сравнение s[v - 1] != "L" даёт при сложении 0, если буква подходит, и 1 в остальных случаях.

У вершины 2 буква L, а оба ребёнка уже листья. Путь к левому листу 3 стоит 0 + 0. Для шага вправо сравнение s[1] != "R" даёт при сложении 1, поэтому путь к листу 6 стоит 1 + 0. Для правого шага используем сравнение s[v - 1] != "R". Левый путь дешевле, поэтому dp[2] = 0. Любой спуск из вершины начинается с одного из её детей. Поэтому берём минимум только по существующим детям.

В третьем наборе две вершины, и у корня left = 0, right = 2. Ноль означает, что левого ребёнка нет. Ветка if left выполняется только при ненулевом left, поэтому best пока равно 2. Для шага к правому листу меняем L на R, поэтому best = min(2, 0 + 1) = 1. До начала пути меняем не больше одной буквы на каждый спуск, а спусков не больше n − 1. Поэтому начальное значение best = n больше цены любого пути.

В пятом наборе начинаем BFS со списка order = [1]. Цикл добавляет детей вершины 1 и получает [1, 5, 2]. Затем он читает добавленную вершину 5 и дописывает её ребёнка 4, получая [1, 5, 2, 4]. В Python цикл for v in order читает и те элементы, которые добавили в конец списка во время обхода. Полный порядок BFS в этом наборе равен [1, 5, 2, 4, 3, 6, 7]. Если пройти order с конца, ответ каждого ребёнка будет готов до расчёта для родителя. На рисунке знак «?» стоит у вершин, для которых ещё предстоит выбрать путь.

В корне путь влево стоит 0 + dp[5] = 2, а вправо стоит 1 + dp[2] = 1. Минимум dp[1] = 1 даёт замена буквы в корне с L на R.

import sys


def minimum_changes(s, children):
    order = [1]
    for v in order:
        left, right = children[v]
        if left:
            order.append(left)
        if right:
            order.append(right)

    n = len(s)
    dp = [0] * (n + 1)
    for v in reversed(order):
        left, right = children[v]
        if not left and not right:
            continue
        best = n
        if left:
            best = dp[left] + (s[v - 1] != "L")
        if right:
            best = min(best, dp[right] + (s[v - 1] != "R"))
        dp[v] = best
    return dp[1]


read = sys.stdin.readline
answers = []
for _ in range(int(read())):
    n = int(read())
    s = read().strip()
    children = [(0, 0)]
    for _ in range(n):
        children.append(tuple(map(int, read().split())))
    answers.append(str(minimum_changes(s, children)))
print("\n".join(answers))

В пятом наборе BFS посещает 7 вершин, а обратный проход обрабатывает те же 7 вершин. Каждый из двух проходов посещает вершину один раз и проверяет до двух детей. Время: O(n) в худшем случае на набор. В этом наборе order хранит 7 номеров, а dp содержит 8 ячеек с учётом ячейки 0. Дополнительная память: O(n) в худшем случае на набор для order и dp. Строка s и список children хранят входные данные одного набора и занимают O(n) памяти. Если взять третий набор примера четыре раза, answers сохранит четыре строки «1». Пока они в списке, join вставляет между четырьмя цифрами три перевода строки и получает 4 + 3 = 7 символов. При n ≤ 300 000 для записи числа замен хватает шести цифр. Пусть t - число наборов, а nmax - число вершин в самом большом наборе. Список answers и строка для печати вместе занимают O(t) памяти, а join и print тратят O(t) времени. В каждом наборе хотя бы две вершины, поэтому 2t ≤ Σ n, где Σ n - общее число вершин. Вся программа в худшем случае тратит O(Σ n) времени и занимает O(nmax + t) памяти.

Решение 2. DFS от корня

На пути 1 → 2 → 6 нужны два правых шага. В вершинах 1 и 2 написано L, поэтому число замен вдоль пути растёт от 0 до 1, затем до 2. В Stack кладём пары (v, cost), где cost считает замены от корня до v. Начинаем с (1, 0). У ребёнка один родитель, поэтому цену пути к ребёнку получим, прибавив к cost цену шага из этого родителя.

В корне кладём в Stack сначала правого ребёнка, затем левого и получаем stack = [(2, 1), (5, 0)]. Вызов stack.pop() берёт последнюю пару (5, 0), поэтому DFS идёт влево. Когда DFS доходит до листа 7 с ценой 2, в Stack остаётся пара (2, 1). Из вершины 2 DFS доходит сначала до листа 3 с ценой 1, затем до листа 6 с ценой 2.

Останавливаться на первом листе рано. В каждом листе обновляем минимум best. В Stack попадает каждый ребёнок, поэтому DFS посетит все листья. Когда Stack опустеет, в best будет наименьшая цена среди всех листьев.

import sys


def minimum_changes(s, children):
    best = len(s)
    stack = [(1, 0)]
    while stack:
        v, cost = stack.pop()
        left, right = children[v]
        if not left and not right:
            best = min(best, cost)
        if right:
            stack.append((right, cost + (s[v - 1] != "R")))
        if left:
            stack.append((left, cost + (s[v - 1] != "L")))
    return best


read = sys.stdin.readline
answers = []
for _ in range(int(read())):
    n = int(read())
    s = read().strip()
    children = [(0, 0)]
    for _ in range(n):
        children.append(tuple(map(int, read().split())))
    answers.append(str(minimum_changes(s, children)))
print("\n".join(answers))

В пятом наборе цикл извлекает из stack по одной паре для каждой из 7 вершин, всего 7 пар. Цикл обрабатывает каждую из n вершин один раз. Время: O(n) в худшем случае на набор. На цепочке с листьями справа DFS спускается влево, а правые дети остаются в Stack. При n = 6 в нём одновременно лежат три пары. Корень кладём в Stack один раз в начале, а каждую другую вершину добавляем при обработке её единственного родителя. Поэтому в Stack одновременно лежит не больше n пар. Дополнительная память: O(n) в худшем случае на набор для Stack. При повторах третьего набора примера в Stack лежит не больше одной пары, а список ответов растёт. Программа хранит входные данные и выводит ответы так же, как в решении 1. Поэтому для всех наборов в худшем случае нужно O(Σ n) времени и O(nmax + t) памяти.
