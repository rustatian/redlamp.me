Если p лодок везут по два человека, а остальные по одному, то всего лодок n − p, где n - число людей. В примере 2 n = 4, и двоих везёт одна лодка: 4 − 1 = 3. Поэтому нужно составить как можно больше пар с суммой весов не больше limit.

Решение 1. Greedy и Two Pointers

Возьмите пример 2: people = [3, 2, 2, 1], limit = 3. После Sorting получаем [1, 2, 2, 3]. Указатель l стоит на самом лёгком человеке, указатель r на самом тяжёлом.

Сумма 1 + 3 = 4 больше 3. Остальные люди весят не меньше 1, поэтому человек весом 3 с любым из них даёт в сумме не меньше 4. В любой рассадке он едет один. Код делает r -= 1, лодок стало 1.

Теперь сумма 1 + 2 = 3 не больше 3. Самый лёгкий и самый тяжёлый из оставшихся едут вместе: l += 1 и r -= 1, лодок 2. Остался один человек весом 2, теперь l = r = 1. Он едет один, лодок 3.

Правило. Сумма people[l] + people[r] не больше limit: самый лёгкий едет вместе с самым тяжёлым. Иначе самый тяжёлый едет один. Каждый шаг даёт одну новую лодку.

Когда пара помещается, осталось проверить, что самого тяжёлого выгодно сажать именно с самым лёгким. Возьмите people = [1, 2, 3, 4] и limit = 6. Код сажает 4 с 1. Пусть другая рассадка везёт 4 с 2, а 1 с 3. Поменяйте местами людей весом 1 и 2: получатся лодки (4, 1) и (2, 3). Сумма 4 + 1 = 5 не больше 6. Сумма 2 + 3 не больше 2 + 4 = 6, потому что 3 не тяжелее 4. Лодок столько же, 2.

С любыми весами то же самое. Пусть самый лёгкий весит x, а самый тяжёлый h. Если x + h > limit, то сумма h с любым другим весом не меньше x + h, и самый тяжёлый едет один в любой рассадке. Если x + h ≤ limit, пусть в лучшей рассадке самый тяжёлый едет с человеком весом y, а самый лёгкий с человеком весом z. После обмена x и y вторая лодка везёт y + z. Это не больше y + h, потому что z ≤ h, а y + h ≤ limit, потому что h и y ехали вместе. Если самый тяжёлый ехал один, пересадите к нему самого лёгкого. Бывший сосед z самого лёгкого, если он был, остаётся один, и лодок не больше. Если самый лёгкий ехал один, поменяйте местами x и y: лодок снова не больше. Значит, ход кода не увеличивает ответ. После хода люди от l до r снова отсортированы, и для них работает то же правило.

При l = r остался один человек, и код складывает его вес с ним же. В тесте people = [1, 1, 1, 1, 1], limit = 3 в конце l = r = 2 и 1 + 1 = 2 ≤ 3, поэтому код делает l += 1. Ответ от этого не портится: человек один, лодка одна, а после хода l > r, и цикл заканчивается. Ответ 3.

class Solution:
    def numRescueBoats(self, people: list[int], limit: int) -> int:
        people.sort()
        l, r = 0, len(people) - 1
        boats = 0
        while l <= r:
            if people[l] + people[r] <= limit:
                l += 1  # самый лёгкий едет с самым тяжёлым
            r -= 1  # самый тяжёлый едет в этой лодке
            boats += 1
        return boats

Время: n - длина people. Sorting занимает O(n log n). Каждый шаг цикла делает r -= 1 и даёт одну лодку, поэтому шагов столько, сколько лодок, и не больше n. Всего O(n log n) в худшем случае. Дополнительная память: l, r и boats занимают O(1). Python list.sort() меняет сам people, но в худшем случае берёт O(n) рабочей памяти. Итого O(n).

Решение 2. Counting Sort и Two Pointers по весам

Веса целые, от 1 до limit, а limit ≤ 3 · 104. Поэтому Sorting можно заменить подсчётом: cnt[w] - число людей весом w. В примере 2 cnt[1] = 1, cnt[2] = 2, cnt[3] = 1. Указатель hi идёт по весам вниз от limit, указатель lo вверх от 1. Оба пропускают веса, у которых cnt[w] = 0. left - число людей без лодки.

В примере 2 hi = 3 и lo = 1: 1 + 3 = 4 больше 3, человек весом 3 едет один. Затем hi идёт на вес 2, и 1 + 2 = 3 не больше 3: люди весом 1 и 2 едут вместе. Последний человек весом 2 едет один. Лодок 3, как в решении 1.

После цикла while cnt[hi] == 0 указатель hi стоит на весе самого тяжёлого из людей без лодки. После цикла while cnt[lo] == 0 указатель lo стоит на весе самого лёгкого. Люди только уходят из cnt, поэтому hi не нужно идти вверх, а lo вниз. Решение 2 сажает в лодки людей тех же весов, что и решение 1, и ответ тот же.

class Solution:
    def numRescueBoats(self, people: list[int], limit: int) -> int:
        cnt = [0] * (limit + 1)  # cnt[w]: сколько людей весят w
        for w in people:
            cnt[w] += 1
        lo, hi = 1, limit
        left = len(people)
        boats = 0
        while left > 0:
            while cnt[hi] == 0:
                hi -= 1
            cnt[hi] -= 1  # самый тяжёлый садится в новую лодку
            left -= 1
            boats += 1
            if left > 0:
                while cnt[lo] == 0:
                    lo += 1
                if lo + hi <= limit:
                    cnt[lo] -= 1  # самый лёгкий едет с ним
                    left -= 1
        return boats

Время: цикл for делает n прибавлений к cnt. hi только уменьшается, lo только растёт, и оба остаются между 1 и limit: вместе меньше 2 · limit шагов. Каждый шаг цикла while left > 0 даёт одну лодку, их не больше n. Всего O(n + limit) в худшем случае. Дополнительная память: cnt хранит limit + 1 чисел, при limit = 3 · 104 это 30 001 число: O(limit). Вход people не меняется.

Что не подходит

Без Sorting самого лёгкого и самого тяжёлого приходится искать просмотром всех людей без лодки. Если все весят limit, каждый едет один, и просмотров n + (n − 1) + ... + 1 = n(n + 1)/2: O(n²). При n = 5 · 104 это 1 250 025 000 просмотров: слишком долго.

Типичные ошибки

  • Цикл while l < r. В примере 2 после пары (1, 2) остаётся l = r = 1, и человек весом 2 не получает лодку. Ответ 2 вместо 3.
  • Решение 1 без Sorting. На входе примера 2 [3, 2, 2, 1] код получает суммы 4, 5, 5 и 6, все больше 3. Ответ 4 вместо 3.
  • Пара из двух самых лёгких. Для people = [1, 2, 3, 4] и limit = 5 получаются лодки (1, 2), (3) и (4), потому что 3 + 4 = 7 больше 5. Верный ответ 2: (1, 4) и (2, 3).
  • Ответ как сумма весов, делённая на limit. В примере 3 сумма 3 + 5 + 3 + 4 = 15, и 15 / 5 = 3. Верный ответ 4, потому что любая пара весит не меньше 3 + 3 = 6.
  • Решение 2 без проверки if left > 0. Для people = [1] и limit = 1 цикл while cnt[lo] == 0 доходит до lo = 2, а в cnt только места 0 и 1: IndexError.
