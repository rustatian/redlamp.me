Для каждого заклинания нужно посчитать зелья, которые с ним дают произведение не меньше success. Brute Force проверяет все пары: n заклинаний на m зелий, где n - длина spells, а m - длина potions. В примере 1 это 3 · 5 = 15 произведений. При n = m = 105 это 1010 произведений: слишком долго.

Решение 1. Sorting и Binary Search

Возьмём пример 1: spells = [5, 1, 3], potions = [1, 2, 3, 4, 5], success = 7. Заклинание силы 3 с зельем силы 2 даёт 3 · 2 = 6, это меньше 7. С зельем силы 3 получается 3 · 3 = 9, это не меньше 7. Значит, этому заклинанию нужно зелье силы не меньше 3. Это число называется need.

Условие 3 · p ≥ 7 то же, что p ≥ 7 / 3 = 2,33... Сила p - целое число, поэтому наименьшее p равно 3. Значит, need - это 7 / 3, округлённое вверх. Деление // в Python округляет вниз: 7 // 3 = 2. Поэтому need = (success + spell - 1) // spell. Для 7 и 3 это (7 + 3 − 1) // 3 = 9 // 3 = 3.

Прибавка spell - 1 округляет вверх, только если есть остаток. Для делителя 3 остаток бывает 0, 1 или 2, а прибавка равна 2. Число 6 = 2 · 3 + 0: остаток 0, после прибавки 0 + 2 = 2 новой тройки нет, (6 + 2) // 3 = 2. Число 7 = 2 · 3 + 1: остаток 1, после прибавки 1 + 2 = 3 есть ещё одна тройка, (7 + 2) // 3 = 3. Число 8 = 2 · 3 + 2: остаток 2, после прибавки 2 + 2 = 4 тоже есть ещё одна тройка, (8 + 2) // 3 = 3. Для любого делителя d остаток r от 1 до d − 1 после прибавки d − 1 становится не меньше d, но меньше 2d, и частное растёт ровно на 1. При r = 0 сумма равна d − 1, это меньше d, и частное не меняется.

Если зелье силы 3 подходит, то подходит и зелье силы 4: 3 · 4 = 12 не меньше 7. Зелье силы 2 не подходит, и зелье силы 1 тоже: 3 · 1 = 3 меньше 7. Поэтому в упорядоченном ordered = [1, 2, 3, 4, 5] проверка ordered[i] >= need идёт «нет, нет, да, да, да». Первое «да» стоит в индексе 2: это Lower Bound, bisect_left(ordered, 3) = 2. Подходят зелья с индексами 2, 3 и 4. Их число: m − 2 = 5 − 2 = 3.

Правило. Пусть ordered - это potions после Sorting. Для заклинания spell нужная сила зелья need = (success + spell - 1) // spell, а подходящих зелий m - bisect_left(ordered, need).

Sorting меняет порядок зелий, но ответ - это число зелий, а не их номера. Порядок заклинаний код не меняет: ответ для spells[i] стоит на месте i.

Теперь пример 2: spells = [3, 1, 2], potions = [8, 5, 8], success = 16. После Sorting ordered = [5, 8, 8], m = 3. Для заклинания 3: need = (16 + 3 − 1) // 3 = 6, bisect_left даёт 1, ответ 3 − 1 = 2. Для заклинания 1: need = 16, это больше всех зелий, bisect_left даёт 3 = m, ответ 0. Для заклинания 2: need = 8, bisect_left даёт 1, ответ 2. Зелья силы 8 подходят, потому что 2 · 8 = 16 равно success.

from bisect import bisect_left


class Solution:
    def successfulPairs(self, spells: list[int], potions: list[int], success: int) -> list[int]:
        ordered = sorted(potions)
        m = len(ordered)
        pairs = []
        for spell in spells:
            need = (success + spell - 1) // spell  # наименьшая сила зелья с успешной парой
            pairs.append(m - bisect_left(ordered, need))
        return pairs

Время: Sorting делает O(m log m) сравнений. Каждый из n поисков делает не больше ⌊log₂ m⌋ + 1 проверок, где ⌊x⌋ - это x, округлённое вниз. Для m = 105 число log₂ m равно примерно 16,6, поэтому проверок не больше 16 + 1 = 17. Всего O(m log m + n log m) в худшем случае. При n = 105 поиски делают не больше 17 · 105 = 1 700 000 проверок, а Brute Force 1010 произведений. Дополнительная память: ordered хранит m чисел, остальное занимает O(1): всего O(m) в худшем случае. Вход и ответ pairs не считаем.

Решение 2. Sorting и Two Pointers

Binary Search можно заменить указателем j по зельям, если идти по заклинаниям от слабого к сильному. Это Two Pointers: второй указатель стоит на текущем заклинании. Снова пример 1, ordered = [1, 2, 3, 4, 5]. Заклинание 1 не подходит ни к одному зелью. Заклинание 3 подходит к зельям силы 3, 4 и 5. Заклинание 5 подходит к зельям силы 2, 3, 4 и 5. Подходящие зелья стоят в конце ordered, и у более сильного заклинания их не меньше. Зелье силы 3 подошло к заклинанию 3, значит, оно подходит и к заклинанию 5: 5 · 3 = 15 не меньше 3 · 3 = 9.

Указатель j стоит на начале подходящих зелий: подходят ordered[j:]. Сначала j = m: ordered[m:] пуст, код ещё не нашёл подходящих зелий. Код проверяет самое сильное зелье вне этого конца, ordered[j - 1]. Если произведение не меньше success, зелье подходит, и код делает j -= 1. Иначе ответ готов: pairs[i] = m - j. Зелья левее тоже не подходят. Для заклинания 3 зелье силы 1 слабее проверенного зелья силы 2, и 3 · 1 = 3 меньше 3 · 2 = 6. При j = 0 левее зелий нет: подходят все зелья, и цикл заканчивается.

Ответы нужно записать на места исходных заклинаний. Поэтому код упорядочивает не силы, а номера заклинаний: by_strength = sorted(range(len(spells)), key=lambda i: spells[i]). Запись key=lambda i: spells[i] говорит sorted сравнивать номер i по силе spells[i]: для spells = [5, 1, 3] номера 0, 1, 2 сравниваются по числам 5, 1, 3. Для примера 1 это [1, 2, 0]: сначала заклинание с номером 1 (сила 1), потом с номером 2 (сила 3), потом с номером 0 (сила 5).

Ход по примеру 1. Заклинание 1: 1 · 5 = 5 меньше 7, ответ 5 − 5 = 0. Заклинание 3: произведения 3 · 5, 3 · 4 и 3 · 3 не меньше 7, и j идёт от 5 до 2. Затем 3 · 2 = 6 меньше 7: ответ 5 − 2 = 3. Заклинание 5 начинает с j = 2: 5 · 2 = 10 не меньше 7, и j = 1. Затем 5 · 1 = 5 меньше 7: ответ 5 − 1 = 4. Зелья силы 3, 4 и 5 код не проверяет заново.

class Solution:
    def successfulPairs(self, spells: list[int], potions: list[int], success: int) -> list[int]:
        ordered = sorted(potions)
        m = len(ordered)
        by_strength = sorted(range(len(spells)), key=lambda i: spells[i])
        pairs = [0] * len(spells)
        j = m  # зелья ordered[j:] дают успешную пару с текущим заклинанием
        for i in by_strength:
            while j > 0 and spells[i] * ordered[j - 1] >= success:
                j -= 1
            pairs[i] = m - j
        return pairs

Время: Sorting занимает O(m log m) для зелий и O(n log n) для заклинаний. Указатель j начинает с m и только уменьшается, поэтому j -= 1 выполняется не больше m раз. Каждая проверка while ведёт к шагу j -= 1 или заканчивает цикл одного заклинания: шагов не больше m, концов цикла ровно n, проверок не больше n + m. В примере 1 это 7 проверок: 4 шага и 3 конца цикла. При n = m = 105 это не больше 2 · 105 проверок. Всего O(n log n + m log m) в худшем случае. Дополнительная память: ordered хранит m чисел, by_strength хранит n чисел: O(n + m) в худшем случае.

Типичные ошибки

  • need = success // spell без округления вверх. В примере 1 для заклинания 3 это 2, bisect_left(ordered, 2) даёт 1, и ответ 5 − 1 = 4 вместо 3. Зелье силы 2 не подходит: 3 · 2 = 6 меньше 7.
  • bisect_right вместо bisect_left. В примере 2 для заклинания 2 получается need = 8 и bisect_right([5, 8, 8], 8) = 3. Ответ 0 вместо 2: зелья силы 8 не считаются, хотя 2 · 8 = 16 равно success.
  • Binary Search без Sorting. В примере 2 bisect_left([8, 5, 8], 6) даёт 2, и ответ для заклинания 3 равен 3 − 2 = 1 вместо 2. Поиск работает только для упорядоченного Array.
  • Решение 2 с ответами в порядке Sorting. Для примера 1 получается [0, 3, 4] для заклинаний 1, 3, 5. Верный ответ [4, 0, 3].
