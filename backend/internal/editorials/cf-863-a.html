У числа 2010200 справа два нуля. Допишем два нуля слева и получим палиндром 002010200. Если убрать обе пары крайних нулей, останется палиндром 20102.

У числа 320 один ноль справа. Если нулей слева не добавлять, крайние цифры в 320 разные: 3 и 0. Если добавить два или больше нулей, как в 00320, на втором месте от каждого края стоят разные цифры: 0 и 2. Поэтому слева нужен ровно один ноль. В записи 0320 крайние нули совпадают, но внутри стоят разные цифры: 3 и 2. Поэтому ответ NO.

Удалим из записи все нули справа и получим остаток core. При x ≥ 1 остаток core непустой. Его первая цифра ненулевая, так как запись x не начинается с нуля. Последняя цифра core тоже ненулевая, так как все нули справа удалены. Если добавить слева меньше нулей, чем их было в конце, первая цифра core окажется в паре с нулём из конца числа. Если добавить слева больше нулей, чем их было в конце, лишний добавленный ноль окажется в паре с последней цифрой core. Поэтому в палиндроме группы нулей по краям должны иметь одинаковую длину. Сравним core с его обратной записью back. Если записи совпали, равные группы нулей по краям сохранят палиндром. Если нулей в конце нет, проверяем всё число.

Число 11 уже палиндром. Для 1100 допишем слева два нуля и получим палиндром 001100. У числа 1200 тоже два нуля в конце, но в записи 001200 внутри стоят разные цифры: 1 и 2.

digits = input()
core = digits.rstrip("0")
back = core[::-1]
print("YES" if core == back else "NO")

Пусть d обозначает число цифр на входе. При 1 ≤ x ≤ 109 это не более десяти цифр. Время: O(d) в худшем случае: чтение, удаление нулей, разворот и сравнение занимают линейное время. Дополнительная память: O(d) в худшем случае: кроме входной строки digits, программа хранит core и back длиной не более d каждый. Программа читает одно число, поэтому оценки для одного случая относятся и ко всей программе. Для вывода одного ответа с переводом строки нужно O(1) памяти.
