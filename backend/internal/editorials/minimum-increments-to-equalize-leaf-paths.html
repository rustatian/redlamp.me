В третьем примере у путей к листьям 2 и 3 счёт равен 8, а у пути к листу 4 он равен 10. Оба пути со счётом 8 проходят через вершину 1. Прибавим 2 к её стоимости и выровняем все три счёта одним изменением.

В цепочке 0 → 1 → 2 → 3 поиск наибольшей суммы от корня до листа посетит все четыре вершины. При поиске от вершины 1 снова посетим 1, 2 и 3. Обходы от всех вершин цепочки дадут 4 + 3 + 2 + 1 = 10 посещений. Так можно найти наибольшую сумму до листа для каждой вершины, каждый раз заново обходя её поддерево. Здесь четыре поиска, и каждый посещает не более четырёх вершин. Для n вершин получим n поисков, в каждом не более n посещений. Поэтому время в худшем случае равно O(n2). При n = 100 000 в цепочке получится 5 000 050 000 посещений.

Решение 1. Dynamic Programming на Tree

В третьем примере изменим только стоимость листа 3: пусть она равна 2. Теперь у вершины 1 дети дают суммы 1 и 2. Путь 1 → 3 уже даёт наибольшую сумму 4 + 2 = 6. Если прибавить 1 в листе 2, сумма на пути 1 → 2 тоже станет равна 6, а на пути 1 → 3 останется прежней. У корня сравниваем уже 6 и 7. Теперь прибавим 7 − 6 = 1 к стоимости вершины 1, и счёт каждого пути от корня станет равен 3 + 7 = 10.

Пусть best[v] хранит наибольшую исходную сумму от вершины v до листа под ней. У листа v единственный путь состоит из него самого, поэтому его сумма уже равна best[v] = cost[v]. У вершины с детьми обозначим через largest наибольшее из значений best[child]. Пусть в каждой ветви все пути от ребёнка child до листьев уже имеют сумму best[child]. Прибавка largest − best[child] к стоимости ребёнка доводит сумму каждого пути в его ветви до largest. Теперь у каждого пути от v до листа сумма равна cost[v] + largest = best[v]. Поэтому код добавляет к answer по единице за каждого ребёнка с меньшей суммой.

В нашем примере пути к листьям 2 и 3 расходятся только на последнем шаге. Чтобы сравнять их счета, придётся увеличить стоимость листа 2. У путей к листьям 3 и 4 общий только корень. После него путь 1 → 3 даёт исходную сумму 6, а лист 4 даёт 7. Прибавка в корне увеличит оба счёта поровну, а прибавка в листе 4 только увеличит разницу. Чтобы сравнять эти счета, придётся увеличить стоимость вершины 1 или 3. Путь из одного листа 2 и путь 1 → 3 не пересекаются, поэтому даже при конечном счёте больше 10 одной изменённой вершины не хватит.

Для каждого ребёнка с best[child] < largest выделим путь от него до листа, который даёт best[child]. Сравним его с путём, который даёт сумму largest от другого ребёнка до листа. Пути к этим листьям совпадают от корня до родителя этих детей включительно. Прибавка в любой вершине этого участка увеличивает оба счёта поровну. Прибавка после общего участка на пути с большей суммой увеличивает разницу. Значит, на каждом выделенном пути нужно изменить хотя бы одну вершину.

На выделенном пути каждый шаг ведёт к ребёнку с наибольшим best. У каждой вершины, кроме корня, один родитель. Если бы два выделенных пути встретились, то путь, который начинается выше, прошёл бы через начало второго пути. Для этого пришлось бы спуститься к ребёнку с меньшим best, ведь именно с такого ребёнка начинается второй путь. Значит, выделенные пути не пересекаются и каждому нужна отдельная прибавка. Код насчитал answer таких путей, и одной прибавки в начале каждого хватает.

В примере вершину 1 нужно обработать после 2 и 3, но до 0. Код строит список order от корня, записывая ребёнка после родителя, а затем читает список с конца. При обходе parent[v] указывает, какого соседа нужно пропустить, чтобы не вернуться назад.

class Solution:
    def minIncrease(self, n: int, edges: list[list[int]], cost: list[int]) -> int:
        neighbors = [[] for _ in range(n)]
        for a, b in edges:
            neighbors[a].append(b)
            neighbors[b].append(a)

        parent = [-1] * n
        order = [0]
        for v in order:
            for child in neighbors[v]:
                if child != parent[v]:
                    parent[child] = v
                    order.append(child)

        best = cost.copy()
        answer = 0
        for v in reversed(order):
            largest = 0
            for child in neighbors[v]:
                if child != parent[v]:
                    largest = max(largest, best[child])

            for child in neighbors[v]:
                if child != parent[v] and best[child] < largest:
                    answer += 1
            best[v] += largest

        return answer

Время: в третьем примере четыре ребра дают восемь записей о соседях, по две на ребро. В обоих решениях в списках соседей всего 2 · (n − 1) записей. Первое решение просматривает каждый список три раза, поэтому время в худшем случае равно O(n). Дополнительная память: в примере код хранит пять списков соседей, а в parent, order и best по пять записей. В общем случае на каждую вершину приходится один список соседей и по одной записи в каждом из трёх других списков. Вместе с записями о соседях это O(n) памяти в худшем случае.

Решение 2. Greedy по счёту листа

В изменённом примере на пути 0 → 1 → 3 сначала получаем score[1] = 4 + 3 = 7, затем score[3] = 2 + 7 = 9. При переходе к ребёнку код прибавляет к его исходной стоимости сумму от корня до родителя. У листа 4 исходный счёт равен 10, а у листа 2 он равен 8.

Рассмотрим листья от большего счёта к меньшему. На пути от листа 4 к корню поставим метку 10. Этот путь не входит в поддерево вершины 1, поэтому там ещё нет меток и first_score[1] = 0. При подъёме от листа 3 пометим вершины 3 и 1 числом 9 и встретим метку 10 у корня. Разницу 10 − 9 = 1 прибавим в вершине 1, общей для путей к листьям 2 и 3. Теперь у пути к листу 2 счёт равен 9, а у пути к листу 3 он равен 10.

При подъёме от листа 2 остановимся в вершине 1, потому что её метка 9 уже не равна нулю. Прибавим в листе 2 оставшуюся разницу 10 − 9 = 1. Все три счёта теперь равны 10, а ответ снова 2.

По условию cost[i] ≥ 1, поэтому счёт каждого листа положителен. После записи такого счёта проверка first_score[v] == 0 больше не даст записать метку в ту же вершину. Код идёт только к родителю, поэтому метки в поддереве v могут появиться только при подъёме от листа этого поддерева. При первом таком подъёме на пути до v включительно ещё нет меток, поэтому код доходит до v. Листья идут по убыванию счёта, поэтому код записывает в first_score[v] наибольший исходный счёт среди листьев этого поддерева.

В примере метки различаются на концах двух рёбер: 0 → 1 и 1 → 2. На ребре 1 → 2 метка ребёнка равна score[1] + best[2] = 7 + 1 = 8. Метка родителя равна score[1] + largest = 7 + 2 = 9. Для любого ребра к best[child] и largest прибавляем одну и ту же сумму от корня до родителя. Такая прибавка сохраняет порядок, поэтому метка ребёнка меньше метки родителя ровно тогда, когда best[child] < largest.

На ребре 1 → 2 метка 9 у родителя уже стояла, когда лист 2 получил метку 8. В исходном третьем примере оба листа 3 и 2 имеют счёт 8. При подъёме от листа 2 код доходит до вершины 1, где лист 3 уже поставил метку 8. Метка останавливает подъём, но проверка 8 > 8 ложна, поэтому answer остаётся равным 1. Если метка родителя больше метки ребёнка, её поставил лист с большим счётом, который код обработал раньше. Поэтому подъём, который впервые помечает ребёнка, останавливается у его уже помеченного родителя v. Здесь условие first_score[v] > score[leaf] считает то же необходимое увеличение, что и сравнение ветвей в первом решении. При следующем подъёме снизу код остановится у ребёнка или раньше, поэтому каждое ребро с разными метками он учитывает ровно один раз.

Во втором примере у корня 0 только один сосед, его ребёнок 1. У листа 2 тоже один сосед, его родитель 1. Проверка v != 0 исключает корень. У остальных вершин len(neighbors[v]) == 1 означает, что есть только родитель и нет детей.

class Solution:
    def minIncrease(self, n: int, edges: list[list[int]], cost: list[int]) -> int:
        neighbors = [[] for _ in range(n)]
        for a, b in edges:
            neighbors[a].append(b)
            neighbors[b].append(a)

        parent = [-1] * n
        score = cost.copy()
        stack = [0]
        leaves = []
        while stack:
            v = stack.pop()
            if v != 0 and len(neighbors[v]) == 1:
                leaves.append(v)
            for child in neighbors[v]:
                if child != parent[v]:
                    parent[child] = v
                    score[child] += score[v]
                    stack.append(child)

        leaves.sort(key=lambda leaf: score[leaf], reverse=True)
        first_score = [0] * n
        answer = 0
        for leaf in leaves:
            v = leaf
            while v != -1 and first_score[v] == 0:
                first_score[v] = score[leaf]
                v = parent[v]
            if v != -1 and first_score[v] > score[leaf]:
                answer += 1

        return answer

Время: O(n log n) в худшем случае из-за Sorting листьев. Все подъёмы вместе ставят по одной метке на вершину. Для каждого листа код ещё раз проверяет условие while при остановке и один раз проверяет if после цикла. Листьев не больше n, поэтому все подъёмы занимают O(n) времени. Дополнительная память: в исходном третьем примере в parent, score и first_score по пять записей, а в leaves три листа. В Stack одновременно бывает до трёх вершин. Для листьев 4, 3 и 2 вызов sort хранит значения score[leaf], равные 10, 8 и 8. Для n вершин в каждом из первых трёх списков по n записей. В leaves и в Stack не больше чем по n вершин, так как в каждый из них вершина попадает не более одного раза. Sorting хранит по одной записи для исходного счёта каждого листа. Для примера запишем счета из двух частей [8, 8] и [10] по убыванию во временный список [10, 8, 8]. В нём 2 + 1 = 3 записи, по одной на лист. При объединении частей sort достаточно двух временных записей на лист, одной для его номера и одной для счёта. Листьев не больше n, поэтому для объединения хватает O(n) временной памяти. Вместе со списками соседей это O(n) памяти в худшем случае.
