В первом примере пути к листьям 2 и 4 начинаются одинаково: 0 → 1. Если считать доход заново для каждого листа, ворота в общей части пути придётся проверить несколько раз. Такой Brute Force занимает O(n · h) времени в худшем случае, где h обозначает наибольшую глубину. При n = 100 000 построим цепочку из 50 000 вершин от корня и присоединим к её концу ещё 50 000 листьев. Тогда число проверок ворот на путях Алисы равно 50 001 · 50 000 = 2 500 050 000.

Решение 1. BFS от корня

До вершины 3 Алиса идёт по пути 0 → 1 → 3 и тратит 2 секунды. В Tree путь от корня к каждой вершине единственный, поэтому время прихода Алисы равно глубине вершины.

Цикл for v in order начинает с order = [0] и добавляет в список соседа 1. Затем цикл берёт из списка вершину 1, пропускает её родителя 0 и добавляет соседей 2 и 3. Теперь order = [0, 1, 2, 3], а для вершины 2 уже известны parent[2] = 1 и depth[2] = 2. BFS читает список order с начала и добавляет детей в конец. У вершины v все соседи, кроме её родителя, лежат на один уровень глубже. Поэтому для каждого такого соседа u записываем parent[u] = v и depth[u] = depth[v] + 1.

Боб поднимается по родителям: 3 → 1 → 0. Запишем в bob_time время его прихода в каждую из этих вершин: 0, 1 и 2 соответственно. Для вершин 2 и 4 остаётся начальное значение n = 5. Оно больше любой глубины: путь в Tree из n вершин содержит не более n − 1 рёбер.

У ворот 1 оба оказываются через секунду, и Алиса получает 4 / 2 = 2. Ворота 3 Боб уже открыл, поэтому Алиса платит 0. В вершине 4 Алисе достаётся вся награда 6. Если Алиса выберет путь через v, её долю в этой вершине определяет сравнение depth[v] и bob_time[v]. Например, при общей плате 6 каждый платит 3: все значения amount чётные, и операция // 2 делит их без остатка.

В вершине 1 доход уже учитывает плату в корне: income[1] = −2 + 2 = 0. Для детей вершины 1 получаем income[2] = income[1] + 2 = 2 и income[3] = income[1] + 0 = 0. В листе 4 получаем income[4] = income[3] + 6 = 6. Чтобы получить сумму до ребёнка, прибавляем к его доле готовую сумму родителя: в order родитель стоит раньше.

Из корня 0 Алиса делает первый шаг к его единственному соседу 1. В вершину 2 она приходит из 1 и останавливается, потому что других соседей у 2 нет. Листья узнаём по одному соседу, исключив корень: в этом примере подходят только 2 и 4, а больший доход равен 6.

class Solution:
    def mostProfitablePath(self, edges: list[list[int]], bob: int, amount: list[int]) -> int:
        n = len(amount)
        adj = [[] for _ in range(n)]
        for a, b in edges:
            adj[a].append(b)
            adj[b].append(a)

        parent = [-1] * n
        depth = [0] * n
        order = [0]
        for v in order:
            for u in adj[v]:
                if u != parent[v]:
                    parent[u] = v
                    depth[u] = depth[v] + 1
                    order.append(u)

        bob_time = [n] * n
        v = bob
        time = 0
        while v != -1:
            bob_time[v] = time
            v = parent[v]
            time += 1

        income = [0] * n
        for v in order:
            if depth[v] < bob_time[v]:
                income[v] = amount[v]
            elif depth[v] == bob_time[v]:
                income[v] = amount[v] // 2
            if v != 0:
                income[v] += income[parent[v]]

        return max(income[v] for v in range(1, n) if len(adj[v]) == 1)

Время: O(n) в худшем случае. Каждое ребро встречается в списках соседей дважды, а Боб проходит не больше n вершин. Дополнительная память: O(n) в худшем случае для списков соседей, порядка обхода, родителей, глубин, времени Боба и сумм.

Решение 2. Dynamic Programming от листьев

Из вершины 3 можно пойти только к листу 4, поэтому доход на оставшейся части пути равен 0 + 6 = 6. Лист 2 приносит награду 2, и на этом путь заканчивается. Пусть best[v] хранит наибольший доход от ворот v до листа, включая сами ворота v. Из вершины 1 можно пойти к ребёнку 2 или 3, поэтому best[1] = 2 + max(2, 6) = 8. Спускаясь из внутренней вершины к листу, Алиса выбирает ровно одного ребёнка, поэтому берём наибольшее из значений best[u]. Если читать order с конца, то при обработке родителя результаты всех его детей уже известны.

Время Боба тоже можно считать снизу вверх: он начинает в вершине 3 и через секунду приходит к её родителю. Сначала ставим 0 в вершине bob и n во всех остальных. Возьмём времена детей вершины 1 из решения 1. Сначала проверяем ребёнка 2 и сохраняем начальное значение bob_time[1] = min(5, 5 + 1) = 5. Затем проверяем ребёнка 3 и получаем bob_time[1] = min(5, 0 + 1) = 1. После проверки всех детей сравниваем время Боба с глубиной вершины 1. Оба значения равны 1, поэтому в best[1] записываем долю Алисы из решения 1 (2). Затем прибавляем к этой доле доход от лучшего продолжения.

Если Боб не начал в v, то попасть туда он может только от одного из её детей за один шаг. Берём меньшее из bob_time[v] и bob_time[u] + 1 для каждого ребёнка. Там, куда Боб не заходит, сравнение с n + 1 сохраняет n. В корне учитываем плату за ворота 0 и получаем ответ: best[0] = −2 + 8 = 6.

class Solution:
    def mostProfitablePath(self, edges: list[list[int]], bob: int, amount: list[int]) -> int:
        n = len(amount)
        adj = [[] for _ in range(n)]
        for a, b in edges:
            adj[a].append(b)
            adj[b].append(a)

        order = [(0, -1, 0)]
        for v, parent, depth in order:
            for u in adj[v]:
                if u != parent:
                    order.append((u, v, depth + 1))

        bob_time = [n] * n
        bob_time[bob] = 0
        best = [0] * n
        for v, parent, depth in reversed(order):
            children = [u for u in adj[v] if u != parent]
            for u in children:
                bob_time[v] = min(bob_time[v], bob_time[u] + 1)

            if depth < bob_time[v]:
                best[v] = amount[v]
            elif depth == bob_time[v]:
                best[v] = amount[v] // 2
            if children:
                best[v] += max(best[u] for u in children)

        return best[0]

Время: O(n) в худшем случае. При выборе продолжения каждый ребёнок участвует в расчёте только у своего родителя. Дополнительная память: O(n) в худшем случае для соседей, записей обхода, времени Боба, сумм и списка детей текущей вершины.

Почему нельзя остановиться раньше

На пути 0 → 1 → 2 при bob = 1 и amount = [2, 4, -10] у Алисы в корне есть 2. Хотя у корня один сосед, Алиса обязана идти дальше. Ворота 1 уже открыты, а в листе 2 нужно заплатить 10. Поэтому ответ 2 + 0 − 10 = −8: даже убыточное продолжение нужно учесть.
