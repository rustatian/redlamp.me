Нужен индекс вершины: числа, которое больше обоих соседей. Время должно быть O(log n), где n - длина arr.

Brute Force ищет наибольшее число и для этого читает все n чисел. Для arr = [0, 10, 5, 2] это 4 чтения, наибольшее число 10 стоит в индексе 1. При n = 105 это 105 чтений, то есть O(n).

Решение 1. Binary Search

Сравним каждое число с правым соседом. Для arr = [0, 10, 5, 2] условие arr[i] > arr[i + 1] при i = 0, 1, 2 даёт «нет, да, да»: 0 > 10 нет, 10 > 5 да, 5 > 2 да. Вершина - индекс 1, первое «да».

То же верно для любой горы. Слева от вершины числа растут: arr[i] < arr[i + 1], ответ «нет». От вершины вправо числа убывают: ответ «да». Для [1, 3, 6, 9, 7, 4, 2] условие при i = 0, 1, ..., 5 идёт «нет, нет, нет, да, да, да»: первое «да» стоит в индексе 3, там число 9.

Все «нет» стоят перед всеми «да», поэтому первое «да» ищет Binary Search. Пара lo и hi - отрезок индексов, в котором стоит вершина. Сначала lo = 0 и hi = n - 1. Проверка идёт на mid = (lo + hi) // 2. Для lo = 2 и hi = 3 получаем mid = (2 + 3) // 2 = 2: даже для двух соседних индексов mid меньше hi. Так же и для любых lo < hi: индекс mid меньше hi, то есть не больше n − 2, и arr[mid + 1] существует.

Возьмём [1, 3, 6, 9, 7, 4, 2], n = 7. Сначала lo = 0, hi = 6, mid = 3. Число arr[3] = 9 больше arr[4] = 7: «да». Вершина стоит в mid или левее: hi = 3. Теперь mid = 1, и arr[1] = 3 меньше arr[2] = 6: «нет». Условия в индексах 0 и 1 - «нет», поэтому вершина правее: lo = 2. Теперь mid = 2, и arr[2] = 6 меньше arr[3] = 9: «нет», lo = 3. Тогда lo = hi = 3: остался один индекс, ответ 3 после 3 проверок.

Правило. Инвариант: вершина лежит в отрезке [lo, hi]. «Да» в mid значит, что вершина в mid или левее: hi = mid. «Нет» в mid значит, что вершина правее mid: lo = mid + 1. Цикл идёт, пока lo < hi.

class Solution:
    def peakIndexInMountainArray(self, arr: list[int]) -> int:
        lo, hi = 0, len(arr) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] > arr[mid + 1]:
                hi = mid  # «да»: вершина в mid или левее
            else:
                lo = mid + 1  # «нет»: mid левее вершины
        return lo

В примере длина отрезка идёт так: 7, 4, 2, 1. Это 3 проверки. При s = 7 и mid = 3 «да» оставляет [0, 3], 4 индекса, а «нет» оставляет [4, 6], 3 индекса. Одна проверка оставляет не больше (s + 1) // 2 индексов, где s - длина отрезка. Для n = 105 и вершины в индексе 1 длина идёт так: 100 000, 50 000, 25 000, 12 500, 6 250, 3 125, 1 563, 782, 391, 196, 98, 49, 25, 13, 7, 4, 2, 1. Это 17 проверок.

Время: O(log n) в худшем случае: не больше 17 проверок для n = 105, потому что 216 = 65 536 < 105 ≤ 131 072 = 217. Дополнительная память: O(1) в худшем случае: числа lo, hi и mid. Вход arr и ответ не считаем.

Другой способ: Ternary Search

Ternary Search берёт две точки m1 < m2 и отбрасывает треть отрезка. Для [1, 3, 6, 9, 7, 4, 2] точки m1 = 0 + 6 // 3 = 2 и m2 = 6 − 6 // 3 = 4: arr[2] = 6 меньше arr[4] = 7. Если бы вершина стояла в m1 или левее, числа от m1 вправо убывали бы, и arr[m1] было бы больше arr[m2]. Значит, вершина правее m1, и индексы 0, 1, 2 отброшены.

Каждый шаг оставляет около 2/3 отрезка, поэтому для n = 105 нужно около 28 шагов: 105 · (2/3)28 ≈ 1,2. Это больше 17 проверок Binary Search, а каждый шаг и каждая проверка читают по 2 числа.

Типичные ошибки

  • hi = len(arr) вместо hi = len(arr) - 1. Для [0, 1, 2, 3, 0]: lo = 0, hi = 5, mid = 2, «нет», lo = 3. Потом mid = 4, и чтение arr[5] даёт IndexError.
  • lo = mid вместо lo = mid + 1. Для [0, 1, 0]: mid = 1, «да», hi = 1. Потом lo = 0, mid = 0, «нет», и lo = mid = 0: отрезок тот же, цикл не заканчивается.
  • while lo <= hi из главы 1 вместо while lo < hi. Для [0, 1, 0]: mid = 1, «да», hi = 1. Потом mid = 0, «нет», lo = 1. При lo = hi = 1 проверка снова даёт «да» и hi = mid = 1: отрезок тот же, цикл не заканчивается.
  • hi = mid - 1 вместо hi = mid. Для [0, 10, 5, 2]: mid = 1, «да», и hi = 0. Вершина с индексом 1 вышла из отрезка, ответ 0 вместо 1. Вершина сама может стоять в mid.
  • Сравнение с последним числом, arr[mid] > arr[-1], вместо соседа. Для [1, 3, 6, 9, 7, 4, 2] условие идёт «нет, да, да, да, да, да, нет»: это не «нет, ..., да», и Binary Search на нём даёт ответ 1 вместо 3.
