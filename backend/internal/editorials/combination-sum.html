Нужно выписать каждый набор чисел с суммой target один раз. Порядок записи не важен: [2, 2, 3] и [3, 2, 2] это один набор.

Решение 1. Backtracking

Возьмите пример 1: candidates = [2, 3, 6, 7], target = 7. Набор [2, 2, 3] можно записать тремя способами: [2, 2, 3], [2, 3, 2] и [3, 2, 2]. Оставим одну запись, где каждое следующее число не меньше предыдущего. Для этого набора это [2, 2, 3].

Сначала код делает Sorting для candidates. Функция dfs(start, remain) работает с одним общим list по имени path. В path лежат уже выбранные числа, а remain равно target минус их сумма. Цикл перебирает индексы i от start: кладёт candidates[i] в path, вызывает dfs(i, remain - candidates[i]) и убирает число через path.pop().

Следующий вызов получает i, а не i + 1. Поэтому число можно взять снова, и получается [2, 2, 3]. Индексы меньше i следующий вызов не берёт. После числа 3 с индексом 1 следующий вызов начинает с индекса 1, поэтому число 2 с индексом 0 после 3 не встанет. Записей [2, 3, 2] и [3, 2, 2] не будет.

Когда remain равно 0, сумма path равна target. Вызов сохраняет копию path в res и возвращается.

Теперь Pruning. Возьмите path = [2, 2, 2]: сумма 6, remain = 1. Число 2 больше 1: с ним сумма станет 8, больше 7. Числа, которые можно добавить потом, только увеличат сумму: каждое из них не меньше 2. Числа 3, 6 и 7 стоят после Sorting правее и тоже больше 1. Ни одно из них не даёт ответ, поэтому цикл заканчивается через break.

Рисунок показывает все 10 вызовов на примере 1. Окно на строке candidates отмечает числа, которые проверяет цикл. Выделены числа, которые цикл кладёт в path. В кадре с ответом выделен весь path: его копия идёт в res. Ответы появляются в порядке [2, 2, 3], [7].

Возьмите [2, 2, 3]. Вызов dfs(0, 7) кладёт 2 и вызывает dfs(0, 5). Тот кладёт 2 и вызывает dfs(0, 3), а он кладёт 3 и вызывает dfs(1, 0). Последний вызов сохраняет [2, 2, 3]. На каждом шаге нужное число не больше remain, поэтому break его не пропускает. Числа в path идут в порядке candidates, поэтому другого пути к этому набору нет. Так каждый набор появляется ровно один раз.

Без Pruning цикл кладёт каждое число и делает вызов, а новый вызов сразу возвращается при remain < 0. В примере 1 это 28 вызовов вместо 10. При candidates = [5, 6, ..., 34] (30 чисел) и target = 35 ответов 149, а разница больше: 18 472 вызова без Pruning и 999 с ним.

class Solution:
    def combinationSum(self, candidates: list[int], target: int) -> list[list[int]]:
        candidates.sort()  # Sorting: числа по возрастанию
        res = []
        path = []

        def dfs(start, remain):
            if remain == 0:
                res.append(path[:])  # копия: path ещё изменится
                return
            for i in range(start, len(candidates)):
                if candidates[i] > remain:
                    break  # дальше числа ещё больше
                path.append(candidates[i])
                dfs(i, remain - candidates[i])  # i: это число можно взять снова
                path.pop()

        dfs(0, target)
        return res

Время: пусть m - длина candidates, V - число вызовов dfs, R - число ответов, S - сумма их длин. Sorting стоит O(m log m). Каждый шаг цикла делает вызов dfs или break. Вызовов из цикла V − 1, потому что первый вызов dfs(0, target) идёт не из цикла. Break бывает не больше одного раза в вызове. Значит, шагов цикла не больше 2V − 1. В примере 1 это 9 шагов с вызовом и 7 с break, всего 16. Копии path[:] переписывают S чисел: в примере 1 это 3 + 1 = 4. Время O(m log m + V + S) в худшем случае. При candidates = [5, 6, ..., 34] и target = 35: V = 999, шагов цикла 1847, R = 149, S = 573.

При candidates = [4, 6, 8] и target = 39 ответов нет: сумма чётных чисел чётная, а 39 нечётное. Но вызовов 94: V может быть намного больше R.

Дополнительная память: каждое число path не меньше min(candidates), а сумма path не больше target. Поэтому в path не больше d = target // min(candidates) чисел, а Call Stack держит до d + 1 вызовов dfs. В примере 1 d = 7 // 2 = 3: path = [2, 2, 2] и 4 вызова. При candidates = [2] и target = 40 получаем d = 20 и 21 вызов. Sorting в Python берёт до O(m) памяти. Всего O(m + d). Ответ, R list с S числами, считаем отдельно.

Типичные ошибки

  • dfs(i + 1, ...) вместо dfs(i, ...). Тогда число нельзя взять второй раз. Для примера 1 ответ [[7]] теряет [2, 2, 3].
  • Цикл от 0 вместо start. Тогда после 3 снова можно взять 2. Для примера 1 выйдет 4 list: [2, 2, 3], [2, 3, 2], [3, 2, 2] и [7].
  • break без Sorting. Возьмите candidates = [8, 7, 4, 3], target = 11. Вызов с path = [8] получает remain = 3 и начинает с 8 > 3: break, и до числа 3 цикл не доходит. Ответ пустой, хотя наборов три: [3, 4, 4], [3, 8] и [4, 7].
  • res.append(path) без копии. Тогда все элементы res это один и тот же list path. В конце он пустой, и для примера 1 ответ равен [[], []].
  • Нет ни break, ни возврата при remain < 0. Тогда в примере 1 вызов dfs(0, 1) кладёт 2 и вызывает dfs(0, -1), тот снова кладёт 2, и remain уменьшается без конца. Python останавливает код с RecursionError.
