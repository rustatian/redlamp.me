Шаги из условия не зависят от чисел на картах. Они только открывают верхнюю карту и переносят следующую карту вниз. Поэтому места колоды открываются в одном и том же порядке при любых числах. Пусть n - число карт. Пронумеруйте места сверху вниз: 0, 1, ..., n − 1. Когда порядок мест известен, остаётся положить на эти места карты по возрастанию.

Решение 1. Sorting и Simulation на Deque

Положите номера мест в Deque places и выполните с ними шаги из условия. В примере 1 n = 7, и сначала places = [0, 1, 2, 3, 4, 5, 6]. Первый popleft() достаёт место 0: оно открывается первым. Второй popleft() и append переносят место 1 вниз: places = [2, 3, 4, 5, 6, 1]. Потом открывается место 2, а место 3 уходит вниз: places = [4, 5, 6, 1, 3].

После Sorting карты идут так: 2, 3, 5, 7, 11, 13, 17. Карта 2 должна открыться первой, поэтому она лежит на месте 0. Карта 3 должна открыться второй, поэтому она лежит на месте 2. Цикл берёт карты по возрастанию и записывает каждую карту в answer на место, которое открывается сейчас. Последняя карта 17 ложится на место 5, и получается answer = [2, 13, 3, 11, 5, 17, 7].

Сравните places с колодой из пояснения примера 1. После первого шага places = [2, 3, 4, 5, 6, 1], а колода [3, 11, 5, 17, 7, 13]. Это answer[2], answer[3], answer[4], answer[5], answer[6] и answer[1]. Шаги из условия двигают карты колоды answer так же, как Simulation двигает номера в places: карта с места i стоит там, где стоит номер i. Значит, карты открываются с мест 0, 2, 4, 6, 3, 1, 5, а на этих местах лежат 2, 3, 5, 7, 11, 13, 17.

from collections import deque


class Solution:
    def deckRevealedIncreasing(self, deck: list[int]) -> list[int]:
        n = len(deck)
        places = deque(range(n))  # номера мест колоды, место 0 - верх
        answer = [0] * n
        for card in sorted(deck):
            answer[places.popleft()] = card  # это место открывается сейчас
            if places:
                places.append(places.popleft())  # это место уходит вниз колоды
        return answer

Время: sorted(deck) занимает O(n log n). Создание places и answer занимает O(n). Цикл делает n шагов. Каждый шаг записывает одну карту в answer. Последний шаг ничего не переносит вниз. Всего n записей, 2n − 1 вызовов popleft и n − 1 вызовов append, каждый вызов за O(1). В примере 1 это 7 записей, 13 вызовов popleft и 6 вызовов append. Итого O(n log n) в худшем случае. Дополнительная память: places хранит не больше n номеров, а sorted(deck) делает копию из n чисел: O(n). Ответ answer из n чисел считаем отдельно.

Simulation на list с pop(0) вместо Deque даёт верный ответ, но каждый pop(0) сдвигает все остальные номера на одну позицию. Для n = 4 два вызова pop(0) на каждом шаге сдвигают 3 + 2, 2 + 1 и 1 + 0 номеров, а последний вызов ничего не сдвигает: всего 9 = 3² сдвигов. За всю Simulation это (n − 1)² сдвигов, время O(n²). При n = 1000 это 998 001 сдвиг, а Deque делает 1999 вызовов popleft без сдвигов. Такое решение тоже проходит тесты этой задачи, но число сдвигов растёт как n², а число вызовов popleft только как n.

Решение 2. Обратная Simulation на Deque

Шаги можно пройти назад, от последней открытой карты к первой. В пояснении примера 1 шаг вперёд берёт колоду [11, 17, 13], открывает 11 и переносит 17 вниз: остаётся [13, 17]. Шаг назад отменяет эти два действия в обратном порядке. Сначала нижняя карта 17 возвращается наверх: [17, 13]. Потом открытая карта 11 ложится наверх: [11, 17, 13]. С любой колодой шаг назад делает то же: нижняя карта возвращается наверх, потом открытая карта ложится наверх. Каждый шаг назад даёт колоду, которая была перед открытием его карты. Карты открываются по возрастанию, поэтому назад они идут по убыванию.

В примере 1 последней открывается 17: d = [17]. Перед ней открылась 13. Нижняя карта 17 уходит наверх, и d = [17] не меняется. Затем 13 ложится наверх: d = [13, 17]. Шаг для карты 11 даёт d = [11, 17, 13], как в абзаце выше. После шага для карты 2 получается начальная колода [2, 13, 3, 11, 5, 17, 7].

Код проверяет if d. Пустой d значит, что карта открывается последней. Перед последним шагом в колоде одна карта, и переносить вниз нечего. Поэтому для карты 17 шаг назад только кладёт её в d.

from collections import deque


class Solution:
    def deckRevealedIncreasing(self, deck: list[int]) -> list[int]:
        d = deque()
        for card in sorted(deck, reverse=True):
            if d:
                d.appendleft(d.pop())  # нижняя карта возвращается наверх
            d.appendleft(card)  # открытая карта возвращается наверх
        return list(d)

Время: sorted(deck, reverse=True) занимает O(n log n). Цикл делает n шагов: n вызовов appendleft для карт, n − 1 вызовов pop и n − 1 вызовов appendleft для нижних карт. Каждый вызов стоит O(1). list(d) копирует n чисел за O(n). Итого O(n log n) в худшем случае. Дополнительная память: sorted(deck, reverse=True) делает копию из n чисел, а d хранит не больше n чисел: O(n). Список list(d) - это ответ.

Что не подходит

Brute Force берёт порядки колоды один за другим и для каждого выполняет шаги из условия. Порядков n! (Factorial), и в худшем случае верный порядок идёт последним. Для каждого порядка шаги делают 2n − 1 вызовов popleft, как в решении 1, поэтому время O(n · n!). При n = 1000 число 1000! имеет 2568 цифр: слишком долго.

Типичные ошибки

  • Частая догадка: положить меньшие карты по порядку на места 0, 2, 4 и так далее, а остальные карты на места 1, 3, 5 и так далее. Для deck = [1, 2, 3, 4] это даёт верный ответ [1, 3, 2, 4]. Но в примере 1 получается [2, 11, 3, 13, 5, 17, 7], и карты открываются в порядке 2, 3, 5, 7, 13, 11, 17. После места 6 вниз уходит место 1, поэтому второй круг начинается с места 3.
  • Нет проверки if places. На последнем шаге первый popleft() забирает последнее место, и второй popleft() вызывает IndexError. Так падает каждый тест, например deck = [1].
  • В решении 2 сначала карта ложится наверх, а потом нижняя карта уходит наверх. Тогда сверху оказывается не та карта. В примере 1 получается [7, 2, 13, 3, 11, 5, 17], и первой открывается 7.
