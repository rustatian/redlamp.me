В цепочке 0 → 1 ← 2 ← 3 рассмотрим пути к столице без учёта стрелок. Из города 1 надо пройти одну дорогу, из города 2 две, а из города 3 три. Если пройти каждый путь отдельно, получится 1 + 2 + 3 = 6 переходов. На каждом из трёх путей отметим дорогу 0 → 1, потому что по ней надо ехать против стрелки. Для ответа считаем разные отмеченные дороги, поэтому здесь нужен один разворот. При n = 50 000 в такой цепочке будет n(n − 1)/2 переходов, то есть 1 249 975 000. Такой подсчёт занимает O(n2) времени в худшем случае.

Решение 1. BFS от столицы

В первом примере у столицы две дороги: 0 → 1 и 4 → 0. При обходе из 0 в 1 мы идём по стрелке, а из 0 в 4 против стрелки. Жителям нужен путь в обратную сторону, поэтому дорогу 0 → 1 надо развернуть, а 4 → 0 можно оставить.

Для дороги 0 → 1 запишем пару (1, 1) в adj[0] и пару (0, 0) в adj[1]. Первое число в паре указывает соседа, второе служит флагом: 1 при переходе по исходной стрелке, 0 при переходе против неё. Благодаря двум записям BFS может пройти по дороге в обе стороны.

После обхода соседей столицы в Deque стоят города 1 и 4. BFS берёт город 1 из начала Deque и добавляет его нового соседа 3 в конец. Так BFS продлевает путь 0 → 1 на одну дорогу и получает путь 0 → 1 → 3. В обратном порядке получается 3 → 1 → 0, и другого пути к столице в Tree нет. Когда BFS впервые находит neighbor из city, единственный путь от neighbor к столице начинается с шага в city. Каждую дорогу с флагом 1 на таком переходе придётся развернуть. Этих разворотов достаточно: теперь каждый переход по стрелке сокращает оставшийся путь до столицы на одну дорогу.

В changes прибавили по единице за дороги 0 → 1, 1 → 3 и 4 → 5, поэтому ответ равен 3. При переходе из 0 в 1 BFS ставит seen[1] = True. Позже при просмотре adj[3] BFS видит эту отметку и пропускает переход в 1. BFS отмечает каждого нового соседа перед добавлением в Deque, поэтому учитывает флаг каждой дороги только один раз.

from collections import deque


class Solution:
    def minReorder(self, n: int, connections: list[list[int]]) -> int:
        adj = [[] for _ in range(n)]
        for a, b in connections:
            adj[a].append((b, 1))
            adj[b].append((a, 0))

        seen = [False] * n
        seen[0] = True
        queue = deque([0])
        changes = 0
        while queue:
            city = queue.popleft()
            for neighbor, flag in adj[city]:
                if seen[neighbor]:
                    continue
                seen[neighbor] = True
                changes += flag
                queue.append(neighbor)
        return changes

Время: O(n) в худшем случае. При n = 6 в списках соседей 10 записей, в общем случае их 2(n − 1). Каждую запись обход читает один раз. Дополнительная память: O(n) в худшем случае для списков соседей, отметок seen и Deque.

Решение 2. Stack для удаления листьев по одному

Во втором примере у города 4 одна дорога, 3 → 4. Для выезда из 4 её надо развернуть. Путь из другого города к столице не проходит через 4, потому что для въезда и выезда нужны две разные дороги. Город с одной оставшейся дорогой называют листом. Если не учитывать стрелки, удаление любого листа, кроме столицы, сохраняет пути остальных городов к столице. Единственная дорога листа должна вести к соседу, если сам лист не столица. Удаляя такие листья, прибавляем единицу к changes, только если стрелка ведёт в лист.

У города 3 дороги с номерами 2 и 3 в списке connections, если считать с нуля. Сумма номеров равна 5. После удаления дороги № 3 остаётся номер 5 − 3 = 2. При этом число дорог degree[3] уменьшается с 2 до 1. Поэтому код добавляет город 3 в список листьев leaves и на следующем шаге берёт номер его дороги из road_sum[3]. Для каждого оставшегося города код хранит число его дорог в degree и сумму их номеров в road_sum. Когда у города остаётся одна дорога, сумма даёт её номер.

Последней остаётся дорога 1 → 0 с номером 0. Оба города теперь листья, но в leaves попадает только город 1. Два листа, соединённые дорогой, составляют всё оставшееся Tree, потому что ни у одного из них нет другой дороги. Один из них обязательно столица, ведь она остаётся в Tree при каждом удалении. Значит, соседа листа из leaves нельзя удалить раньше самого листа. Когда pop() вернёт лист, в road_sum[leaf] всё ещё будет номер его единственной дороги.

Во втором примере разворота требуют только 3 → 4 и 1 → 2, ответ равен 2. После этих разворотов из города 4 можно проехать до столицы по пути 4 → 3 → 2 → 1 → 0. Дорога каждого удалённого листа уже ведёт к его оставшемуся соседу. Когда у соседа появится путь к столице, жители листа тоже смогут им воспользоваться.

Если считать дороги без учёта стрелок, от города 3 до столицы их три, а от города 4 через 3 их четыре. После удаления города 4 самым дальним от столицы становится город 3. У самого дальнего города есть сосед на пути к столице. От любого другого соседа единственный путь к столице шёл бы через этот город и был бы на одну дорогу длиннее. Значит, пока в Tree есть дорога, у самого дальнего города всего один сосед и этот город можно удалить как лист. Поэтому удаление листьев закончится, когда останется только столица.

class Solution:
    def minReorder(self, n: int, connections: list[list[int]]) -> int:
        degree = [0] * n
        road_sum = [0] * n
        for i, (a, b) in enumerate(connections):
            degree[a] += 1
            degree[b] += 1
            road_sum[a] += i
            road_sum[b] += i

        leaves = [v for v in range(1, n) if degree[v] == 1]
        changes = 0
        while leaves:
            leaf = leaves.pop()
            i = road_sum[leaf]
            a, b = connections[i]
            if b == leaf:
                changes += 1
                neighbor = a
            else:
                neighbor = b
            degree[neighbor] -= 1
            road_sum[neighbor] -= i
            if neighbor != 0 and degree[neighbor] == 1:
                leaves.append(neighbor)
        return changes

Время: O(n) в худшем случае. Сначала код читает n − 1 дорог, затем находит первые листья среди n − 1 городов. Каждая из этих вершин попадает в leaves один раз, а при удалении код обновляет данные только у её соседа. Дополнительная память: O(n) в худшем случае. В degree и road_sum по n чисел, а в leaves одновременно не больше n − 1 городов.
