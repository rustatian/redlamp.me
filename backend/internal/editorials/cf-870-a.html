Brute Force по парам цифр

В первом примере цифры 2 и 5 дают два числа: 10 · 2 + 5 = 25 и 10 · 5 + 2 = 52. Общих цифр нет, поэтому одна цифра не подойдёт. Наименьшая возможная цифра десятков равна 2, а для единиц тогда нужна цифра из второго списка. Там наименьшая цифра равна 5, поэтому ответ равен 25.

Во втором примере цифра 1 есть в обоих списках. Она сама подходит и меньше любого двузначного числа. Число красиво ровно тогда, когда в нём есть цифра от 1 до 8, поэтому 90 не подходит.

Если в обоих списках стоит 4, одной четвёрки достаточно. Заменим 4 во втором списке на 7: теперь нужны обе цифры, и из чисел 47 и 74 выбираем 47. Поменяем списки местами: четвёрка теперь во втором списке, но в ответе она по-прежнему стоит в разряде десятков.

Переберём все пары (a, b), взяв по цифре из каждого списка. Если цифры совпали, запишем в candidate саму цифру. Если они разные, возьмём меньшее число из двух порядков записи. Так мы проверим каждую общую цифру и лучший порядок для каждой пары. Число из трёх цифр или длиннее брать незачем: любая пара уже даёт подходящее число короче. Начнём с best = 100: каждый кандидат меньше этого числа. После каждой пары в best останется наименьшее из проверенных чисел.

n, m = map(int, input().split())
first = list(map(int, input().split()))
second = list(map(int, input().split()))

best = 100
for a in first:
    for b in second:
        if a == b:
            candidate = a
        else:
            candidate = min(10 * a + b, 10 * b + a)
        best = min(best, candidate)
print(best)

Время: O(n · m) в худшем случае: для каждой из n цифр проверяем все m цифр второго списка. Дополнительная память: O(n + m) в худшем случае: два списка хранят n + m чисел. При чтении каждой строки Python временно хранит её текст и части после split(). Программа решает один случай, поэтому оценки для всего запуска те же. Единственный вызов print выводит не более двух цифр и перевод строки, для этого достаточно O(1) памяти.
