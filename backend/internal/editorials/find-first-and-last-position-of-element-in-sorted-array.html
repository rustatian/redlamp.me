Нужны индексы первого и последнего target в упорядоченном nums, а поиск должен занимать O(log n), где n - длина nums.

Brute Force проходит nums слева направо и сравнивает каждое число с target. Для nums = [5, 7, 7, 8, 8, 10] и target = 8 это 6 сравнений: восьмёрки стоят в индексах 3 и 4. При n = 105 это 100 000 сравнений, то есть O(n), а нужно O(log n). Brute Force не использует порядок чисел.

Решение 1. Binary Search

Возьмём тот же nums = [5, 7, 7, 8, 8, 10], n = 6, и target = 8. Условие nums[i] ≥ 8 в индексах 0, 1, 2, 3, 4, 5 даёт: нет, нет, нет, да, да, да. Первое «да» стоит в индексе 3: это первая восьмёрка. Условие nums[i] > 8 даёт: нет, нет, нет, нет, нет, да. Первое «да» стоит в индексе 5: это число 10, первое число больше 8. Array упорядочен, поэтому после первого «да» идут только «да»: оба условия идут «нет, ..., нет, да, ..., да». Восьмёрки стоят в индексах 3 и 4, и их 5 − 3 = 2.

Правило. Пусть left - первый индекс i с nums[i] ≥ target (Lower Bound), а right - первый индекс i с nums[i] > target (Upper Bound). Если такого индекса нет, он равен n. Чисел, равных target, ровно right - left. При left < right ответ [left, right - 1], иначе [-1, -1].

В примере 1 left = 3 и right = 5. Индексы 0, 1, 2 левее left: там 5, 7, 7, и это меньше 8. Индексы 5 и правее: там 10, и это больше 8. В индексах 3 и 4 условие nums[i] ≥ 8 даёт «да», а nums[i] > 8 даёт «нет». Значит, там стоят числа, равные 8, и ответ [3, 4].

Для target = 6 первое число не меньше 6 - это 7 в индексе 1. Первое число больше 6 - тоже 7 в индексе 1. Тогда left = right = 1, между ними нет индексов, и ответ [-1, -1]. Для target = 11 оба индекса равны n = 6, для пустого nums оба равны 0. Во всех этих случаях left = right и ответ [-1, -1].

Числа целые, поэтому nums[i] > 8 - то же самое, что nums[i] ≥ 9: в индексах 0, 1, 2, 3, 4, 5 оба условия дают нет, нет, нет, нет, нет, да. Значит, right - это left для target + 1. Одна функция lower(x) ищет первый индекс с nums[i] ≥ x, и тогда left = lower(target), а right = lower(target + 1).

Binary Search находит первое «да» без проверки каждого индекса. Возьмём lower(8). Ответ - одно из n + 1 = 7 мест от 0 до 6, поэтому lo = 0 и hi = 6: ответ лежит от lo до hi включительно. Середина mid = (0 + 6) // 2 = 3, и 8 ≥ 8: «да». Первое «да» стоит в mid или левее, поэтому hi = 3. Теперь mid = (0 + 3) // 2 = 1, и 7 ≥ 8: «нет». Первое «да» правее mid, поэтому lo = 2. Теперь mid = 2, и 7 ≥ 8: «нет», поэтому lo = 3. Теперь lo = hi = 3: ответ 3. Это 3 проверки.

Для lower(9) проверки идут так: mid = 3, 8 ≥ 9 «нет», lo = 4; mid = 5, 10 ≥ 9 «да», hi = 5; mid = 4, 8 ≥ 9 «нет», lo = 5. Ответ 5, это right.

Для target = 6 поиск lower(6) тоже делает 3 проверки: 8 ≥ 6 «да», 7 ≥ 6 «да», 5 ≥ 6 «нет», ответ 1. Поиск lower(7) идёт так же: 8 ≥ 7 «да», 7 ≥ 7 «да», 5 ≥ 7 «нет», ответ тоже 1.

class Solution:
    def searchRange(self, nums: list[int], target: int) -> list[int]:
        def lower(x):
            lo, hi = 0, len(nums)
            while lo < hi:
                mid = (lo + hi) // 2
                if nums[mid] >= x:
                    hi = mid  # mid может быть первым «да»
                else:
                    lo = mid + 1  # mid и числа левее него меньше x
            return lo

        left = lower(target)
        right = lower(target + 1)  # индекс первого числа больше target
        if left == right:
            return [-1, -1]
        return [left, right - 1]

Середина с «да» может быть первым «да», поэтому hi = mid, а не mid - 1. Середина с «нет» и числа левее неё меньше x, поэтому lo = mid + 1. Начальное hi = len(nums), а не len(nums) - 1, потому что ответ n возможен. Цикл не читает nums[n]: из lo < hi следует mid < hi, а hi не больше n. Например, при lo = 4 и hi = 6 середина mid = (4 + 6) // 2 = 5, и nums[6] не читается.

Время: каждая проверка оставляет не больше половины отрезка длины hi - lo: из длины 6 получается 3 или 2. Поэтому один вызов lower делает не больше ⌊log2 n⌋ + 1 проверок при n ≥ 1. Для n = 6 это 3, для n = 105 это 17. Два вызова дают не больше 2 · 17 = 34 проверок: O(log n) в худшем случае. Дополнительная память: числа lo, hi, mid, left и right, O(1) в худшем случае.

Готовая функция

Модуль bisect даёт те же два числа: bisect_left(nums, target) равно left, а bisect_right(nums, target) равно right. Для примера 1 это 3 и 5, для примера 2 это 1 и 1. Время каждого вызова O(log n) в худшем случае, дополнительная память O(1) в худшем случае.

Другой способ: одно число target и шаги в стороны

Binary Search находит любое число, равное target, а затем цикл идёт от него влево и вправо, пока числа равны target. Возьмём nums из 105 семёрок и target = 7. Этот поиск начинается с lo = 0 и hi = n - 1 = 99999. В первой середине (0 + 99999) // 2 = 49999 уже стоит 7. Цикл делает 49 999 шагов влево и 50 000 шагов вправо, всего 99 999 шагов: O(n) в худшем случае, а нужно O(log n). Шагов на 1 меньше, чем чисел, равных target. Больше всего их, когда все n чисел равны.

Типичные ошибки

  • return [left, right] без «- 1». Для примера 1 функция возвращает [3, 5], а нужен ответ [3, 4]: индекс 5 хранит число 10, а не восьмёрку.
  • Проверка «target нет» как left == len(nums). Для target = 6 в примере 2 получается left = right = 1, условие ложно, и функция возвращает [1, 0] вместо [-1, -1].
  • if nums[left] != target без проверки left < len(nums). Для nums = [1, 2, 3] и target = 4 получается left = 3, и nums[3] вызывает IndexError. Для пустого nums ошибка уже при nums[0].
  • hi = len(nums) - 1 в lower. Для nums = [5, 7, 7, 8, 8, 10] и target = 10 поиск lower(11) возвращает 5 вместо 6. Тогда left = right = 5, и функция возвращает [-1, -1] вместо [5, 5].
  • hi = mid - 1 при «да». Для примера 1 первая проверка lower(8) даёт hi = 2, и первая восьмёрка в индексе 3 выпадает из отрезка. Тогда lower(8) возвращает 2 вместо 3, lower(9) возвращает 4 вместо 5, и функция возвращает [2, 3] вместо [3, 4].
