Нужно найти окна из m = len(p) букв подряд в s, у которых счётчики букв такие же, как у p. Длина s равна n.

Пример 1: s = "cbaebabacd", p = "abc", m = 3. В окне "cba" по одной букве a, b, c, как в p. В окне "bae" есть e и нет c. Окно "cba" - Anagram строки p, окно "bae" - нет.

Brute Force считает счётчики каждого окна с нуля: n − m + 1 окон по m букв. Это O((n − m + 1) · m) чтений. Произведение самое большое при m около n / 2. При n = 3 · 104 и m = 15 000 это 15 001 · 15 000 = 225 015 000 чтений букв: слишком долго.

Решение 1. Sliding Window со счётчиками

Счётчик - это list из 26 чисел. Число на месте ord(c) - 97 показывает, сколько раз встретилась буква c. Здесь ord("a") = 97, поэтому a стоит на месте 0, b на месте 1, z на месте 25. need - счётчик p, have - счётчик текущего окна.

Для p = "abc" в need стоят единицы на местах 0, 1, 2, а остальные 23 числа равны 0. Окно с концом r занимает номера r − m + 1..r. При r = 2 это окно "cba" (номера 0..2): have == need, индекс 0 идёт в ответ.

При r = 3 окно "bae" (номера 1..3). От предыдущего окна оно отличается двумя буквами: c вышла, e вошла. Считать окно заново не нужно: уменьшите счётчик c на 1 и увеличьте счётчик e на 1. Теперь в have стоят a = 1, b = 1, e = 1. В need c = 1 и e = 0, поэтому have != need.

Правило. Когда конец окна сдвинулся на номер r, буква s[r] вошла в окно: её счётчик в have растёт на 1. Если r ≥ m, буква s[r - m] вышла из окна: её счётчик в have падает на 1. Окно подходит, когда r ≥ m − 1 и have == need. Тогда в ответ идёт номер r − m + 1.

В примере 1 have получает 10 прибавлений и 7 вычитаний, а код делает 8 сравнений have с need: при r = 2..9. Счётчики равны при r = 2 и r = 8. Это индексы 2 − 3 + 1 = 0 и 8 − 3 + 1 = 6, как в условии.

Шаг с r ≥ m заменяет в have одну старую букву окна на новую, как c на e при r = 3, поэтому have всегда равен счётчику окна. При r < m никакая буква не выходит: окно растёт от 1 до m букв, и первое окно из m букв получается при r = m − 1.

Если m > n, например s = "a" и p = "ab", то r доходит только до 0. Условие r ≥ m − 1 = 1 не выполняется, и ответ - пустой list.

class Solution:
    def findAnagrams(self, s: str, p: str) -> list[int]:
        n, m = len(s), len(p)
        need = [0] * 26
        have = [0] * 26
        for c in p:
            need[ord(c) - 97] += 1
        res = []
        for r in range(n):
            have[ord(s[r]) - 97] += 1  # буква s[r] вошла в окно
            if r >= m:
                have[ord(s[r - m]) - 97] -= 1  # буква s[r - m] вышла из окна
            if r >= m - 1 and have == need:
                res.append(r - m + 1)
        return res

Время: в худшем случае O(m + 26 · n): m прибавлений в need, затем n шагов. Каждый шаг делает не больше двух обновлений и не больше одного сравнения have с need из 26 чисел. Число 26 - размер алфавита, поэтому это O(n + m). При n = 3 · 104 сравнений чисел не больше 26 · 30 000 = 780 000. Дополнительная память: два list по 26 чисел и несколько чисел n, m, r: O(1) в худшем случае. Ответ res хранит до n − m + 1 номеров, его считаем отдельно.

Решение 2. Sliding Window со счётчиком совпадений

Решение 1 сравнивает до 26 чисел на каждом шаге. Решение 2 хранит одно число matches: сколько букв из 26 имеют have[x] == need[x]. Здесь have[x] - счётчик буквы x. В коде x - уже номер буквы: x = ord(s[r]) - 97. Окно подходит, когда matches == 26.

Пример 2: s = "abab", p = "ab", m = 2. В need a = 1 и b = 1, а в have пока одни нули. У 24 букв, которых нет в p, have == need == 0. Поэтому в начале matches = 26 − 2 = 24, где 2 - число разных букв p.

При r = 0 вошла a. До изменения have[a] = 0 и need[a] = 1: не равны, matches не меняется. После изменения have[a] = 1 = need[a], и matches = 25. При r = 1 вошла b, и matches = 26: индекс 0 идёт в ответ.

При r = 2 вошла a: до изменения have[a] = 1 = need[a], поэтому matches уменьшается с 26 до 25, а после изменения have[a] = 2 не равно need[a]. Потом вышла s[0] = a: have[a] стало 1, равно need[a], и matches = 26: индекс 1 идёт в ответ. При r = 3 вошла b и вышла s[1] = b: снова matches = 26, индекс 2 идёт в ответ. Ответ [0, 1, 2].

Правило. Перед изменением счётчика буквы x: если have[x] == need[x], уменьшите matches на 1. Измените have[x]. После изменения: если have[x] == need[x], увеличьте matches на 1.

Каждое изменение have[x] меняет равенство только для буквы x. Поэтому matches всегда равно числу букв с have == need, а matches == 26 означает have == need.

class Solution:
    def findAnagrams(self, s: str, p: str) -> list[int]:
        n, m = len(s), len(p)
        need = [0] * 26
        have = [0] * 26
        for c in p:
            need[ord(c) - 97] += 1
        matches = 26 - len(set(p))  # число букв, у которых have == need
        res = []
        for r in range(n):
            x = ord(s[r]) - 97
            if have[x] == need[x]:
                matches -= 1
            have[x] += 1
            if have[x] == need[x]:
                matches += 1
            if r >= m:
                y = ord(s[r - m]) - 97
                if have[y] == need[y]:
                    matches -= 1
                have[y] -= 1
                if have[y] == need[y]:
                    matches += 1
            if r >= m - 1 and matches == 26:
                res.append(r - m + 1)
        return res

Время: ожидаемое O(m + n): m прибавлений в need и n шагов. Шаг делает не больше двух обновлений счётчика и одну проверку matches == 26, и их число не зависит от n и m: сравнение 26 чисел не нужно. Построение set(p) читает m букв и хранит не больше 26 разных букв, поэтому тоже занимает ожидаемое O(m). Дополнительная память: два list по 26 чисел, set из не больше 26 букв и несколько чисел: O(1) в худшем случае. Ответ res считаем отдельно.

Типичные ошибки

  • Сравнить set букв окна и set(p). Для s = "abb" и p = "aab" оба set равны {a, b}, но в окне b = 2, а в p b = 1. Такой код вернёт [0], а ответ [].
  • Сравнить суммы кодов букв. Для s = "bc" и p = "ad" суммы равны: 98 + 99 = 197 = 97 + 100. Такой код вернёт [0], а ответ [].
  • Вычитать s[r - m] уже при r ≥ m − 1. При r = 2 и m = 3 это s[-1]: Python считает отрицательный номер с конца, и в примере 1 это буква d. Счётчик d в have становится −1, и такой код вернёт [] вместо [0, 6].
