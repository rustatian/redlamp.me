Окно - это k минут подряд, когда Миша не спит благодаря вам. Нужно найти окно, при котором Миша запишет больше всего теорем.

Две части ответа

Пример 1: n = 6, k = 3, a = [1, 3, 5, 2, 5, 4], t = [1, 1, 0, 1, 0, 0]. Минуты в коде нумеруются с 0.

Минуты с t = 1 Миша записывает сам, окно на них не влияет: a[0] + a[1] + a[3] = 1 + 3 + 2 = 6. Эту часть ответа обозначим base. Окно добавляет только теоремы минут сна, то есть минут с t = 0. Таких минут три: 2, 4 и 5, в них 5, 5 и 4 теоремы. Сумму теорем минут сна внутри окна обозначим gain. Ответ = base + наибольший gain.

Окон n − k + 1 = 6 − 3 + 1 = 4. Начало окна - его первая минута.

  • Начало 0, минуты 0..2: сон только в минуте 2, gain = 5, ответ 6 + 5 = 11.
  • Начало 1, минуты 1..3: сон только в минуте 2, gain = 5, ответ 6 + 5 = 11.
  • Начало 2, минуты 2..4: сон в минутах 2 и 4, gain = 5 + 5 = 10, ответ 6 + 10 = 16.
  • Начало 3, минуты 3..5: сон в минутах 4 и 5, gain = 5 + 4 = 9, ответ 6 + 9 = 15.

Наибольший gain равен 10, ответ 16. Начало 2 в коде - это начало третьей минуты в нумерации условия.

Brute Force считает gain каждого окна заново: k чтений на окно, (n − k + 1) · k чтений всего. При n = 105 и k = 5 · 104 это 50 001 · 50 000 = 2 500 050 000 чтений, около 2,5 · 109: слишком долго.

Решение 1. Sliding Window

Окна с началами 0 и 1 (минуты 0..2 и 1..3) имеют общие минуты 1 и 2. Окно сдвинулось на 1 минуту: минута 3 вошла, минута 0 вышла. У обеих минут t = 1, поэтому gain не меняется: 5 + 0 − 0 = 5.

Окно 2..4: вошла минута 4 с t = 0, вышла минута 1 с t = 1. gain = 5 + 5 − 0 = 10. Окно 3..5: вошла минута 5 с t = 0, вышла минута 2 с t = 0. gain = 10 + 4 − 5 = 9. Считать окно заново не нужно.

Правило. Окно с последней минутой r занимает минуты r − k + 1..r. При сдвиге минута r входит, а минута r − k выходит. Если у минуты t = 0, она меняет gain на +a[r] при входе и на −a[r − k] при выходе. Если t = 1, gain не меняется.

Первый цикл считает base и gain первого окна: в него входят минуты 0..k − 1, поэтому условие i < k. Второй цикл идёт по r от k до n − 1 и делает n − k сдвигов. Вместе с первым окном получается n − k + 1 окон: при n = 6 и k = 3 это 3 сдвига и 4 окна. При k = n сдвигов нет, окно одно.

import sys

n, k = map(int, sys.stdin.readline().split())
a = list(map(int, sys.stdin.readline().split()))
t = list(map(int, sys.stdin.readline().split()))
# base - теоремы минут с t = 1, gain - теоремы минут сна в окне из k минут
base = 0
gain = 0
for i in range(n):
    if t[i] == 1:
        base += a[i]
    elif i < k:
        gain += a[i]
best = gain
for r in range(k, n):
    # минута r входит в окно, минута r - k выходит
    if t[r] == 0:
        gain += a[r]
    if t[r - k] == 0:
        gain -= a[r - k]
    best = max(best, gain)
print(base + best)

Время: O(n) в худшем случае: первый цикл делает n шагов, второй n − k, вместе 2n − k ≤ 2n шагов. При n = 105 это не больше 2 · 105 шагов. Дополнительная память: O(1) в худшем случае: только числа base, gain, best, i и r. Списки a и t - вход, ответ - одно число, их считаем отдельно.

Решение 2. Prefix Sum

Заменим a[i] на 0 в минутах с t = 1: получится b = [0, 0, 5, 0, 5, 4]. Теперь gain окна - сумма b по минутам окна. Пусть p[j] - сумма первых j чисел b. При j = 0 чисел нет, поэтому p[0] = 0, и в p всего n + 1 = 7 чисел. Для примера p = [0, 0, 0, 5, 5, 10, 14]: p[3] = 0 + 0 + 5 = 5.

Окно из минут 2..4 имеет gain = p[5] − p[2] = 10 − 0 = 10. Это b[2] + b[3] + b[4] = 5 + 0 + 5: из p[5] вычли p[2], и остались числа b[2..4]. Здесь r = 5 - первая минута после окна. Окно из k минут занимает минуты r − k..r − 1, и его gain = p[r] − p[r − k]. Значения r от k до n дают n − k + 1 окон. В примере r = 3, 4, 5, 6, а gain равен 5, 5, 10, 9.

В коде b не хранится: для t = 1 получается p[i + 1] = p[i], для t = 0 получается p[i + 1] = p[i] + a[i].

import sys

n, k = map(int, sys.stdin.readline().split())
a = list(map(int, sys.stdin.readline().split()))
t = list(map(int, sys.stdin.readline().split()))
# base - теоремы минут с t = 1, p[j] - теоремы минут сна среди первых j минут
base = 0
p = [0] * (n + 1)
for i in range(n):
    if t[i] == 1:
        base += a[i]
        p[i + 1] = p[i]
    else:
        p[i + 1] = p[i] + a[i]
best = 0
for r in range(k, n + 1):
    # окно из минут r - k..r - 1 даёт p[r] - p[r - k]
    best = max(best, p[r] - p[r - k])
print(base + best)

Время: O(n) в худшем случае: n шагов для p и n − k + 1 разностей. Дополнительная память: O(n) в худшем случае: список p хранит n + 1 число, при n = 105 это 100 001 число. Решение 1 не хранит p. Зато p даёт gain любого отрезка минут, а не только окна длины k: для минут l..r − 1 это p[r] − p[l].

Типичные ошибки

  • gain считает все минуты окна, а не только минуты сна. Минуты с t = 1 уже в base, и окно считает их второй раз. В примере 1 окно 2..4 даёт a[2] + a[3] + a[4] = 5 + 2 + 5 = 12, и 6 + 12 = 18 вместо 16: теоремы минуты 3 посчитаны дважды.
  • Окно выбирают по наибольшей сумме a, не глядя на t. Для a = [10, 10, 3, 4, 1], t = [1, 1, 0, 0, 0] и k = 2 наибольшая сумма 20 у окна 0..1, но его gain равен 0. Окно 2..3 даёт gain = 3 + 4 = 7. Ответ 20 + 7 = 27, а не 20.
  • В решении 1 первое окно забыто: best = 0 вместо best = gain. Для a = [9, 9, 1, 1, 1], t = [0, 0, 1, 0, 0] и k = 2 первое окно даёт gain = 18 и ответ 1 + 18 = 19. Без него наибольший gain равен 9, ответ 10.
  • Последнее окно пропущено: цикл range(k, n - 1) делает на 1 сдвиг меньше. Для a = [1, 1, 1, 9, 9], t = [0, 0, 1, 0, 0] и k = 2 последнее окно 3..4 даёт gain = 18 и ответ 1 + 18 = 19. Без него наибольший gain равен 9, ответ 10.
