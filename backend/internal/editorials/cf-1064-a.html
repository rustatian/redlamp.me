Сколько сантиметров не хватает

Во втором примере длины даны в порядке 2, 5, 3. Запишем их по возрастанию и получим a = 2, b = 3, c = 5. Палочки длиной 2 и 3 см могут соединить концы палочки длиной 5 см только по прямой, потому что 2 + 3 = 5. Площадь при этом равна нулю. Если удлинить первую палочку на 1 см, получится треугольник со сторонами 3, 3 и 5.

Треугольник положительной площади получится ровно тогда, когда сумма любых двух длин больше третьей. После вызова sorted достаточно проверить a + b > c. Два других неравенства выполнены, потому что суммы c + a и c + b больше наибольшей длины c.

Решение 1. Формула для числа минут

В третьем примере у двух коротких палочек вместе 10 + 10 = 20 см, а у длинной палочки 100 см. Длинную палочку нельзя укоротить, поэтому двум другим нужна суммарная длина хотя бы 101 см. Даже если все 80 минут удлинять короткие палочки, в сумме получится только 100 см. За 81 минуту можно удлинить одну палочку с 10 до 91 см и получить нужную сумму 91 + 10 = 101.

Когда a + b ≤ c, первым двум палочкам в сумме не хватает c + 1 − (a + b) сантиметров. Каждый из этих сантиметров требует отдельной минуты. Удлиним первую палочку ровно на это число сантиметров. Её длина станет равна c + 1 − b и не превысит c, потому что b ≥ 1. Если выбрать вторую палочку, её новая длина c + 1 − a тоже не превысит c, потому что a ≥ 1. В обоих случаях сумма первых двух длин равна c + 1, и треугольник получается за это минимальное время.

Для длин 1, 3 и 5 нужны две минуты, для 2, 3 и 5 нужна одна, а для 3, 3 и 5 менять длины уже не нужно.

В первом примере 3 + 4 > 5, поэтому нужно 0 минут, хотя 5 + 1 − (3 + 4) = −1. В коде max(0, ...) даёт ноль, если сумма уже больше c, и число недостающих сантиметров в остальных случаях.

a, b, c = sorted(map(int, input().split()))
minutes = max(0, c + 1 - (a + b))
print(minutes)

Время: O(1) в худшем случае. Код упорядочивает всего три числа и вычисляет одну формулу. Поэтому верхняя граница числа операций не зависит от длин палочек. Дополнительная память: O(1) в худшем случае. Временные списки от split и sorted содержат по три элемента.

Решение 2. Brute Force

Для длин 2, 3 и 5 можно оставить последнюю палочку длиной 5 см и перебрать конечные длины x и y первых двух палочек. Например, за одну минуту можно получить пару x = 2, y = 4, для которой 2 + 4 > 5. В таблице показаны все 12 пар для этого примера.

Достаточно перебрать пары в границах a ≤ x ≤ c и b ≤ y ≤ c, ведь треугольник из первого решения укладывается в эти границы и требует наименьшего времени. При таких границах пара подходит, если x + y > c.

Пара x = y = 5 тоже подходит, но требует (5 − 2) + (5 − 3) = 5 минут. В начале best равно времени, за которое можно довести обе длины до c. Для каждой подходящей пары код считает затраты (x − a) + (y − b) и сохраняет наименьшее значение.

a, b, c = sorted(map(int, input().split()))
best = (c - a) + (c - b)
for x in range(a, c + 1):
    for y in range(b, c + 1):
        if x + y > c:
            best = min(best, (x - a) + (y - b))
print(best)

При a = b = 1 и c = 100 код проверит 100 · 100 = 10 000 пар. Значений x не больше c, и для каждого из них код проверяет не больше c значений y. Время: O(c2) в худшем случае, где c обозначает наибольшую исходную длину. Дополнительная память: O(1) в худшем случае. При чтении код создаёт те же два списка по три элемента, что и в первом решении. Во время перебора код хранит исходные длины a, b, c, текущую пару x, y и наименьшее найденное время best.
