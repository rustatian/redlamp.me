Ответ: все правильные String длины 2n из ( и ), каждая один раз. Порядок ответов не важен.

Решение 1. Backtracking с Pruning

При n = 3 String ответа имеет 6 символов, и на каждом месте стоит ( или ). Всех String из 6 таких символов 26 = 64, а правильных из них только 5. Backtracking строит String слева направо в list path и не продолжает префикс, который уже нельзя закончить правильно.

Возьмите префикс ()). В нём одна скобка ( и две скобки ). У второй ) нет своей ( левее, и символы правее этого не исправят. Префикс (((( при n = 3 тоже не годится: в нём уже 4 скобки (, а в правильной String их ровно 3.

Вызов dfs(opened, closed) знает, сколько скобок ( и ) уже стоит в path. Новый символ добавляется только после проверки:

( можно добавить, если opened < n. ) можно добавить, если closed < opened.

Поэтому в каждом префиксе path скобок ) не больше, чем скобок (, а скобок ( не больше n. При n = 3 полный path имеет длину 6. В нём opened не больше 3, closed не больше opened, а вместе их 6. Это возможно только при opened = closed = 3. Значит, каждая String, которую код кладёт в res, правильная.

Возьмите правильную String (())(). Каждый её префикс проходит проверку, поэтому dfs добавляет её символы один за другим и доходит до длины 6. Так dfs находит каждую правильную String. Повторов нет: две разные String различаются на первом месте, где у них разные символы, и на этом месте dfs идёт в разные ветки.

Рисунок показывает все 8 вызовов dfs при n = 2. После ответа (()) три path.pop() оставляют в path только (. Вызов с этим префиксом пробует вторую ветку, ), и строит второй ответ ()().

Возьмите префикс (() при n = 3: opened = 2, closed = 1. Добавьте 3 − 2 = 1 скобку (, затем 3 − 1 = 2 скобки ). Получится правильная String (()()). Так же можно закончить любой префикс, который прошёл проверки. Поэтому в поиске нет веток без ответа.

class Solution:
    def generateParenthesis(self, n: int) -> list[str]:
        res = []
        path = []

        def dfs(opened, closed):
            if len(path) == 2 * n:
                res.append(''.join(path))
                return
            if opened < n:  # ещё не все n скобок '(' стоят в path
                path.append('(')
                dfs(opened + 1, closed)
                path.pop()
            if closed < opened:  # у новой ')' есть своя '(' левее
                path.append(')')
                dfs(opened, closed + 1)
                path.pop()

        dfs(0, 0)
        return res

Время: пусть R это число ответов. Каждый вызов лежит на пути от dfs(0, 0) к какому-то ответу. На каждом таком пути 2n + 1 вызовов, по одному для каждой длины path от 0 до 2n. Поэтому вызовов не больше (2n + 1) · R. Вызов с длиной path меньше 2n делает не больше двух append и двух pop, а вызов с длиной 2n делает join из 2n символов. Всего O(nR). При n = 3 вызовов 22, и это не больше 7 · 5 = 35. При n = 8 ответов 1430, вызовов 6917, а join пишет 16 · 1430 = 22 880 символов. Перебор всех String из ( и ) при n = 8 проверяет 216 = 48 = 65 536 String, в каждой до 16 символов: O(n · 4n).

Дополнительная память: path хранит до 2n символов, а Call Stack держит до 2n + 1 вызовов dfs: O(n). Ответ занимает 2n · R символов. Код главы с s + '(' создаёт новую String в каждом вызове, и каждый вызов в Call Stack держит свою String. На пути к первому ответу это String длины 0, 1, ..., 2n: при n = 3 всего 0 + 1 + ... + 6 = 21 символ, O(n2). Общий path при n = 3 хранит не больше 6 символов.

Решение 2. Dynamic Programming

Возьмите правильную String (())(). Первая ( стоит на месте 0. Её пара это ) на месте 3: после префикса (()) впервые closed равно opened, 2 и 2. Внутри этой пары стоит (), после неё тоже (). Обе части правильные, в каждой 1 пара, а всего 1 + 1 + 1 = 3 пары.

Так устроена каждая правильная String с k парами: '(' + a + ')' + b. Здесь a это правильная String с i парами, b это правильная String с k − 1 − i парами, а i от 0 до k − 1. Первая ( и её пара ) не входят в a: в (()) по 2 скобки ( и ), а в a = () по 2 − 1 = 1 скобке. До места пары closed меньше opened, поэтому без первой ( в каждом префиксе a скобок ) не больше, чем скобок (. На месте пары closed = opened, поэтому в a поровну скобок ( и ), и a правильная. Часть b начинается при closed = opened, поэтому b тоже правильная. Обратно, сборка из правильных a и b всегда даёт правильную String. Место пары первой скобки у String одно, поэтому разные i, a и b дают разные String.

Значит, list dp[k] всех правильных String с k парами собирается из списков dp[0], ..., dp[k - 1]. Начало dp[0] = ['']: одна пустая String. Дальше dp[1] = ['()'] и dp[2] = ['()()', '(())']. При k = 3 сборка даёт 2 String при i = 0, 1 String при i = 1 и 2 String при i = 2: всего 5, как в примере 1.

class Solution:
    def generateParenthesis(self, n: int) -> list[str]:
        dp = [['']]  # dp[k]: все правильные String с k парами
        for k in range(1, n + 1):
            cur = []
            for i in range(k):
                # i пар внутри первой пары скобок, k - 1 - i пар после неё
                for a in dp[i]:
                    for b in dp[k - 1 - i]:
                        cur.append('(' + a + ')' + b)
            dp.append(cur)
        return dp[n]

Время: числа String в dp[1], ..., dp[8] равны 1, 2, 5, 14, 42, 132, 429 и 1430. Каждое следующее число хотя бы вдвое больше. Из String s в dp[k] при k ≥ 1 получаются две разные String в dp[k + 1]: '()' + s при i = 0 и '(' + s + ')' при i = k. Для разных s эти String тоже разные, потому что у них разные i, a или b. Значит, в dp[n - 1] не больше R/2 String, в dp[n - 2] не больше R/4, и так далее. Списки от dp[1] до dp[n - 1] вместе содержат не больше R/2 + R/4 + ... String, а эта сумма меньше R. При n = 8 это 1 + 2 + 5 + 14 + 42 + 132 + 429 = 625 String. Всего код собирает меньше 2R String, при n = 8 это 2055. Каждая сборка копирует O(n) символов, всего O(nR).

Дополнительная память: dp хранит все списки до dp[n - 1]: не больше R String длины меньше 2n, O(nR). При n = 8 это 626 String и 8162 символа. Ответ dp[n] занимает 2n · R символов. Решение 1 при n = 8 хранит в path не больше 16 символов.

Типичные ошибки

  • Проверка closed < n вместо closed < opened. При n = 2 код вернёт все 6 String с двумя ( и двумя ), среди них ))((.
  • elif перед второй проверкой. Тогда вызов с opened < n не пробует ), и при n = 3 ответ только ((())).
  • res.append(path) без join. В res попадает один и тот же list, и после всех pop он пустой: при n = 2 ответ [[], []].
