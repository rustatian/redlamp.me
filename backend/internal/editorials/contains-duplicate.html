Нужно узнать, есть ли в nums два равных числа на разных местах.

Решение 1. Hash Table

Возьмите пример 1: nums = [1, 2, 3, 1]. Код идёт по числам слева направо и хранит в seen числа, которые уже прошёл. Сначала seen пуст. Числа 1 в нём нет, и код записывает 1. Числа 2 нет в {1}, и код записывает 2. Числа 3 нет в {1, 2}, и код записывает 3. Четвёртое число 1 уже есть в seen = {1, 2, 3}: код записал его, когда прошёл место 0. Числа на местах 0 и 3 равны, ответ True после 4 проверок.

Правило. Для каждого числа x: сначала проверка x in seen, потом запись seen.add(x).

В примере 1 перед проверкой числа nums[3] в seen лежат числа 1, 2 и 3 с мест 0, 1 и 2. Так на каждом шаге: перед проверкой числа nums[j] в seen лежат все числа левее места j и только они, потому что код записывает каждое число сразу после его проверки. Поэтому проверка x in seen находит число только тогда, когда такое же число стоит левее. Значит, при ответе True пара равных чисел есть.

Ответ False тоже верный. В примере 1 равные числа стоят на местах i = 0 и j = 3, и на шаге j число nums[i] уже лежит в seen. Так для любых равных чисел на местах i < j: если код дошёл до места j, то проверка находит nums[i]. Поэтому цикл проходит все числа только тогда, когда равных чисел нет. В примере 2 nums = [1, 2, 3, 4]: ни одна из 4 проверок не находит число, и код возвращает False.

class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
        seen = set()
        for x in nums:
            if x in seen:
                return True
            seen.add(x)  # запись после проверки: x не найдёт сам себя
        return False

Время: n - длина nums. Цикл делает не больше n проверок и не больше n записей: в примере 1 это 4 проверки и 3 записи. seen - это Python set, то есть Hash Table: одна проверка и одна запись занимают ожидаемое O(1). Всего ожидаемое O(n). Дополнительная память: seen хранит не больше n чисел: O(n). Ответ - одно значение True или False.

Цикл останавливается на первом повторе. В примере 3 nums = [1, 1, 1, 3, 3, 4, 3, 2, 4, 2] это второе число: код делает 2 проверки. Короткая запись return len(set(nums)) < len(nums) даёт тот же ответ. В set каждое значение лежит один раз, поэтому при повторе в нём меньше n чисел: в примере 1 их 3 при n = 4. Без повтора в нём все n чисел: в примере 2 их 4 при n = 4. Но set(nums) всегда читает все числа: в примере 3 все 10.

Решение 2. Sorting

Возьмите nums = [4, 2, 9, 4, 1]. Числа 4 стоят на местах 0 и 3, между ними числа 2 и 9. После Sorting a = [1, 2, 4, 4, 9], и числа 4 стоят рядом: на местах 2 и 3. Код сравнивает каждое число с левым соседом. Числа 2 и 1 разные, 4 и 2 разные, 4 и 4 равны: ответ True после 3 сравнений.

Сравнения соседей хватает. В a каждое число не меньше числа слева. Поэтому между двумя числами 4 может стоять только число не меньше 4 и не больше 4, то есть тоже 4. Равные числа стоят в a подряд. Если пара равных чисел есть, то в a есть и пара равных соседей. Если все n − 1 пар соседей разные, то равных чисел нет. В примере 2 a = [1, 2, 3, 4]: 3 сравнения, равных соседей нет, ответ False.

class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
        a = sorted(nums)
        for i in range(1, len(a)):
            if a[i] == a[i - 1]:  # равные числа стоят рядом
                return True
        return False

Время: Sorting занимает O(n log n) в худшем случае. Цикл делает не больше n − 1 сравнений. Всего O(n log n) в худшем случае. Дополнительная память: sorted(nums) создаёт копию a из n чисел: O(n).

При n = 105 разных случайных чисел Sorting делает около 1 530 000 сравнений, а решение 1 делает 100 000 проверок и 100 000 записей. Оценка решения 2 верна для любого входа, оценка решения 1 ожидаемая.

Что не подходит

Brute Force сравнивает числа на парах мест, пока не найдёт равные. В примере 2 все числа разные, и он сравнивает все 4 · 3 / 2 = 6 пар. Для n разных чисел пар n(n − 1)/2: O(n²). При n = 105 это 4 999 950 000 сравнений, почти 5 · 109: слишком долго.

Столько же сравнений даёт seen = [] вместо set(). Проверка x in seen для list сравнивает x с числами по одному. В примере 2 это 0 + 1 + 2 + 3 = 6 сравнений, для n разных чисел n(n − 1)/2.

Типичные ошибки

  • Записать x в seen до проверки. Тогда x находит сам себя: для nums = [7] код вернёт True вместо False.
  • Сравнивать соседей без Sorting. В примере 1 соседи 1 и 2, 2 и 3, 3 и 1 разные, и код вернёт False вместо True.
  • Поставить return False внутрь цикла, после seen.add(x). Тогда код вернёт False после первого же числа: в примере 1 вместо True.
