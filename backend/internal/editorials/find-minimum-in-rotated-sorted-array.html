Нужен наименьший элемент повёрнутого Array, и поиск должен занимать O(log n).

Brute Force берёт min(nums). Это Linear Scan: он читает все n чисел. Для nums = [4, 5, 6, 7, 0, 1, 2] это 7 чисел. При n = 5000 это 5000 чисел, то есть O(n), а нужно O(log n). Brute Force не использует порядок Array.

Решение 1. Binary Search

Возьмём nums = [4, 5, 6, 7, 0, 1, 2]. Исходный Array был [0, 1, 2, 4, 5, 6, 7]. Четыре поворота перенесли числа 4, 5, 6, 7 в начало. Теперь Array состоит из двух упорядоченных частей: левой [4, 5, 6, 7] и правой [0, 1, 2]. Минимум стоит в начале правой части.

Сравним каждое число с последним числом: nums[-1] = 2. Все числа разные, и в исходном Array числа 4, 5, 6, 7 левой части стояли правее числа 2, поэтому они больше 2. Числа 0, 1, 2 правой части не больше 2. Условие nums[i] ≤ nums[-1] для i = 0, 1, ..., 6 даёт «нет, нет, нет, нет, да, да, да».

Минимум стоит на первом «да»: индекс 4, число 0. Lower Bound находит первое «да»: это Binary Search по условию вида «нет, ..., нет, да, ..., да».

Если Array упорядочен целиком, как [11, 13, 15, 17], левой части нет. Каждое число не больше последнего числа 17, все ответы «да», и первое «да» стоит на индексе 0. Минимум 11.

Пара lo и hi задаёт отрезок индексов, где есть первое «да». Сначала lo = 0 и hi = 6. Последний индекс, здесь 6, всегда даёт «да», потому что nums[-1] ≤ nums[-1]. Поэтому первое «да» всегда есть в отрезке. Три проверки для nums = [4, 5, 6, 7, 0, 1, 2]:

  1. mid = (0 + 6) // 2 = 3, nums[3] = 7 больше 2: «нет». Индексы 0, 1, 2, 3 тоже «нет», потому что «да» идут только после всех «нет». Ход lo = mid + 1 = 4.
  2. mid = (4 + 6) // 2 = 5, nums[5] = 1 не больше 2: «да». Первое «да» стоит на индексе 5 или левее. Индекс 5 остаётся в отрезке: hi = mid = 5.
  3. mid = (4 + 5) // 2 = 4, nums[4] = 0 не больше 2: «да». Ход hi = mid = 4.

Теперь lo = hi = 4, и цикл заканчивается. Ответ nums[4] = 0 после 3 проверок.

Для [11, 13, 15, 17] поиск идёт к левому краю. Сначала mid = (0 + 3) // 2 = 1, и nums[1] = 13 не больше 17: hi = 1. Потом mid = 0, и nums[0] = 11 не больше 17: hi = 0. Ответ 11 после 2 проверок.

Правило. Инвариант: первое «да» условия nums[i] ≤ nums[-1] лежит в отрезке [lo, hi]. «Да» на mid даёт ход hi = mid, «нет» на mid даёт ход lo = mid + 1. Цикл идёт, пока lo < hi. Когда lo = hi, в отрезке один индекс, и это индекс минимума.

class Solution:
    def findMin(self, nums: list[int]) -> int:
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if nums[mid] <= nums[-1]:
                hi = mid  # на mid «да»: первое «да» не правее mid
            else:
                lo = mid + 1  # на mid «нет»: индексы от lo до mid тоже «нет»
        return nums[lo]

Время: O(log n) в худшем случае. Проверка оставляет не больше половины отрезка, округлённой вверх: из 7 индексов не больше 4, из 5000 не больше 2500. Самый длинный путь при n = 5000 даёт длины отрезка 5000, 2500, 1250, 625, 313, 157, 79, 40, 20, 10, 5, 3, 2, 1. Это 13 проверок, пока длина не станет 1. 13 - это наименьшее k с 2k ≥ 5000: 212 = 4096 < 5000 ≤ 8192 = 213. Дополнительная память: O(1) в худшем случае: числа lo, hi и mid. Вход nums и ответ не считаем.

Типичные ошибки

  • hi = mid - 1 вместо hi = mid. Для nums = [5, 6, 1, 2, 3, 4] сначала lo = 0, hi = 5, mid = 2, и nums[2] = 1 не больше 4: «да». Ход hi = 1 убирает из отрезка индекс 2, а это первое «да». Потом mid = 0, nums[0] = 5 больше 4, и lo = 1. Цикл заканчивается с ответом 6 вместо 1.
  • Сравнение с nums[0] вместо nums[-1]. Пусть условие nums[mid] >= nums[0] даёт ход lo = mid + 1, иначе hi = mid. Для [11, 13, 15, 17] числа 13 и 15 не меньше 11, lo доходит до 3, и ответ 17 вместо 11. У упорядоченного Array нет левой части, и минимум стоит на индексе 0.
  • while lo <= hi вместо while lo < hi. Для nums = [7] получаем lo = hi = 0 и mid = 0, а ход hi = mid ничего не меняет. Цикл не заканчивается.
  • return lo вместо return nums[lo]. Для [4, 5, 6, 7, 0, 1, 2] получаем 4 вместо 0: lo - это индекс минимума, а нужно само число.
