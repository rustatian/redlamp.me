В Subarray [2, 4, 7, 2] из примера 2 все числа лежат от 2 до 7. Поэтому два любых числа отличаются не больше чем на 7 − 2 = 5, например 4 − 2 = 2 и 7 − 4 = 3. Так и в любом Subarray: все числа лежат от минимума до максимума, и модуль разности двух чисел не больше max − min. Пара из максимума и минимума тоже есть в Subarray. Значит, Subarray подходит ровно тогда, когда max − min ≤ limit.

Решение 1. Sliding Window и два Monotonic Deque

Возьмите пример 2: nums = [10, 1, 2, 4, 7, 2], limit = 5. Указатель r проходит по номерам от 0 до 5. Для каждого r указатель l стоит на самом левом номере, при котором окно от l до r подходит. Ответ это наибольшая длина r - l + 1.

Указатель l идёт только вправо. При r = 4 и l = 1 окно [1, 2, 4, 7] не подходит: 7 − 1 = 6 > 5. Окно от номера 1 до номера 5 тоже содержит 1 и 7. Поэтому начало 1 не нужно ни для r = 4, ни для r = 5, и код делает ход l += 1.

Для проверки окна нужны его максимум и минимум. Их дают два Monotonic Deque из главы. В mx лежат номера окна, их значения убывают, поэтому nums[mx[0]] это максимум окна. В mn значения номеров растут, и nums[mn[0]] это минимум окна.

При r = 3 приходит x = 4. В mx был номер 2 со значением 2. Это число меньше 4 и стоит левее. Пока номер 2 в окне, номер 3 тоже в окне. Поэтому номер 2 больше не станет максимумом, и mx.pop() удаляет его. При r = 5 приходит x = 2, и из mn сзади уходят номера 4, 3 и 2 со значениями 7, 4 и 2. Номер 2 с равным значением 2 тоже уходит: число 2 на номере 5 остаётся в окне дольше.

Правило. Пришло x = nums[r]. Удалите сзади из mx номера со значениями ≤ x, а из mn номера со значениями ≥ x. Добавьте r в оба Deque. Пока разность nums[mx[0]] - nums[mn[0]] больше limit, делайте ход l += 1 и удаляйте спереди номер меньше l.

При r = 4 после добавления mx = [4] и mn = [1, 2, 3, 4] со значениями 1, 2, 4, 7. Разность 7 − 1 = 6 > 5. Ход l += 1 даёт l = 2. В mn меньше 2 только номер 1, он стоит первым и уходит спереди. Теперь 7 − 2 = 5 ≤ 5, и сжатие закончено.

За один ход l += 1 спереди уходит не больше одного номера из каждого Deque. Номера в Deque растут слева направо, и до хода все они не меньше l. После хода меньше нового l может быть только номер, равный старому l. Если он есть в Deque, то он стоит первым.

При r = 5 окно от номера 2 до номера 5 это [2, 4, 7, 2] с разностью 7 − 2 = 5. Его длина 4, это ответ.

Почему best равен ответу. Ход l += 1 идёт, только когда в окне от l до r есть два числа с разностью больше limit. Эти два числа есть и в каждом окне от того же начала до большего r. Поэтому после сжатия ни одно окно, которое начинается левее l и кончается на r, не подходит. Окно от l до r подходит: условие цикла сжатия ложно. Значит, r - l + 1 это длина самого длинного подходящего Subarray, который кончается на r. Самый длинный Subarray кончается на одном из номеров r, а best это наибольшая длина по всем r.

from collections import deque


class Solution:
    def longestSubarray(self, nums: list[int], limit: int) -> int:
        mx = deque()  # номера окна, их значения убывают
        mn = deque()  # номера окна, их значения растут
        l = 0
        best = 0
        for r, x in enumerate(nums):
            while mx and nums[mx[-1]] <= x:
                mx.pop()
            mx.append(r)
            while mn and nums[mn[-1]] >= x:
                mn.pop()
            mn.append(r)
            # nums[mx[0]] - максимум окна, nums[mn[0]] - минимум
            while nums[mx[0]] - nums[mn[0]] > limit:
                l += 1
                if mx[0] < l:
                    mx.popleft()
                if mn[0] < l:
                    mn.popleft()
            best = max(best, r - l + 1)
        return best

Время: n это длина nums. Каждый номер входит в mx и в mn по одному разу: ровно 2n вызовов append. Каждый номер выходит из каждого Deque не больше одного раза: не больше 2n вызовов pop и popleft вместе. Каждое сравнение в цикле удаления сзади либо удаляет номер, либо заканчивает этот цикл: таких сравнений тоже O(n). Указатель l не обгоняет r: окно из одного числа даёт разность 0 ≤ limit. Поэтому сдвигов l не больше n − 1. Каждая проверка разности либо даёт сдвиг l, либо заканчивает сжатие для своего r: проверок не больше (n − 1) + n. Всё вместе O(n) в худшем случае. В примере 2 код делает 12 вызовов append, 7 вызовов pop, 2 вызова popleft, 2 сдвига l и 8 проверок разности.

Дополнительная память: Deque хранят только номера от l до r, каждый номер не больше одного раза. Пусть w это наибольшая длина окна до сжатия. Тогда в каждом Deque не больше w номеров: O(w), в худшем случае O(n). Например, при nums = [1, 2, ..., n] и limit = 109 окно не сжимается, и mn в конце хранит все n номеров. В примере 2 наибольшее число номеров в двух Deque вместе равно 5: при r = 4 до сжатия mx = [4] и mn = [1, 2, 3, 4]. Ответ это одно число.

Что не подходит

Brute Force перебирает каждое начало l и каждый конец r ≥ l и обновляет минимум и максимум на ходу. Это n(n + 1)/2 пар, O(n²) времени. В примере 2 это 21 пара. При n = 105 это 5 000 050 000 пар: слишком долго.

Типичные ошибки

  • Проверять только соседние числа. В примере 1 в [2, 4, 7] соседи отличаются на 2 и на 3, но 7 − 2 = 5 > 4. Такой код вернёт 3 вместо 2.
  • Вызывать max и min для среза окна на каждом шаге. При limit = 109 окно не сжимается, и срезы длины 1, 2, ..., n читают n(n + 1)/2 элементов для max и столько же для min. При n = 105 это 10 000 100 000 чтений: слишком долго.
