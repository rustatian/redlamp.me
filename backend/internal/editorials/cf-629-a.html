Число пар в одной строке зависит только от числа шоколадок в ней. Поэтому достаточно посчитать шоколадки в каждой строке и в каждом столбце.

Решение 1. Combinations

Пример 2: торт 4 × 4. В столбце 2 лежат 3 шоколадки: в строках 1, 3 и 4. Из них получаются 3 пары: строки 1 и 3, 1 и 4, 3 и 4.

Это же число дают Product Rule и деление на 2. Первую шоколадку пары можно выбрать 3 способами, вторую 2 способами из оставшихся: 3 · 2 = 6. Каждую пару так посчитали 2 раза. Пару из строк 1 и 3 посчитали в порядке 1, 3 и в порядке 3, 1. Поэтому пар 6 / 2 = 3.

Правило. В строке или в столбце с k шоколадками C(k, 2) = k · (k − 1) / 2 пар.

При k = 0 и k = 1 формула даёт 0: одной шоколадке не с кем составить пару. Рисунок сравнивает формулу с перебором всех пар для k от 0 до 6. Для всех 7 значений k числа совпадают.

В примере 2 в каждой из 4 строк по 2 шоколадки: 1 + 1 + 1 + 1 = 4 пары. В столбцах 1, 2, 3 и 4 лежат 2, 3, 2 и 1 шоколадка: 1 + 3 + 1 + 0 = 5 пар. Ответ 4 + 5 = 9, как в примере.

Ответ всегда равен сумме C(k, 2) по всем n строкам и всем n столбцам. Проверим это на клетках примера 2. Клетка (1, 2) это строка 1 и столбец 2, как в пояснении к примеру 1. Шоколадки (1, 1) и (1, 2) лежат в одной строке и в разных столбцах. Их пару считает только C(2, 2) = 1 строки 1: формула столбца считает пары внутри одного столбца. Так же пару (1, 1) и (2, 1) считает только C(2, 2) = 1 столбца 1. Шоколадки (1, 1) и (3, 2) лежат в разных строках и в разных столбцах, и их пару не считает ни одна формула. Пары внутри строк и пары внутри столбцов не пересекаются, поэтому Sum Rule складывает их числа. Каждая нужная пара входит в сумму ровно 1 раз.

Программа проходит по клеткам один раз. Для шоколадки в строке i и столбце j она увеличивает счётчики rows[i] и cols[j]. Индексы в коде начинаются с 0, поэтому столбец 2 примера это cols[1] = 3. Затем программа складывает C(k, 2) для всех 2n счётчиков.

n = int(input())
rows = [0] * n  # rows[i]: шоколадки в строке i
cols = [0] * n  # cols[j]: шоколадки в столбце j
for i in range(n):
    line = input()
    for j in range(n):
        if line[j] == "C":
            rows[i] += 1
            cols[j] += 1
pairs = 0
for k in rows + cols:
    pairs += k * (k - 1) // 2  # C(k, 2) пар в одном ряду
print(pairs)

Время: O(n²) для любого торта n × n: n² проверок клеток и 2n вычислений C(k, 2). При n = 100 это 10 000 проверок и 200 вычислений. Дополнительная память: O(n): списки rows и cols по n чисел и их общая копия rows + cols из 2n чисел. Торт программа читает по одной строке и целиком не хранит.

Что не подходит

Brute Force перебирает все пары шоколадок торта и для каждой пары проверяет строку и столбец. Если шоколадок m, то пар C(m, 2). Это O(m²) проверок. Шоколадок не больше n², поэтому в худшем случае это O(n⁴). При n = 100 и шоколадке в каждой клетке m = 10 000, и проверок C(10 000, 2) = 49 995 000. Наш запуск такого перебора на Python занял около 4 секунд при ограничении 1 секунда: слишком долго.

Типичные ошибки

  • Формула k · (k − 1) без деления на 2 считает каждую пару 2 раза. Для примера 1 она даёт 8 вместо 4.
  • Деление k * (k - 1) / 2 в Python даёт десятичную дробь. Для примера 1 программа печатает 4.0 вместо 4, и ответ не принимают. Нужно деление нацело //. Оно точное: из двух соседних чисел k и k − 1 одно чётное, поэтому k · (k − 1) делится на 2. Например, 3 · 2 = 6.
  • Счёт только по строкам теряет пары в столбцах. Для примера 2 он даёт 4 вместо 9.
  • C(m, 2) для всех m шоколадок торта считает и пары из разных строк и разных столбцов. В примере 1 m = 5, и получится 10 вместо 4.
