Решение 1. Greedy с Min-Heap

Возьмём пример a = [4, −4, 1, −3, 1, −3]. Первые три зелья пьём: здоровье 4, 0, 1. С четвёртым зельем −3 здоровье стало бы 1 − 3 = −2. Значит, все четыре первых зелья выпить нельзя, и одно из них надо пропустить.

Какое из первых четырёх зелий пропустить
Не пьёмПьёмЗдоровье по шагамИтог
4−4, 1, −3−4, −3, −6нельзя
−44, 1, −34, 5, 2здоровье 2
14, −4, −34, 0, −3нельзя
−34, −4, 14, 0, 1здоровье 1

В обоих допустимых вариантах выпито 3 зелья. Вариант без −4 оставляет здоровье 2, а вариант без −3 только 1. Если следующее зелье можно выпить при здоровье 1, то его можно выпить и при здоровье 2. Поэтому пропускаем самое вредное выпитое зелье, то есть наименьшее число. Дальше зелье 1 даёт здоровье 3, а последнее −3 даёт 0. Выпито 5 зелий, здоровье по шагам 4, 5, 2, 3, 0, как в пояснении к примеру.

Правило. Каждое зелье x пьём: health += x, и x идёт в Min-Heap h. Если health < 0, удаляем из h наименьшее число и вычитаем его из health. Ответ: len(h).

Одного удаления хватает. Перед зельем x здоровье было не меньше 0: в примере перед −3 оно равно 1. Если health стало отрицательным, то x < 0. Наименьшее число h не больше x: в примере −4 ≤ −3. Поэтому после удаления здоровье 1 − 3 + 4 = 2 не меньше, чем перед зельем x. Удалённое число отрицательное, и здоровье на каждом шаге после его места выросло на 4: было 1 и −2, стало 5 и 2, поэтому ни на одном шаге здоровье не становится отрицательным.

Почему Greedy не проигрывает на любом входе

Назовём лучшим выбором из j зелий такой выбор, при котором здоровье ни разу не стало отрицательным, а в конце оно наибольшее. После каждого шага код сохраняет свойство: лучший выбор из j зелий на пройденных зельях даёт здоровье, равное сумме j наибольших чисел h, а выбрать больше len(h) зелий нельзя.

После трёх зелий примера h содержит 4, −4 и 1. Лучший выбор из 1 зелья даёт 4, из 2 зелий 4 + 1 = 5, из 3 зелий 4 − 4 + 1 = 1. Каждая такая сумма не меньше 0: среднее j наибольших чисел не меньше среднего всех чисел h, а сумма всех чисел h равна health ≥ 0.

Пусть пришло зелье x = −3. Выбор без x состоит только из старых зелий, и лучший такой выбор даёт сумму j наибольших чисел h. Выбор с x - это выбор из j − 1 старых зелий и x в конце. Зелье x стоит последним, поэтому нужно одно новое условие: здоровье в конце не меньше 0. Лучший выбор с x даёт сумму j − 1 наибольших чисел h плюс x, если эта сумма не меньше 0. Для j = 2 это 4 + 1 = 5 без x и 4 − 3 = 1 с x. Лучший выбор даёт 5: это сумма двух наибольших чисел из 4, −4, 1 и −3. Для j = 3 это 4 − 4 + 1 = 1 без x и 4 + 1 − 3 = 2 с x. Лучший выбор даёт 2: это сумма трёх наибольших чисел 4, 1 и −3. Возьмём j наибольших чисел из h и x. Если x среди них, то остальные j − 1 чисел - наибольшие числа h, и это сумма с x. Иначе это j наибольших чисел h, и это сумма без x. Другая из двух сумм не больше: это тоже сумма j чисел из h и x. Если сумма с x меньше 0, то выбор без x всё равно лучше, так как его сумма не меньше 0. Поэтому для каждого j ≤ len(h) лучший выбор даёт сумму j наибольших чисел из h и x.

Выбор из len(h) + 1 зелий обязательно берёт x: из старых зелий больше len(h) выбрать нельзя. Лучший такой выбор даёт health + x, если эта сумма не меньше 0. Эту сумму код получает в строке health += x и в этом случае оставляет x в h. В примере для j = 4 сумма 4 − 4 + 1 − 3 = −2 < 0, такого выбора нет. Код удаляет наименьшее число −4, и в h остаются 3 числа. Для j ≤ 3 сумма j наибольших чисел от этого не меняется. Свойство снова верно, и в конце len(h) равно наибольшему числу зелий.

import sys
import heapq

data = sys.stdin.buffer.read().split()
n = int(data[0])
h = []
health = 0
for i in range(1, n + 1):
    x = int(data[i])
    health += x
    heapq.heappush(h, x)
    if health < 0:
        # наименьшее число Heap не больше x, поэтому одного удаления хватает
        health -= heapq.heappop(h)
print(len(h))

Время: O(n log(n + 1)) в худшем случае. Цикл делает n вызовов heappush и не больше n вызовов heappop. В h не больше n чисел, поэтому каждый вызов стоит O(log(n + 1)). В примере 6 вызовов heappush и 1 вызов heappop. Дополнительная память: O(n): когда все ai ≥ 0, h хранит все n чисел. Список data хранит n + 1 чисел входа. Ответ - одно число.

Что не подходит

Dynamic Programming по числу выпитых зелий: best[j] - наибольшее здоровье после j выпитых зелий. Зелье номер i обновляет best[j] для j от i до 1, всего 1 + 2 + ... + n = n(n + 1)/2 обновлений. При n = 2 · 105 это 20 000 100 000 обновлений, около 2 · 1010: слишком долго.

Типичные ошибки

  • Пропускать текущее зелье, если с ним здоровье станет отрицательным. Для a = [5, −5, −1, −1, −1] такой код пьёт 5 и −5, получает здоровье 0 и пропускает все три −1: ответ 2. Верный ответ 4: без −5 здоровье по шагам 5, 4, 3, 2.
  • Брать зелья в порядке убывания ai и забыть про порядок в ряду. Для a = [−1, 1] такой код берёт 1, потом −1: ответ 2. Но −1 стоит первым, и при здоровье 0 его выпить нельзя: верный ответ 1.
