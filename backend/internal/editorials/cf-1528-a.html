Во втором наборе примера отрезки на пути от вершины 1 к вершине 3 равны [1, 3], [4, 6] и [7, 9]. На первом ребре наибольшее расстояние между числами равно |1 − 6| = 5. На втором ребре наибольшее расстояние равно |4 − 9| = 5. Для суммы 10 нужны оба максимума. Но в вершине 2 нельзя взять одновременно 6 для первого ребра и 4 для второго.

Почему хватает концов отрезка

Оставим в крайних вершинах числа 1 и 9. При числе 5 в средней вершине сумма равна 4 + 4 = 8. При замене 5 на левый конец 4 получим 3 + 5 = 8. При замене 5 на правый конец 6 получим 5 + 3 = 8.

Добавим к средней вершине ещё одного соседа с числом 9. Теперь при числе 5 сумма равна 4 + 4 + 4 = 12, а при замене 5 на 4 получим 3 + 5 + 5 = 13. Одна прибавка с 4 до 5 покрывает потерю на ребре к соседу с числом 1, а вторая увеличивает сумму на 1.

Если у соседей числа 1, 1 и 9, то при числе 5 в средней вершине все три расстояния по-прежнему равны 4. При замене 5 на правый конец 6 сумма вырастет с 12 до 5 + 5 + 3 = 13.

Теперь возьмём отрезок [3, 7] и соседа с числом 4. Для чисел 6, 5, 4 и 3 расстояния до 4 равны 2, 1, 0 и 1.

Пусть число x в одной вершине лежит строго внутри отрезка. При замене x могут измениться только слагаемые для рёбер этой вершины. Обозначим через d расстояние от x до левого конца отрезка. При замене x на левый конец расстояние до любого числа больше x вырастет на d. Если число соседа не больше левого конца, расстояние до него уменьшится ровно на d. Если число соседа лежит строго между левым концом и x, исходное расстояние меньше d, а новое неотрицательно. В обоих случаях расстояние до меньшего числа может сократиться не более чем на d. Если число соседа равно x, то при сдвиге к любому концу расстояние вырастет с 0 до длины сдвига.

Если больших чисел не меньше, чем меньших, подберём каждому соседу с меньшим числом отдельного соседа с большим. В каждой паре прибавка d покрывает возможную потерю не более d. У остальных соседей расстояние растёт, поэтому при сдвиге влево сумма не уменьшится. При сдвиге к правому концу расстояние до меньшего числа растёт на длину сдвига, а до большего может сократиться не более чем на эту длину. Если меньших чисел не меньше, чем больших, то на каждую возможную потерю найдётся отдельная прибавка. При равном числе соседей с большими и меньшими значениями подходят оба конца.

Возьмём путь с отрезками [1, 1], [2, 4], [6, 8] и [9, 9]. Для чисел (1, 3, 7, 9) сумма равна 2 + 4 + 2 = 8. Заменим 3 на правый конец 4 и получим 3 + 3 + 2 = 8. Теперь у вершины с числом 7 слева стоит 4, а справа 9. Заменим 7 на левый конец 6 и получим 3 + (6 − 4) + (9 − 6) = 3 + 2 + 3 = 8. При любом выборе числа вдоль этого пути возрастают от 1 до 9, поэтому сумма расстояний всегда равна 9 − 1 = 8.

Возьмём набор с наибольшей суммой и по очереди заменим внутренние значения концами их отрезков. Перед каждой заменой сравним число в вершине с текущими числами её соседей и по этому правилу выберем конец. Сумма и так наибольшая, поэтому ни одна замена её не изменит. После всех замен в каждой вершине стоит один из концов её отрезка.

Для трёх вершин из примера Brute Force проверит 23 = 8 наборов концов. Если для каждого заново складывать расстояния по рёбрам, время в худшем случае составит O(n · 2n). При n = 100 000 и разных концах каждого отрезка понадобится 99 999 · 2100 000 вычислений расстояния.

Dynamic Programming по двум значениям вершины

Выберем вершину 1 корнем Tree. Вершина 2 - родитель вершины 3, а вершина 3 - ребёнок вершины 2. В поддереве вершины 3 в нашем примере нет рёбер, так что и для числа 7, и для числа 9 сумма равна 0. Запишем dp[3] = (0, 0). В dp[v][0] храним наибольшую сумму внутри поддерева v, если в самой вершине v выбрали левый конец. В dp[v][1] храним наибольшую сумму для правого конца. Ребро (2, 3) учтём при расчёте пары для вершины 2.

Если в вершине 2 взять 4, ребёнок 3 даст на выбор 7 − 4 = 3 или 9 − 4 = 5. Если взять 6, лучший вклад ребёнка равен 9 − 6 = 3. Получаем dp[2] = (5, 3). Теперь возьмём 1 в корне. Число 4 у ребёнка даёт (4 − 1) + 5 = 8, а число 6 даёт (6 − 1) + 3 = 8. При числе 3 в корне лучший результат равен 6.

Выберем вершину 2 корнем и возьмём в ней 4. У ребёнка 1 левый конец даёт вклад 4 − 1 = 3, а правый даёт 4 − 3 = 1. Для ребёнка 3 мы уже получили 3 при левом конце и 5 при правом. Два левых конца дают 3 + 3 = 6, а два правых дают 1 + 5 = 6. Если взять левый конец у ребёнка 1 и правый у ребёнка 3, получим 3 + 5 = 8.

Для каждого значения x родителя сравниваем два вклада ребёнка c. К сумме dp[c][0] прибавляем расстояние от x до левого конца его отрезка, а к dp[c][1] прибавляем расстояние до правого. Если добавить ребро (1, 3), получится цикл 1, 2, 3, 1. Между вершинами из поддеревьев разных детей уже есть путь через родителя этих детей. Ребро между такими вершинами тоже образовало бы цикл, а в Tree циклов нет. При заданном x можно независимо выбрать больший вклад каждого ребёнка и сложить эти вклады.

Вернёмся к корню 1. Цикл начинает с order = [1] и добавляет соседа 2. Затем он обрабатывает добавленную вершину 2, пропускает её родителя 1 и добавляет 3. В Tree от корня к каждой вершине ведёт один путь, поэтому достаточно пропускать родителя. В списке order дети идут после родителя, как в нашем примере [1, 2, 3]. При обходе в обратном порядке пары всех детей готовы к моменту обработки родителя. Поддерево корня содержит все рёбра, и из его пары (8, 6) берём большее число 8.

import sys


def solve_case(read):
    n = int(read())
    bounds = [(0, 0)]
    for _ in range(n):
        bounds.append(tuple(map(int, read().split())))

    neighbors = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, read().split())
        neighbors[u].append(v)
        neighbors[v].append(u)

    parent = [0] * (n + 1)
    order = [1]
    for v in order:
        for c in neighbors[v]:
            if c != parent[v]:
                parent[c] = v
                order.append(c)

    dp = [(0, 0)] * (n + 1)
    for v in reversed(order):
        left, right = bounds[v]
        best_left = best_right = 0
        for c in neighbors[v]:
            if c == parent[v]:
                continue
            low, high = bounds[c]
            at_low, at_high = dp[c]
            best_left += max(at_low + abs(left - low), at_high + abs(left - high))
            best_right += max(at_low + abs(right - low), at_high + abs(right - high))
        dp[v] = best_left, best_right

    return max(dp[1])


read = sys.stdin.buffer.readline
answers = [str(solve_case(read)) for _ in range(int(read()))]
print("\n".join(answers))

Во втором наборе примера код читает три пары границ и два ребра. Он добавляет три пары в bounds, четыре записи в списки соседей и две вершины в order после корня. Для n вершин код читает n пар границ и добавляет в order все n − 1 вершин, кроме корня. Каждое из n − 1 рёбер даёт две записи, по одной в списке каждого конца.

Пусть у вершины 1 девять соседей. В среде задачи первые четыре вызова append заполняют все 4 ячейки списка neighbors[1]. При пятом вызове список расширяется до 8 ячеек, и Python может скопировать 4 записи списка. Следующие три вызова заполняют оставшиеся три ячейки без копирования прежних записей. При девятом вызове Python может скопировать все 8 прежних записей. С шестого по девятый вызов Python копирует в среднем не более 8 / 4 = 2 записей за вызов.

При расширении Python оставляет запас ячеек, пропорциональный длине списка. Чтобы заполнить запас, нужно по одному вызову append на ячейку. Число записей списка, которые Python может скопировать при следующем расширении, растёт пропорционально числу этих вызовов. Поэтому общее время всех вызовов append пропорционально числу добавленных элементов во всех списках.

На пути из трёх вершин каждый обход просматривает 1 + 2 + 1 = 4 записи в списках соседей. В dp три пары для вершин этого пути и одна неиспользуемая пара с индексом 0. Каждый обход просматривает 2 · (n − 1) записей соседей, а расчёт обеих сумм требует четырёх вычислений расстояния на ребро. Время: O(n) в худшем случае на один набор. Дополнительная память: O(n) в худшем случае на один набор. Кроме списков соседей, код хранит границы отрезков, родителей, порядок обхода и по паре dp для каждой вершины.

В трёх наборах примера общее число вершин равно Σ n = 2 + 3 + 6 = 11. Если в каждом из t = 64 наборов дано Tree из двух вершин с отрезками [1, 1], то список answers хранит 64 строки "0". Пока список в памяти, join ставит между 64 нулями 63 перевода строки и получает строку из 127 символов. В каждом Tree меньше 105 рёбер, а расстояние между числами на концах любого ребра меньше 109. Значит, сумма меньше 1014 и в ответе не более 14 цифр. Перевод всех ответов в строки, их соединение и печать занимают O(t) времени в худшем случае. В каждом наборе хотя бы две вершины, поэтому 2 · t ≤ Σ n. С учётом вывода время для всех наборов в худшем случае равно O(Σ n + t) = O(Σ n). Для текущего Tree и списка answers требуется O(nmax + t) дополнительной памяти в худшем случае, где nmax - число вершин в самом большом Tree. Строка для печати занимает ещё O(t) памяти в худшем случае.
