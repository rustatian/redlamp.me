При n = 2 на первое место можно поставить любое из четырёх чисел. Для второго места останутся три варианта, для третьего два, для последнего один. Всего получится 4 · 3 · 2 · 1 = 24 порядка. Такое произведение чисел от 1 до 4 называют Factorial числа 4 и записывают 4!.

Если для каждого порядка сравнить всех соседей, получится 24 · 3 = 72 сравнения. При n = 100 000 пришлось бы сделать (200 000)! · 199 999 сравнений. Такой Brute Force занимает O(n · (2n)!) времени в худшем случае.

Пары обратных порядков

В порядке [1, 3, 4, 2] дважды за числом идёт большее число (1 < 3 и 3 < 4). Назовём такой переход подъёмом. Прочитаем числа справа налево и получим [2, 4, 3, 1]. Теперь подъём один (2 < 4), поэтому при n = 2 подходит только первый порядок.

Разворот меняет местами числа в каждой паре соседей. Числа различны, поэтому при развороте каждый переход от большего числа к меньшему станет подъёмом, а каждый подъём станет переходом к меньшему числу. Если в исходном порядке было q подъёмов из 2n − 1 переходов, в обратном их будет 2n − 1 − q. При q ≥ n это не больше n − 1, а при q ≤ n − 1 это хотя бы n.

Повторный разворот возвращает исходный порядок. Так все порядки делятся на пары, в каждой из которых подходит ровно один. При n = 2 подходят 11 порядков с двумя подъёмами и один с тремя, всего 12 из 24. Для произвольного n число всех порядков равно (2n)!, а число подходящих равно (2n)! / 2.

Как взять остаток

Возьмём для примера делитель 7 и те же 24 порядка. Если сначала взять остаток 24 % 7 = 3, деление 3 // 2 даст 1. Нужен остаток от половины числа порядков, то есть 12 % 7 = 5. Разделим пополам множитель 4 в записи 4! = 3! · 4 и получим 4! / 2 = 3! · 2. Для длины 2n сокращаем множитель 2n до n, поэтому (2n)! / 2 = (2n − 1)! · n.

При n = 2 код начинает с answer = 2 и умножает его сначала на 2, затем на 3. При n = 1 множителей в цикле нет, и ответ равен 1. В общем случае answer начинается с n, а цикл перебирает множители от 2 до 2n − 1 включительно.

Если умножить 24 и его остаток 3 на 2, получатся 48 и 6. Оба произведения дают остаток 6 при делении на 7, так как их разность 48 − 6 = 42 равна 6 · 7. После каждого умножения % MOD оставляет остаток от деления на 1 000 000 007. Отброшенная часть делится на MOD. После умножения на следующий множитель она всё ещё делится на MOD, поэтому на остаток не влияет.

import sys

MOD = 1_000_000_007
readline = sys.stdin.readline
t = int(readline())
answers = []
for _ in range(t):
    n = int(readline())
    answer = n
    for factor in range(2, 2 * n):
        answer = answer * factor % MOD
    answers.append(str(answer))

print("\n".join(answers))

За один набор цикл умножает answer на factor ровно 2n − 2 раз. Пусть S обозначает сумму всех n. По условию S ≤ 100 000, поэтому за все наборы тело этого цикла выполнится меньше 200 000 раз.

Программа читает по одному n и хранит в answer остаток от деления текущего произведения на MOD. При n = 1 цикл пуст, но программа добавляет строку "1" в список answers. Для следующего набора с n = 2 она добавляет строку "12". Всего в списке t строк длиной не больше десяти цифр, ведь каждый ответ меньше MOD. Перед печатью join соединяет их в одну строку. Чтение t чисел, запись ответов в список, соединение строк и печать занимают O(t) времени. Каждый набор добавляет к S хотя бы 1, поэтому t ≤ S.

Время: O(n) для одного набора и O(S) для всего ввода в худшем случае. Дополнительная память: O(1) для вычисления одного ответа и O(t) для всей программы в худшем случае.
