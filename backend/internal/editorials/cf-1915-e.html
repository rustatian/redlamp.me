Нужно узнать, есть ли Subarray стаканов, на котором Юлия и её спутник выпьют поровну. Номера стаканов идут с 1, как в условии.

Знаки + и −

В первом наборе примера a = [1, 3, 2]. Юлия пьёт из стаканов 1 и 3: 1 + 2 = 3. Спутник пьёт из стакана 2: это 3 единицы. Перенесём сок спутника в левую часть равенства 1 + 2 = 3: получится 1 − 3 + 2 = 0. Стаканы с нечётными номерами входят в эту сумму со знаком +, стаканы с чётными номерами со знаком −.

Знак стакана зависит только от его номера. Поэтому сумма со знаками любого Subarray равна соку Юлии минус сок спутника на этом Subarray. Во втором наборе a = [1, 1, 1, 1, 1, 1]. Subarray со 2-го стакана по 5-й начинается с чётного стакана, и его сумма со знаками равна −1 + 1 − 1 + 1 = 0. Юлия пьёт из стаканов 3 и 5: 1 + 1 = 2. Спутник пьёт из стаканов 2 и 4: 1 + 1 = 2. Формула условия для l = 2 и r = 5 сравнивает a2 + a4 и a3 + a5: это те же две суммы.

Правило. Subarray подходит, если его сумма со знаками равна 0, и не подходит, если она не равна 0.

Решение 1. Prefix Sum и Hash Table

Пусть p[i] - сумма со знаками первых i стаканов, p[0] = 0. Для a = [1, 3, 2] это p[1] = 1, p[2] = 1 − 3 = −2 и p[3] = −2 + 2 = 0. Сумма со знаками стаканов 2 и 3 равна −3 + 2 = −1. То же число даёт p[3] − p[1] = 0 − 1 = −1: из суммы первых 3 стаканов убрали первый стакан. Так для любых l и r: сумма со знаками стаканов с l-го по r-й равна p[r] − p[l − 1].

В первом наборе p[3] = p[0] = 0, поэтому p[3] − p[0] = 0: подходят стаканы с 1-го по 3-й. Разность p[r] − p[l − 1] равна 0 только тогда, когда p[r] = p[l − 1]. Поэтому ответ YES, если среди n + 1 префиксов p[0], ..., p[n] есть два равных, и NO, если все они разные.

Четвёртый набор: a = [1, 2, 11, 4, 1, 5, 1, 2], префиксы 0, 1, −1, 10, 6, 7, 2, 3, 1. Равны p[1] = 1 и p[8] = 1: это l = 2 и r = 8. Юлия пьёт 11 + 1 + 1 = 13, спутник 2 + 4 + 5 + 2 = 13. Третий набор: a = [1, 6, 9, 8, 55, 3, 14, 2, 7, 2], префиксы 0, 1, −5, 4, −4, 51, 48, 62, 60, 67, 65. Все 11 значений разные, поэтому разность p[r] − p[l − 1] не равна 0 ни для одной пары l и r: ответ NO.

Код не хранит список p. Текущий префикс лежит в s, а более ранние префиксы в set seen. В начале seen = {0}: это p[0]. В коде a[i] - стакан номер i + 1, поэтому знак + идёт при чётном i. После каждого стакана код проверяет s in seen и только потом записывает s. Поэтому перед проверкой префикса p[j] в seen лежат p[0], ..., p[j − 1] и только они. Если p[j] равен более раннему префиксу, проверка его находит, и код отвечает YES. Если цикл дошёл до конца, то ни один префикс не равен более раннему: ответ NO.

В четвёртом наборе первые 7 проверок не находят префикс в seen, восьмая находит 1.

import sys

t = int(sys.stdin.readline())
out = []
for _ in range(t):
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    seen = {0}  # префикс до первого стакана
    s = 0
    found = False
    for i in range(n):
        # a[i] - стакан номер i + 1: при чётном i номер нечётный, знак +
        s += a[i] if i % 2 == 0 else -a[i]
        if s in seen:
            found = True
            break
        seen.add(s)  # запись после проверки: префикс не найдёт сам себя
    out.append("YES" if found else "NO")
print("\n".join(out))

Время: n - число стаканов в наборе. Цикл делает не больше n проверок s in seen и не больше n записей. seen - это Python set, то есть Hash Table: одна проверка и одна запись занимают ожидаемое O(1). Всего ожидаемое O(n) на набор и ожидаемое O(∑n) на весь вход: ∑n - общее число стаканов во всех наборах, не больше 2 · 105. Дополнительная память: O(n) на набор. В seen не больше n + 1 префиксов: один есть до цикла, и каждый шаг добавляет не больше одного. При ответе NO их ровно n + 1. Список a хранит n чисел набора: это вход. Ответ отдельно: в out t строк.

Решение 2. Sorting

Этот код записывает все n + 1 префиксов в список p и сортирует его. В четвёртом наборе p = [0, 1, -1, 10, 6, 7, 2, 3, 1], после Sorting p = [-1, 0, 1, 1, 2, 3, 6, 7, 10]. Два префикса 1 теперь стоят рядом. Код сравнивает каждое число с левым соседом: −1 и 0 разные, 0 и 1 разные, 1 и 1 равны. Ответ YES после 3 сравнений.

Сравнения соседей хватает. После Sorting каждое число не меньше числа слева. Поэтому между двумя числами 1 может стоять только число не меньше 1 и не больше 1, то есть тоже 1. Равные префиксы стоят подряд, и если два префикса равны, то равны и два соседа. В третьем наборе после Sorting p = [-5, -4, 0, 1, 4, 48, 51, 60, 62, 65, 67]: все 10 пар соседей разные, ответ NO.

Sorting теряет места префиксов. Задача спрашивает только YES или NO, поэтому места не нужны.

import sys

t = int(sys.stdin.readline())
out = []
for _ in range(t):
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    p = [0] * (n + 1)  # p[i] - префикс со знаками после i стаканов
    for i in range(n):
        p[i + 1] = p[i] + (a[i] if i % 2 == 0 else -a[i])
    p.sort()
    found = False
    for i in range(1, n + 1):
        if p[i] == p[i - 1]:  # равные префиксы после Sorting стоят рядом
            found = True
            break
    out.append("YES" if found else "NO")
print("\n".join(out))

Время: O(n log n) на набор в худшем случае. p.sort() делает O(n log n) сравнений, первый цикл делает n сложений, второй не больше n сравнений. Дополнительная память: O(n) на набор: список p хранит n + 1 префиксов, а p.sort() берёт до O(n) рабочей памяти. Вход и ответ отдельно, как в решении 1.

Что не подходит

Brute Force берёт каждое l, двигает r от l до n и прибавляет стакан r к сумме со знаками: одно сложение на пару l ≤ r. В первом наборе n = 3, и пар 3 · 4 / 2 = 6. Для n стаканов пар n(n + 1)/2: O(n²). При n = 2 · 105 это 20 000 100 000 сложений, около 2 · 1010: слишком долго.

Типичные ошибки

  • Начать с пустого seen. Тогда теряется p[0] = 0, а с ним каждый Subarray, который начинается с первого стакана. В первом наборе префиксы 1, −2 и 0 разные, и код отвечает NO вместо YES.
  • Один seen на все наборы. Возьмите вход из двух наборов [1, 2, 4] и [3, 5]: верные ответы NO и NO. Первый набор оставляет в seen префиксы 0, 1, −1 и 3. Во втором наборе первый префикс равен 3, и код отвечает YES.
  • Записать s в seen до проверки. Тогда каждый префикс находит сам себя: для одного стакана a = [5] код отвечает YES вместо NO.
  • Проверять только s == 0. Так код находит только Subarray, который начинается с первого стакана. В четвёртом наборе префикс 0 после начала не встречается, и код отвечает NO вместо YES.
  • Хранить префиксы в списке: seen = [0]. Ответы верные, но проверка s in seen сравнивает s с числами списка, пока не найдёт равное. В третьем наборе равных префиксов нет, и 10 проверок делают 1 + 2 + ... + 10 = 55 сравнений. Для n стаканов и ответа NO это n(n + 1)/2 сравнений: O(n²). При n = 2 · 105 это 20 000 100 000 сравнений: слишком долго.
