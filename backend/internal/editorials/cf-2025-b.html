Код из условия сам считает нужные числа, если построить таблицу до n = 105. Строка n требует n − 1 сложений, всего 1 + 2 + ... + 99999 = 4 999 950 000 сложений, около 5 · 109: слишком долго. Поэтому сначала найдём закономерность на маленьких n.

Решение 1. Степени двойки по модулю

Выпишем строки таблицы для n от 0 до 5 по коду из условия. Строка n начинается с C[n][0] = 1 и кончается C[n][n] = 1. Числа между ними код считает слева направо. Например, C[5][3] = C[5][2] + C[4][2] = 4 + 4 = 8.

В строке 5 перед последней единицей стоят 1, 2, 4, 8, 16, в строке 4 стоят 1, 2, 4, 8. Это степени двойки: C[n][k] = 2k при k < n. Пример условия это подтверждает: C[5][2] = 4 = 22 и C[5][3] = 8 = 23. Пары (2, 1) и (100000, 1) обе дают 2 = 21: число n на ответ не влияет.

Докажем, что так будет в любой строке. Посмотрим, как строка 5 получается из строки 4. Формула для C[5][k] складывает соседа слева C[5][k − 1] и число C[4][k − 1] из строки 4. При k от 1 до 4 это столбцы от 0 до 3 строки 4: числа 1, 2, 4, 8. Единица на краю строки 4 стоит в столбце 4, и в эти суммы она не попадает.

Строка 5 тогда равна 1, 1 + 1 = 2, 2 + 2 = 4, 4 + 4 = 8, 8 + 8 = 16 и единица на краю. В каждой сумме два одинаковых слагаемых: 2k − 1 слева и 2k − 1 из строки выше. Их сумма 2 · 2k − 1 = 2k. Так же из строки 5 получается строка 6, из строки 6 строка 7 и так до n = 105.

Правило. По неверной формуле C[n][k] = 2k при 0 ≤ k < n.

Число 299999 имеет 30103 цифры, поэтому условие просит остаток от деления на M = 109 + 7. Посчитаем остатки заранее: p[0] = 1 и p[k] = p[k − 1] · 2 % M. Остаток произведения можно считать по остатку множителя, как в лекции Modular Arithmetic, поэтому p[k] равно остатку 2k. Пока 2k меньше M, взятие % ничего не меняет: p[29] = 229 = 536870912. Следующее число 536870912 · 2 = 1073741824 уже больше M = 1000000007, но меньше 2 · M. Поэтому % вычитает M один раз: p[30] = 1073741824 − 1000000007 = 73741817.

Ответ на пару (n, k) равен p[k]. Список p строим до K, наибольшего k входа: в примере K = 99999. Код выводит p[33333] = 326186014, p[66666] = 984426998 и p[99999] = 303861760, как в примере.

import sys

M = 10**9 + 7
data = sys.stdin.buffer.read().split()
t = int(data[0])
ks = [int(x) for x in data[t + 1:2 * t + 1]]  # числа n не нужны: при k < n ответ зависит только от k
K = max(ks)
p = [1] * (K + 1)  # p[k] = 2 в степени k по модулю M
for k in range(1, K + 1):
    p[k] = p[k - 1] * 2 % M
print("\n".join(str(p[k]) for k in ks))

Время: O(K + t): цикл для p делает K шагов, и каждая из t пар берёт одно число p[k]. Дополнительная память: O(K + t): список p из K + 1 чисел, список ks из t чисел и список data из 2t + 1 слов входа. Строки ответа в эту память не входят.

Типичные ошибки

  • Счёт правильных Combinations вместо неверной формулы. Для пары (5, 2) C(5, 2) = 10, а нужен ответ 4.
  • Ответ без %. Для пары (31, 30) получится 230 = 1073741824, а нужен остаток 73741817.
