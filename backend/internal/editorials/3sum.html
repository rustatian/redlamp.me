Нужны все тройки чисел с суммой 0, взятые с трёх разных мест nums. Тройку задают её числа, а не места: в примере 1 места 0, 1, 2 и места 1, 2, 4 дают одну тройку [−1, 0, 1].

Решение 1. Sorting и Two Pointers

Сначала выполните Sorting. Пример 1 даёт a = [-4, -1, -1, 0, 1, 2]. Первое число тройки стоит на месте i, а два других правее. Их сумма должна быть равна -a[i]. Эту пару ищут Two Pointers, как в задаче 167 Two Sum II: l начинает с места i + 1, r с места n − 1, где n - длина nums.

При i = 0 первое число равно −4. Сумма −4 + (−1) + 2 = −3 меньше 0. Число 2 самое большое на местах от l до r. Поэтому −4 и −1 с любым числом этих мест дают не больше −3, и число −1 на месте 1 не входит в тройку с −4. Ход l += 1 ничего не теряет. Следующие суммы −3, −2 и −1 тоже меньше 0. После 4 сумм l доходит до r: троек с −4 нет.

При i = 1 первое число равно −1. Сумма −1 + (−1) + 2 = 0 даёт тройку [−1, −1, 2]. В паре с −1 и −1 третье число может быть только 2, а другое место с числом 2 дало бы ту же тройку. Поэтому место l больше не нужно. По той же причине не нужно место r, и после тройки оба указателя идут внутрь: l = 3, r = 4. Сумма −1 + 0 + 1 = 0 даёт вторую тройку [−1, 0, 1].

На месте 2 снова стоит −1. Места правее 2 лежат и правее 1, поэтому все тройки с первым числом −1 уже нашёл шаг i = 1. Шаг i = 2 пропускает их через continue. При i = 3 сумма 0 + 1 + 2 = 3 больше 0. Число 1 самое маленькое на местах от l до r. Поэтому 0 и 2 с любым числом этих мест дают не меньше 3, и r идёт влево. Всего на примере 1 решение вычисляет 4 + 2 + 1 = 7 сумм.

Правило. Сумма меньше 0: l += 1. Сумма больше 0: r -= 1. Сумма равна 0: тройка идёт в ответ, затем l += 1 и r -= 1.

Повторы второго числа покажет вход [-2, -2, 0, 0, 2, 2]. При i = 0 сначала l = 1 и r = 5: сумма −2 + (−2) + 2 = −2 меньше 0. Затем места l = 2 и r = 5 дают −2 + 0 + 2 = 0 и тройку [−2, 0, 2]. Ходы дают l = 3 и r = 4, и там снова −2 + 0 + 2 = 0: это та же тройка. Поэтому после тройки цикл while двигает l, пока l < r и a[l] равно прошлому второму числу. Здесь l доходит до 4, и поиск при i = 0 закончен. Шаги i = 1 и i = 3 пропускает continue, а шаг i = 2 троек не даёт. Ответ: [[-2, 0, 2]].

С этим циклом второе число каждой новой тройки при том же i больше прошлого. Первое число тройки самое маленькое, и у разных i оно разное, потому что равные соседи пропущены. Поэтому тройки ответа не повторяются.

class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        a = sorted(nums)
        n = len(a)
        res = []
        for i in range(n - 2):
            # равное соседу первое число уже дало все свои тройки
            if i > 0 and a[i] == a[i - 1]:
                continue
            l, r = i + 1, n - 1
            while l < r:
                s = a[i] + a[l] + a[r]
                if s < 0:
                    l += 1
                elif s > 0:
                    r -= 1
                else:
                    res.append([a[i], a[l], a[r]])
                    l += 1
                    r -= 1
                    # второе число тройки должно стать больше
                    while l < r and a[l] == a[l - 1]:
                        l += 1
        return res

Время: Sorting стоит O(n log n). При одном i каждая сумма и каждый шаг цикла пропуска уменьшают разность r - l хотя бы на 1. Сначала она равна n − i − 2, поэтому сумм не больше n − i − 2. При i = 0 в примере 1 это 6 − 0 − 2 = 4 суммы. Всего сумм не больше (n − 2) + (n − 3) + ... + 1 = (n − 1)(n − 2)/2: O(n²) в худшем случае. При n = 3000 это 4 495 501 сумма. Дополнительная память: копия a из n чисел и Sorting в Python, O(n). Ответ из q троек хранит 3q чисел, его не считаем.

Решение 2. Hash Table

Этот способ тоже начинает с Sorting и тоже пропускает равные первые числа. Для места i место j идёт вправо. Hash Table seen (Python set) хранит числа между местами i и j. Число a[j] будет третьим числом тройки, а второе должно быть равно need = -a[i] - a[j]. Если need лежит в seen, то тройка найдена.

Вход [-2, -2, 0, 0, 2, 2], i = 0. При j = 4 в seen лежат −2 и 0, а need = −(−2) − 2 = 0. Число 0 есть, это тройка [−2, 0, 2]. При j = 5 снова need = 0, но a[5] = 2 равно третьему числу прошлой тройки. Тройка та же, и проверка a[j] != last не пускает её в ответ.

Одной переменной last хватает. Число need из seen стоит левее места j, поэтому после Sorting need ≤ a[j], и третье число самое большое в тройке. При том же i третье число задаёт всю тройку, а равные числа a[j] после Sorting стоят подряд. Поэтому повтор дают только следующие места с тем же a[j], и last ещё равно этому числу. Каждую тройку находит первое место i с её первым числом. В примере 1 тройка [−1, −1, 2] стоит на местах 1, 2 и 5 Array a. При i = 1 и j = 5 число −1 с места 2 уже лежит в seen.

class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        a = sorted(nums)
        n = len(a)
        res = []
        for i in range(n - 2):
            if i > 0 and a[i] == a[i - 1]:
                continue
            seen = set()  # значения a[i + 1], ..., a[j - 1]
            last = None  # третье число последней тройки с этим a[i]
            for j in range(i + 1, n):
                need = -a[i] - a[j]
                if need in seen and a[j] != last:
                    res.append([a[i], need, a[j]])
                    last = a[j]
                seen.add(a[j])
        return res

Время: при шаге i место j проходит не больше n − i − 1 мест. Всего не больше (n − 1) + (n − 2) + ... + 2 = n(n − 1)/2 − 1 проверок need in seen. Проверка и добавление в Hash Table стоят O(1) в ожидаемом случае. Вместе с Sorting за O(n log n) время O(n²) в ожидаемом случае. Дополнительная память: копия a из n чисел и seen, в котором меньше n чисел, O(n). Ответ тоже не считаем.

Что не подходит

Brute Force проверяет все тройки мест: n(n − 1)(n − 2)/6 сумм, O(n³). При n = 3000 это 4 495 501 000 сумм: слишком долго.

Типичные ошибки

  • Нет пропуска равных первых чисел. В примере 1 шаг i = 2 с числом −1 снова находит [−1, 0, 1].
  • Сравнение со следующим числом: a[i] == a[i + 1]. В примере 1 тогда пропущен шаг i = 1. Правее места 2 нет второго числа −1, и тройка [−1, −1, 2] теряется.
  • Выход из цикла после первой тройки. При i = 1 в примере 1 две тройки, и break теряет [−1, 0, 1].
  • Цикл пропуска без условия l < r. В примере 3 после тройки [0, 0, 0] места l = 2 и r = 1. Число a[2] равно a[1], цикл делает l = 3, и a[3] даёт IndexError.
