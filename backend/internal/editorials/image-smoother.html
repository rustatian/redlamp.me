Для каждой клетки нужны два числа: сумма её окна 3 × 3 без клеток за краем изображения и число клеток в этом окне. Ответ для клетки это первое число, делённое на второе с округлением вниз.

Решение 1. Двумерная Prefix Sum

Возьмите пример 2: img = [[100, 200, 100], [200, 50, 200], [100, 200, 100]], m = 3 строки и n = 3 столбца. Клетка (i, j) стоит в строке i и столбце j, номера с 0. Окно клетки (0, 0) это строки −1..1 и столбцы −1..1. Строки −1 и столбца −1 в img нет, поэтому границы окна обрезают: r1 = max(0, i - 1) = 0, r2 = min(m - 1, i + 1) = 1, так же c1 = 0 и c2 = 1 для столбцов. В окне остались строки 0..1 и столбцы 0..1: 100 + 200 + 200 + 50 = 550.

Число клеток считают по обрезанным границам: строк r2 − r1 + 1 = 2, столбцов c2 − c1 + 1 = 2, клеток 2 · 2 = 4. Ответ 550 // 4 = 137: оператор // делит с округлением вниз, а 550 / 4 = 137,5. У клетки (0, 1) окно это строки 0..1 и столбцы 0..2: 2 · 3 = 6 клеток, сумма 850, ответ 850 // 6 = 141. У клетки (1, 1) окно целое: 3 · 3 = 9 клеток, сумма 1250, ответ 1250 // 9 = 138.

Правило. Окно клетки (i, j): строки от r1 = max(0, i − 1) до r2 = min(m − 1, i + 1), столбцы от c1 = max(0, j − 1) до c2 = min(n − 1, j + 1). Клеток в окне (r2 − r1 + 1) · (c2 − c1 + 1).

Сумму окна код берёт из таблицы P размера (m + 1) × (n + 1). P[i][j] это сумма клеток img в строках 0..i − 1 и столбцах 0..j − 1. При i = 0 это строки 0..−1: таких строк нет. При j = 0 это столбцы 0..−1: таких столбцов нет. Поэтому строка 0 и столбец 0 таблицы P состоят из нулей. Для примера 2 строки P такие: [0, 0, 0, 0], [0, 100, 300, 400], [0, 300, 550, 850], [0, 400, 850, 1250]. P[2][2] = 550 это строки 0..1 и столбцы 0..1, то есть окно клетки (0, 0).

Каждое число P код считает из трёх готовых. Пример для P[2][2]: 50 + 300 + 300 − 100 = 550. Число 50 это клетка (1, 1). P[1][2] = 300 это прямоугольник сверху: строка 0, столбцы 0..1. P[2][1] = 300 это прямоугольник слева: строки 0..1, столбец 0. Клетка (0, 0) со значением 100 входит в оба прямоугольника, поэтому P[1][1] = 100 вычитают один раз. В общем виде: P[i + 1][j + 1] = img[i][j] + P[i][j + 1] + P[i + 1][j] - P[i][j]. В примере i = 1 и j = 1.

Возьмите клетку (2, 2): её окно это строки 1..2 и столбцы 1..2. Код считает сумму окна так: 1250 − 400 − 400 + 100 = 550. P[3][3] = 1250 это вся img. P[1][3] = 400 это строка 0: она выше окна. P[3][1] = 400 это столбец 0: он левее окна. Клетка (0, 0) стоит и в строке 0, и в столбце 0. Её 100 вычли два раза. Поэтому P[1][1] = 100 прибавляют один раз. Прямой счёт даёт то же: 50 + 200 + 200 + 100 = 550. В общем виде сумма строк r1..r2 и столбцов c1..c2 равна P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1].

У клетки (0, 0) три числа из четырёх стоят в строке 0 или в столбце 0 таблицы P: 550 − 0 − 0 + 0 = 550. Поэтому окну у края не нужна отдельная ветка в коде.

class Solution:
    def imageSmoother(self, img: list[list[int]]) -> list[list[int]]:
        m, n = len(img), len(img[0])
        # P[i + 1][j + 1]: сумма строк 0..i и столбцов 0..j
        P = [[0] * (n + 1) for _ in range(m + 1)]
        for i in range(m):
            for j in range(n):
                P[i + 1][j + 1] = img[i][j] + P[i][j + 1] + P[i + 1][j] - P[i][j]
        ans = [[0] * n for _ in range(m)]
        for i in range(m):
            r1, r2 = max(0, i - 1), min(m - 1, i + 1)
            for j in range(n):
                c1, c2 = max(0, j - 1), min(n - 1, j + 1)
                total = P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]
                cells = (r2 - r1 + 1) * (c2 - c1 + 1)  # клеток в обрезанном окне
                ans[i][j] = total // cells
        return ans

Время: в img m строк и n столбцов, всего mn клеток. Построение P делает 3 сложения или вычитания на клетку. На клетку ответа код берёт 4 числа P, делает одно умножение и одно деление. Итого O(mn) на каждом входе. При m = n = 200 это 40 000 клеток. Дополнительная память: P хранит (m + 1)(n + 1) чисел, O(mn). При m = n = 200 это 201 · 201 = 40 401 число. Ответ отдельно: mn чисел в ans.

Решение 2. Прямой обход окна

В окне не больше 9 клеток, поэтому код складывает их прямо из img, без P. Границы берут из правила выше: строки r от r1 до r2, столбцы c от c1 до c2. Функция range не берёт правую границу, поэтому после min(...) в коде стоит + 1. Для каждой клетки окна код делает total += img[r][c] и cells += 1. У клетки (0, 1) примера 2 это строки 0..1 и столбцы 0..2: 100 + 200 + 100 + 200 + 50 + 200 = 850, cells = 6, ответ 850 // 6 = 141.

class Solution:
    def imageSmoother(self, img: list[list[int]]) -> list[list[int]]:
        m, n = len(img), len(img[0])
        ans = [[0] * n for _ in range(m)]
        for i in range(m):
            for j in range(n):
                total, cells = 0, 0
                for r in range(max(0, i - 1), min(m - 1, i + 1) + 1):
                    for c in range(max(0, j - 1), min(n - 1, j + 1) + 1):
                        total += img[r][c]
                        cells += 1
                ans[i][j] = total // cells
        return ans

Время: на клетку ответа код делает не больше 9 сложений total += img[r][c], всего не больше 9mn: O(mn) на каждом входе. В примере 2 у 4 угловых клеток по 4 сложения, у 4 клеток на сторонах по 6 и у центра 9: 16 + 24 + 9 = 49 сложений. При m = n = 200 сложений не больше 9 · 40 000 = 360 000. Дополнительная память: числа m, n, i, j, r, c, total и cells, O(1). Ответ отдельно: mn чисел в ans.

При окне 3 × 3 оба решения делают O(mn) операций, и Решение 2 обходится без P. При большом окне Решение 1 делает меньше операций. Если бы окно было 21 × 21, прямой обход делал бы до 21 · 21 = 441 сложения на клетку, а Решение 1 по-прежнему брало бы 4 числа P.

Типичные ошибки

  • Делить на 9 в каждой клетке. У клетки (0, 0) примера 2 выйдет 550 // 9 = 61, а ответ 137.
  • Обходить строки i − 1..i + 1 и столбцы j − 1..j + 1 и проверять только нижний и правый край: if r < m and c < n. При i = 0 строка r = −1 проходит такую проверку. Индекс −1 в Python не даёт ошибки: img[-1] это последняя строка. В примере 2 клетка (0, 0) тогда набирает все 9 клеток: 1250 // 9 = 138, а ответ 137.
  • Писать ответ в img в Решении 2. В примере 2 после записи img[0][0] = 137 окно клетки (0, 1) читает 137 вместо 100: (137 + 200 + 100 + 200 + 50 + 200) // 6 = 887 // 6 = 147, а ответ 141. Окна читают старые значения, поэтому ответ идёт в отдельную таблицу ans.
  • round(total / cells) вместо total // cells. В примере 2 round(550 / 4) даёт 138, а округление вниз даёт 137.
  • Создать ans как [[0] * n] * m. Это m ссылок на одну и ту же строку, и запись в одну строку видна во всех. В примере 2 код вернёт три строки [137, 141, 137], а строка 1 ответа равна [141, 138, 141].
