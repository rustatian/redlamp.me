Нужно проверить, есть ли положительные i и j, для которых T(i) + T(j) = n. Здесь T(k) = k(k + 1) / 2.

Примеры значений: T(1) = 1, T(2) = 1 + 2 = 3, T(3) = 1 + 2 + 3 = 6, T(4) = 10, T(22) = 22 · 23 / 2 = 253. Пример 1: 256 = T(2) + T(22) = 3 + 253.

Оба слагаемых не меньше 1, поэтому каждое из них меньше n. Для n = 256 подходят T(1), ..., T(22): T(22) = 253 < 256, а T(23) = 276 > 256. Обозначим число таких T(k) через K. Для n ≤ 109 выходит K ≤ 44 720: T(44 720) = 999 961 560 < 109, а T(44 721) = 1 000 006 281 > 109. Условие T(k) < n значит k(k + 1) < 2n, поэтому K ≈ √(2n). Проверка: для n = 256 получаем √(2 · 256) = √512 ≈ 22,6 и K = 22. Для n = 109 получаем √(2 · 109) ≈ 44 721 и K = 44 720.

Brute Force проверяет все пары из K чисел. При K = 44 720 это 44 720 · 44 720 = 1 999 878 400, около 2 · 109 проверок: слишком долго. Наш запуск такого перебора при n = 108 (K = 14 141, 199 967 881 пара) занял около 7 секунд при ограничении 2 секунды.

Решение 1. Binary Search

Список tri хранит числа T(k) < n по возрастанию: T(k + 1) − T(k) = k + 1 > 0, например T(3) − T(2) = 6 − 3 = 3. Для n = 256 это 1, 3, 6, 10, 15, 21, ..., 231, 253. Первое слагаемое t берём из tri. Второе слагаемое равно n − t: его ищем в tri через Binary Search.

Пример 1: сначала t = 1, нужно найти 256 − 1 = 255, и в tri этого числа нет. Затем t = 3, нужно найти 256 − 3 = 253. У Binary Search lo = 0 и hi = 21: это номера первого и последнего числа tri. Середина mid = (0 + 21) // 2 = 10, и tri[10] = 66 < 253. Числа tri[0..10] не больше 66, поэтому все они меньше 253, и lo = 11. Следующие mid равны 16, 19 и 20, а на 5-й проверке mid = 21 и tri[21] = 253. Binary Search нашёл 253 за 5 проверок. Linear Scan проверил бы все 22 числа.

Пример 2: n = 512. В tri 31 число: T(31) = 496 < 512 < 528 = T(32). Числа 512 − t равны 511, 509, 506, ... Всего 31 поиск, и ни один не находит число: ответ NO.

Решение не теряет пары. Для n = 256 пара 3 + 253 найдена при t = 3: число 253 лежит в tri, потому что 253 < 256. Так же для любой пары n = T(i) + T(j): при t = T(i) число n − t = T(j) меньше n и лежит в tri. Обратно, если n − t лежит в tri, то n = t + (n − t), и оба слагаемых лежат в tri.

def has(a, target):
    lo, hi = 0, len(a) - 1  # target может стоять только в a[lo..hi]
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return True
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return False


n = int(input())
tri = []  # tri[i] = T(i + 1), по возрастанию
k = 1
while k * (k + 1) // 2 < n:
    tri.append(k * (k + 1) // 2)
    k += 1
answer = "NO"
for t in tri:
    if has(tri, n - t):
        answer = "YES"
        break
print(answer)

Время: O(√n log n) в худшем случае. Худший случай - ответ NO: тогда выполняются все K поисков. Список tri строится за K шагов. Один поиск делает не больше ⌊log2 K⌋ + 1 проверок. При K = 44 720 имеем 215 = 32 768 ≤ 44 720 < 65 536 = 216, поэтому ⌊log2 K⌋ + 1 = 15 + 1 = 16. При n = 109 проверок не больше 44 720 · 16 = 715 520. Дополнительная память: O(√n) в худшем случае: tri хранит K чисел, при n = 109 это 44 720 чисел.

Решение 2. Two Pointers

Решение 1 ищет n − t отдельно для каждого t. Порядок tri позволяет искать пару без Binary Search: достаточно сдвигать указатели lo и hi. Пара ищется в окне tri[lo..hi]. Сначала окно - весь список: lo = 0 (номер наименьшего числа) и hi = K − 1 (номер наибольшего). Каждый шаг считает s = tri[lo] + tri[hi].

Пример 1: n = 256, lo = 0, hi = 21, s = 1 + 253 = 254 < 256. Все числа окна не больше 253, поэтому сумма 1 + любое число окна не больше 254 и меньше 256. У числа 1 нет пары, и lo = 1. Следующая сумма 3 + 253 = 256: пара найдена, ответ YES.

Пример, где сдвигается hi: n = 8. В tri = [1, 3, 6] три числа: T(3) = 6 < 8 < 10 = T(4). Сумма 1 + 6 = 7 меньше 8, поэтому lo = 1. Следующая сумма 3 + 6 = 9 больше 8. В окне tri[1..2] числа 3 и 6. Все числа окна не меньше tri[lo] = 3, поэтому сумма 6 + любое число окна не меньше 6 + 3 = 9 и больше 8. У числа 6 нет пары, и hi = 1. Теперь в окне одно число, 3. Сумма 3 + 3 = 6 меньше 8, поэтому lo = 2. Получилось lo = 2 > hi = 1: пар не осталось, ответ NO.

Правило. При s < n делаем lo += 1, при s > n делаем hi -= 1, при s = n ответ YES. Цикл идёт, пока lo ≤ hi: при lo = hi сумма равна 2 · tri[lo], и два слагаемых могут быть равными.

Каждый шаг сдвигает lo или hi на 1, и разность hi − lo падает с K − 1 до −1. Поэтому шагов не больше K.

n = int(input())
tri = []  # tri[i] = T(i + 1), по возрастанию
k = 1
while k * (k + 1) // 2 < n:
    tri.append(k * (k + 1) // 2)
    k += 1
answer = "NO"
lo, hi = 0, len(tri) - 1  # пара может стоять только в tri[lo..hi]
while lo <= hi:
    s = tri[lo] + tri[hi]
    if s == n:
        answer = "YES"
        break
    if s < n:
        lo += 1
    else:
        hi -= 1
print(answer)

Время: O(√n) в худшем случае: K шагов строят tri и не больше K шагов двигают указатели. При n = 109 это не больше 44 720 + 44 720 шагов. Дополнительная память: O(√n) в худшем случае: tri хранит K чисел, при n = 109 это 44 720 чисел.

Типичные ошибки

  • В tri попало число 0 (k = 0), и tri идёт до T(k) ≤ n. Тогда каждое треугольное n получает пару n + 0. Для n = 10 = T(4) программа печатает YES, а ответ NO: 10 − 1 = 9, 10 − 3 = 7, 10 − 6 = 4, и ни одно из чисел 9, 7, 4 не треугольное.
  • tri кончается слишком рано, например на k = 31 622 (это √109, округлённый вниз) вместо k = 44 720. Для n = 999 961 561 = T(1) + T(44 720) нужное число T(44 720) пропадает, и программа печатает NO вместо YES.
  • Цикл while lo < hi вместо while lo <= hi. В решении 1 при n = 2 список tri = [1], lo = hi = 0, цикл не начнётся, и ответ NO вместо YES (2 = 1 + 1). В решении 2 при n = 6 список tri = [1, 3]: после суммы 1 + 3 = 4 < 6 получается lo = hi = 1, сумма 3 + 3 = 6 не проверена, и ответ тоже NO вместо YES.
  • Проверка if n - t in tri: на списке. Оператор in просматривает числа списка по порядку, пока не найдёт нужное, то есть делает Linear Scan. При ответе NO и n = 109 это 44 720 поисков по 44 720 чисел: 1 999 878 400 сравнений, как у Brute Force. Наш запуск занял больше 4 секунд при ограничении 2 секунды.
