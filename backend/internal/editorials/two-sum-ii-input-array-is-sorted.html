Нужны два разных места Array numbers, числа на которых дают в сумме target. Места в коде считаются с 0, а ответ это номера с 1: место 0 имеет номер 1.

Решение 1. Two Pointers

Возьмите пример 1: numbers = [2, 7, 11, 15], target = 9. Указатель l стоит на первом месте, указатель r на последнем. Сумма 2 + 15 = 17 больше 9. Array отсортирован, поэтому числа между l и r не меньше 2. Значит, число 15 с любым из них даёт не меньше 17. Число 15 не входит в ответ, и r идёт влево.

Сумма 2 + 11 = 13 тоже больше 9, и r снова идёт влево. Сумма 2 + 7 = 9 равна target. Места 0 и 1 дают ответ [1, 2].

В примере 1 двигался только r. Возьмите другой вход: numbers = [1, 2, 3, 4, 4, 9, 56, 90] и target = 8. Суммы 1 + 90 = 91, 1 + 56 = 57 и 1 + 9 = 10 больше 8, и r три раза идёт влево. Теперь r стоит на месте 4, и сумма 1 + 4 = 5 меньше 8. Числа между l и r не больше 4. Значит, число 1 с любым из них даёт не больше 5. Число 1 не входит в ответ, и l идёт вправо.

Правило. Сумма больше target: r -= 1. Сумма меньше target: l += 1. Сумма равна target: ответ [l + 1, r + 1].

Каждый ход выбрасывает число, которое ни с одним числом окна от l до r не даёт target. Поэтому пара ответа всегда остаётся в окне: это инвариант. Пока ответ в окне, l меньше r, и цикл не может закончиться без ответа. На входе с target = 8 ответ стоит на местах 3 и 4. Окно сжимается от мест 0 и 7 до мест 3 и 4, суммы равны 91, 57, 10, 5, 6, 7 и 8. Ответ [4, 5].

class Solution:
    def twoSum(self, numbers: list[int], target: int) -> list[int]:
        l, r = 0, len(numbers) - 1
        while l < r:
            s = numbers[l] + numbers[r]
            if s == target:
                return [l + 1, r + 1]
            if s < target:
                l += 1  # numbers[l] мало даже с самым большим числом окна
            else:
                r -= 1  # numbers[r] много даже с самым маленьким числом окна

Время: n это длина numbers. Сначала r - l равно n − 1. Каждая сумма без ответа уменьшает эту разность на 1, поэтому сумм не больше n − 1: O(n) в худшем случае. На входе с target = 8 длина n = 8, и сумм ровно n − 1 = 7, потому что ответ стоит на соседних местах 3 и 4. Дополнительная память: l, r и s, O(1). Ответ это два числа.

Решение 2. Binary Search

Этот способ тоже использует порядок чисел. Пусть первое число пары стоит на месте i. Тогда второе число равно need = target - numbers[i], и его можно искать Binary Search правее места i. В примере 1 при i = 0 нужно число 9 − 2 = 7. Поиск идёт по отрезку мест от lo = 1 до hi = 3. Середина mid = (1 + 3) // 2 = 2, там число 11. Оно больше 7, поэтому 7 может стоять только левее: hi = 1. Новая середина mid = 1, там число 7. Ответ [1, 2].

Поиск идёт только правее i. Место i нельзя взять второй раз. Пару с местом j левее i уже проверил поиск при i = j.

На входе с target = 8 поиск идёт при i = 0, 1, 2 и 3 и делает 11 проверок mid. Чисел 7, 6 и 5 правее мест 0, 1 и 2 нет. Число 4 для i = 3 стоит на месте 4, ответ [4, 5]. Решение 1 на этом входе делает меньше работы: 7 сумм.

class Solution:
    def twoSum(self, numbers: list[int], target: int) -> list[int]:
        n = len(numbers)
        for i in range(n - 1):
            need = target - numbers[i]
            lo, hi = i + 1, n - 1  # ищем need правее места i
            while lo <= hi:
                mid = (lo + hi) // 2
                if numbers[mid] == need:
                    return [i + 1, mid + 1]
                if numbers[mid] < need:
                    lo = mid + 1
                else:
                    hi = mid - 1

Время: на шаге 1 рисунка Binary Search отрезок от 1 до 7 имеет 7 мест. После проверки mid = 4 остаётся отрезок от 5 до 7 из 3 мест. Каждая проверка mid оставляет не больше половины отрезка. При n = 3 · 104 первый отрезок имеет 29 999 мест, дальше не больше 14 999, 7 499, 3 749 и так далее до 1. Это не больше 15 проверок на один поиск. Поисков не больше n − 1, поэтому время O(n log n) в худшем случае. Дополнительная память: n, i, need, lo, hi и mid, O(1). Поиск идёт по местам самого numbers. Срез numbers[i + 1:] скопировал бы до n − 1 чисел.

Что не подходит

Brute Force проверяет все пары мест: до n(n − 1)/2 сумм, O(n²). При n = 3 · 104 это 449 985 000 сумм: слишком долго.

Hash Table из уже пройденных чисел находит пару за ожидаемое время O(n). Но она хранит до u записей, где u это число разных значений в numbers. Решения 1 и 2 хранят только несколько переменных, как требует условие.

Типичные ошибки

  • Места вместо номеров. В примере 1 return [l, r] даёт [0, 1], а нужен ответ [1, 2].
  • Не тот ход. В примере 1 сумма 2 + 15 = 17 больше 9. Ход l += 1 выбросит число 2, а оно входит в ответ.
  • Поиск в решении 2 с места 0. Для numbers = [3, 3] и target = 6 первая середина mid = 0 совпадает с i = 0. Ответ [1, 1] берёт одно число два раза.
