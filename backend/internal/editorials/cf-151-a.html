Решение 1. Подсчёт полных порций

В первом примере четыре бутылки по 5 мл дают 20 мл. Из них можно налить 20 // 3 = 6 порций по 3 мл. Останется 20 − 6 · 3 = 2 мл. Для положительных чисел операция // даёт целую часть частного.

Если взять три бутылки по 2 мл, то ни в одной из них не будет полных 3 мл. Но вместе они дадут 6 мл, как раз на две порции. Поэтому в выражении k * l // nl сначала считаем общий объём напитка.

В первом примере лаймы дают 10 · 8 = 80 долек, по одной на порцию. Соли хватит на 100 // 1 = 100 порций. Теперь k * l // nl, c * d и p // np можно сравнить, потому что все три числа обозначают количества порций.

На каждую из шести порций напитка найдутся и долька, и грамм соли. Седьмую собрать нельзя, потому что для неё не хватит напитка. Число полных порций portions равно наименьшему из трёх чисел.

Если друзей трое, каждый получит 6 // 3 = 2 порции. Если друзей четверо, после первого общего тоста останутся две порции. Их не хватит всем четверым на второй тост. Семерым друзьям шести порций не хватит даже на первый общий тост. Поэтому число тостов на человека равно portions // n.

n, k, l, c, d, p, nl, np = map(int, input().split())

drink_portions = k * l // nl
lime_portions = c * d
salt_portions = p // np
portions = min(drink_portions, lime_portions, salt_portions)
print(portions // n)

Даже для тысячи друзей программа читает восемь чисел и передаёт в min три числа. Число действий и число переменных не зависят от n и размеров запасов. Время: O(1) в худшем случае. Дополнительная память: O(1) в худшем случае.

Решение 2. По одному общему тосту за шаг

Пусть у троих друзей есть 48 мл напитка, 16 долек и 23 г соли. Если каждому нужны 2 мл напитка и 4 г соли, за один общий тост уйдут 6 мл, 3 дольки и 12 г. Останутся 42 мл, 13 долек и 11 г. Для второго общего тоста не хватает одного грамма соли.

Перед каждым тостом цикл проверяет, хватит ли всех трёх запасов на всю группу. Если хватает, вычитаем расход и увеличиваем rounds на один. На каждом таком шаге все друзья делают по одному тосту. Когда хотя бы одного запаса не хватит, rounds уже содержит наибольшее число тостов на человека.

n, k, l, c, d, p, nl, np = map(int, input().split())

drink = k * l
slices = c * d
drink_per_round = n * nl
salt_per_round = n * np
rounds = 0
while drink >= drink_per_round and slices >= n and p >= salt_per_round:
    drink -= drink_per_round
    slices -= n
    p -= salt_per_round
    rounds += 1
print(rounds)

При n = nl = np = 1 запасов в 1000 мл, 1000 долек и 1000 г хватит ровно на 1000 шагов цикла. Больше шагов быть не может, потому что соли не больше 1000 г, а за шаг уходит хотя бы грамм. При заданных n и np за шаг уходит n · np граммов соли, поэтому начального запаса p хватит не более чем на p // (n · np) шагов. Даже при нулевом ответе цикл один раз проверит условие. Программа хранит новые остатки в тех же переменных. Время: O(1 + p // (n · np)) в худшем случае. Дополнительная память: O(1) в худшем случае.
