Каждый шаг меняет одно число: наименьшее, а из равных наименьших - число с меньшим индексом.

Решение 1. Min-Heap пар

Возьмите пример 1: nums = [2, 1, 3, 5, 6], k = 5, multiplier = 2. Код строит list пар h = [(2, 0), (1, 1), (3, 2), (5, 3), (6, 4)]: в паре число и его индекс. После heapq.heapify(h) в h[0] стоит наименьшая пара (1, 1). Код берёт из неё x = 1 и i = 1 и пишет nums[1] = 1 · 2 = 2. Затем heapq.heapreplace удаляет пару из h[0] и добавляет (2, 1).

Теперь в h две пары с числом 2: (2, 0) и (2, 1). Python сравнивает tuple по элементам слева направо до первого различия. Первые элементы равны, а вторые 0 < 1, поэтому (2, 0) < (2, 1). На шаге 2 в h[0] стоит (2, 0), и код меняет nums[0] на 2 · 2 = 4. Второй элемент пары, индекс, выбирает из равных чисел первое.

Пусть n - длина nums. В h всегда n пар, по одной для каждого индекса, и в паре индекса i стоит текущее nums[i]. В начале это так: пары взяты из nums. Шаг меняет только nums[i] для пары из h[0]. heapreplace удаляет именно эту старую пару и добавляет пару с новым числом. В примере 1 после шага 1 в h снова 5 пар, а у индекса 1 пара (2, 1). Min-Heap держит наименьшую пару в h[0]: у неё наименьшее число, а из равных чисел наименьший индекс. Это то число, которое выбирает условие.

Время: создание h и heapify стоят O(n). Каждый из k шагов делает один heapreplace за O(log(n + 1)). Всего O(n + k log(n + 1)) в худшем случае. Дополнительная память: h хранит n пар, O(n): в примере 1 это 5 пар. Ответ код пишет прямо в nums, поэтому после вызова вход изменён.

import heapq


class Solution:
    def getFinalState(self, nums: list[int], k: int, multiplier: int) -> list[int]:
        h = [(x, i) for i, x in enumerate(nums)]  # при равных x меньше пара с меньшим i
        heapq.heapify(h)
        for _ in range(k):
            x, i = h[0]  # наименьшее число, из равных - первый индекс
            nums[i] = x * multiplier
            heapq.heapreplace(h, (nums[i], i))  # новое число того же индекса
        return nums

Решение 2. Linear Scan

По условию k ≤ 10 и n ≤ 100, поэтому каждый шаг может просмотреть все n чисел. Переменная j хранит индекс наименьшего из просмотренных чисел. Шаг 2 примера 1 начинается с nums = [2, 2, 3, 5, 6] и j = 0. При i = 1 код проверяет 2 < 2. Это ложь, и j остаётся 0. Числа 3, 5 и 6 тоже не меньше 2. Код меняет nums[0] на 2 · 2 = 4, как и решение 1.

После цикла nums[j] - наименьшее число: каждое число сравнивается с nums[j], и j переходит на любое меньшее. Знак < не переводит j на равное число. Поэтому j - первый индекс наименьшего числа.

Время: каждый шаг делает n − 1 сравнений, всего k(n − 1): O(k · n) в худшем случае. В примере 1 это 5 · 4 = 20 сравнений. При n = 100 и k = 10 это 10 · 99 = 990 сравнений, поэтому Linear Scan подходит для этих ограничений. Дополнительная память: три числа _, j и i, O(1). Ответ код тоже пишет в nums.

class Solution:
    def getFinalState(self, nums: list[int], k: int, multiplier: int) -> list[int]:
        for _ in range(k):
            j = 0
            for i in range(1, len(nums)):
                if nums[i] < nums[j]:  # строго меньше: из равных остаётся первый индекс
                    j = i
            nums[j] *= multiplier
        return nums

Типичные ошибки

  • Знак <= вместо < в решении 2. Тогда j переходит на последнее из равных чисел. В примере 1 шаг 2 меняет nums[1], и ответ [4, 8, 6, 5, 6] вместо [8, 4, 6, 5, 6].
  • heappush вместо heapreplace в решении 1. Старая пара (1, 1) остаётся в h[0], и все 5 шагов снова берут x = 1 и i = 1. Ответ [2, 2, 3, 5, 6].
  • Умножить по одному разу k наименьших чисел, например после Sorting. Один индекс может быть выбран несколько раз: в примере 1 пять шагов выбирают индексы 1, 0, 1, 2, 0. При k = n = 5 такой код умножит все числа и вернёт [4, 2, 6, 10, 12].
