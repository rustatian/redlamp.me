Нужно выписать каждый набор из k разных чисел от 1 до n ровно один раз. Число таких наборов обозначим C(n, k).

Решение 1. Backtracking

Возьмите пример 1: n = 4, k = 2, в ответе C(4, 2) = 6 наборов. Записи [1, 3] и [3, 1] дают один и тот же набор. Чтобы не получить его два раза, пишем числа набора по возрастанию. Тогда у каждого набора ровно одна запись: [1, 3].

Функция dfs(start) работает с одним общим list по имени path. Если в path уже k чисел, она сохраняет копию path в res и заканчивает работу. Иначе цикл перебирает числа x от start: кладёт x в path, вызывает dfs(x + 1) и убирает x через path.pop(). Вызов dfs(x + 1) берёт только числа больше x. Поэтому числа в path всегда идут по возрастанию, и запись [3, 1] не появится.

Осталось выбрать, где цикл останавливается. В примере 1 первый вызов dfs(1) начинает с пустого path, и нужно ещё 2 числа. После числа 4 нет ни одного числа, поэтому path = [4] нельзя дополнить до длины 2. Значит, x = 4 пробовать не нужно.

В общем случае нужно ещё need = k - len(path) чисел. После выбора x остаются числа от x + 1 до n, их n − x. Чтобы набор получился, нужно n − x ≥ need − 1, то есть x ≤ n − need + 1. В примере 1 при need = 2 это x ≤ 3. Правая граница range в цикл не входит, поэтому в коде стоит range(start, n - need + 2). Такая граница это Pruning: код не идёт по пути, который не даёт ни одного ответа.

Рисунок показывает все 10 вызовов на примере 1. Окно на строке чисел отмечает x, которые пробует цикл. Ответы появляются в порядке [1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4], как в выходе примера.

Каждый набор появляется ровно один раз. Возьмите [2, 4]. Вызов dfs(1) при x = 2 кладёт 2 и вызывает dfs(3). Затем dfs(3) при x = 4 кладёт 4 и вызывает dfs(5), а он сохраняет [2, 4]. Других путей к [2, 4] нет: в path числа идут по возрастанию, поэтому первым должно быть 2, а вторым 4.

Каждый вызов получает path, который можно дополнить до ответа. После x ≤ n − need + 1 остаются хотя бы need − 1 чисел. Например, при path = [3] остаётся число 4, и получается [3, 4].

Без Pruning цикл шёл бы до n: range(start, n + 1). В примере 1 это 11 вызовов вместо 10: лишний вызов получает path = [4]. При n = k = 4 разница больше: 16 вызовов без Pruning и 5 с ним, а ответ один: [1, 2, 3, 4]. При n = k = 20 код без Pruning посещает все 220 = 1 048 576 Subsets чисел от 1 до 20 ради одного ответа. С Pruning вызовов 21: пустой path и path длины 1, 2, ..., 20.

class Solution:
    def combine(self, n: int, k: int) -> list[list[int]]:
        res = []
        path = []

        def dfs(start):
            if len(path) == k:
                res.append(path[:])  # копия: path ещё изменится
                return
            need = k - len(path)
            # после x нужно ещё need - 1 чисел из x + 1, ..., n
            for x in range(start, n - need + 2):
                path.append(x)
                dfs(x + 1)  # дальше только числа больше x
                path.pop()

        dfs(1)
        return res

Время: path каждого вызова это начало какого-то ответа длиной от 0 до k чисел, и у разных вызовов path разные. У одного ответа k + 1 таких начал, поэтому вызовов не больше (k + 1) · C(n, k). Каждый шаг цикла делает один вызов, поэтому шагов на 1 меньше, чем вызовов. Копия path[:] переписывает k чисел каждого ответа: всего k · C(n, k) чисел. Время O(k · C(n, k)) для любого входа. Самый большой ответ при n = 20 и k = 10: C(20, 10) = 184 756 наборов, 1 847 560 скопированных чисел и 352 716 вызовов.

Дополнительная память: path хранит до k чисел, а Call Stack держит до k + 1 вызовов dfs: O(k). В примере 1 это до 2 чисел и 3 вызовов. Ответ занимает C(n, k) list по k чисел, его считаем отдельно.

Решение 2. Next Combination

Наборы можно выписать по одному без Recursion, в лексикографическом порядке: сначала сравниваем первые числа, при равенстве вторые и так далее. Возьмите n = 5 и k = 3. Первый набор [1, 2, 3], последний [3, 4, 5].

Места в наборе считаем с 0. При n = 5 и k = 3 на месте 2 может стоять самое большее 5. На месте 1 самое большее 4: правее него ещё одно место, и там нужно большее число. На месте 0 самое большее 3. В общем случае максимум места i равен n − k + i + 1.

Шаг от набора c к следующему такой. Цикл while ищет самое правое место i, где c[i] меньше максимума. Затем c[i] растёт на 1, а места правее i получают числа c[i] + 1, c[i] + 2 и так далее. Возьмите c = [1, 4, 5]. На местах 2 и 1 стоят максимумы 5 и 4. На месте 0 стоит 1, это меньше 3. Получаем c[0] = 2, затем c[1] = 3 и c[2] = 4: следующий набор [2, 3, 4].

Между [1, 4, 5] и [2, 3, 4] других наборов нет. Набор, который идёт после [1, 4, 5] и начинается с 1, должен иметь большее второе число или то же второе и большее третье. Но 4 и 5 уже максимумы мест 1 и 2. Среди наборов с первым числом 2 самый маленький [2, 3, 4]. После [3, 4, 5] все места на максимуме, i доходит до −1, и код возвращает res.

Рисунок показывает все 10 наборов при n = 5 и k = 3 и шаг после каждого.

Решение 2 выдаёт наборы в том же порядке, что и решение 1.

class Solution:
    def combine(self, n: int, k: int) -> list[list[int]]:
        c = list(range(1, k + 1))  # первый набор: 1, 2, ..., k
        res = []
        while True:
            res.append(c[:])
            # самое правое место i, где число ещё можно увеличить
            i = k - 1
            while i >= 0 and c[i] == n - k + i + 1:
                i -= 1
            if i < 0:
                return res
            c[i] += 1
            for j in range(i + 1, k):
                c[j] = c[j - 1] + 1

Время: один шаг проверяет в цикле while не больше k мест и меняет в цикле for не больше k − 1 мест. Копия c[:] переписывает k чисел. На каждый из C(n, k) наборов приходится O(k) работы: время O(k · C(n, k)) для любого входа. При n = 5 и k = 3 копии дают 10 · 3 = 30 чисел.

Дополнительная память: c хранит k чисел, кроме него код держит только i и j: O(k). Ответ считаем отдельно.

Типичные ошибки

  • res.append(path) без копии. Тогда все 6 элементов res это один и тот же list path. После последнего pop он пустой, и для примера 1 ответ равен [[], [], [], [], [], []].
  • dfs(start + 1) вместо dfs(x + 1). Тогда после x следующий вызов снова может взять x или меньшее число. Для примера 1 выйдет 9 list, среди них [2, 2] и [3, 2].
  • Граница range(start, n - need + 1) на 1 меньше нужной. В примере 1 первый вызов не пробует x = 3, а вызовы с need = 1 не пробуют x = 4. Ответ [[1, 2], [1, 3], [2, 3]] теряет 3 набора.
