Ответ - наименьшая сумма цен k соседних строк. Цена строки - наименьшая стоимость её опор. Строки не зависят друг от друга, поэтому сначала считаем цену каждой строки, а потом выбираем лучшие k соседних.

Цена строки и окно из строк

Возьмём второй тест примера 1: k = 2, d = 1, 4 строки по 4 столбца. Строки и столбцы нумеруем с 0. В строке [0, 2, 1, 0] опоры в столбцах 0 и 3 обязательны и стоят по 1. Расстояние между ними 3 − 0 − 1 = 2 больше d = 1, поэтому нужна ещё одна опора. Таблица показывает все варианты опор этой строки.

Brute Force перебирает варианты опор. Кроме берегов, у строки m − 2 столбцов: каждый можно взять или не взять. Получается 2m − 2 вариантов на строку. При m = 30 это 228 = 268 435 456 вариантов. При m = 2 · 105 их 2199 998: слишком долго.

Решение 1. Dynamic Programming, Monotonic Deque и Sliding Window

Пусть dp[j] - наименьшая стоимость опор в столбцах 0..j, если опора стоит в столбце j. Опора в столбце 0 обязательна. Возьмём тест 4 примера 1: a = [0, 10, 4, 8, 4, 4, 2, 0], d = 1. Опора на берегу стоит 0 + 1, поэтому dp[0] = 1.

Предыдущая опора стоит в столбце p. Расстояние j − p − 1 не больше d, поэтому p ≥ j − d − 1. С такой опорой p наименьшая стоимость равна a[j] + 1 + dp[p]: опоры левее p не меняют расстояние от p до j. Для j = 1 подходит только p = 0: dp[1] = a[1] + 1 + dp[0] = 10 + 1 + 1 = 12. Для j = 2 подходят p = 0 и p = 1: dp[2] = 4 + 1 + min(1, 12) = 6. Для j = 3 подходят p = 1 и p = 2: dp[3] = 8 + 1 + min(12, 6) = 15. Столбец 0 не подходит: расстояние 3 − 0 − 1 = 2 больше d = 1. Дальше dp[4] = 11, dp[5] = 16, dp[6] = 14 и dp[7] = 15. Последняя опора обязана стоять в столбце 7, поэтому цена строки - dp[7] = 15. Это ответ теста 4.

Правило. dp[0] = 1. Для j ≥ 1 верно dp[j] = a[j] + 1 + min(dp[j − d − 1..j − 1]), столбцы левее 0 не считаем. Цена строки - dp[m − 1].

Минимум окна можно искать циклом: столбец j читает min(j, d + 1) значений dp. Это O(m · d) на строку. При m = 2 · 105 и d = m одна строка даёт около 2 · 1010 чтений: слишком долго.

Минимум окна даёт Monotonic Deque из главы. В dq лежат номера столбцов окна, не обязательно всех. Значения dp в dq растут от начала к концу, поэтому dp[dq[0]] - минимум окна.

Сзади удаляем столбцы, которые не лучше нового. Для j = 4 в dq стоят столбцы 2 и 3 со значениями dp 6 и 15, а dp[4] = 11. Для j = 5 окно - столбцы 3 и 4. Столбец 3 выходит из окна раньше столбца 4, а 15 больше 11. Минимумом окна столбец 3 уже не станет, и dq.pop() удаляет его. Значение 6 меньше 11, поэтому столбец 2 остаётся. Столбец с равным dp тоже удаляем: новый столбец остаётся в окне дольше.

Цикл не удалит dq[0]: dp[j] = a[j] + 1 + dp[dq[0]] больше dp[dq[0]]. Поэтому dq не пустеет, и проверка на пустой dq не нужна.

Спереди убираем столбцы вне окна. Для j = 3 окно - столбцы 1 и 2, а в dq стоит столбец 0. Здесь dq[0] равен 0, а j − d − 1 = 1. Условие 0 < 1 верно, и dq.popleft() убирает столбец 0. Одного popleft за шаг хватает: окно сдвигается на один столбец, и вне окна может оказаться только столбец j − d − 2. Для j = 3 это столбец 0. Для j = 1 и j = 2 число j − d − 1 равно −1 и 0, а номера в dq не меньше 0: условие ложно.

Цены строк лежат в списке cost. Окно из k соседних строк - это Sliding Window. Оно сдвигается на одну строку: строка i входит, строка i − k выходит, и сумма меняется на cost[i] - cost[i - k]. Для cost = [6, 4, 4, 6] и k = 2 первая сумма равна 6 + 4 = 10. При i = 2 получаем 10 + 4 − 6 = 8, при i = 3 получаем 8 + 6 − 4 = 10. Наименьшая сумма 8.

import sys
from collections import deque


def row_cost(a, d):
    m = len(a)
    dp = [0] * m
    dp[0] = 1  # опора на берегу стоит 0 + 1
    dq = deque([0])  # столбцы окна, dp растёт от начала к концу
    for j in range(1, m):
        # предыдущая опора стоит в столбцах j - d - 1..j - 1
        if dq[0] < j - d - 1:
            dq.popleft()
        dp[j] = a[j] + 1 + dp[dq[0]]
        while dp[dq[-1]] >= dp[j]:
            dq.pop()
        dq.append(j)
    return dp[-1]


def main():
    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n, _, k, d = map(int, sys.stdin.readline().split())
        cost = [row_cost(list(map(int, sys.stdin.readline().split())), d) for _ in range(n)]
        s = sum(cost[:k])
        best = s
        for i in range(k, n):
            s += cost[i] - cost[i - k]
            best = min(best, s)
        out.append(best)
    print("\n".join(map(str, out)))


main()

Время: O(n · m) в худшем случае на набор. Каждый столбец входит в dq один раз и выходит не больше одного раза. В строке теста 4 это 8 входов в dq, 3 выхода сзади и 3 спереди. Окно из k строк делает n − k сдвигов. Для всех наборов вместе n · m в сумме не больше 2 · 105, поэтому весь вход даёт не больше 2 · 105 входов в dq. Дополнительная память: O(m + n) в худшем случае: списки a и dp хранят по m чисел, dq хранит не больше m номеров, cost хранит n цен. Строки входа читаются по одной, весь вход не хранится. Список out - ответ, его считаем отдельно.

Другой способ: Ordered Set

Значения dp последних d + 1 столбцов можно держать в Ordered Set с частотами (в C++ это multiset): минимум стоит в начале, а значение столбца, который вышел из окна, удаляем. Каждый столбец один раз вставляется и не больше одного раза удаляется, и каждая операция стоит O(log d). Всего O(n · m · log d). Monotonic Deque убирает множитель log d.

Типичные ошибки

  • Окно из d столбцов вместо d + 1: условие dq[0] < j - d. Для строки [0, 2, 1, 0] и d = 1 такой код ставит опору в каждом столбце: цена 7 вместо 4.
  • Базовое значение dp[0] = 0: опора на берегу тоже стоит 1. В тесте 3 примера 1 каждая строка стоит 2, ответ 4, а такой код вернёт 2.
  • Выбор k самых дешёвых строк вместо k соседних. Для строк [0, 0, 5, 0], [0, 7, 7, 0], [0, 0, 0, 0], d = 1 и k = 2 цены равны 3, 10 и 3. Две самые дешёвые строки дают 6, но они не соседние. Верный ответ 13.
