Нужно найти наибольшую высоту бака h, при которой хватает x единиц воды.

Сколько воды нужно для высоты h

Возьмём первый набор примера: a = [3, 1, 2, 4, 6, 2, 5] и h = 5. Столбцы высоты 3, 1, 2, 4 и 2 получают 2, 4, 3, 1 и 3 единицы, а столбцы высоты 6 и 5 не получают ничего. Всего нужно 2 + 4 + 3 + 1 + 3 = 13 единиц. Эту сумму назовём water(5), а для любой высоты - water(h).

Столбец высоты ai получает h − ai единиц воды, если ai < h, и ничего, если ai ≥ h. Одной формулой: столбец получает max(0, h − ai) единиц. Для h = 4 и столбца высоты 6 разность h − ai равна −2, а max(0, −2) = 0: воды нет.

С ростом h воды не становится меньше: при h + 1 каждый столбец получает не меньше воды, чем при h. Поэтому проверка water(h) ≤ x монотонная. При x = 9 она даёт «да» для h = 1, 2, 3, 4 (water равна 0, 1, 4 и 8) и «нет» для каждого h от 5 (water(5) = 13). Нужно последнее «да».

Brute Force проверяет h = 1, 2, 3, ... подряд, пока воды хватает. Возьмём n = 2 · 105, все ai = 109 и x = 109. Каждая единица высоты выше 109 стоит 2 · 105 единиц воды, а 5000 · 2 · 105 = 109. Поэтому воды хватает на 5000 единиц высоты, и ответ равен 109 + 5000 = 1 000 005 000. Это 1 000 005 001 проверка, и в каждой складывается 2 · 105 чисел: около 2 · 1014 сложений. Это слишком долго.

Решение 1. Binary Search

В первом наборе примера самый высокий столбец имеет высоту 6, а x = 9. При h = 6 + 9 + 1 = 16 один этот столбец получает 16 − 6 = 10 единиц воды, а это больше 9. Для любого набора так же: при h = max(a) + x + 1 один самый высокий столбец уже получает x + 1 единиц воды, а это больше x. Высота h = 1 подходит всегда: каждое ai ≥ 1, поэтому water(1) = 0 ≤ x. Поэтому ответ лежит между lo = 1 и hi = max(a) + x. В примере max(a) + x = 6 + 9 = 15.

Каждый шаг проверяет середину mid = (lo + hi + 1) // 2. Сначала lo = 1, hi = 15, mid = 8, water(8) = 33 > 9. Каждое h ≥ 8 требует не меньше 33 единиц, поэтому hi = 7. Дальше mid = (1 + 7 + 1) // 2 = 4 и water(4) = 8 ≤ 9: высота 4 подходит, и lo = 4. Меньшие высоты не нужны, потому что ответ наибольший. Затем mid = 6, water(6) = 19 > 9, и hi = 5. Потом mid = 5, water(5) = 13 > 9, и hi = 4. Теперь lo = hi = 4: ответ 4 после 4 проверок.

Плюс 1 в mid нужен для наибольшего ответа. Возьмём набор 2 примера: a = [1, 1, 1], x = 10, ответ 4. Поиск с серединой (lo + hi) // 2 начинается с lo = 1 и hi = max(a) + x = 1 + 10 = 11. Середины 6, 3 и 4 дают water = 15 > 10, 6 ≤ 10 и 9 ≤ 10, и поиск приходит к lo = 4 и hi = 5. Здесь (4 + 5) // 2 равно 4, то есть lo. Высота 4 подходит, поэтому lo = mid ничего не меняет, и цикл не кончается. Если к сумме lo + hi добавить 1, середина равна (4 + 5 + 1) // 2 = 5 и больше lo, поэтому отрезок сужается на каждом шаге.

import sys

data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, x = int(data[pos]), int(data[pos + 1])
    a = list(map(int, data[pos + 2:pos + 2 + n]))
    pos += 2 + n
    # lo подходит, ответ не больше hi
    lo, hi = 1, max(a) + x
    while lo < hi:
        mid = (lo + hi + 1) // 2
        water = sum(max(0, mid - v) for v in a)
        if water <= x:
            lo = mid
        else:
            hi = mid - 1
    out.append(lo)
print("\n".join(map(str, out)))

Каждая проверка сужает отрезок примерно вдвое: из 15 высот остаются 7, потом 4, 2 и 1.

Время: O(n log(M + x)) на набор в худшем случае, M = max(a). В отрезке от 1 до M + x не больше 2 · 109 высот, а 230 < 2 · 109 ≤ 231. Поэтому проверок не больше 31, и каждая складывает n чисел. Для суммы n = 2 · 105 это не больше 6,2 · 106 сложений. Дополнительная память: O(n) на набор в худшем случае: срез data[pos + 2:pos + 2 + n] и список a хранят по n чисел, а поиск хранит только lo, hi, mid и water. Вход (список data) и ответ (список out) считаем отдельно.

Решение 2. Sorting

Sorting ставит столбцы по возрастанию: a = [1, 2, 2, 3, 4, 5, 6]. Сумма water(h) не зависит от порядка столбцов, поэтому ответ не меняется. При h = 4 высоту не больше 4 имеют k = 5 столбцов: 1, 2, 2, 3 и 4. Их сумма total = 12. Они получают 3, 2, 2, 1 и 0 единиц, всего 3 + 2 + 2 + 1 + 0 = 8 = 5 · 4 − 12. Столбцы высоты 5 и 6 выше 4 и воды не получают. Для любого h так же: если ровно k столбцов имеют высоту не больше h, а total - сумма их высот, то water(h) = k · h − total. Каждый из этих столбцов добавляет h − ai, а столбец высоты h добавляет 0. Остальные столбцы выше h и воды не получают.

Чтобы найти k, перебираем k = 0, 1, 2, ... и считаем число need. Для k = 4 имеем total = 1 + 2 + 2 + 3 = 8 и a[4] = 4. Пять самых низких столбцов 1, 2, 2, 3 и 4 поднимаются до высоты 4: это те же 8 единиц, need = 5 · 4 − (8 + 4) = 8. В общем виде need = (k + 1) · a[k] − (total + a[k]), где total - сумма k самых низких столбцов, то есть a[0] + ... + a[k − 1]. Число need - вода, которая поднимает k + 1 самых низких столбцов до высоты a[k]: это water(a[k]). Цикл увеличивает k, пока need ≤ x. Для нашего a при k = 0, 1, 2, 3 и 4 получаем need = 0, 1, 1, 4 и 8, все не больше x = 9. Для k = 5 получаем need = 6 · 5 − (12 + 5) = 13 > 9. Цикл останавливается при k = 5 и total = 12.

После остановки смотрим на два последних шага. В первом наборе шаг k = 4 прошёл: water(4) = 8 ≤ 9. Шаг k = 5 остановил цикл: water(5) = 13 > 9. Значит, ответ h удовлетворяет 4 ≤ h < 5. Для такого h ровно 5 столбцов 1, 2, 2, 3 и 4 не выше h, и water(h) = 5 · h − 12. Условие 5 · h − 12 ≤ 9 даёт 5 · h ≤ 21: наибольшее целое h равно 21 // 5 = 4.

В первом наборе промежуток 4 ≤ h < 5 содержит одно целое число: ответ 21 // 5 = 4 равен a[4]. Возьмём третий набор примера: a = [1, 4, 3, 4], x = 1. После Sorting a = [1, 3, 4, 4]. Шаг k = 0 даёт need = 1 · 1 − (0 + 1) = 0 ≤ 1, поэтому total = 1 и k = 1. Шаг k = 1 даёт need = 2 · 3 − (1 + 3) = 2 > 1, и цикл останавливается при k = 1 и total = 1. Ответ лежит в промежутке 1 ≤ h < 3: только столбец высоты 1 не выше h, и water(h) = 1 · h − 1. Условие h − 1 ≤ 1 даёт h ≤ 2, и ответ равен (1 + 1) // 1 = 2. Ответ 2 лежит строго между a[0] = 1 и a[1] = 3.

В общем виде после остановки на шаге k ответ равен (x + total) // k. Шаг k − 1 прошёл: его need равен k · a[k − 1] − total ≤ x, потому что k самых низких столбцов в сумме дают total. Значит, k · a[k − 1] ≤ x + total, и (x + total) // k не меньше a[k − 1]. Шаг k остановил цикл: его need равен (k + 1) · a[k] − (total + a[k]) = k · a[k] − total > x. Значит, x + total < k · a[k], и (x + total) // k меньше a[k]. В первом наборе 5 · 4 − 12 = 8 ≤ 9 и 5 · 5 − 12 = 13 > 9. В третьем наборе 1 · 1 − 1 = 0 ≤ 1 и 1 · 3 − 1 = 2 > 1.

На первом шаге need = 1 · a[0] − (0 + a[0]) = 0 ≤ x, поэтому k ≥ 1 и деления на 0 нет. Пример: a = [1] и x = 109. Цикл делает один шаг и кончается при k = n = 1 без остановки: столбца a[1] нет. Тогда k = 1, total = 1, и ответ равен (109 + 1) // 1 = 1 000 000 001. Так же для любого набора: если цикл дошёл до k = n без остановки, в формулу входят все столбцы и верхней границы нет.

import sys

data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, x = int(data[pos]), int(data[pos + 1])
    a = sorted(map(int, data[pos + 2:pos + 2 + n]))
    pos += 2 + n
    # total - сумма k самых низких столбцов
    k, total = 0, 0
    while k < n:
        # вода, чтобы поднять k + 1 самых низких столбцов до высоты a[k]
        need = (k + 1) * a[k] - (total + a[k])
        if need > x:
            break
        total += a[k]
        k += 1
    # в формуле участвуют k самых низких столбцов: k * h - total <= x
    out.append((x + total) // k)
print("\n".join(map(str, out)))

Время: O(n log n) на набор в худшем случае: Sorting делает O(n log n) сравнений, а цикл while делает не больше n шагов. Для суммы n = 2 · 105 циклы всех наборов вместе делают не больше 2 · 105 шагов. Дополнительная память: O(n) на набор в худшем случае: срез data[pos + 2:pos + 2 + n] и отсортированный список a хранят по n чисел, а цикл хранит только k, total и need. Вход (список data) и ответ (список out) считаем отдельно.

Типичные ошибки

  • Граница hi = max(a) вместо max(a) + x. Для a = [1] и x = 109 поиск идёт по отрезку от 1 до 1 и выводит 1 вместо 1 000 000 001.
  • Сумма mid - v без max(0, ...) считает отрицательную воду. Для a = [1, 109] и x = 1 при h = 2 столбец высоты 109 даёт слагаемое 2 − 109, меньше нуля. Такая программа выводит 500 000 001 вместо 2.
