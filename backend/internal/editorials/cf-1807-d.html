Для каждого запроса нужна чётность суммы Array после замены. Prefix Sum даёт эту сумму одной формулой, без прохода по Array.

Решение 1. Prefix Sum

Первый набор примера: a = [2, 2, 1, 3, 2]. Запрос 2 3 3 заменяет a2 и a3 на 3. После замены Array состоит из трёх частей. Слева a1 = 2. В середине r − l + 1 = 2 числа, каждое равно k = 3. Справа a4 + a5 = 3 + 2 = 5. Новая сумма 2 + 3 · 2 + 5 = 13, она нечётная: YES.

Суммы слева и справа даёт Prefix Sum с номерами с 1: p[0] = 0 и p[i] = p[i − 1] + ai. Здесь p = [0, 2, 4, 5, 8, 10], и сумма всего Array total = p[5] = 10. Слева лежит p[l − 1] = p[1] = 2. Справа лежит total − p[r] = 10 − 5 = 5.

Вместе две части дают total − (p[r] − p[l − 1]). Разность p[3] − p[1] = 5 − 2 = 3 это старая сумма отрезка a2 + a3 = 2 + 1. Новая сумма 10 − 3 + 3 · 2 = 13: то же число.

Правило. Сумма al + ... + ar равна p[r] − p[l − 1]. После замены отрезка на k сумма Array равна total − (p[r] − p[l − 1]) + k · (r − l + 1).

Запрос 1 5 5 берёт весь Array. Слева ничего нет, и p[0] = 0 даёт сумму отрезка p[5] − p[0] = 10 без отдельного if. Новая сумма 10 − 10 + 5 · 5 = 25: YES.

Каждое из n чисел после замены не больше 109, поэтому новая сумма не больше 2 · 105 · 109 = 2 · 1014. Целые числа Python не переполняются, а в C++ для такой суммы нужен 64-битный тип.

Вход содержит до 2 · 105 чисел a и до 6 · 105 чисел запросов. Программа читает его одним вызовом sys.stdin.buffer.read().split() и печатает все ответы одним print.

import sys

data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, q = int(data[pos]), int(data[pos + 1])
    pos += 2
    # p[i] = a[1] + ... + a[i], p[0] = 0
    p = [0] * (n + 1)
    for i in range(1, n + 1):
        p[i] = p[i - 1] + int(data[pos])
        pos += 1
    total = p[n]
    for _ in range(q):
        l, r, k = int(data[pos]), int(data[pos + 1]), int(data[pos + 2])
        pos += 3
        # убираем старую сумму отрезка, добавляем r - l + 1 чисел k
        s = total - (p[r] - p[l - 1]) + k * (r - l + 1)
        out.append("YES" if s % 2 == 1 else "NO")
print("\n".join(out))

Время: O(n + q) на набор: n сложений для p и одна формула на запрос. Все наборы вместе дают не больше 2 · 105 сложений для p и 2 · 105 формул. Дополнительная память: O(∑n + ∑q), где ∑n и ∑q это суммы n и q по всем наборам. p хранит n + 1 чисел одного набора. Список data хранит все числа входа всех наборов. Если набор один, это 3 + n + 3q элементов: при n = q = 2 · 105 это 800 003. Ответ отдельно: в out по строке на каждый запрос всех наборов.

Что не подходит

Brute Force для каждого запроса строит новый Array и складывает все его n чисел. Это n сложений на запрос и n · q на набор, O(n · q). При n = q = 2 · 105 это 4 · 1010 сложений: слишком долго.

Типичные ошибки

  • Старая сумма отрезка равна p[r] − p[l − 1], а не p[r] − p[l]. В p[r] − p[l] нет al, поэтому новая сумма выходит больше верной на al. На первом наборе примера эта ошибка не видна. Там l = 1 или l = 2, а a1 = a2 = 2: сумма растёт на чётное число, и все пять ответов совпадают с верными. Во втором наборе все ai = 1 и p[i] = i. Запрос 3 8 13 даёт p[8] − p[3] = 5 вместо 6, сумму 10 − 5 + 13 · 6 = 83 вместо 10 − 6 + 13 · 6 = 82 и YES вместо NO.
  • Отрезок от l до r содержит r − l + 1 чисел, а не r − l. Запрос 2 3 3 заменяет два числа. С множителем r − l = 1 сумма будет 10 − 3 + 3 · 1 = 10, и ответ NO вместо YES.
  • Замену нельзя записывать в a: каждый запрос спрашивает про исходный a. Иначе после запросов 2 3 3, 2 3 4 и 1 5 5 получится a = [5, 5, 5, 5, 5]. Запрос 1 4 9 тогда даст 9 · 4 + 5 = 41 и YES. Верная сумма 9 · 4 + 2 = 38 чётная: NO.
