Числа приходят по одному, и каждое сразу встаёт в начало или в конец Deque. Сторону выбирает одно сравнение нового числа с первым числом Deque.

Решение 1. Greedy на Deque

Возьмём p = [3, 1, 2, 4] из примера. Первое число 3 ложится в пустой Deque: d = [3]. У пустого Deque начало и конец совпадают, поэтому здесь выбора нет.

Число 1 даёт два варианта: [1, 3] или [3, 1]. Следующие числа 2 и 4 встают только слева или справа от этой пары. Сделаем для 2 и 4 одни и те же ходы в обоих вариантах. Тогда слева от пары стоят одни и те же числа, справа тоже. Например, ходы «2 в конец, 4 в начало» дают [4, 1, 3, 2] и [4, 3, 1, 2]. Первое различие стоит на месте пары: 1 против 3. Число 1 меньше 3, поэтому вариант [1, 3] выигрывает при любых следующих ходах. Ход d.appendleft(1) даёт d = [1, 3].

Число 2 даёт [2, 1, 3] или [1, 3, 2]. Первое различие теперь 2 против 1, а 1 меньше. Поэтому 2 идёт в конец: d = [1, 3, 2]. Число 4 больше d[0] = 1 и тоже идёт в конец. Получаем [1, 3, 2, 4]: это ответ первого набора примера.

Правило. Новое число x в начале даёт [x, d[0], ...], а в конце [d[0], ..., x]. Все числа разные, поэтому эти варианты различаются уже в первом числе: x против d[0]. Если x < d[0], кладём x в начало, иначе в конец.

Следующие числа встают только снаружи от текущего Deque. При одних и тех же следующих ходах оба варианта получают одинаковые числа слева и справа, и меньший вариант остаётся меньшим. Пусть цепочка ходов на шаге с числом x нарушает правило. Замена этого одного хода при тех же остальных ходах даёт меньшую последовательность. Поэтому наименьшую последовательность дают только ходы по правилу, и Greedy делает именно их.

В начало встаёт только число меньше d[0]. Поэтому d[0] всегда равно наименьшему из уже добавленных чисел. Для p = [4, 6, 2, 5, 1, 3] в начало встают 2 и 1: каждое меньше всех чисел перед ним. Числа 6, 5 и 3 идут в конец в порядке прихода. Ответ [1, 2, 4, 6, 5, 3].

import sys
from collections import deque

data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n = int(data[pos])
    d = deque()
    # первое число: Deque пуст, начало и конец совпадают
    d.append(int(data[pos + 1]))
    for i in range(pos + 2, pos + 1 + n):
        x = int(data[i])
        # [x, d[0], ...] или [d[0], ..., x]: первое различие x и d[0]
        if x < d[0]:
            d.appendleft(x)
        else:
            d.append(x)
    pos += 1 + n
    out.append(" ".join(map(str, d)))
print("\n".join(out))

Время: O(n) на набор в худшем случае. Цикл делает n − 1 сравнений x < d[0], а Deque получает n добавлений, каждое за O(1). Для [3, 1, 2, 4] это 3 сравнения и 4 добавления. Во всех наборах вместе не больше 2 · 105 чисел, и каждый набор делает на одно сравнение меньше, чем у него чисел. Поэтому все наборы вместе делают меньше 2 · 105 сравнений. Дополнительная память: O(1) для любого входа: рабочее состояние - числа t, n, pos, i и x. Deque d хранит сам ответ из n чисел. Вызов join собирает из него строку ответа, и в out лежат t таких строк. Список data хранит все 1 + t + ∑n чисел входа, где ∑n - сумма n по всем наборам.

Что не подходит

Python list вместо Deque: вызов a.insert(0, x) сдвигает каждое число a на одно место вправо. На убывающем входе каждое число встаёт в начало, и сдвигов 0 + 1 + ... + (n − 1) = n(n − 1)/2. При n = 2 · 105 это 19 999 900 000 сдвигов, около 2 · 1010: слишком долго.

Типичные ошибки

  • Сравнение с последним числом d[-1]. В третьем наборе примера p = [3, 1, 2]. После d = [1, 3] число 2 меньше d[-1] = 3 и встаёт в начало: ответ [2, 1, 3] вместо [1, 3, 2].
  • Сравнение с предыдущим числом p, а не с d[0]. Для p = [1, 3, 2] число 2 меньше предыдущего числа 3 и встаёт в начало: ответ [2, 1, 3] вместо [1, 3, 2].
