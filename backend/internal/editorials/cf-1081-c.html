Смена - это кирпич, цвет которого не совпадает с цветом соседа слева. Нужно посчитать раскраски ряда ровно с k сменами.

Brute Force перебирает все mn раскрасок и в каждой считает смены. При n = 4 и m = 3 это 34 = 81 раскраска. При n = m = 2000 это 20002000 раскрасок, число из 6603 цифр: слишком долго.

Решение 1. Combinations и Product Rule

Пример 2: n = 3, m = 2, k = 1, цвета Ж и С. Сменой может быть только кирпич 2 или кирпич 3: у кирпича 1 нет соседа слева. Одно место смены из двух выбираем C(2, 1) = 2 способами.

Пусть смена на кирпиче 2. Кирпич 1 красим в любой из 2 цветов. Кирпич 2 должен отличаться от кирпича 1, поэтому для него остаётся m − 1 = 1 цвет. Кирпич 3 не смена: он повторяет цвет кирпича 2. Получаем ЖСС и СЖЖ. Смена на кирпиче 3 даёт ЖЖС и ССЖ. Всего 2 · 2 · 1 = 4 раскраски, как в примере.

В общем случае сменой может быть любой кирпич от 2 до n: это n − 1 мест. Места k смен выбираем C(n − 1, k) способами. Потом красим кирпичи слева направо, и цвет соседа слева уже известен. Кирпич 1 красим m способами. Каждый кирпич смены красим в один из m − 1 цветов: все цвета, кроме цвета соседа слева. Каждый другой кирпич повторяет цвет соседа слева: 1 способ. Product Rule даёт ответ C(n − 1, k) · m · (m − 1)k.

Раскраска ССЖ сама задаёт свой выбор: смена на кирпиче 3, кирпич 1 цвета С, кирпич 3 цвета Ж. Поэтому ССЖ получается только из этого выбора. И наоборот, каждый выбор даёт раскраску ровно с k сменами: кирпич смены отличается от соседа слева, а другой кирпич совпадает с ним. Значит, формула считает каждую раскраску ровно один раз.

Проверим формулу при n = 4 и m = 3. Для k = 0, 1, 2, 3 она даёт 3, 18, 36 и 24. Brute Force по всем 81 раскраске даёт те же числа. Сумма 3 + 18 + 36 + 24 = 81: у каждой раскраски от 0 до 3 смен.

Осталось найти C(n − 1, k) по модулю M = 998244353. Список fact хранит fact[i] = i! % M для i от 0 до n − 1. Делить остатки нельзя, поэтому деление на k! и (n − 1 − k)! заменяем умножением на обратные элементы: pow(fact[k], M - 2, M), как в лекции Modular Arithmetic. Обратный элемент есть, потому что M простое. Числа k! и (n − 1 − k)! - произведения чисел не больше 1999. Ни одно из этих чисел на M не делится.

При n = 4, m = 3 и k = 2 список fact = [1, 1, 2, 6], а C(3, 2) = 3! / (2! · 1!) = 6 / 2 = 3. Обратный элемент числа 2 равен pow(2, M - 2, M) = 499122177: произведение 2 · 499122177 = 998244354 = M + 1 даёт остаток 1. Обратный элемент числа 1! = 1 равен 1. Тогда 6 · 499122177 · 1 = 2994733062 = 3 · M + 3, и остаток 3 равен C(3, 2). Ответ 3 · 3 · 22 = 36.

Формула верна и для крайних случаев. При m = 1 и k = 0 pow(0, 0, M) равно 1, и ответ 1: все кирпичи одного цвета. При m = 1 и k ≥ 1 pow(0, k, M) равно 0: другого цвета нет. При n = 1 список fact = [1], C(0, 0) = 1, и ответ m.

import sys

M = 998244353
n, m, k = map(int, sys.stdin.readline().split())
fact = [1] * n
for i in range(1, n):
    fact[i] = fact[i - 1] * i % M
# C(n - 1, k): делим на k! и (n - 1 - k)! умножением на обратные элементы
c = fact[n - 1] * pow(fact[k], M - 2, M) % M * pow(fact[n - 1 - k], M - 2, M) % M
print(c * m % M * pow(m - 1, k, M) % M)

Время: O(n + log M): n − 1 шагов цикла для fact и три вызова pow. Показатели степени не больше M − 2 = 998244351, у этого числа 30 двоичных цифр, поэтому одна pow делает не больше 60 умножений. Дополнительная память: O(n): список fact из n чисел.

Решение 2. Dynamic Programming

Пусть f[i][j] - число раскрасок первых i кирпичей с j сменами. Один кирпич красим m способами, и смен у него нет: f[1][0] = m, а f[1][j] = 0 при j ≥ 1.

Добавим справа кирпич i + 1. Если его цвет равен цвету кирпича i, число смен не меняется: 1 способ. Если цвет другой, смен становится на одну больше: m − 1 способов. Поэтому f[i + 1][j] = f[i][j] + f[i][j − 1] · (m − 1). При j = 0 второго слагаемого нет.

Возьмём n = 4, m = 3, k = 2. Строка i = 1 равна [3, 0, 0]. Для i = 2 получаем f[2][1] = 0 + 3 · 2 = 6 и строку [3, 6, 0]. Для i = 3 строка [3, 12, 12], для i = 4 строка [3, 18, 36]. Ответ f[4][2] = 12 + 12 · 2 = 36, как у решения 1.

Новая строка зависит только от предыдущей, поэтому код хранит одну строку f. Список [0] + f сдвигает её на одно место вправо, и zip даёт пары f[j] и f[j − 1]. Для строки [3, 6, 0] это список [0, 3, 6, 0] и пары (3, 0), (6, 3), (0, 6). zip останавливается в конце более короткого списка, поэтому последнее число списка [0, 3, 6, 0] пары не получает: оно дало бы столбец k + 1 = 3. Новая строка [3, 6 + 3 · 2, 0 + 6 · 2] = [3, 12, 12]. Число f[i + 1][j] берёт числа только из столбцов j и j − 1. Поэтому столбцы больше k на ответ не влияют, и строка хранит j от 0 до k.

import sys

M = 998244353
n, m, k = map(int, sys.stdin.readline().split())
# f[j]: число раскрасок первых i кирпичей с j сменами, сначала i = 1
f = [m] + [0] * k
for i in range(2, n + 1):
    # a = f[j], b = f[j - 1]; список [0] + f даёт b = 0 при j = 0
    f = [(a + b * (m - 1)) % M for a, b in zip(f, [0] + f)]
print(f[k])

Время: O(n · (k + 1)): n − 1 новых строк по k + 1 чисел. При n = 2000 и k = 1999 это 1999 · 2000 = 3 998 000 вычислений. Python в браузере (Pyodide) на нашем компьютере делает их меньше чем за 1 с, а ограничение по времени 2 с. Дополнительная память: O(k + 1): строка f из k + 1 чисел, список [0] + f из k + 2 чисел и новая строка. Вся таблица f[i][j] при n = 2000 заняла бы 2000 · 2000 = 4 · 106 чисел.

Типичные ошибки

  • C(n, k) вместо C(n − 1, k). Кирпич 1 не бывает сменой, поэтому мест n − 1. В примере 2 C(3, 1) · 2 · 1 = 6 вместо 4.
  • mk вместо (m − 1)k. Кирпич смены не может взять цвет соседа слева. В примере 2 C(2, 1) · 2 · 21 = 8 вместо 4.
  • Модуль 109 + 7 из примеров главы. Здесь модуль 998244353. При n = 20, m = 10, k = 10 верный ответ 615551622, а с модулем 109 + 7 получится 671408633.
  • Целочисленное деление остатков: fact[n - 1] // (fact[k] * fact[n - 1 - k]). При n = 14 и k = 7 нужно C(13, 7) = 1716. Но 13! больше M, и fact[13] = 237554682. Тогда 237554682 // (5040 · 720) = 65, а не 1716.
