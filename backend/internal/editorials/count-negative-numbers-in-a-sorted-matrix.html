Нужно посчитать клетки с числом меньше 0. Ноль неотрицательный: в примере 2 есть число 0, и ответ 0.

Brute Force сравнивает с 0 каждую клетку. В примере 1 это 16 сравнений. Для Matrix 100 × 100 это 100 · 100 = 10 000 сравнений: время O(m · n). Порядок чисел позволяет прочитать меньше клеток.

Решение 1. Binary Search

Возьмём ряд 2 примера 1: [1, 1, −1, −2]. Для каждого числа запишем «да», если оно отрицательное, и «нет», если оно неотрицательное. Ответы идут «нет, нет, да, да»: сначала неотрицательные числа, потом отрицательные. Если число отрицательное, то числа правее него не больше него и тоже отрицательные. Для −1 в индексе 2 число правее равно −2. Если число неотрицательное, то числа левее него не меньше него и тоже неотрицательные. Для 1 в индексе 1 число левее равно 1.

Пусть j - индекс первого отрицательного числа, а n - длина ряда. В ряду 2 это j = 2, и ряд даёт n − j = 4 − 2 = 2 отрицательных числа. Если в ряду нет отрицательных чисел, считаем j = n. Ряд [3, 2] из примера 2 даёт j = 2 и 2 − 2 = 0 отрицательных.

Binary Search ищет j. Индекс j лежит от lo до hi. Сначала lo = 0 и hi = n = 4: значение j = 4 значит «отрицательных чисел нет», поэтому отрезок от lo до hi включает 4. Первая середина mid = (0 + 4) // 2 = 2. Число −1 отрицательное, поэтому j ≤ 2 и hi = mid = 2. Вторая середина (0 + 2) // 2 = 1. Число 1 неотрицательное, поэтому j ≥ 2 и lo = mid + 1 = 2. Теперь lo = hi = 2: j = 2 после двух проверок.

Для рядов 0, 1, 2, 3 примера 1 индекс j равен 3, 3, 2, 0. Ряды дают 1 + 1 + 2 + 4 = 8 отрицательных чисел. Всего Binary Search сделал 2 + 2 + 2 + 3 = 9 проверок.

Правило. Инвариант: индекс j первого отрицательного числа лежит от lo до hi. Значение j = len(row) значит «отрицательных нет», поэтому hi начинается с len(row). Если row[mid] < 0, то hi = mid, иначе lo = mid + 1. При lo = hi ряд даёт len(row) - lo отрицательных чисел. Пока lo < hi, середина меньше hi, и чтение row[mid] остаётся в ряду: для lo = 3 и hi = 4 середина равна 3, а не 4.

class Solution:
    def countNegatives(self, grid: list[list[int]]) -> int:
        count = 0
        for row in grid:
            lo, hi = 0, len(row)
            while lo < hi:
                mid = (lo + hi) // 2
                if row[mid] < 0:
                    hi = mid  # первое отрицательное число в индексе mid или левее
                else:
                    lo = mid + 1  # числа с индексами от 0 до mid неотрицательные
            count += len(row) - lo
        return count

Время: O(m log n) в худшем случае: m рядов, и на каждый ряд не больше 7 проверок при n = 100. После проверки разность hi - lo не больше прежней разности, делённой нацело на 2: 100, 50, 25, 12, 6, 3, 1, 0. Для Matrix 100 × 100 это не больше 7 · 100 = 700 проверок вместо 10 000. Дополнительная память: O(1) в худшем случае: числа count, lo, hi, mid и переменная row: она указывает на ряд входа, копии ряда нет. Вход и ответ не считаем.

Решение 2. Two Pointers

Столбцы тоже упорядочены. Начнём в левом нижнем углу: ряд i = m - 1 = 3 и столбец j = 0 в примере 1. Одна проверка grid[i][j] < 0 убирает ряд или столбец. Это Two Pointers: позиции i и j двигаются только в одну сторону, i вверх, j вправо. Клетку (i, j) читаем как ряд i и столбец j.

Клетка (3, 0) хранит −1: число отрицательное. Числа правее него в ряду 3 не больше −1, поэтому весь ряд от столбца 0 до конца отрицателен. Прибавляем n − j = 4 − 0 = 4 и переходим на ряд выше: i = 2. Клетка (2, 0) хранит 1: число неотрицательное. Числа над ним в столбце 0 равны 3 и 4, они не меньше 1. Значит, в столбце 0 нет отрицательных чисел в рядах от 0 до 2, и j = 1.

Клетка (2, 1) тоже хранит 1, и j = 2. В клетке (2, 2) лежит −1: ряд 2 отрицателен от столбца 2 до конца, это n − j = 4 − 2 = 2 числа. Столбцы 0 и 1 ряда 2 хранят 1 и 1: отрицательных там нет. Путь по примеру 1 проходит клетки (3, 0), (2, 0), (2, 1), (2, 2), (1, 2), (1, 3), (0, 3): 7 проверок. Ряды 3, 2, 1, 0 дают 4, 2, 1, 1 отрицательных чисел: 4 + 2 + 1 + 1 = 8.

Правило. Инвариант: ряды ниже i уже посчитаны, а в рядах от 0 до i левее столбца j нет отрицательных чисел. Отрицательная клетка даёт count += n - j и i -= 1. Неотрицательная клетка даёт j += 1.

Цикл кончается и при j = n. В примере 2 клетки (1, 0) и (1, 1) хранят 1 и 0: обе неотрицательные, и j становится 2 = n при i = 1. Левее столбца 2 лежит весь ряд, поэтому по инварианту в рядах 0 и 1 нет отрицательных чисел, и ответ 0.

class Solution:
    def countNegatives(self, grid: list[list[int]]) -> int:
        m, n = len(grid), len(grid[0])
        count = 0
        i, j = m - 1, 0
        while i >= 0 and j < n:
            if grid[i][j] < 0:
                count += n - j  # ряд i отрицателен от столбца j до конца
                i -= 1
            else:
                j += 1  # в столбце j ряды от 0 до i неотрицательны
        return count

Время: O(m + n) в худшем случае. Путь идёт только вверх и вправо и остаётся в Matrix: не больше m − 1 шагов вверх и n − 1 шагов вправо. Шагов не больше m + n − 2, а клеток на одну больше: m + n − 1. Для 4 × 4 это 7 клеток, для 100 × 100 это 199. Дополнительная память: O(1) в худшем случае: числа m, n, count, i, j. Вход и ответ не считаем.

Типичные ошибки

  • Условие row[mid] <= 0 вместо row[mid] < 0 считает ноль отрицательным. В примере 2 ряд [1, 0] даёт j = 1 вместо 2, то есть 2 − 1 = 1 отрицательное число вместо 0. Ответ 1 вместо 0.
  • Отрезок hi = len(row) - 1 вместо hi = len(row). Ряд [3, 2] не имеет отрицательных чисел, но поиск не может дать j = 2: он даёт j = 1, то есть 2 − 1 = 1 отрицательное число вместо 0. Пример 2 даёт ответ 2 вместо 0.
