Ответ строится прямо в начале chars: для каждой группы её символ, а для группы длиннее 1 ещё и цифры длины. Ниже n это длина chars.

Решение 1. Two Pointers

Возьмите пример 1: chars = ["a", "a", "b", "b", "c", "c", "c"]. Индекс read читает ячейки слева направо. Индекс write показывает ячейку для следующего символа ответа. В начале группы код запоминает её первую ячейку в start. Потом read идёт вправо, пока chars[read] равен chars[start]. Когда read останавливается, длина группы равна count = read - start.

  • Группа "aa": start = 0, read = 2, count = 2. Код пишет "a" в ячейку 0 и "2" в ячейку 1, write = 2.
  • Группа "bb": start = 2, read = 4, count = 2. Символы "b" и "2" идут в ячейки 2 и 3, write = 4.
  • Группа "ccc": start = 4, read = 7, count = 3. Символы "c" и "3" идут в ячейки 4 и 5, write = 6.

Теперь read = 7 = n, и внешний цикл заканчивается. Метод возвращает 6, первые 6 ячеек содержат ["a", "2", "b", "2", "c", "3"].

Цифры длины без временной String. В примере 3 у группы "b" длина count = 12. Её цифры идут слева направо: сначала 1, потом 2. Код ищет power, наибольшую степень 10, которая не больше count. Сначала power = 1. Число 10 не больше 12, поэтому power = 10. Число 100 больше 12, и поиск заканчивается. Здесь // это деление нацело, а % 10 оставляет последнюю цифру. Первая цифра 12 // 10 % 10 = 1. Потом power = 10 // 10 = 1 и вторая цифра 12 // 1 % 10 = 2. Потом power = 1 // 10 = 0, и цикл цифр заканчивается. Без остатка % 10 вторая цифра была бы 12 // 1 = 12.

Рисунок показывает пример 3 по шагам. После группы "b" индекс read = 13 стоит за концом chars. Ячейки от 4 до 12 хранят старые "b": read их уже прочитал, и в ответ они не входят. Метод возвращает 4.

Почему запись не портит непрочитанные символы. Код пишет группу только после того, как read прошёл её целиком. Группа длины 1 занимает в ответе 1 ячейку: в примере 3 группа "a" даёт только "a" в ячейке 0. Группа длины count ≥ 2 занимает 1 ячейку для символа и по одной ячейке для каждой цифры count. При n ≤ 2000 длина группы имеет не больше четырёх цифр. Длина из одной цифры здесь не меньше 2, из двух цифр не меньше 10, из трёх цифр не меньше 100, из четырёх цифр не меньше 1000. Такие группы занимают 2, 3, 4 и 5 ячеек, и это не больше их длины.

Значит, если перед группой write ≤ start, то после неё write ≤ start + count = read. В начале write = read = 0. Поэтому write никогда не обгоняет read, и код пишет только в ячейки, которые read уже прошёл. Все сравнения с chars[start] идут до первой записи группы, поэтому символ группы ещё не изменён. В примере 1 после группы "ccc" write = 6, а read = 7.

Инвариант. Перед каждой группой первые write ячеек содержат сжатую запись символов левее read, и write ≤ read. В примере 1 перед группой "ccc" write = read = 4, а первые 4 ячейки содержат ["a", "2", "b", "2"].

Время: read проходит каждую из n ячеек один раз. Пусть g это число групп. Сравнение chars[read] == chars[start] выполняется n + g − 1 раз: n раз оно верно и g − 1 раз неверно. Последняя группа останавливается на условии read < n без сравнения. Записей столько, сколько символов в ответе, не больше n. Для длины из d цифр цикл power проверяет условие d раз и делает d − 1 шагов power *= 10, а цикл цифр делает d записей. У каждой группы длины count ≥ 2 цифр меньше, чем count, поэтому всех цифр меньше n. Итого O(n) в худшем случае. В примере 1 n = 7 и g = 3: 7 + 3 − 1 = 9 сравнений и 6 записей. Дополнительная память: числа n, read, write, start, count и power, O(1) для любого входа. Вызов str от одной цифры даёт один символ. Ответ лежит в самом chars.

class Solution:
    def compress(self, chars: list[str]) -> int:
        n = len(chars)
        read = write = 0
        while read < n:
            start = read
            while read < n and chars[read] == chars[start]:
                read += 1
            count = read - start
            chars[write] = chars[start]  # write ≤ start: эту ячейку read уже прошёл
            write += 1
            if count > 1:
                power = 1
                while power * 10 <= count:  # наибольшая степень 10, не больше count
                    power *= 10
                while power > 0:
                    chars[write] = str(count // power % 10)  # цифры слева направо
                    write += 1
                    power //= 10
        return write

Другие способы

Цикл for c in str(count) тоже пишет верные цифры. Но str(count) создаёт временную String из всех цифр count: O(log(n + 1)) дополнительной памяти. При count = 2000 это 4 символа, а условие требует постоянную память и для цифр.

Можно собрать ответ в новой String и потом скопировать её в chars. Ответ будет верным, но новая String хранит до n символов: для ["a", "b", "c"] все 3 символа. Это O(n) дополнительной памяти.

Типичные ошибки

  • Цифры с конца. Цикл while count > 0 пишет count % 10 и делит count нацело на 10, поэтому младшая цифра идёт первой. В примере 3 такой код оставляет ["a", "b", "2", "1"].
  • Длина 1 тоже записана. Тогда группа длины 1 занимает 2 ячейки, и write обгоняет read. Для ["a", "b"] код пишет "1" в ячейку 1 поверх непрочитанной "b". Потом read читает "1" как новую группу, и запись в ячейку 2 даёт IndexError.
  • Последняя группа потеряна. Код пишет группу, только когда видит следующий символ другой группы. После цикла последняя группа остаётся незаписанной. В примере 1 такой код возвращает 4: группы "ccc" нет в ответе.
