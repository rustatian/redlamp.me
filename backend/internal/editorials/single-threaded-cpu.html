Процессор выбирает только из пришедших задач. Решение держит пришедшие задачи в Min-Heap и пропускает время простоя одним присваиванием.

Решение 1. Sorting и Min-Heap

Сначала код делает Sorting троек (приход, длительность, номер) по времени прихода. В примере 1 arr = [(1, 2, 0), (2, 4, 1), (3, 2, 2), (4, 1, 3)]. Указатель j идёт по arr слева направо. Задача попадает в Min-Heap h парой (длительность, номер), когда её приход не больше текущего времени t.

В Python (2, 2) < (4, 1), так как 2 < 4. И (2, 1) < (2, 2): длительности равны, а 1 < 2. То есть Python сравнивает пары сначала по длительности, а при равных длительностях по номеру. Значит, heappop выдаёт самую короткую задачу, а из равных по длительности задачу с меньшим номером. Так процессор выбирает задачу по условию.

Пример 1. В начале t = 0 и h пуст, поэтому код ставит t = max(0, 1) = 1. После задачи 0, в момент 3, в h лежат (4, 1) и (2, 2), и первой выходит (2, 2). Ответ [0, 2, 3, 1].

Перед каждым heappop в h лежат все пришедшие и ещё не выполненные задачи, и только они. Внутренний цикл кладёт задачи, пока arr[j][0] ≤ t. Он останавливается на первой задаче с приходом больше t или в конце arr. arr отсортирован, поэтому у всех задач правее приход тоже больше t. Задачи с равным приходом входят в h за один проход внутреннего цикла, поэтому их порядок в arr не важен. Каждая задача входит в h один раз, поэтому выполненная задача в h не возвращается. Значит, h хранит ровно доступные задачи, и heappop берёт из них ту же задачу, что и процессор из условия.

Перед внутренним циклом h может быть пуст. Тогда из h вышли все j задач, которые в него вошли: j = len(order) < n. Значит, arr[j] существует, и arr[j][0] - ближайший приход среди задач, которых ещё нет в h. Если arr[j][0] > t, процессор простаивает до этого момента. Если задача пришла раньше, во время прошлой задачи, max оставляет t без изменения. В примере 1 при t = 3 так и есть: t = max(3, 2) = 3. В тесте [[1, 3], [10, 2], [10, 2]] задача 0 работает с 1 до 4. Затем h пуст, и t = max(4, 10) = 10. В момент 10 обе задачи 1 и 2 входят в h. Длительности равны 2, поэтому первой идёт задача 1.

Можно ждать по одной единице времени: t += 1, пока ничего не пришло. Тогда код делает один шаг ожидания на каждую единицу простоя. Для tasks = [[1, 1], [109, 1]] это 999 999 999 шагов ожидания: слишком долго. Можно и без Heap проверять все n задач при каждом выборе. Каждый выбор проверяет n задач, выборов n: O(n²). При n = 105 это около 1010 проверок: тоже слишком долго.

import heapq


class Solution:
    def getOrder(self, tasks: list[list[int]]) -> list[int]:
        n = len(tasks)
        arr = sorted((a, d, i) for i, (a, d) in enumerate(tasks))  # по времени прихода
        h = []  # пришедшие задачи: (длительность, номер)
        order = []
        t = 0
        j = 0  # arr[j] - первая задача, которой ещё нет в h
        while len(order) < n:
            if not h:
                t = max(t, arr[j][0])  # процессор ждёт следующий приход
            while j < n and arr[j][0] <= t:
                a, d, i = arr[j]
                heapq.heappush(h, (d, i))
                j += 1
            d, i = heapq.heappop(h)
            order.append(i)
            t += d
        return order

Время: n - число задач. Sorting стоит O(n log(n + 1)). Код делает n heappush и n heappop, каждый за O(log(n + 1)). Внешний цикл делает n шагов, поэтому строка с max выполняется не больше n раз. Итого O(n log(n + 1)) в худшем случае. В примере 1 код делает 4 heappush и 4 heappop. Дополнительная память: arr хранит n троек, h не больше n пар: O(n). В примере 2 все задачи приходят в 7, и в h сразу 5 пар. Ответ order отдельно: O(n), n номеров.

Типичные ошибки

  • Sorting только по длительности. Для tasks = [[1, 5], [10, 1]] такой порядок равен [1, 0]. Правильно [0, 1]: в момент 1 задача 1 ещё не пришла.
  • t = arr[j][0] без max. Для tasks = [[1, 3], [2, 5], [3, 1]] задача 0 заканчивается в 4, h пуст, и код ставит t = 2. В h входит только задача 1, и ответ [0, 1, 2]. Правильно [0, 2, 1]: в момент 4 пришли обе задачи, и задача 2 короче.
  • arr[j][0] < t вместо arr[j][0] ≤ t. В примере 1 при t = 1 условие 1 < 1 ложно, h остаётся пустым, и heappop даёт IndexError. Задача с приходом ровно t уже доступна.
