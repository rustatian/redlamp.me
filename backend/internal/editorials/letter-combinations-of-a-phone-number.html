Нужно перебрать все способы выбрать по одной букве для каждой цифры.

Решение 1. Backtracking

Возьмите пример 1: digits = "23". Цифра 2 даёт букву a, b или c, цифра 3 даёт d, e или f. Выбор для одной цифры не зависит от выбора для другой, поэтому ответов 3 · 3 = 9.

Пусть n это длина digits. Перемножим числа букв на кнопках всех цифр и назовём результат R: это число ответов. На кнопках 7 и 9 по 4 буквы, на остальных по 3. Поэтому у "79" 4 · 4 = 16 ответов, а больше всего ответов у "9999": R = 44 = 256. Ответы не повторяются: два разных набора выборов различаются хотя бы для одной цифры, а буквы одной кнопки разные. Так у "22" ответы ab и ba различаются уже на месте 0.

Функция dfs(i) выбирает букву для цифры digits[i]. Общий для всех вызовов list path хранит буквы, уже выбранные для цифр с номерами от 0 до i − 1. Цикл по KEYS[digits[i]] пробует каждую букву кнопки: кладёт её в path, вызывает dfs(i + 1) и убирает её через path.pop(). При i == len(digits) в path лежат все n букв, и ''.join(path) даёт один ответ для res.

Для "23" вызовы идут уровнями: 1 вызов dfs(0), 3 вызова dfs(1) и 9 вызовов dfs(2). Всего 13 вызовов. Рисунок показывает вызовы по порядку.

После path.pop() в path снова те же буквы, что до path.append(ch). На шаге 3 рисунка join даёт ответ ad. Затем pop убирает d, append кладёт e, и на шаге 4 path равен ['a', 'e']. После ответа af два pop убирают f и a, append кладёт b, и на шаге 6 path равен ['b']. Так ветки d, e и f после буквы a начинаются с одного и того же path = ['a']. Каждый набор выборов доходит до join ровно один раз: ответы не теряются и не повторяются.

KEYS = {'2': 'abc', '3': 'def', '4': 'ghi', '5': 'jkl',
        '6': 'mno', '7': 'pqrs', '8': 'tuv', '9': 'wxyz'}


class Solution:
    def letterCombinations(self, digits: str) -> list[str]:
        res = []
        path = []

        def dfs(i):
            if i == len(digits):
                res.append(''.join(path))
                return
            for ch in KEYS[digits[i]]:
                path.append(ch)
                dfs(i + 1)
                path.pop()  # path снова такой, как до append

        dfs(0)
        return res

Время: на уровне i вызовов столько, сколько вариантов у первых i цифр. Для "9999" уровни дают 1, 4, 16, 64 и 256 вызовов, всего 341. На каждой кнопке не меньше 3 букв, поэтому каждый уровень хотя бы в 3 раза больше предыдущего. Последний уровень даёт R вызовов, уровень перед ним не больше R/3, ещё на один раньше не больше R/9. При n ≤ 4 уровней перед последним не больше 4, и вместе они дают не больше R/3 + R/9 + R/27 + R/81 = 40R/81 вызовов. Это меньше R/2, поэтому всего вызовов меньше 1,5 · R: для "9999" это 341 < 384, для "23" это 13 < 13,5. Каждый вызов, кроме dfs(0), идёт после одного append и перед одним pop. R вызовов с i == len(digits) делают join из n букв: nR символов. Вызовы, append и pop дают O(R) шагов, join даёт nR символов: всего O(nR) в худшем случае. Для "23" join пишет 18 символов, для "9999" 1024.

Дополнительная память: path хранит до n букв, а Call Stack держит до n + 1 вызовов dfs: O(n). KEYS хранит 8 кнопок при любом входе. Ответ занимает nR символов.

Решение 2. Расширение префиксов в цикле

Те же ответы можно строить без Recursion. После i шагов цикла list level хранит все варианты первых i цифр. Сначала level = ['']: один пустой префикс. Цифра d продлевает каждый префикс каждой буквой своей кнопки. Для "23" после цифры 2 в level 3 префикса, после цифры 3 их 9. Последний level и есть ответ.

Вариант первых i + 1 цифр состоит из варианта первых i цифр и одной буквы кнопки digits[i]. Запись [p + ch for p in level for ch in KEYS[d]] берёт каждую пару из префикса p и буквы ch один раз. Поэтому новый level содержит каждый вариант ровно один раз.

KEYS = {'2': 'abc', '3': 'def', '4': 'ghi', '5': 'jkl',
        '6': 'mno', '7': 'pqrs', '8': 'tuv', '9': 'wxyz'}


class Solution:
    def letterCombinations(self, digits: str) -> list[str]:
        level = ['']
        for d in digits:
            # каждый префикс продлеваем каждой буквой кнопки d
            level = [p + ch for p in level for ch in KEYS[d]]
        return level

Время: шаг с цифрой номер i, считая с 1, создаёт столько String длины i, сколько вариантов у первых i цифр. Для "23" шаги пишут 3 · 1 + 9 · 2 = 21 символ. Для "9999" шаги пишут 4 + 32 + 192 + 1024 = 1252 символа. Следующий шаг создаёт хотя бы в 3 раза больше String, и каждая из них длиннее. Поэтому каждый шаг пишет меньше трети символов следующего шага. Последний шаг пишет nR символов, и, как в решении 1, шаги перед ним вместе пишут меньше половины от nR, а всего меньше 1,5 · nR. Для "9999" это 1252 < 1536. Время O(nR) в худшем случае.

Дополнительная память: пока строится новый level, старый ещё хранится. Для "9999" перед последним шагом старый level хранит 64 String по 3 буквы: 192 символа. path решения 1 на этом входе хранит не больше 4 букв. Каждый level содержит не больше R String длины не больше n, поэтому дополнительная память O(nR) в худшем случае. Последний level это ответ.

Типичные ошибки

  • Нет path.pop() после dfs(i + 1). Тогда path только растёт. Для "23" такой код вернёт 9 String, но верна только первая: ad. Вторая уже ade, третья adef.
  • Буквы кнопки по формуле chr(ord('a') + 3 * (int(d) - 2) + j) для j = 0, 1, 2. Формула считает, что на каждой кнопке 3 буквы. На кнопке 7 их 4, поэтому формула теряет s и сдвигает кнопки 8 и 9. Для "8" она даёт s, t, u вместо t, u, v, а для "79" 9 ответов вместо 16.
