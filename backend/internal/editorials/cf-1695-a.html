В сетке 4 × 4 из примера возьмём три верхние строки и два левых столбца. Наибольшее число внутри такого прямоугольника равно 15. Сдвинем его на один столбец вправо, и максимум станет равен 16. По размеру 3 × 2 Michael не может определить, какое число назвать.

При высоте 3 в сетке 4 × 4 верхняя строка может быть 1 или 2: начиная со строки 3, прямоугольник доходит до строки 5. При ширине 2 левый столбец может быть 1, 2 или 3: начиная со столбца 4, прямоугольник доходит до столбца 5. Каждая пара верхней строки и левого столбца задаёт одно положение. Поэтому у прямоугольника 3 × 2 в этой сетке есть 2 · 3 = 6 положений. Brute Force проверяет все размеры: для каждого положения просматривает все клетки внутри и находит максимум. Здесь на каждое из шести положений приходится шесть клеток, всего 6 · 6 = 36 просмотров. Если максимумы совпали во всех положениях, такой размер подходит. Среди подходящих размеров выбираем наименьшую площадь.

Для каждого размера умножим площадь прямоугольника на число вариантов верхней строки и на число вариантов левого столбца. Для размера h × w получим h · w · (n − h + 1) · (m − w + 1) просмотров клеток. Сложим эти числа для всех размеров в сетке 40 × 40 и получим 131 790 400 просмотров с учётом повторов. Есть не больше n · m размеров и не больше n · m положений для каждого размера. В каждом положении перебор проверит до n · m клеток. Время такого перебора равно O(n3 · m3) в худшем случае. Запись O(...) показывает верхнюю границу роста числа действий или объёма памяти при увеличении входа.

Решение. Положение максимума

Число 16 больше всех остальных и стоит в клетке (2, 3). Joe может накрыть эту клетку при любом допустимом размере: начнём с одной клетки и добавим соседние строки и столбцы до нужных размеров. Значит, любой ответ, кроме 16, окажется неверным хотя бы в одном положении. Все числа различны, поэтому в прямоугольнике без клетки с общим максимумом ответ будет меньше. Поэтому подходят ровно те размеры, при которых каждое положение прямоугольника накрывает клетку с общим максимумом.

От верхнего края до числа 16 идут две строки, а от нижнего три, если считать и строку с самим числом. При высоте 2 Joe может взять две нижние строки и пропустить 16. При высоте 3 верхняя полоса занимает строки с 1 по 3, а нижняя со 2 по 4. Вторая строка входит в обе полосы.

Пусть i обозначает номер строки с максимумом, считая от единицы. У верхнего края полоса должна захватить строки с 1 по i, поэтому нужна высота h ≥ i. У нижнего края в неё должны войти строки с i по n включительно, поэтому h ≥ n − i + 1. У любой полосы высоты h номер первой строки не больше n − h + 1, а номер последней не меньше h. При выполнении обоих условий n − h + 1 ≤ i ≤ h, поэтому строка i входит в каждую полосу. Наименьшая высота равна h = max(i, n − i + 1).

До третьего столбца слева нужно взять три столбца, а справа два. При ширине 2 Joe может пропустить третий столбец, взяв первые два. При ширине 3 даже у левого края прямоугольник уже захватит третий столбец, а у правого начнётся со второго. Так же считаем ширину для столбца j с максимумом: w = max(j, m − j + 1).

В примере подойдут любые три соседние строки и любые три соседних столбца. При любом их сочетании внутри будет клетка (2, 3), поэтому минимальная площадь равна 3 · 3 = 9. В общем случае строки и столбцы тоже можно выбирать независимо. Произведение минимальной высоты и минимальной ширины даёт наименьшую площадь h · w.

В сетке из одной клетки со значением -7 максимум тоже равен -7. Код начинает с best = None, чтобы первое прочитанное число стало максимумом даже при отрицательном значении. Когда встречается большее число, код сохраняет его в best и запоминает его координаты в i и j.

import sys

read = sys.stdin.readline


def minimum_area(n, m):
    best = None
    for r in range(1, n + 1):
        row = list(map(int, read().split()))
        for c, value in enumerate(row, 1):
            if best is None or value > best:
                best = value
                i, j = r, c

    h = max(i, n - i + 1)
    w = max(j, m - j + 1)
    return h * w


t = int(read())
answers = []
for _ in range(t):
    n, m = map(int, read().split())
    answers.append(str(minimum_area(n, m)))
print("\n".join(answers))

Для сетки 4 × 4 программа просматривает 16 чисел и разбирает по 4 числа в строке. Время: O(n · m) в худшем случае для одной сетки. Дополнительная память: O(m) в худшем случае на обработку одной сетки: при чтении строки код хранит её части и список чисел.

В примере число сеток t = 3, общее число клеток S = 1 + 16 + 6 = 23, а наибольшая ширина M = 4. Программа читает три пары размеров, а перед печатью join соединяет ответы 1, 9 и 4. Площадь не больше 40 · 40 = 1600, поэтому в каждом ответе не больше четырёх цифр. Чтение t пар размеров и соединение t ответов занимают O(t) времени в худшем случае. В каждой сетке есть хотя бы одна клетка, поэтому t ≤ S. Для всего ввода время равно O(S) в худшем случае. Перед печатью список из t коротких ответов и строка, которую из них собирает join, занимают память одновременно. Для всего ввода нужно O(M + t) памяти в худшем случае.
