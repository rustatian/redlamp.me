В тройке [5, 5, 7] можно заменить 5 на 1, а 7 на 2. Результат каждого сравнения сохранится. Дадим разным числам номера в порядке их первого появления. Тогда первое число равно 1, а самый большой номер не больше n.

При n = 3 перебор проверит и [1, 2, 2], и [1, 3, 3]: обе тройки дают NEN. Первое число оставим равным 1, а для каждой следующей позиции переберём все номера от 1 до n. Для тройки получится 3 · 3 = 9 вариантов для проверки. Если проверять все n пар в каждом из nn−1 вариантов, при n = 50 понадобится 5050 сравнений. Запись O(...) задаёт верхнюю границу роста времени или расхода памяти при увеличении размера входа. Здесь число сравнений равно n · nn−1 = nn, поэтому время перебора в худшем случае равно O(nn).

Решение 1. Подсчёт букв N

Для EEE подходит тройка [5, 5, 5]. Если в строке нет N, можно поставить одно число на все позиции.

Для ENE поставим 5 на первую позицию. Первая E требует 5 на второй позиции. Последняя E сравнивает третье число с первым, поэтому третье число тоже равно 5. Средняя N требует, чтобы эти две пятёрки различались. Такой же конфликт возникает при одной N в круге любой длины. Если от одного числа этой пары дойти до другого по кругу в обход N, на пути будут только равенства. Значит, числа в паре равны.

В ENNEENE три буквы N. Если пропустить эти три сравнения, получатся три группы позиций. Позиции 7, 1, 2 соединены буквами E через конец строки. Позиция 3 стоит отдельно, а позиции 4, 5, 6 образуют ещё одну группу. Дадим этим группам номера 1, 2 и 3 соответственно.

Если букв N хотя бы две, то на пути в обход каждой из них встретится ещё одна N. Поэтому числа этой пары принадлежат разным группам. Можно присвоить каждой группе свой номер. Тогда внутри группы выполняются все равенства, а на каждой границе числа различаются. Счётчик count_n хранит число букв N, поэтому программа выводит NO только при count_n == 1.

t = int(input())
answers = []

for _ in range(t):
    s = input()
    count_n = 0
    for letter in s:
        if letter == "N":
            count_n += 1
    answers.append("NO" if count_n == 1 else "YES")

print("\n".join(answers))

Время: на четырёх строках примера цикл проверит 3 + 2 + 7 + 4 = 16 букв. В ответах YES, NO, YES, YES всего 11 букв. Метод join добавляет между ответами три перевода строки и получает строку из 14 символов. В каждом ответе не больше трёх букв, поэтому сбор, объединение и печать t ответов занимают O(t) времени. В каждой входной строке хотя бы две буквы, поэтому сумма длин L не меньше 2t. В худшем случае время равно O(n) для одной строки и O(L) для всей программы с учётом вывода. Дополнительная память: в худшем случае O(1) для подсчёта без учёта входной строки. Для всей программы нужно O(t) дополнительной памяти в худшем случае. В момент вызова join список answers хранит все t ответов, пока строится строка для печати.

Решение 2. Dynamic Programming

Пройдём по NENN от числа 1. По первой N можно перейти к 2, а по E придётся остаться на 2. Следующая N разрешает перейти как к 1, так и к 3. Из 3 по последней N можно вернуться к 1 или перейти к 2.

Переменная same показывает, можно ли после прочитанных букв получить 1. Переменная other показывает, можно ли получить какое-нибудь другое число. В начале пути доступно только число 1. При E обе переменные сохраняют свои значения.

При N перейти к 1 можно с любого числа, кроме самой единицы, поэтому новым значением same становится прежнее other. Перейти к числу, отличному и от текущего, и от 1, можно всегда. Для этого подойдёт хотя бы одно из чисел 2 и 3, поэтому other получает значение True.

В последнем столбце у same и other стоит «да»: таблица учитывает оба пути до проверки на возврат. Путь до 1 замыкает круг, а у пути до 2 конец отличается от начала. Поэтому ответ YES возможен ровно тогда, когда после последней буквы same равно True.

t = int(input())
answers = []

for _ in range(t):
    s = input()
    same, other = True, False
    for letter in s:
        if letter == "N":
            same, other = other, True
    answers.append("YES" if same else "NO")

print("\n".join(answers))

Время: на каждую букву приходится одна проверка и не более одного обновления пары переменных. Сбор и печать ответов занимают O(t) времени, как в первом решении. Поэтому в худшем случае время равно O(n) для одной строки и O(L) для всех наборов. Дополнительная память: без учёта входной строки для двух переменных нужно O(1) в худшем случае. С учётом списка ответов и строки, которую собирает join, всей программе нужно O(t) дополнительной памяти в худшем случае.
