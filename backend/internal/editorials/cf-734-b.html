Решение. Greedy

При вводе 1 1 1 1 можно собрать либо 32, либо 256: на оба числа не хватит двоек. Если разобрать 32 и взять его двойку для 256, сумма вырастет на 256 − 32 = 224.

Пока есть свободные пятёрка и шестёрка, для нового 256 нужна только одна двойка. Если двойка свободна, прибавим 256 к сумме. Если двойка входит в 32, достаточно разобрать только это число. В обоих случаях сумма растёт, поэтому сначала соберём как можно больше чисел 256.

При вводе 5 1 3 4 первыми закончатся пятёрки: их хватит на три числа 256. Число таких троек цифр n256 равно наименьшему из k2, k5 и k6.

В примере осталось 5 − 3 = 2 двойки и одна тройка. Соберём ещё одно число 32 и получим 3 · 256 + 32 = 800. Для 32 берём по одной тройке и одной оставшейся двойке, пока есть обе цифры. Поэтому n32 равно меньшему из двух чисел: k3 и k2 − n256.

Первые два кадра рисунка ниже показывают оба шага для 5 1 3 4. Третий кадр сравнивает вводы 1 1 1 1 и 2 1 1 1. Если добавить к 1 1 1 1 вторую цифру 2, после сборки 256 останется k2 − n256 = 2 − 1 = 1 двойка. Эта двойка вместе с единственной тройкой позволяет собрать ещё и число 32, поэтому максимальная сумма растёт с 256 до 288.

k2, k3, k5, k6 = map(int, input().split())
n256 = min(k2, k5, k6)
n32 = min(k2 - n256, k3)
print(256 * n256 + 32 * n32)

Пусть L и R обозначают длины строки ввода и записи ответа. Время: O(L + R) в худшем случае на единственный набор за весь запуск. Программа читает строку целиком, делает два вызова min и печатает одно число. Дополнительная память: O(L + R) в худшем случае за запуск. При разборе строки split() создаёт список из четырёх строк, а при печати нужна строка ответа. При заданных пределах длины чисел ограничены, поэтому для стандартной записи входа обе оценки равны O(1).
