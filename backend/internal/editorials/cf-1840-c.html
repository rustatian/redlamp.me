Нужно посчитать отрезки подряд идущих дней: в каждом не меньше k дней, и каждый день в нём не жарче q. Дни нумеруются с 1, как в условии.

Подходящие дни и блоки

Пример: a = [0, 3, -2, 5, -4, -4], k = 1, q = 3 (последний набор примера). День подходит, если ai ≤ q. Подходят дни 1, 2, 3 со значениями 0, 3, −2 и дни 5, 6 со значениями −4, −4. День 4 горячий: 5 > 3. Блок - это подходящие дни подряд, которые нельзя продлить влево или вправо. Здесь два блока: дни 1..3 и дни 5..6. Отпуском называем выбранный отрезок дней. Отпуск не содержит день 4, поэтому он целиком лежит в одном блоке.

В блоке из 3 дней при k = 1 есть 6 отпусков: [1], [2], [3], [1, 2], [2, 3], [1, 2, 3]. В блоке из 2 дней есть 3 отпуска: [5], [6], [5, 6]. Всего 6 + 3 = 9, это ответ набора.

Brute Force берёт каждый первый день и двигает последний день вправо до горячего дня или до конца. Каждая пара (первый день, последний день) - один шаг. Если все дни подходят, шагов n(n + 1)/2: это O(n2) в худшем случае. При n = 2 · 105 это 20 000 100 000 шагов: слишком долго.

Решение 1. Sliding Window

Фиксируем последний день отпуска r и считаем отпуска, которые кончаются в этот день. Пусть run - число подходящих дней подряд, которые кончаются в день r. Эти дни образуют окно: оно начинается в первый день блока. Если день r горячий, run = 0 и окна нет.

В примере при r = 3 значение run = 3: подходят дни 1, 2, 3. Отпуск с последним днём 3 может начаться в день 1, 2 или 3. Это три отпуска: [1, 2, 3], [2, 3], [3]. Начало s не левее первого дня блока: s ≥ r − run + 1 = 3 − 3 + 1 = 1. Длина r − s + 1 не меньше k: s ≤ r − k + 1 = 3 − 1 + 1 = 3. Подходят начала s = 1, 2, 3. Их число (r − k + 1) − (r − run + 1) + 1 = run − k + 1 = 3.

Окно короче k не даёт отпусков. Пример: a = [12, 12, 10, 15], k = 3, q = 12 (третий набор примера). Дни 1, 2, 3 подходят, день 4 горячий. В день 1 значение run = 1, и run − k + 1 = 1 − 3 + 1 = −1. Начало s должно быть не меньше r − run + 1 = 1 − 1 + 1 = 1 и не больше r − k + 1 = 1 − 3 + 1 = −1. Такого s нет, поэтому прибавляем max(0, −1) = 0. В день 3 значение run = 3, и run − k + 1 = 1: один отпуск [1, 2, 3]. В день 4 значение run = 0, и run − k + 1 = −2: прибавляем 0. Ответ 1.

Правило. В день r кончается max(0, run − k + 1) отпусков. Ответ - сумма этих чисел по всем дням r. Отпуск кончается ровно в один день, поэтому сумма не считает его дважды.

Код читает весь вход в список data. Для текущего набора pos - позиция температуры дня 1. Температура дня r лежит в data[pos + r - 1]: это шаг цикла с i = pos + r - 1.

import sys

data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, k, q = int(data[pos]), int(data[pos + 1]), int(data[pos + 2])
    pos += 3
    run = 0
    res = 0
    for i in range(pos, pos + n):
        # run - число подходящих дней подряд, которые кончаются в этот день
        if int(data[i]) <= q:
            run += 1
        else:
            run = 0
        # run - k + 1 вариантов начала: от первого дня блока до дня на k - 1 раньше текущего
        res += max(0, run - k + 1)
    pos += n
    out.append(res)
print("\n".join(map(str, out)))

Время: O(n) в худшем случае на набор: один шаг цикла на день. Все наборы вместе дают не больше Σn ≤ 2 · 105 шагов, где Σn - сумма n по всем наборам. Дополнительная память: O(1) в худшем случае: числа t, pos, n, k, q, run, res, i и счётчик цикла по наборам. Список data хранит 1 + 3t + Σn слов входа, список out хранит t чисел ответа. Вход и ответ считаем отдельно от дополнительной памяти.

Решение 2. Формула для блока

Решение 1 прибавляет вклад каждого дня. Блок можно посчитать сразу, когда он закончился. Пример: блок из run = 3 дней и k = 2. Считаем отпуска по первому дню. Отпуск с первым днём 1 кончается в день 2 или 3: 2 отпуска. С первым днём 2 он кончается в день 3: 1 отпуск. С первым днём 3 длина не больше 1, а нужно не меньше 2: 0 отпусков. Всего 2 + 1 = 3.

Для первого дня блока подходят m = run − k + 1 длин: в примере m = 3 − 2 + 1 = 2, длины 2 и 3. Для каждого следующего дня на одну длину меньше: m, m − 1, ..., 1, дальше 0. Сумма 1 + 2 + ... + m равна m(m + 1)/2: при m = 3 это 1 + 2 + 3 = 6 = 3 · 4 / 2, а в примере 2 · 3 / 2 = 3. Если run < k, то m ≤ 0 и отпусков нет.

Это те же числа, что прибавляет Решение 1: в блоке из 3 дней при k = 2 вклады дней равны 0, 1, 2, и их сумма 3. Для a = [0, 3, -2, 5, -4, -4], k = 2, q = 3 блоки из 3 и 2 дней дают 3 и 1, всего 4.

import sys


def ways(run, k):
    # m - число подходящих длин для первого дня блока
    m = run - k + 1
    return m * (m + 1) // 2 if m > 0 else 0


data = sys.stdin.buffer.read().split()
t = int(data[0])
pos = 1
out = []
for _ in range(t):
    n, k, q = int(data[pos]), int(data[pos + 1]), int(data[pos + 2])
    pos += 3
    run = 0
    res = 0
    for i in range(pos, pos + n):
        if int(data[i]) <= q:
            run += 1
        else:
            # горячий день закрыл блок из run дней
            res += ways(run, k)
            run = 0
    res += ways(run, k)
    pos += n
    out.append(res)
print("\n".join(map(str, out)))

Время: O(n) в худшем случае на набор: n шагов цикла и не больше n + 1 вызовов ways. В ways нет цикла. Дополнительная память: O(1) в худшем случае: те же числа и число m в ways. Списки data и out - вход и ответ, как в Решении 1.

Типичные ошибки

  • Значение run не сбрасывается на горячем дне. Для a = [1, 5, 1], k = 1, q = 1 значения run были бы 1, 1, 2, и ответ 4 вместо 2.
  • Нет max(0, ...). Для a = [12, 12, 10, 15], k = 3, q = 12 вклады были бы −1, 0, 1, −2, и ответ −2 вместо 1.
  • Знак < вместо ≤: день с ai = q тоже подходит. Для a = [3, 3], k = 1, q = 3 верный ответ 3, а со знаком < получится 0.
  • В Решении 2 нет проверки m > 0. Блок из 1 дня при k = 4 даёт m = 1 − 4 + 1 = −2, и m(m + 1)/2 = (−2) · (−1)/2 = 1: отпуск, которого нет.
  • В Решении 2 не посчитан последний блок. Для a = [1, 1], k = 1, q = 1 горячего дня нет, и без последнего вызова ways ответ 0 вместо 3.
  • 32-битное целое: при n = 2 · 105, k = 1 и всех подходящих днях ответ 20 000 100 000 больше 2 147 483 647. В Python целое число растёт само.
