Нужно найти наименьшее число, которое есть и в nums1, и в nums2. Пусть n - длина nums1, а m - длина nums2. Brute Force сравнивает каждое x из nums1 с каждым y из nums2: в худшем случае n · m сравнений. При n = m = 105 это 1010 сравнений: слишком долго. Оба Array упорядочены, и это позволяет сравнивать намного меньше.

Решение 1. Binary Search

Возьмите пример 2: nums1 = [1, 2, 3, 6] и nums2 = [2, 3, 4, 5]. Берём числа nums1 слева направо и каждое ищем в nums2 через Binary Search. Первое найденное число и есть ответ.

Число 1: lo = 0, hi = 3, mid = 1. Число nums2[1] = 3 больше 1, поэтому hi = 0. Теперь mid = 0, число nums2[0] = 2 больше 1, поэтому hi = −1. Отрезок [lo, hi] пуст: числа 1 нет в nums2. Число 2: mid = 1, nums2[1] = 3 больше 2, hi = 0. Потом mid = 0, и nums2[0] = 2 равно 2. Ответ 2 после 4 проверок.

Правило. Для каждого x по порядку ищем x в nums2. Первое найденное x возвращаем. Если не нашлось ни одного x, возвращаем -1.

Первое найденное x - наименьшее общее число. В примере 2 число 1 не нашлось, значит, оно не общее. Число 2 нашлось, и оно общее. Любое общее число меньше 2 стояло бы в nums1 левее 2, а левее стоит только 1. В общем случае nums1 упорядочен: все числа правее x не меньше x. Поэтому общее число меньше x стояло бы левее x, а числа левее x уже искали и не нашли. Одинаковые числа ищутся повторно, но результат тот же: для nums1 = [5, 5, 5, 7] и nums2 = [1, 7, 7] число 5 ищется три раза и не находится, потом находится 7. Ответ 7.

Binary Search находит x в nums2, если оно там есть. Если x есть в nums2, его место всё время лежит в отрезке [lo, hi]. Для x = 1 число nums2[1] = 3 больше 1, а nums2 упорядочен, поэтому nums2[1], nums2[2] и nums2[3] тоже больше 1. Среди них нет числа 1, и код делает hi = mid − 1 = 0.

class Solution:
    def getCommon(self, nums1: list[int], nums2: list[int]) -> int:
        for x in nums1:
            lo, hi = 0, len(nums2) - 1
            while lo <= hi:
                mid = (lo + hi) // 2
                if nums2[mid] == x:
                    return x  # nums1 упорядочен: первое найденное x самое маленькое
                if nums2[mid] < x:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return -1

Время: один поиск делает не больше ⌊log2 m⌋ + 1 проверок, где ⌊log2 m⌋ - это log2 m, округлённый вниз. Каждая проверка оставляет не больше половины отрезка. Для m = 105 это 16 + 1 = 17, потому что 216 = 65 536 ≤ 105 < 131 072 = 217. Поисков не больше n, поэтому всего O(n log m) в худшем случае. При n = m = 105 это не больше 1,7 · 106 проверок. Дополнительная память: O(1) в худшем случае: числа x, lo, hi и mid. Входные Array не копируются.

Решение 2. Two Pointers

Решение 1 начинает каждый поиск с полного отрезка nums2. Two Pointers проходят оба Array по одному разу. Возьмите nums1 = [1, 3, 5, 6] и nums2 = [2, 4, 6]. Указатель i стоит на nums1[0] = 1, указатель j на nums2[0] = 2.

Сравниваем 1 и 2. Число 1 меньше 2, а nums2 упорядочен: все числа nums2 от места j не меньше 2, и числа 1 среди них нет. Число 1 пропускаем: i = 1. Теперь 3 больше 2, а в nums1 от места i все числа не меньше 3, и числа 2 среди них нет. Число 2 пропускаем: j = 1. Дальше 3 и 4: i = 2. Потом 5 и 4: j = 2. Потом 5 и 6: i = 3. Наконец 6 и 6 равны, ответ 6.

Правило. Если nums1[i] == nums2[j], это ответ. Иначе сдвигаем указатель того числа, которое меньше. Когда указатель дошёл до конца своего Array, возвращаем -1.

Указатели не проходят мимо ответа. Ответ 6 стоит в nums1 на месте 3, а в nums2 на месте 2. Сначала i = 0 и j = 0, то есть i ≤ 3 и j ≤ 2. Указатель i сдвигается, только если nums1[i] < nums2[j]. При i = 3 это значит 6 < nums2[j], но j ≤ 2, поэтому nums2[j] не больше nums2[2] = 6: сдвига нет. Указатель j сдвигается, только если nums1[i] > nums2[j]. При j = 2 это значит nums1[i] > 6, но i ≤ 3, поэтому nums1[i] не больше nums1[3] = 6: сдвига нет. Значит, всегда i ≤ 3 и j ≤ 2. В примере пары (i, j) такие: (0, 0), (1, 0), (1, 1), (2, 1), (2, 2), (3, 2).

Так как 3 < 4 = n и 2 < 3 = m, условие цикла всегда верно. Каждый шаг без ответа увеличивает i + j на 1, а i + j ≤ 3 + 2 = 5, поэтому цикл не идёт бесконечно и кончается возвратом: код возвращает первую пару с равными числами v = nums1[i] = nums2[j]. Число v общее, поэтому v ≥ 6, ведь 6 - наименьшее общее. С другой стороны, i ≤ 3, поэтому v ≤ nums1[3] = 6. Значит, v = 6. Если общих чисел нет, равной пары не будет, и цикл кончится, когда i = n или j = m: ответ −1.

class Solution:
    def getCommon(self, nums1: list[int], nums2: list[int]) -> int:
        i, j = 0, 0
        while i < len(nums1) and j < len(nums2):
            if nums1[i] == nums2[j]:
                return nums1[i]
            if nums1[i] < nums2[j]:
                i += 1  # nums1[i] меньше всех чисел nums2[j:], его там нет
            else:
                j += 1  # nums2[j] меньше всех чисел nums1[i:], его там нет
        return -1

Время: каждый шаг цикла двигает один указатель, то есть увеличивает i + j на 1, или возвращает ответ. Цикл идёт, пока i < n и j < m, значит, в каждом шаге i + j ≤ n + m − 2. Поэтому шагов не больше n + m − 1, всего O(n + m) в худшем случае. При n = m = 105 это не больше 199 999 шагов. Дополнительная память: O(1) в худшем случае: числа i и j.

Какое решение выбрать

При n = m = 105 в худшем случае Two Pointers делают меньше шагов, чем Binary Search проверок. При n = 10 и m = 105 Binary Search делает не больше 10 · 17 = 170 проверок, а Two Pointers до 105 + 10 − 1 = 100 009 шагов. Binary Search выгоднее, когда n мало, а m велико.

Ещё один способ: Hash Table

Строка s = set(nums2) один раз кладёт числа nums2 в Hash Table. Потом для каждого x из nums1 по порядку проверяем x in s. Первое x, которое есть в s, и есть ответ, как в решении 1. Время: ожидаемое O(n + m): m вставок в s и не больше n проверок x in s, каждая в среднем занимает O(1). Дополнительная память: O(m) в худшем случае: s хранит до m чисел. Решения 1 и 2 не копируют nums2.

Типичные ошибки

  • Ответ как меньшее из первых чисел: min(nums1[0], nums2[0]). В примере 2 это min(1, 2) = 1, но числа 1 нет в nums2. Верный ответ 2.
  • return -1 внутри цикла for, сразу после первого ненайденного x. Для nums1 = [1, 2, 3] и nums2 = [2, 4] число 1 не найдено, и код возвращает −1. Верный ответ 2.
  • Binary Search с while lo < hi. Для nums1 = [1] и nums2 = [1] сразу lo = hi = 0, цикл не начинается, и ответ −1 вместо 1.
  • В решении 2 условие цикла с or вместо and. Для nums1 = [1, 2, 3] и nums2 = [4] указатель i доходит до 3 при j = 0, и nums1[3] даёт IndexError.
