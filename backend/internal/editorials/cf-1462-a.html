Из списка [9, 2, 7, 1] можно по очереди удалять числа с левого и правого края. Но при удалении числа 9 через pop(0) Python сдвинет три оставшихся элемента. После удаления числа 1 справа останется [2, 7], и при удалении числа 2 сдвинется ещё один элемент. При n = 300 из каждой пары одно число удаляем слева, всего 300 / 2 = 150 раз. Число сдвигов при удалении слева убывает на два, от 299 до 1. В среднем это (299 + 1) / 2 = 150 сдвигов, а всего 150 · 150 = 22 500. При чётном n оба множителя равны n / 2. При любой длине доски удаляем n чисел, и каждое удаление сдвигает не больше n − 1 элементов. Время такого решения для одного набора в худшем случае равно O(n2).

Решение 1. Two Pointers

На доске b = [3, 4, 5, 2, 9, 1, 1] число 3 стоит у левого края, а число 1 у правого. Именно эти места Поликарп занял первыми. Между ними остались числа [4, 5, 2, 9, 1]. На третьем ходу Поликарп записал 4 в первую свободную клетку слева (left = 1). На четвёртом ходу он записал 1 в первую свободную клетку справа (right = 5).

Пусть left и right хранят индексы первого и последнего из ещё не прочитанных чисел. Добавим в ответ b[left] и увеличим left на один. Если числа ещё остались, добавим b[right] и уменьшим right на один. После каждой пары на участке от left до right остаются только места для более поздних ходов. Поэтому для следующей пары подходит тот же порядок чтения.

В середине примера left = right = 3. Берём b[3] = 2 слева, и left становится равным 4. Теперь left > right, поэтому проверка перед чтением справа не даст записать середину дважды. Получился ответ [3, 1, 4, 1, 5, 9, 2].

import sys

read = sys.stdin.readline
t = int(read())
answers = []
for _ in range(t):
    n = int(read())
    b = read().split()
    left = 0
    right = n - 1
    a = []
    while left <= right:
        a.append(b[left])
        left += 1
        if left <= right:
            a.append(b[right])
            right -= 1
    answers.append(" ".join(a))

print("\n".join(answers))

В наборах длины 7 и 4 код добавляет в a всего 7 + 4 = 11 чисел. На этом входе из двух наборов вызовы read() читают построчно 28 символов (2, 7, 3 4 5 2 9 1 1, 4 и 9 2 7 1 с переводами строки). Вызовы split() делят строки досок на 7 + 4 = 11 частей. Числа можно оставить строками, потому что меняется только их порядок. Для этих двух наборов " ".join(a) собирает строки ответа длиной 7 + 6 = 13 и 4 + 3 = 7 символов с учётом пробелов. Затем "\n".join(answers) соединяет их в строку из 13 + 1 + 7 = 21 символа, а print добавляет перевод строки и выводит 22 символа. Обозначим сумму длин всех наборов через S. В каждом наборе n ≥ 1, поэтому число наборов t ≤ S, и внешний цикл делает не больше S шагов. В записи каждого bi до 109 не больше 10 цифр, а в числах t и n до 300 не больше 3 цифр. При одиночных пробелах строка доски из n чисел с переводом строки содержит не больше 11n символов, а строка для n или t занимает до 4 символов. Поэтому на один набор read() и split() читают до 11n + 4 символов, а весь вход содержит не больше 11S + 4t + 4 ≤ 15S + 4 символов. Строка ответа " ".join(a) для одного набора имеет длину не больше 10n + (n − 1) = 11n − 1 символов. Сумма длин t строк в answers не больше 11S − t, поэтому с t − 1 переводами строки "\n".join(answers) строит до 11S − 1 символов, а print выводит до 11S символов. Вызовы read(), split(), join и print просматривают или копируют каждый символ один раз, поэтому их время работы пропорционально числу символов. Время: O(n) на один набор и O(S) на все наборы в худшем случае.

К концу прохода списки b и a содержат по 7 элементов для первого набора и по 4 для второго (в общем случае до 10 цифр в числе). Для этих двух наборов answers хранит в памяти обе строки длиной 13 и 7 символов, пока "\n".join(answers) создаёт строку из 21 символа для печати (в общем случае до 11S − 1 символов). Входные данные и напечатанный ответ считаем отдельно от этих временных списков и строк. Дополнительная память: O(n) на один набор и O(S) на все наборы в худшем случае.

Решение 2. Заполнение по чётности индекса

Прочитаем доску [9, 2, 7, 1] слева направо. Числа 9 и 2 Поликарп записал у левого края на первом и третьем ходах. На втором ходу он записал 1 у правого края, а на четвёртом поставил 7 левее единицы. На нечётных ходах левая часть растёт вправо, а на чётных правая часть растёт влево. Поэтому сначала на доске идут числа с нечётных мест ответа по порядку, а затем с чётных мест в обратном порядке.

В Python первое и третье места ответа имеют индексы 0 и 2. Запишем туда 9 и 2, а оставшиеся 7 и 1 запишем по индексам 3 и 1. Получится a = [9, 1, 2, 7]. Первый цикл проходит чётные индексы от начала, второй проходит нечётные от конца. Каждое место относится только к одной из этих групп, поэтому код заполнит его ровно раз.

Чтобы читать числа доски по одному в обоих циклах, код вызывает values = iter(read().split()). Вызов read().split() возвращает обычный список строк, например ['9', '2', '7', '1']. Сам список не помнит, какой элемент уже прочитали: вызов next прямо от списка из первого решения сразу выдаст ошибку TypeError. Функция iter создаёт по списку объект values, который хранит место следующего элемента и начинает с начала доски. На примере ['9', '2', '7', '1'] первый цикл дважды вызывает next(values): берёт '9' для a[0], затем берёт '2' для a[2] и останавливается перед '7'. Второй цикл использует тот же объект values, поэтому не возвращается к началу доски, а сразу берёт '7' для a[3] и '1' для a[1].

import sys

read = sys.stdin.readline
t = int(read())
answers = []
for _ in range(t):
    n = int(read())
    values = iter(read().split())
    a = [""] * n
    for even in range(0, n, 2):
        a[even] = next(values)
    for odd in reversed(range(1, n, 2)):
        a[odd] = next(values)
    answers.append(" ".join(a))

print("\n".join(answers))

В первом наборе длины 7 первый цикл делает 4 записи, а второй 3; во втором наборе длины 4 каждый цикл делает по 2 записи. Всего для этих двух досок код делает 7 + 4 = 11 вызовов next(values) и записей в a. Вызов iter не копирует список, а next(values) переходит к следующему элементу. Как и в решении 1, на этом примере функции read(), split(), join и print читают 28 символов входа, строят строки ответа длиной 13 и 7 символов, соединяют их в 21 символ и выводят 22 символа. По оценке из решения 1, при t ≤ S и числах до 10 цифр эти операции со строками обрабатывают не больше 11n + 4 символов входа и 11n − 1 символов строки ответа на один набор (и до 15S + 4 символов входа и 11S символов вывода на все наборы). Время: O(n) на один набор и O(S) на все наборы в худшем случае.

В одном наборе список от split() и список a занимают по n мест, а объект values хранит только текущее положение в первом списке. Для двух наборов из первого решения answers хранит те же строки длиной 13 и 7 символов, пока "\n".join(answers) собирает строку из 21 символа для печати (в общем случае до 11S − 1 символов). Входные данные и напечатанный ответ считаем отдельно. Дополнительная память: O(n) на один набор и O(S) на все наборы в худшем случае.
