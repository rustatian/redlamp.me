Для каждого номера q нужно назвать горку с этим червяком. Решение 1 ищет горку Binary Search по Prefix Sum размеров горок. Решение 2 записывает горку каждого червяка в Array.

Brute Force идёт по горкам слева направо и складывает их размеры: получается счёт червяков в пройденных горках. Он останавливается на первой горке, где счёт не меньше q. Для a = [2, 7, 3, 4, 9] и q = 11 счёт равен 2, 9, 12. Первый счёт не меньше 11 равен 12: это третья горка, ответ 3 после 3 проверок. Худший вопрос лежит в последней горке: n проверок. Для m вопросов это n · m проверок, то есть O(n · m). При n = m = 105 это 1010 проверок: слишком долго.

Решение 1. Prefix Sum и Binary Search

Если Brute Force не останавливать, его счёт после каждой горки равен 2, 9, 12, 16, 25: например, 2 + 7 = 9 после двух горок. Эти числа хранит Prefix Sum p: для a = [2, 7, 3, 4, 9] получаем p = [2, 9, 12, 16, 25]. Число p[i] - номер последнего червяка горки i + 1: индексы Array идут с 0, а горки с 1. Горка 1 кончается на номере 2, горка 2 на номере 9, горка 3 на номере 12.

Возьмём q = 11. Число p[1] = 9 меньше 11: номера до 9 лежат в горках 1 и 2, и червяка 11 среди них нет. Число p[2] = 12 не меньше 11, поэтому червяк 11 лежит в горке 3. Горка 3 - первая, где p[i] ≥ 11.

Условие p[i] ≥ 11 для индексов 0, 1, 2, 3, 4 даёт «нет, нет, да, да, да». При любом q все «нет» идут раньше всех «да»: каждое ai ≥ 1, поэтому каждое следующее число p больше предыдущего. Последнее число p равно S = a1 + ... + an, то есть числу всех червяков, а q ≤ S, поэтому «да» есть всегда. Первое «да» находит Binary Search.

Правило. Червяк q лежит в горке i + 1, где i = bisect_left(p, q): это Lower Bound, первый индекс с p[i] ≥ q.

Функция bisect_left из модуля bisect делает этот поиск. Для q = 11 поиск держит отрезок [lo, hi], в котором стоит первое «да». Сначала lo = 0 и hi = n = 5. Середина mid = (0 + 5) // 2 = 2: p[2] = 12 ≥ 11, первое «да» не правее 2, hi = 2. Теперь mid = (0 + 2) // 2 = 1: p[1] = 9 < 11, первое «да» правее 1, lo = 2. Отрезок [2, 2] даёт индекс 2 и горку 3 после 2 проверок.

Для q = 1 первый индекс равен 0, горка 1. Для q = 25 первый индекс равен 4, горка 5. Вместе с q = 11 это ответы примера: 1, 5, 3.

import sys
from bisect import bisect_left
from itertools import accumulate

data = sys.stdin.buffer.read().split()
n = int(data[0])
# p[i] - номер последнего червяка в горке i + 1
p = list(accumulate(map(int, data[1:1 + n])))
out = []
for q in map(int, data[2 + n:]):
    # первый индекс i с p[i] >= q: червяк q лежит в горке i + 1
    out.append(bisect_left(p, q) + 1)
print("\n".join(map(str, out)))

Время: O(n + m log n) в худшем случае. Prefix Sum делает n − 1 сложение. Каждый из m вопросов делает не больше ⌊log2 n⌋ + 1 сравнений: при n = 5 это 3, при n = 105 это 17. Все вопросы при n = m = 105 дают не больше 1 700 000 сравнений. Дополнительная память: O(n + m) в худшем случае. Список p хранит n чисел, срез data[1:1 + n] хранит n элементов, срез data[2 + n:] хранит m элементов. Список data с входом и список out с ответом отдельно.

Решение 2. Array владельцев

Запишем в Array owner горку каждого червяка: owner[k] - горка червяка с номером k + 1. Для a = [2, 7, 3, 4, 9] горка 1 даёт 2 записи «1», горка 2 даёт 7 записей «2», горка 3 даёт 3 записи «3», горка 4 даёт 4 записи «4», горка 5 даёт 9 записей «5». Всего S = 2 + 7 + 3 + 4 + 9 = 25 записей.

Номера червяков идут подряд, а горки по порядку, поэтому запись червяка с номером q стоит на месте q − 1. Для q = 11 это место 10: owner[10] = 3, горка 3. Червяки 10, 11, 12 горки 3 записаны в owner на местах 9, 10, 11, и все три записи равны 3.

Правило. Ответ на вопрос q равен owner[q - 1].

import sys

data = sys.stdin.buffer.read().split()
n = int(data[0])
# owner[k] - номер горки червяка с номером k + 1
owner = []
for i in range(n):
    owner += [i + 1] * int(data[1 + i])
out = [owner[int(q) - 1] for q in data[2 + n:]]
print("\n".join(map(str, out)))

Время: O(S + m) в худшем случае. Цикл делает n шагов и дописывает в owner S записей, а каждый вопрос читает одну запись. Каждое ai ≥ 1, поэтому n ≤ S. При S = 106 и m = 105 это 1 100 000 записей и чтений. Дополнительная память: O(S + m) в худшем случае. Список owner хранит S ≤ 106 чисел, срез data[2 + n:] хранит m элементов. Временный список [i + 1] * int(data[1 + i]) хранит не больше 1000 чисел. Список data с входом и список out с ответом отдельно.

Решение 2 тратит память ради времени: каждый вопрос стоит одно чтение, а в решении 1 до 17 сравнений. Но при ai = 10 и n = 105 в owner 106 записей, а в p только 105.

Типичные ошибки

  • bisect_right вместо bisect_left. Червяк 9 последний в горке 2: bisect_left(p, 9) = 1 даёт горку 2, а bisect_right(p, 9) = 2 даёт горку 3. Червяк, который лежит последним в своей горке, получает номер следующей горки.
  • Забыли прибавить 1. Для q = 11 функция bisect_left(p, 11) возвращает 2: это индекс в p, а горка имеет номер 3.
  • owner[q] вместо owner[q - 1]. Для q = 9 это owner[9] = 3, но червяк 9 лежит в горке 2. Для q = 25 в owner нет места 25: у него места от 0 до 24, и будет IndexError.
