При n = 5 Brute Force проверяет 5! = 120 порядков чисел. Заранее запишем в таблицу, какие числа простые. В порядке [5, 2, 3, 4, 1] у числа 5 отметка True, а у номера его места 1 отметка False. Если простое число стоит на месте с непростым номером, отбрасываем весь порядок. Для одного места читаем из таблицы не более двух отметок, поэтому проверка занимает O(1) времени. В каждом порядке проверяем от одного до n мест, поэтому время перебора в худшем случае O(n · n!). При n = 100 порядков больше 10157, поэтому проверок мест тоже больше 10157.

Как посчитать допустимые порядки

При n = 2 подходит только порядок [1, 2]. При n = 3 числа 2 и 3 можно поменять местами, поэтому есть два порядка. При n = 4 можно также поменять местами 1 и 4, и всего получается 2 · 2 = 4 порядка.

При n = 5 у чисел 2, 3, 5 есть ровно три места с простыми номерами. Для места 2 есть три варианта, для места 3 останется два, а место 5 займёт последнее число. С добавлением 5 число порядков в группе простых выросло с 2 до 3! = 3 · 2 · 1 = 6.

На местах 1 и 4 по-прежнему можно записать [1, 4] или [4, 1]. К каждому из шести порядков простых чисел подходят оба варианта, поэтому ответ равен 6 · 2 = 12.

Номера мест и значения берутся из одних и тех же чисел, поэтому для k простых значений есть ровно k простых мест. Остальные n − k чисел занимают оставшиеся места. Пара порядков внутри групп однозначно задаёт весь ряд. Для каждой группы берём Factorial её размера и получаем k! · (n − k)! способов.

При n = 1 простых чисел нет, а для числа 1 есть единственное место. У пустой группы один порядок, поэтому 0! = 1.

Решение 1. Trial Division

Для 23 проверяем остатки от деления на 2, 3, 4 и останавливаемся, так как 5 · 5 > 23. Для 25 проверяем и 5, так как 5 · 5 = 25. Остаток 25 % 5 = 0, поэтому 25 составное. Так проверяем каждое число value от 2 до n включительно. Если value составное, у него есть пара множителей больше единицы. Хотя бы один из них не больше √value, иначе их произведение превысит value. Если ни одно число от 2 до этой границы не делит value нацело, увеличиваем k.

При n = 5 начнём с answer = 1 и для примера возьмём модуль 5. Для группы простых чисел size = 3, поэтому умножаем answer сначала на 2, затем на 3. После первого умножения получаем 2, после второго берём остаток 6 % 5 = 1. Для второй группы size = 2, поэтому умножаем тот же answer на 2 и получаем остаток 2, как у 12 при делении на 5.

Разность произведений 6 · 2 и 1 · 2 равна 5 · 2 и делится на 5. Когда берём остаток, отбрасываем часть числа, которая делится на модуль без остатка. После умножения на factor эта часть по-прежнему делится на модуль без остатка, поэтому остатки произведений совпадают. После каждого умножения код сохраняет в answer остаток по модулю 109 + 7. При n = 1 размеры групп равны 0 и 1. В обоих случаях range(2, size + 1) пуст, поэтому answer остаётся равным 1.

class Solution:
    def numPrimeArrangements(self, n: int) -> int:
        def is_prime(value):
            divisor = 2
            while divisor * divisor <= value:
                if value % divisor == 0:
                    return False
                divisor += 1
            return True

        k = 0
        for value in range(2, n + 1):
            if is_prime(value):
                k += 1

        modulus = 10**9 + 7
        answer = 1
        for size in (k, n - k):
            for factor in range(2, size + 1):
                answer = answer * factor % modulus
        return answer

При n = 100 код проверяет делители 236 раз и делает 98 умножений для Factorial. Время: O(n√n) в худшем случае. На каждое число приходится не более √n проверок делителя, а на обе группы вместе нужно не более n умножений для Factorial. Дополнительная память: O(1) в худшем случае, так как при любом n храним лишь несколько чисел: счётчики, размеры двух групп, модуль и текущий остаток answer.

Решение 2. Sieve of Eratosthenes

При n = 10 ставим False для 0 и 1, а для чисел от 2 до 10 пока оставляем True. При p = 2 вычёркиваем сначала 4, затем 6, 8, 10. При p = 3 начинаем с 9 и до конца таблицы вычёркиваем только это число. Оба прохода начинаются после 3, поэтому у 2 и 3 остаётся True. Ещё две отметки True остаются у 5 и 7. Функция sum считает True за 1, а False за 0, поэтому k = 4.

Для p = 3 начинаем с 9 = 3 · 3, потому что 6 = 3 · 2 уже вычеркнули при p = 2. Так же для каждого простого p начинаем с p · p и идём с шагом p. Цикл вычёркивает только произведения двух чисел не меньше 2, поэтому все вычеркнутые числа составные. Отметка простого p остаётся равной True, поэтому условие if is_prime[p] выполняется.

При n = 16 проход для 2 ставит is_prime[4] = False, поэтому при p = 4 код пропускает внутренний цикл. У числа 15 = 5 · 3 есть делитель 3 меньше 5. При p = 3 переменная multiple растёт с шагом 3 и принимает значения 9, 12, 15. Запишем составное число как p · q, где оба множителя больше 1, а p - наименьший делитель больше 1. Если бы у p был делитель от 2 до p − 1, он делил бы и исходное число, вопреки выбору p. Поэтому p прост. Число q тоже делит исходное число, поэтому q ≥ p и p · q ≥ p · p. Цикл с условием p · p ≤ n дойдёт до этого делителя и вычеркнет число. Если цикл дойдёт до проверки самого составного числа, его отметка уже будет False.

class Solution:
    def numPrimeArrangements(self, n: int) -> int:
        is_prime = [True] * (n + 1)
        is_prime[0] = is_prime[1] = False
        p = 2
        while p * p <= n:
            if is_prime[p]:
                for multiple in range(p * p, n + 1, p):
                    is_prime[multiple] = False
            p += 1

        k = sum(is_prime)
        modulus = 10**9 + 7
        answer = 1
        for size in (k, n - k):
            for factor in range(2, size + 1):
                answer = answer * factor % modulus
        return answer

При n = 16 код записывает False в is_prime[12] при p = 2 и ещё раз при p = 3. При подсчёте операций учитываем каждую запись, даже если в ячейке уже было False. При n = 100 внешний цикл проверяет девять значений p от 2 до 10. Внутренний цикл запускается только для 2, 3, 5, 7 и делает 49 + 31 + 16 + 8 = 104 записи в таблицу. При p = 2 цикл начинает с 4 и посещает 49 из 50 чётных чисел от 1 до 100. Для каждого простого p ≤ √n цикл посещает кратные p от p · p до n. Всего от 1 до n есть n // p кратных p, поэтому за проход цикл делает не более n/p записей.

При n = 100 возьмём все знаменатели от 2 до √100 = 10, включая составные. Тогда число записей не больше 100 · (1/2 + 1/3 + ... + 1/10). Для знаменателей 2 и 3 сумма дробей не больше 2 · (1/2) = 1. Для знаменателей от 4 до 7 сумма не больше 4 · (1/4) = 1, а для знаменателей от 8 до 10 не больше 3 · (1/8) < 1. Так как 23 = 8, пишем log2 8 = 3. Из 8 < 10 < 16 = 24 получаем 3 < log2 10 < 4. До начала четвёртой группы знаменатели не доходят, поэтому три группы дают верхнюю границу 3 · 100 = 300 записей.

В группе со знаменателями от d до 2 · d − 1 не более d дробей, каждая не больше 1/d. Их сумма не больше 1, поэтому на группу приходится не более n записей. Первые знаменатели групп удваиваются, поэтому группа с номером j начинается с 2j. Запись log2 n показывает, в какую степень надо возвести 2, чтобы получить n. Так как степень двойки растёт с показателем, из 2j ≤ √n ≤ n следует j ≤ log2 n. Номера групп начинаются с 1, поэтому групп не больше log2 n.

Внешний цикл проверяет не более √n значений p, так как p · p ≤ n. Вне внутреннего цикла на каждое p уходит O(1) времени: проверяем условие и отметку, затем увеличиваем p. Эти шаги, начальное заполнение таблицы, подсчёт отметок и умножения для ответа вместе занимают O(n) времени. Время: O(n log n) в худшем случае (верхняя граница). Дополнительная память: O(n) в худшем случае для n + 1 отметок.
