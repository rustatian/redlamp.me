Нужна самая короткая часть s подряд, в которой хватает всех букв t. Повторы считаются: для t = "AAB" окну нужны две буквы A. Окно [l, r] - это часть s от места l до места r, места считаются с 0. Окно хорошее, если в нём хватает всех букв t, и плохое, если не хватает.

Brute Force берёт каждое начало l и двигает конец r вправо, пока окно плохое. Для s из m букв это до m + (m − 1) + ... + 1 = m(m + 1)/2 окон: столько будет, когда ни одно начало не даёт хорошего окна. Это O(m2) окон. При m = 105 это 5 000 050 000 окон: слишком долго. Каждое окно ещё нужно проверить на буквы t.

Решение 1. Sliding Window с need и missing

Возьмите пример 1: s = "ADOBECODEBANC", t = "ABC". Граница r идёт вправо и добавляет букву. Граница l идёт вправо и убирает букву. Если считать буквы окна заново на каждом шаге, шаг стоит столько действий, сколько букв в окне, до m. Поэтому код хранит счётчики need и missing.

need[c] - сколько букв c окну ещё нужно. Если need[c] меньше 0, в окне лишние буквы c. Буквы, которой нет в t, в начале нет в need: need.get(c, 0) даёт для неё 0. Когда r первый раз добавляет такую букву, строка need[c] = need.get(c, 0) - 1 создаёт в need ключ c со значением -1. missing - сколько букв t окну не хватает всего. В начале need = {"A": 1, "B": 1, "C": 1} и missing = 3. Окно хорошее, когда missing == 0. Код помнит лучшее окно из найденных: best_len - его длина, best_l - его начало. В начале best_len = len(s) + 1: окна такой длины в s нет, поэтому любое хорошее окно короче.

Начало примера 1. Буква A на месте 0: need["A"] равно 1, больше 0, поэтому missing становится 3 − 1 = 2. Букв D (место 1), O (место 2) и E (место 4) нет в t: missing не меняется, а need["D"], need["O"] и need["E"] становятся -1. Буква B на месте 3 даёт missing = 1, буква C на месте 5 даёт missing = 0. Окно [0, 5] = "ADOBEC" хорошее, длина 6: код записывает best_len = 6 и best_l = 0. Потом l убирает A: need["A"] становится 1, больше 0, поэтому missing = 1. Окно плохое, и r идёт дальше.

Продолжение. Буква A на месте 10 снова даёт missing = 0. Окно [1, 10] хорошее, длина 10, ответ не меняется. Теперь l убирает D, O, B, E. Каждая из этих букв стоит в окне два раза, а нужно не больше одной, поэтому missing остаётся 0. Окно [5, 10] имеет длину 6, как best_len: ответ не меняется. Буква C на месте 5 нужна: после её удаления missing = 1, l = 6, окно плохое. Буква C на месте 12 снова даёт missing = 0, окно [6, 12] имеет длину 7. Окно [8, 12] имеет длину 5: best_len = 5. Окно [9, 12] = "BANC" имеет длину 4: best_len = 4, best_l = 9. Потом l убирает B, missing = 1, и s кончилась. Ответ s[9:13] = "BANC".

Правило. Окно получило букву c = s[r]: если need[c] > 0, то missing -= 1; потом need[c] -= 1. Пока missing == 0, окно хорошее: запишите его, если оно короче лучшего, и уберите c = s[l]: need[c] += 1; если стало need[c] > 0, то missing += 1; потом l += 1.

missing - это сумма положительных чисел в need. В начале 1 + 1 + 1 = 3. Каждый шаг правила меняет одно число need[c] на 1. Сумма меняется на 1, когда положительное число уменьшается или когда число после увеличения положительное. Правило меняет missing ровно в этих двух случаях и тоже на 1. В примере 1 это видно на четырёх шагах. need["A"] уменьшается с 1 до 0: сумма и missing уменьшаются на 1. need["D"] уменьшается с 0 до -1: сумма и missing не меняются. need["C"] увеличивается с 0 до 1: сумма и missing растут на 1. need["D"] увеличивается с -2 до -1: сумма и missing не меняются. После буквы C на месте 5 в need нет положительных чисел, и missing = 0. Значит, в окне каждой буквы не меньше, чем в t.

Граница r никогда не идёт назад. Цикл while заканчивается, только когда окно плохое. Окно внутри плохого окна тоже плохое: в нём каждой буквы не больше, чем в большом окне. На шаге r = 9 окно [1, 9] = "DOBECODEB" плохое: в нём нет A. Окна [2, 9], ..., [9, 9] тоже плохие. Хорошие окна с началом от 1 кончаются правее 9, поэтому r идёт только вправо.

Код находит самое короткое окно. Ответ [9, 12] = "BANC". Левая граница l проходит место 9, только когда окно [9, r] хорошее. Окно [9, r] с r < 12 было бы короче "BANC", а такого хорошего окна нет. Поэтому при r = 12 граница l ещё не правее 9: она равна 6. Окна [6, 12], [7, 12] и [8, 12] содержат окно [9, 12], поэтому хорошие. Цикл идёт, пока l не станет 9, и записывает длину 4. Те же рассуждения верны для самого короткого окна любых s и t.

Если окно ни разу не стало хорошим, best_len остаётся len(s) + 1, и код возвращает "". В примере 3 s = "a", t = "aa": need = {"a": 2}, missing = 2. Буква a даёт missing = 1, и s кончается.

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = {}
        for c in t:
            need[c] = need.get(c, 0) + 1
        missing = len(t)  # сколько букв t ещё не хватает окну
        l = 0
        best_len, best_l = len(s) + 1, 0
        for r in range(len(s)):
            c = s[r]
            if need.get(c, 0) > 0:
                missing -= 1
            need[c] = need.get(c, 0) - 1
            while missing == 0:  # окно хорошее: записать длину и сжать слева
                if r - l + 1 < best_len:
                    best_len, best_l = r - l + 1, l
                need[s[l]] += 1
                if need[s[l]] > 0:
                    missing += 1
                l += 1
        return s[best_l:best_l + best_len] if best_len <= len(s) else ""

Время: m - длина s, n - длина t. Первый цикл делает n шагов, r делает m шагов. Граница l только растёт и никогда не больше m, поэтому за весь проход она делает не больше m шагов, хотя while стоит внутри for. Всего не больше n + 2m шагов, и каждый шаг делает несколько операций с need, каждая за ожидаемое O(1) для Hash Table. Итого ожидаемое O(m + n). При m = n = 105 это не больше 3 · 105 шагов. В примере 1 первый цикл делает 3 шага, r делает 13, l делает 10, а ответ записывается 3 раза. Дополнительная память: в need лежат только буквы, не больше 52 ключей: O(1) в худшем случае. Числа best_l и best_len хранят ответ, а срез делается один раз в конце. Входные строки и строка ответа в дополнительную память не входят.

Типичные ошибки

  • Проверять, что в окне есть каждая буква t, и не считать повторы. Для s = "a" и t = "aa" такая проверка принимает окно "a", а ответ - пустая строка. Счётчики дают missing = 1, и окно плохое.
  • Записывать ответ после цикла while. Для s = "a" и t = "a" цикл убирает a и делает l = 1 при r = 0. Длина r - l + 1 равна 0, меньше best_len, который равен len(s) + 1 = 2, и код вернёт "" вместо "a". Ответ записывают внутри цикла, пока окно хорошее.
