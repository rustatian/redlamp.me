Решение. Math

Возьмите пример 2: n = 25, k = 13. Кратные 13 идут с шагом 13: 13, 26, 39, 52. Частное 25 // 13 равно 1, потому что 25 = 13 · 1 + 12. Кратное 1 · 13 = 13 не больше 25. Следующее кратное (1 + 1) · 13 = 26 уже больше 25. Ответ 26.

Пример 3: n = 26, k = 13. Частное 26 // 13 равно 2, и кратное 2 · 13 = 26 равно n. Ответ должен быть больше n, поэтому снова берём следующее кратное: (2 + 1) · 13 = 39.

Правило. Пусть q = n // k. Ответ равен (q + 1) · k.

Почему ответ наименьший. Остаток 25 % 13 равен 12. Кратное 13 = 25 − 12 и все кратные до него не больше 25. Следующее кратное 26 = 25 + (13 − 12) больше 25. Между 13 и 26 других кратных 13 нет, поэтому 26 это наименьшее кратное 13, которое больше 25.

Для любых n и k то же самое: n = q · k + r, где остаток r = n % k от 0 до k − 1. Кратное q · k = n − r не больше n. Следующее кратное (q + 1) · k = n + (k − r), а k − r от 1 до k. Поэтому ответ от n + 1 до n + k. В примере 3 остаток 0, и ответ 26 + 13 = 39.

При n = 3, 6 и 9 само n делится на 3, и ответ равен n + 3.

n, k = map(int, input().split())
q = n // k  # сколько раз k целиком помещается в n
print((q + 1) * k)

Время: O(1): одно деление и одно умножение. Дополнительная память: O(1): одно число q.

Типичные ошибки

  • Формула (n + k - 1) // k * k даёт кратное не меньше n, а нужно кратное больше n. Для примера 3 она даёт 26 вместо 39.
  • Brute Force проверяет числа n + 1, n + 2 и так далее до первого кратного k. Ответ не больше n + k, поэтому проверок не больше k: это O(k). При n = k = 109 это 109 проверок: слишком долго.
