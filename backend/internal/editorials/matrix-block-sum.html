Для каждой клетки (i, j) нужна сумма её окна: квадрата из 2k + 1 строк и 2k + 1 столбцов с центром в этой клетке, без клеток за краем Matrix.

Возьмите пример 1: mat = [[1, 2, 3], [4, 5, 6], [7, 8, 9]], k = 1. Brute Force для каждой клетки складывает все клетки её окна. Окно клетки (1, 1) - вся Matrix: 9 чисел, сумма 45. Окна клеток (0, 0) и (0, 1) имеют 4 общие клетки с числами 1, 2, 4 и 5. Brute Force складывает их для каждого окна заново. В окне не больше min(m, 2k + 1) строк и min(n, 2k + 1) столбцов, где m × n - размер mat. Поэтому Brute Force делает не больше mn · min(m, 2k + 1) · min(n, 2k + 1) сложений. При m = n = 100 и k = 100 окно каждой клетки - вся Matrix из 104 клеток. Для 104 клеток ответа это 104 · 104 = 108 сложений: слишком долго. В нашем замере Python в браузере (Pyodide) тратит на них от 3,02 до 3,20 с: на нашем компьютере это немного больше лимита скрытого теста 3 с.

Решение 1. Двумерная Prefix Sum

Сложите в примере 1 клетки в строках 0..1 и столбцах 0..2: 1 + 2 + 3 + 4 + 5 + 6 = 21. Таблица P хранит такие суммы для всех прямоугольников от левого верхнего угла. P[i][j] - сумма клеток в строках 0..i − 1 и столбцах 0..j − 1, поэтому 21 лежит в P[2][3]. В P на одну строку и на один столбец больше, чем в mat: m + 1 строк и n + 1 столбцов. Строка 0 и столбец 0 таблицы P состоят из нулей: при i = 0 или j = 0 в прямоугольнике нет клеток.

Код считает каждое новое число P из клетки mat и трёх готовых чисел P. P[2][3] = mat[1][2] + P[1][3] + P[2][2] − P[1][2] = 6 + 6 + 12 − 3 = 21. Здесь P[1][3] = 6 - сумма строки выше: 1 + 2 + 3. P[2][2] = 12 - сумма столбцов левее: 1 + 2 + 4 + 5. Числа 1 и 2 входят в обе суммы, поэтому код вычитает P[1][2] = 1 + 2 = 3 один раз. Строки P для примера 1: [0, 0, 0, 0], [0, 1, 3, 6], [0, 5, 12, 21], [0, 12, 27, 45]. Рисунок показывает все 9 шагов этого цикла.

Окно клетки (2, 2) - строки 1..2 и столбцы 1..2: 5 + 6 + 8 + 9 = 28. Ту же сумму дают четыре числа P. P[3][3] = 45 - сумма всей Matrix. Строка 0 в окно не входит: код вычитает P[1][3] = 6. Столбец 0 тоже не входит: код вычитает P[3][1] = 12. Клетка (0, 0) со значением 1 стоит и в строке 0, и в столбце 0, поэтому она вычтена два раза. Код прибавляет её обратно: P[1][1] = 1. Получается 45 − 6 − 12 + 1 = 28. Для строк r1..r2 и столбцов c1..c2 формула такая: P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1].

У края окно выходит за Matrix. Для клетки (0, 2) условие даёт строки −1..1 и столбцы 1..3, но строки −1 и столбца 3 в Matrix нет. В сумму входят только клетки, которые есть в Matrix, поэтому код обрезает границы: r1 = max(0, i - k) = 0, r2 = min(m - 1, i + k) = 1, c1 = max(0, j - k) = 1, c2 = min(n - 1, j + k) = 2. Остаются строки 0..1 и столбцы 1..2: 2 + 3 + 5 + 6 = 16. Формула даёт P[2][3] − P[0][3] − P[2][1] + P[0][1] = 21 − 0 − 5 + 0 = 16. Числа P[0][3] и P[0][1] стоят в нулевой строке P, поэтому у края работает та же формула без отдельного if. Рисунок показывает все 9 клеток ответа в порядке цикла.

class Solution:
    def matrixBlockSum(self, mat: list[list[int]], k: int) -> list[list[int]]:
        m, n = len(mat), len(mat[0])
        # P[i][j]: сумма строк 0..i-1 и столбцов 0..j-1
        P = [[0] * (n + 1) for _ in range(m + 1)]
        for i in range(m):
            for j in range(n):
                P[i + 1][j + 1] = mat[i][j] + P[i][j + 1] + P[i + 1][j] - P[i][j]
        answer = [[0] * n for _ in range(m)]
        for i in range(m):
            r1, r2 = max(0, i - k), min(m - 1, i + k)
            for j in range(n):
                c1, c2 = max(0, j - k), min(n - 1, j + k)
                answer[i][j] = P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]
        return answer

Время: первый двойной цикл считает mn чисел P, второй считает mn чисел ответа, по 4 обращения к P на каждое: O(mn) для любого входа, от k число шагов не зависит. При m = n = 100 это 2 · 104 шагов вместо 108 сложений: в 5000 раз меньше. Дополнительная память: P хранит (m + 1)(n + 1) чисел, при m = n = 100 это 10 201 число: O(mn). Ответ отдельно: mn чисел в answer.

Решение 2. Prefix Sum по строкам, затем по столбцам

Окно клетки (0, 2) - строки 0..1 и столбцы 1..2. В строке 0 это 2 + 3 = 5, в строке 1 это 5 + 6 = 11, вместе 5 + 11 = 16: сумма окна собрана по строкам. Столбцы окна зависят только от j, а строки окна только от i. Поэтому код делает два прохода, и каждый считает суммы на отрезках одномерной Prefix Sum.

Первый проход считает rows[i][j]: сумму столбцов c1..c2 в одной строке i. Список p - Prefix Sum строки: p[c] равно сумме первых c чисел строки. Для строки 0 это [0, 1, 3, 6], и rows[0][2] = p[3] − p[1] = 6 − 1 = 5. Для примера 1 получается rows = [[3, 6, 5], [9, 15, 11], [15, 24, 17]].

Второй проход идёт по столбцам rows и считает сумму строк r1..r2. Для столбца 2 список p равен [0, 5, 16, 33]. answer[0][2] = p[2] − p[0] = 16 − 0 = 16, как в решении 1. answer[2][2] = p[3] − p[1] = 33 − 5 = 28. Каждая клетка окна стоит в одной из строк r1..r2 и в одном из столбцов c1..c2. Поэтому она входит ровно в одно из чисел rows[r][j], которые складывает второй проход.

class Solution:
    def matrixBlockSum(self, mat: list[list[int]], k: int) -> list[list[int]]:
        m, n = len(mat), len(mat[0])
        # rows[i][j]: сумма столбцов окна в одной строке i
        rows = []
        for i in range(m):
            p = [0]
            for x in mat[i]:
                p.append(p[-1] + x)
            rows.append([p[min(n - 1, j + k) + 1] - p[max(0, j - k)] for j in range(n)])
        answer = [[0] * n for _ in range(m)]
        for j in range(n):
            # p: Prefix Sum столбца j таблицы rows
            p = [0]
            for i in range(m):
                p.append(p[-1] + rows[i][j])
            for i in range(m):
                answer[i][j] = p[min(m - 1, i + k) + 1] - p[max(0, i - k)]
        return answer

Время: первый проход делает для каждой строки n шагов для p и n шагов для rows. Второй делает для каждого столбца m шагов для p и m шагов для answer. Вместе это 4mn шагов: O(mn) для любого входа. Дополнительная память: rows хранит mn чисел, а p не больше max(m, n) + 1 чисел: O(mn). Таблица rows годится только для одного k, а P из решения 1 даёт сумму любого прямоугольника.

Типичные ошибки

  • Строки P умножением списка: P = [[0] * (n + 1)] * (m + 1). Это m + 1 ссылок на одну и ту же строку. P[r2 + 1] и P[r1] - одна и та же строка, в примере 1 это [0, 12, 15, 18]. Каждая запись прибавляет mat[i][j] к числу этой строки с индексом j + 1, поэтому в ней стоят суммы столбцов: 1 + 4 + 7 = 12, 2 + 5 + 8 = 15 и 3 + 6 + 9 = 18. Для клетки (2, 2) код считает 18 − 18 − 12 + 12 = 0 вместо 28. Так же код получает 0 в каждой клетке ответа для любого входа. Создавайте каждую строку в цикле, как в решении 1.
  • Границы без max: r1 = i - k и c1 = j - k. Для клетки (0, 0) это −1, а индекс −1 в Python берёт последний элемент списка. Код не падает и считает 12 − 27 − 21 + 45 = 9 вместо 12.
  • Границы без min: c2 = j + k. Для клетки (0, 2) получается c2 + 1 = 4, а в строке P есть только индексы 0..3. Код падает с IndexError.
  • Формула без + P[r1][c1]. В примере 1 ошибается только клетка (2, 2): 45 − 6 − 12 = 27 вместо 28. У остальных клеток r1 = 0 или c1 = 0, и P[r1][c1] = 0. В примере 2 у всех клеток r1 = 0 и c1 = 0, и эта ошибка не видна.
  • Перепутаны m и n: c2 = min(m - 1, j + k). Оба примера имеют размер 3 × 3, и на них такой код проходит. Для mat = [[1, 2, 3, 4]], k = 1 верный ответ [[3, 6, 9, 7]], а такой код возвращает [[1, 1, 0, -2]].
