Нужно посчитать Subarray, в которых ровно k разных чисел.

Brute Force берёт каждое начало i и идёт вправо до конца Array. Он кладёт числа в set seen и прибавляет 1, когда len(seen) == k. Окон n(n + 1)/2, где n - длина nums. При n = 2 · 104 это 200 010 000 шагов: слишком долго. Можно остановить внутренний цикл при len(seen) > k, но в худшем случае это не помогает. Для 20 000 одинаковых чисел и k = 1 в seen всегда одно число, и шагов те же 200 010 000.

Решение 1. Sliding Window: «не больше k» минус «не больше k − 1»

Сначала считаем другое: окна, в которых не больше m разных чисел. Возьмите пример 1: nums = [1, 2, 1, 2, 3], m = 2. Окно [1, 2, 1, 2] подходит: в нём 2 разных числа. Любая его часть тоже подходит: в части разных чисел не больше, чем во всём окне. Поэтому для каждого конца r подходящие начала идут подряд от самого левого подходящего начала l до r. Для r = 3 это начала 0, 1, 2, 3: окна [1, 2, 1, 2], [2, 1, 2], [1, 2], [2]. Таких окон r − l + 1 = 4.

Возьмите m = 1. Начало 0 не подходит при r = 1: в [1, 2] два разных числа. При r = 2 оно тоже не подходит: в [1, 2, 1] тоже два разных числа. Правило: если начало не подошло при конце r, оно не подойдёт и при r + 1, потому что число справа не уменьшает количество разных чисел. Поэтому l и r только растут.

В коде ниже cnt - это dict: для каждого числа окна он хранит, сколько раз число стоит в окне. Число ключей len(cnt) равно числу разных чисел окна. Код кладёт в окно nums[r]. Пока ключей больше m, код убирает nums[l] и сдвигает l. Когда счётчик числа стал 0, код удаляет ключ: иначе len(cnt) считало бы число, которого в окне уже нет.

При r = 0, 1, 2, 3 окно начинается с l = 0, и код прибавляет 1, 2, 3, 4. При r = 4 число 3 даёт третий ключ, и цикл убирает числа слева: сначала 1, потом 2, потом снова 1. Число 1 стояло в окне дважды: его ключ исчез при втором удалении. Цикл остановился при l = 3: в окне из чисел 2 и 3 два ключа. Код прибавил 4 − 3 + 1 = 2. Всего 1 + 2 + 3 + 4 + 2 = 12 окон. В примере 1 соседние числа разные, поэтому при m = 1 окно состоит из одного числа: 1 + 1 + 1 + 1 + 1 = 5.

Для «ровно k» прямой подсчёт не работает: в окне [1, 2] ровно 2 разных числа, а в его части [2] одно, и часть уже не подходит. Зато окно, в котором не больше k разных чисел, имеет либо ровно k разных, либо не больше k − 1. Поэтому окон «ровно k» столько, сколько окон «не больше k» минус окон «не больше k − 1». Для примера 1 и k = 2 это 12 − 5 = 7.

Возьмите конец r = 4. Проход «не больше 2» даёт l = 3, проход «не больше 1» даёт l = 4. Начала 0, 1 и 2 дают окна с тремя разными числами. Начало 4 даёт окно [3] с одним числом. Остаётся начало 3: окно [2, 3] с ровно 2 разными числами. Разность 2 − 1 = 1 считает именно его.

class Solution:
    def subarraysWithKDistinct(self, nums: list[int], k: int) -> int:
        return self.at_most(nums, k) - self.at_most(nums, k - 1)

    def at_most(self, nums: list[int], m: int) -> int:
        cnt = {}
        l = 0
        res = 0
        for r in range(len(nums)):
            cnt[nums[r]] = cnt.get(nums[r], 0) + 1
            while len(cnt) > m:
                cnt[nums[l]] -= 1
                if cnt[nums[l]] == 0:
                    del cnt[nums[l]]  # len(cnt) считает только числа окна
                l += 1
            res += r - l + 1
        return res

Время: Проход добавляет каждое число в окно один раз и убирает из окна не больше одного раза: не больше 2n шагов. Два прохода делают не больше 4n шагов, при n = 2 · 104 это 80 000. Один шаг с Hash Table занимает ожидаемое O(1), поэтому время ожидаемое O(n). Дополнительная память: перед добавлением числа в cnt там не больше m ключей, после добавления не больше m + 1. Большее значение m равно k. Ключей не больше n, поэтому в худшем случае O(min(n, k + 1)).

При k = 1 второй вызов - это self.at_most(nums, 0), и он возвращает 0. Цикл while убирает число сразу после добавления, l становится равным r + 1, и к res прибавляется r - l + 1 = 0.

Типичные ошибки

  • Вернуть self.at_most(nums, k) без вычитания. Для примера 1 получится 12, а ответ 7: лишние 5 окон состоят из одного числа.
  • Не удалять ключ, когда его счётчик стал 0. Для примера 1 при m = 2 и r = 4 ключи 1, 2, 3 остаются в cnt со счётчиком 0, len(cnt) остаётся равным 3, цикл сдвигает l до 5, и nums[5] даёт IndexError.
