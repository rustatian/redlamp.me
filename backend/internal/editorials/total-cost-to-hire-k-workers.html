Решение повторяет k раундов условия. Чтобы не просматривать всех кандидатов в каждом раунде, решение хранит левую и правую группы в двух Min-Heap.

Решение 1. Два Min-Heap

Пример 1: costs = [17, 12, 10, 2, 7, 2, 11, 20, 8], k = 3, candidates = 4, n = 9. Левая группа - номера 0, 1, 2, 3 с ценами 17, 12, 10, 2. Правая группа - номера 5, 6, 7, 8 с ценами 2, 11, 20, 8. Номер 4 с ценой 7 не входит ни в одну группу: это середина.

Min-Heap left хранит левую группу, right - правую. Запись - tuple (цена, номер). Tuple сравниваются сначала по цене, а при равной цене по номеру. Поэтому вершина left[0] - наименьшая запись: самый дешёвый работник левой группы, а при равной цене - с меньшим номером. Середина - номера от l до r, в примере l = r = 4.

Раунд 1. Вершины (2, 3) и (2, 5). Цены равны, номер 3 меньше: нанимаем номер 3 за 2. Остались 8 работников, первые 4 из них - номера 0, 1, 2, 4. Значит, номер 4 переходит из середины в левую группу: код добавляет (7, 4) в left и ставит l = 5. Последние 4 - по-прежнему номера 5, 6, 7, 8, и right не меняется.

Раунд 2. Вершины (7, 4) и (2, 5): нанимаем номер 5 за 2. Теперь l = 5 > r = 4: середина пуста, пополнения нет. Остались номера 0, 1, 2, 4, 6, 7, 8. По условию номер 4 входит в обе группы, а в коде он лежит только в left. Раунд 3. Вершины (7, 4) и (8, 8): нанимаем номер 4 за 7. Сумма 2 + 2 + 7 = 11.

Так в каждом раунде, пока середина не пуста: left хранит первых candidates оставшихся работников, а right - последних candidates. Наём слева убирает одного из первых candidates. Его место в группе занимает первый работник середины, номер l: код добавляет его в left и увеличивает l. Правая группа при этом не меняется. Наём справа так же добавляет номер r в right и уменьшает r. Когда середина пуста, в двух Heap вместе лежат все оставшиеся, каждый один раз. В каждом Heap не больше candidates записей, поэтому оставшихся не больше 2 · candidates, и группы условия тоже содержат всех оставшихся.

Начальные указатели: l = candidates и r = max(l, n - candidates) - 1. В примере 1 это l = 4 и r = max(4, 5) − 1 = 4. Пример 2: costs = [1, 2, 4, 1], candidates = 3. Первые 3 - номера 0, 1, 2, последние 3 - номера 1, 2, 3. Здесь l = 3 и r = max(3, 1) − 1 = 2. left получает номера 0, 1, 2, right - только номер 3, и копий нет. Середина пуста с самого начала.

С max начальное r + 1 не меньше l: в примере 1 это 5 ≥ 4, в примере 2 это 3 ≥ 3. Код меняет l или r на 1 только при l <= r, поэтому всегда l ≤ r + 1. Все номера в left меньше l, а все номера в right больше r. Значит, любой номер слева меньше любого номера справа. При равной цене условие right[0] < left[0] ложно, и код берёт работника из left, как в раунде 1 примера 1.

В примере 2 код сначала берёт (1, 0) из пары вершин (1, 0) и (1, 3), затем (1, 3) из пары (2, 1) и (1, 3). В раунде 3 right пуст, и код берёт (2, 1) из left. Сумма 1 + 1 + 2 = 4. Пустой Heap не участвует в выборе: при пустом right условие right and (not left or right[0] < left[0]) ложно, а при пустом left часть not left делает его истинным. Пустой Heap бывает только при пустой середине. Тогда все оставшиеся лежат в другом Heap, а оставшиеся есть в каждом раунде, потому что k ≤ n.

Время: начальных записей h = min(n, 2 · candidates), в примере 1 это 8, в примере 2 это 4. Создание записей и два heapify стоят O(h). Повторные heappush при построении стоили бы O(h log(h + 1)) в худшем случае. Каждый из k раундов делает один heappop и не больше одного heappush. В каждом Heap не больше h записей, поэтому одна такая операция стоит O(log(h + 1)). Итого O(h + k log(h + 1)) в худшем случае. В примере 1 это 8 записей, 2 heapify, 3 heappop и 1 heappush. При n = 105, k = 1 и candidates = 1 код создаёт 2 записи, делает 1 heappop и 1 heappush. Чтение входа из n цен стоит отдельно O(n). Дополнительная память: heappush идёт только после heappop, поэтому в двух Heap вместе никогда не больше h записей: O(h). В примере 1 пик 8 записей. Ответ - одно число, O(1).

Без Heap можно делать Linear Scan всех доступных в каждом раунде. В раунде доступны min(m, 2 · candidates) работников, где m - число оставшихся. Это не больше h просмотров за раунд и O(k · h) времени в худшем случае. При n = k = 105 и candidates = 5 · 104 доступны все оставшиеся, и просмотров 105 + (105 − 1) + ... + 1 = 5 000 050 000, около 5 · 109. Это слишком долго.

import heapq


class Solution:
    def totalCost(self, costs: list[int], k: int, candidates: int) -> int:
        n = len(costs)
        l = candidates
        r = max(l, n - candidates) - 1  # середина l..r: работники, которых ещё нет в Heap
        left = [(costs[i], i) for i in range(l)]
        right = [(costs[i], i) for i in range(r + 1, n)]
        heapq.heapify(left)
        heapq.heapify(right)
        total = 0
        for _ in range(k):
            if right and (not left or right[0] < left[0]):
                cost, i = heapq.heappop(right)
                if l <= r:
                    heapq.heappush(right, (costs[r], r))  # пополнение с той же стороны
                    r -= 1
            else:
                cost, i = heapq.heappop(left)
                if l <= r:
                    heapq.heappush(left, (costs[l], l))
                    l += 1
            total += cost
        return total

Типичные ошибки

  • Sorting всех цен и сумма k наименьших. Для costs = [3, 1, 2], k = 1, candidates = 1 доступны только номера 0 и 2, и ответ 2. Sorting даёт 1: номер 1 в середине.
  • r = n - candidates - 1 без max. Для costs = [5, 1, 5], k = 2, candidates = 2 номер 1 попадает в оба Heap. Код нанимает его дважды и возвращает 1 + 1 = 2, а ответ 1 + 5 = 6.
  • Выбор right при равных ценах вершин. Для costs = [2, 1, 5, 2], k = 2, candidates = 1 верно нанять номер 0, затем номер 1: сумма 2 + 1 = 3. Если первым нанять номер 3, в правую группу приходит номер 2 с ценой 5, и второй наём стоит 2: сумма 4.
  • Пополнение без проверки l <= r. В примере 2 после первого найма код добавит в left номер 3, который уже лежит в right. Во втором раунде код нанимает его из left, и следующее пополнение читает costs[4]: IndexError.
