В первом примере для нового ребра есть 4 · 2 = 8 пар вершин. Если для каждой пары обойти получившееся Tree из каждой вершины, насчитаем 8 · 6 · 6 = 288 посещений вершин. Если соединить вершины с номером 0, из вершины 0 первого Tree до самой дальней вершины два ребра, а из его вершины 1 три ребра. Для каждой пары наибольшее из найденных расстояний равно диаметру получившегося Tree. При выборе вершины 0 в первом Tree оба варианта дают диаметр 3. Остальные шесть пар дают диаметр 4, поэтому наименьший диаметр равен 3. Такой Brute Force требует O(n · m · (n + m)2) времени. При n = m = 105 это 4 · 1020 посещений.

Решение 1. Два обхода BFS

Для пары вершин с номером 0 запишем длину самого длинного пути через новое ребро как 1 + 1 + 1 = 3. Перенесём первый конец ребра в вершину 2. Теперь от вершины 1 первого Tree до вершины 1 второго придётся пройти 2 + 1 + 1 = 4 ребра.

В этих суммах крайние слагаемые показывают, как далеко можно уйти от каждого конца нового ребра в своём Tree. Концы выбираем независимо. В каждом Tree выбираем вершину, у которой это расстояние меньше всего. Это центр Tree. Расстояние от него до самой дальней вершины называют радиусом.

У пути 0 → 1 → 2 → 3 → 4 → 5 диаметр равен 5. Из вершины 2 до конца 5 три ребра, а из вершины 3 столько же до конца 0. Обе вершины в середине пути служат центрами. Для любого Tree берём ближайшую к середине самого длинного пути вершину (см. доказательство под рисунком с двумя обходами BFS). Радиус равен половине диаметра с округлением вверх, то есть (d + 1) // 2.

В первом примере диаметры равны 2 и 1, поэтому оба радиуса равны 1. Пути внутри каждого Tree сохраняют длину. Чтобы выйти из него и вернуться, пришлось бы дважды пройти по новому ребру. Сравним исходные диаметры с найденными длинами путей через новое ребро. При соединении центров диаметр равен max(2, 1, 3) = 3, а после переноса конца в вершину 2 он равен max(2, 1, 4) = 4. В общем случае при соединении центров диаметр равен max(d1, d2, r1 + 1 + r2). Это максимум из двух исходных диаметров и длины самого длинного пути через новое ребро. Первые два числа одинаковы для всех пар, а третье при соединении центров наименьшее. Большее третье число не уменьшит максимум, поэтому соединение центров даёт наименьший диаметр.

Чтобы получить d1, запустим BFS в первом Tree из вершины 0. В dist получим [0, 1, 1, 1]: вершины 1, 2 и 3 образуют один слой расстояний. Все три соседа вершины 0 попадают в Deque в порядке рёбер на входе: сначала 1, затем 2, затем 3. Deque берёт их в том же порядке. Поэтому второй BFS начнётся в вершине 3, даст [1, 2, 2, 0] и вернёт расстояние 2. Для второго BFS годится любая вершина этого слоя: от каждого из трёх листьев до другого листа два ребра через 0. BFS обходит слои по возрастанию расстояния, поэтому последняя вершина всегда одна из самых дальних. В каждом Tree первый BFS находит конец одного из самых длинных путей, а второй BFS из этого конца измеряет диаметр.

Почему выбираем центр у середины диаметра и начинаем второй BFS с самой дальней вершины

На пути длины 5 отметим точку C посередине ребра между вершинами 2 и 3. До каждого конца от неё 2,5 ребра.

Во втором примере условия у самого длинного пути 4 → 2 → 0 → 3 → 6 середина C находится в вершине 0. Из вершины 5 идём к C через 2. Чтобы продолжить путь к 4, пришлось бы ещё раз пройти ребро между 0 и 2. Путь 5 → 2 → 4 содержит всего два ребра. Путь 5 → 2 → 0 → 3 → 6 идёт через C и содержит четыре ребра. До вершины 3 через C всего 2 + 1 = 3 ребра, поэтому от старта 5 она ближе, чем вершина 6.

Теперь возьмём произвольное Tree и отметим середину C одного из его самых длинных путей. Обозначим длину этого пути через d. Путь к C может пройти по рёбрам не более чем одной половины, ведь в Tree перейти с одной половины на другую можно только через C. От любой вершины через C можно дойти хотя бы до одного конца этого пути без повторения рёбер. Значит, от любой вершины до C не больше d / 2, иначе до этого конца было бы больше d рёбер.

Пусть от старта BFS до C расстояние x. От старта через C до любой вершины пройдём не больше x + d / 2 рёбер. Расстояние до неё не больше длины этого маршрута, даже если в нём повторяется ребро. До одного из концов путь через C идёт без повторов и даёт ровно x + d / 2 рёбер. Если вершина ближе к C, чем этот конец, то даже через C до неё меньше x + d / 2 рёбер. Поэтому любая самая дальняя от старта вершина лежит на расстоянии d / 2 от C. От неё через C до одного из концов ровно d рёбер, их и насчитает второй BFS. Наибольшее расстояние от старта равно x + d / 2, поэтому оно меньше всего у ближайшей к C вершины. При чётном диаметре у неё x = 0, при нечётном x = 0,5.

from collections import deque


def diameter(edges):
    adj = [[] for _ in range(len(edges) + 1)]
    for a, b in edges:
        adj[a].append(b)
        adj[b].append(a)

    def farthest(start):
        dist = [-1] * len(adj)
        dist[start] = 0
        queue = deque([start])
        while queue:
            node = queue.popleft()
            for neighbor in adj[node]:
                if dist[neighbor] == -1:
                    dist[neighbor] = dist[node] + 1
                    queue.append(neighbor)
        return node, dist[node]

    end, _ = farthest(0)
    return farthest(end)[1]


class Solution:
    def minimumDiameterAfterMerge(self, edges1: list[list[int]], edges2: list[list[int]]) -> int:
        d1 = diameter(edges1)
        d2 = diameter(edges2)
        r1 = (d1 + 1) // 2
        r2 = (d2 + 1) // 2
        return max(d1, d2, r1 + 1 + r2)

В первом примере в двух Tree четыре и две вершины. После двух обходов каждого Tree получим 2 · (4 + 2) = 12 извлечений из Deque и 2 · (6 + 2) = 16 просмотров записей о соседях. Каждый BFS берёт каждую вершину один раз и просматривает каждое ребро с двух сторон. Время: O(n + m) в худшем случае. Больше всего записей нужно при обходе первого Tree: четыре списка в adj, шесть номеров соседей, четыре расстояния и три вершины в Deque. Всего 4 + 6 + 4 + 3 = 17 записей. Два Tree обрабатываем по очереди. Для Tree из k вершин нужны k списков, 2 · (k − 1) номеров соседей, k расстояний и не больше k мест в Deque. Дополнительная память: O(n + m) в худшем случае.

Решение 2. Leaf Peeling

Вернёмся к пути от 0 до 5. Только у вершин 0 и 5 по одному соседу. Такие вершины называют листьями. Снимем оба листа, затем снимем новые листья 1 и 4. Останется ребро между 2 и 3. В каждом из двух слоёв мы убрали по два ребра, значит, исходная длина равна 2 · 2 + 1 = 5.

В первом Tree из примера 2 после удаления первого слоя остаётся путь 2 → 0 → 3. Вершина 0 остаётся, потому что на этом пути у неё два соседа. У каждой внутренней вершины пути есть два соседа на нём, поэтому она не лист. Значит, путь между любыми двумя оставшимися вершинами сохраняется целиком.

На пути 1 → 2 → 3 → 4 от 1 до 3 идём через 2. Ребро от 1 к 3 дало бы второй путь между ними, а в Tree путь только один. Поэтому любой второй сосед конца пути лежит вне пути. Через него путь можно продлить на одно ребро. Если в Tree есть ребро, у каждого конца самого длинного пути только один сосед. Если в Tree больше двух вершин, при удалении слоя каждый самый длинный путь теряет по ребру с каждого конца. Если перед удалением диаметр равен d, от такого пути остаётся d − 2 рёбер. Новый диаметр не меньше длины этого остатка.

Вернём к концам пути 1 → 2 → 3 → 4 снятые листья 0 и 5. К трём рёбрам добавятся ещё два. Если бы у концов 1 и 4 был общий сосед v вне пути, можно было бы пройти по пути от 1 до 4 и вернуться по рёбрам 4 → v и v → 1. В Tree такой возврат без повтора рёбер невозможен. У концов любого пути в оставшемся Tree до удаления было хотя бы по два соседа. Если концы различны, путь использует по одному ребру у каждого конца. Значит, у каждого конца был сосед вне пути, как у 1 и 4 в примере. У разных концов эти соседи различны.

После снятия листьев в первом Tree из примера 1 остаётся только вершина 0. Два её прежних соседа дают путь 1 → 0 → 2. Так можно продлить путь из одной оставшейся вершины на два ребра, ведь до удаления у неё было хотя бы два соседа. Обозначим новый диаметр через L. Продлив путь длины L с обоих концов, получим в исходном Tree путь длины L + 2. Его длина не превышает исходный диаметр, поэтому L + 2 ≤ d и L ≤ d − 2. Значит, каждый слой уменьшает диаметр ровно на два ребра.

У вершины 4 на пути от 0 до 5 соседи 3 и 5, сумма их номеров равна 8. Когда уберём лист 5, в сумме останется 8 − 5 = 3, номер единственного соседа. Код берёт номер соседа листа из neighbor_sum. Если бы на последнем ребре между 2 и 3 код удалил лист 2, сумма neighbor_sum[3] стала бы равной 2 − 2 = 0 ещё до обработки листа 3. Код хранит число оставшихся вершин в remaining. На этом ребре проверка remaining > 2 останавливает цикл. Пока вершин больше двух, два листа не могут быть соседями, иначе ни у одного из них не было бы ребра к остальным вершинам. Поэтому код обновляет сумму и число соседей degree только у вершин вне текущего слоя.

В первом Tree из примера 1 листья 1, 2 и 3 соседствуют с вершиной 0. При их удалении degree[0] падает с 3 до 2, затем до 1 и до 0. Когда число соседей уменьшается до 1, код добавляет вершину в next_leaves. Здесь после слоя remaining = 1, поэтому вершина 0 остаётся в списке и код уже не ищет у неё соседа.

Если осталась одна вершина, остаточный диаметр равен 0. Если остались две, их соединяет одно ребро. Прибавим к диаметру остатка по два ребра за каждый снятый слой и получим d = 2 · rounds + remaining − 1. Если к пути длины 5 присоединить Tree из одной вершины, путь через новое ребро при соединении центров имеет длину 3 + 1 + 0 = 4. Исходный путь длиннее, поэтому ответ равен 5.

def diameter(edges):
    size = len(edges) + 1
    degree = [0] * size
    neighbor_sum = [0] * size
    for a, b in edges:
        degree[a] += 1
        degree[b] += 1
        neighbor_sum[a] += b
        neighbor_sum[b] += a

    leaves = [v for v in range(size) if degree[v] == 1]
    remaining = size
    rounds = 0
    while remaining > 2:
        remaining -= len(leaves)
        next_leaves = []
        for leaf in leaves:
            neighbor = neighbor_sum[leaf]
            neighbor_sum[neighbor] -= leaf
            degree[neighbor] -= 1
            if degree[neighbor] == 1:
                next_leaves.append(neighbor)
        leaves = next_leaves
        rounds += 1
    return 2 * rounds + remaining - 1


class Solution:
    def minimumDiameterAfterMerge(self, edges1: list[list[int]], edges2: list[list[int]]) -> int:
        d1 = diameter(edges1)
        d2 = diameter(edges2)
        r1 = (d1 + 1) // 2
        r2 = (d2 + 1) // 2
        return max(d1, d2, r1 + 1 + r2)

В первом примере код читает четыре ребра, проверяет число соседей у шести вершин при отборе первых листьев и удаляет три листа. Код один раз читает каждое ребро и не больше одного раза удаляет каждую вершину. Время: O(n + m) в худшем случае. В первом Tree в degree и neighbor_sum по четыре числа. Перед сменой слоя в leaves три листа, а в next_leaves одна вершина. В этот момент код хранит больше всего записей: 4 + 4 + 3 + 1 = 12. Для Tree из k вершин два числовых списка занимают 2k записей. Списки соседних слоёв вместе содержат не больше k вершин: каждая попадает только в один слой. Дополнительная память: O(n + m) в худшем случае.
