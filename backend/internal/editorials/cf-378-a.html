Решение 1. Перебор граней (Brute Force)

Пусть a = 2, b = 4 и выпало x = 1. До числа первого игрока один шаг, поэтому da = 1. Для второго игрока разность 1 − 4 равна −3, а расстояние db = 3. В Python abs(1 - 4) даёт 3. Функция abs вычисляет модуль разности, то есть расстояние между числами.

Здесь da < db, поэтому увеличиваем счётчик побед первого игрока first.

В выделенном столбце для x = 3 расстояния равны, поэтому увеличиваем ties. При x = 4 расстояние db = 0 меньше da = 2, поэтому увеличиваем second.

Грани 1 и 2 дают победу первому игроку, грань 3 даёт ничью, а на гранях 4, 5 и 6 выигрывает второй игрок. Получаем ответ 2 1 3. Цикл с range(1, 7) проверяет каждую из шести граней ровно один раз. Для каждой грани срабатывает только одна из трёх ветвей, поэтому счётчики учитывают все исходы без повторов.

a, b = map(int, input().split())
first = 0
ties = 0
second = 0

for x in range(1, 7):
    da = abs(x - a)
    db = abs(x - b)
    if da < db:
        first += 1
    elif da == db:
        ties += 1
    else:
        second += 1

print(first, ties, second)

Время: O(1) в худшем случае. При любых a и b цикл делает шесть шагов. Дополнительная память: O(1) в худшем случае. Для перебора нужны три счётчика, текущее значение x и два расстояния.

Решение 2. Подсчёт по середине отрезка

Для чисел 2 и 5 середина отрезка на числовой прямой равна 3,5. При x = 3 до 2 один шаг, а до 5 два шага. Внутри отрезка расстояния до концов в сумме дают его длину. В левой половине отрезка до левого конца меньше половины длины, а до правого больше. В правой половине по той же причине ближе правый конец.

При x = 1 до 2 один шаг, а до 5 получается 1 + 3 = 4 шага. За пределами отрезка путь до дальнего конца проходит через ближний и включает весь отрезок. Значения 1, 2 и 3 ближе к 2, а 4, 5 и 6 ближе к 5. Если числа игроков различны, слева от середины выигрывает игрок с меньшим числом, справа выигрывает игрок с большим числом. Если на кубике выпала сама середина, расстояния равны.

Для чисел 2 и 4 середина равна 3. Чтобы выиграл игрок с числом 2, нужно x < 3, то есть 2 · x < 6. Для целого x это то же самое, что 2 · x ≤ 5. После деления на 2 получаем x ≤ 2,5. Так как x целое, последняя подходящая грань равна 2. Операция // округляет результат деления вниз до целого числа, поэтому 5 // 2 даёт 2. Подходят грани от 1 до 5 // 2 включительно, всего две.

Сумма total = a + b вдвое больше координаты середины отрезка. Для грани слева от середины получаем 2 · x ≤ total − 1. Числа на гранях начинаются с 1, поэтому последнее подходящее число left = (total - 1) // 2 равно количеству таких граней.

Для пары 2 и 5 деление 7 // 2 даёт 3, а для пары 2 и 4 тот же результат даёт 6 // 2. В обоих случаях справа лежат грани 4, 5 и 6. Первые три грани 1, 2 и 3 в эту группу не входят. Вычитаем эти 3 грани из шести и получаем 6 − 3 = 3. По тому же правилу деление total // 2 округляет координату середины вниз до целого числа. В общем случае справа лежат значения от total // 2 + 1 до 6. В эту группу не входят числа от 1 до total // 2, и их ровно total // 2. Вычитаем их из шести и получаем right = 6 - total // 2. Оставшиеся грани дают ничью, их число ties = 6 - left - right.

При a = 4 и b = 2 у первого игрока большее число. Ему подходят три грани справа от середины, поэтому ответ будет 3 1 2. При a < b первым выводим left. Если оба написали 4, любая грань даёт равные расстояния до их чисел. Поэтому при a == b сразу выводим 0 6 0.

a, b = map(int, input().split())

if a == b:
    print(0, 6, 0)
else:
    total = a + b
    left = (total - 1) // 2
    right = 6 - total // 2
    ties = 6 - left - right
    if a < b:
        print(left, ties, right)
    else:
        print(right, ties, left)

Время: O(1) в худшем случае. При разных a и b число действий в формулах постоянно. Дополнительная память: O(1) в худшем случае. В ветви для разных чисел код хранит четыре промежуточных значения total, left, right и ties.
