Возьмём строку [2, 4, 2, 7]. У числа 24 = 16 последняя цифра 6. Возводим её в квадрат и делим 36 на 7 с остатком 1. Если пропустить шаг с последней цифрой, получится 162 = 256 с остатком 4. При target = 1 такая замена потеряет подходящий номер.

Можно вычислить обе степени целиком и после каждой взять остаток. При a = b = 1000 выражение a ** b % 10 сначала строит число 103000. У числа 1000b после единицы стоят 3 · b нулей. На 100 таких строках при b = 1000 Python 100 раз построит число из 3001 цифры, хотя дальше нужна лишь цифра 0.

Решение 1. Binary Exponentiation

В строке [2, 3, 3, 10] первая степень равна 23 = 8, поэтому pow(2, 3, 10) даёт 8. Вторая степень равна 83 = 512, поэтому pow(8, 3, 10) возвращает последнюю цифру 2. В переменную digit записываем остаток от деления ab на 10, то есть последнюю цифру первой степени. В value записываем результат pow(digit, c, m), то есть остаток от деления digitc на m.

В первом примере из условия value принимает значения 2, 0 и 2. С target = 2 совпали два остатка, поэтому ответ равен [0, 2]. Функция enumerate даёт каждой строке её номер i, начиная с нуля. Каждый номер проходит одну проверку и попадает в answer при совпадении второго остатка с target.

Число 13 в двоичной записи имеет вид 1101. Единицы указывают, какие степени двойки входят в сумму 13 = 8 + 4 + 1. Получаем 213 = 28 · 24 · 21, потому что справа всего 13 множителей, равных 2.

Чтобы найти последнюю цифру 213, начнём с 2 и трижды возведём число в квадрат, каждый раз оставляя последнюю цифру. В записи 1101 вторая цифра справа равна 0, поэтому множитель 22 = 4 пропускаем. Для 24 берём последнюю цифру квадрата 4 · 4 = 16 и получаем 6.

При переходе от 24 к 28 нужен квадрат 16 · 16 = 256. Заменим первый множитель его последней цифрой и получим 6 · 16 = 96. После такой же замены второго множителя получим 6 · 6 = 36. При замене числа его последней цифрой мы вычитаем из него целые десятки. Из произведения при этом вычитаем те же десятки, умноженные на другой множитель, поэтому последняя цифра сохраняется. Перемножаем последние цифры степеней с показателями 8, 4 и 1. Получаем 6 · 6 · 2 = 72. Последняя цифра 2 и есть результат pow(2, 13, 10). Этот способ вычисления степени называют Binary Exponentiation.

Для строки [2, 4, 3, 7] второй вызов имеет вид pow(6, 3, 7). Квадрат 6 · 6 = 36 при делении на 7 даёт остаток 1. Если умножить на 6 остаток 1 вместо 36, произведение уменьшится на (36 − 1) · 6 = 210. Число 210 делится на 7 без остатка, поэтому оба произведения дают остаток 6. При любом делителе m разность между числом и его остатком делится на m без остатка. После умножения на один и тот же множитель эта разность по-прежнему делится на m. Поэтому замена множителя его остатком сохраняет остаток произведения.

class Solution:
    def getGoodIndices(self, variables: list[list[int]], target: int) -> list[int]:
        answer = []
        for i, (a, b, c, m) in enumerate(variables):
            digit = pow(a, b, 10)
            value = pow(digit, c, m)
            if value == target:
                answer.append(i)
        return answer

Пусть q обозначает число строк, а B обозначает наибольший из всех показателей b и c. На строку приходятся два вызова pow. После каждого умножения первый вызов берёт остаток от деления на 10, а второй берёт остаток от деления на m. По условию a и m не больше 1000, поэтому каждый множитель не больше 1000. Произведение не превышает 1 000 000, поэтому умножение и вычисление остатка занимают постоянное время. В примере с 1101 мы трижды возвели число в квадрат, а для произведения 6 · 6 · 2 сделали ещё два умножения. На каждую двоичную цифру приходится не более одного возведения в квадрат, а для единицы может понадобиться ещё одно умножение. Поэтому для четырёх цифр 1101 нужно не более 4 · 2 = 8 умножений.

Так как 13 = 2 · 6 + 1, операция 13 // 2 отбрасывает остаток 1 и даёт 6. В двоичной записи из 1101 получаем 110. Тем же способом из 6 получаем 3, затем 1 и 0. Каждое такое деление отбрасывает последнюю двоичную цифру.

Наибольшее число с тремя двоичными цифрами равно 7 (111), а с четырьмя равно 15 (1111). Так как 7 < 13 ≤ 15, для записи 13 нужны четыре двоичные цифры. В двоичной записи равенство 15 + 1 = 16 имеет вид 1111 + 1 = 10000. Если к числу из k двоичных единиц прибавить 1, получится единица с k нулями. Единица с k двоичными нулями равна 2k, поэтому для k цифр максимум равен 2k − 1. Чтобы записать B, берём наименьшее целое k, при котором B ≤ 2k − 1. Прибавим 1 к обеим частям неравенства и получим 2k ≥ B + 1.

При B = 13 получаем B + 1 = 14. Из 23 = 8 и 24 = 16 получаем log2(8) = 3 и log2(16) = 4. Логарифм по основанию 2 показывает, в какую степень надо возвести 2, чтобы получить заданное число. Степень двойки растёт с показателем, поэтому из 8 < 14 < 16 следует 3 < log2(14) < 4. Наименьший целый показатель, при котором степень двойки не меньше 14, равен 4. Чтобы получить число двоичных цифр в записи B, округляем log2(B + 1) вверх до целого.

В первом примере из условия у показателей не больше двух двоичных цифр, поэтому шесть вызовов требуют не более 6 · 4 = 24 умножений. Если у B всего k двоичных цифр, каждый вызов требует не более 2 · k умножений. Два вызова на строку дают не более q · 2 · (2 · k) = 4 · q · k умножений на весь вход. Время: O(q · log(B + 1)) в худшем случае. Дополнительная память: O(1) в худшем случае. Число рабочих переменных постоянно, а список answer хранит сам ответ.

Решение 2. Repeated Multiplication

Для строки [2, 4, 2, 7] начнём с digit = 1. Четыре раза умножим его на 2, каждый раз оставляя последнюю цифру. Получим 2, 4, 8 и 6. Теперь начнём с value = 1 и дважды умножим его на 6. После каждого умножения берём остаток от деления на 7. Сначала получим 6, затем 1.

Чтобы найти последнюю цифру 83, после второго умножения можно заменить 64 на 4. При следующем умножении на 8 произведение уменьшится на 60 · 8 = 480, а последняя цифра сохранится. Внутри каждого цикла делитель один и тот же. По правилу из первого решения после b шагов в digit лежит нужная последняя цифра, а после c шагов в value лежит нужный второй остаток.

class Solution:
    def getGoodIndices(self, variables: list[list[int]], target: int) -> list[int]:
        answer = []
        for i, (a, b, c, m) in enumerate(variables):
            digit = 1
            for _ in range(b):
                digit = digit * a % 10
            value = 1
            for _ in range(c):
                value = value * digit % m
            if value == target:
                answer.append(i)
        return answer

Если в каждой из 100 строк b = c = 1000, на весь вход нужно 100 · (1000 + 1000) = 200 000 умножений. На строку нужно b + c умножений. Так как b + c ≤ 2 · B, на q строк нужно не более 2 · q · B умножений. Время: O(q · B) в худшем случае. Дополнительная память: O(1) в худшем случае. Каждый шаг цикла записывает новый остаток в ту же переменную.
