После каждого хода набор камней меняется, поэтому на каждом ходу нужно снова найти два самых тяжёлых камня среди оставшихся.

Решение 1. Max-Heap на heapq

В примере 1 stones = [2, 7, 4, 1, 8, 1]. Код записывает веса со знаком минус: h = [-2, -7, -4, -1, -8, -1]. Функции heapify, heappop и heappush модуля heapq работают как Min-Heap: после heapify в h[0] стоит наименьшее число -8, и heappop удаляет и возвращает его. Это вес самого тяжёлого камня 8 со знаком минус: 8 больше 7, а −8 меньше −7.

Первый heappop даёт -8, то есть y = 8. Второй heappop даёт наименьшее из оставшихся чисел, -7, то есть x = 7. Оно не меньше −8, поэтому x ≤ y. Веса разные, и heappush возвращает в h остаток 8 − 7 = 1 как -1. Теперь в h[0] стоит -4: камень 4 стал самым тяжёлым. Остальные ходы показывает рисунок. В конце в h остаётся -1, ответ 1.

После каждого heappop и heappush Min-Heap снова держит наименьшее число в h[0]. Поэтому на каждом ходу два heappop дают два самых тяжёлых камня из оставшихся, как требует условие. Цикл идёт, пока в h не меньше двух камней. В конце в h одно число или ни одного. В тесте stones = [2, 2] веса равны, оба камня разрушаются, h пуст, и код возвращает 0.

import heapq


class Solution:
    def lastStoneWeight(self, stones: list[int]) -> int:
        h = [-s for s in stones]  # -h[0] равно весу самого тяжёлого камня
        heapq.heapify(h)
        while len(h) > 1:
            y = -heapq.heappop(h)  # самый тяжёлый камень
            x = -heapq.heappop(h)  # второй по весу, x ≤ y
            if y != x:
                heapq.heappush(h, -(y - x))  # остаток y - x возвращается
        return -h[0] if h else 0

Время: n - число камней. Создание h и heapify стоят O(n). Каждый ход делает два heappop и не больше одного heappush, поэтому камней становится меньше хотя бы на 1. Значит, ходов не больше n − 1, при n = 30 не больше 29. Каждый heappop и heappush стоит O(log(n + 1)). Всего O(n log(n + 1)) в худшем случае. В примере 1 код делает 4 хода: 8 heappop и 3 heappush. Дополнительная память: h хранит не больше n чисел: O(n).

Решение 2. Sorting и Binary Search

a = sorted(stones) ставит веса по возрастанию. В примере 1 a = [1, 1, 2, 4, 7, 8]: два самых тяжёлых камня стоят в конце. Два вызова a.pop() дают y = 8 и x = 7, и a = [1, 1, 2, 4]. Остаток 1 нужно поставить так, чтобы a остался отсортированным. bisect.insort(a, 1) ищет место через Binary Search и находит место 2, после двух единиц. Затем вставляет туда 1: a = [1, 1, 1, 2, 4].

Перед каждым ходом a отсортирован. Два pop удаляют два последних числа, и остальные числа остаются по порядку. insort ставит остаток после всех чисел, которые не больше его, и перед всеми большими. Поэтому на каждом ходу a[-1] и a[-2] - два самых тяжёлых камня, и решение 2 делает те же ходы, что и решение 1.

import bisect


class Solution:
    def lastStoneWeight(self, stones: list[int]) -> int:
        a = sorted(stones)  # веса по возрастанию: самые тяжёлые в конце
        while len(a) > 1:
            y = a.pop()
            x = a.pop()
            if y != x:
                bisect.insort(a, y - x)  # остаток встаёт на своё место
        return a[0] if a else 0

Время: sorted стоит O(n log(n + 1)). Каждый pop с конца стоит O(1). insort делает O(log(n + 1)) сравнений, но вставка сдвигает вправо все числа после места остатка. Каждый ход убирает хотя бы один камень, поэтому перед ходом k в a не больше n − k + 1 чисел, а после двух pop не больше n − k − 1. Значит, сдвигов всего не больше (n − 2) + (n − 3) + … + 1 + 0 = (n − 1)(n − 2)/2, и всё решение стоит O(n²) в худшем случае. При n = 30 это не больше 406 сдвигов. В примере 1 три вызова insort сдвигают 2 + 0 + 0 = 2 числа. Дополнительная память: копия a хранит n чисел: O(n).

Типичные ошибки

  • heapq без минуса: решение 1 с h = list(stones), y = heapq.heappop(h), x = heapq.heappop(h), heapq.heappush(h, y - x) и return h[0] if h else 0. Тогда heappop даёт самый лёгкий камень. В примере 1 первый ход разбивает 1 и 1, а не 8 и 7. На втором ходу y = 2 и x = 4, и в h попадает 2 − 4 = −2. Ответ −17 вместо 1.
  • Остаток без минуса: heappush(h, y - x). Положительное число больше всех отрицательных чисел в h, поэтому heappop достаёт его последним, как самый лёгкий камень. В примере 1 ответ −1 вместо 1.
  • return -h[0] без проверки пустого h. В тесте stones = [2, 2] камней не остаётся, и h[0] даёт IndexError.
  • Один Sorting и a.append(y - x) вместо insort. В примере 1 после первого хода a = [1, 1, 2, 4, 1], и второй ход разбивает 1 и 4, а не 4 и 2. Здесь y = 1 и x = 4, и в a попадает 1 − 4 = −3. Ответ −7 вместо 1.
