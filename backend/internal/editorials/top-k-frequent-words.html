Сначала считаем, сколько раз встречается каждое слово. Затем выбираем k лучших слов: более частое слово лучше, а при равной частоте лучше то, что стоит раньше по алфавиту.

Решение 1. Counter и Min-Heap всех пар

В примере 1 words = ["i", "love", "leetcode", "i", "love", "coding"], k = 2. Counter(words) проходит по словам один раз и считает частоты: i и love по 2 раза, leetcode и coding по 1 разу. Разных слов u = 4.

Для каждого слова w с частотой c код строит пару (-c, w). Python сравнивает tuple по полям слева направо. Пара (-2, 'love') меньше пары (-1, 'coding'), потому что −2 < −1: у более частого слова пара меньше. У пар (-2, 'i') и (-2, 'love') первые поля равны, поэтому Python сравнивает слова: 'i' < 'love'. Значит, пары по возрастанию идут в том же порядке, что и слова в ответе.

heapq.heapify(h) строит Min-Heap из 4 пар, и в h[0] стоит наименьшая пара (-2, 'i'). heappop удаляет и возвращает h[0], а на место h[0] встаёт наименьшая из оставшихся пар. Первый вызов возвращает пару (-2, 'i'), и [1] берёт из неё слово 'i'. Второй вызов возвращает (-2, 'love'), и в ans идёт 'love'. После k = 2 вызовов цикл заканчивается, и ответ ["i", "love"].

Значит, k вызовов heappop дают k наименьших пар по возрастанию, то есть k лучших слов сразу в порядке ответа. Остальные u − k пар остаются в h: в примере это пары leetcode и coding.

import heapq
from collections import Counter


class Solution:
    def topKFrequent(self, words: list[str], k: int) -> list[str]:
        cnt = Counter(words)
        h = [(-c, w) for w, c in cnt.items()]  # минус: частое слово идёт раньше
        heapq.heapify(h)
        ans = []
        for _ in range(k):
            ans.append(heapq.heappop(h)[1])  # h[0] - лучшая из оставшихся пар
        return ans

Время: n - число слов, u - число разных слов, u ≤ n. Слово не длиннее 10 букв, поэтому одно обращение к Hash Table и одно сравнение двух слов читают не больше 10 букв каждого слова: O(1). Counter делает n обновлений Hash Table: ожидаемое O(n). Создание u пар и heapify стоят O(u). Каждый из k вызовов heappop стоит O(log(u + 1)). Всего ожидаемое O(n + k log(u + 1)). Дополнительная память: cnt и h хранят по u записей: O(u). Список ans из k слов - это ответ, его не считаем.

Решение 2. Max-Heap размера k

Дополнительный вопрос просит ожидаемое O(n log(k + 1)) времени. Решение 1 тоже укладывается в эту оценку. При n = u = 500 и k = 2 его часть k log2(u + 1) = 2 · log2(501) ≈ 18, а n log2(k + 1) = 500 · log2(3) ≈ 792. Дробь k / log2(k + 1) растёт с ростом k: 1/1 при k = 1, 3/2 при k = 3, 7/3 при k = 7. Поэтому при k ≤ n получаем k / log2(k + 1) ≤ n / log2(n + 1), то есть k log2(n + 1) ≤ n log2(k + 1). Так как u ≤ n, часть k log2(u + 1) тоже не больше n log2(k + 1). А часть n не больше n log2(k + 1), так как log2(k + 1) ≥ 1.

Решение 2 использует другой способ: оно держит в h не больше k пар, лучшие пары среди уже просмотренных. h - это Max-Heap, поэтому в h[0] стоит наибольшая пара, то есть худшая из выбранных. Когда в h уже k пар, новая пара p входит, только если p < h[0]. Тогда heapreplace_max удаляет h[0] и ставит p. Функции heappush_max и heapreplace_max есть в heapq с версии Python 3.14.

Возьмём words = ["e", "a", "d", "b", "f", "c", "a", "d", "b", "c", "a"] и k = 3. Counter хранит слова в порядке первого появления: e 1, a 3, d 2, b 2, f 1, c 2. Первые три пары код кладёт через heappush_max, и худшая из них (-1, 'e') стоит в h[0]. Пара (-2, 'b') меньше её: −2 < −1. Поэтому b заменяет e, и худшей становится (-2, 'd'). Пара (-1, 'f') больше (-2, 'd'), и f не входит. У пар (-2, 'c') и (-2, 'd') частоты равны, а 'c' < 'd'. Поэтому c заменяет d.

Удалённая пара не входит в ответ. Когда b заменяет e, в h есть (-3, 'a') и (-2, 'd'), и вместе с (-2, 'b') это 3 пары меньше (-1, 'e'). Значит, e не входит в 3 лучших слова. Пропущенная пара больше h[0], поэтому все k пар в h лучше её. Так для каждого слова вне h есть k слов лучше него, и после цикла в h остаются ровно k лучших пар. Они стоят в порядке Heap: [(-2, 'c'), (-3, 'a'), (-2, 'b')]. h.sort() ставит их по возрастанию, и ответ ["a", "b", "c"].

import heapq
from collections import Counter


class Solution:
    def topKFrequent(self, words: list[str], k: int) -> list[str]:
        cnt = Counter(words)
        h = []  # Max-Heap: в h[0] худшая из выбранных пар
        for w, c in cnt.items():
            p = (-c, w)
            if len(h) < k:
                heapq.heappush_max(h, p)
            elif p < h[0]:
                heapq.heapreplace_max(h, p)  # p лучше худшей пары
        h.sort()
        return [w for c, w in h]

Время: Counter стоит ожидаемое O(n), как в решении 1. В h не больше k пар, поэтому каждый вызов heappush_max и heapreplace_max стоит O(log(k + 1)). Таких вызовов не больше u. h.sort() сортирует k пар за O(k log(k + 1)). Всего ожидаемое O(n + u log(k + 1)), так как k ≤ u. Это не больше O(n log(k + 1)): n ≤ n log2(k + 1), а u log2(k + 1) ≤ n log2(k + 1), так как u ≤ n. Дополнительная память: cnt хранит u записей, h не больше k пар: O(u). При u ≤ n это O(n), как просит дополнительный вопрос.

Типичные ошибки

  • Sorting только по частоте: sorted(cnt, key=cnt.get, reverse=True). Слова с равной частотой остаются в порядке первого появления. Для words = ["b", "a", "b", "c", "a"], k = 2 ответ ["b", "a"] вместо ["a", "b"].
  • Sorting пар (частота, слово) с reverse=True: sorted(cnt.items(), key=lambda p: (p[1], p[0]), reverse=True). Обратный порядок действует и на слова: при равной частоте они идут от конца алфавита. В примере 1 ответ ["love", "i"] вместо ["i", "love"].
  • В решении 2 Min-Heap пар (c, w) без минуса. В h[0] стоит пара с наименьшей частотой, а при равной частоте пара с меньшим словом. Код удаляет h[0] как худшую пару, но меньшее слово лучше. Для words = ["a", "b", "c"], k = 2 код удаляет a и возвращает ["b", "c"] вместо ["a", "b"].
  • Ответ решения 2 без h.sort(). Для words из решения 2 и k = 3 код вернёт ["c", "a", "b"]: это порядок Heap, а не порядок ответа.
