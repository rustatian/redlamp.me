n это длина nums. Brute Force сравнивает nums[i] и nums[j] для каждой пары мест i < j. Пар мест n(n − 1)/2: в примере 1 n = 6, и пар 6 · 5 / 2 = 15. При n = 100 их 4950. Такое решение проходит тесты этой задачи, но число сравнений растёт как n²: O(n²). Решения ниже читают каждое число один раз.

Решение 1. Hash Table

Возьмите пример 1: nums = [1, 2, 3, 1, 1, 3]. На месте 4 стоит число 1. Левее него число 1 стоит на местах 0 и 3. Значит, хороших пар с j = 4 ровно 2: (0, 4) и (3, 4). Для любого места j таких пар столько, сколько чисел, равных nums[j], стоит левее него.

Hash Table freq хранит для каждого числа, сколько раз оно уже встретилось. Для числа x сначала прибавляем freq[x] к ответу pairs, потом увеличиваем freq[x] на 1. Числа, которого ещё не было, в freq нет, и freq.get(x, 0) даёт 0.

Возьмите пару (2, 5). На шаге места 2 число 3 с места 5 ещё не прочитано, и freq.get(3, 0) дало 0. На шаге места 5 число 3 с места 2 уже учтено: freq[3] было 1, и пара (2, 5) добавилась. Так каждая хорошая пара (i, j) попадает в ответ ровно один раз, на шаге места j. На шаге места i число nums[j] ещё не прочитано. На шаге места j число nums[i] уже учтено в freq. Новых пар на шагах примера 1: 0, 0, 0, 1, 2 и 1. Сумма 0 + 0 + 0 + 1 + 2 + 1 = 4 равна ответу.

class Solution:
    def numIdenticalPairs(self, nums: list[int]) -> int:
        freq = {}  # freq[x] - сколько раз число x уже встретилось
        pairs = 0
        for x in nums:
            pairs += freq.get(x, 0)  # x даёт пару с каждым равным числом левее
            freq[x] = freq.get(x, 0) + 1
        return pairs

Время: цикл делает n шагов. На каждом шаге два чтения и одна запись в freq, каждое за ожидаемое O(1). Всего ожидаемое O(n). В примере 1 это 6 шагов вместо 15 сравнений Brute Force, при n = 100 это 100 шагов вместо 4950. Дополнительная память: freq хранит одну запись для каждого разного числа: O(u), где u это число разных значений в nums. В примере 1 u = 3. Ответ это одно число.

Решение 2. Combinations

Посмотрите сразу на все числа 1 в примере 1. Они стоят на местах 0, 3 и 4. Хорошая пара из них это выбор 2 мест из 3, а порядок внутри пары задаёт условие i < j. Это C(3, 2) = 3 · 2 / 2 = 3 пары: (0, 3), (0, 4) и (3, 4). Числа 3 стоят на местах 2 и 5: C(2, 2) = 1 пара. Число 2 одно: C(1, 2) = 0. Всего 3 + 0 + 1 = 4.

Правило. Если число встречается k раз, оно даёт C(k, 2) = k(k − 1)/2 хороших пар. Два разных числа хорошую пару не дают. Группы разных чисел не пересекаются, поэтому по Sum Rule ответ это сумма C(k, 2) по всем числам.

Решение 1 считает те же пары. Числа 1 на местах 0, 3 и 4 добавили 0, 1 и 2, всего 3 = C(3, 2). Для k равных чисел решение 1 добавит 0 + 1 + ... + (k − 1) = k(k − 1)/2. В примере 2 k = 4: 0 + 1 + 2 + 3 = 6 = 4 · 3 / 2.

Числа в nums от 1 до 100. Поэтому вместо Hash Table подходит Array cnt из 101 счётчика: cnt[v] это сколько раз число v есть в nums. Счётчик числа v стоит на месте v, место 0 не используется.

class Solution:
    def numIdenticalPairs(self, nums: list[int]) -> int:
        cnt = [0] * 101  # cnt[v] - сколько раз число v есть в nums
        for x in nums:
            cnt[x] += 1
        pairs = 0
        for k in cnt:
            pairs += k * (k - 1) // 2  # C(k, 2) пар из k равных чисел
        return pairs

Время: первый цикл делает n шагов, второй всегда 101 шаг: O(n + 101) = O(n) в худшем случае. При n = 100 это 201 шаг. Дополнительная память: cnt хранит 101 число при любом n: O(1).

Типичные ошибки

  • Перебирать j по range(n) или по range(i, n). Тогда число попадает в пару с самим собой, а при range(n) каждая хорошая пара считается ещё раз в обратном порядке. На примере 1 получится 14 или 10 вместо 4. Нужен range(i + 1, n).
  • Увеличить freq[x] до прибавления. Тогда число попадает в пару с самим собой. На примере 2 шаги дают 1 + 2 + 3 + 4 = 10, а ответ 6.
  • Считать k(k − 1) без деления на 2. Так пара мест 0 и 1 считается два раза: как (0, 1) и как (1, 0). На примере 2 получится 4 · 3 = 12 вместо 6.
  • cnt = [0] * 100. В таком Array последнее место 99, и число 100 даёт IndexError.
