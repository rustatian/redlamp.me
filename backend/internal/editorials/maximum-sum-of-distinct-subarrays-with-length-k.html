В примере 1 окна [2, 9, 9] и [9, 9, 9] дают наибольшие суммы 20 и 27, но в них число 9 повторяется, поэтому ответ 15, а не 27.

Пусть n - длина nums. Brute Force строит для каждого окна set из k чисел и сравнивает его размер с k. Окон n − k + 1, и каждое окно читается заново: (n − k + 1) · k чтений. При n = 105 наибольшее число чтений даёт k = 5 · 104: 50 001 · 50 000 = 2 500 050 000. Это ожидаемое время O(nk): слишком долго.

Решение 1. Sliding Window и dict счётчиков

Сдвиг окна [1, 5, 4] на один шаг вправо даёт окно [5, 4, 2]: число 1 уходит, число 2 входит. Сумма меняется за два действия: 10 − 1 + 2 = 11. Нужно знать ещё одно: все ли числа окна разные.

Для этого храните dict cnt: ключ - число, значение - сколько раз число стоит в окне. Для [4, 2, 9] это {4: 1, 2: 1, 9: 1}, для [2, 9, 9] это {2: 1, 9: 2}.

Сдвиг с [1, 5, 4] на [5, 4, 2] меняет cnt так. Было {1: 1, 5: 1, 4: 1}. Число 2 входит и получает +1, число 1 уходит и получает −1: {1: 0, 5: 1, 4: 1, 2: 1}. Это четыре ключа при k = 3, хотя три числа окна разные. После удаления ключа 1 остаётся {5: 1, 4: 1, 2: 1}: три ключа.

Правило. Окно подходит, когда len(cnt) == k. При сдвиге вошедшее число получает +1, а ушедшее −1. Ключ со счётчиком 0 нужно удалить.

Пусть r - номер правого конца окна. Входит x = nums[r], а при r ≥ k уходит y = nums[r - k]. В примере 1 при r = 3 входит x = 2 и уходит y = nums[0] = 1. Первое окно из k чисел кончается на r = k − 1 = 2, последнее на r = n − 1 = 6.

Сумма всех счётчиков равна числу чисел в окне. В окне из k чисел она равна k: для {2: 1, 9: 2} это 1 + 2 = 3. Каждый счётчик не меньше 1, потому что ключи с нулём удалены. У [4, 2, 9] три ключа и сумма счётчиков 3, поэтому все счётчики равны 1 и все числа разные. У [2, 9, 9] два ключа: числа не разные. Пока окно короче k, в нём меньше k чисел и меньше k ключей: в примере 1 при r = 1 окно [1, 5], в cnt два ключа.

На рисунке скобка в строке nums - окно, бледные числа уже ушли из окна, две нижние строки - ключи cnt и их счётчики. Окна с r = 2, 3 и 4 подходят: len(cnt) = 3 и суммы 10, 11 и 15. Окна с r = 5 и r = 6 не подходят: число 9 повторяется. Лучшая сумма best = 15. В примере 2 получается cnt = {4: 3}: один ключ при k = 3, поэтому best остаётся 0.

class Solution:
    def maximumSubarraySum(self, nums: list[int], k: int) -> int:
        cnt = {}  # число -> сколько раз оно стоит в окне
        total = 0  # сумма окна
        best = 0
        for r, x in enumerate(nums):
            cnt[x] = cnt.get(x, 0) + 1
            total += x
            if r >= k:  # в окне k + 1 чисел: самое левое число уходит
                y = nums[r - k]
                cnt[y] -= 1
                if cnt[y] == 0:
                    del cnt[y]  # ключ со счётчиком 0 исказил бы len(cnt)
                total -= y
            if len(cnt) == k:  # k чисел и k разных ключей: все числа разные
                best = max(best, total)
        return best

Время: ожидаемое O(n): цикл делает n шагов, на каждом шаге несколько операций dict, и каждая операция Hash Table имеет ожидаемое время O(1). При n = 105 цикл делает 105 шагов. Дополнительная память: в худшем случае O(k): cnt хранит не больше k + 1 ключей. Вход nums и ответ не входят в дополнительную память.

Типичные ошибки

  • Ключ со счётчиком 0 остаётся в cnt. В примере 1 окно [5, 4, 2] не засчитывается: в cnt четыре ключа. Следующие окна тоже: в cnt лежат 5 ключей. Код возвращает 10 вместо 15.
  • Проверка len(cnt) == k стоит до ухода числа y. Тогда в окне k + 1 чисел. В примере 1 при r = 5 в cnt ключи 4, 2 и 9: три ключа при k = 3, хотя в окне [4, 2, 9, 9] число 9 повторяется. Сумма этого окна 24, и код возвращает 24 вместо 15.
  • Окно хранится в set, а не в dict счётчиков. Для nums = [9, 9, 1, 2] и k = 2 ответ 10: окно [9, 1] подходит. После [9, 9] set равен {9}: set хранит число 9 один раз, хотя в окне две девятки. При r = 2 число nums[0] = 9 уходит, и set теряет 9, хотя в окне [9, 1] число 9 ещё стоит. При r = 3 уходит nums[1] = 9, а в set {1} числа 9 нет: код с remove падает с KeyError, а код с discard возвращает 3 вместо 10.
