Нужен индекс target в упорядоченном Array nums или -1, и поиск должен занимать O(log n).

Brute Force проверяет индексы 0, 1, 2, ... по порядку. Для nums = [-1, 0, 3, 5, 9, 12] и target = 9 это 5 сравнений: число 9 стоит на индексе 4. Если target нет, Brute Force сравнивает все n чисел, где n - длина nums. При n = 104 это 10 000 сравнений, то есть O(n), а нужно O(log n). Brute Force не использует порядок Array.

Решение 1. Binary Search

Пара lo и hi задаёт отрезок индексов, где target ещё может стоять. Возьмём nums = [-1, 0, 3, 5, 9, 12], n = 6, и target = 9. Сначала lo = 0 и hi = 5: в отрезке все индексы. Середина отрезка: mid = (lo + hi) // 2 = 2.

Проверка: nums[2] = 3 меньше 9. Array упорядочен по возрастанию, поэтому nums[0] = -1 и nums[1] = 0 тоже меньше 9. Число 9 не стоит на индексах 0, 1, 2, и отрезок сужается: lo = mid + 1 = 3. Новая середина mid = (3 + 5) // 2 = 4, и nums[4] = 9. Ответ 4 после двух проверок.

Теперь target = 2: этого числа в nums нет. Первая проверка: nums[2] = 3 больше 2. Числа на индексах 3, 4, 5 ещё больше, поэтому 2 не стоит на индексах 2, 3, 4, 5, и hi = mid - 1 = 1. Дальше mid = 0 и nums[0] = -1 меньше 2: lo = 1. Потом mid = 1 и nums[1] = 0 меньше 2: lo = 2. Теперь lo = 2 больше hi = 1: отрезок пуст, для 2 не осталось индексов. Ответ −1 после трёх проверок.

Правило. Инвариант: если target есть в nums, его индекс лежит в отрезке [lo, hi]. Цикл идёт, пока lo <= hi. При nums[mid] < target ход lo = mid + 1, при nums[mid] > target ход hi = mid - 1. Пустой отрезок lo > hi значит, что target нет.

Одна проверка делит отрезок на левую часть, индекс mid и правую часть. Остаётся левая или правая часть. Пусть s - длина отрезка. Для отрезка [0, 5] длина s = 6. При mid = 2 в левой части 2 индекса, в правой 3. Для любого s каждая часть не длиннее ⌊s / 2⌋, где ⌊x⌋ - это x, округлённое вниз. Для s = 6 это ⌊6 / 2⌋ = 3. Если target всё время правее mid, длины равны 6, 3, 1. Это самый длинный путь: 3 проверки, потом длина 0.

class Solution:
    def search(self, nums: list[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            if nums[mid] < target:
                lo = mid + 1  # слева от mid числа не больше nums[mid]: target там нет
            else:
                hi = mid - 1  # справа от mid числа не меньше nums[mid]: target там нет
        return -1

Время: O(log n) в худшем случае: не больше ⌊log₂ n⌋ + 1 проверок середины. Для n = 104 самый длинный путь даёт длины отрезка 10 000, 5 000, 2 500, 1 250, 625, 312, 156, 78, 39, 19, 9, 4, 2, 1. Это 14 проверок. Формула даёт то же: 213 = 8 192 ≤ 10 000 < 16 384 = 214, поэтому ⌊log₂ 10 000⌋ = 13 и 13 + 1 = 14. Дополнительная память: O(1) в худшем случае: числа lo, hi и mid. Вход nums и ответ не считаем.

Типичные ошибки

  • hi = len(nums) вместо hi = len(nums) - 1. Индекс len(nums) лежит за концом nums. Оба примера условия этот код проходит. Он ломается, когда target больше всех чисел. Для nums = [5] и target = 6: lo = 0, hi = 1, mid = 0, nums[0] = 5 меньше 6, и lo = 1. Потом lo = hi = 1 и mid = 1, а индекса 1 в nums нет: IndexError.
  • while lo < hi вместо lo <= hi. Для nums = [5] и target = 5 получаем lo = hi = 0, цикл не начинается, и ответ −1 вместо 0. Отрезок из одного индекса тоже нужно проверить.
  • lo = mid вместо lo = mid + 1. Для nums = [1, 3] и target = 3: lo = 0, hi = 1, mid = 0, nums[0] = 1 меньше 3, и lo снова равно 0. Цикл не заканчивается.
  • hi = mid вместо hi = mid - 1. Для nums = [1, 3] и target = 0: mid = 0, nums[0] = 1 больше 0, и hi становится 0. Потом lo = hi = 0, снова mid = 0 и hi = 0. Цикл не заканчивается.
  • Срез nums[mid + 1:] вместо границ lo и hi. Для nums = [-1, 0, 3, 5, 9, 12] и target = 9 срез nums[3:] равен [5, 9, 12], и в нём число 9 стоит на индексе 1, а в nums на индексе 4. Срез ещё копирует ссылки на числа. Для n = 1024 и target больше всех чисел срезы длин 512, 256, ..., 1 копируют вместе 1 023 ссылки: время и дополнительная память O(n) в худшем случае.
