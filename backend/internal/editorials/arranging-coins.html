Четыре ряда занимают 1 + 2 + 3 + 4 = 10 монет. Пары 1 + 4 и 2 + 3 дают по 5: две пары, 2 · 5 = 10, то есть 4 · 5 / 2. Для k рядов нужно 1 + 2 + ... + k = k(k + 1) / 2 монет. Ответ - наибольшее k, при котором k(k + 1) / 2 ≤ n.

Brute Force выкладывает ряды по порядку и вычитает монеты. Для n = 8: ряд 1 забирает 1 монету, остаётся 7. Ряд 2 забирает 2, остаётся 5. Ряд 3 забирает 3, остаётся 2. Ряду 4 нужны 4 монеты, а осталось 2: ответ 3. Brute Force проверяет «хватает монет на следующий ряд?» один раз на каждый ряд и ещё один раз в конце, когда ответ «нет». Для n = 8 это 4 проверки, а при ответе k проверок k + 1. Число k меньше √(2n). Для n = 8 это 3 < √16 = 4. Причина: k2 / 2 < k(k + 1) / 2 ≤ n, поэтому k2 < 2n. Значит, время O(√n). При n = 231 − 1 ответ равен 65 535: на эти ряды нужно 65 535 · 65 536 / 2 = 2 147 450 880 монет, остаётся 32 767. Ряду 65 536 нужно 65 536 монет, поэтому проверок 65 536. Это укладывается в лимит времени, и Brute Force тоже проходит тесты. Binary Search - тема этой главы: при таком n он делает не больше 31 проверки.

Решение 1. Binary Search

Назовём k подходящим, если монет хватает на k рядов: k(k + 1) / 2 ≤ n. Для n = 8 числа k = 1, 2, 3, 4, 5 требуют 1, 3, 6, 10, 15 монет. Подходят k = 1, 2, 3, не подходят k = 4 и 5. Каждый следующий ряд добавляет монеты: для k = 3 нужно 6 монет, для k = 4 нужно 6 + 4 = 10. Поэтому с ростом k нужно больше монет, и если k подходит, подходят и все меньшие числа. Подходящие и неподходящие k идут так: «подходит, ..., подходит, не подходит, ..., не подходит». Нужно последнее «подходит»: k = 3.

Binary Search ищет эту границу на отрезке [lo, hi]. Сначала lo = 1 и hi = n: для n = 8 это отрезок [1, 8]. Число 1 подходит, потому что n ≥ 1. Ответ не больше n: k рядов требуют k(k + 1) / 2 ≥ k монет.

Для n = 8 первая середина mid = (lo + hi + 1) // 2 = (1 + 8 + 1) // 2 = 5. Для 5 рядов нужно 5 · 6 / 2 = 15 монет, и 15 больше 8: число 5 не подходит, большие числа тоже. Ставим hi = mid - 1 = 4. Вторая середина (1 + 4 + 1) // 2 = 3, и 3 · 4 / 2 = 6 ≤ 8: число 3 подходит, ответ не меньше 3, и lo = mid = 3. Третья середина (3 + 4 + 1) // 2 = 4, и 4 · 5 / 2 = 10 больше 8: hi = mid - 1 = 3. Теперь lo = hi = 3: ответ 3 после трёх проверок.

Правило. Инвариант: число lo подходит, а ответ не больше hi. При lo = hi ответ равен lo. Подходящая середина даёт lo = mid, неподходящая даёт hi = mid - 1. Середину берём с + 1: mid = (lo + hi + 1) // 2. Без + 1 поиск для n = 8 доходит до lo = 2 и hi = 3: середина (2 + 3) // 2 = 2 равна lo, 2 · 3 / 2 = 3 ≤ 8, ход lo = mid ничего не меняет, и цикл не заканчивается.

class Solution:
    def arrangeCoins(self, n: int) -> int:
        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if mid * (mid + 1) // 2 <= n:
                lo = mid  # монет хватает на mid рядов: ответ не меньше mid
            else:
                hi = mid - 1  # на mid рядов не хватает: ответ меньше mid
        return lo

Время: O(log n) в худшем случае. После проверки на отрезке [lo, hi] остаётся не больше ⌈s / 2⌉ значений k, где s - прежнее число значений, а ⌈x⌉ - это x, округлённое вверх. Для n = 8 значений 8, 4, 2, 1: 3 проверки. Для n = 231 − 1 значений не больше 231 − 1, 230, 229, ..., 2, 1: не больше 31 проверки. Дополнительная память: O(1) в худшем случае: числа lo, hi и mid. Вход n и ответ не считаем.

Решение 2. Формула и isqrt

Условие k(k + 1) / 2 ≤ n решается и без поиска. Для n = 8 число k = 3 требует 6 монет, и 8 · 6 + 1 = 49 = 72. Число k = 4 требует 10 монет, и 8 · 10 + 1 = 81 = 92. Это квадраты нечётных чисел 2k + 1, и так для каждого k: 8 · k(k + 1) / 2 + 1 = 4k2 + 4k + 1 = (2k + 1)2. Умножим обе части условия на 8 и прибавим 1: оно станет (2k + 1)2 ≤ 8n + 1. Для n = 8 имеем 8n + 1 = 65: 49 ≤ 65, поэтому k = 3 подходит, а 81 > 65, поэтому k = 4 не подходит.

isqrt(x) - наибольшее целое s, для которого s2 ≤ x. Для x = 65: 82 = 64 ≤ 65 < 81 = 92, поэтому isqrt(65) = 8. Квадраты растут, поэтому (2k + 1)2 ≤ 65 ровно при 2k + 1 ≤ 8. Нечётное число 2k + 1 не больше 8, когда оно не больше 7, то есть k ≤ 3. Наибольшее k равно (8 − 1) // 2 = 3. Для n = 3 имеем 8n + 1 = 25 = 52 и isqrt(25) = 5. Условие 2k + 1 ≤ 5 даёт k ≤ 2, и (5 − 1) // 2 = 2: два ряда заполнены полностью, монет не осталось.

Правило. Ответ равен (isqrt(8 * n + 1) - 1) // 2.

from math import isqrt


class Solution:
    def arrangeCoins(self, n: int) -> int:
        root = isqrt(8 * n + 1)
        return (root - 1) // 2

Время: O(1) в худшем случае: несколько арифметических действий над числами меньше 234, ведь 8n + 1 < 234 при n ≤ 231 − 1. Дополнительная память: O(1) в худшем случае: число root.

Типичные ошибки

  • Условие mid * (mid + 1) // 2 < n вместо <=. Для n = 3 два ряда занимают 1 + 2 = 3 монеты, то есть все. С этим условием первая середина (1 + 3 + 1) // 2 = 2, и 2 · 3 / 2 = 3 < 3 неверно, поэтому hi = 1 и ответ 1 вместо 2. Два ряда полные, хотя монет не осталось.
  • Формула int((2 * n) ** 0.5) вместо точной. Для n = 5: √10 ≈ 3,16, и int даёт 3, а три ряда требуют 6 монет, ответ 2. Для n = 8: √16 = 4, а ответ 3. Точная формула решения 2 использует 8n + 1.
